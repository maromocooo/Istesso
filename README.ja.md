# Istesso

[English](README.md) · **日本語** · [简体中文](README.zh-Hans.md) · [한국어](README.ko.md) · [Español](README.es.md)

Istesso は、ほかの PC で動くアプリを、手元の PC にふつうの窓として映します。通信には、Istesso 自身が暗号化した経路を使います。基準は一つです。少しでもリモートだと感じたら失敗です。

> [!IMPORTANT]
> Istesso は試用の段階です。作者が毎日使いながら、足りないところを探しています。その作業の多くは、まだ `main` に入っていないブランチで進んでいます。ダウンロードできる実行ファイルはありません。ソースからビルドして使います。いま何がどの機器で動くかは、下の表にあります。

## Istesso の仕組み

Istesso は、作業ごとに、いちばん遅れの少ない場所を次の順で選ぶ設計です。

1. 手元の PC でできることは、そこで動かします。ほかの PC とそろえるのは、その状態だけです。
2. 文字で済む作業には、端末で直接つなぎます。
3. 残るのは、画面が必要で、ほかの PC で動くアプリです。これだけを映像で中継します。アプリ一つを窓一つに映し、ポインターは手元で描きます。

どの窓がリモートか分からないことが合格の条件です。中継した窓と、手元で動かした同じアプリの窓を、同じ画面で計測して比べます。人の目でも、中継したほうを見分けられるか試します。この基準は、家庭の有線 LAN でつないだ PC に適用します。Wi-Fi とインターネット越しの接続は対象外です。

名前の由来は、音楽の指示 *l'istesso tempo* です。拍子が変わっても、同じ速さを保ちます。

## いま使える機能

各列は、アプリがどこで動き、どの機器に映るかを表します。

| できること | Linux ホスト → Mac | Mac ホスト → Mac | Linux ホスト → Android XR ヘッドセット |
|---|---|---|---|
| 一度だけ使えるコードで 2 台をペアリングする | `Verified` 2026-11-16（[記録](docs/milestones.md#m0-共通の土台) (日本語)） | `Trial` | `Trial` |
| すべての PC とそれぞれのアプリを一つの一覧で見る | `Verified` 2026-11-16（[記録](docs/milestones.md#m0-共通の土台) (日本語)） | `Trial` | `Planned` |
| ホストでアプリを開き、手元の窓一つに映して、キー、ポインター、スクロールで操作する | `Trial` | `Trial` | `Trial` |
| その窓と手元の PC の間で文字をコピーして貼り付ける | `Trial` | `Trial` | `Planned` |
| 入力方式を使って日本語を打つ | `Trial` | `Trial` | `Trial` |
| ホストの音を手元で聞く | `Planned` | `Planned` | `Planned` |
| アプリがどの PC に入っていても、アプリを起動する窓（ランチャー）から開く | `Planned` | `Planned` | `Planned` |
| USB 機器をほかの PC に引き渡し、そこに挿したように見せる | `Out of scope` | `Out of scope` | `Out of scope` |

- `Verified`（確認済み）は、読者が使う手順で、その役割の実機で `main` から動かして確かめたものです。確認した日付と記録へのリンクが必ず付きます。
- `Trial`（試用中）は、作者がブランチからビルドした試用版で動くものです。まだ `main` からは再現できません。
- `Planned`（計画中）は、設計中か、まだ手を付けていないものです。
- `Out of scope`（対象外）は、今回のリリースに含めないものです。

ヘッドセットは Wi-Fi でつなぐので、家庭の有線 LAN 向けの遅延基準の対象外です。この列の `Trial` は、試用版で使えるという意味です。遅延基準を満たすかどうかは示しません。

遅延は、2 台を有線でつなぎ、85 Hz の画面に 3440×1440 の映像を映して比べます。同じ画面で同じアプリを手元で動かしたときに比べ、中継で増える遅延の上限は、中央値で 12 ms、測定値を小さい順に並べたときの 95% の位置で 24 ms、99% の位置で 47 ms です。2026-11-17 に、試作のビューアー（映像を表示する側）と計測用のホストで、この関門を通りました。受け入れは、Istesso 自身のクライアントとホストで計測して、最終判定を出してからです（[関門の記録](docs/measurements/2026-11-17-m1-gate.md) (日本語)）。

## これからの予定

- Istesso 自身のクライアントとホストを `main` に入れ、そのあとで遅延の最終判定を行います。
- どのホストの音も、自分で選んだ一つの出力先で、何時間も途切れずに聞けるようにします。
- 複数の PC にまたがるランチャーから、スリープ中のホストを起こせるようにします。
- PC の間で保存領域を共有します。Istesso のアプリとエージェントを専用ユーザーで動かし、自分のファイルから切り離します。
- ビルドやジョブ（ひとまとまりの処理）は、それに向いた PC で動かします。
- 機器を挿し替えずに、ほかの PC から使えるようにします。すべての PC の機器を一つの一覧に出します。機器を使うアプリは、それが挿さっている PC で開き、窓は手元から操作します。最初に直接制御するのは、キーに機能を割り当てられるキーパッドです。表にあるとおり、USB 機器そのものをほかの PC に引き渡すことは対象外です。
- Android XR ヘッドセット用のクライアントを `main` に入れます。
- macOS と Ubuntu 向けの署名付きパッケージと更新の仕組みを用意し、ペアリングの外部レビューを受けます。
- Windows への対応は、今回のリリースのあとです。

各段階と、その段階を通るための試験は [docs/milestones.md](docs/milestones.md) (日本語) にあります。

## 分かっている制約

- 同じ PC で同じユーザーとして動くほかのプログラムから、Istesso を守る仕組みはありません。信頼できるプログラムだけを動かす、自分の PC で使ってください。
- 遅延の基準は家庭の有線 LAN が対象です。Wi-Fi とインターネットは対象外です（[Wi-Fi について](docs/wifi.md) (日本語)）。
- Linux ホストには、映像をハードウェアで圧縮する NVENC を備えた NVIDIA GPU が必要です。
- Mac ホストを再起動すると、誰かがその Mac で一度ログインするまで使えません。
- Mac をホストにすると、30 日ごとに、その Mac の画面に macOS の確認が出ます。システムの選択画面を使わずに、アプリが画面収録を続けてよいかを尋ねます。これは、この方法で画面を収録するアプリに Apple が定めた決まりです。Istesso が追加したものではなく、ソースからビルドしても確認が出ます。署名付きのビルドは配布していません。配布方法はまだ決まっていません。
- インストーラー、自動更新、署名付きの実行ファイルはありません。ペアリングは外部レビューをまだ受けていません。
- これまでの遅延の値は、試作のビューアーで測ったものです。受け入れは最終判定を待ちます。
- 今回のリリースは Windows に対応しません。

## 似た道具との違い

| 道具の種類 | できること | Istesso の作り | その道具が向く場面 |
|---|---|---|---|
| リモートデスクトップ（VNC、RDP など） | ほかの PC のデスクトップ全体を、ログイン画面も含めて使えます。インターネット越しにも使えます | 手元のデスクトップに、アプリごとの窓が、手元の窓やほかの PC の窓と並びます | デスクトップ全体やログイン画面が必要なとき、インターネット越しに使うとき、Windows を使うとき |
| ssh でつなぐ端末と、複数の端末をまとめて管理する道具 | どんな回線でも、文字のやり取りの遅れを最小にできます。接続が切れても作業は続きます | Istesso はこれに取って代わるものではありません。端末での文字のやり取りが三段階のうちの二つ目です。映像は画面が要るアプリだけに使います | 文字で済む作業をするとき |
| 窓の転送（ssh 経由の X11 など） | ssh の接続を通して、ほかの PC の X11 アプリの窓を一つずつ手元に表示します | 窓ごとに、ハードウェアで圧縮した映像を送ります。手元で動かした窓と比べて計測します | 使うのが X11 アプリで、接続の準備を ssh だけで済ませたいとき |
| ゲーム配信 | 全画面表示、マウスの移動量による操作、ゲームパッド、インターネット越しのプレイに対応します | アプリの窓向けです。ポインターの位置を画面上の絶対座標で伝え、カーソルを手元で描きます。ゲームは今回のリリースの対象外です | ゲームで遊ぶとき |

## まず試す

ここでは 1 台の PC を使います。分かるのは、その PC の役割、入っているアプリ、つながっている機器だけです。2 台をつないでほかの PC のアプリを映す手順は、まだこの README に載せていません。新しくクローンした状態から、この手順を確かめ直していないためです。

`git`、Rust 1.85 以降、C のビルド用の道具一式（macOS では Xcode Command Line Tools）が必要です。

```sh
git clone https://github.com/maromocooo/Istesso.git
cd Istesso
cargo build --release --locked -p istesso-cli
./target/release/istesso doctor
./target/release/istesso apps list
./target/release/istesso devices list
```

- `doctor` は、この PC の役割を表示します。たとえば、映像をハードウェアで圧縮できるか、Apple 向けにビルドできるか、常時稼働のホストに向くかが分かります。PC の名前とネットワークアドレスも出るので、どこかに貼る前に内容を確認してください。
- `apps list` は、この PC に入っているアプリを表示します。
- `devices list` は、この PC につながっている機器を表示します。

最後に新しいクローンから試したのは 2026-11-19 です。macOS 26.5（Apple silicon）で動かしました（[記録](docs/readme-checks.md) (日本語)）。

## ソースからビルドする

- Rust 1.85 以降が必要です。macOS と Linux でビルドできます。CI（変更ごとの自動確認）では、どちらでもビルドとテストを行います。
- 署名付きの実行ファイルは公開していません。Istesso の配布方法は未定です。

変更を送る前に、次のコマンドを実行してください。CI も同じ確認を行います。

```sh
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo deny check
```

`cargo deny check` には [cargo-deny](https://github.com/EmbarkStudios/cargo-deny) が必要です。

## セキュリティ

- ペアリングでは、片方の PC に一度だけ使える 8 文字のコードを表示し、もう片方に入力します。2 台は、このコードを使い、双方を確かめながら共通の鍵を作る手順（PAKE の一種である SPAKE2）を実行します。そのあと、互いの長期鍵を交換して固定します（[ADR 0006](docs/adr/0006-pairing.md) (日本語)）。
- それ以降の接続では毎回、固定した鍵で双方を確かめます。暗号化には Noise プロトコルフレームワークを使い、映像も同じ鍵で暗号化して送ります（[ADR 0007](docs/adr/0007-control-channel.md)、[ADR 0015](docs/adr/0015-media-transport.md) (日本語)）。
- ペアリングしたばかりの PC に許すのは、表示と操作だけです。権限はそれぞれ、許可した側の PC で取り消せます。

ペアリングはまだ外部レビューを受けていません。リリース前に受ける予定です。同じ PC で同じユーザーとして動くほかのプログラムから、Istesso を守る仕組みはありません。

脆弱性を報告するときは、GitHub の Security タブで「Report a vulnerability」を選び、非公開で報告してください。公開の issue には書かないでください。

## 開発に参加するには

- 開発者とコーディングエージェントが守る決まりは [AGENTS.md](AGENTS.md) (日本語) にあります。ブランチを切って作業し、新しい振る舞いにはテストを付けてください。
- GPL・AGPL のコードは取り込みません。外部のコードを使う前に、[docs/components.md](docs/components.md) (日本語) に照らして確認してください。仕様やプロトコルを借りる前には、ライセンスと特許の条件の両方を確認します。はっきりしないものは採りません。
- 映像、入力、音の経路を変えるときは、変更前後の計測値をプルリクエストに書いてください。測れなかったときは、その旨を書いてください。
- 機器に対応するためのアダプターは、接続のためのインターフェースがまだ固まっていません。アダプターを追加するプルリクエストは、まだ受け付けていません（[ADR 0012](docs/adr/0012-device-framework.md) (日本語)）。
