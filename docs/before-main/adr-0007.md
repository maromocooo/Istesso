### A3. ホストのフォルダーの指し方が 4 つある（【問い】）

| 指し方 | だれが決める | 字の決まり |
|---|---|---|
| `shell_open` の `project` にパス（`/…` か `~/…`） | 接続側 | 受け側のユーザーが入れるフォルダーなら、どこでも |
| `shell_open` の `project` に、登録したプロジェクトの名前（`proto-ish-projects`） | 受け側の登録（`istesso projects add`） | 英数字で始まる。`/` を含まない。大文字と小文字を区別しない |
| `mount_open` の `folder` に ID（`proto-mount-channel`） | 受け側の `--mount-folder <ID>=<フォルダー>` | `a-z`、`0-9`、`-` の 1〜32 字。`-` で始まらない |
| Air の表 `ISTESSO_MOUNT_HOST_PATH[<機械>/<ID>]`（`proto-ish-mount`） | 接続側 | マウントの ID ごとに、シェルを始めるフォルダー |

- `proto-ish-mount` の ADR は「受け側が ID でシェルを開く形にするか。おすすめ：プロジェクトの一覧を作るときに、そちらへ移す」と問うている。`proto-ish-projects` は、まさに「受け側が名前で開く」を作った。2 つの流れは、互いを見ていない。
- ADR 0025 の 1.1 は「ほかの機械から頼めるのは、プロジェクトの ID だけ。フォルダーの場所を受け取らない」。シェルのパスの形は、これと違う。
- 【提案】
  1. **シェルのパスの形は残す。** シェルは、開いたあとで、どこへでも cd できる。始めるフォルダーを絞っても、守りにならない（考えた）。このことを、シェルの節に 1 文で書く。ADR 0025 の 1.1 の「ID だけ」は、マウントとエディターのように、**フォルダーが守りの境目になる頼み**のための決まり、と書き分ける。
  2. **マウントの ID は、登録したプロジェクトの名前にする**（登録を 1 つに）。`--mount-folder` は、「この名前のプロジェクトを見せる」に変える。字の決まりは、きついほう（`a-z`、`0-9`、`-`）に、プロジェクトの名前もそろえるか、マウントのときだけ小文字に直して引く。
  3. そうすれば、Air の表 `ISTESSO_MOUNT_HOST_PATH` は要らない。cd でマウントしたフォルダーと、シェルの始まるフォルダーが、受け側の 1 つの登録から決まる（食い違いを手元で見分けられない、という `proto-ish-mount` の心配がなくなる）。
- 【問い A3】マウントの ID とプロジェクトの名前を 1 つにするか。おすすめ：**する**（`proto-ish-mount` と `proto-ish-projects` を合わせたあとに、1 つのコミットで）。

### A4. 端末の名指し：シェルは名前を断り、マウントは名前を受ける（直す）

- シェル：`--allow-shell` は**名前を受けない**（守りの見直しの指摘。名前は端末が自分で名乗るもの）。名前を渡すと、指紋を示して断る（ADR の文。コードは読んでいない）。
- マウント：`--allow-mount` の説明は「paired device (id or name)」。`MountPolicy::resolve` は `peers.find(selector)` で、名前でも引く（読んだ：`proto-ish-mount` の `crates/istesso-agent/src/mount/mod.rs`。動かしていない）。起動のときに鍵に直して覚えるので、あとで名前を変えても広がらない（読んだ）。それでも、起動のときに同じ名前を名乗った別の端末を、取り違えうる（考えた）。
- 【提案】**`--allow-mount` も、指紋（id）だけにする。** 名前を渡したら、シェルと同じく、その名前の端末の指紋を示して断る。マウントの節の「だれが、どのフォルダーを」に 1 文足す。

### A5. 権利の重さ（見直しで足りないと言われたもの）

- 試用版の通しの見直し（review-net の 1、2026-11-20 朝）：「見る」がなくても「操作」だけで、打てて、コピーも取れる（`serve.rs` の 603 行、493〜501 行。資料：`Claude outputs/streams-1120/review-net-findings.md`）。
- 【提案】入力の節に足す：**`input_open` と、`copy`／`paste` は、「見る」と「操作」の両方を持つ端末にだけ通す。** 映していない端末が打てると、何が起きているかを見ずに入力することになるため。開いているあいだの読み直し（1 秒おき）も、両方を見る。シェル、転送、マウント、エディターの節の「『操作』の権利を持っていること」も、同じ言い方にそろえるか、シェルとマウントは M5 の別の権利（「シェル」「ファイル」）にまとめるまで、いまの「操作」だけのままかを書く。
- 【問い A5】シェルとマウントも「見る」を求めるか。おすすめ：**求めない**（映像を使わないので「見る」は意味が合わない。M5 で、それぞれの権利にする、とすでに書いてある）。入力とコピーだけ、両方を求める。

### A6. 転送：ほかのユーザーからの接続（決まった）

- 持ち主の答え（2026-11-20 07:2x）：「ポートの転送で、Air のほかのユーザーからの接続は『断る』でよい」（資料：`Claude outputs/morning-2026-11-20.md`）。

### A8. エディター：まだのことを、はっきり書く
