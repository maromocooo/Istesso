# Mac をホストにした毎日の試用版（m4-daily-host）

- 状態：作った。Air の上で、許可の要らない範囲を確かめた。2026-11-19 11:47 に、Mac Studio（有線）の画面全体の絵が、Air の試用版のビューアー（窓なし）に届いた（下の「確かめたこと」）。
- ブランチ：`m4-daily-host`（`m4-capture` に `main` を合わせたもの）。**試用版だけ**です。製品の Mac ホストではありません。
- ねらい（持ち主、2026-11-19）：Air の試用版の窓と AURA から、Mac Studio（届くまでは Mac mini）のアプリを使う。まず画面全体で端から端まで通し、そのあと、アプリ 1 つの窓だけにする。

## 形

```text
Air（クライアント）                                Mac のホスト
試用版のビューアー（変えていない）── 絵（暗号化、4791N）── Istesso Dev Daily Host ── ScreenCaptureKit → VideoToolbox H.265
  └ istesso input relay ───────── 入力（制御チャンネル、4792N）── 試用の istesso agent ─ 入力の口 ─┘ → CGEventPostToPid（そのアプリのプロセスだけ）
AURA ─────────────────────────── 絵 4793N（4:2:0）、入力 4794N ── 同じ
```

- 絵は、Linux のホストと**同じ通り道**です。`scripts/m1-step3-host.py` が使う `istesso-media` の `istesso_media_host_send`（ADR 0015）を、プログラムに静的につないでいます。ビューアーと AURA は、何も変えずに受け取ります。
- 言葉（`pause`、`detach`、`resume`、`admit`、`close`）と、答えの JSON の行も、`m1-step3-host.py` と同じです。
- 入力は、`istesso agent` が渡すデータグラム（`key`、`pointer_at`、`button`、`scroll`、試用版の `text`）のうち、キーと確定した文字は、そのアプリのプロセスへ直に送ります。ポインターは、アプリの窓の形では、セッションを通す形（形 4）が既定です（直送のクリックは、ほかのプロセスに届かなかったため。下の「入力が届く範囲」）。範囲の外へは送らず、ロック中は、離すほかは何も送りません。確定した文字は `CGEventKeyboardSetUnicodeString` で送り、中身はどこにも書きません（ADR 0007 の「確定した文字」の上限と捨て方のとおり）。
- 圧縮の設定は、m4-plan.md の手順 2 で測ったもの（RealTime なし、並べ替えなし、キーフレームは求められたときだけ、BGRA のまま渡す）。Air には 4:4:4、AURA には 4:2:0。
- 遅れを溜めない：エンコーダーが前の 1 枚を持っているあいだに来た絵は、待たせずに、いちばん新しい 1 枚だけを残して、空いたらすぐ渡します（古い絵は捨てて、数える）。見ている端末がいないあいだは、圧縮しません。見ているあいだは、変化がなくても毎秒 20 枚渡して、エンコーダーを起こしておきます（m4-plan.md の 6.1b の F）。
- 時刻の記録：`frame_out`（画面に出た時刻と、届いた時刻）、`encoded`（渡した時刻と、出てきた時刻）、`sent`、毎秒の行（取り込み、圧縮、捨てた数、圧縮の時間の中央値と最大）。Linux のホストの記録と並べられる形です（正式な計測は、まだしない）。
- 計測の合図：Air の見張りは、`busy` で、窓と中継を止めます（ssh もしない）。ホストのプログラムは、ホスト自身の合図を 2 秒おきに読み、`busy` で絵を止めてエンコーダーを手放し、`free` で戻します。

## 使い方（Air で、このブランチのチェックアウトから）

**始める前に、Mac Studio のロックを外しておく。** ロック中は、ホストは何も映さず、入力も、コピーと貼り付けも、通さない（Air の窓の題名に「Studio はロック中」と出る）。

```sh
export ISTESSO_MAC_HOST=<ホストの ssh の名前>   # 言わなければ istesso-studio
scripts/daily-mac.sh setup                 # ここでビルドし、sign.env の証明書で署名して、ホストに写す
scripts/daily-mac.sh pair-line             # ホストで持ち主が打つ 1 行（Air と AURA のペアリング）
scripts/daily-mac.sh open TextEdit         # アプリを開いて、その窓だけを、ここの窓 1 枚に
scripts/daily-mac.sh open x --display      # 画面全体（最初の確かめだけ）
scripts/daily-mac.sh open TextEdit --for aura --size 1920x1080   # AURA 向け（ホストの側だけ）
scripts/daily-mac.sh list | hide APP | close APP | stop
```

- `close` は、2 とおりです（コードで確かめた、2026-11-19）。
  - 試用版の新しい文書で開いたもの（TextEdit）：その文書の窓だけを閉じる。TextEdit は終わらせない。窓の一覧にその窓がなくなったと確かめてから、その文書だけを消す。
  - それ以外（Dia、Safari、メモなど）：ホストに `close` を送り、ホストは、そのアプリに**終了を頼む**（「終了」メニューと同じ頼み方）。保存していないものがあれば、アプリが窓の中で尋ねて、残る。**Dia を開いたままにしたいときは、`close dia` ではなく `stop`**（前に「`close` は Dia を開いたまま残す」と書いたのは誤り）。
- `stop` は、試用版のプログラムだけを止めます。ホストのアプリは、開いたまま残します（持ち主のアプリなので）。窓は元の画面に戻ります。
- **コピーと貼り付けは、アプリの窓では既定で入る**（持ち主の決め、2026-11-19。Ubuntu と同じ）。ショートカットから開いたもの（環境が決まっていて `DAILY_CLIPBOARD` を持たない）も入る。切るのは `DAILY_CLIPBOARD=0` だけ。画面全体、生成した絵、AURA では、いままでどおり入らない。**流れ（エージェント）が自分の確かめで開くときは、コピーと貼り付けを試すのでなければ、`DAILY_CLIPBOARD=0` を付ける**（Studio のペーストボードに触らないため）。
- **新しい文書の名前と置き場所**（持ち主の決め、2026-11-19。持ち主が AURA で開いた TextEdit に、ほかの流れの古い試用の文書が出て、そこに打ったため）：`daily-mac.sh` が TextEdit を開くときは、どの形（`--for aura` も）でも、いつも新しい文書を作る。持ち主が開くと `~/.cache/istesso-daily-mac/documents/owner/owner-<アプリ>-<日付-時刻>.txt`、流れが開くと（`DAILY_STREAM=<流れの名前>` を付ける）`…/documents/streams/stream-<名前>-<アプリ>-<日付-時刻>.txt`。そのときアプリは、前の窓を戻さずに起動する（起動の引数 `-ApplePersistenceIgnoreState YES`。その起動の引数のドメインだけに効き、持ち主の TextEdit の設定には何も書かない）。もう動いている TextEdit が前から持っている窓は、映さない（開く前の窓の一覧と比べて、あとから出た窓だけを映す）。`close` が消すのは、自分が作ったその文書だけ（上の 2 つの場所と名前の形に合うものだけ）。
- ホストの上の場所：`~/.cache/istesso-daily-mac/`（プログラム、試用の身元 `config/`、アプリごとの `run/<名前>/`）。

### ぼやけをなくす：2 倍の画面（案の比べ。決めるのは持ち主）

| | A：仮想ディスプレイを 2 倍で作る | B：4K のダミープラグを挿し、2 倍（HiDPI）のモードにする |
|---|---|---|

| 壊れやすさ | OS の更新で、予告なく止まり得る。非公開の API を製品に載せるのは、まだ決めたことのない危うさ | 部品が要るだけ。OS の更新に強い |

- **画面の拍（持ち主の指摘）**：アプリは、窓が載っている画面の拍で描く。いまの画面は 240 Hz（1 枚 4.2 ms）。60 Hz のプラグへ窓を動かすと、描く間隔が 16.7 ms になり、遅れが増える。だから、プラグは **4K で 120 Hz 以上**（HDMI 2.1、または同じだけ出せる DisplayPort / USB-C のもの）で、HiDPI のモードを出せる EDID のものに限る。仮想ディスプレイ（A）は、非公開の API で拍を指定する形と読めるが、120 Hz 以上を指定できるか、それで描かれるかは、未確認。
- **送る拍と、受ける側**：いまは、取り込みを毎秒 60 枚に絞っている（`--fps 60`）。Air の画面は 60 Hz（外部ディスプレイなら 85 Hz）、AURA は 72 Hz。描く拍（120 または 240）が受ける側の拍の倍数でないと、受ける側では、ときどき 1 枚抜けたり 2 回出たりして、動きがぎくしゃくする（とくに 72 Hz）。案：取り込みは、受ける側の拍に合わせて上限を決め（Air 60 枚、AURA 72 枚）、描く側は 120 Hz 以上にしておく。取り込みは、いちばん新しい絵を、その拍で取るので、描く側が速いほど、1 枚が古くならない。確かめは、正式な計測のときに。
- おすすめだった：B。買うなら、HiDPI のモードを持つ EDID の、4K 120 Hz 以上のダミープラグ（HDMI 2.1）。

### 変換中の文字を、アプリの中に（`--inline`。試用だけ。既定は切）

[ADR 0023](adr/0023-mac-inline-input-source.md) のホストの側。入力ソース（Istesso Dev Input）と、そのつなぎ方（`macos/input-method/wire.swift`）は、入力ソースの流れのもの（ブランチ `m4-input-method-trial` を、このブランチに合わせた）。ホストの側は `macos/daily-host/inline.swift`。

- **切り替え**：`--inline`（または `ISTESSO_DAILY_INLINE=1`）。`daily-mac.sh` では `DAILY_INLINE=1`（アプリの窓の形だけ。画面全体、AURA、`--generated` では付けない）。**付けなければ、いまと同じ**：ソケットを作らない、入力ソースに触れない、種類 5 を送らない（ビューアーは帯）。`preedit` は、いままでどおり「知らないもの」と数える。ただ 1 つ、前の `--inline` の起動が戻さずに終わった印（`previous-source`）が残っていれば、その入力ソースに戻す。

- **順**：つながったら、まず `hello`（中継しているアプリのバンドル ID）。`preedit` は `mark`（文字、UTF-8 のバイトの範囲、ホストの変換の番号）、空の `preedit` は `clear`、確定（`text`）は `commit`（同じ番号）。確定のあとに来たもの（キー、クリック、次の文字）は、`inserted` が来るまで、順のまま持つ（長くて 50 ms。過ぎたら送り、`inserted_timeout` と数える）。
- **アプリの中に出すのは**：アクセシビリティで欄が文字の欄で、Istesso の入力ソースがこのホストの手で選ばれていて、入力ソースが中継しているアプリについて `active` を言い、キャレットが映している窓の中にあるときだけ（種類 5 の状態 1）。それ以外は 0（帯）。
  - `inactive` のすぐあとでも、0.5 秒ごとに `caret` を聞き、答えが来れば `active` とみなして戻る（Studio で見た「`active` のすぐあとに `inactive`」に、帯のまま残らないため）。
- **キーのあとの変換**：ホストがアプリにキー（または文字の道の文字）を送ってから 50 ms のあいだに来た変換中の文字と確定は、50 ms が過ぎるまで待つ（あとのものも順のまま待つ）。変換がキーを追い越したため（Studio で見た、2026-11-19 21:47、2 回：「かな」、Return、「です」で、Return と「です」が消えた）。
- **断られたとき**：`commit` が断られたら（`stale` 以外）、いまの文字の道（キーのイベントに文字を載せる）で届ける。`stale` は届け直さない。`mark` が断られたら、見せていたものを `clear` し、その変換は帯（状態 0）。その変換の確定も文字の道。帯は、確定、ビューアーのキーの押下（変換が終わった印）、入力ソースが切れたときに終わる。`secure-input` の断りは「パスワードの欄」とはみなさない。
  - 入力ソース 0.4 の答え（2026-11-19）：`commit` の `ok` は「入った」。`ok:true, inserted:false, ended:…` は、もう入っている（打ち直さない、文字の道でも送らない）。`ok:false, why:"cleared"` は、入っていない（文字の道で届ける）。`ok:false` で理由のないものは「分からない」として打ち直さない。アプリが終わらせた変換の `commit`、50 ms の待ちが過ぎたあとの断りも、打ち直さない（あとのキーより後に入るため）。`mark` が `why:"ended"` で断られたら、その変換はここでも終わり（欄の番号を進める）。`caret` の `ok` は四角が読めたか（`rect_ok`）で、理由のない答えは「有効」とみなす。
  - 切れたとき、ロックしたとき、止めるときは、まず `clear` を送り、その答えを（100 ms まで）待ってから、入力ソースを戻す（戻すのが先だと、入力ソースが書きかけの文字を書類に確定してしまうため）。手元のキーで戻すときは、入力方式のふつうのとおり、入力ソースが 1 回だけ確定して `ended` を言う。
  - 持ち主が手で別の入力方式を選んだら（同じ入力方式のかな・英字の切り替えは別の選びとみなさない）、次につながるまで Istesso に戻さない。
- **アプリが変換を終わらせたとき**（`ended`）：入力ソースが 1 回だけ確定している。ホストは種類 5 の欄の番号を 1 つ進める（いまのビューアーは、番号が変わると、確定せずに変換を捨てる）。そのあと 1 秒のあいだ、ビューアーの空の `preedit` が来るまで、行き違いの `preedit` と確定は捨てる（2 回入らないため）。
- **欄の状態（種類 5）**：`AXSecureTextField` は 2（いつでも）。文字の欄でないことが 100 ms 続き、入力ソースも `active` でないときだけ 3。読めないときは 0（帯）。別の要素がキーボードを持ったら、番号を進める。キャレットは、入力ソースの四角（大域の点、上から）を、注入と同じ `origin` と `scale`（絵の 1 ピクセルあたりの点）で絵のピクセルにする。2 倍の仮想ディスプレイでは 1 点が 2 ピクセル（自己試験で確かめる）。入力ソースの言う倍率と、窓のある画面の倍率が違えば `caret_scale_differs` と数える。
- **入力ソースの切り替え**：見ている端末がいて（絵が止まっておらず、計測の合図で止めてもおらず）、画面がロックされておらず、Studio の手元のキーボードが `--inline-local-idle` 秒（既定 3）打たれていないあいだだけ、Istesso の入力ソースを選ぶ。手元で打たれたら、100 ms 以内に元に戻す（HID の状態の「最後のキーからの秒」。入力監視は使わない。ホストが送るキーは `privateState`）。端末が離れて 10 秒だれも見ていなければ戻す（大きさを変えたときの作り直しと、始まりの仮想ディスプレイ作りのあいだは、見る端末が一時いなくなるので、それを切れたとみなさない。Studio で見た、2026-11-19。手元のキーボード、ロック、止めるときは、すぐ戻す）。止めるとき（SIGTERM、終わり）も戻す。落ちたあとは、次の起動で戻す。
  - 切り替える前の入力ソースは、ソケットのフォルダーの `previous-source`（0600）に 1 回だけ書く。枠ごとに `hold-slot-N`（プロセス番号）を書き、最後に手放す枠だけが戻す（動いていないプロセスの印は数えない）。戻すときに、持ち主が手で別の入力ソースにしていれば、そのままにする。ID は記録に書かない。
- **記録**：1 秒おきに `{"kind":"inline", 数}`、種類 5 が変わるたびに `{"kind":"field","state":…,"serial":…}`。文字、そのハッシュ、ほかのアプリの識別子、持ち主の入力ソースの ID は、どこにも書かない。
- **自己試験**（`--self-test`。ビルドのたび）：本物の入力ソースもアクセシビリティも使わない。入力ソースの代わり（ソケットの向こうの、同じ行を話すもの）と、入力ソースの一覧の代わりで、上の決まりを 58 通り確かめる。本物の署名の確かめが、アドホックの相手を断ることも見る。
- **まだ（Studio で、まとめ役の合図のあと）**：本物の入力ソースとの通し、確定とキーの順番、`inserted` の待ちの長さ、2 倍の仮想ディスプレイでのキャレットの位置、手元のキーの最初の 1 打。
- **`trial-daily` を合わせた**（bc353b5）：エージェント、中継、プロトコル、CLI は `trial-daily` のもの（`preedit`、確定した文字、コピーと貼り付け、スクロール、欄の番号、`peers allow/deny`、`devices list`）。このブランチにしかなかったのは、プロトコルの試験のスクロールの上限の確かめだけで、それは足した。`istesso-media` も `trial-daily` のもの。

#### 持ち主のいる最初の試し（TextEdit の試しの書類だけ）

まとめ役が持ち主に知らせてから行う。Studio の画面に窓が出て、メニューバーの入力ソースの印が変わる。開くのは、こちらの新しい TextEdit の書類だけ（持ち主の書類は開かない）。

1. **前に**：入力ソース 0.4 を Studio に置く（持ち主の OK が要る。入力ソースの流れの手順）。「Istesso Dev Input」が入力ソースの一覧で有効なこと。ホストのアクセシビリティの許可は、いまのもの。計測の合図が `free` なこと。
2. **Air で**：`scripts/daily-mac.sh setup`（署名したホストを写す）。そのあと `DAILY_INLINE=1 scripts/daily-mac.sh open TextEdit`。Air のビューアーは `trial-daily` のもの（`preedit` と種類 5 を知るもの）。
3. **見ること**（持ち主が Air で打つ）：
   - 打ち始めると、TextEdit の中に下線つきの変換中の文字が出る。候補の窓は、Air の上で、キャレットのすぐ下に出る。Air の帯には出ない。
   - Return で確定：1 回だけ入る。確定のすぐあとに速く打つ：順番が入れ替わらない。
   - 変換中に、TextEdit の別の所をクリック：その文字が 1 回だけ入り、Air で 2 回目が入らない。
   - Studio の手元のキーボードで打つ：メニューバーの入力ソースが元に戻り、手元の日本語入力が使える（そのあいだ Air は帯）。3 秒打たないと、Istesso に戻る。手元の最初の 1 打が英字で入るかも見る。
   - 変換中に Air の窓を閉じる（切る）：TextEdit に何も残らない。入力ソースが元に戻る。
   - `scripts/daily-mac.sh stop`：入力ソースが元に戻る（メニューバーで見る）。
4. **記録**（ホストの `run/TextEdit/`）：`host.err` の `inline:` の行（選んだ・戻した・はい／いいえ）、フレームの記録の `inline`（`commit_inserted`、`inserted_timeout`、`commit_refused_*`、`commit_cleared_text_path` などの数）と `field`（状態と番号）。文字はどこにもない。
5. **やめるとき**：`scripts/daily-mac.sh stop`。入力ソースが Istesso のまま残ったら、持ち主がメニューバーで選び直す（次にホストが起動したときにも、書いておいた元の入力ソースに戻す）。うまくいかなければ、`DAILY_INLINE` を付けずに開き直す（いまの帯の形）。

#### ビューアーに要るもの（試用版の流れへの仕様。`trial-daily` はこちらでは変えない）

いまは、欄の番号を進めることで代えている（いまのビューアーで動く）。ただし番号の変化は「別の欄」の意味なので、次の 2 つが起きうる：(a) 終わらせのすぐあと（往復 1 回のうち）に始めた新しい変換も捨てられる、(b) 終わらせと別の欄の移動の区別がつかない。そこで、専用の知らせを足す。

1. **種類 5 に「アプリが終わらせた」数を足す**（ADR 0015 の決まった部分のあと、位置 16、1 バイト：`ended`。決まった部分の長さを 17 にする。知らない見る側は読み飛ばす）。ホストは、アプリが変換を終わらせるたびに 1 進める（256 で 0）。欄の番号は進めない。
2. **ビューアーは**、`ended` が前と違うとき、変換中の文字があり、それをアプリの中に送っていた（`_preeditSent`）なら：入力方式の変換を、**確定せずに**捨てる（`discardMarkedText`、`unmarkText`）。空の `preedit` を 1 回送る（いまの `clearInlinePreedit` のとおり）。`text` は送らない。帯にも出さない。ほかの状態（パスワード、欄の外、`_movesSinceNotice`）は変えない。変換中の文字がなければ、何もしない。
3. **行き違い**：ビューアーは、変換ごとに番号を付けて `preedit` と `text` に載せる（`"comp":n`、0 から増える。変換を捨てた・確定したら次へ）。ホストは、終わったビューアーの番号を覚え、その番号の `preedit`・`text` を捨てる（1 秒の窓の代わり。いまの (a) がなくなる）。エージェントは、知らない項目を通すか、`InputEvent::Preedit` と `Text` に `comp: Option<u32>` を足す（ADR 0007 を先に直す）。
4. 試し：ホストの試しの形で、変換中にアプリの別の所を押す → アプリに 1 回だけ入り、Air で確定し直さない（Air の記録で `text` が 0、ホストで `commit_after_end_dropped` が 0 か 1）。

## まだのこと

- メニューの項目の名前は、どこにも書かない（最近使ったファイルの名前が、メニューに出るため。持ち主の決め）。案 A（メニューを読んで、Air の窓のメニューバーに出す）は、あとで作る。
- パネルが出ているあいだ、アプリの新しい窓（メニューなど）が絵に入るまで、最大 0.2 秒遅れる（受け入れた）。あとで、アクセシビリティの知らせ（窓ができた）で、すぐ置き直せるかを見る。

- **メニューバー**（ファイル、編集、…）：アプリの窓の形では、絵に入らない。金曜日は、⌘ のショートカット（⌘S、⌘O、⌘Z など）が使える（キーはアプリに届く）。案（決めるのは持ち主）：
  - **案 A（おすすめ）：メニューを読んで、Air の窓のメニューバーに出す。** ホストが、アクセシビリティでアプリのメニュー（`kAXMenuBarAttribute`）を読み、項目の名前、ショートカット、有効かどうか、チェックの印を、Air に送る。Air のビューアーは、その窓が前面のあいだ、自分のメニューバーにそれを出す。項目を選ぶと、ホストが、その項目を「押す」（`AXPress`）。見た目も使い方も、Mac のアプリそのものになり、説明が要らない。新しいメッセージが要るので、ADR 0007 を先に直す。メニューの名前は、画面の文字と同じ扱い（ログに書かない）。
  - 案 B：メニューが開いたあいだだけ、取り込む範囲を、メニューの窓まで広げる（メニューは、そのアプリの窓なので、範囲の決まりは変わらない）。作るのは小さいが、メニューバーそのもの（どこを押せば開くか）は、まだ見えない。
  - 案 C：Air の窓の上の帯に、ホストのメニューバーの帯（画面のいちばん上）を、そのアプリが前面のときだけ一緒に取り込む。ほかのアプリの名前や、メニューバーの右側（時計、通知など）も入るので、ADR 0017（読むのはアプリの窓まで）に合わない。
- 開く・保存のパネル：システムの別のプロセス（`com.apple.appkit.xpc.openAndSavePanelService`）が出す窓。**そのアプリ自身が、同じ場所と大きさの窓をアクセシビリティで持っているとき（つまり、そのアプリのパネルのときだけ）、そしてそのアプリが前面のときだけ**、取り込みにも、入力の範囲にも入れる。ほかのアプリのためのパネルは、入れない（自動のセキュリティの確かめの指摘、2026-11-19）。パネルの上で押したときは、ドラッグと離すのも、そのパネルの中に収める。実機では、まだ試していない。

- **（金曜日のあと）画面収録の定期的な確かめ直し。** macOS 15 以降は、「画面の取り込みを続けて許可しますか」という問いを、ときどき出す（ScreenCaptureKit でも出る、と報じられている。**未確認**）。誰も前にいない Mac Studio を外から（AURA などで）使うと、押すまで取り込みが止まる。避けるには、Apple に申請して受ける権利 `com.apple.developer.persistent-content-capture`（遠隔操作のアプリ向け）が要る見込み（Apple の文書は、まだ読んでいない。**未確認**）。M9 の一覧にも載せる（まとめ役）。

- Mac のホストの上で、画面の取り込み、入力の注入、アプリを開くこと。ほかのプロセスの窓へのクリック（形 1 が届くか。届かなければ形 2、3 を試す切り替え `--click-form` がある）。確かめには、数えるだけの窓 `Istesso Dev Input Target` を使う。
- ホストに日本語の入力方式が入っているとき、確定した文字のイベントがそのまま入るか。
- アプリのメニューバーは、絵に入らない（アプリの窓の範囲だけを取り込むため）。
- ADR 0017 は、画面全体の取り込みを製品に入れないと決めている。`--display` は、最初の確かめのためだけ。

## Studio に確認の窓が出たとき

Air の窓のタイトルに「— Studio で確認が出ています」と出たら、持ち主が Studio の前で確認に答えてください。この通知は窓の中身を読み取らず、表示も保存もしません。ログに残すのは、確認が出たことと消えたことだけです。

確認の窓を出すアプリの一覧は、プログラムに組み込んである。2026-11-19 に Mac Studio（macOS 26 の系）で、持ち主が確認の窓を出したまま `--prompt-windows` で読んで、見たもの：

| 確認 | 窓を出したもの | レイヤー | 大きさ（ポイント） |
|---|---|---|---|
| 管理者のパスワード（`do shell script … with administrator privileges`） | `com.apple.SecurityAgent` | 1000 | 260×418 |
| ファイルとフォルダ（デスクトップのフォルダ。こちらの開発用のアプリから） | `com.apple.UserNotificationCenter` | 8（モーダルのパネルの高さ） | 410×358 |
| アクセシビリティ（「デバイスの制御とデータへのアクセス」。ほかの流れの試しのアプリ） | `com.apple.accessibility.universalAccessAuthWarn` | 0 | 461×181 |

- 判定の下限のレイヤーは、出すものごとに決める：SecurityAgent と UserNotificationCenter は 8 以上、universalAccessAuthWarn は 0 以上（このプロセスは、確認のほかに窓を出さないので、0 でも取り違えない）。一覧のファイルで足したものは 8 以上。
- ほかの確認（ペーストの許可、Gatekeeper の問いなど）は、見てから足す。足すときは、Studio の `~/.config/istesso/daily-mac-system-prompts.txt` に 1 行に 1 つ書けば、次の起動から使う（128 バイト以内の正しい ID を先頭から 16 件まで。形式や上限に合わない行は、標準エラーに知らせて読み飛ばす）。
