# Mac をホストにした毎日の試用版（m4-daily-host）

- 状態：作った。Air の上で、許可の要らない範囲を確かめた。2026-11-19 11:47 に、Mac Studio（有線）の画面全体の絵が、Air の試用版のビューアー（窓なし）に届いた（下の「確かめたこと」）。
- ブランチ：`m4-daily-host`（`m4-capture` に `main` を合わせたもの）。**試用版だけ**です。製品の Mac ホストではありません。
- ねらい（持ち主、2026-11-19）：Air の試用版の窓と AURA から、Mac Studio（届くまでは Mac mini）のアプリを使う。まず画面全体で端から端まで通し、そのあと、アプリ 1 つの窓だけにする。

## 形

```text
Air（クライアント）                                Mac のホスト
試用版のビューアー（変えていない）── 絵（暗号化、4791N）── Istesso Dev Daily Host ── ScreenCaptureKit → VideoToolbox H.265
  └ istesso input relay ───────── 入力（制御チャンネル、4792N）── 試用の istesso agent ─ 入力の口 ─┘ → CGEventPostToPid（そのアプリのプロセスだけ）
AURA ─────────────────────────── 絵 4793N（4:2:0）、入力 4794N ── 同じ
```

- 絵は、Linux のホストと**同じ通り道**です。`scripts/m1-step3-host.py` が使う `istesso-media` の `istesso_media_host_send`（ADR 0015）を、プログラムに静的につないでいます。ビューアーと AURA は、何も変えずに受け取ります。
- 言葉（`pause`、`detach`、`resume`、`admit`、`close`）と、答えの JSON の行も、`m1-step3-host.py` と同じです。
- 入力は、`istesso agent` が渡すデータグラム（`key`、`pointer_at`、`button`、`scroll`、試用版の `text`）のうち、キーと確定した文字は、そのアプリのプロセスへ直に送ります。ポインターは、アプリの窓の形では、セッションを通す形（形 4）が既定です（直送のクリックは、ほかのプロセスに届かなかったため。下の「入力が届く範囲」）。範囲の外へは送らず、ロック中は、離すほかは何も送りません。確定した文字は `CGEventKeyboardSetUnicodeString` で送り、中身はどこにも書きません（ADR 0007 の「確定した文字」の上限と捨て方のとおり）。
- 圧縮の設定は、m4-plan.md の手順 2 で測ったもの（RealTime なし、並べ替えなし、キーフレームは求められたときだけ、BGRA のまま渡す）。Air には 4:4:4、AURA には 4:2:0。
- 遅れを溜めない：エンコーダーが前の 1 枚を持っているあいだに来た絵は、待たせずに、いちばん新しい 1 枚だけを残して、空いたらすぐ渡します（古い絵は捨てて、数える）。見ている端末がいないあいだは、圧縮しません。見ているあいだは、変化がなくても毎秒 20 枚渡して、エンコーダーを起こしておきます（m4-plan.md の 6.1b の F）。
- 時刻の記録：`frame_out`（画面に出た時刻と、届いた時刻）、`encoded`（渡した時刻と、出てきた時刻）、`sent`、毎秒の行（取り込み、圧縮、捨てた数、圧縮の時間の中央値と最大）。Linux のホストの記録と並べられる形です（正式な計測は、まだしない）。
- 計測の合図：Air の見張りは、`busy` で、窓と中継を止めます（ssh もしない）。ホストのプログラムは、ホスト自身の合図を 2 秒おきに読み、`busy` で絵を止めてエンコーダーを手放し、`free` で戻します。

## 使い方（Air で、このブランチのチェックアウトから）

```sh
export ISTESSO_MAC_HOST=<ホストの ssh の名前>   # 言わなければ istesso-studio
scripts/daily-mac.sh setup                 # ここでビルドし、sign.env の証明書で署名して、ホストに写す
scripts/daily-mac.sh pair-line             # ホストで持ち主が打つ 1 行（Air と AURA のペアリング）
scripts/daily-mac.sh open TextEdit         # アプリを開いて、その窓だけを、ここの窓 1 枚に
scripts/daily-mac.sh open x --display      # 画面全体（最初の確かめだけ）
scripts/daily-mac.sh open TextEdit --for aura --size 1920x1080   # AURA 向け（ホストの側だけ）
scripts/daily-mac.sh list | hide APP | close APP | stop
```

- `close` は、アプリの「終了」と同じ頼み方です。保存していないものがあれば、アプリが窓の中で尋ねて、残ります。
- `stop` は、試用版のプログラムだけを止めます。ホストのアプリは、開いたまま残します（持ち主のアプリなので）。
- ホストの上の場所：`~/.cache/istesso-daily-mac/`（プログラム、試用の身元 `config/`、アプリごとの `run/<名前>/`）。

| 壊れやすさ | OS の更新で、予告なく止まり得る。非公開の API を製品に載せるのは、まだ決めたことのない危うさ | 部品が要るだけ。OS の更新に強い |

- **画面の拍（持ち主の指摘）**：アプリは、窓が載っている画面の拍で描く。いまの画面は 240 Hz（1 枚 4.2 ms）。60 Hz のプラグへ窓を動かすと、描く間隔が 16.7 ms になり、遅れが増える。だから、プラグは **4K で 120 Hz 以上**（HDMI 2.1、または同じだけ出せる DisplayPort / USB-C のもの）で、HiDPI のモードを出せる EDID のものに限る。仮想ディスプレイ（A）は、非公開の API で拍を指定する形と読めるが、120 Hz 以上を指定できるか、それで描かれるかは、未確認。
- **送る拍と、受ける側**：いまは、取り込みを毎秒 60 枚に絞っている（`--fps 60`）。Air の画面は 60 Hz（外部ディスプレイなら 85 Hz）、AURA は 72 Hz。描く拍（120 または 240）が受ける側の拍の倍数でないと、受ける側では、ときどき 1 枚抜けたり 2 回出たりして、動きがぎくしゃくする（とくに 72 Hz）。案：取り込みは、受ける側の拍に合わせて上限を決め（Air 60 枚、AURA 72 枚）、描く側は 120 Hz 以上にしておく。取り込みは、いちばん新しい絵を、その拍で取るので、描く側が速いほど、1 枚が古くならない。確かめは、正式な計測のときに。
- おすすめだった：B。買うなら、HiDPI のモードを持つ EDID の、4K 120 Hz 以上のダミープラグ（HDMI 2.1）。
- **持ち主の決め（2026-11-19）：プラグを買う前に、試用版でだけ A を試す。** 結果（下）がよかったので、いまはプラグを買わない。

#### A を試した（2026-11-19 13:00:02〜13:00:16、Mac Studio、`--vd-check 1720x720@120`。見た）

- 前の状態（読むだけ）：画面は 1 枚、主の画面、原点 0,0、3440×1440 ポイント、3440×1440 画素、240 Hz。
- 仮想ディスプレイ（非公開の `CGVirtualDisplay`。宣言は、このプログラムのランタイムの中身から書いた `virtual-display.h`。ほかのプロジェクトのコードは読んでいない）を作り、2 倍（HiDPI）を求めた。**1720×720 ポイント、3440×1440 画素、120 Hz** になった（画面の倍率 2.0、毎秒の上限 120）。選べるモードの一覧にも、2 倍のもの（1720×720 pt / 3440×1440 px など）が 120 Hz で並んだ。
- その画面に、このプログラムの窓を 1 枚置き、毎拍描き直した：**描いたのは毎秒 126 枚、ScreenCaptureKit が取り込んだのは毎秒 115.6 枚、大きさ 3440×1440 画素**（2 倍のまま取れる）。
- セッションを通して、窓の中の（100, 50）ポイントを押すと、窓は（100, 50）で受け取った（座標の対応は正しい）。ポインターは、押したあと、元の場所へ戻した。
- 仮想ディスプレイを外したあと：画面は 1 枚、主の画面、原点 0,0、3440×1440、240 Hz。**前と同じ。**
- まだ：持ち主の目での、Air の上の文字の鮮明さ（アプリの窓をこの画面に置いて、確かめる）。

#### アプリの窓の形に入れた（2026-11-19、試用版）

- 仮想ディスプレイの大きさは、**受ける側の画面**（Air のいまの主の画面のポイント。2 倍、120 Hz）。`daily-mac.sh` が Air で読んで渡す（`DAILY_VIRTUAL=0` で使わない）。AURA の枠の大きさは、あとで。
- 作るのは、見ている端末が来たとき（ロック中は作らない）。窓を動かす前に、その窓の元の場所を覚える。最後の端末が離れても、つなぎ直しで戻ってくるかもしれないので、30 秒は待つ（`--virtual-keep`）。そのあとで、窓を元の場所へ戻し、仮想ディスプレイを外す。元の場所が、いまはどの画面にもないときは、主の画面の見える範囲に収める。
- 置き場所：**主の画面の右下の角に、角だけで触れる**（斜め）。辺で隣り合わないので、主の画面からポインターが入り込みにくい（角を正確に通らないと移れない）。この置き方は、このプログラムが動いているあいだだけ（`forAppOnly`。終われば macOS が戻す）。
- 窓が 2 倍の画面へ移ると、絵も 2 倍の画素で作り直す（640×432 ポイントの窓で、640×432 → 1280×864 画素）。
- **ホストのプログラムが落ちたとき**（見た。2026-11-19 13:04、こちらの数える窓で）：仮想ディスプレイは、プログラムと一緒に消える。macOS は、その上にあった窓を、**元の場所（主の画面の上）に戻した**（3440,1470 → 200,808）。見えないまま残る窓はなかった。画面の並びとモードも、前と同じに戻った。

#### 製品での形（持ち主の決め）

- 既定は、仮想ディスプレイ（2 倍、120 Hz 以上）。それが使えない Mac には、ダミープラグを勧める。
- **macOS の更新で壊れたことに気づく自己点検**を入れる：起動のたびに（と、更新のあとに）、仮想ディスプレイを作り、2 倍のモード、拍、取り込み、座標を、今回と同じ手順で確かめる。どれかが違えば、使う人に知らせ、物の画面かプラグの形に落とす。
- 試用版では、仮想ディスプレイは、見ている端末があるあいだだけ作り、いなくなったら外す。アプリの窓をそこへ動かすのは、アプリの窓の形のときだけで、Mac Studio の画面で何かが動く前に、持ち主に知らせる。
- どちらも、窓を、その画面へ動かす作りが要る（まだ作っていない）。

### 他の目のレビューのあとの直し（2026-11-19 12:3x）

- ロック中、またはログインのセッションが画面の前にないときは、どの形でも、離すほかは何も送らない（キー、文字、移動、押下）。画面全体の形でも、ログインの窓（ロックの画面のパスワードの欄）には送らない。ロックの知らせを受けたら、押されているものを、すぐ全部離す。ロックしたこと、外れたことは `{"istesso":"locked"}`、`{"istesso":"unlocked"}` で言い、Air の窓の題名に「Studio はロック中」と出す（遠くからロックを外すのは、あとで、セキュリティの確かめを経て設計する）。
- 見ている端末があるあいだは、Mac の画面を眠らせない（このプログラムの主張。最後の端末が離れて 10 秒で外す。m4-plan.md の 4.5b）。設定は変えない。
- 入力は、アクセシビリティを待たない：アクセシビリティの呼び出し（前面に出す、窓の大きさ、パネルの見分け）は、別の列で動かし、入力は、前に見つけた結果を使う（応えないアプリにも、0.25 秒で見切る）。押下とスクロールの直前だけは、窓の一覧を読み直す（1 回。WindowServer が答えるので、アプリを待たない）。キャッシュのあとで窓が動いた、閉じた、手前にほかが来たときは、押さない（`--self-test`）。
- 押したままが残らないように：受けるソケットを 1 MB にし、修飾キーは、押されているキーから毎回出し直す（失った離すで、⌘ が残らない）。何かが押されたまま 8 秒なにも来なければ、全部離す。
- `daily-mac.sh`：数値（`--fps`、`--slot`、`DAILY_CLICK_FORM`）と `DAILY_HOST_EXTRA`、`DAILY_MAC_DIR` を確かめてから使う。ホストのフォルダーは `~/` のあとの名前だけで、`eval` を使わない。前のアプリは消さずに `replaced/` へ移し、同じ場所に新しいものを置く。
- `--self-test` は 31 通り。

### Air の窓の大きさと、前面（試用版の新しい入力のイベント。ビューアーの側は試用版の流れが作る）

`istesso_proto::InputEvent` に、試用版だけのイベントを 2 つ足した（ADR 0007 の「入力」。エージェントは、そのまま渡す。古い受け手は、知らないイベントとして 1 つだけ読み飛ばす）。

| イベント | いつ送るか | ホストがすること |
|---|---|---|
| `{"kind":"focus"}` | Air の窓が、打ち込む窓になったとき（キーボードの焦点を得たとき） | そのアプリと、映している窓を、前に出す（アクセシビリティ。入力の道とは別の列） |
| `{"kind":"resize","width":W,"height":H}` | 持ち主が Air の窓の端を引いて、**引き終わったとき 1 回だけ**（`windowDidEndLiveResize`、または少し静かになってから）。W、H は、絵の欄が欲しい大きさ（絵の画素。いまの窓は、絵 1 画素を 1 ポイントで出しているので、そのポイント数）。64〜8192 | 映している窓を、その大きさに近づける（アプリの最小・最大と、画面の大きさの中で）。0.3 秒後に、窓がいま持っている大きさで、流れを作り直す。変わらなかったときも作り直す（それが答え） |

持ち主の決め（2026-11-19）：

- 引いているあいだは、何も送らない。ビューアーは、いまの絵を縮めたり広げたりして見せるだけ。
- ホストの答えは、新しい流れの大きさ（つなぎ直したあとの `StreamInfo` の幅と高さ）。ビューアーは、その大きさに窓を合わせ、**それに対して、もう 1 度は頼まない**（行ったり来たりにしない）。答えより前に、持ち主がまた引いたときだけ、また 1 回頼む。
- ホストの側から窓の大きさが変わったとき（Mac で直接、または上の答え）も、ビューアーは新しい流れの大きさに合わせるだけで、頼まない。

### 開けるアプリ、いくつも同時に、閉じ方（2026-11-19）

- **開けるのは、一覧にあるものだけ**：`scripts/daily-mac-apps.txt`（TextEdit、Safari、メモ、プレビュー、Finder、数える窓）と、持ち主が足す `~/.config/istesso/daily-mac-apps.txt`（Air の上。同じ形）。行ごとに、名前、バンドル ID（またはホームの下の `~/` の場所）、始め方：`document:txt`（試用版の新しい空の文書）、`new-window`（前面になったら、そのプロセスだけに ⌘N を送り、その新しい窓だけを映す）、`as-is`（開いたまま。メモのように、アプリ自身が前の中身を出すことがある）。持ち主の文書を、こちらから開くことはない。
- **いくつも同時に**：アプリごとに、ホストのプログラム、試用のエージェント、仮想ディスプレイを 1 つずつ（枠 1〜3、ポート 4791N／4792N）。1 枚の仮想ディスプレイを分け合わない理由：プログラムが別なので、1 つが落ちても、ほかのアプリの窓と画面には響かない（落ちたプログラムの仮想ディスプレイだけが消え、その窓は macOS が元の場所へ戻す。見た）。キーは、それぞれのホストが、自分のアプリが前面で、映している窓がキーを受ける窓のときだけ送るので、キーは、Air で打ち込んでいる窓のアプリにだけ入る（Air の窓が前面になると `focus` で、そのアプリを前に出す）。
- 仮想ディスプレイは、枠の番号の順に、主の画面の右下の角から横に並べる（枠 1 が角に触れ、枠 2 は枠 1 にだけ触れる）。
- **止めるとき**（`stop`、`close`、プログラムが終わるとき）：窓を元の場所へ戻し、仮想ディスプレイを外してから終わる。
- **閉じるとき**（持ち主の決め）：試用版の文書は、その窓を閉じ（アプリは終わらせない）、窓の一覧にその窓がなくなったと確かめてから、ファイルを消す。閉じたのと同じ手順の中では、消さない。窓が残っていれば、ファイルも残して、そう言う。
- **持ち主の決め（2026-11-19）**：持ち主のいない確かめで開くのは、TextEdit（こちらの新しい文書）と、こちらの数える窓だけ。メモ、Safari、Finder、プレビューは、持ち主の中身を見せるので、開くのは持ち主だけ。一覧では、それらに `owner` と書き、`daily-mac.sh` は、`DAILY_OWNER=1` があり、しかも端末から打たれたときだけ開く（エージェントは `DAILY_OWNER` を付けない決まりで、エージェントのコマンドには端末がない）。Spotlight などから持ち主がクリックして始める「Istesso Dev Open」（端末がない）から起動されたときも、持ち主とみなす（`DAILY_OPEN_HANDLER=1` があり、そのアプリのプログラムが、起動のもとをたどった先にあるとき）。**これは、エージェントのための決まりを守らせる仕組みで、守りの壁ではない。** 同じユーザーで動くエージェントなら、端末をまねることも、URL スキームを呼ぶこともできる。決まりは「エージェントは、それをしない」こと。持ち主が開いたときも、絵の中身は、どこにも記録しない（記録は数と時刻だけ。いまのフレームの記録も、そうなっている）。
- AURA の向き（`--for aura`）：いまは仮想ディスプレイを使わず、`--size 1920x1080` の窓をホストの画面のまま送る（1 倍、4:2:0、毎秒 60 枚）。AURA の枠のための仮想ディスプレイは、1920×1080 ポイントの 1 倍（1920×1080 画素）を案にする。2 倍（3840×2160 画素）は、Mac Studio の圧縮で毎秒 60 枚に間に合う見込みだが、測っていない。

### アプリを入れるとき：画面全体（`open desktop`）

- インストーラー、管理者のパスワードを求める画面、「インターネットからダウンロードしたアプリ」の問い、許可の問いは、そのアプリの窓ではないので、アプリの窓の形では映らない。そのために、画面全体を送る形を、名前 `desktop` で開けるようにした（`daily.sh open desktop --host mac`。試用版の流れと合わせる）。
- Mac の全部が映るので、開くのは持ち主だけ（`DAILY_OWNER=1`、持ち主の端末か「Istesso Dev Open」から）。クリックはセッションを通す（形 4。範囲は画面全体、ログインの窓を除く）。キーは前面のアプリへ。ロック中は、何も送らない。
- 見込み（確かめていない）：システムの管理者のパスワードの画面（SecurityAgent）は、取り込みから外されるか、作ったイベントを受け付けないかもしれない。そのときは、Mac Studio の前で打つことになる。持ち主が金曜日に試す。

### パスワードの欄（こちらの数える窓で確かめる）

- 数える窓の下に、パスワードの欄（`NSSecureTextField`）を足した。数えるのは、欄にある文字の数と、macOS の安全な入力（Secure Event Input）が入ったかだけ。中身は書かない。
- 見込み：そのアプリのプロセスへ直に送るキーは、安全な入力が入っていても、その欄に届く（安全な入力が止めるのは、ほかのプログラムがキーを盗み見ることで、プロセスへの直送は、それにあたらないと読める）。確かめは、持ち主が Mac Studio で打っていないと分かってから。

## まだのこと

- メニューの項目の名前は、どこにも書かない（最近使ったファイルの名前が、メニューに出るため。持ち主の決め）。案 A（メニューを読んで、Air の窓のメニューバーに出す）は、あとで作る。
- パネルが出ているあいだ、アプリの新しい窓（メニューなど）が絵に入るまで、最大 0.2 秒遅れる（受け入れた）。あとで、アクセシビリティの知らせ（窓ができた）で、すぐ置き直せるかを見る。

- **メニューバー**（ファイル、編集、…）：アプリの窓の形では、絵に入らない。金曜日は、⌘ のショートカット（⌘S、⌘O、⌘Z など）が使える（キーはアプリに届く）。案（決めるのは持ち主）：
  - **案 A（おすすめ）：メニューを読んで、Air の窓のメニューバーに出す。** ホストが、アクセシビリティでアプリのメニュー（`kAXMenuBarAttribute`）を読み、項目の名前、ショートカット、有効かどうか、チェックの印を、Air に送る。Air のビューアーは、その窓が前面のあいだ、自分のメニューバーにそれを出す。項目を選ぶと、ホストが、その項目を「押す」（`AXPress`）。見た目も使い方も、Mac のアプリそのものになり、説明が要らない。新しいメッセージが要るので、ADR 0007 を先に直す。メニューの名前は、画面の文字と同じ扱い（ログに書かない）。
  - 案 B：メニューが開いたあいだだけ、取り込む範囲を、メニューの窓まで広げる（メニューは、そのアプリの窓なので、範囲の決まりは変わらない）。作るのは小さいが、メニューバーそのもの（どこを押せば開くか）は、まだ見えない。
  - 案 C：Air の窓の上の帯に、ホストのメニューバーの帯（画面のいちばん上）を、そのアプリが前面のときだけ一緒に取り込む。ほかのアプリの名前や、メニューバーの右側（時計、通知など）も入るので、ADR 0017（読むのはアプリの窓まで）に合わない。
