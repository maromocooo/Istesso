# M9 の進め方：配布と公開の下ごしらえ

M9 は、Mac の署名・公証つき pkg と、Ubuntu の .deb を作り、公開する段階です（[milestones.md](milestones.md)、R-12）。この文書は、その下ごしらえです。**何も入れず、本物の証明書で署名せず、公開もしていません。** 用意したものは `packaging/` にあります（[README](../packaging/README.md)）。

読むときの注意：

- 「提案」と書いたものは、私の提案です。決まったことではありません。
- 持ち主がすでに決めたことは、「決定」と書いて、そのまま載せました。
- Apple の画面や Ubuntu の細かい仕様は、この文書を書いた Mac の上で確かめていません。自信のないところは「要確認」と書きました。
- 計測のコード、暗号、入力の経路には、手を入れていません（遅延の計測は要りません）。

### 0.1 名前と識別子（**決定**：持ち主が、この表を受け入れた。2026-11-17）

許可（画面収録、ローカルネットワーク、アクセシビリティ）は、**識別子**に結びつきます。そのため、いま決めて、変えません。持ち主は `maromoco.com` を持っているので、逆さにして `com.maromoco` を使います。開発ビルドは、自己署名の証明書で署名し、**本番と同じ識別子**を使います（許可の確認を、本番と同じ形でできるように）。開発専用の補助（テストアプリ、計測の道具）は、別の接頭辞にして、本番の許可の一覧に混ざらないようにします。

| 何か | 名前・識別子（提案） | 現れる場所 | あとで変えるときの代償 |
|---|---|---|---|
| クライアントのアプリ | 名前 `Istesso`。バンドル ID `com.maromoco.istesso` | `Info.plist`（`CFBundleIdentifier`、`CFBundleName`）。署名の識別子。システム設定の許可の一覧に、アプリ名で見える。`/Applications/Istesso.app`。設定の置き場の名前は `istesso`（コード側。別の決まり） | **許可が全部失われる**（画面収録、ローカルネットワーク、アクセシビリティ）。全員が、与え直す。指定要件が変わるので、署名の確かめ直しも要る |
| launchd のエージェント | ラベル `com.maromoco.istesso.agent` | plist の `Label` と、ファイル名 `/Library/LaunchAgents/com.maromoco.istesso.agent.plist`。`launchctl` の表示。システム設定の「ログイン項目」に見える | 古いラベルのエージェントを、新しい版の pkg が止めて消す処理が要る。許可には影響しない（許可は、`AssociatedBundleIdentifiers` のバンドルに付く） |
| pkg | 識別子 `com.maromoco.istesso.pkg` | `pkgbuild --identifier`。`pkgutil --pkgs` の一覧。インストールの記録（レシート） | 古いレシートが残る。更新の判断に使われるので、変えると「別のパッケージ」になり、上書きの扱いが変わる |
| Mac ホストのアプリ（別バンドルにするとき） | 名前 `Istesso Host`。バンドル ID `com.maromoco.istesso.host` | クライアントと同じ場所に加えて、画面収録とアクセシビリティの一覧に、別の項目として見える | 名前を先に決めておけば、ない。実際に作るのは、M4 の結果のあと。同じバンドルにするなら、この行は使わない |
| 開発専用の補助 | 接頭辞 `com.maromoco.istesso-dev.`（例：`com.maromoco.istesso-dev.flash`、`.screen-probe`）。名前は `Istesso Dev Flash` のように、`Dev` を入れる | 開発用の Mac の許可の一覧。配布物には入らない | 今ある `dev.istesso.*` からの付け替えは、開発用アプリの許可を 1 回与え直す程度（5 の 7）。配布には影響しない |
| Linux のパッケージ | `istesso` | `dpkg -l`、`apt`。`/usr/bin/istesso`、`/usr/share/doc/istesso/` | 変えると別のパッケージ。旧版の `Replaces`、`Conflicts` が要る。設定ファイルの引き継ぎも要る |
| systemd のユニット | `istesso-agent.service`（ユーザーユニット） | `/usr/lib/systemd/user/`。`systemctl --user` の表示。利用者が有効にしたリンク | 利用者が有効にした分は、リンクが切れる。postinst で付け替える処理が要る |
| デスクトップファイル、アプリ ID | `com.maromoco.istesso`（`com.maromoco.istesso.desktop`）。いまは画面のアプリがないので、作らない。作るときに、この名前にする | `/usr/share/applications/`。Wayland のアプリ ID。ポータルの許可の一覧 | 画面共有などの許可が、Linux でも失われる |
| Linux のグループ | `istesso` | `/etc/group`。`limits.d` の `@istesso` | 変えると、利用者を入れ直す。limits の設定ファイルも直す |
| Linux の設定ファイル | `/etc/security/limits.d/40-istesso.conf`、`/etc/istesso/` | パッケージの conffile | 利用者が直した分の引き継ぎが要る |

注：

- **名前の商標の調べが、持ち主の側で進んでいる。リリースの前に、名前がもう一度決まり直すかもしれない。** そのため、名前と識別子は、プラットフォームごとに 1 か所にまとめておく（Mac は `build-pkg.sh`、`uninstall.sh`、plist、pkg-scripts の冒頭の定数。Linux は `build-deb.sh`、`debian/`、`systemd/`、`etc/`）。変えるときは、許可が失われる代償（上の表）を先に確かめる。
- **Linux のパッケージ名 `istesso` の衝突の確認（読むだけ。2026-11-17 16:07、日本時間）：** Debian のパッケージ検索（packages.debian.org、名前に `istesso` を含むもの、全スイート・全セクション・全アーキテクチャ）、Ubuntu のパッケージ検索（packages.ubuntu.com、同じ条件。新しい版を含む全スイート）、Debian のソース検索（sources.debian.org）で、`istesso` だけを送って調べた。**どれも結果なし。** ホストの Ubuntu 24.04（main、restricted、universe、multiverse）にも、`istesso` で始まるパッケージと `/usr/bin/istesso` はない（調整役の確認）。パッケージ名が衝突しないことが、いまのところ確かめられた。これらの検索は、公開時点の状態でしかない。リリースの直前に、もう一度確かめる。
- 既存の開発用の識別子（`dev.istesso.*`）の付け替えは、持ち主が承認した。作業は、そのスクリプトを持つ流れが、調整役の指示で行う。

### 1.2 置く場所（提案）

| 場所 | 中身 | 持ち主 |
|---|---|---|
| `/Applications/Istesso.app` | バンドル | root:wheel（pkg が作る） |
| `/Library/LaunchAgents/com.maromoco.istesso.agent.plist` | launchd のエージェント | root:wheel、0644 |
| `/usr/local/bin/istesso` | バンドルの実行ファイルへのシンボリックリンク | root |
| `~/Library/Application Support/istesso/` | 端末の鍵、ペアリング済みの一覧（`istesso-agent` の `paths.rs` で決まっている） | 利用者。**pkg は触らない** |
| `~/Library/Caches/istesso/` | 作り直せるもの | 利用者 |

`/Applications` に固定するのは、許可がバンドルの場所と署名に結びつくためです。pkg は、バンドルを「再配置しない」設定で作ります（`BundleIsRelocatable` を false）。ビルドのフォルダーなど、別の場所にあるコピーに、勝手に上書きされないようにするためです。

### 1.3 常駐（launchd。提案）

| 項目 | 内容 |
|---|---|
| ラベル | `com.maromoco.istesso.agent` |
| 種類 | ユーザーごとの LaunchAgent（`/Library/LaunchAgents`）。LaunchDaemon にしない。画面収録とローカルネットワークの許可は、ログインしたセッションに属するため。鍵も利用者のフォルダーにある |
| 起動 | ログイン時（`RunAtLoad`）。`LimitLoadToSessionType` は `Aqua`。エラーで終わったら 10 秒おいて再起動（`KeepAlive` の `SuccessfulExit` が false）。正常終了（0）は、止めたままにする |
| 実行するもの | `/Applications/Istesso.app/Contents/MacOS/istesso agent`。`AssociatedBundleIdentifiers` でバンドルに結びつける |
| 優先度 | `ProcessType` は `Interactive`（遅延が大事なため） |
| ログ | ファイルは作らない。標準エラーは統合ログへ。ペアリングコード、鍵、トークンは出さない（AGENTS.md） |
| 止め方 | その場で止める：`launchctl bootout gui/$(id -u)/com.maromoco.istesso.agent`。次のログインから止める：`launchctl disable gui/$(id -u)/com.maromoco.istesso.agent`。外す：`uninstall.sh` |
| 入れたとき | pkg の preinstall が、ログインしている人のエージェントを止める。postinstall が、同じ人のエージェントを起動する。ほかのユーザーは、次のログインで起動する。どちらも、失敗しても入れる処理を止めない |

ホストの Mac は、人がログインしたままにする形です（M4 の決定）。ログイン前のホストは、いまの範囲に入りません。

### 1.4 更新で許可を失わないために（提案）

許可は、バンドル ID と、署名の「指定要件」（Developer ID と Team ID を含む）に結びつきます。更新の決まりは次のとおりです。

1. バンドル ID を変えない。Team ID（同じ証明書の持ち主）を変えない。
2. 毎回、同じ場所（`/Applications/Istesso.app`）に、バンドル全体に署名したものを入れる。
3. 署名なしのバンドル、アドホック署名のバンドルを、利用者の手元に出さない。
4. 実行ファイルの名前を変えない。
5. 古いバンドルを消してから新しく作らない。pkg が、場所はそのまま、中身を上書きする。

リリースごとの確認（署名したビルドで、Mac の実機。AGENTS.md の「実機で確かめる」）：

- 1 つ前の版を入れ、画面収録、アクセシビリティ、ローカルネットワークを与える。
- 新しい版を、pkg で上から入れる。許可の画面が、もう一度出ないこと。`istesso doctor` で許可の状態が同じであること。
- 別の端末に、エージェントから届くこと。

### 1.5 pkg の作り方（`packaging/macos/build-pkg.sh`）

流れ：バンドルを作業用フォルダーに複製 → 署名（環境変数があれば）→ launchd の plist とシンボリックリンクを足す → `pkgbuild`（再配置しない）→ `productbuild`（署名は環境変数があれば）→ 公証とステープル（`ISTESSO_NOTARY_PROFILE` があれば）。署名の指定がなければ、署名なしで作り、そう表示します。

ビルド UUID の確認（署名したビルドでやる。提案）：`dwarfdump --uuid` で、バンドルの実行ファイルの UUID が、ほかの配布物と重ならないことを見る。重なるときは、ビルドし直す。

### 1.6 リリースの手順の順番（署名の前の確認を含む）

1. リリース用にビルドする：`macos/client/build.sh`（`origin/m1-own-client`、ADR 0018）。**リリースの流れは、`measuring` を、ビルドに決して渡さない。** 計測用のビルドは、計測の鍵のための入口をプログラムの中に持つ。配るビルドには、そのコードが、まったく入らない（持ち主の決定）。
2. **Developer ID で署名する前に**、署名しようとするバンドルに `macos/client/build.sh check` を実行する。実行ファイルの中に、計測用の印（`measure-keys`、`istesso_measure_keys`）があれば失敗する。**失敗したら、リリースを止める。** 直してからやり直す。`build-pkg.sh` も、署名の前に、同じ印を実行ファイルから探し、あれば止まる（二重の確認。印の一覧は、`build.sh` の `marks` と同じにしておく）。
3. `build-pkg.sh` で署名、pkg、公証（1.5）。

開発用の補助の識別子（0.1 の接頭辞のもとで、いま使われているもの）：`com.maromoco.istesso-dev.audio`（`Istesso Dev Audio`）、`com.maromoco.istesso-dev.measure`（`Istesso Dev Measure`）。配布物には入らない。

## 2. Ubuntu

### 2.1 `.deb` の中身（提案）

| 場所 | 中身 |
|---|---|
| `/usr/bin/istesso` | コマンドラインとエージェント |
| `/usr/lib/systemd/user/istesso-agent.service` | ユーザーユニット（有効にはしない） |
| `/usr/lib/udev/rules.d/70-istesso-usb.rules` | 対応 USB 機器を、グループ `plugdev` に開く |
| `/etc/security/limits.d/40-istesso.conf` | グループ `istesso` に、リアルタイム優先度と nice だけを許す（conffile。利用者が直したものは、更新で上書きしない） |
| `/usr/share/doc/istesso/` | `LICENSE-MIT`、`LICENSE-APACHE`、`copyright`、`third-party-licenses/` |

Docker は必須にしません（R-12）。ホストのコンポジターなどの部品（M1 以降）は、できたときに足します。

### 2.2 systemd（提案：ユーザーユニット）

ホストの前には、ふつう誰もいません。それでも**システムユニットにしない**理由は 3 つです。

1. 端末の鍵とペアリング済みの一覧が、その利用者のフォルダーにある。
2. 映像と音の部品（コンポジター、PipeWire）が、その利用者のユーザーサービスである。
3. システムユニットにすると、利用者名を決め打ちにする必要がある。

誰もログインしていなくても動くようにするのは、`loginctl enable-linger <利用者>` です。これは root の仕事で、利用者を知っているのは持ち主だけなので、パッケージは行いません（2.3 の表の最後）。持ち主が、1 回、次の 2 行を実行します。

```sh
sudo loginctl enable-linger <利用者>
systemctl --user enable --now istesso-agent.service
```

止め方：`systemctl --user stop istesso-agent.service`（無効にするのは `disable`）。正常終了は再起動しない。エラーで終わったら、5 秒おいて再起動する。

### 2.3 root が要るもの（インストーラーの仕事）

| # | もの | 置く場所 | 理由 | 誰がやるか |
|---|---|---|---|---|
| 1 | USB 機器の udev の決まり（グループの形） | `/usr/lib/udev/rules.d/70-istesso-usb.rules` | 機器の口（`/dev/hidraw*`）は root だけが開ける。`uaccess` は、その PC の前でログインしている人にしか効かず、ホストでは効かない。グループ `plugdev`（ホストの利用者がすでに入っている）に与える。1 回の導入で済む | `.deb` |
| 2 | リアルタイム優先度と nice の上限 | `/etc/security/limits.d/40-istesso.conf`（グループ `istesso`、`rtprio 95`、`nice -19` だけ） | 取り込みと送り出しを、ほかの仕事に遅らされないため。ディストリビューションの `pipewire` グループの設定は使わない。あれは固定できるメモリの上限（`memlock`）も決めており、`pipewire` グループの人と一緒になって下げないため。**この設定が、ユーザーサービスにも読まれることは、M2 の観察による**（M2 の計画の手順 6。実機での確認は M2 の流れ） | `.deb` がファイルを置き、グループを作る。**利用者をグループに入れるのは、持ち主**（`sudo gpasswd -a <利用者> istesso`） |
| 3 | GPU が同時に圧縮できる枚数 | `/etc/istesso/encoder-sessions`（数字 1 つ） | GPU の上限を超えると、圧縮が途中で失敗するため。**映像が流れていないときに、1 回だけ数え、その数から 2 を引いた数**にする。数えられなければ 8。2 以下なら 1 | `.deb` の postinst。数える小さなプログラム（`/usr/libexec/istesso/count-encoder-sessions`。名前は提案。**まだない**）があれば、それを呼ぶ。なければ 8 を書く。すでにファイルがあれば、上書きしない |
| 4 | CPU を深い眠りに入れない：`/dev/cpu_dma_latency` を、利用者のものにする udev の決まり（**計測で、やる価値があると分かったときだけ。まだ決めていない**） | 入れるなら `/usr/lib/udev/rules.d/` に 1 つ（いまは作らない） | 機器を表示するセッションのあいだ、CPU の眠りからの復帰が、遅延に出るかもしれない。`/dev/cpu_dma_latency` は、開いて値を書き、開いたままにするあいだだけ効く。普通は root だけが開ける。**要確認**（実機で効果を測ってから、別に決める） | いまは何もしない |

### 2.5 リポジトリ（提案）

R-12 は、署名つきのリポジトリを求めています。署名の鍵（リリース用の GPG 鍵）は、持ち主の手元に置き、リポジトリにも CI にも入れません。`.deb` 自体には署名せず、リポジトリの `Release` ファイルに署名します（`apt` の標準の形）。リポジトリを作る道具（`reprepro` か `aptly` など）と、置く場所（静的なファイルの置き場）は、まだ決めていません。要決定（5 の 2）。

## 4. 最初のリリースについての決定（2026-11-17、持ち主）

### 4.1 自動更新：入れない（決定）

- **最初のリリースには、自動更新を入れない。**
- Mac：アプリは、新しい版があることを、利用者に**知らせるだけ**にする。入れるのは、利用者が pkg を開いて行う。許可は、1.4 のとおり残る。
- Ubuntu：更新は `apt` の仕事。`unattended-upgrades` を使うかは、利用者の選択。
- 知らせる仕組み（フィードの置き場、版の確かめ方、確かめるときに IP アドレスと版が知られること）は、別に設計する（5 の 6）。**自動で入れる形は、最初のリリースのあとに、もう一度決める。** そのとき必要なもの：更新の置き場、更新ファイルへの署名の鍵（Developer ID の署名とは別）、クライアントの検証。危険：鍵が漏れると全員の PC で他人のコードが動くこと。途中でセッションが切れること。クライアントとホストの版が合わなくなること。

### 4.2 外部レビュー：最初のリリースの条件にしない（決定）

- ペアリングと通信の部分は、**外部レビューを受けていない**。リリースの文章（README、ダウンロードのページ、リリースノート）に、そう書く。
- 文面に入れること（提案）：「ペアリングと通信の部分は、外部のレビューを受けていません。信頼できる LAN の中か、VPN の中で使ってください。」
- 脅威モデルと、設計の文書（ADR 0006 ペアリング、ADR 0007 制御チャンネル）を、読める形で公開する。**レビューは、リリースのあとに、歓迎する形で呼びかける。** 見積りは、とらない。
- 読める形の脅威モデルのページを書くのは、別の流れの仕事（5 の 5）。この文書では、書かない。
- 時間と費用の見立ては、この決定で要らなくなったので、消した。
