# M5 の進め方：ストレージと隔離（設計）

M5 は、統合ストレージ（R-06）、隔離（R-07）、インストールの振り分け（R-05）の段階です。

**今週は、設計までです**（2026-11-16 に決定）。実装するときも、試験用のフォルダーの中だけで動かし、ふだんのファイルには触れません。ねらいは、ファイルが消える、壊れる事故を避けることで、ここだけは急ぎません。

この文書は、設計と、あとで実装するときの決まりです。決定が要るところは、2つの ADR に分けました。どちらも提案です。

決めごとで判断がつかないところは、ねらいに合うほうを選びました（[milestones.md](milestones.md) の「今週の進め方」）。**M5 では、2つのねらいがぶつかるところがあります。** 使い手は開発者に限らないので、説明なしで使えることが大事です。一方で、M5 のねらいは、事故を避けることで、急ぎません。ぶつかるところでは、M5 のねらいを先にしました。選んだところは、「10. 決まったことと、まだ決まっていないこと」に書いてあります。

- [ADR 0013](adr/0013-unified-storage.md)：統合ストレージは、一覧と合算から作る。中身は、人が名指ししたコピーから始める。
- [ADR 0014](adr/0014-dedicated-user-in-practice.md)：ホストの役は、丸ごと専用ユーザーで動かす。

土台は [ADR 0003](adr/0003-isolation.md)（隔離は専用ユーザーで行う）です。規約は先に [AGENTS.md](../AGENTS.md) を読んでください。

読むときの注意：

- **この文書は、実機で何も動かさずに書きました。** Air は、読むだけの調査をしました（4.2）。Ubuntu のホストは、見ていません（4.3 に、確かめるコマンドがあります）。
- ADR 0009（`m1-latency` ブランチ）と ADR 0010（`m3-app-manager` ブランチ）は、まだ `main` にありません。リンクにせずに、番号で指します。

## 1. 確かめること（受け入れ条件の案）

[milestones.md](milestones.md) の M5 には、受け入れ条件がまだありません。公開に書けるのは、受け入れ条件を通った機能だけなので、先に条件を決めます。次は、その案です。3つの組は、別々に通せます。

| # | 条件 | 要件 |
|---|---|---|
| S1 | 2台の実機で、どちらからでも、両方の領域のファイルが1つの一覧で見える。合計の容量と空きが出る | R-06 |
| S2 | 片方を止めると、その PC にしかないファイルに「取得できない」の印が付く。合計が、「いま使える分」と「止まっている分」に分かれる | R-06 |
| S3 | ほかの PC のファイルを取得すると、元と同じ中身になる（ハッシュが一致する）。途中で接続を切っても、壊れたファイルが残らない | R-06 |
| S4 | どの操作も、領域の外のファイルを、作らない、変えない、消さない。領域の中でも、消さない、上書きしない | 今週の決定 |
| I1 | 専用ユーザーから、ふだんのホームに置いた目印のファイルが読めない。Linux と macOS の両方で | R-07 |
| I2 | 専用ユーザーが、管理者の権限を持っていない | R-07 |
| I3 | herdr の上のコーディングエージェントから読めるのが、領域だけである。ツールのサンドボックスを切っても、ふだんのホームは読めない | R-07 |
| I4 | ホストの役のプロセスが、すべて専用ユーザーで動いている。ふだんのユーザーで動くエージェントは、アプリの起動を断る | R-07、ADR 0014 |
| H1 | ホストを起動した直後（ログイン画面のまま、SSH だけ）の状態で、S1〜S3 が通る | 2026-11-16 の決定（4.4） |
| H2 | その状態で、ホストの役のプロセスが専用ユーザーで動いていて、I1〜I3 が成り立つ | 同上 |
| R1 | 手元で `.deb` を渡すと、Linux のホストの `inbox/` に届く。インストールの前に、そのホストで管理者の確認（`sudo`）が出る | R-05 |
| R2 | `.dmg` を渡すと、どの Mac に入れるかを尋ねる。Gatekeeper の確認が、省略されない | R-05 |

アプリが、ほかの PC のファイルをふつうのフォルダーとして開くこと（マウント）は、この案に入れていません。事故がいちばん起きやすいところで、方式も決まっていないためです（ADR 0013 の段階 3）。

この案は、コマンドで確かめる形です。使い手は開発者に限らないので、使う人の入口は、ランチャーの画面（M3）に置くことになります。画面からできることを条件に足すかどうかは、まだ決まっていません（10.2）。

**M5 は、今週は設計までなので、今週は、どの条件も通りません。** 今週の公開と LP には、書きません（milestones.md の「この決定を当てはめると」）。

## 2. 今週やること、やらないこと

| | 内容 |
|---|---|
| やる | 設計（この文書と、ADR 2本）。読むだけの調査 |
| 今週は始めない | 実装（手順 1〜4）。設計が受け入れられてから、試験用のフォルダーの中だけで始める（ねらい：ここだけは急がない） |
| やらない | ユーザーを作る。ホームの権限を変える。マウントする。ふだんのフォルダーを領域にする。インストールを実行する |

## 3. 何を、どこに置くか

詳しくは ADR 0013 の「何を、どこに置くか」にあります。

```text
 PC ごとに1つ：隔離領域（専用ユーザーのホーム。試すあいだは、試験用のフォルダー）
   .istesso-area   印。これがないフォルダーは、領域として扱わない
   files/          統合ストレージに出すファイル   ──▶ ほかの PC から、一覧と取得
   inbox/          ほかの端末から届いたもの       ◀── ほかの PC から、受け渡し
   それ以外         アプリの設定、エージェントの作業場所（ほかの PC からは見えない）

 ふだんのユーザーのホーム
   ふだんのファイル  仕組みは、自分からは読まない。人が名指ししたファイルだけを読む
```

- 1つのファイルの実体は、1台の PC にだけあります。写しを自動では作りません。だから、容量は足し算になり、止まっている PC のファイルは取得できません（R-06 のとおり）。
- Istesso 自身の設定（端末の鍵、ペアリングの一覧）は、いまと同じ場所に置きます。`files/` の下には置きません。

## 4. 何を、何から、どの仕組みで隔てるか

### 4.1 一覧

| 守るもの | 何から | Linux | macOS |
|---|---|---|---|
| ふだんのファイル | この仕組みで動かすアプリ、コーディングエージェント、ペアリングした端末 | OS の権限。専用ユーザーは、ふだんのホーム（750 のはず。4.3 で確かめる）に入れない | OS の権限。専用ユーザーを、グループ `staff` に入れずに作る（ふだんの側を、何も変えない。効くかどうかは未確認）。足りなければ、ふだんのホームを 700 にするかを、人に尋ねる（4.2） |
| 領域の中のファイル | ふだんのユーザーで動くアプリ | OS の権限。専用ユーザーのホームに、ほかのユーザーは入れない | 同じ |
| ほかの PC の領域 | ペアリングした端末 | ペアリングの鍵と、端末ごとの権限（[ADR 0006](adr/0006-pairing.md)、[ADR 0007](adr/0007-control-channel.md)）。一覧と中身には、新しい権限「ファイル」（ADR 0013） | 同じ |
| 領域の外のすべて | Istesso 自身のコードのまちがい | 領域の決まり（印、相対パスだけ、リンクをたどらない）。専用ユーザーで動くので、OS の権限でも止まる | 同じ |
| コーディングエージェントが読める範囲 | コーディングエージェント | OS の権限（専用ユーザー）と、ツールのサンドボックス（二重の柵） | 同じ |
| 端末の鍵と、ペアリングの一覧 | コーディングエージェント、アプリ | ツールのサンドボックスだけ。OS の権限では隔てない（ADR 0014 の「鍵に手が届くことへの備え」） | 同じ |

隔てないもの（同じ PC のネットワーク、誰でも読める場所、プロセスの一覧、資源の使い切り）は、ADR 0014 の「専用ユーザーでも、隔てられないもの」にあります。

### 4.2 Air で見たこと

読むだけの調査です（2026-11-16、macOS 26.5.1）。何も変えていません。

| 見たもの | 結果 |
|---|---|
| ふだんのホーム | 750。グループは `staff` |
| 書類、デスクトップ、ダウンロード、ライブラリ | 700 |
| ホームの直下に置いたファイルやフォルダー | 644 や 755 のものがある |
| 新しく作るファイルの既定（umask） | 022。誰でも読める権限で作られる |
| `/Users/Shared` | 誰でも書ける |
| FileVault | 入っている。自動ログインは使えない |
| ローカルのアカウント | 1つ。専用ユーザーは、まだない |

読み取れること：Mac では、専用ユーザーをふつうに作るだけでは足りません。ふつうに作ったユーザーは `staff` に入るはずなので、ふだんのホームの直下を一覧でき、誰でも読める権限のファイルは中身も読めます。

塞ぎ方は、2つあります。

| 塞ぎ方 | ふだんの側 | メモ |
|---|---|---|
| 専用ユーザーを、`staff` でないグループで作る | 何も変えない | macOS の、ユーザーを作る道具に、グループを指定する口がある（`sysadminctl -addUser` の `-GID`）。`staff` に入っていないユーザーで、アプリがふつうに動くかは、確かめていない |
| ふだんのホームを 700 にする | ホームの権限を変える | 本人のコマンド1つで、戻せる。ほかのユーザーにホームの中を見せる機能（ファイル共有の「パブリック」など）は、使えなくなることがある |

**上を先に試します。** M5 の決まりは「ふだんのファイルには触れない」なので、ふだんの側を変えない方法を先にします。足りないと分かったときだけ、下を人に尋ねます。今週は、どちらも行いません。

### 4.3 Ubuntu のホストで確かめること

どれも読むだけです。結果を記録するときは、ユーザー名とホスト名を伏せます。最後の行は、4.4 のためのものです。

```sh
stat -c '%a %U:%G' "$HOME"              # ホームの権限。750 か 700 なら、ほかのユーザーは読めない
id                                      # 入っているグループ
ls -l /dev/dri/                         # GPU の口を開けるグループ
loginctl show-user "$USER" -p Linger    # ログインなしでサービスを動かす設定
findmnt --real -o TARGET,FSTYPE,OPTIONS # ほかのディスクと、その権限の付け方
lsblk -o NAME,FSTYPE,MOUNTPOINT         # ディスクの暗号化（crypto_LUKS）が入っているか
```

### 4.4 誰も座っていないホスト

2026-11-16 に、次のことが決まりました。**ホストは、画面の前に誰も座っていない状態がふつうである。** 起こしたばかりで、ログイン画面のままのこともある。各流れの受け入れ条件に、「ホストを起動した直後（ログイン画面のまま、SSH だけ）の状態で動く」を足す。動かないものは、理由と、インストーラー（M9）が何を入れれば動くかを書く。

M5 のぶんは、条件 H1 と H2 です（1.）。専用ユーザーとストレージについて、分かっていることを並べます。どれも、実機では確かめていません。

| ログインの前に | Linux | macOS |
|---|---|---|
| 専用ユーザーのエージェントが動くか（一覧、合算、取得と受け渡し） | 動く見込み。専用ユーザーのサービスを、ログインなしで動かす設定（linger）を入れておく | デーモンとして登録すれば、動く見込み。動くときのユーザーは、専用ユーザー。セッションの中に登録したものは、ログインするまで動かない |
| 領域（専用ユーザーのホーム）を読めるか | 読める。ただし、ディスクの暗号化（LUKS）が入った PC は、起動のときに人がパスフレーズを入れるまで、OS が立ち上がらない | FileVault が解除されるまで、読めない。Apple シリコンの macOS 26 以降では、SSH で解除できる（[m4-plan.md](m4-plan.md) の 4.4） |
| 端末の鍵と、ペアリングの一覧を読めるか | 読める。いまは、所有者だけが読めるファイルにある。ログインのときに開くキーリングへ移すと、ログインするまで読めなくなる | 同じ。ログインのキーチェーンへ移すと、ログインするまで読めなくなる |
| 権限 | GPU の口、機器、音の優先度は、PC の前でログインしている人にだけ、自動で付く。専用ユーザーには、グループなどで与える。GPU は ADR 0014。機器は M7、音の優先度は M2 の流れが確かめる | 画面収録などの許可は、アプリごとに覚えられる。ログインの前後で変わらない見込み |
| 隔離して動かすアプリ | 動く見込み。専用ユーザーの仮想コンポジターの中で動くので、デスクトップへのログインは要らない（ADR 0009） | 動かない。アプリは、専用ユーザーがログインしているセッションの中でしか動かない（m4-plan.md の 4.4） |

この状態で動かないものと、その理由：

| 動かないもの | 理由 | インストーラー（M9）が入れるもの、伝えること |
|---|---|---|
| ディスクの暗号化（LUKS、FileVault）が解除される前の、すべて | OS か、領域のあるディスクが、まだ読めない。Istesso より手前の話である | 導入のときに、「起動のあと、人が解除するまで、このホストは止まって見える」と伝える。暗号化を切るかどうかは、使う人が決める。仕組みは、黙って切らない |
| Mac で、ログインの前の、アプリを使うもの | アプリは、ログインしているセッションの中でしか動かない | m4-plan.md の 4.4 の3つの形（自動ログイン、ログイン画面の中継、何もしない）から選ぶ |
| いまの状態（どの PC でも） | エージェントが、常駐のサービスになっていない。人が、SSH から手で起動している（[milestones.md](milestones.md) の M0） | Linux：専用ユーザー、GPU のグループ、linger、専用ユーザーのサービス。macOS：専用ユーザー、エージェントのデーモンの登録（root で1回）、セッションの中で動く部分の登録 |

統合ストレージから見ると、解除されていないホストは、止まっているホストと同じです。その PC にしかないファイルには、「取得できない」の印が付きます。

鍵の置き場所について：[ADR 0006](adr/0006-pairing.md) は、端末の秘密鍵を OS のキーチェーンへ移すことを、公開前の宿題にしています。ホストの役では、ログインなしで読める置き場所にする必要があります（ADR 0014）。

## 5. 権限の要るもの

一覧と理由は、ADR 0014 の「権限の要るものと、その理由」にあります。要点だけを書きます。

- 権限が要るのは、**導入のときの1回だけ**です。専用ユーザーを作る、GPU を使えるグループに入れる、ログインなしで動かす設定（Linux）。専用ユーザーを作る、エージェントをデーモンとして登録する、OS の許可を出す（macOS）。
- 動いているあいだには、要りません。root で動き続けるプログラムも、パスワードなしの `sudo` の規則も置きません。
- 専用ユーザーに、管理者の権限は与えません。
- 統合ストレージの段階 1 と 2（一覧、合算、名指しのコピー）には、権限が要りません。
- 権限の要るコマンドは、エージェントが提示し、人が内容を見てから実行します（M1 と同じ決まり）。
- 製品では、この導入を、手順書ではなく、インストーラー（M9）が行う形にします。使う人がするのは、管理者のパスワードを1回入れることだけです（背景：導入のかんたんさ）。
- 取り除くときに、専用ユーザーとそのホームを、仕組みは消しません。消すのは、人が自分で行います（ねらい：事故を避ける）。

## 6. 統合ストレージの形

段階と理由は、ADR 0013 にあります。コマンドの形は、次の案です。名前は、実装のときに決めます。

| コマンド（案） | 内容 | 段階 |
|---|---|---|
| `istesso area init <フォルダー>` | 空のフォルダーに印を付けて、領域にする | 手順 1 |
| `istesso storage` | 全部の PC の領域の、容量と空き。合計は、「いま使える分」と「止まっている分」に分ける | 1 |
| `istesso files list [パス]` | 全部の PC の `files/` を合わせた一覧。止まっている PC のファイルには、印が付く | 1 |
| `istesso files get <端末> <パス>` | ほかの PC のファイル1つを、手元の領域へ写す | 2 |
| `istesso files put <ファイル> <端末>` | 人が名指ししたファイル1つを、ほかの PC の `inbox/` へ送る | 2 |

## 7. 試験用のフォルダーで試す

試すあいだの決まりです。コードで守らせ、テストで破ろうとします。

1. **根は、必ず名指しする。** 既定の場所を持たない。環境変数（案：`ISTESSO_AREA`）か、引数で渡す。
2. **根として受け付けるのは、OS の一時フォルダーの下と、リポジトリの `target/` の下だけ。** ホーム、ホームの親、`/`、ほかのユーザーのホーム、外付けのディスクは、断る。根そのものがリンクのときも、断る。
3. **印のないフォルダーでは、動かない。** 印は、`istesso area init` が、空のフォルダーにだけ作る。空でなければ、断る。
4. **根の中に置くのは、テストが作ったファイルだけ。** ふだんのファイルの写しを入れない。
5. **読むのも書くのも、根の下だけ。** `..` と絶対パスを断る。リンクをたどらない。開いたあとで、根の下にあることを確かめ直す。試すあいだは、受け渡しで送るファイルも、根の下のものに限る。
6. **消さない。上書きしない。** 削除の操作を持たない。仕組みが消すのは、その受け渡しが自分で作った一時ファイルだけ。名前を付けるときは、同じ名前がすでにあれば失敗する方法を使う（確かめてから付ける、の2手にしない）。片づけは、試験用のフォルダーごと、人が行う。テストが作った一時フォルダーの片づけは、テストの道具に任せる。
7. **鍵とペアリングは、試験用のものを使う。** `ISTESSO_CONFIG_DIR` と `ISTESSO_CACHE_DIR` を、試験用のフォルダーに向ける。人のペアリングには、権限を足さない。
8. **根の外が変わっていないことを、確かめる。** テストでは、根の隣に「触ってはいけないフォルダー」を作り、前後でファイルの一覧とハッシュが同じことを見る。実機では、書き込みを試験用のフォルダーに限るサンドボックスの中で動かす（macOS の `sandbox-exec`、Linux の `bwrap`。どちらも権限は要らない見込み。未確認）。
9. **専用ユーザーで動いていないあいだは、「隔離は効いていない」と表示する。** 試験用のフォルダーは、決まりを確かめる場所で、隔離ではない。
10. **元のファイルは、読むだけで開く。** 写すだけで、動かさない。送ったあとも、元は残る。
11. **空きの下限を守る。** 受け取ると、ディスクの空きが下限を割るときは、断る。領域がディスクを使い切って、ふだんの側の保存が失敗する、という事故を防ぐ。
12. **書き終えてから、名前を付ける。** 一時ファイルをディスクに書き終えたこと（同期）を確かめてから、名前を変える。

決まり 2 は、専用ユーザーを作る段階（手順 5）で、「専用ユーザーのホーム」に置き換えます。

## 9. ダウンロードの振り分け（R-05）

今週は、考え方だけです。

- **入口は、人がファイルを渡す形にする。** ダウンロードのフォルダーを見張る形は、採らない。ふだんのフォルダーを、仕組みが自分から読むことになるため（決まり：ふだんのファイルには触れない）。
- 説明なしで使えるように、渡し方は「開く」にする。手元の OS で開けない種類のファイル（Mac での `.deb` や `.AppImage`）を開くアプリとして、Istesso を登録する。ダウンロードしたファイルを開くと、行き先を尋ねる画面が出る。コマンド（`istesso install <ファイル>`）も用意する。
- 行き先は、拡張子で決める。`.deb` と `.AppImage` は Linux のホストへ。`.dmg` と `.pkg` は、Mac を選ばせる。
- 運ぶのは、段階 2 の受け渡し。行き先の `inbox/` に届く。「インストール」の権限を持つ端末だけが、頼める（ADR 0006）。
- **入れるのは、行き先のホストで、確認を省略せずに行う。** 専用ユーザーは管理者の権限を持たないので、`.deb` と `.pkg` は、そのホストの管理者が内容を見てから入れる。`.AppImage` と、専用ユーザーの中に置くアプリは、root が要らない。
- 決まっていないこと：管理者の確認に、だれが、どこで応えるか。ホストの前には、ふつう誰もいない（4.4）ので、ホストの前で応える形は取れない。中継した窓で応えるか、SSH で応えるか、を決める。届いたファイルの署名を、どう確かめるか。
