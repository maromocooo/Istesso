# M7 の進め方：USB 機器と Stream Deck

M7 は、普段使っている USB 機器を、この仕組みの中でも使えるようにする段階です。この文書は、**今週（2026-11-16 の週）に通せるものと、通せないもの**を、[ADR 0004](adr/0004-usb-devices.md) に照らして示し、手順を書いたものです。

規約は先に [AGENTS.md](../AGENTS.md) を読んでください。決定は ADR 0004 と [ADR 0012](adr/0012-device-framework.md)（機器対応のフレームワーク）にあります。

この文書を書いた時点では、コードは 1 行も書いていません。2 台の実機を、何も変えずに調べただけです。手順の中のコマンドで「試していない」と書いたものは、そのとおり、試していません。

## 1. 今週通せるもの、通せないもの

今週の目標は、受け入れ条件を通すことです。通らなかったものは、公開の文面に書きません。ほかの流れは止めません。受け入れ条件は「6. 受け入れの確認」にあります。

| 受け入れの確認 | 今週 | 条件と理由 |
|---|---|---|
| A. 機器の一覧 | 通せる | 1 台の中は、権限も、足すパッケージも要らない。全台を合わせるには、共通のクレートにメッセージを 1 つ足す。先に本線（M1）と合わせる（手順 1、2） |
| B. Stream Deck：公式ソフトなしで制御できる。切り替えられる | Mac の分は、通せる見込み。Linux の分は、人の手が 1 回要る | Stream Deck Plus は、Mac につながっている。公式ソフトを止めるたびに、聞く（手順 3、5） |
| B. Stream Deck：公式ソフトのまま、ホットキーが Istesso の窓の中のアプリに届く | ホットキー 1 つ（⌘A）については、2026-11-17 に通った。ほかは、まだ確かめていない | 2026-11-16 は ⌘A のボタンが「a」になった。本線が窓の側を直したあと、人が実物のボタンで確かめた（手順 4）。ふだんの使い方になる道なので、B の中で、いちばん重い |
| B. Stream Deck：直接制御で、ボタン 1 つから、ほかの PC のアプリを開く | アプリマネージャー（M3）が `main` に入ってから | 通知を端末のあいだで運ぶところと、割り当ての設定ファイルまでは、先に作れる（手順 4） |
| C. 起動先の選び方 | 選ぶところまでは、通せる。窓が出るところは、まだ | 例のとおりに「Ubuntu で開いて、Mac に窓が出る」には、映像の経路（M1）とアプリマネージャー（M3）が `main` に要る（手順 6） |
| D. 声の回り込み | 基準の形だけ | 音を運ぶ形は、音の経路（M2）が `main` に入ってから（手順 7） |
| E. 2 つ目の機器を通して、口を固める | 通せない | 2 つ目の機器が、決まっていない。今週は、手順書とひな形の下書きまで |
| F. ホストの前に誰もいない状態で動く | Stream Deck の分は、手順 5 で確かめる。カメラは、まだ | カメラと音は、いまの設定では動かない見込み（ADR 0004 の「ホストの前に誰もいない状態」） |

- E が通るまで、「自分のエージェントで機器を足せる」とは、公開の文面に書かない。外からの機器のプルリクエストも、受け付けない（README に書いた）。
- USB/IP の付け替えは、今回の公開では作らない。手動の試しも、今週はしない。
- キーボードとマウス（入力の転送）は、映像の経路（M1）の中にある。オーディオ機器（音を運ぶ）は M2 である。M7 では、一覧に出すところまでを受け持つ。
- Windows は、今回の公開に含めない。機器とやり取りする関数は、Mac と Linux のぶんだけ作る。

見積もり（測った値ではない）：A と、B のうち Mac の分で、今週の大半を使います。C の選ぶところは 1〜2 日です。

### Stream Deck で、今週の終わりにできること

- **公式ソフトのまま使う場合：** 今までどおりに使える。ホットキーのボタンが Istesso の窓の中のアプリに届くことは、ホットキー 1 つ（⌘A）について、2026-11-17 に通った。ほかの形のホットキーは、まだ確かめていない（手順 4）。直接制御のあいだは、ふだんのプロファイルが使えないので、こちらが毎日の使い方になる。
- **直接制御に切り替えた場合：** Mac に挿したまま、ボタン、つまみ、タッチを Istesso が読み、ボタンに絵を出せる。ボタンでアプリを開けるのは、アプリマネージャー（M3）が `main` に入った日からで、今週に間に合うかは M3 しだいである。
- 直接制御に切り替えているあいだ、ふだんのプロファイルは使えない。その理解でよい。公式ソフトを止めているあいだは、プロファイルもプラグインも動かない。公式ソフトを起動し直すと、戻る。

## 3. 体制と決まり

映像（M1）、音（M2）、アプリマネージャー（M3）の作業と、同じ 2 台を使います。

- 作業は、`main` から切った `m7-usb-devices` ブランチの、専用の作業ツリーで行う。ほかの流れの作業ツリーには触らない。
- 映像の計測が走っているあいだは、2 台の上で何も動かさない。確かめ方は、AGENTS.md の「計測の合図」に従う（`m1-latency` ブランチにあり、このブランチには、まだ入っていない）。
- ホストで使う場所は、`~/.cache/istesso-m7-wip/` だけ。いまは、書式を確かめた udev の決まりのファイルが 1 つ置いてある。
- 何も入れない。`sudo` は使わない。パッケージを展開して、そこから動かすこともしない。足りないものは、「5. 人に頼むこと」に書く。
- **Stream Deck は、人が毎日使っている道具である。** 公式ソフトは、その都度、聞いてから止める。試したあとは、公式ソフトを起動し直して、元どおりに使えることを確かめる。
- 機器の製造番号を、記録、試験、文書、ログに入れない。
- 共通のクレート（`istesso-proto`、`istesso-link`）を変えるときは、先に本線（M1）と合わせる。`istesso-link` にメッセージを足すときは、[ADR 0007](adr/0007-control-channel.md) を先に直す（AGENTS.md）。

## 4. 手順

### 手順 0：調べる（済み）

「2. 環境」のとおりです。

### 手順 1：1 台の中の一覧

`istesso devices list` で、その PC につながっている機器を、種類と一緒に出します。

- Linux は sysfs を読む。Mac は `system_profiler` の出力を読む（`istesso doctor` と同じ作り）。読んだものを解析する部分は、OS に触らない関数にして、テストを付ける。
- 種類に振り分ける：キーボードとマウス（転送）、オーディオ（音を運ぶ）、カメラ、アダプターのある機器（直接制御）、その他。ハブは出さない。
- 「その他」の機器には、「この PC のアプリから使えます」と出す。付け替えは、今回は作らない。
- 1 台の機器が、2 つの種類を持つことがある（カメラとマイク）。
- 内蔵のマイクとカメラも出す。外付けか内蔵かを区別する。会議アプリを開く PC を選ぶのに使う。仮想のカメラは、数えない。
- アダプターのある機器には、「作者が確認済み」か「投稿者が確認」かを出す。
- 製造番号は、表示にもログにも出さない。同じ型の機器が 2 台あるときの区別には、挿してある場所を使う。

| 要るもの | 内容 |
|---|---|
| 機材 | 2 台の実機 |
| 権限 | なし |
| パッケージ | なし |
| 人がやること | なし |

確認：

1. Ubuntu と Mac で実行して、OS の道具（`lsusb`、`system_profiler`）と同じ機器が出る。
2. Stream Deck Plus が「直接制御」、カメラが「カメラ」と「オーディオ」、キーボードとマウスが「転送」と出る。
3. 出力に、製造番号が入っていない。
4. ホストがログイン画面のままでも、SSH から同じ一覧が出る。

### 手順 2：全台を合わせた一覧

`istesso devices list --all` で、ペアリング済みの全端末の機器を、1 つの一覧にします。機器ごとに、どの PC に挿してあるかが分かります。

- `istesso-proto` に機器の型を、`istesso-link` に問い合わせを 1 つ足す。暗号の手順は変えない。
- 一覧を見るのは「閲覧」の権限、機器を切り替えるのは「USB」の権限とする案で始める（R-13）。
- 応答しない端末の機器には、アプリの一覧と同じ `!` を付ける。

| 要るもの | 内容 |
|---|---|
| 機材 | 2 台の実機 |
| 権限 | なし |
| パッケージ | なし |
| 人がやること | なし。本線（M1）との調整は、流れのあいだで行う |

確認：

1. どちらの PC からでも、両方の機器が 1 つの一覧で見える。
2. 片方のエージェントを止めると、その PC の機器に `!` が付く。
3. KVM 切替器ごしの機器が、両方の PC の行に出ることを記録する。まとめるかどうかは、それを見て決める。

### 手順 3：フレームワークの最初の形と、最初のアダプター（Stream Deck Plus、Mac）

ADR 0012 のとおりに、いちばん小さいフレームワークを作り、その上に、最初のアダプターとして Stream Deck Plus を載せます。

- 第一の情報源は、Elgato が公開している HID の仕様。足りないところだけ、components.md の「取り込める」にある実装を参考にする。写さない。
- 口は HID だけ。通知は、ボタン（8 個）、つまみ（4 個。回す、押す）、タッチ、絵を出す、明るさ、元に戻す。
- アダプターは、1 つのディレクトリに収める。使うレポートの ID と命令のバイト、ほしい絵の形式、公式ソフト、この機器を使うアプリを、先に名乗る。画像を扱うクレートを持たない。絵の変換は、フレームワークが行う。
- フレームワークは、名乗っていないレポートと命令への書き込みを通さない。
- 記録を取る道具と、再生の試験。
- 公式ソフトが動いているあいだは、機器に触らない。

| 要るもの | 内容 |
|---|---|
| 機材 | Stream Deck Plus（Mac につながっている） |
| 権限 | 分からない。macOS が「入力監視」の許可を求めるかもしれない。求められたら、理由を ADR 0004 に足す |
| パッケージ | OS に入れるものはない。依存クレートを足す（HID と話す部品、絵の形式を変える部品。どちらも本体の側）。足したら `cargo deny check licenses` を通し、components.md に書く |
| 人がやること | 公式ソフトを止めてよいかを、聞かれるたびに答える。macOS のダイアログが出たら、応える |

確認：

1. 公式ソフトを止めた状態で、8 個のボタン、4 個のつまみ、タッチが、通知として出る。
2. ボタン 1 つに絵を出せる。明るさを変えられる。
3. 記録を取り、機器なしで再生する試験が、Mac、Ubuntu、CI で通る。記録に、製造番号が入っていない。
4. **Stream Deck のための特別なコードが、本体にない。** アダプターのディレクトリを消しても、本体のビルドとテストが通る。足りないものが出たら、口を直す。
5. 名乗っていないレポートと命令への書き込みが、止まる（試験で確かめる）。
6. 公式ソフトを起動し直すと、元どおりに使える。

### 手順 4：Stream Deck の 2 つの使い道

**公式ソフトのまま：ホットキーが、Istesso の窓の中のアプリに届く。** M7 の側で作るものは、ありません。直接制御のあいだは、ふだんのプロファイルが使えないので、公式ソフトのまま使うこの道が、毎日の使い方になります。直接制御の確認より、こちらを重く見ます。

- **2026-11-16 に、人が手で試して、通らなかった。** 公式ソフトで、ホットキー ⌘A のボタンを作り、Istesso の窓を前にして押した。テキストエディターに「a」が打ち込まれ、全選択にならなかった。Mac のふつうのアプリでは、同じボタンで全選択になる。
- 原因は、本線の窓（`m1-latency` ブランチ）の側にある。窓は、修飾キーの状態を、修飾キーを押した知らせだけから追っている。こういうホットキーは、修飾キーの知らせなしで、キーにフラグだけが付いて届く。
- 本線が、窓の側を直した（`m1-latency` ブランチ）。キーのフラグが名指ししている修飾キーが、押されていないときは、そのキーのあいだだけ、押されたものとして扱う。
- **2026-11-17 に、ホットキー 1 つ（⌘A）について、通った。** 人が、実物の Stream Deck のボタンを、Istesso の窓を前にして押した。全選択になった。
- まだ確かめていないもの：ほかの修飾キーと、その組み合わせ。いくつものキーを続けて送るボタン。押し続けるキー。

**直接制御：ボタン 1 つから、ほかの PC のアプリを開く。**

- 通知（ボタン、つまみ、タッチ、絵）を、制御チャンネルの上で運ぶ。相手が USB の権限を持つときだけ運ぶ。運ぶのは、フレームワークの受け持ちである。
- 割り当ては、設定ファイルに書く（どのボタンが、どのアプリか）。ボタンには、そのアプリの絵を出す。
- アプリを開くところは、アプリマネージャー（M3）の `istesso open` を使う。M3 が `main` に入ってから、つなぐ。

| 要るもの | 内容 |
|---|---|
| 機材 | 2 台の実機と、Stream Deck Plus |
| 権限 | なし |
| パッケージ | なし |
| 人がやること | まだ確かめていない形のホットキーを、試す（ふだん使っているボタンで足りる）。ADR 0007 にメッセージを足すので、本線（M1）と合わせる |

確認：

1. 公式ソフトを動かしたまま、ホットキーのボタンを押すと、Istesso の窓の中のアプリが、そのキーを受け取る。⌘A のボタンで、全選択になる（2026-11-16 は「a」になった。直したあと、2026-11-17 に通った）。まだ確かめていないもの：ほかの修飾キーと、その組み合わせ。いくつものキーを続けて送るボタン。押し続けるキー。
2. Mac に挿した Stream Deck のボタンを押すと、Ubuntu の側で、その通知が見える。USB の権限を持たない端末には、届かない。
3. 直接制御で、ボタンに、割り当てたアプリの絵が出る。押すと、ほかの PC のアプリが開く（M3 が `main` に入ってから）。

### 手順 5：Stream Deck を Linux で

挿し替えは、手順 3 の確認が通ったあとに、1 回だけ頼みます。

- udev の決まりを入れてもらう（「5. 人に頼むこと」の 2）。決まりそのものは、ログインし直しも再起動も要らない。ホストを再起動する回が先に来るなら、そのときのほかの `sudo` の依頼と、まとめて頼む。
- 人が、Stream Deck Plus を Ubuntu のホストに挿し替える。
- 手順 3 と同じアダプターを、Ubuntu で動かす。
- **ホストがログイン画面のままの状態でも、確かめる。** 再起動のすぐあと、人がデスクトップにログインする前が、その状態である。そのためだけに、ログアウトや再起動は頼まない。再起動の回に、アダプターがまだなければ、機器の口を開けるかどうかだけを先に確かめ、アダプターでの確認は「まだ」と記録する。

udev の決まりは、最初から、グループに与える形にしました。`uaccess` は、その PC の前でログインしている人にしか効きません。ログイン画面のままでは開けないことが、仕組みから分かっています。頼むのを 1 回で済ませるためです。グループは、ホストのユーザーがもう入っている `plugdev` を使います。

この `sudo` の 3 行は、使う人に求めてよい手間ではありません。今週、インストーラーがないあいだだけの手間です。インストーラー（M9）の .deb が、同じ決まりを一緒に入れるようにします。

| 要るもの | 内容 |
|---|---|
| 機材 | Stream Deck Plus を、Ubuntu のホストに挿す |
| 権限 | 導入のときに 1 回、root（udev の決まり）。動かすときは要らない |
| パッケージ | HID と話す部品が求めるもの。`libudev-dev` は、もう入っている |
| 人がやること | `sudo` のコマンド 3 行を 1 回。挿し替え。ホストを再起動する回があれば、Stream Deck Plus をホストに挿しておく。試したあと、Mac に戻す |

確認：

1. root でないユーザーで、手順 3 の確認 1〜3 が、Ubuntu でも通る。
2. **ホストがログイン画面のままの状態で、SSH から動かしたエージェントが、機器を開ける。**
3. udev の決まりを外すと、機器を開けなくなる（権限が要る理由を確かめる）。

### 手順 6：起動先の選び方

`istesso-catalog` が起動先を選ぶところに、機器の条件を足します。決まりは、ADR 0004 の決定の 6〜8 です。

- いまの順（手元 → 起きているホスト → 負荷の低いホスト）の前に、機器の条件を見る。
- 分かっているときだけ、寄せる。分からないときは、今までどおり手元で開く。
- 項目ごとに、どの PC で開くかと、その理由を出す。使う人が、指定し直せる。
- 会議のページを、1 つの項目として登録できる。開くと、カメラのある PC のブラウザーで、そのページが開く。ブラウザーそのものは、寄せない。
- マイクとカメラのある PC が 2 台以上あるとき、家では、外付けを内蔵より優先する。出先では、手元の端末を使う。
- 選ばれた PC が止まっているときは、「！」と、起こす操作を出す。ほかの PC では、自動では開かない。条件を満たす PC がほかにあれば、「この PC で開く」を出す。
- 今回作るのは、項目ごとの理由と直し方、会議のページの項目、分かっていること（機器の説明、会議アプリの表、会議のための種類）まで。アプリが機器を実際に使ったのを見つけて反映する機能は、今回は作らない。

| 要るもの | 内容 |
|---|---|
| 機材 | 選び方の中身は、どの PC でも作って試せる。確かめるのは 2 台の実機 |
| 権限 | なし |
| パッケージ | なし |
| 人がやること | なし |

確認（ADR 0004 の 2 つの例を、そのまま試験にする）：

1. 外付けのマイクとカメラが Ubuntu に挿してあるとき、会議アプリの起動先に Ubuntu が選ばれる。理由が「カメラを使うため」と出る。
2. 外付けのマイクとカメラがどこにも挿していないとき、会議アプリの起動先に、手元の Mac が選ばれる。
3. 出先（VPN 経由）では、手元の Mac が選ばれる。
4. 機器を使うと分かっていないアプリは、今までどおり、手元が選ばれる。ブラウザーも、手元が選ばれる。
5. 登録した会議のページの項目は、Ubuntu が選ばれる。
6. 使う人が指定し直すと、その PC が選ばれる。
7. 選ばれた PC が止まっているときは、`!` が付き、ほかの PC は選ばれない。

窓が実際に開くところ（`istesso open`）は、M3 の流れが `main` に入ってから、M3 の側でつなぎます。ホストがログイン画面のままの状態で、会議アプリがカメラを開けるかは、そのときに確かめます。

### 手順 7：声の回り込みの確認

ADR 0004 の「確認項目」の、3 つの形のうち、今週できるのは 1 つ目（基準）だけです。

- **形 1（今週、人ができる）：** Ubuntu のホストで会議を開き、ホストのスピーカーで聞く。相手に、相手自身の声が返って聞こえるかを聞く。1 人でも確かめられる：別の回線につないだスマートフォンから、イヤホンで同じ会議に入り、スマートフォンに向かって話して、自分の声が遅れて返ってくるかを聞く。
- **形 2、3（今週はできない）：** 音を運ぶ経路（M2）と、窓を映す経路（M1）が、`main` に入ってから。

| 要るもの | 内容 |
|---|---|
| 機材 | ホストのスピーカー、カメラのマイク、会議の相手（またはスマートフォン） |
| 権限 | なし |
| パッケージ | なし |
| 人がやること | 会議に入って、聞く。10 分ほど |

確認：結果を `docs/measurements/` に書く（日付、どの形か、会議のアプリ、スピーカーの音量、聞こえたか）。形 2 と 3 の結果と比べるための基準になります。

## 5. 人に頼むこと

質問と、人の手が要る作業を、1 つの一覧にします。決めてほしいことは、いまはありません。

1. **（手順 3）公式ソフトを止めてよいかを、聞かれるたびに答える。** 止めているあいだ、普段のボタンとプロファイルは使えません。
2. **（手順 5。手順 3 が通ったあとに、1 回。ホストを再起動する回が先に来るなら、そのときのほかの `sudo` の依頼とまとめて）次を実行する。** インストーラーができるまでの、1 回だけの手間です。書式は `udevadm verify` で確かめました。入れて動かすことは、試していません。

   ```sh
   printf '%s\n' 'KERNEL=="hidraw*", SUBSYSTEM=="hidraw", ATTRS{idVendor}=="0fd9", MODE="0660", GROUP="plugdev", TAG+="uaccess"' | sudo tee /etc/udev/rules.d/70-istesso-streamdeck.rules
   sudo udevadm control --reload-rules
   sudo udevadm trigger --subsystem-match=hidraw
   ```

   - 何が変わるか：Elgato の機器（ID が `0fd9`）と直接話す口を、グループ `plugdev` の人と、その PC の前でログインしている人が、開けるようになる。ほかの機器の権限は、変わらない。ホストのユーザーは、もう `plugdev` に入っているので、ユーザーの設定は変えない。
   - ログインし直しも、再起動も、要らない。
   - 元に戻すには：`sudo rm /etc/udev/rules.d/70-istesso-streamdeck.rules` のあと、2 行目と 3 行目をもう 1 度実行する。
3. **（手順 5。手順 3 が通ったあとに、1 回）Stream Deck Plus を、Ubuntu のホストに挿し替える。** ログイン画面のままの状態での確認は、ホストを再起動する回に行います。その回には、挿したままにしておいてもらいます。そのためだけに、ログアウトや再起動は頼みません。
4. **（手順 4）まだ確かめていない形のホットキーを、試す。** Istesso の窓を前に出した状態で、ふだん使っているボタンを押してもらえば足ります。確かめたいのは、ほかの修飾キーと、その組み合わせ。いくつものキーを続けて送るボタン。押し続けるキーです。⌘A は、2026-11-17 に通りました。
5. **（手順 7）会議に入って、声が返るかを聞く。** 10 分ほどです。

## 6. 受け入れの確認（2026-11-16 に採用）

採用されたのは、最初の案の 5 つ（一覧、Stream Deck、起動先、回り込み、口を固める）と、あとから足された 3 つ（ホットキー、ボタンからアプリを開く、ホストの前に誰もいない状態）です。付け替えの確認は、今回は作らないので外しました。文面は、そのあとの決定に合わせてあります。

- **A. 機器の一覧。** どの PC からでも、全 PC の機器が、1 つの一覧で見える。機器ごとに、どの PC に挿してあるか、種類、使い方（転送、直接制御、音を運ぶ、その PC のアプリから使う）が分かる。
- **B. Stream Deck。**
  - Stream Deck Plus を、公式ソフトなしで、この仕組みが制御できる。公式ソフトと切り替えられる。Mac と Linux の両方で。
  - 公式ソフトを動かしたまま、ホットキーのボタンが、Istesso の窓の中のアプリに届く。ホットキー 1 つ（⌘A）については、2026-11-17 に通った（人が、実物のボタンで確かめた）。ほかの修飾キーと、その組み合わせ。いくつものキーを続けて送るボタン。押し続けるキーは、まだ確かめていない。B の中で、いちばん重く見る。
  - 直接制御のモードで、ボタン 1 つから、ほかの PC のアプリを開ける。ボタンには、そのアプリの絵が出る（M3 が `main` に入ってから）。
- **C. 起動先の選び方。** 機器を使うアプリが、その機器を使えるホストで開く。会議アプリが、マイクとカメラのある PC で開く。ADR 0004 の 2 つの例が、そのとおりになる。
- **D. 声の回り込み。** スピーカーで聞く会議で、声が回り込まない（3 つの形）。
- **E. 口を固める。** 種類の違う 2 つ目の機器を通して、口を固める。
- **F. ホストの前に誰もいない状態。** A〜C が、ホストを起動した直後（ログイン画面のまま、SSH だけ）の状態で動く。動かないものは、理由と、インストーラー（M9）で何を入れれば動くかを書く。

この流れで足したい確認（提案）：

- B に、「Stream Deck のための特別なコードが、本体にない（アダプターのディレクトリを消しても、本体のビルドとテストが通る）」。ADR 0012 の決定を、検査にしたものである。
- E に、「手順書とひな形だけを渡されたエージェントが、2 つ目の機器のアダプターを書ける。そのプルリクエストは、本体を触らない」。想定する投稿の流れを、1 度通すためである。

## 7. 見つけたこと

- **Stream Deck の参考実装の LICENSE は、MIT ではない。** プロジェクトは「MIT」と名乗っているが、LICENSE の本文は、HPND（Historical Permission Notice and Disclaimer）の系統の文面である。SPDX の文面と比べると、いちばん近いのは HPND-sell-variant で、語の並びの一致は 0.85 だった。違いは、「sell」の語がないことなど。条件は、著作権表示と許諾の文を残すことと、作者の名前を宣伝に使わないことで、コピーレフトではない。components.md を直した。
- **jiegec/usbip は、libusb（LGPL-2.1）を使う。** 0.9.0 は、`rusb` と `nusb` の 2 つのクレートに依存している。`rusb` は libusb を呼ぶ。クレートの表示は MIT なので、`cargo deny` はこれに気づかない。付け替えを作るときに要る注意として、components.md に書いた。
- **レポートの ID だけでは、絵を書くことと、それ以外を分けられない。** 命令のバイトも名乗らせることになった（ADR 0012 の決定の 7）。
- **ホストのカメラと音は、持ち主がデスクトップにログインしているから開けている。** ADR 0004 の「ホストの前に誰もいない状態」に書いた。音のほうは、音の流れ（M2）に伝える。
