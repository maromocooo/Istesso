# M3 の確認：実機 2 台で、アプリを起動して、離れて、戻って、閉じる

アプリマネージャーの最初の一切れ（[ADR 0010](adr/0010-session-start.md)）を、実機 2 台で確かめる手順です。映像の経路はまだ入っていないので、映像を運ばない偽物（`scripts/` のランナー、ビューアー、アプリ）を使います。`scripts/m3-trial.sh` が、下の手順をそのまま実行して、項目ごとに `ok` か `FAIL` を表示します。

## 何を確かめるか

| 部分 | 確かめること |
|---|---|
| `leave` | 起動する。Ctrl-C で離れても、アプリはホストで動き続ける。`istesso sessions` に出る。同じコマンドで戻れる。窓を閉じようとすると、アプリに頼みが届いて、アプリが終わる |
| `unsaved` | 保存するものがあるアプリは、閉じるよう頼まれても、尋ねたまま残る。窓も残る。`istesso sessions stop` でも残る。`--force` で終わる |
| `lost` | クライアントが何も言わずにいなくなる。15 秒で絵が止まり、アプリは動き続ける。約 20 秒かかる |
| `host` | ホストにいる人が、`istesso sessions --local` で、ほかの端末が始めたアプリを見る。閉じるよう頼む。力ずくで終わらせる。尋ねる先のソケットは、本人しか入れない場所にある |
| `slots` | 圧縮の枠を 1 つにした試験用のエージェントで、窓を 2 つ開く。2 つめは断られずに開き、1 つめの映像が止まる（アプリは動いている）。一覧に、止まっている窓が出る。1 つめに向くと、映像が戻り、2 つめが止まる |
| `nobody` | ホストの前にだれもいない状態の代わり：ランタイムディレクトリも、画面も、セッションバスもない環境で、試験用のエージェントを起動する。アプリが起動する。あとからログインした人が `istesso sessions --local` で尋ねても、エージェントが見つかる |
| `broken` | ホストのランナーが途中で落ちる。コマンドが、理由を表示してエラーで終わる |

確かめないこと：

- ペアリングの解除。実機のペアリングの一覧を書き換えることになるので、ここでは行いません。自動のテスト（`cargo test -p istesso-agent`）が、自前の一覧で確かめています：解除すると接続が切れる、つなぎ直せない、アプリは残る、ほかの端末から使える。
- ホストを起動し直した直後の状態そのもの。`nobody` は、環境を空にして代えています。エージェントが自動で起動すること、ログインが 1 つもない状態でのランタイムディレクトリは、人と一緒に確かめる項目です（ADR 0010 の 14）。

## 触るもの、触らないもの

- ホストでは、**試験用のエージェント**を別のポート（既定は 47820）で動かします。発見（mDNS）は止め、キャッシュとソケットは専用の場所に置きます（`ISTESSO_CACHE_DIR`、`ISTESSO_RUNTIME_DIR`）。ふだんのエージェント（47801）、端末の鍵、ペアリングの一覧は、読むだけで、変えません。
- ホストは Linux を前提にしています（`nobody` が `/proc` を読みます）。
- 試験用のアプリ 2 つ（「Istesso M3 Saved」と「Istesso M3 Unsaved」）は、試験用のエージェントの一覧にだけ出ます。置き場所を `XDG_DATA_HOME` で専用のディレクトリに向けるので、利用者のメニューには出ません。
- クライアントでは、キャッシュだけを専用の場所（`M3_WORK` の下）に置きます。ふだんのキャッシュは変えません。
- 遅延の計測をしているときは、動かさないでください（[AGENTS.md](../AGENTS.md)）。全部で 1 分半ほどです。

## 準備

1. 2 台がペアリング済みで、クライアントからホストへ SSH で入れること。
2. クライアントで、このブランチをビルドする。

   ```sh
   cargo build -p istesso-cli
   ```

3. ホストに、同じブランチを置いてビルドする。場所は、既定では `~/.cache/istesso-m3-wip/src` です（`M3_HOST_DIR` で変えられます）。

   ```sh
   rsync -a --exclude target --exclude .git ./ <ホストの SSH の宛先>:.cache/istesso-m3-wip/src/
   ssh <ホストの SSH の宛先> 'cd ~/.cache/istesso-m3-wip/src && cargo build -p istesso-cli'
   ```

## 実行

クライアントで、リポジトリの上から実行します。

```sh
M3_SSH=<ホストの SSH の宛先> M3_ADDRESS=<ホストのアドレス> scripts/m3-trial.sh
```

- `M3_ADDRESS` は、クライアントからホストへ届くアドレスです。IPv6 は角かっこに入れ、リンクローカルのアドレスには、クライアント側のゾーンを数字で付けます（例：`[fe80::1%12]`。数字は、macOS なら `ifconfig <インターフェース>` の `scopeid`、Linux なら `ip -o link` の先頭の番号）。
- 部分を選ぶには、名前を並べます：`scripts/m3-trial.sh leave unsaved`。何も書かなければ、7 つ全部です。
- はじめに、どの経路を使ったかを表示します（アドレスの種類と、パケットが出ていくインターフェース）。

  ```text
    path  IPv4, leaving this machine through en5 (USB 10/100/1000 LAN)
  ```

- 終わりに、失敗した項目の数を表示します。0 なら、終了コードも 0 です。

## 読み方

- それぞれのコマンドが表示したものは、`M3_WORK`（既定は一時ディレクトリの `istesso-m3-trial`）に残ります。`leave-1.txt` は 1 回目の `istesso open`、`leave-2.txt` は戻ったときのもの、などです。
- ホスト側の記録は、`<M3_HOST_DIR>/agent.log`（試験用のエージェントと、偽物のランナーの言ったこと）と、`<M3_HOST_DIR>/notes/`（偽物のアプリが書いた、自分に起きたこと）にあります。
- `host-list.txt` と `nobody-list.txt` には、始めた端末の名前が入ります。記録や報告に写すときは、消してください。
- IPv6 のリンクローカルのアドレスを指しても、あとの接続が IPv4 になることがあります。クライアントが、ホストの申告したほかのアドレスを覚えて、同時に試すためです。ホストの `agent.log` の `for <アドレス>` を見ると、接続ごとの経路が分かります。

## 偽物がしていること

| 偽物 | していること |
|---|---|
| ランナー（`fake-session-runner.sh`） | `start` に `ready` と答え、`attach` に `attached` と答える。`close` を受けたら、`application` の行で知ったアプリのプロセスに、シグナル（USR1）を送る。標準入力が閉じたら終わる。映像は作らない。入力のソケットも作らない |
| ビューアー（`fake-viewer.sh`） | `offer` を出し、`show` を受けたら `shown` と言う。`ISTESSO_FAKE_VIEWER_CLOSE_AFTER=<秒>` を付けると、その秒数のあとで `close` と言う（人が窓を閉じようとした、の代わり）。窓は出さない |
| アプリ（`fake-application.sh`） | USR1 を「閉じてほしい」と受け取る。ふつうは終わる。`--unsaved` を付けると、尋ねたことにして残る |

本物のランナーは、シグナルではなく、コンポジターから窓に「閉じてほしい」と伝えます。そのための追加は、映像の側の作業です。
