## 読み方で読む

- **入力**：ON の 2 回（1.37、1.34）は、OFF の 2 回（1.34〜1.40）の中。
- **フレームが届く**：ON2（0.15）は、OFF（0.16、0.16）より 0.01 低い。表の最後の桁の話で、読まない。
- **復号**：ON1（3.20）は、OFF の高いほう（3.18）より 0.02 高い。ON2（3.17）は、中。全部のフレームで数えても、同じ並び（ON1 が、OFF の高いほうより 0.02 高い。ON2 は、中）。
- **出口から、描くまで**：ON1（0.46）は、OFF の高いほうより 0.01 高い。ON2（0.44）は、中。
- **描いてから、映るまで**：ON1 は中、ON2（17.89）は、OFF の高いほうより 0.09 高い。これは、画面の更新を待つ時間で、切り替えがかかる所ではない。
- **クライアントの側の合計**：ON1（5.23）は、OFF（5.15、5.17）より 0.06 高い。ON2（5.14）は、0.01 低い。
- **全部**：ON の 2 回は、OFF の 2 回の中。

OFF の 2 回の外に出た値は、どれも、その区間の揺れ（OFF の 2 回の差）より小さくしか、出ていない。出た向きは、「遅い」ほうで、2 回のうち 1 回だけである。**切り替えを入れて速くなった区間は、ない。遅くなった、とも言えない。効き目は、見えなかった。**

区間の平均は、数える誤差（0.002 ms）ではなく、回ごとの条件の動き（OFF の 2 回で、復号が 0.06 ms）で揺れている。だから、この回で見つけられる効き目は、復号で 0.06 ms、入力で 0.06 ms、描くまでで 0.03 ms より大きいものだけである。

## 言えること、言えないこと

- **言えること**：わりあい静かな Mac（負荷 2.5〜3.2、映像の解析は止めてある）では、5 つ全部を入れても、クライアントの中の区間は、0.06 ms より大きくは、変わらない。リアルタイムの扱いは、困ったことを起こさなかった。
- **言えないこと**：
  - 切り替え 1 つずつの効き目。測ったのは、「5 つ全部」という 1 つの組み合わせだけである。`picture-qos` だけの形は、この組み合わせの中に、ない（リアルタイムが、置き換える）。
  - **負荷のある Mac での効き目。** 優先度は、ほかの仕事と取り合うときに効く。静かな Mac では、もともと待たされないので、差が出ない、ということがありうる。本線は、今日の午後、負荷のあるときに、得を見ている（別の計測）。この回は、それを、確かめても、打ち消してもいない。
  - 0.06 ms より小さい効き目。全体の差（標準誤差 0.23 ms）。
- **それを確かめる回**：同じ OFF、ON、OFF、ON を、(1) 決まった負荷をかけた Mac（たとえば、映像の解析を動かしたまま。または、ふつうの優先度の計算を、コアの数だけ走らせる）と、(2) ほかに何も動いていない Mac で、それぞれ行う。読むのは、全部のフレームで数えた区間（復号、描くまで）と、入力の区間。負荷のある回で ON の 2 回が OFF の 2 回の外（速いほう）に出て、静かな回で出なければ、「負荷のあるときにだけ効く」と言える。切り替え 1 つずつは、そのあとで、効いた条件の中で分ける（`keys-qos` と `input-qos` は入力の区間、`picture-qos` か `picture-realtime` は復号と描くまで）。

## 復号の時間が、最初の比べと違うこと

- **見えたこと**：この回の復号は 3.13〜3.20 ms。同じ夜の、最初の比べ（19:21〜19:38）では 3.41〜3.48 ms だった。0.3 ms 短い。最初の比べでは、試作（3.43、3.44）と自前のクライアント（3.41、3.48）が、同じだった。「出口から、描くまで」（0.42〜0.46 と 0.51〜0.58）と、入力の区間（1.34〜1.40 と 1.42〜1.47）も、同じ向きに、短い。ホストの側の区間（エンコード 3.96〜4.08 と 3.93〜3.97）は、変わっていない。
- **違っていた条件**：最初の比べのあいだ、システムのデーモン（映像の解析）が、1 コアを使い続けていた（負荷 4.0〜4.7）。この回は、止めてあった（負荷 2.5〜3.2）。
- **考えたこと**（確かめていない）：違いは、プログラムではなく、Mac の状態にある。同じプログラムで 0.3 ms 違い、違うプログラムで同じだったからである。クライアントの側の 3 つの区間が、そろって短いので、復号器だけの話ではなく、そのデーモンと、CPU か、復号器の周りの何かを、取り合っていた、と読める。**もしそうなら、切り替え（優先度）が効くのは、まさに、その取り合いのあるときである。** 上の「確かめる回」の (1) が、これも確かめる。

## 同じ時間に動いていたもの
