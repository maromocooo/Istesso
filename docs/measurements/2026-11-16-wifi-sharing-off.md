# Mac の共有の機能を設定で切って AWDL を止める（Wi-Fi で使うときの参考値）

- 日付：2026-11-16
- コミット：この記録と同じコミット
- 目的：Mac の AWDL は、Mac を有線にして解決する。アダプターが届くまでのつなぎとして、共有の機能を設定で切るだけで AWDL が止まったままになるかを確かめる。あわせて、Wi-Fi で使うときの参考値を 1 回取る。
- 結論：**止まったままにはなりません。** この Mac が自分から AWDL を使うことはなくなりますが、近くの機器に求められると戻ります。52 分のあいだに 2 回、それぞれ 20 秒あまりでした。

## 条件

| 項目 | 値 |
|---|---|
| ホスト | Ubuntu 24.04、RTX 4090。有線（2.5 Gbps） |
| クライアント | MacBook Air（M4）、macOS 26.5.1。Wi-Fi（6 GHz 帯、802.11ax） |
| 接続 | ホストは有線、Mac は Wi-Fi。計測は有線側のアドレスに向け、ケーブルを通っていることを前後に確かめた |
| 解像度とフレームレート | 経路の計測は映像なし。既製の部品の 1 本は 1720×720、85 fps |
| クライアントのディスプレイ | 外部（3440×1440、84.96 Hz） |
| コーデックとビットレート、エンコーダーの設定、経路 | [最初の 1 本の記録](2026-11-16-step3-first-path.md)と同じ |

## 切ったもの

11:31 に、次の 4 つを切りました。`sudo` は要りません。

| 機能 | 切り方 | 元の値 |
|---|---|---|
| AirDrop で見つけてもらうこと | `defaults write com.apple.sharingd DiscoverableMode -string "Off"` | `Everyone` |
| Handoff | `defaults -currentHost write com.apple.coreservices.useractivityd ActivityAdvertisingAllowed -bool false` と、同じドメインの `ActivityReceivingAllowed -bool false` | どちらも未設定 |
| AirPlay レシーバー | `defaults -currentHost write com.apple.controlcenter AirplayRecieverEnabled -bool false` | 未設定 |
| ユニバーサルコントロール | `defaults write com.apple.universalcontrol Disable -bool true` | 未設定 |

そのあと `killall sharingd useractivityd UniversalControl AirPlayXPCHelper` で、設定を読み直させました。

元に戻すには、1 行目に `Everyone` を書き戻し、残りの 4 つのキーを `defaults delete`（Handoff と AirPlay は `defaults -currentHost delete`）で消して、同じ `killall` を実行します。

4 つをまとめて切ったので、どれが AWDL を動かしていたかは分けていません。システム設定の画面にどう表示されるかも確かめていません。切っているあいだは、この Mac で AirDrop の受信、Handoff、この Mac への AirPlay、ユニバーサルコントロールが使えません。

## 確かめ方

AWDL が動いているあいだ、Mac のカーネルは、チャンネルの割り当てを数秒おきにログに書きます（`AWDL ON:` で始まる行）。この行の数を数えました。

```sh
/usr/bin/log show --start "<開始時刻>" --style compact \
    --predicate 'process == "kernel" AND eventMessage CONTAINS "awdl0" AND eventMessage CONTAINS "AWDL ON:"' | wc -l
```

`ifconfig awdl0` の `status` は、切ったあとも `active` のままです。インターフェースは残り、使う機能がなくなるので、チャンネルを移らなくなります。これまでの「止め続ける」方法（[記録](2026-11-16-wifi-path-awdl-off.md)）は、インターフェースごと落としていました。

## 結果

### AWDL

| 時間帯 | `AWDL ON:` の行 |
|---|---|
| 切る前（11:10:00 からの 100 秒） | 27 本 |
| 切ったあと、11:32:10 から 12:05:00 まで（約 33 分） | 0 本 |
| **12:05:00 から 12:05:25 まで（25 秒）** | **14 本** |
| 12:05:26 から 12:14:03 まで（約 9 分） | 0 本 |
| **12:14:04 から 12:14:25 まで（21 秒）** | **14 本** |
| 12:14:26 から 12:24:00 まで（約 10 分） | 0 本 |

切ったあと、11:32:05 に AWDL の上の最後の広告（`_companion-link._tcp`）が止まり、11:32:10 からは `AWDL ON:` の行が出なくなりました。

12:05:00 に戻ったのは、近くにある別の Apple の機器に求められたためです。`rapportd` のログに、相手から「AWDL が要る」という知らせが届いたこと（`Received NeedsAWDL enable event from peer`）と、それを受けて AWDL の上の広告を始めたことが残っています。求めたのはユニバーサルコントロールです（ログでは `Ensemble` という名前）。この Mac でユニバーサルコントロールを切っていても、相手からの求めには応じます。24 秒後に広告は止まりました。12:14:04 にも同じことが起き、21 秒後に止まりました（このときは Mac で何も測っていません）。

同じ知らせは、切る前の 11:26 から 11:28 に 16 秒おきに、11:31 にも 1 回届いていました。

戻っていた 25 秒のあいだ、経路は切る前と同じ状態になりました。そのとき流していた `ping` は最大 466 ms で、同じ時間に測っていた 49 回の入力のうち 13 回で、中継した窓の反応が 100 ms を超えました（[内訳の記録](2026-11-16-step3-breakdown.md)の 1 回目）。

### 経路

11:39:28 から 395 秒、Mac からホスト（有線側）とルーターへ、同時に 1200 回ずつ `ping` を流しました。このあいだ、AWDL は動いていません。

| 経路 | AWDL の止め方 | 欠落 | 最小 | 中央値 | 95% | 99% | 最大 |
|---|---|---|---|---|---|---|---|
| Mac → ホスト | **設定で切る** | 0 | 2.4 ms | **3.2 ms** | **7.2 ms** | **9.8 ms** | 19.5 ms |
| Mac → ルーター | **設定で切る** | 0 | 1.9 ms | 3.1 ms | 6.9 ms | 8.8 ms | 23.9 ms |
| Mac → ホスト | 止め続ける（[記録](2026-11-16-path-host-wired.md)） | 0 | 2.0 ms | 3.3 ms | 7.1 ms | 9.7 ms | 324.6 ms |
| Mac → ホスト | 何もしない（同上） | 0 | 2.4 ms | 4.1 ms | 71.8 ms | 108.1 ms | 386.1 ms |

## わかったこと

- **設定で切ると、この Mac が自分から AWDL を使うことはなくなります。** 切る前は数秒おきにチャンネルを移っていたのが、33 分のあいだ 1 度も動きませんでした。動いていないあいだの経路は、`sudo` で止め続ける方法と同じです（中央値 3.2 ms、95 パーセンタイル 7.2 ms）。
- **ただし、止まったままにはなりません。** 近くの機器がユニバーサルコントロールのために AWDL を求めると、この Mac は設定に関係なく応じます。52 分に 2 回（12:05 と 12:14）、それぞれ 20 秒あまりでした。そのあいだの計測値は使えません。
- **既製の部品の 1 本は、AWDL が動いていなければ、止め続ける方法のときと同じ中央値（19.5 ms）でした。** 99 パーセンタイルは 41.6 ms と 25.1 ms で開いていますが、500 回の 99 パーセンタイルは遅いほうの 5 回で決まります。この 1 回ずつでは、止め方の違いによるものかどうかは言えません。

アダプターが届くまでの測り方：

- 共有の機能は切ったままにする。
- 計測のたびに、そのあいだの `AWDL ON:` の行を数える。1 本でもあれば、最初の行の 2 秒前から最後の行の 5 秒後までに送った入力を外して集計し、外した数を記録に書く。
- 求めてくる側の機器でユニバーサルコントロールを切るか、計測のあいだその機器をスリープさせれば、戻らなくなるはずです（確かめていません）。

まだ行っていないこと：

- ルーターのチャンネルを AWDL に合わせる案の参考値。ルーターの設定を変える必要があり、人の作業を待っています。
