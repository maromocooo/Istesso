# ルーターのチャンネルを AWDL に合わせる（Wi-Fi で使うときの参考値）

- 日付：2026-11-16
- コミット：この記録と同じコミット
- 目的：Mac の Wi-Fi が AWDL のために別のチャンネルへ移るのが、経路の遅れの原因だった（[記録](2026-11-16-step0-wifi-path.md)）。ルーターのチャンネルを AWDL が使うチャンネルに合わせれば、移らずに済むはずである。共有の機能を切らずに、その状態でどこまで良くなるかを見る。共有の機能を設定で切る案（[記録](2026-11-16-wifi-sharing-off.md)）と並べる参考値で、判定には使わない。

## 条件

| 項目 | 値 |
|---|---|
| ホスト | Ubuntu 24.04、RTX 4090。有線（2.5 Gbps） |
| クライアント | MacBook Air（M4）、macOS 26.5.1。Wi-Fi は **5 GHz 帯のチャンネル 44**（40 MHz 幅、802.11ax。計測用に用意したネットワーク）。信号は −45 dBm 前後 |
| 共有の機能 | **元の設定に戻した**（AirDrop の検出は「すべての人」、Handoff、AirPlay レシーバー、ユニバーサルコントロールは既定）。AWDL は動いている |
| 接続 | ホストは有線、Mac は Wi-Fi。計測は有線側のアドレスに向け、ケーブルを通っていることを確かめた |
| 解像度とフレームレート | 経路の計測は映像なし。既製の部品の 1 本は 1720×720、85 fps、灰色の絵 |
| クライアントのディスプレイ | 外部（3440×1440、84.96 Hz） |
| コーデックとビットレート、エンコーダーの設定、経路 | [最初の 1 本の記録](2026-11-16-step3-first-path.md)と同じ。フレームはメインメモリー経由、復号はソフトウェア |

これまでの計測では、Mac は 6 GHz 帯のチャンネル 53 につながっていました。AWDL が使うのは、チャンネル 44 と 6 です。

## 測り方

1. **経路だけ**（13:36:27 から 36 分）。Mac からホスト（有線側）とルーターへ、同時に `ping` を 0.2 秒おきに流した。約 9 分おきに来ていた「近くの機器からの AWDL の要求」を何回も含むように、30 分以上測った。
2. **既製の部品の 1 本**（14:17:20 から 32 分、4,540 回）。[README.md](README.md) の「内訳の計測」のとおり。7,000 回の予定で始め、30 分を過ぎたところで打ち切った。そのあいだ、Mac からホストとルーターへの `ping` も流した。手元の窓と中継した窓は、どちらも前面に出さずに起動した。

AWDL の動きは、Mac のカーネルのログにあるチャンネルの割り当ての行（`AWDL ON:`）と、近くの機器からの要求の行（`rapportd` の `NeedsAWDL enable`）で見ました。

## 結果

### AWDL

- 36 分のあいだ、AWDL はずっと動いていました（割り当ての行が 456 本）。近くの機器からの要求は 36 回で、61 秒おきです。
- 割り当ては、どの行も「時間の 90% をルーターのチャンネル（44）で過ごす」でした。16 に分けた時間のうち、チャンネル 6 に移るのは 1 つだけです。6 GHz 帯のときは、ルーターのチャンネルで過ごす時間が 24〜78% でした。

### 経路

| 経路 | 条件 | 回数 | 欠落 | 最小 | 中央値 | 95% | 99% | 最大 |
|---|---|---|---|---|---|---|---|---|
| Mac → ホスト | **チャンネル 44、共有あり** | 7,012 | 0 | 1.9 ms | **3.8 ms** | **6.7 ms** | **10.8 ms** | 142.6 ms |
| Mac → ルーター | **チャンネル 44、共有あり** | 7,011 | 0 | 2.1 ms | 3.7 ms | 6.7 ms | 11.0 ms | 143.7 ms |
| Mac → ホスト | 6 GHz 帯、共有あり（[記録](2026-11-16-path-host-wired.md)） | 900 | 0 | 2.4 ms | 4.1 ms | 71.8 ms | 108.1 ms | 386.1 ms |
| Mac → ホスト | 6 GHz 帯、共有を切る。AWDL が動かなかった時間帯（[記録](2026-11-16-wifi-sharing-off.md)） | 1,200 | 0 | 2.4 ms | 3.2 ms | 7.2 ms | 9.8 ms | 19.5 ms |

- 20 ms を超えた応答は、ホストへの経路で 9 回（0.13%）、ルーターへの経路で 7 回でした。
- そのうち 3 回（87 ms、116 ms、143 ms）は、13:40:32 からの 8 秒間に集まっています。ルーターへの経路にも同じ時刻に出ています。このとき、AWDL の割り当ては変わっていません。直前の 13:39:42 に Wi-Fi のスキャンがログにありますが、原因は確かめていません。
- 遅い応答（8.8 ms 超、131 回）が戻る時刻は、AWDL の時間の刻み（16 TU の倍数）にほとんどそろっていません。そろい方は 0.10〜0.18 で、偶然の水準は 0.09 です（1.0 がいつも同じ位相）。午前の 6 GHz 帯のときのような、はっきりした周期は出ていません。

### 既製の部品の 1 本

32 分のあいだ、AWDL は動き続けていました（割り当ての行が 419 本、どれもルーターのチャンネルで 90%。近くの機器からの要求は 29 回）。4,540 回の入力は、どちらの窓にもすべて映りました。

| 指標 | 中央値 | 95% | 99% | 最大 |
|---|---|---|---|---|
| **追加遅延の、手元の窓との差（合格ラインの指標）** | **21.1 ms** | **25.4 ms** | **28.5 ms** | — |
| 　6 GHz 帯で共有を切り、AWDL が動かなかった回（500 回。[記録](2026-11-16-step3-breakdown.md)） | 21.4 ms | 23.8 ms | 27.6 ms | — |
| 　合格ライン | 12 ms | 24 ms | 47 ms | — |
| 追加遅延（中継した窓） | 38.8 ms | 48.6 ms | 54.9 ms | 151.2 ms |
| 追加遅延（手元の窓） | 17.7 ms | 23.2 ms | 26.4 ms | 39.5 ms |
| ネットワーク（入力の行きと、最初のパケットの帰り） | 4.1 ms | 7.8 ms | 14.8 ms | 107.9 ms |
| 　6 GHz 帯で共有を切り、AWDL が動かなかった回 | 3.4 ms | 6.2 ms | 16.5 ms | 36.9 ms |
| `ping` の往復（計測と同じ時間、Mac → ホスト、6,036 回） | 3.9 ms | 6.8 ms | 10.9 ms | 44.2 ms |

- 中継した窓の反応が 60 ms を超えた入力は 28 回（0.62%）、100 ms を超えた入力は 3 回（0.07%）でした。
- 手元の窓の追加遅延の中央値は 17.7 ms で、いつもの値（17.3 ms）から 0.4 ms でした。
- ネットワーク以外の区間は、6 GHz 帯の回と 0.2 ms 以内で同じです（平均で、コンポジター 9.0 ms、圧縮まで 1.8 ms、復号 2.5 ms、描くまで 1.7 ms、描いてから画面に出るまで 18.8 ms）。

Mac が Wi-Fi で、灰色の絵と 1720×720 なので、判定には使えない値です。

参考：入力ごとの差は、中央値 23.5 ms、95 パーセンタイル 23.5 ms、99 パーセンタイル 35.3 ms、最大 129.5 ms。更新 1 回ぶん以内が 40.1%、2 回ぶん以内が 95.6%、3 回ぶん以内が 99.5%。

カメラでの計測：行っていません。

## わかったこと

1. **ルーターをチャンネル 44 にすると、共有の機能を切らなくても、AWDL は経路をほとんど乱しません。** AWDL が動き続けた 36 分と 32 分のどちらでも、経路の 95 パーセンタイルは 6.7〜6.8 ms でした。6 GHz 帯で AWDL が動いていたときは 71.8 ms です。
2. **6 GHz 帯で共有を切る案と比べると、ふだんの値は少し大きく、乱れる時間がなくなります。** 経路の中央値は 3.8 ms と 3.2 ms、既製の部品の 1 本のネットワークは中央値で 4.1 ms と 3.4 ms です。一方、6 GHz 帯では、共有を切っていても、近くの機器に求められると 9 分おきくらいに 20 秒あまり AWDL が戻り、そのあいだは `ping` が最大 466 ms になりました（[記録](2026-11-16-wifi-sharing-off.md)）。チャンネル 44 では、合わせて 68 分のあいだ、そういう時間はありませんでした。
3. **合格ラインの指標は、どちらの案でもほぼ同じです。** 中央値は 21.1 ms と 21.4 ms、95 パーセンタイルは 25.4 ms と 23.8 ms でした。6 GHz 帯の値は、AWDL が戻らなかった 500 回のものです。
4. **残っている乱れは、まれで短いものです。** 経路だけの 36 分に、80 ms を超える応答が 3 回（8 秒のあいだ）ありました。映像を通した 32 分では、中継した窓の反応が 100 ms を超えたのは 3 回です。原因は確かめていません。

2 つの案を並べると、次のとおりです。

| | 6 GHz 帯で、共有の機能を切る | 5 GHz 帯のチャンネル 44 で、共有の機能はそのまま |
|---|---|---|
| 経路（中央値 / 95% / 99%） | 3.2 / 7.2 / 9.8 ms（AWDL が戻っていないとき） | 3.8 / 6.7 / 10.8 ms |
| AWDL が戻る時間 | 9 分おきくらいに 20 秒あまり。防げない。計測では、その区間の入力を外す | なし（68 分のあいだ） |
| 使えなくなるもの | AirDrop の受信、Handoff、この Mac への AirPlay、ユニバーサルコントロール | なし |
| 要るもの | 計測のたびの確認 | ルーターの 5 GHz 帯をチャンネル 44 に固定する。帯域の幅は 40 MHz だった |

どちらの Wi-Fi に Mac を置くかは、この結果を見て人が決めます。判定は、どちらの案でもなく、Mac を有線にして行います。
