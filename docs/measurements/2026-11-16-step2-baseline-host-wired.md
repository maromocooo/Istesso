# 手順 2：既存の配信ソフトでの基準（ホストを有線にしたあと）

- 日付：2026-11-16
- コミット：19c210b
- 目的：ホストを有線にして、[Wi-Fi での基準](2026-11-16-step2-baseline-sunshine-moonlight.md)を測り直す。成熟した実装がこの機材でどこまで届くかを、ネットワークの影響を減らして見る。

## 条件

Wi-Fi での基準と同じで、ホストの接続だけが違います。

| 項目 | 値 |
|---|---|
| ホスト | Ubuntu 24.04、RTX 4090、Sunshine 2026.914.233613。取り込みは X11、エンコーダーは NVENC |
| クライアント | MacBook Air（M4）、macOS 26.5.1、Moonlight 6.2.0。`open` で起動 |
| 接続 | ホストは有線（2.5 Gbps）、Mac は Wi-Fi（6 GHz 帯）。AWDL は止め続け、計測のあいだ戻らなかった。経路の往復は中央値 3.3 ms、95 パーセンタイル 7.1 ms（[記録](2026-11-16-path-host-wired.md)） |
| 解像度とフレームレート | 1720×720、85 fps。窓で表示 |
| クライアントのディスプレイ | 外部（3440×1440、84.96 Hz）。手元の窓と中継した窓を並べた |
| コーデックとビットレート | H.265、30 Mbps |
| エンコーダーの設定 | Sunshine の既定 |
| 経路 | 映像は Sunshine と Moonlight の経路。入力は合成の入力（UDP） |

## 測り方

[README.md](README.md) の「画面での計測」のとおりで、500 回ずつです（乱数の種は 20261116）。

| 回 | Moonlight の V-sync | 時刻（JST） |
|---|---|---|
| A | なし（`--no-vsync`） | 10:42:53〜10:45:57 |
| B | あり（既定） | 10:46:05〜10:49:24 |

## 結果

### 手元の窓との差

| 回 | ホスト | 中央値 | 95% | 99% | 最大 |
|---|---|---|---|---|---|
| A：V-sync なし | **有線** | **19.1 ms** | **53.3 ms** | 66.6 ms | 84.9 ms |
| A：V-sync なし | Wi-Fi（前回） | 24.3 ms | 60.6 ms | 76.4 ms | 147.0 ms |
| B：V-sync あり | **有線** | 47.1 ms | 58.9 ms | 70.6 ms | 94.2 ms |
| B：V-sync あり | Wi-Fi（前回） | 47.1 ms | 94.2 ms | 235.4 ms | 376.6 ms |

画面更新の回数（1回 11.8 ms）で数えると、次のとおりです。

| 遅れた更新の回数 | 0 | 1 | 2 | 3 | 4 | 5 | 6 以上 |
|---|---|---|---|---|---|---|---|
| A：V-sync なし、有線 | 43 | 154 | 173 | 56 | 47 | 20 | 7 |
| B：V-sync あり、有線 | 0 | 0 | 51 | 145 | 215 | 83 | 6 |

A では、更新 1 回ぶん以内が 39.4%、2 回ぶん以内が 74.0% でした（Wi-Fi では 23.8% と 63.2%）。

### 追加遅延（往復時間 − アプリ自身の応答時間）

| 対象 | 回 | 中央値 | 95% | 99% | 最大 |
|---|---|---|---|---|---|
| 中継した窓 | A：V-sync なし | 37.9 ms | 71.7 ms | 81.7 ms | 112.1 ms |
| 中継した窓 | B：V-sync あり | 62.0 ms | 76.4 ms | 89.5 ms | 109.6 ms |
| 手元の窓（中継なし） | A のとき | 19.9 ms | 30.0 ms | 39.3 ms | 61.7 ms |
| 手元の窓（中継なし） | B のとき | 18.0 ms | 23.3 ms | 25.7 ms | 69.7 ms |

アプリ自身の応答時間は、ホストで中央値 2.8 ms、手元で 3.0 ms でした。

B の追加遅延は、ホストのログのうち B の 500 回ぶんと対にして出しました。ホストのテストアプリを A と B で起動し直さなかったので、1つのログに 2 回ぶんが入っていたためです。この取り違えは、道具が警告するようにしました。

## わかったこと

1. **ホストを有線にしても、成熟した実装は、手元の窓より中央値で 19 ms（画面更新 1.6 回ぶん）遅れます。** Wi-Fi のときの 24 ms から 5 ms 縮みました。95 パーセンタイルは 61 ms から 53 ms です。
2. **残っている遅れの中心は、ネットワークではなくホストの処理です。** Moonlight の統計では、ネットワークは 5 ms、ホストの処理は平均 11.5 ms で、有線にする前と変わっていません。取り込みが X11 の方法であることが効いているとみています。
3. **裾も残っています。** 有線で AWDL を止めても、95 パーセンタイルは更新 4〜5 回ぶんです。ホストの処理の最大は 39 ms ありました。
4. **V-sync あり（Moonlight の既定）は、有線にしても中央値が変わりません（47 ms）。** 待ち行列の 15 ms が、ネットワークとは関係なく乗っています。

合格ラインを決める材料として、この機材でいちばんよかった値（A、有線）を並べます。

| 指標 | 成熟した実装（A、有線） |
|---|---|
| 手元の窓との差（中央値 / 95%） | 19.1 ms / 53.3 ms |
| 更新 1 回ぶん以内に収まった割合 | 39.4% |
| 更新 2 回ぶん以内に収まった割合 | 74.0% |
