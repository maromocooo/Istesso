## 何を確かめたか

ホストは、ふだん、机にだれもログインしていない状態で動かす。これまでの計測は、机にログインした状態だった。ログイン画面だけの状態で、映像・入力・音が同じように動くかを確かめる。

## 見つかったこと 1：ログイン画面だけでは、コンポジターが起動しなかった

「前」の遅延の予行（16:41〜16:43）で止まった。コンポジターの部品が、起動のときに落ちた（`the compositor did not start`）。遅延の値は、1 つも測っていない。

- 原因（読むだけで確かめた）：GPU の描画の口（`/dev/dri/renderD*`）は、グループ `render` のもの。ユーザーは `render` にも `video` にも入っていなかった。机にログインしているときは、OS が、その席のユーザーに口を開ける。ログイン画面だけでは、開けない。
- NVIDIA の口（エンコーダー）は、だれでも開ける。だから、エンコーダーの部品は見つかっていた。
- 直し：ユーザーをグループ `render` に入れる（下の 3 行目）。「後」の回で、コンポジターが起動し、予行 20 回が全部映った（つなぎ直し 0）。
- 手順を変えたことになるので、これはインストーラーの仕事になる。パッケージはユーザーをグループに入れない（どのユーザーがエージェントを動かすか知らないため）。入れる行を表示する。

## 置いた 3 つの設定

3 つとも、持ち主が自分で置いた。効くのは次の再起動から。

| 行 | 何を許すか | 戻す行 |
|---|---|---|
| `printf '%s - rtprio 95\n%s - nice -19\n' "$USER" "$USER" \| sudo tee /etc/security/limits.d/50-istesso-rt.conf` | そのユーザーのプロセスが、リアルタイムの優先度を 95 まで、nice を −19 まで求められる（PipeWire と、ユーザーのサービス管理も） | `sudo rm /etc/security/limits.d/50-istesso-rt.conf` |
| `printf 'SUBSYSTEM=="misc", KERNEL=="cpu_dma_latency", OWNER="%s", MODE="0600"\n' "$USER" \| sudo tee /etc/udev/rules.d/71-istesso-cpu-dma-latency.rules` | そのユーザーだけが `/dev/cpu_dma_latency` を開ける。開いているあいだ、CPU は深い眠りに入らない（電力と熱が増える）。そのユーザーのどのプログラムでもできる | `sudo rm /etc/udev/rules.d/71-istesso-cpu-dma-latency.rules && sudo chown root:root /dev/cpu_dma_latency && sudo chmod 600 /dev/cpu_dma_latency` |
| `sudo gpasswd -a "$USER" render` | ログインしていなくても、そのユーザーのプログラムが GPU の描画の口を開ける。画面の出力の口（`card*`、グループ `video`）は開けない | `sudo gpasswd -d "$USER" render` |

2 回目の再起動のあとに確かめたこと：`render` グループに入っていて、描画の口を読み書きできる。`/dev/cpu_dma_latency` はそのユーザーのもの。上限は、リアルタイム 95、nice −19。固定できるメモリの上限は変わっていない。
