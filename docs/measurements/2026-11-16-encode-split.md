# 色の変換と圧縮の内訳（ホストだけ）

- 日付：2026-11-16（23:32）
- コミット：この記録と同じコミット（ホストのスクリプトが、色の変換を出た時刻を書くようにした）
- 目的：仮の判定（[記録](2026-11-16-m1-provisional-verdict.md)）で 4.04 ms だった「色の変換と圧縮」の区間を、2 つに分ける。確定の判定までに余裕を取り戻す順番（[M1 の計画](../m1-plan.md) の手順 5）の 1 番目。
- 結論：**ほとんどが、エンコーダーの中です。色の変換は平均 0.16 ms、エンコーダーは平均 3.92 ms。** 色の変換を別の作りにしても、取り戻せるのは 0.1 ms ほどです。この区間を縮めるなら、エンコーダーの使い方（NVENC を直接使い、1 フレームを分けて圧縮させる、など）を変えるしかありません。

## 条件

| 項目 | 値 |
|---|---|
| ホスト | Ubuntu 24.04、RTX 4090、GStreamer 1.24.2。コンポジターは、修正を当てたもの（`scripts/patches/`） |
| 絵 | テストアプリの動く文字、3440×1440、毎秒 85 枚。GPU で描く |
| 経路 | 仮の判定と同じ：フレームは GPU の上に置いたまま、`cudaconvert` で 4:4:4 に変換、`nvcudah265enc`（`preset=p1 tune=ultra-low-latency`、上限 30 Mbps、キーフレームは最初だけ） |
| 送り先 | なし（ホストの中の、誰も聞いていないポート）。Mac は使っていない。入力も送っていない |
| 測ったもの | 45 秒ぶん。始めの 5 分の 1 を除いた 3,059 フレームの全部 |
| ほかに動いていたもの | **静かな状態ではありません。** 同じホストで、手で試すための窓の経路（1720×720）が動いていて、ブラウザーが動画を再生していました。計測の直前の GPU の使用率は 5%、エンコーダーは 2% |

## 結果

| 区間 | 平均 | 中央値 | 95% | 99% | 最大 |
|---|---|---|---|---|---|
| コンポジターを出てから、色の変換を出るまで | 0.16 ms | 0.16 ms | 0.30 ms | 0.36 ms | 0.51 ms |
| 色の変換を出てから、圧縮が済むまで | 3.92 ms | 3.91 ms | 4.12 ms | 4.20 ms | 4.44 ms |
| 合わせて | 4.09 ms | 4.07 ms | 4.39 ms | 4.48 ms | 4.76 ms |

- 圧縮したフレームは、平均 7.2 kB（仮の判定では 7.7 kB）。
- 合わせた値は、仮の判定の 4.04 ms と 0.05 ms しか違いません。ほかのものが動いていても、この区間はほとんど動かなかった、と読めます。
- 圧縮の時間は、ばらつきが小さい（中央値 3.91 ms、99% 4.20 ms）。待ち行列ではなく、エンコーダーが 1 フレームにかける時間そのもの、と見ています。確かめていません。

カメラでの計測：行っていません。

## まだ測っていないもの

入力の受け渡し（プローブ → 中継のコマンド → 制御チャンネル → エージェント → 経路のプログラム）を、プログラムごとに分ける計測は、道具だけ入れました。

- `istesso input relay --timings <ファイル>` と `istesso agent --input-timings <ファイル>` が、入力のメッセージを受け取った時刻と、渡し終えるまでの時間を書きます。**書くのは時刻と件数だけで、何のキーかは書きません。** 時刻だけでも、いつ打ったかは分かるので、指定したときにだけ書き、ファイルは持ち主だけが読めるようにしています。
- `scripts/m1-step3-breakdown.py` に `--relay-timings` と `--agent-timings` を渡すと、最初の行（入力の経路とネットワーク）を、プログラムごとに分けて表示します。
- 測るには、Mac の外部ディスプレイを 4 分ほど使います（2 つの窓を前面に出す）。人が Mac を使っているあいだは走らせていません。

## 再現のしかた

ホストで、仮の判定と同じ設定の経路を、ログを付けて動かします（`scripts/m1-step3-host.py --frames cuda --chroma 444 --bitrate 30000 --gop -1 --vbv 353 --render-on-commit --no-input --no-key-requests --log <ファイル>`）。その中でテストアプリを `--picture text --fps 85 --draw gpu` で動かし、ログの `frame_out`、`converted`、`encoded` の時刻を、フレームごとに引きます。
