# 絵を止める・戻す、閉じるよう頼む、窓がなくなったことを知らせる：動作の確認

- 日付：2026-11-17（03:06〜03:24）
- コミット：b160101（パイプラインの指示、コンポジターの 3 つ目の修正、`istesso-media` の `offer`）。この記録は、次のコミット
- 目的：アプリマネージャー（M3）のセッションの約束（ADR 0010、`m3-app-manager` ブランチ）のうち、パイプラインとコンポジターにできなかった 3 つを作って、確かめる。(1) アプリを終わらせずに絵を止めて、エンコーダーを GPU に返し、戻す（`pause`、`resume`、`detach`）。(2) アプリの窓に、閉じるよう頼む（`close`）。(3) 最後の窓が閉じたことを知らせる（`empty`）。指示と答えの形は、[ADR 0015](../adr/0015-media-transport.md) の「止める、戻す、離す」と、[ADR 0009](../adr/0009-host-compositor.md) にある。
- 結論：**3 つとも働く。** 絵を止めると、GPU が開けるエンコーダーの数が 1 つ戻り、戻すと 1 つ減る。止めるのに約 27 ms、戻して最初のフレーム（キーフレーム）が出るまでに約 50 ms、Mac の窓に絵が出るまでは、そこから約 10 ms。止めているあいだも、アプリは描き続ける。閉じるよう頼むと、保存するものがないテキストエディターは 5 ms で窓を閉じて自分で終わり、保存していない文字があるときは、尋ねて残る。
- **見つかった不足：アプリが尋ねる窓（「保存しますか」）が、絵に出ない。** 数えられてはいる（窓が 2 枚になる）が、Mac の窓には、元の窓しか映らない。この記録の時点では、直していない（下の「見つかったこと」）。**あとで、原因が分かり、直した**（[記録](2026-11-17-dialog-windows.md)）。

## これは、遅延の計測ではない

時間は、ホストのパイプラインが自分の時計で書いたものと、Mac のビューアー（シェルから起動。優先度が低い）が書いたものです。合格ラインの指標とは関係がありません。

## 条件

| 項目 | 値 |
|---|---|
| ホスト | Ubuntu 24.04、RTX 4090（ドライバー 590.48.01）、GStreamer 1.24.2。コンポジターは、3 つの修正を当てたもの。自分の作業用の写しでビルドした |
| クライアント | MacBook Air（M4）、macOS 26。ビューアーは、シェルから起動。窓は、内蔵ディスプレイの隅に、小さく出した |
| 絵 | 3440×1440、毎秒 85 枚まで、テストアプリの動く文字（閉じるよう頼む確認は、1720×720 で、テキストエディター） |
| 経路 | 暗号化した経路（ADR 0015）。2 台の、実際のペアリングと鍵 |
| 指示 | パイプラインの標準入力に、1 行 1 語（`tmux` の窓に打ち込んだ） |
| ほかに動いていたもの | 持ち主が試している窓の経路（エンコーダーを 1 つ持っている）、音の長い試験、ほかの流れの確認 |

## 結果

### エンコーダーが、本当に返る

GPU 自身の数え方は、このドライバーでは使えませんでした。`nvidia-smi --query-gpu=encoder.stats.sessionCount` は、エンコーダーが開いていても 0 を返し、`nvidia-smi encodersessions` は、何も挙げません。そこで、**あといくつ開けるか**を数えました：小さいエンコーダー（320×240）を、GPU が断るまで開いて、全部閉じる（約 1 秒。そのあいだ、PC の空きを全部持つ）。

| 状態 | あと開けるエンコーダーの数 |
|---|---|
| このパイプラインが、絵を作っている | 10 |
| 絵を止めた（`pause`） | 11 |
| 戻した（`resume`） | 10 |
| このパイプラインを起動する前（持ち主の試用の窓だけ） | 11 |

この GPU とドライバーで同時に開けるのは、12 と見ています（空きの 11 と、持ち主の試用の窓が持つ 1 つ。ほかの流れのパイプラインが動いているあいだは、空きがもう 1 つ減りました）。止めているあいだ、このパイプラインは 1 つも持っていません。

### かかる時間（ホストの時計）

| 区間 | 中央値 | 最小〜最大 | 回数 |
|---|---|---|---|
| `pause`：語を読んでから、エンコーダーを閉じ終えるまで | 27.1 ms | 16.9〜33.3 ms | 12 |
| `resume`：語を読んでから、エンコーダーの要素ができるまで | 4.3 ms | 1.0〜6.0 ms | 12 |
| `resume`：最初のフレームがエンコーダーを出るまで | 50.1 ms | 38.8〜57.3 ms | 12 |
| `resume`：そのフレームを、ライブラリーに渡し終えるまで | 50.3 ms | 39.1〜57.5 ms | 12 |

- 最初のフレームは、12 回とも、キーフレームでした。
- 戻すときの時間は、ほとんどが、GPU がエンコーダーを開く時間です。
- この 12 回のあと、戻し方を 1 か所変えました（止めたときに手元にあったフレームを、新しいエンコーダーに最初に通す。下の「エンコーダーが開けないとき」）。変えたあとの値は、ホストだけで 44.7〜49.6 ms（3 回）と 34.8 ms、2 台の回で 42.8 ms と **147.2 ms**（1 回だけ、長かった。理由は調べていません）。

### 止めているあいだ、アプリは止まらない

テストアプリを、「描いてよい」と知らされたときだけ描く形（`--when-told`）で動かし、絵を止めているあいだに、キーを 5 回送りました（このパイプラインだけの入力のソケットから）。

| 項目 | 値 |
|---|---|
| アプリが答えたキー | 5 回のうち 5 回 |
| キーが届いてから、アプリがフレームを確定するまで | 11.66〜11.80 ms（アプリが知らされる拍、1 フレームぶん） |
| そのあいだに圧縮したフレーム | 0 |

「アプリが確定したら描く」の決まりでは、アプリへの知らせは、フレームとは別の拍で出ます。止めているあいだ、コンポジターは何も描かず、フレームをためません（手元に持つのは、止めたときの 1 枚だけ）。**決まった拍で描く設定（`--no-render-on-commit`）では、フレームを作り続けて捨てる形にしてありますが、動かしていません。**

### 2 台で：止めて、戻して、離して、戻す

ビューアーをつないだまま、ホストのパイプラインに `pause`、`resume`、`detach`、`resume` を送りました（2 回。下は 1 回目）。

| したこと | ホスト | Mac のビューアー |
|---|---|---|
| `pause` | 25.7 ms でエンコーダーを閉じた | 接続は、つながったまま。絵は、最後の 1 枚のまま 6.05 秒 |
| `resume` | 51.8 ms で、キーフレームを渡し終えた | キーフレーム（99.0 kB）が、最初のバイトから 1.9 ms で揃い、7.0 ms で復号され、7.4 ms で窓に渡った |
| `detach` | 24.2 ms でエンコーダーを閉じた。見る側を、すぐに切った | 接続が切れた。つなぎ直そうとして、断られ続けた（返事がない） |
| `resume` | 58.1 ms で、キーフレームを渡し終えた | 自分でつなぎ直して（0.5 秒おきに試している）、つないでから 19.6 ms で絵が出た |

- `resume` と言ってから、Mac の窓に絵が戻るまでは、ホストの約 52 ms と、Mac の約 7 ms と、経路（1 ms 未満）で、**約 60 ms** です。
- 戻ったあとの窓を取り込んで、絵が欠けていないことを見ました（文字の絵の全体が出ている）。
- 2 回目（戻し方を変えたあと）も、同じように働きました（Mac：8.5 ms で復号、9.2 ms で窓）。

### エンコーダーが開けないとき

GPU の空きを、小さいエンコーダーで全部ふさいでから、`resume` と言いました。

- はじめの作りでは、**パイプラインが終わりました**（`Could not encode stream`）。コンポジターも同じプロセスなので、アプリは表示先を失います。
- 直したあと：`{"istesso":"refused","word":"resume","reason":"…"}` と答えて、絵は止まったまま、パイプラインは動き続けました。そのあとに送ったキー 3 回に、アプリは 3 回とも答えました。空きを戻してから、もう 1 度 `resume` と言うと、34.8 ms で戻りました。

### 閉じるよう頼む、窓がなくなったことを知らせる

テキストエディター（gnome-text-editor）を、このパイプラインのコンポジターの中で動かしました。エディターの状態の置き場所は、自分の作業用のフォルダーに分けてあります（下の「見つかったこと」）。

| 場合 | `close` のあと |
|---|---|
| 保存するものがない | 5 ms で、窓の数が 1 から 0 になり、`{"istesso":"empty"}` が出た。エディターのプロセスは、頼んでから 200 ms 以内に、自分で終わった。パイプラインは、動き続けた |
| 保存していない文字がある（入力のソケットから 4 文字打った） | 窓の数が 1 から 2 になった（エディターが、尋ねる窓を作った）。`empty` は出ない。もう 1 度頼んでも、残る。ファイルには、何も書かれていない。**力ずくでは、終わらせていません** |
| テストアプリ（`istesso-flash`） | 1.7 ms で、窓の数が 0 になった |

コンポジターのテスト（`cargo test -p wayland-display-core`。ホストで 54 本が通る。うち 5 本が今回のもの）でも、同じことを、本物の Wayland クライアントで確かめています：頼まれて閉じる、頼まれても閉じない、2 枚のうち 1 枚だけ閉じる、頼まなければ何も起きない。3 つの修正を、元のコミット（`1301f86`）に順に当てると、ビルドしてテストした木と、1 バイトも違いません。

## 見つかったこと

- **アプリが尋ねる窓が、絵に出ない。** 保存していない文字があるエディターに閉じるよう頼むと、エディターは 2 枚目のトップレベルを作ります（数は 2 になる）。ところが、Mac の窓を 3 回取り込んでも、映っているのは、元の窓だけでした（ホストのポインターを動かしたあとも、同じ）。人は、尋ねられていることが分からず、答えられません。コンポジターが窓を並べるところを読みましたが、原因は、まだ分かっていません。`close` を人に使わせる前に、直す必要があります。
- **gnome-text-editor は、`--standalone --ignore-session` を付けても、同じ人の状態の置き場所（セッション、下書き）を読み書きする。** 状態の置き場所を分けずに 1 回起動したところ、持ち主が試しているエディターの、保存していないタブが、こちらのエディターに開き、状態のファイル（`session.gvariant`）が書き換わり、下書きが 1 つ増えました（本線に報告済み。持ち主の下書きは、そのまま）。そのあとは、`XDG_DATA_HOME`、`XDG_CONFIG_HOME`、`XDG_STATE_HOME`、`XDG_CACHE_HOME` を自分のフォルダーに向けて起動し、持ち主の置き場所が変わっていないことを、前後で確かめました。**1 人の中で同じアプリを 2 つ動かすときは、置き場所を分ける必要がある**（ADR 0010 の「分かっている限界」に関わる）。
- 置き場所を分けても、前の回の下書きが残っていると、「保存するものがない」はずの回でも尋ねてきます。確認は、毎回、新しい置き場所で行いました。
- GPU の「いくつ開いているか」は、このドライバーでは読めません。枠を数える側（アプリマネージャー）は、GPU に聞くのではなく、自分が開いた数を数えることになります。

## まだ確かめていないこと

- 決まった拍で描く設定（`--no-render-on-commit`）での、止める・戻す。
- 長い時間（数分以上）止めたあとの、戻し。
- 見る側が 2 台のとき。止めているあいだに、見る側がつないできたとき（つながって、戻したときのキーフレームから受け取るはず）。
- `detach` のあと、0.1 秒以内に送るのをやめる、という約束（ADR 0010）。見る側を切るのは、語を読んだその場で行っていますが、時間は測っていません。
- 暗号化していない UDP の経路での、止める・戻す。
- アプリが 2 つ以上の窓を持つときの `close`（全部の窓に頼む。1 枚だけには、頼めない）。
- Mac の側の時間を、アプリとして起動して測ること。

## 朝に見ること（数分）

閉じるよう頼んだときにアプリが尋ねる窓は、あとで直しました。人の手で確かめるには、コマンド 1 つで足ります（`scripts/try.sh` の `TRY=channel`。くわしくは、[あとから開く窓の記録](2026-11-17-dialog-windows.md)の「朝に見ること」）。

1. Mac のターミナルで、このブランチの作業ツリーに入って、次を実行する。いま試している窓は、止まります（保存していないものがあれば、先に保存する）。

   ```sh
   TRY=channel scripts/try.sh gnome-text-editor --standalone
   ```

2. 見ること。
   - 何か打ってから、エディターの「閉じる」ボタン（×）を押す。尋ねる窓が中央に出て、マウスでもキーボードでも答えられるか。
   - 「破棄」を選ぶと、エディターが終わる。このとき、ホストのパイプラインのログ（`~/.cache/istesso-try/pipeline.log`）に `{"istesso":"empty"}` が出る。`scripts/try.sh` は、これを見ていないので、Mac の窓は、開いたまま残る。
   - 絵を止める・戻す（`pause`、`resume`）は、ホストで `tmux attach -t step3` して、語を打つと試せる。

3. 終わったら、`scripts/try.sh stop`。
