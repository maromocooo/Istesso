# 手順 3 の経路：Mac も有線にして（4:4:4、キーフレームは求められたときだけ）

- 日付：2026-11-16
- コミット：この記録と同じコミット（プローブが前面に固定した窓を見つける。テストアプリとビューアーを前面に固定できる。ホストのスクリプトが IPv6 の送り先を受ける）
- 目的：Mac を、LAN 付きのハブで有線にした。経路の往復時間と、決めた設定（[ADR 0002](../adr/0002-latency-first.md)：3440×1440、4:4:4、キーフレームは求められたときだけ、上限 30 Mbps）の値を、有線で測り直す。
- 結論：**経路の往復は中央値 0.5〜0.6 ms、95 パーセンタイル 0.8〜1.0 ms になった**（Wi-Fi では 3.9 ms と 7.2 ms）。**追加遅延の、手元の窓との差は、中央値 11.0 ms、95 パーセンタイル 11.1 ms**。ただし、**ハブを通したディスプレイが 60 Hz になっていて、判定の条件（85 Hz）ではない。** 判定の値としては使えない。85 Hz に戻してから測り直す。

| クライアント | MacBook Air（M4）、macOS 26.5.1。VideoToolbox で復号 |
| 接続 | **2 台とも有線。** Mac は、LAN 付きの USB ハブ（1000BASE-T、全二重）。Wi-Fi（5 GHz 帯のチャンネル 44）も入れたままで、計測の通信だけをケーブルに通した（下の「ケーブルを通す方法」） |
| 解像度とフレームレート | 3440×1440、毎秒 85 枚（描き始めが 85 回まで）。テストアプリの動く絵（色つきの文字のスクロール、線の太さ 2 ピクセル）。ホストのテストアプリは GPU で描画 |
| クライアントのディスプレイ | 外部（3440×1440、拡大なし）。**60.00 Hz**。ハブの映像出力を通したためで、選べるのは 60 Hz と 50 Hz だけだった。これまでの計測は、Mac に直接つないで 84.96 Hz |
| コーデックとビットレート | H.265（Main 4:4:4、8 ビット）。上限 30 Mbps、実際は 5.2 Mbps |
| エンコーダーの設定 | `preset=p1 tune=ultra-low-latency zero-reorder-delay=true b-frames=0 rate-control=cbr`。キーフレームは求められたときだけ（`gop-size=-1`）。レート制御のバッファーは 1 フレームぶん（353 kbit）。色は sRGB と書く |

| 窓 | 中継した窓は 860×360 に縮めて表示、手元の窓は 600×400。どちらも前面に出さずに起動し、**ほかの窓より上に固定**した（下の「窓を上に固定する」） |

## ケーブルを通す方法

Mac の有線のアダプターには、LAN の IPv4 アドレスがまだありません（手動の設定で、自分だけのアドレスになっていて、ルーターもない）。IPv4 では、ホストへの通信は Wi-Fi から出ていきます。設定を変えるのは人に頼むことにして、今回は、**どちらの PC もケーブルの上に持っている IPv6 のアドレス**を使いました。設定は何も変えていません。

- 映像：ホストの送り先を、Mac の有線のアダプターの IPv6 アドレスにする（`scripts/m1-step3-host.py --to '[アドレス]:5004'`）。受信側は `udpsrc address=::` で待つ。
- 入力：プローブに `--relayed-interface <有線の名前>` を渡して、ホストの有線の IPv6 アドレスへ送る。
- キーフレームの求め：受信側が、映像の送り主へ返す。ホストは IPv4 と IPv6 の両方で待つ。
- 確かめ方：計測のあいだに Mac の有線のアダプターが受け取った量を見た（500 回を送った 183 秒のあいだに 120 MB。5.2 Mbps で 183 秒ぶんは 119 MB）。計測の前後に、ホストのそのアドレスが有線のアダプターのものであることも見ている。

ホストの `tmux` は、コマンドを zsh で動かします。IPv6 のアドレスを囲む角かっこは、zsh ではファイル名のパターンになるので、引用符で囲まないとコマンドが始まりません。1 回目は、これでホストのテストアプリが起動していませんでした。

## やり直した回と、道具の変更

この値が取れるまでに、4 回やり直しました。どの回も、値が出る前か、途中で無効と分かったものです。

| 回 | 起きたこと | 直したこと |
|---|---|---|
| 1 | 計測のスクリプトの書き間違いで、ホストの経路に渡す引数が壊れ、映像が始まらなかった | スクリプトを直した |
| 2 | ホストのテストアプリが起動していなかった（上の、角かっこ） | 引用符で囲んだ。起動しなかったときは、理由を表示して知らせる |
| 3 | 264 回目から、中継した窓が反応しなくなった。**人が使っているターミナルの窓が、中継した窓の中央にかぶさった。** プローブは、窓の中央の色を画面から読んでいる。始めるときにはかぶさっていなかったので、気づかずに最後まで待ち続けた | 計測の窓を、ほかの窓より上に固定できるようにした（下）。プローブは、どちらかの窓が 5 回続けて反応しなかったら、窓の重なりを調べ直し、かぶさっていれば理由を言って止まる |
| 4 | 上に固定した窓を、プローブが見つけられなかった（ふつうの窓だけを探していた） | 上に固定した窓も探す。かぶさっているかどうかは、その窓と同じ高さか、それより下の高さで、手前にある窓を見る |

3 回目の、反応していた 264 回ぶんだけを集計すると、差は中央値 12.2 ms、95 パーセンタイル 11.9 ms でした。窓の大きさと位置が違い（1720×720、前面に固定せず）、回数も少ないので、上の値とは並べません。

### 窓を上に固定する

- テストアプリ：`istesso-flash --on-top`。
- ビューアー：環境変数 `ISTESSO_ON_TOP` を付けて起動する。
- どちらも、キーボードを受け取る窓にはなりません（`open -n -g` で、前面に出さずに起動する）。人が打っているキーを横取りしないまま、ほかの窓の下にもなりません。

道具を変えたので、[README.md](README.md) のとおり、手元のテストアプリを 2 つ並べて（どちらも上に固定）、差が 0 になることを確かめました。200 回で、差は中央値 0.17 ms、95 パーセンタイル 0.43 ms、99 パーセンタイル −0.03 ms。入力ごとの差は、全部が更新 1 回ぶん以内でした。

## わかったこと

- **Mac を有線にすると、経路は 1 ms を切ります。** ネットワークの区間は 5.8 ms から 1.0 ms になり、ばらつきもなくなりました（95 パーセンタイル 1.6 ms）。
- **中央値は、60 Hz のディスプレイで 11.0 ms でした。** 合格ライン（12 ms）の内側ですが、条件が違うので、判定にはなりません。これまでの回では、中央値の差は、中継のために足される区間の平均の合計とほぼ同じでした（Wi-Fi で 85 Hz のとき 15.5 ms と 15.6 ms、今回 11.0 ms と 10.8 ms）。足される区間はディスプレイに左右されないので、85 Hz でも 11 ms 前後と見込んでいます。合格ラインまでの余裕は 1 ms ほどしかなく、測って確かめます。
- **判定の前に、ディスプレイを 85 Hz に戻す必要があります。** ハブの映像出力では、この解像度で 60 Hz までしか選べません。ディスプレイを Mac に直接つなぎ、ハブは LAN のためだけに使う形にします（人の作業）。
- **人が Mac を使っているあいだに測るなら、窓は上に固定します。** ふつうの窓のままだと、作業中の窓がかぶさって、計測が途中から無効になります。判定の回は、これまでどおり、2 つの窓を前面に出して、人が触らずに測ります。
- Mac の有線のアダプターに LAN の IPv4 アドレスが付けば、IPv6 を使う回り道は要らなくなります。Wi-Fi を切るのは、そのあとです（切ると、いまの SSH の接続も切れるので、つなぎ直しが要ります）。

## 再現のしかた

1. ホストで、決めた設定の経路を動かす（[README.md](README.md) の「内訳の計測」）。送り先は Mac の有線のアダプターの IPv6 アドレス。
2. Mac で、ビューアー（`udpsrc address=::`、`ISTESSO_ON_TOP` つき）と、手元のテストアプリ（`--on-top`）を、`open -n -g` で起動する。
3. `istesso-screen-probe --relayed '[ホストの有線の IPv6 アドレス]:47811' --relayed-interface <有線の名前> --relayed-window "title:Istesso Relay" --count 500`。
4. `istesso measure compare` と `scripts/m1-step3-breakdown.py` で集計する。`--refresh-hz` には、そのときのディスプレイの値を渡す。
