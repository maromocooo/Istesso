# 手順 3：毎秒 85 枚を超えない形と、GPU で描くテストアプリ（判定に近い条件）

- 日付：2026-11-16
- コミット：この記録と同じコミット（テストアプリの GPU 描画と「次のフレームで答える」動き、コンポジターの修正の作り直し）
- 目的：[前の記録](2026-11-16-step3-render-on-commit.md)の修正は、85 fps のところに 108〜118 枚のフレームを出していた。判定は、毎秒 85 枚を超えない実装で測ると決まった。その形に作り直し、判定の解像度（3440×1440）と動く絵で測る。あわせて、ホストのテストアプリを GPU で描く形にして、CPU で描く形と比べる。

## 条件

| 項目 | 値 |
|---|---|
| ホスト | Ubuntu 24.04、RTX 4090（ドライバー 590.48.01）、GStreamer 1.24.2、gst-wayland-display（`1301f86`）に `scripts/patches/gst-wayland-display-render-on-commit.patch`。フレームは CUDA のメモリーで渡す |
| クライアント | MacBook Air（M4）、macOS 26.5.1。VideoToolbox で復号 |
| 接続 | ホストは有線。Mac は Wi-Fi（5 GHz 帯のチャンネル 44、共有の機能は元の設定） |
| 解像度とフレームレート | 3440×1440 と 1720×720、85 fps。3440×1440 の絵は、Mac では 1720×720 の窓に縮めて出した |
| クライアントのディスプレイ | 外部（3440×1440、84.96 Hz）。2 つの窓は前面に出さずに起動 |
| テストアプリの絵 | 動く絵（文字のスクロール）、1 秒に 85 回。**入力には、次のフレームで答える。** 手元の窓は 600×400 で、CPU で描く。ホストの側は、CPU で描く形と GPU で描く形の 2 通り |
| コーデックとビットレート | H.265、30 Mbps（固定ビットレート）、レート制御のバッファーは 353 kbit、キーフレームは 170 フレームごと |
| 経路 | RTP を UDP で。暗号化なし |

### 変えたこと

**1. コンポジターの修正を作り直した。** フレームを描き始めるのは、アプリが新しい絵を確定したときで、どの 1 秒を取っても、描き始める回数がフレームレート（85）を超えないようにしました。86 枚目は、直前の 85 枚のうちいちばん古いものから 1 秒たつまで待ちます。何も確定されないときは、フレーム 2 つぶんの時間がたったら、そのままの絵を出します（映像を止めないため）。前の版にあったタイマーの重なりは、なくなりました。

**2. テストアプリが、入力に次のフレームで答えるようにした。** これまでは、入力のたびに、流れる文字の 85 枚とは別に 1 枚を描いていました。アプリが 85 枚を使い切っているところにもう 1 枚を足すので、コンポジターが 85 枚を守ると、その 1 枚は次の番まで待つことになります。待ちがなくなったように見えたのは、余分な 1 枚を出していたからでした。ふつうのアプリは、入力への反応を、次に描くフレームに入れます。テストアプリも、動く絵ではそうするようにしました（`--answer next-frame`。既定）。次のフレームまで待つ時間は、アプリ自身の応答時間に入り、手元の窓でも中継した窓でも、指標からは引かれます。

**3. ホストのテストアプリを、GPU で描けるようにした**（`--draw gpu`）。コンポジターには、GPU の上にあるバッファーがそのまま渡ります。絵は、CPU で描いたものと 1 画素も違いません（コンポジターの出力 1 フレーム、1,238,400 画素を比べた）。手元の窓は、CPU で描いたままです。

## 測り方

[README.md](README.md) の「内訳の計測」のとおり、500 回ずつです。

| 回 | 解像度 | ホストのテストアプリ | 時刻（JST） |
|---|---|---|---|
| A | 3440×1440 | CPU で描く | 16:16:16〜16:20:18 |
| B | 3440×1440 | GPU で描く | 16:20:56〜16:24:56 |
| C | 1720×720 | GPU で描く | 16:25:12〜16:29:08 |

99 パーセンタイルは、500 回なので判断に使いません。Mac が Wi-Fi で、2 つの窓を前面に出しておらず、絵も縮めて出しているので、判定には使えない値です。

「どの 1 秒でも 86 以下」は、フレームがコンポジターを出た時刻で数えた値です。描き始めの時刻では 85 以下になるように作ってあり、描くのにかかる時間がフレームごとに違うので、出た時刻で数えると 1 枚多い 1 秒があります。

カメラでの計測：行っていません。

## わかったこと

1. **毎秒 85 枚のままで、決まった間隔を待つ時間はなくせます。** B と C では、コンポジターの区間が平均 1.9〜2.0 ms でした。アプリが次のフレームで答え、コンポジターがその確定をすぐ描けば、余分なフレームは要りません。
2. **判定の解像度と動く絵で、中央値の差は 13.6 ms、95 パーセンタイルは 16.8 ms でした（B）。** 合格ラインの中央値（12 ms）まで、あと 1.6 ms です。Mac は Wi-Fi のままです。
3. **ホストのテストアプリを GPU で描く形にすると、3440×1440 で中央値の差が 6.2 ms 下がりました**（19.8 ms から 13.6 ms）。CPU で描く形では、コンポジターが毎フレーム 20 MB を GPU に上げるので、次の確定が来たときに前のフレームがまだ終わっておらず、待ちが出ます（コンポジターの区間が 8.7 ms）。CPU で描く形の値は、そういうアプリを中継したときの参考として残します。
4. **1720×720 では、中央値の差が 11.5 ms でした。** 3440×1440 との違い（2.1 ms）は、圧縮（+1.5 ms）と復号（+0.6 ms）です。

### 12 ms までの道筋（3440×1440、動く絵）

B の差を、区間に分けます。平均で 14.4 ms、中央値で 13.6 ms です。

| 区間 | いま（平均） | 目標 | どうやって |
|---|---|---|---|
| ネットワーク（入力の行きと、最初のパケットの帰り。手元の窓で入力が届くまでの 0.2 ms を引いた値） | 5.9 ms | 1.5 ms | Mac を有線にする。Wi-Fi では `ping` の往復だけで中央値 4.0 ms ある。有線では 1 ms を切るはずで、残りは両側でプログラムが起こされるまでの時間（測っていない） |
| フレームが届く（最初のパケットから最後まで） | 1.0 ms | 0.3 ms | Mac を有線にする。35 個のパケットが、Wi-Fi では間を空けて届いている |
| コンポジター | 1.9 ms | 1.9 ms | 自前のコンポジターでも、この値を保つ |
| 色の変換、圧縮 | 2.5 ms | 2.5 ms | そのまま。画素数で決まっている（1720×720 では 1.0 ms） |
| パケットにして渡す | 0.2 ms | 0.2 ms | そのまま |
| 復号 | 2.5 ms | 2.5 ms | そのまま（1720×720 では 1.9 ms） |
| 描くまで | 0.3 ms | 0.3 ms | そのまま |
| 描いてから画面に出るまでの、手元の窓との違い | 0.1 ms | 0.1 ms | そのまま |
| **合計** | **14.4 ms** | **9.3 ms** | |

- **要るのは、Mac を有線にすることだけです。** それで平均 9.3 ms、中央値では 8〜9 ms になる見込みで、ラインまで約 3 ms の余裕ができます。有線での値は、まだ測っていません。
- 余裕の使いみちは、画質です。ビットレートを上げたり、色を間引かない形（4:4:4）にしたりすると、圧縮、転送、復号の時間が増えます。その分は、画質の条件を決めるときに測ります。
- 自前の実装（手順 4）は、ホストの側で 1.9 + 2.5 + 0.2 = 4.6 ms、Mac の側で 2.5 + 0.3 = 2.8 ms を上回らないことが目安になります。暗号化の時間は、まだ入っていません。

読むときの注意：

- **手元の窓の値が、少し大きく出た回があります**（A で 18.3 ms。いつもは 17.3 ms 前後）。2 ms のずれには達していないので、やり直していません。テストアプリが次のフレームで答えるようになったので、フレームの確定がいつも決まった刻みに乗ります。その刻みとディスプレイの更新のずれ方で、値が動くのかもしれません。確かめていません。
- コンポジターは、フレームを描いたときに、アプリへ「次のフレームを描いてよい」と知らせます。知らされてから描くアプリは、フレームが出た直後に次の絵を確定し、次の番までほぼ 1 フレームぶん待つことになります。テストアプリは、自分の時計で描いているので、これに当たりません。自前のコンポジターでは、知らせる時刻を、次に出す時刻の少し前に置きます。
- 3440×1440 の絵は、Mac では半分の大きさの窓に縮めて出しています。等倍で出したときの値は、判定の置き方（中継の窓を画面いっぱいに、手元の窓を隅に重ねる）で測ります。
- キーフレームは 2 秒おきのままで、大きさをそろえています。画質は、まだ測っていません。
