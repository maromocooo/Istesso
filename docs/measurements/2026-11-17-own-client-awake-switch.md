# 自前のクライアントの「速いコアを起こしておく」切り替え：切、回り続ける、1 ms ごとに起きる

**この回は、音の夜の試験が動いている夜に測った。読めるのは、同じ夜の、切り替えを入れた回と切った回の差だけである。ここの値を、静かな条件で測った値と、比べてはいけない。**

- 日付：2026-11-17、22:00〜22:26（日本時間）。本線が測った。この記録は、6 回の出力と、フレームの記録から、数え直して書いた

- 順番：OFF1、SPIN1、TICK1、OFF2、SPIN2、TICK2。500 入力ずつ。ホストの側は、6 回とも同じ（前の比べと同じ。関門の判定の形）。その前に、20 入力の予行を、SPIN と TICK で 1 回ずつ
- 走らせたスクリプト：`run-awake-compare.sh`。前の「起こす」比べ（[記録](2026-11-17-own-client-wake-switches.md)）のスクリプトの写しで、切り替えの名前と、回の順番だけを変えてある。リポジトリには入れていない
- 読み方（測る前に、本線が、調整役の記録に書いたもの。21:52 と 21:59）：

  > 主に、クライアントの側の、待ちでない区間の合計を読む。その中の、復号、出口から描くまで、入力の道も読む。OFF の 2 回の差が、その区間の揺れである。ON の 2 回が、OFF の 2 回より、揺れを超えて短ければ「効き目」。1 回だけなら「分からない」。TICK の 2 回が、揺れを超えて OFF より短く、TICK と SPIN の差が、OFF の揺れの中なら「tick で足りる」。SPIN だけが短ければ「spin だけが効く」。どちらも揺れの中なら「効き目は見えない」。電力は、Mac 全体ではなく、プロセスに付いた値（ON − OFF）。中央値と 95% は、M1 の線と比べるためだけ。今夜の値は、同じ夜の中の差としてだけ読み、静かな条件の値とは比べない。予行のログに、切り替えが動いた跡がなければ、始めない。

- 結論（この規則で読むと）：**SPIN は「効き目」。TICK は「効き目は見えない」。したがって「spin だけが効く」**（TICK と SPIN の差は、OFF の揺れより、ずっと大きい）。ただし、下の「読み」のとおり、その効き目が、速いコアに仕事が移ったからか、コアが眠らないからかは、分けていない。電力は、SPIN で、プロセスに付いた値が、約 3.3〜3.4 W 増えた。TICK では、増えなかった

## 読み方で読む

規則どおりに、揺れは、OFF の 2 回の差である。

- **クライアントの側の、待ちでない区間の合計**：揺れは 0.03。SPIN は 2.09、2.08 で、OFF（3.78、3.81）より、**1.69〜1.73 短い**（揺れの 50 倍以上）。2 回とも。TICK は 3.79、3.81 で、OFF の 2 回の中。
- **復号**：揺れは 0.02。SPIN は 1.95、1.94 で、OFF（3.15、3.17）より 1.2〜1.23 短い。TICK（3.16、3.18）は、OFF の中（TICK2 は、OFF の高いほうより 0.01 高い）。
- **出口から、描くまで**：揺れは 0.01。SPIN は 0.06 で、OFF（0.43、0.44）より 0.37〜0.38 短い。TICK（0.43）は、中。
- **入力の道とネットワーク**：揺れは 0.01。SPIN は 1.07、1.05 で、OFF（1.36、1.37）より 0.29〜0.32 短い。入力の道は、片方の端が Mac にある（前の「昼の記録の読み直し」と同じ大きさ）。TICK（1.34、1.35）は、OFF より 0.01〜0.03 短いだけで、揺れと同じくらい。
- **フレームが届く、待ち行列**：SPIN で、0.16 → 0.07、0.04 → 0.01。TICK は、変わらない。
- **ホストの側の、待ちでない区間**：4 つの形の間で、揺れ（0.04）を超えるのは、SPIN の 0.25〜0.32 の短さだけで、その差は、入力の道の差（0.29〜0.32）と、ほぼ同じである。コンポジターとエンコードは、変わらない。ホストは、6 回とも同じ。
- **描いてから、映るまで（待ち）**：OFF は 17.71、17.76。SPIN は 17.73、17.96。TICK は 17.34、17.58。TICK は、OFF より 0.18〜0.42 短い。これは待ちで、読み方の外である。TICK が 6 回の中でいちばん短く出た「全部」（33.47、33.67。OFF より 0.08〜0.48 短い。揺れは 0.20）は、おもに、この待ちから来ている。
- **全部**：SPIN は 31.88、32.07 で、OFF（33.75、33.95）より 1.68〜2.07 短い。TICK は 33.47、33.67 で、同じ順の OFF より、0.28、0.28 短い（TICK2 を OFF1 と比べると 0.08 短い）。揺れ（0.20）を、2 回とも超えたとは言えない。
- **入力ごとの遅れ**：2 回以上遅れた入力の割合は、OFF 7.2、8.4 %。SPIN 2.8、1.8 %。TICK 5.4、6.6 %。TICK は OFF より 0.6〜3.0 ポイント低いが、500 入力の割合で、OFF の 2 回の差が 1.2 ポイントある。この割合は、規則の主な読みではない。

**規則で読むと**：SPIN の 2 回は、どちらも、OFF の 2 回より、揺れを超えて短い。**効き目がある。** TICK の 2 回は、OFF の揺れの中。**tick で足りる、とは、言えない。spin だけが効いた。**

## 見たこと、読み（確かめていない）

### 見たこと

- SPIN で、クライアントの側の、待ちでない区間の合計が、3.8 ms から 2.1 ms に、約 1.7 ms 短くなった（復号 1.2 ms、出口から描くまで 0.4 ms、入力の道 0.3 ms、届く 0.1 ms）。「全部」は、約 1.7〜2.1 ms 短くなった。
- TICK では、その合計は変わらなかった。
- OFF のあいだ、このプロセスのプロセッサー時間の、ほとんどすべてが、省電力のコアの上にあった（`usage` の行）。SPIN のあいだは、ほとんどすべてが、速いコアの上にあった。TICK のあいだは、OFF と同じに、省電力のコアの上にあった。

### 読み（確かめていない。どれも、この回では、試していない）

1. **切っているとき、クライアントのプロセッサー時間が、ほとんど省電力のコアの上にあるのは、見えたこと。なぜ、システムがそう置くのかは、分からない。** 窓が前にないから（回のあいだ、窓は、99.6 % 以上、前になかった）かもしれない。ほかの理由かもしれない。
2. **したがって、「spin の効き目」には、2 つのものが混ざっているかもしれない**：(a) 仕事が、速いコアに移ったこと、(b) コアが眠らずに、起こされたままなこと。この回では、分けていない。TICK は、(b) の一部（1 ms ごとに起きる）を入れても、効かなかったが、それは、仕事が速いコアに移らなかったことと、合う。それも、確かめていない。
3. **前の「起こす」比べの 5 つの優先度の切り替えは、これを起こさなかった**（[記録](2026-11-17-own-client-wake-switches.md)）。優先度を上げても、仕事は、速いコアには移らなかった、と読める。確かめていない。
4. **分けるための回**（製品が知るべきこと）：(i) 同じ OFF と SPIN を、**クライアントの窓を、回のあいだ、ずっと前に置いて**行う。OFF が、そのとき、自分から速いコアの上で走るなら、「窓が前にある」ことが、鍵だった、と言える。(ii) 製品の形（窓が前にあって、入力から 3 秒）を、本物のキーで打っているあいだに、動かす。この回は、その条件を、通っていない。**SPIN より安く、仕事を速いコアに移す道は、分からない**（TICK は、移さなかった。ほかのものは、試していない）。
5. **かかるもの**：SPIN は、入っているあいだ、プロセスに約 3.3〜3.4 W が付いた。この Mac は、ファンがない。熱で全体が遅くされるかどうか、電池でどれだけ減るかは、測っていない。

- ホストは、変えていない（ホストの側の区間は、変わっていない）。
- **電池で動かしたときのこと**：何も、測っていない。
- **条件つきの形**（窓が前にあって、入力が続いているあいだだけ入る）：動かしていない。本物のキーも、通していない。
- **静かな条件の値との比べ**：していない。今夜の値は、音の夜の試験が動いている夜の、同じ夜の中の差としてだけ、読む。

- SPIN が、ほかのアプリの速いコアと取り合うことがあるかどうか。
