# カーソルを手元で描く：動作の確認

- 日付：2026-11-17（02:06〜02:21）
- コミット：b3bec07（コンポジターの 2 つ目の修正、`istesso-media`、ホストのスクリプト、ビューアー）。この記録と、集計の道具への 1 行は、次のコミット
- 目的：カーソルを絵から外して、クライアントが手元で描く（[M1 の計画](../m1-plan.md) の手順 4 の順 7、[ADR 0009](../adr/0009-host-compositor.md)、[ADR 0015](../adr/0015-media-transport.md) の「カーソル」）。人の手を借りずに確かめられるところまでを、2 台の実機で確かめる。
- 結論：**カーソルの形は、ホストのアプリからビューアーまで届き、ビューアーは、それを絵の上に描く。ホストの絵からは、カーソルが消えている。** 文字の欄の上では I 字、ダイアログの地の上では矢印、ダイアログの外では「画像なし」と、アプリが変えるとおりに変わった。フレームは、カーソルを外しても、変わらずに全部届いた。
- **確かめていないこと：本物のポインターに付いて動くこと、Mac 自身のカーソルが消えること。** Mac のポインターを、こちらからは動かさないため。朝に、人が見る（下の「朝に見ること」。数分）。

## これは、遅延の計測ではない

カーソルが「手に付いてくる」かどうかは、人が見て決めることで、ここには数値がありません。Mac の側のプログラムは、シェルから起動しました（アプリのバンドルも、`open` も使っていません）。窓は、内蔵ディスプレイの左上の隅に、860×360 ポイント（絵の 1720×720 と、画素が 1 対 1）で出し、前面に固定せず、終わったら閉じました。

## 条件

| 項目 | 値 |
|---|---|
| ホスト | Ubuntu 24.04、RTX 4090、GStreamer 1.24.2。コンポジターは、2 つの修正を当てたもの（`render-on-commit` と `cursor-messages`）。自分の作業用の写しでビルドした |
| クライアント | MacBook Air（M4）、macOS 26。ビューアーは、シェルから起動 |
| 接続 | 2 台とも有線。映像とカーソルは、暗号化した経路（ADR 0015）。2 台の、実際のペアリングと鍵 |
| 絵 | 1720×720、毎秒 85 枚まで。アプリは、文字の欄が 1 つあるダイアログ（`zenity --entry`）。フレームの数を見る回だけ、テストアプリの動く文字（3440×1440） |
| ホストのポインター | このパイプラインだけのソケットに、ポインターの位置を書いて動かした（`--input-socket`。人が試している経路のソケットにも、入力の中継にも、触れていない）。**Mac のポインターは、動かしていない** |
| ビューアーのカーソル | `ISTESSO_CURSOR_AT=430,180`：ポインターに関係なく、ビューの中央にカーソルを描く（確認のための指定） |

## 結果

### カーソルの形が届いて、変わる

ホストのポインターを、ダイアログの中で動かした。コンポジターが伝えたカーソルは 21 回：矢印（24×24、ホットスポット 3,1）が 10 回、I 字（24×24、ホットスポット 11,12）が 4 回、「画像なし」が 7 回。ライブラリーが断ったものは 0。

| ホストのポインターの位置 | ビューアーに届いたカーソル | ビューアーの窓（中央を切り出して見た） |
|---|---|---|
| 文字の欄の上 | 画像、24×24、ホットスポット 11,12 | I 字。指定した点が、I 字の中央にある |
| ダイアログの地の上 | 画像、24×24、ホットスポット 3,1 | 矢印。指定した点に、矢印の先がある |
| ダイアログの外（何もないところ） | 画像なし | 何も描かれていない（中央の 160×120 ピクセルに、暗くない画素が 0） |

ホットスポットが、指定した点に重なっている。大きさは、絵と同じ縮尺（この窓では、画像の 1 ピクセルが、画面の 1 ピクセル）。

### 絵の中に、カーソルがない

ホストのポインターを、ダイアログの地の上（絵の 230,60）に置いて、ビューアーの窓の、その点のまわり 80×80 ピクセルを比べた。

| ホストの設定 | 黒い画素（矢印の黒） | 「カーソルを伝える」の絵との違い（40 レベルを超えて違う画素） |
|---|---|---|
| カーソルを伝える（`--cursor`） | 0 | — |
| カーソルを絵に描く（これまで）、ポインターがその点にある | 66 | 109 |
| カーソルを絵に描く、ポインターをほかへ動かしたあと | 0 | 0 |

`--cursor` を付けると、ポインターがそこにあっても、絵はポインターがないときと同じである。コンポジターのテストでも、同じことを、フレームの画素を直接比べて確かめている（`cargo test -p wayland-display-core`）。

### フレームは、変わらずに届く

カーソルを伝える設定で、テストアプリ（3440×1440、動く文字）を 1 分流し、そのあいだ、ホストのポインターを動かし続けた。

| 項目 | 値 |
|---|---|
| ホストが圧縮したフレーム | 5,160（毎秒 86.0。ポインターが動いても、フレームは増えていない） |
| 相手に送った / 届いた / 復号した | 5,106 / 5,106 / 5,105（最後の 1 枚は、止めたときに復号の途中）。連番の飛び 0、接続がその場で受け取りきらなかったフレーム 0 |
| ホスト：圧縮が済んでから、書き終えるまで（中央値） | 0.325 ms（カーソルなしの回：0.325〜0.329 ms。[記録](2026-11-17-encrypted-video-first-look.md)） |
| Mac：最初のバイトから、VideoToolbox に渡すまで（中央値） | 0.149 ms（同：0.142〜0.149 ms） |
| カーソル | コンポジターが伝えたのは 2 回（始めの「画像なし」と、アプリの矢印）。ビューアーに届いたのも 2 回 |

### 自動のテストで確かめてあること

- コンポジター（ホストで 49 本が通る。うち 14 本が今回のもの）：クライアントが設定したカーソルが、画像とホットスポットつきで伝わる。同じカーソルを設定し直しても、2 度は伝えない。隠したら「隠れている」と伝わる。大きすぎる画像（300×300）や、ホットスポットが外にある画像は、「画像なし」として伝わる。フレームの画素を、設定のありとなしで比べる。
- 画像を信頼しないこと（コンポジター、ホストのライブラリー、見る側のライブラリーの 3 か所。それぞれにテスト）：辺が 1〜256 ピクセル、ホットスポットが画像の中、バイト数が大きさとちょうど合う、というもの以外は、読まない、送らない、受け取らない。
- 頻度：1 フレームにつき 20 回カーソルを変えても、フレームは全部届き、見る側に届くカーソルは 1 秒に 100 回以下で、最後に届くのは、最後に設定したもの。
- 権限：権限を外された相手には、カーソルも送らない。ペアリング一覧が読めないあいだは、誰にも送らない。

## 朝に見ること（数分）

Mac のポインターを使うので、人が行います。**コマンド 1 つで起動できるようにしました**（`scripts/try.sh` の `TRY=channel`。くわしくは、[あとから開く窓の記録](2026-11-17-dialog-windows.md)の「朝に見ること」）。

1. Mac のターミナルで、このブランチの作業ツリーに入って、次を実行する。いま試している窓は、止まります（保存していないものがあれば、先に保存する）。

   ```sh
   TRY=channel scripts/try.sh gnome-text-editor --standalone
   ```

2. 見るもの：

   | すること | こうなるはず |
   |---|---|
   | 窓をクリックして、ポインターを窓の中で動かす | Mac の矢印が消えて、アプリのカーソルが、手のとおりに動く。遅れて付いてくる感じがない |
   | 速く、大きく動かす | カーソルが、ポインターの位置から離れない。絵の中に、もう 1 つのカーソルが見えない |
   | 文字のところと、タイトルやボタンのところを行き来する | I 字と矢印が、切り替わる。切り替わりは、絵と同じだけ遅れる（形は、ホストのアプリが決めるため） |
   | ポインターを窓の外へ出す | Mac のカーソルに戻る。窓の中に、カーソルの絵が残らない |
   | ほかのアプリの窓をクリックしてから、ポインターをビューアーの上に戻す | Mac のカーソルのまま（窓が、打ち込む先になっていないあいだは、手元のカーソルを出さない） |
   | 文字を打つ | アプリがポインターを隠したら、何も出ない。動かすと、また出る |

3. 終わったら、`scripts/try.sh stop`。

気づいたことがあれば、どの行で、どう違ったかを知らせてください。

## わかったこと

- コンポジターは、小さな修正で、カーソルを外に出せた。描いている場所が 1 か所、状態を受け取る場所が 1 か所だった。
- アプリは、カーソルの切り替えを、「ホットスポットを伝える」「新しい画像を確定する」の 2 つに分けて送ることがある。そのあいだに、古い画像と新しいホットスポットの組が、1 回だけ伝わることがある（ホストの記録に、同じホットスポットの行が 2 つ続く）。見る側に送るのは、フレームの間隔に 1 回、最新のものだけなので、ふつうは見えない。見えるようなら、確定を待ってから伝える形に直す。
- 元のコンポジターは、カーソルを絵に描くとき、画像の左上をポインターの位置に置いている（ホットスポットを引いていない）。手元で描く形では、ホットスポットを使うので、この違いはなくなる。

## まだ確かめていないこと

- 本物のポインターに付いて動くこと、Mac 自身のカーソルが消えること、窓が打ち込む先でないときの動き（上の「朝に見ること」）。
- ビューアーをアプリとして起動したとき（`open`）。カーソルの矩形の扱いは、起動のしかたでは変わらないはずだが、見ていない。
- 外部ディスプレイの全体に出す形（判定の置き方）と、内蔵ディスプレイとのあいだをポインターが行き来するとき。
- 拡大率が 2 のカーソル（HiDPI のアプリ）。並びとテストにはあるが、実物では見ていない。
- 画像が GPU の上のバッファーで渡されるカーソル（「画像なし」として伝わるはず）。
- 手元のカーソルで、当てるテストの結果がどう変わるか。
