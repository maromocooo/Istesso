# Mac mini：取り込みの速さを、設定ごとに比べる（入力なし）

- 日付：2026-11-17（Mac mini の時計で 20:23〜20:31）
- 道具：`macos/lock-check` の「Istesso Lock Check Dev」（`com.maromoco.istesso-dev.lock-check`。開発の証明書で署名。実行ファイルの SHA-256 は `18c9c847` で始まる）。人が 20:18 に、画面収録とアクセシビリティの許可を、これに出し直した（古い「Istesso Lock Check」の行は、人が外した）
- 目的：[M4 の計画](../m4-plan.md) の 5c の (b)。仮想ディスプレイで、窓が毎秒 89 回描かれても取り込みが毎秒約 75 枚だった（手順 0b の 4）理由を探す。人の提案 4 つ（17:54）と、こちらの案を、1 設定 1 回ずつ、2 周。
- 結論（下の表から）：
  - **物の画面がつながっているかぎり、どの設定でも、毎秒 85 枚には届かない。** 窓は約 60〜63 回しか描かれず、仮想ディスプレイ（85 Hz）の上でも同じ。
  - **仮想ディスプレイの上の窓だけ（形 A）は、描いた回数をそのまま取れる**（毎秒 61〜63 枚。描いた回数との差は 0〜0.4）。物の画面の上の窓は、描いた回数より毎秒約 7 枚少ない（55〜57 枚）。
  - **仮想ディスプレイの画面ごと（形 C、3440×1440）は、ちょうど半分**（毎秒 31.5 枚。届く間隔の中央値 約 34.7 ms）。設定を変えても変わらない。
  - フレームの最短の間隔を 1/85 秒にしても、待ち行列を 8 にしても、絵の形式を 420v にしても、窓を半分の大きさにしても、取れる枚数は変わらなかった。1/85 秒にすると、「変わっていない」（idle）のフレームが減っただけ（毎秒 75〜86 → 15〜19）。
  - 「落ちた」という状態のフレームは、OS からは来ない（状態は complete、idle、stopped だけが来た）。落ちた数は「描いた回数 − 取れた枚数」と読む。

- 道具は 1 回ごとに終わり、次を起動するまでの数秒は、ディスプレイを点けておく主張がない。ロック中は、主張がないと数秒で消える（17:21 の確かめと同じ）。20:27 の消えて点いたのは、その隙間と読める。確かめていない。
- 1 周目の最初の回の始めには、画面の一覧から、モードが読めなかった（ディスプレイがまだ眠っていた）。
- 終わったあと（20:32）、ディスプレイはスリープ中、画面は 1280×720、モード 7 つ。道具は残っていない。仮想ディスプレイも残っていない（どの回も「消えた」）。

## 読み取れること

- 毎秒 85 枚を妨げているのは、取り込みの設定ではない。窓が、物の画面の拍（約 60）でしか描かれないことである。物の画面がつながったままの Mac では、仮想ディスプレイを作っても、85 は出ない。
- 物の画面をつながず、「使っている」の合図を出したとき（手順 0b の 4）は、窓が 89 回描かれ、取り込みは約 75 枚だった。そのときの 75 と 89 の差が、ここでの「仮想ディスプレイの上の窓は、描いたぶんを全部取れる」と合わない。差は、画面をつながない並びでしか出ない。人が次にケーブルを抜けるとき、同じ設定の表を、その並びで取る。
- 画面ごとの取り込み（形 C）が 3440×1440 でちょうど半分になるのは、どの設定でも同じだった。製品は形 A（窓だけ）なので、判定には効かない。理由は調べていない。
- 1/85 秒の最短の間隔は、少し早く来たフレームを捨てていない（取れる枚数は同じ）。
