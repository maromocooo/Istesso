# M7：Stream Deck + を、実機で初めて動かした記録（2026-11-17）

機器対応のフレームワークと、最初のアダプター（Stream Deck +）を、Mac につながっている実機で動かしました。夜のあいだに、人の手を借りずにできる範囲だけです。遅延の計測ではありません。映像・入力・音の経路には、手を入れていません。

## 条件

| 項目 | 内容 |
|---|---|
| 日時 | 2026-11-17 0:53 ごろ |
| PC | MacBook Air、macOS 26.5 |
| 機器 | Stream Deck +。ファームウェアの版は 2.0.3.2。ハブごしにつながっている |
| 公式ソフト | Elgato Stream Deck 7.6.1。確かめるあいだだけ止めた |
| 使ったもの | `istesso-devices check --listen 3 --record <ファイル>`（コミット `f6c7ceb`） |

機器を見分けられる情報（製造番号など）は、読んでいません。記録にも入っていません。アダプターは、製造番号を返すレポートを名乗っていないので、読もうとしても、フレームワークが止めます。

## 公式ソフトの止め方と、戻し方

| 時刻 | したこと |
|---|---|
| 0:53:09 | 止める前の様子を書き留めた。公式ソフトは動いていて、機器を開いていた。ふつうのアプリとして動いていて、隠れてはいなかった |
| 0:53:44 | 公式ソフトの本体のプロセスに、終了のシグナル（TERM）を送った。1 秒以内に終わった。強制終了は、していない |
| 0:53:44〜0:53:49 | 機器を確かめた（下の表） |
| 0:53:49 | `open -g -b com.elgato.StreamDeck` で、公式ソフトを起動し直した |
| 0:53:57 | 公式ソフトが、機器を開き直した |

- 公式ソフトが機器を持っていなかった時間は、約 13 秒です。
- 起動し直したあと、公式ソフトのプロセスと、その補助のプロセスが、止める前と同じ顔ぶれで動いています。
- **止める前と違うところが 1 つあります。** 起動し直した公式ソフトが、設定の窓を開いて、いちばん前に出ました。窓は、内蔵のディスプレイにあります。Istesso の試用の窓は、外付けのディスプレイにあり、重なっていません。この窓には、触っていません（閉じてもいません）。
- 終了に AppleScript を使わなかったのは、macOS が「ほかのアプリを操作する許可」を尋ねるかもしれないためです。
- 念のため、6:30 に公式ソフトが動いていなければ起動し直す見張りを、夜のあいだ動かしてあります。

## 確かめたこと

受け入れの確認（[m7-plan.md](../m7-plan.md) の 6）の B「Stream Deck Plus を、公式ソフトなしで、この仕組みが制御できる」のうち、人の手が要らない分です。

| 確かめたこと | 結果 | どうして分かるか |

| 機器を開く | できた | macOS は、開くことを断らなかった。画面は見ていないので、許可を尋ねる表示が出たかどうかは、分からない |
| 機器に尋ねて、答えを読む | できた | ファームウェアの版（2.0.3.2）が読めた。答えの並びは、公開の仕様のとおりだった |
| 明るさを変える | 送れた | 機器への書き込みが、エラーなく終わった。見た目は、確かめていない |
| ボタン 2 つ（左上と右下）と、帯に、絵を出す | 送れた | 同上。絵は、ボタンが 2 回、帯が 5 回に分けて送られた。見た目は、確かめていない |

| ボタン、つまみ、タッチの知らせ | 3 秒待って、0 件 | 誰も触っていないので、0 件で正しい。知らせが出ることは、確かめていない |
| やり取りを記録して、機器なしで再生する | できた | 記録を `adapters/streamdeck_plus/recordings/first-run-on-the-device.rec` に置いた。`cargo test` が、機器なしで再生する |

## 朝、人の手で確かめること

数分で終わります。公式ソフトを止めるので、止めてよいときに行ってください。

1. **いまの様子を見る。** 公式ソフトの設定の窓が、前に出ているはずです。閉じてかまいません。Stream Deck のボタンに、いつもの絵が出ているか、押すといつもどおりに動くか、明るさがいつもどおりかを見てください。
2. **公式ソフトを終了する。** メニューバーの Stream Deck のアイコンから「終了」を選びます。
3. **次を実行する。** `link-proj-devices` のディレクトリで行います。

   ```sh
   cargo run -p istesso-devices -- check --listen 60
   ```

4. **見る。**
   - 8 個のボタンに、色が出る。左上から右へ、赤、橙、黄、緑。下の段は、左から、水色、青、紫、桃色。この順に見えれば、ボタンの番号の並びが合っています。
   - 帯に、4 色の帯が出る（左から、赤、橙、黄、緑）。
   - 絵が、逆さや裏返しになっていない。
5. **触る（60 秒のあいだに）。** 端末に、1 行ずつ出ます。
   - ボタンを、左上から順に 1 つずつ押す：`button 0 down`、`button 0 up`、…、`button 7 up`。
   - つまみを、左から順に、右に回す、左に回す、押す：`dial 0 turn 1`、`dial 0 turn -1`、`dial 0 down`、`dial 0 up`。
   - 帯を、軽くたたく、長く押す、なぞる：`touch tap …`、`touch long …`、`touch flick … -> …`。
6. **終わると、機器にロゴが出る。** そのあと、公式ソフトを起動します。いつもの絵が戻ることを見てください。

違うところがあれば、端末に出た行と、見えたものを教えてください。記録を残したいときは、`--record ファイル名` を付けます。

## 確かめていないこと

- 絵が、実際に見えること。向きと、色。
- ボタンの番号の並び（仕様の図が読めなかったので、左上から右へ、上の段から、と仮に置いている）。
- ボタン、つまみ、タッチの知らせ。仕様から手で書き起こした記録では確かめたが、実機の知らせは、まだ 1 つも見ていない。
- 公式ソフトとの切り替えを、Istesso が行うこと。今回は、手順として、こちらで止めて、戻した。
- 機器を抜いて、挿し直したときの動き。長い時間の動き。
- Linux。ホストがログイン画面のままの状態。
- 端末のあいだで運ぶこと。ボタンから、ほかの PC のアプリを開くこと。

アダプターの「確認した人」は、「まだ」のままにしてあります。上の「朝、人の手で確かめること」が済んだら、「作者が確認済み」に替えます。

## 気づいたこと

- 公式ソフトは、`open -g` で起動しても、自分で前に出て、設定の窓を開く。次に止めて戻すときは、窓を開かずに起動する方法（ログインのときの起動のしかた）を使うかどうかを、決めてからにする。
- macOS では、Stream Deck + を開くのに、追加の許可は要らなかった見込み。断られずに開けて、読み書きできた。
