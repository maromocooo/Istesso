### テストを次に始めたら、既定はどうなるか

- WirePlumber は 0.4.12 から、「前に選ばれた既定」の積み重ねを持ち、いま選ばれている既定が使えないときは、**優先度で選ぶ前に**、その中から選ぶ（ホストの `/usr/share/doc/wireplumber/NEWS.rst.gz`、0.4.12 の項：“WirePlumber now maintains a stack of previously configured default nodes and prioritizes to one of those when the actively configured default node becomes unavailable, before calculating the next default using priorities”）。0.5 の文書も同じことを書いている（[settings](https://pipewire.pages.freedesktop.org/wireplumber/daemon/configuration/settings.html) の `stream.restore-default-targets`）。
- そのため、**持ち主の出力があるあいだは、テストを始めても既定は変わらない。** 実際に、19:06:50 のあと、回 06〜17 で、テストの出力先を 12 回作ったが、既定は 1 度も変わらなかった（見張りの記録）。
- **持ち主の出力がなくなったとき**（USB の機器を抜いた、など）に、テストの出力先か聞くための出力先があれば、それが既定になる（積み重ねの 1 番め、2 番め）。こちらの出力先の `priority.session = 0`（`crates/istesso-audio/src/linux.rs`）は、優先度で選ぶときにしか効かず、積み重ねには効かない。

### 持ち主への提案 1：覚えている行を消す（持ち主が、ホストのデスクトップで行う）

**しなくても、いまの音には害はない**（持ち主の出力がある限り）。消すなら、音を何も鳴らしていないときに、次の順で。

```sh
cp ~/.local/state/wireplumber/default-nodes ~/.local/state/wireplumber/default-nodes.before-2026-11-18   # 戻すための写し
wpctl clear-default                     # 覚えている既定を、積み重ねも含めて、すべて消す（0.4.16 から）
wpctl status                            # 「Audio › Sinks」の、持ち主の出力の番号を読む
wpctl set-default <その番号>              # 持ち主の出力を、ふたたび既定として覚えさせる
grep -c istesso ~/.local/state/wireplumber/default-nodes   # 0 になっていること
```

- 消えるもの：`default-nodes` の、聞くための出力先とテストの出力先の 2 行。**それと、持ち主のほかの機器 3 つの「前に選んだ」記録も消える**（`clear-default` は、まとめて消すため。0.4.16 の項：“Fixed the wpctl clear-default command to completely clear all the default nodes state instead of only the last set default”）。そのため、持ち主の出力がなくなったときの行き先は、機器の優先度で決まるようになる。
- 残るもの：`restore-stream` の古いテストの出力先の音量の 4 行、`default-profile`、`default-routes`、それぞれの機器の音量。
- 2 行めと 4 行めのあいだに、既定が一瞬ほかの機器に移ることがある。そのため、音を鳴らしていないときに行う。

### 提案 1 の結果（2026-11-18 09:50。行っていない）

持ち主は、条件つきで、こちらが行うことを認めた。条件の 1 つは、**こちらの出力先の 2 行だけを消し、持ち主のほかの機器 3 つの記録は残すこと**。WirePlumber を止めず、状態のファイルを横から書き換えずに、それができる形を探したが、**見つからなかった**ので、行っていない。ホストでは、何も変えていない（写しも作っていない）。

- `wpctl clear-default [ID]` は、「既定に選んだノードを消す（ID がなければ、すべて）」（ホストの `wpctl clear-default --help`）。ID は、どの種類の既定か（出力、入力など）を指すもので、積み重ねの中の 1 行は選べない。0.4.16 からは、その種類の積み重ねをまとめて消す。
- `wpctl set-default` は、選んだものを積み重ねの先頭に置くだけで、ほかの行は消えない。
- 0.4.17 の既定を扱う部品（`libwireplumber-module-default-nodes`）には、積み重ねの 1 行を消す口が、見当たらない（`wpctl` のコマンドにも、メタデータのキーにもない）。

### 提案 2：テストと製品の出力先を、既定として覚えられない作りにする（持ち主の返事のあとで、このブランチで変える）

- **既定にしないための、ノードの性質は見つからなかった。** PipeWire の性質の一覧（[pw_keys](https://docs.pipewire.org/group__pw__keys.html)）にも、WirePlumber 0.5 の設定の文書にも、出力先を「既定に選ばない」ものはない。`priority.session`（“priority in session manager”）は、上のとおり、積み重ねには効かない。`node.dont-reconnect` は、流す側（ストリーム）の性質で、関係がない。
- **テストの側：出力先（`Audio/Sink`）として作らない。** テストの取り込みを、出力先ではなく、受け取る側のストリーム（`media.class = Stream/Input/Audio`）として作り、自動ではつながないようにする（`node.autoconnect = false`。pw_keys：“node wants to be automatically connected to a compatible node”）。テストの正弦波は、いまと同じく `pw-link` で、名指しでつなぐ。セッションマネージャーが既定の候補にするのは出力先と入力（`Audio/Sink`、`Audio/Source` など）だけなので（0.4 の作りについての理解。変えたあとに確かめる）、**選べる一覧に出ず、既定にもならず、別のアプリの音も流れ込まない。** `media.class` の意味は pw_keys の “class Ex: "Video/Source"” のとおり。変えるのは `istesso audio serve --source pipewire` のテスト用の選択（たとえば `--as-stream`）で、製品の作りは変えない。名前も、テストごとに変えない（積み重ねを増やさない）。
- **製品の側：出力先は、聞いているあいだだけ作る。** 製品の出力先は、人が選べる出力先である必要があり、選べば積み重ねに入るのは避けられない。そこで、出力先を作るのは聞き始めるときだけにし、止めたら消す（いまの `scripts/istesso-audio.sh start` と `stop` の形）。こうすれば、積み重ねに名前が残っていても、出力先がないあいだは、既定に選ばれない。名前は 1 つに固定する。既定を切り替えるのは、人が「Mac で聞く」を選んだときだけにし、止めるときに、その前の既定（`default.configured.audio.sink`）に戻す（[m2-plan.md](../m2-plan.md) の「出口を選ぶ操作（選んだら既定の出力先を切り替え、やめたら戻す）」）。積み重ねから自分の名前を消すことはしない（WirePlumber の状態のファイルは書かない。4.2）。
- **2026-11-18 に、テストの側を作った**（持ち主が認めた。次の夜の回から使う）：`istesso audio serve --test-input`。性質の上書きの形で、`media.class = Stream/Input/Audio` と `node.autoconnect = false` を先に置く（手で渡した `--node-property` が、あとから勝つ）。ストリームはもともと、自動でつなぐ指定（`AUTOCONNECT`）なしで開いている。単体のテストを足した。**ホストでは、まだ動かしていない**（ポートの名前は、決め打ちせず、`pw-link -i` で読む形にした）。製品の側は、いまの `scripts/istesso-audio.sh` が、すでに「聞いているあいだだけ、1 つの決まった名前（`istesso-audio`）で作る」形になっている。
- 確かめること（変えたあとで）：テストを始めて終えたあと、`default-nodes` の行が前と同じであること、`wpctl status` の出力先の一覧に、テストのものが出ないこと。

**ホストでは、何も変えていません。** 止めたもの、書いたもの、鳴らしたものはありません。
