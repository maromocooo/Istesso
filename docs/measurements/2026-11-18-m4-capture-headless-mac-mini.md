# Mac mini：画面をつながずに、取り込みの速さを設定ごとに比べる（入力なし）

- 日付：2026-11-17 の夜〜18 日（Mac mini の時計で 00:00〜00:05）
- 道具：「Istesso Lock Check Dev」（実行ファイルの SHA-256 は `ee650090` で始まる）。どの回も `--rate` か `--virtual-display` で起動した（入力を送る部分のないクラス。付いていない起動は、走らせる側のスクリプトが断る）
- 目的：[M4 の計画](../m4-plan.md) の 5c の (b)。画面をつながない Mac で、仮想ディスプレイの上の毎秒 85 枚が取れるか。前の回（手順 0b の 4）では、窓が 89 回描かれ、取り込みは約 75 枚だった。
- 結論：
  - **画面をつながないと、仮想ディスプレイの拍（85 Hz）で描かれる**（窓は毎秒 86〜89 回。届く間隔の中央値 11.6〜12.9 ms）。物の画面がつながっているとき（約 60）とは違う。
  - **それでも、取り込みは 85 に届かなかった。** 窓だけで毎秒 71〜76 枚、画面ごとで 69〜78 枚。届く間隔の 95% は約 35 ms：ときどき 2 フレームぶん抜ける。拍ではなく、届ける側で抜けている、と読める（**分かっていない**）。
  - 半分の大きさの窓でも同じ（76 枚）なので、画素の数で頭打ちではない。最短の間隔を 1/85 秒にすると、少し減った（71 枚）。待ち行列 8、420v は、ほぼ変わらない。
  - 代わりの画面（1920×1080、60 Hz）だけのときは、窓が 63 回描かれ、取り込みは 56 枚。画面ごとの取り込みは、取り込める画面の一覧に出ず、始まらなかった。

## ケーブルを挿し直したあと

- 人が挿し直した（00:04 ごろ）。10 秒後（00:04:32）と、30 秒後（00:05:03）に読んだ：**どちらも、代わりの画面（1920×1080、モード 1 つ）のまま**。ディスプレイは 00:04:03 から消えている。眠っている画面は、つなぎ直しても、まだ見つけ直されていない、と読める（**分かっていない**）。こちらでは、起こしも、設定の変更もしていない。
- 前の挿し直し（17:51）では、ディスプレイを点けて読むと、1920×1080（モード 17）になっていた。今回、点いたときに何になるかは、まだ読んでいない。

## 読み取れること

- 画面をつながない Mac（たとえば、しまってある Mac mini や Mac Studio）なら、仮想ディスプレイの拍は 85 Hz になる。物の画面が 60 Hz でつながっていると、拍は 60 にそろう（前の記録）。判定の毎秒 85 枚は、画面をつながない形でしか見込めない。
- ただし、取り込みは拍より 13〜18 枚少ない。抜けは、およそ 35 ms の間隔（2 フレームぶん）として現れる。原因は、この表からは分からない。
- 画面をつながず、「使っている」の合図とディスプレイの主張がないと、何も取れない（前の記録）。製品は、端末がセッションを映しているあいだ、この 2 つを持つ（4.5b）。
