# 手順 3：アプリが描いたら、すぐ出すコンポジター（設定の比較 4）

- 日付：2026-11-16
- コミット：この記録と同じコミット（`scripts/patches/gst-wayland-display-render-on-commit.patch` を足したコミット）
- 目的：コンポジターは、フレームを決まった間隔で描いている。アプリが新しい絵を出しても、次の番が来るまで平均 5.9 ms 待つ（[内訳の記録](2026-11-16-step3-breakdown.md)）。アプリが描いたときに、待たずに描いて出すと、どれだけ縮むかを見る。自前のホスト（手順 4）が行う予定のやり方を、既製のコンポジターへの小さな修正で先に測る。

## 条件

| 項目 | 値 |
|---|---|
| ホスト | Ubuntu 24.04、RTX 4090、GStreamer 1.24.2、gst-wayland-display（`1301f86`）。フレームは CUDA のメモリーで渡す。レート制御のバッファーは 353 kbit（[記録](2026-11-16-step3-moving-picture.md)） |
| クライアント | MacBook Air（M4）、macOS 26.5.1。VideoToolbox で復号 |
| 接続 | ホストは有線。Mac は Wi-Fi（5 GHz 帯のチャンネル 44、共有の機能は元の設定） |
| 解像度とフレームレート | 1720×720 と 3440×1440、85 fps（修正したコンポジターでは、下のとおり増える） |
| クライアントのディスプレイ | 外部（3440×1440、84.96 Hz）。2 つの窓は前面に出さずに起動。3440×1440 の絵は、1720×720 の窓に縮めて出した |
| コーデックとビットレート、経路 | H.265、30 Mbps。RTP を UDP で。暗号化なし |

### 修正の中身

コンポジターのプラグイン（MIT ライセンス）に当てる修正を、`scripts/patches/gst-wayland-display-render-on-commit.patch` に置きました。75 行の変更です。

- これまで：フレームを求められると、前のフレームから 1 フレームぶんの時間がたつまでタイマーで待ってから描く。
- 修正後：待っているあいだにアプリが新しい絵を確定したら、その場で描く。求められる前にアプリが確定していたら、待たずに描く。アプリへの「次のフレームを描いてよい」の知らせは、これまでどおり 1 フレームぶんの時間に 1 回にとどめる。

タイマーは残してあるので、何も変わらないときも 1 フレームぶんの時間ごとにフレームが出ます。85 fps で描くアプリでは、タイマーの分とアプリの分が重なり、フレームの数が増えます（下の表）。実験のための修正で、ここは直していません。

## わかったこと

1. **アプリが描いたらすぐ出すと、1720×720 の動く絵で、中央値の差が 19.7 ms から 11.9 ms に下がりました。** 95 パーセンタイルは 24.0 ms から 13.9 ms です。Mac が Wi-Fi のままで、どちらも合格ラインの数値（12 ms、24 ms）の内側に入りました。
2. **縮んだのは、ほぼコンポジターの区間だけです。** 9.1 ms が 1.9 ms になりました。決まった間隔を待つ時間（平均 5.9 ms）がなくなり、さらに 1.3 ms ほど縮んでいます。
3. **3440×1440 では、中央値の差が 27.4 ms から 18.3 ms に下がりましたが、ラインにはまだ 6.3 ms あります。** 95 パーセンタイル（22.8 ms）はラインの内側です。コンポジターの区間に 5.5 ms が残っています。テストアプリが CPU で描いた 20 MB を、コンポジターが毎回 GPU に上げる時間が入っています（[動く絵の記録](2026-11-16-step3-moving-picture.md)）。
4. **残りの中身は、ネットワークと、Mac の画面に出るまでです。** D の差（平均で約 18.7 ms）は、ネットワーク 6.5 ms、コンポジター 5.5 ms、圧縮まで 2.7 ms、フレームが届くまで 0.7 ms、復号 2.4 ms、描くまで 0.3 ms、画面に出るまでの手元の窓との違い 0.7 ms、です。ネットワークは、Mac を有線にすると縮むはずです（測っていません）。
5. **フレームの数が増えています。** 85 fps で描くアプリに対して、1 秒に 108〜118 フレームが出ました。タイマーの分が余計です。自前のコンポジターでは、何も変わらないときにだけ間を空けて出すようにします。

読むときの注意：

- 修正は実験のためのものです。アプリが確定した絵に変化がなくても、フレームを出します。
- 手順 4 では、同じことを自前のコンポジターで行います。この記録の値は、そのときに下回ってはならない目安になります。
- 灰色の絵と、既製の部品のままの値は、[最初の 1 本の記録](2026-11-16-step3-first-path.md)からの一連の記録にあります。この日の朝の最初の値（中央値の差 19.5 ms、灰色の絵、6 GHz 帯）とは、絵も Wi-Fi も違うので、じかには比べられません。
