# 手順 3：フレームを GPU の外に出さずにエンコーダーへ渡す（設定の比較 2、未解決）

- 日付：2026-11-16
- コミット：この記録と同じコミット（`scripts/m1-step3-host.py` に `--gpu-frames` を足したコミット）
- 目的：[内訳の記録](2026-11-16-step3-breakdown.md)で、コンポジターが描き始めてからフレームを出すまでの時間（1720×720 で約 3.3 ms、3440×1440 で約 10 ms）と、エンコーダーの手前で GPU に上げ直す時間は、画素数とともに増えることが分かった。フレームをメインメモリーに出さず、GPU の上のまま渡せば、この時間がなくなるかを見る。
- 結論：**まだ測れていません。** パイプラインは動きますが、映像が最初の絵のまま変わりません。

## 条件

| 項目 | 値 |
|---|---|
| ホスト | Ubuntu 24.04、RTX 4090（ドライバー 590.48.01）、GStreamer 1.24.2、gst-wayland-display（`1301f86`） |
| クライアント | MacBook Air（M4）、macOS 26.5.1。通しの確認にだけ使った |
| 接続 | ホストは有線、Mac は Wi-Fi |
| 解像度とフレームレート | 1720×720 と 3440×1440、85 fps |
| クライアントのディスプレイ | 外部（3440×1440、84.96 Hz） |
| コーデックとビットレート、エンコーダーの設定、経路 | [最初の 1 本の記録](2026-11-16-step3-first-path.md)と同じ |

変えたのは、コンポジターからエンコーダーまでの区間です（`scripts/m1-step3-host.py --gpu-frames`）。

```text
これまで： waylanddisplaysrc ! video/x-raw（RGBx、メインメモリー） ! cudaupload ! cudaconvert ! NV12（CUDA） ! nvcudah265enc
試した形： waylanddisplaysrc ! video/x-raw(memory:DMABuf) ! glupload ! glcolorconvert ! RGBA（OpenGL） ! cudaupload ! cudaconvert ! NV12（CUDA） ! nvcudah265enc
```

OpenGL は、窓の仕組みなしで使っています（`GST_GL_PLATFORM=egl`、`GST_GL_WINDOW=surfaceless`）。

## 結果

動いたこと：

- パイプラインは、エラーなく `PLAYING` になり、85 fps でフレームが流れます（約 100 秒で 8,232 フレーム）。
- OpenGL は、デスクトップのセッションがなくても、NVIDIA の GPU の上で動きます（`GL_RENDERER` が RTX 4090）。デスクトップの X11 の画面を使う形でも、同じように動きました。

動かなかったこと：

- **映像が、最初の絵のまま変わりません。** ホストだけで合成の入力を 300 回送っても、圧縮したフレームの大きさは 1 度も変わりませんでした（1720×720 でも 3440×1440 でも）。同じ計測を、メインメモリーを通す形で行うと、300 回のうち 295 回で、色が変わったフレームを大きさから見つけられます（残りの 5 回はキーフレームに重なった）。
- Mac まで通しても同じです。中継した窓には灰色の絵が出ますが、30 回の入力に 1 度も反応しませんでした。手元の窓は 30 回とも反応しています。

どこで絵が止まっているか（コンポジターの出力か、OpenGL への取り込みか、CUDA への受け渡しか）は、調べていません。

カメラでの計測：行っていません。

## わかったこと

- この機材では、GStreamer の部品だけで、フレームを GPU の上のままエンコーダーまで運ぶ形を組めます。デスクトップのセッションも要りません。
- ただし、固定しているコンポジターのコミットとの組み合わせでは、絵が更新されません。画素を運ぶ時間がなくなるかどうかは、まだ分かりません。

次に行うこと：

- 絵が止まっている場所を特定する。`glcolorconvert` のあとでメインメモリーに戻して（`gldownload`）、中央の色が入力で変わるかを見れば、コンポジターと取り込みの側か、CUDA への受け渡しの側かを分けられる。
- 新しい gst-wayland-display（GStreamer 1.28 以上が要る）で同じことが起きるかは、確かめていない。新しい GStreamer を別に用意するかどうかの判断（m1-plan.md の手順 3）と合わせて考える。
