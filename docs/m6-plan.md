# M6 の進め方：エージェント連携（計画）

M6 は、コーディングエージェントが、どの PC で何を動かすかを自分で覚えなくても、正しい PC でビルド、実行、デプロイができるようにする段階です（R-10）。

この文書は、2026-11-17 に書いた計画です。次の 3 つを分けて書きます。

- [milestones.md](milestones.md) と [requirements.md](requirements.md) に、すでに書いてあること。
- **提案**。この流れが考えた案です。決定ではありません。見出しか行に「提案」と書きます。
- 持ち主が決めること（「6. 持ち主に決めてほしいこと」に、1 つの一覧でまとめました）。

**2026-11-17 の 10:30 と 10:35 に、持ち主が、6. の一覧に答えました。** 答えは 6. に書いてあります。決まったものには「決定」と書きました。1 は、まだ決まっていません。手順 1〜5 は、この計画をもとに、別の流れが作ります（`m6-route` ブランチ）。作るための細部は、4.8 にまとめました。

読むときの注意：

- **この計画を書いた時点では、コードは 1 行も書いていません。実機では、何も動かしていません。** 読んだのは、文書と、いまのコードの公開されている型と、この Mac に入っている herdr（0.9.5）のヘルプの表示だけです。
- ADR 0010（`m3-app-manager` ブランチ）、ADR 0013 と ADR 0014（`plan-m4-m5` ブランチ。どちらも状態は「提案」）、ADR 0015（`m1-dialog-windows` ブランチ）は、まだ `main` にありません。リンクにせずに、番号で指します。
- 規約は先に [AGENTS.md](../AGENTS.md) を読んでください。

## 0. 言葉

「エージェント」が 2 つの意味で使われています。この文書では、次のように呼び分けます。

| 語 | 意味 |
|---|---|
| ホストエージェント | 各 PC で動かしておく `istesso agent`。ペアリング済みの端末からの問い合わせに答える（[ADR 0007](adr/0007-control-channel.md)） |
| コーディングエージェント | ターミナルで動く、コードを書く AI の道具。M6 の「エージェント連携」の相手は、こちら |
| 役割表 | `istesso doctor --json` が出す、その PC にできることの一覧（`roles`、`tools`、OS、GPU など）。全端末のぶんは `istesso hosts --json` で出る |
| タスク | プロジェクトが名前を付けた、ビルド、実行、デプロイの 1 つ |
| 必要条件 | タスクが、動かす PC に求めるもの（例：`xcode_build` の役割がある） |
| 行き先 | 必要条件から決まった、タスクを動かす PC |
| 入口 | AGENTS.md や CLAUDE.md に書く、「ビルド、実行、デプロイは、このコマンドで」という 1 行 |

## 1. M6 は何のためか

### 1.1 書いてあること

[milestones.md](milestones.md) の M6 は、次の 3 行です。

> - `istesso run` / `istesso build` / `istesso deploy`（必要条件から行き先を決める）
> - エージェント向けスキルと、Gate に載せる確認項目
> - herdr を専用ユーザーで動かす手順

もとになる要件は、[requirements.md](requirements.md) の R-10 です。

> - 各ホストが `istesso doctor` で役割表を出す。
> - ビルド・実行・デプロイは振り分けコマンド経由にし、必要条件から行き先を自動で決める。
> - AGENTS.md / CLAUDE.md には入口だけを書く。
> - herdr の Gate（必須要件リスト）に「デプロイ先を確認済み」を常設できるようにする。

関係する要件が、ほかに 2 つあります。

- R-07（隔離）：コーディングエージェントが読めるのは、隔離領域だけにする。プロセスごと、専用ユーザーで動かす。ツールの側のサンドボックスは、二重の柵として併用する。
- R-01 の 2 番目：文字は、ターミナルで直接つなぐ。herdr のセッションは、ホストの側に常駐する。

R-10 の 1 行目（役割表）は、M0 でできています。いまは、[AGENTS.md](../AGENTS.md) の「どこで何を動かすか」の表を、コーディングエージェントが読んで、行き先を自分で選んでいます。M6 は、この表の仕事を、コマンドに移すものです。

### 1.2 受け入れ条件

**milestones.md の M6 には、受け入れ条件が書かれていません。「場所」も書かれていません。** 引用できる条件は、ありません。

`plan-m4-m5` ブランチの milestones.md には、2026-11-16 の決定として、「M5、M6、M7、M9 には、受け入れ条件がまだ書かれていない。それぞれの流れが、先に条件を書く」とあります。同じ決定は、各流れの受け入れ条件に「ホストを起動した直後（ログイン画面のまま、SSH だけ）の状態で動く」を足すことも求めています。この 2 つに従って、条件の**案**を「2.」に書きました。案を条件にするかどうかは、持ち主が決めます（6. の 1）。

## 4. いま作れる部分の提案

この節は、全部が提案です。

### 4.1 置き場所

本線（M1〜M3）が `main` に入っていないので、ほかの流れとぶつからない場所にだけ、置きます。

| もの | 場所 | メモ |
|---|---|---|
| 行き先を決めるライブラリと、確かめるためのコマンド | 新しいクレート `crates/istesso-route/` | ワークスペースは `crates/*` をまとめて読むので、登録のために `Cargo.toml` を直す必要はない。変わる共有のファイルは、`Cargo.lock` だけ |
| スキルと、入口のひな形 | 新しいクレートの中の `crates/istesso-route/agent/`（`agent/skill/SKILL.md`、`agent/entry.md`） | 持ち主の答え（2026-11-17）は、「新しいクレートの中だけで作る」である。はじめの案（リポジトリの根の `agent/`）を、クレートの中に移した |
| ブランチと作業ツリー | この計画のブランチ（`plan-m6`）の上に切った `m6-route`。ドラフトの PR は、`plan-m6` に向ける | このクレートが使う型とコマンドは、全部 `main` にある。計画と一緒に読めるように、計画の上に重ねた |

**直さないもの：** `istesso-proto`、`istesso-link`、`istesso-pair`、`istesso-agent`、`istesso-cli`、`istesso-catalog`、`istesso-doctor`。ADR 0006 と ADR 0007 の手順。メッセージも、権限も、足しません。

コマンドは、はじめは `istesso-route` という別のコマンドにします。`istesso` コマンドの定義は 1 つのファイルにあり、ほかの流れが、同じファイルにコマンドを足しているためです。M7 の流れも、同じ理由で `istesso-devices` を別にしています。本線が `main` に入ったら、`istesso run`、`istesso build`、`istesso deploy` として移します。

依存は、足しません。必要条件のファイルは JSON なので、すでにある `serde_json` で読めます（6.2 の 4）。コマンドの引数は、`istesso` コマンドと同じ `clap` で読みます。ワークスペースに、すでにある部品です。

### 4.2 口

**必要条件のファイル（プロジェクトに置く）。** プロジェクトの根の `.istesso/tasks.json`（決定、2026-11-17。版の番号を持たせる。読む側は、知らない項目を読み飛ばす）。

```json
{
  "version": 1,
  "tasks": {
    "test":    { "kind": "build",  "needs": { "tools": ["cargo"] },
                 "command": ["cargo", "test", "--workspace"] },
    "mac-app": { "kind": "build",  "needs": { "roles": ["xcode_build"] },
                 "command": ["xcodebuild", "-scheme", "App"] },
    "encode":  { "kind": "run",    "needs": { "os": "linux", "roles": ["gpu", "hardware_encode"] },
                 "command": ["./tools/encode-check"] },
    "site":    { "kind": "deploy", "needs": { "roles": ["always_on_candidate"] },
                 "command": ["./tools/publish"] }
  }
}
```

- `needs` に書けるのは、いまの役割表にある項目だけにする：`roles`（全部を満たすこと）、`os`、`arch`、`tools`（`cargo`、`docker`、`gstreamer`、`xcode`）、`host`（人が名指しした PC）。役割表を変えずに始めるためである。
- `command` は、引数の並びで書く。シェルは通さない。
- **版の番号**（決定）：`version` は必ず書く。いまは 1。項目を足すだけの変更では、番号を上げない。意味が変わる変更で、上げる。読む側は、自分の知らない番号のファイルを、読まずに断って、両方の番号を表示する（制御チャンネルの版と同じ考え方。ADR 0007）。
- **知らない項目は、読み飛ばす**（決定）。ファイルの直下と、タスクの中の、知らない項目は、無視する。種類（`kind`）を知らないタスクと、形が読めないタスクは、そのタスクだけを読み飛ばす。ほかのタスクは、読める。読み飛ばしたものは、尋ねられたときに理由を答えられるように、覚えておく。
- **`needs` の中だけは、黙って読み飛ばさない**（提案）。知らない項目、知らない役割、知らない道具が `needs` にあるタスクは、読むが、「この版では決められない」と答える。満たしたことにはしない。条件を 1 つ落として決めると、条件を満たさない PC で動かすことになるためである。
- PC の名前を書くのは、`host` だけである。書かなくて済むなら、書かない。このファイルは、コミットして、ほかの人と分け合うことがある。PC の名前は、そこに書かないほうがよい（下の「覚えた行き先」）。

**役割表（入力）。** `istesso hosts --json` の出力を、そのまま読みます。`main` にある形です。読むのは、端末の ID、名前、手元かどうか、状態、役割表、負荷、最後に答えた時刻だけで、ほかの項目は無視します。渡し方は、ファイルか標準入力から始めます（`istesso hosts --json | istesso-route where build test`）。

**コマンド（案）。**

| コマンド | 動き |
|---|---|
| `istesso-route where <build\|run\|deploy> <タスク> [--hosts <ファイル>] [--json]` | 行き先と理由を答える。何も動かさない |
| `istesso-route check deploy <タスク>` | デプロイ先が、ただ 1 つに決まり、いま答えているかを、終了コードと 1 行で答える。Gate には頼らず、これだけで使える。Gate ができたら、項目「デプロイ先を確認済み」を確かめる手段になる（1.3 の 1） |
| `istesso-route run <タスク>`（`build`、`deploy` も同じ） | 行き先が手元なら、手元で動かす。ほかの PC なら、行き先と理由を出して、決まった終了コードで止まる。**ほかの PC では、まだ動かさない** |
| `istesso-route choose <タスク> <PC> [--hosts <ファイル>]` | 人が選んだ行き先を、覚える（下の「覚えた行き先」）。もう一度実行すると、替わる。選んだ PC が必要条件を満たすかを確かめるので、役割表を読む |
| `istesso-route forget <タスク>` | 覚えた行き先を、忘れる |
| `istesso-route choices` | 覚えている行き先と、ファイルの場所を並べる |

終了コードは、「決まった」「満たす PC がない」「満たす PC が答えない」「デプロイ先が 1 つに決まらない」「ファイルが読めない」「この版では決められない」「行き先がほかの PC なので、動かしていない」を分けます。コーディングエージェントが、文を読まずに分かるようにするためです。出力には、鍵も、アドレスも出しません。

**覚えた行き先（2026-11-17 の決定と、その細部の提案）。**

決定：デプロイ先が 2 台以上に当てはまるときは、止まって、並べる。**いちど PC を選んだら、そのタスクについては覚えておき、次からは尋ねない。** 選んだ内容は、設定に書かれ、あとから変えられる。理由（持ち主）：毎回止まるなら、使われなくなる。

細部は、提案です。

| こと | 案 | 理由 |
|---|---|---|
| 置き場所 | **端末ごと、ユーザーごとの設定のファイル。** プロジェクトの `.istesso/` には置かない。既定は、macOS では `~/Library/Application Support/istesso-route/choices.json`、ほかでは `$XDG_CONFIG_HOME/istesso-route/choices.json`（なければ `~/.config/istesso-route/`）。`ISTESSO_ROUTE_DIR` で変えられる（テストは、必ず一時フォルダーに向ける） | `.istesso/tasks.json` は、コミットして、ほかの人と分け合うことがある。そこに PC を書くと、ほかの人の環境では合わない。PC の名前や ID が、公開のリポジトリに載ることにもなる。選んだのは、その人の、その端末での答えである |
| Istesso の設定の場所と分ける | 端末の鍵とペアリングの一覧がある場所（`istesso id` が表示する Config）には、置かない | そこは、二重の柵で、コーディングエージェントから読めなくする場所である（9. の 4）。行き先を尋ねるのに、鍵のある場所を読ませない |
| 何で覚えるか | PC は、**役割表が使っている ID** で覚える（鍵の指紋。見せてよい値）。名前は、表示のために一緒に書くが、照らし合わせには使わない。タスクは、プロジェクトの根の場所と、タスクの名前の組で覚える | 名前は、変えられる。同じ名前の PC が、2 台ありうる。ID は、ペアリングし直して鍵が変わらないかぎり、同じである。プロジェクトを名前ではなく場所で区別するのは、別のプロジェクトの同じ名前のタスクと、取り違えないためである |
| 選び方 | 止まったときの表示に、当てはまる PC と、`istesso-route choose <タスク> <PC>` を出す。PC は、ID でも、名前でも指せる（名前が 2 台に当てはまるときは、断る）。選べるのは、役割表にあって、そのタスクの必要条件を満たす PC だけ | 選ぶのは、人である。コーディングエージェントは、自分では選ばず、人に尋ねてから、このコマンドを実行する（スキルに書く）。コマンドは、端末の前の人に尋ねる形にしない。コーディングエージェントの中では、答える人がいないためである |
| 覚えた PC が、当てはまり、答えているとき | そこへ行く。尋ねない | 決定のとおり |
| 覚えた PC が、当てはまるが、答えないとき | 止まる。ほかの PC には、行かない。起こせる PC なら、そう出す | 人が選んだ先を、黙って替えない |
| 覚えた PC が、もう当てはまらない、または、役割表にないとき | **止まって、もう一度並べる。理由を出す**（例：「覚えていた PC は、役割 `always_on_candidate` を、もう持っていない」「覚えていた PC は、ペアリング済みの端末の中にない」）。当てはまる PC が 1 台だけ残っていても、止まる。人が、選び直すか、忘れさせる | 行き先が、人の知らないうちに替わることになるため。忘れさせたあとは、覚えていないときと同じ決まりに戻る（1 台だけなら、そこへ行く） |
| 変える、忘れる | `choose` をもう一度（替わる）。`forget`（消える）。ファイルを直接書き換えてもよい | 決定のとおり（設定に書かれ、あとから変えられる） |
| 答えに出すこと | `where` と `check deploy` の答えは、行き先が覚えた選択から来たときに、そう出す。いつ選んだかも出す。`--json` では、`remembered` の項目に入る | 人が、なぜそこへ行くのかを、あとから分かるように |
| ファイルの形 | JSON。`version` を持つ（いまは 1）。読む側は、知らない項目を読み飛ばし、書き直すときも、消さない。知らない番号のファイルと、読めないファイルは、使わずに止まって、場所を出す。書き換えない | 必要条件のファイルと同じ決まり。壊れたファイルを、黙って上書きしない |
| ビルドと実行 | 覚えない。順で選ぶので、尋ねることがない。`choose` は、ビルドと実行のタスクを断る | 決まりを、小さく保つ |

分かっている不足：プロジェクトを場所で区別するので、同じプロジェクトの作業ツリーを 2 つ持つと、作業ツリーごとに 1 回ずつ尋ねられます。足りなければ、必要条件のファイルにプロジェクトの名前を書けるようにします。

pub const TASKS_VERSION: u32 = 1;

pub enum TaskKind { Build, Run, Deploy }
pub enum Tool { Cargo, Docker, Gstreamer, Xcode }

/// What a task needs from the machine it runs on. Every field narrows the

    pub roles: Vec<Role>,          // istesso_proto::Role; all of them
    pub os: Option<OsFamily>,      // istesso_proto::OsFamily
    pub arch: Option<String>,      // as the role table writes it, e.g. "aarch64"

    pub host: Option<String>,
}

    pub name: String,
    pub kind: TaskKind,
    pub needs: Needs,
    /// Needs this version does not know, as they were written ("roles: quantum",
    /// "gpu_memory"). A task that has any is never decided.
    pub unknown_needs: Vec<String>,
    /// Program and arguments; no shell. Empty: the task can be asked about,
    /// not run.
    pub command: Vec<String>,
}

    pub tasks: BTreeMap<String, Task>,

    /// kind, tasks whose shape it cannot read.
    pub skipped: Vec<Skipped>,
}

    NotJson(String),
    NoVersion,
    /// The file is of a version this reader does not know.
    Version { found: u64, known: u32 },

}

/// Looks for `.istesso/tasks.json` in `start` and its parents. Returns the
/// file and the project's root (the folder that holds `.istesso`).
pub fn find_tasks(start: &Path) -> Option<(PathBuf, PathBuf)>;

/// One machine as `istesso hosts --json` shows it; other fields are ignored.
pub struct Candidate {
    pub id: String,
    pub name: String,
    pub local: bool,
    pub state: HostState,                 // Awake: it answered just now
    pub manifest: Option<HostManifest>,   // from the answer, or remembered
    pub status: Option<HostStatus>,       // load; only when it answered
    pub seen_at: Option<u64>,
}

/// An entry without id or name is skipped. A role table in a shape this
/// version cannot read leaves `manifest` empty; the machine stays in the list.
pub fn read_table(text: &str) -> Result<Vec<Candidate>, TableError>;

// ---- decide.rs --------------------------------------------------------------

pub struct Place { pub id: String, pub name: String, pub local: bool }
pub struct Asleep { pub place: Place, pub wake_possible: bool, pub seen_at: Option<u64> }
pub struct Lack { pub place: Place, pub lacks: Vec<String> }

/// A choice a person made for one task of one project (choices.rs).
pub struct Remembered { pub host: String /* id */, pub name: String, pub chosen_at: u64 }
/// Why a remembered choice cannot be used any more.
pub enum Stale { Gone, NoLongerMeets(Vec<String>) }

pub enum Decision {
    /// Run it there. `because` names the needs it meets and why it came first.
    /// `remembered`: when the person chose it, if the place is a remembered choice.
    Go { place: Place, because: Vec<String>, remembered: Option<u64> },
    /// Machines meet the needs, but none of them answers. Nothing else is tried.
    Stopped { places: Vec<Asleep>, remembered: bool },
    /// A deploy task and no single place: more than one machine meets the
    /// needs and none was chosen, or the chosen one cannot be used (`stale`).
    Ambiguous { places: Vec<Place>, stale: Option<(Remembered, Stale)> },
    /// No machine meets the needs; says what each one lacks.
    Nobody { lacking: Vec<Lack> },
    /// The task states needs this version does not know.
    NotUnderstood { needs: Vec<String> },
}

pub enum SeveralMatch { StopAndList, PickInOrder }
/// The one place that says what happens when several machines meet the needs
/// of a task: build and run pick in order, deploy stops and lists.
pub fn when_several_match(kind: TaskKind) -> SeveralMatch;

/// What `candidate` lacks for `needs`, in words; empty when it meets them.
pub fn lacks(needs: &Needs, candidate: &Candidate) -> Vec<String>;

pub fn decide(task: &Task, table: &[Candidate], remembered: Option<&Remembered>) -> Decision;

/// `ISTESSO_ROUTE_DIR`, or the platform's place for settings + "istesso-route".
pub fn choices_dir() -> PathBuf;

pub struct Choices { /* the path and the file as JSON, unknown items kept */ }
impl Choices {
    /// A missing file is an empty list. A file that cannot be read, or one of
    /// an unknown version, is an error; it is never overwritten.
    pub fn load(path: &Path) -> Result<Choices, ChoicesError>;
    pub fn get(&self, project: &Path, task: &str) -> Option<Remembered>;
    pub fn set(&mut self, project: &Path, task: &str, place: &Place, now: u64);
    pub fn forget(&mut self, project: &Path, task: &str) -> bool;
    /// Writes a new file next to the old one and renames it; owner-only (0600).
    pub fn save(&self) -> Result<(), ChoicesError>;
}

/// (M5) and an ADR for running on other machines exist, there are two

pub trait Executor {
    /// `root` is the project's root; the command runs there. Returns the

    fn run(&mut self, place: &Place, task: &Task, root: &Path) -> Result<i32, ExecError>;
}

### 4.3 決め方

0. 知らない必要条件のあるタスクは、決めない（`NotUnderstood`）。
1. 必要条件を満たさない PC を外す。外した理由を、PC ごとに覚える。役割表が分からない PC（`manifest` がない）は、必要条件が空のときだけ、満たす。`host` が書いてあれば、ID か名前がそれと同じ PC だけを残す。1 台も残らなければ、`Nobody`。
2. ビルドと実行は、残った中から、「手元 → 起きているホスト → 負荷の低いホスト」の順で選ぶ。アプリの起動先（R-04）と同じ順である。決まりを 1 つにして、説明を 1 つで済ませるため。「答えている」とは、手元の PC であるか、状態が `awake` であること。負荷が分からない PC は、分かる PC のあと。同じなら、名前の順。
3. 満たす PC が、どれも答えないときは、止まる（`Stopped`）。満たさない PC では、動かさない。
4. **デプロイは、順で選ばない**（決定、2026-11-17）。満たす PC が 2 台以上あれば、止まって、並べて見せる。答えていない PC も、数に入れる（起きているほうを黙って選ぶと、順で選ぶのと同じになる）。人が、行き先を選ぶ。選んだ行き先は、覚えておき、次からは尋ねない（4.2 の「覚えた行き先」）。この決まりは、コードの 1 か所（`when_several_match`）に置く。
5. 答えない PC の役割表は、最後に見えた内容である。行き先の手がかりにはするが、信頼の根拠にはしない（ADR 0007 と同じ扱い）。出力に、いつの内容かを出す。

`project` は、プロジェクトの根の場所（リンクをたどった、絶対の場所）。`host` は、役割表の ID。`name` は、表示のためだけ。

**終了コード。** タスクを手元で動かしたときは、そのタスクの終了コードを、そのまま返します。下の番号は、ふつうのコマンドが使わない所に置きます。

| コード | 意味 |
|---|---|
| 0 | 行き先が決まった。`run` などでは、タスクが 0 で終わった |
| 2 | コマンドの書き方がまちがっている |
| 70 | 必要条件を満たす PC がない |
| 71 | 満たす PC はあるが、答えない |
| 72 | デプロイ先が、1 つに決まらない（選んでいない。覚えた行き先が、もう使えない） |
| 73 | ファイルが読めない、タスクがない、種類が合わない（必要条件のファイル、役割表、覚えた行き先のファイル） |
| 74 | この版では決められない必要条件がある |
| 75 | 行き先はほかの PC である。動かしていない |

**表示の形（英語）。** 1 行目に結論、2 行目から理由を、字下げして出します。`check deploy` は、1 行だけです。`--json` は、`task`、`kind`、`decision`（`go`、`stopped`、`ambiguous`、`nobody`、`not_understood`）と、その中身を出します。

```text
deploy `site` goes to: tower
  it has the role always_on_candidate
  chosen for this task on 2026-11-17 (remembered; `istesso-route choose` changes it, `istesso-route forget` drops it)

deploy `site` has no single place: 2 machines meet its needs
  tower (9f8e-7d6c-5b4a-3921)
  mini (5d4c-3b2a-1f0e-9d8c)
  the remembered choice, tower, no longer has the role always_on_candidate
  choose one: istesso-route choose site <machine>
```

**手元で動かす。** `command` の 1 つ目に `/` が入っていて、絶対の場所でなければ、プロジェクトの根からの場所として読む。作業の場所は、プロジェクトの根。標準入出力は、そのまま渡す。シェルは通さない。役割表は、`--hosts <ファイル>` か、標準入力から読む。標準入力が端末のときは、渡し方を表示して 73 で終わる。

**必要条件のファイルを探す範囲と、使ってよいファイル（2026-11-17 に足した。作った流れが受けたセキュリティの指摘による）。** `.istesso/tasks.json` に書いたコマンドは、このユーザーの権限で動くので、ほかの人が置けるファイルを使わない。探すのは、いまのフォルダーから、プロジェクトの根（上へたどって最初に `.git` がある所。ファイルでもフォルダーでもよい）までに限る。`.git` がなければ、いまのフォルダーだけを見る。`.git` を探すのも、ホームより上には行かず、ファイルシステムの根は見ない。いまのフォルダーは、最初に 1 回だけ実の場所に直す。ファイルと `.istesso` フォルダーがリンクのときは、その先がプロジェクトの根の中にあるときだけ使う。Unix では、ファイルと `.istesso` フォルダーが、いまのユーザーのものであり、グループとほかの人が書けないことを確かめる（Windows など、ほかでは持ち主を確かめない。範囲とリンクの決まりは同じ）。満たさないファイルは、黙って飛ばさず、理由を出して止まる。終了コードは、70〜75 に空きがないので、「ファイルが読めない」と同じ 73 を使う。タスクのコマンドは、これまでどおり、シェルを通さず、引数は書いたまま渡し、作業の場所はプロジェクトの根（`.istesso` のあるフォルダー）にする。

| 場所 | 確かめること |

Tasks are in `.istesso/tasks.json`.」の 1 行。

## 5. 安全

### 5.1 いまの状態

- 権限は、端末ごとに付きます（R-13、[ADR 0006](adr/0006-pairing.md)）。新しくペアリングした端末は、「閲覧」と「操作」を持ちます。
- コーディングエージェントは、いま、ふだんのユーザーで動いています。そのユーザーが読める端末の鍵を、読めます。
- **制約（2026-11-17 に、持ち主が了解した）：M5 が身元を分けるまで、同じ端末の上の人と、コーディングエージェントは、区別できない。** 権限は端末ごとに付き、プロセスごとには付かないためです。相手の PC から見ると、どちらも、その端末です。その端末が持つ権限は、その上のコーディングエージェントも、そのまま使えます。セッションを映している端末の上のコーディングエージェントは、「映している端末」として扱われます。
- だから、それまでは、「エージェントにだけ与える権限」も、「エージェントからだけ外す権限」も、作れません。分けるには、エージェントが別の身元で動くことが要ります（3.2 の 3）。

これは、M6 が足すものではなく、いまの状態です。M6 のいま作れる部分は、これを広げません。

### 5.2 いま作れる部分が使う権限

- 使うのは、役割表と負荷の問い合わせだけです。どちらも、いまある「閲覧」のメッセージです（[ADR 0007](adr/0007-control-channel.md)）。役割表をファイルから渡す形では、通信もしません。
- メッセージ、権限、暗号の手順には、何も足しません。ADR 0006 と ADR 0007 は、変えません。
- root も、OS の許可も、要りません。
- ほかの PC では、何も動かしません。手元で動かすタスクは、プロジェクトのファイルに書いてあるコマンドで、コーディングエージェントが自分で打てるものと同じです。
- 表示とログに、鍵、トークン、ペアリングコードを出しません。タスクのコマンドの引数に秘密を書かない、とスキルに書きます（引数は、同じ PC のほかのユーザーから見えます）。

### 5.5 エージェントに渡さないもの

2026-11-17 に、次の 3 つが決まっています（ADR 0010 の「人が決めたこと」の 13〜15）。

- 入力を送れるのは、そのセッションを映している端末だけ。
- 入力を開くときの権限は、頼まれたときに読み直した値を使う。
- 映像を受け取れるのは、映している端末だけ。

同じ決定は、「映していない端末やエージェントからの操作」を、将来の項目として残しています。別の機能として、はっきりした権限を付けて作るもので、いまは作りません。

M6 は、これに従います。**M6 が作るどの部分も、セッションに入力を送らず、映像を受け取らず、セッションを始めも止めもしません。** 「タスク」の権限は、セッションのどの操作も許しません。窓の要るものは、人が `istesso open` で開きます。

| 6 | 「Gate」とは何か | **herdr にいまある機能ではない。持ち主が設計している途中で、まだ作られていない。** 持ち主が持っておく、いつも満たしていなければならない要件の一覧（文の項目）で、コーディングエージェントが、答える前に自分で確かめる。満たしていれば、印を付けて報告し、満たしていなければ、作業に戻る。**M6 は、これに頼らない。名前だけを、文書に残す**（1.3 の 1） |
| 7 | ほかの PC でタスクを動かす方式の、方向 | **(a)：タスクの名前だけを運ぶメッセージと、新しい権限。** ADR が先である。いまは、何も作らない（5.3、5.4）。採らなかった方向：コマンドラインをそのまま送る（リモートのシェルと同じ強さの権限になる）。Istesso では運ばず、SSH や herdr に任せる（一覧から失効させても切れない） |

| — | 見つけた食い違いのうち 2 つ（9. の 4 と 5） | **了解。** 「M5 が身元を分けるまで、同じ端末の人とコーディングエージェントは、区別できない」を、制約として書いた（5.1） |

## 7. あとで、持ち主の手が要るもの

**M1 の確定の判定が終わるまで、持ち主の手が要る作業は、ありません。** 手順 1〜5 は、権限も、インストールも、実機のペアリングの変更も、要りません。

下は、判定のあと、M5 と一緒に要るものです。頼むときは、ほかの流れの依頼と、1 つの一覧にまとめます。

| いつ | 何を | メモ |
|---|---|---|
| M5 の手順 5 のとき | 専用ユーザーを作る（M5 の依頼。M6 のぶんは、増えない） | root か管理者 |
| 同じとき | 専用ユーザーの中に herdr を入れる。手元からつなぐ道を作る（herdr の、SSH でつなぐ機能を使う。SSH の鍵を 1 つ置く） | 管理者の権限が要るかは、まだ調べていない |
| 手順 8 以降 | 各ホストで、エージェントの身元に「タスク」の権限を与える | コマンド 1 つの見込み。権限を与えるコマンドは、いまはまだない |
| 同じとき | Apple 向けのビルドと署名を専用ユーザーで行うなら、証明書を、そのユーザーのキーチェーンに入れる | ADR 0003 の「結果」 |
| 条件 G のとき | herdr の上で、コーディングエージェントを 1 回動かして、目印のファイルが読めないことを一緒に見る | 10 分ほどの見込み |
| 条件 H のとき | ホストを起動し直す回に、一緒に確かめる | そのためだけの再起動は、頼まない |

## 8. 範囲の外

1 行目と最後の行は、決定です。ほかは、この流れの線の引き方です（提案）。

- 映していない端末や、コーディングエージェントから、セッションを操作すること。ほかの人に画面を見せること（2026-11-17 の決定で、将来の項目）。
- 専用ユーザーを作ること、隔離領域を作ること、二重の柵のひな形（M5）。
- ターミナルを運ぶ仕組みを、Istesso の中に作ること。
- 窓の要るアプリを動かすこと（M3 の `istesso open`）。
- インストールの振り分け（R-05。M5）。
- 外のサービスへのデプロイの中身（「デプロイ」は、この仕組みの中の PC に置くこと。6.2 の 5）。
- Gate そのもの。Gate につなぐこと（6.2 の 6）。
- 複数の PC に、1 つのビルドを分けて配ること。行き先は、タスク 1 つにつき 1 台である（R-11 の「束ねることはしない」と同じ考え方）。
- 止まっている PC を起こすこと（M3）。M6 は、「起こせる」と出すだけである。
- 特定のコーディングエージェントだけで動く作り。スキルと入口は、道具を選ばない形にする。
- Windows（今回の公開に含めない）。
