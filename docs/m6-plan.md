# M6 の進め方：エージェント連携（計画）

M6 は、コーディングエージェントが、どの PC で何を動かすかを自分で覚えなくても、正しい PC でビルド、実行、デプロイができるようにする段階です（R-10）。

この文書は、2026-11-17 に書いた計画です。次の 3 つを分けて書きます。

- [milestones.md](milestones.md) と [requirements.md](requirements.md) に、すでに書いてあること。
- **提案**。この流れが考えた案です。決定ではありません。見出しか行に「提案」と書きます。
- 持ち主が決めること（「6. 持ち主に決めてほしいこと」に、1 つの一覧でまとめました）。

読むときの注意：

- **この文書を書くあいだ、コードは 1 行も書いていません。実機では、何も動かしていません。** 読んだのは、文書と、いまのコードの公開されている型と、この Mac に入っている herdr（0.9.5）のヘルプの表示だけです。
- ADR 0010（`m3-app-manager` ブランチ）、ADR 0013 と ADR 0014（`plan-m4-m5` ブランチ。どちらも状態は「提案」）、ADR 0015（`m1-dialog-windows` ブランチ）は、まだ `main` にありません。リンクにせずに、番号で指します。
- 規約は先に [AGENTS.md](../AGENTS.md) を読んでください。

## 0. 言葉

「エージェント」が 2 つの意味で使われています。この文書では、次のように呼び分けます。

| 語 | 意味 |
|---|---|
| ホストエージェント | 各 PC で動かしておく `istesso agent`。ペアリング済みの端末からの問い合わせに答える（[ADR 0007](adr/0007-control-channel.md)） |
| コーディングエージェント | ターミナルで動く、コードを書く AI の道具。M6 の「エージェント連携」の相手は、こちら |
| 役割表 | `istesso doctor --json` が出す、その PC にできることの一覧（`roles`、`tools`、OS、GPU など）。全端末のぶんは `istesso hosts --json` で出る |
| タスク | プロジェクトが名前を付けた、ビルド、実行、デプロイの 1 つ |
| 必要条件 | タスクが、動かす PC に求めるもの（例：`xcode_build` の役割がある） |
| 行き先 | 必要条件から決まった、タスクを動かす PC |
| 入口 | AGENTS.md や CLAUDE.md に書く、「ビルド、実行、デプロイは、このコマンドで」という 1 行 |

## 1. M6 は何のためか

### 1.1 書いてあること

[milestones.md](milestones.md) の M6 は、次の 3 行です。

> - `istesso run` / `istesso build` / `istesso deploy`（必要条件から行き先を決める）
> - エージェント向けスキルと、Gate に載せる確認項目
> - herdr を専用ユーザーで動かす手順

もとになる要件は、[requirements.md](requirements.md) の R-10 です。

> - 各ホストが `istesso doctor` で役割表を出す。
> - ビルド・実行・デプロイは振り分けコマンド経由にし、必要条件から行き先を自動で決める。
> - AGENTS.md / CLAUDE.md には入口だけを書く。
> - herdr の Gate（必須要件リスト）に「デプロイ先を確認済み」を常設できるようにする。

関係する要件が、ほかに 2 つあります。

- R-07（隔離）：コーディングエージェントが読めるのは、隔離領域だけにする。プロセスごと、専用ユーザーで動かす。ツールの側のサンドボックスは、二重の柵として併用する。
- R-01 の 2 番目：文字は、ターミナルで直接つなぐ。herdr のセッションは、ホストの側に常駐する。

R-10 の 1 行目（役割表）は、M0 でできています。いまは、[AGENTS.md](../AGENTS.md) の「どこで何を動かすか」の表を、コーディングエージェントが読んで、行き先を自分で選んでいます。M6 は、この表の仕事を、コマンドに移すものです。

### 1.2 受け入れ条件

**milestones.md の M6 には、受け入れ条件が書かれていません。「場所」も書かれていません。** 引用できる条件は、ありません。

`plan-m4-m5` ブランチの milestones.md には、2026-11-16 の決定として、「M5、M6、M7、M9 には、受け入れ条件がまだ書かれていない。それぞれの流れが、先に条件を書く」とあります。同じ決定は、各流れの受け入れ条件に「ホストを起動した直後（ログイン画面のまま、SSH だけ）の状態で動く」を足すことも求めています。この 2 つに従って、条件の**案**を「2.」に書きました。案を条件にするかどうかは、持ち主が決めます（6. の 1）。

### 1.3 はっきりしないこと

| # | こと | この計画での扱い |
|---|---|---|
| 1 | **herdr の「Gate」が何か。** リポジトリのどの文書にも、説明がない。herdr 0.9.5 のヘルプの表示にも、その名前のコマンドはなかった（見たのは、ヘルプだけ）。項目の書き方も、満たしたかどうかを、だれが、どう確かめるのかも、分からない | 持ち主に尋ねる（6. の 6）。Istesso の側は、どちらの読み方でも使える形（終了コードと 1 行の表示）にしておく |
| 2 | **「デプロイ」が何を指すか。** この仕組みの中の PC に置くことか。外のサービスに出すことか | 前のほうとして書いた。違っていたら、直す（6. の 5） |

| 5 | **3 行目（herdr を専用ユーザーで動かす手順）と、M5 との分担。** M5 の計画（`plan-m4-m5` ブランチの m5-plan.md）も、手順 6 と条件 I3 で herdr を扱っている | 案：専用ユーザーを作って、読めないことを確かめるのは M5。その中に herdr を入れて、つなぐ手順を書くのは M6 |

### 3.2 M5 の、何を待つのか

| # | 隔離のうち、要るもの | どこで決まり、どこでできるか | これがないと |
|---|---|---|---|
| 1 | **専用ユーザーがあり、ホストの役が、そのユーザーで動いていること** | [ADR 0003](adr/0003-isolation.md)、ADR 0014 の提案 1。M5 の手順 5 と 6 | ほかの端末から頼まれたタスクが、ふだんのユーザーとして動く。ふだんのファイルの全部に、手が届く。ADR 0014 が「見落としやすい穴」と書いているものを、M6 がコマンドで広げることになる |
| 2 | **隔離領域があり、作業の場所が、その中に決まっていること** | ADR 0013 の「何を、どこに置くか」（根の下の、コーディングエージェントの作業場所）。M5 の手順 1 と 5 | タスクを、どのフォルダーで動かすかが決まらない。ソースの置き場所も決まらない |
| 3 | **端末の身元が、ユーザーごとに分かれていること** | ADR 0014 の提案 3 | コーディングエージェントが、人と同じ身元で動く。エージェントにだけ権限を与える、外す、ができない（5.1） |
| 4 | **名指しのコピー（取得と受け渡し）** | ADR 0013 の段階 2。M5 の手順 4 | 成果物を持ち帰る道がない。ソースを届ける道は、別に決める（6. の 7） |
| 5 | **専用ユーザーに渡した鍵は、エージェントの手が届く範囲になる、という前提の上での置き方** | ADR 0003 の「結果」。ADR 0014 の「鍵に手が届くことへの備え」 | デプロイの鍵や、Apple の署名の証明書を、どこに置くかを決められない |
| 6 | **二重の柵のひな形**（コーディングエージェントの設定。読める範囲を領域に絞る） | ADR 0014 の「二重の柵」。M5 の手順 2 | herdr の手順に書く設定が、まだない |
| 7 | **役割表に、隔離の状態が出ること** | ADR 0014 の「採用されたら直すもの」。M5 の手順 5 | 隔離されていない PC を、行き先から外せない |

ADR 0013 と ADR 0014 は、まだ「提案」です。ADR 0014 で A でない案（エージェントはふだんのユーザーで動かす、ユーザーを 2 つ作る）が選ばれると、3 と 5 の中身が変わります。いま作れる部分（1〜5）は、どの案でも変わりません。

## 4. いま作れる部分の提案

この節は、全部が提案です。

### 4.1 置き場所

本線（M1〜M3）が `main` に入っていないので、ほかの流れとぶつからない場所にだけ、置きます。

| もの | 場所 | メモ |
|---|---|---|
| 行き先を決めるライブラリと、確かめるためのコマンド | 新しいクレート `crates/istesso-route/` | ワークスペースは `crates/*` をまとめて読むので、登録のために `Cargo.toml` を直す必要はない。変わる共有のファイルは、`Cargo.lock` だけ |
| スキルと、入口のひな形 | 新しいフォルダー `agent/`（`agent/skill/`、`agent/entry/`） | 文書と、試験用の役割表だけを置く |
| ブランチと作業ツリー | `main` から切った新しいブランチ（案：`m6-route`）と、専用の作業ツリー | このクレートが使うものは、全部 `main` にある |

**直さないもの：** `istesso-proto`、`istesso-link`、`istesso-pair`、`istesso-agent`、`istesso-cli`、`istesso-catalog`、`istesso-doctor`。ADR 0006 と ADR 0007 の手順。メッセージも、権限も、足しません。

コマンドは、はじめは `istesso-route` という別のコマンドにします。`istesso` コマンドの定義は 1 つのファイルにあり、ほかの流れが、同じファイルにコマンドを足しているためです。M7 の流れも、同じ理由で `istesso-devices` を別にしています。本線が `main` に入ったら、`istesso run`、`istesso build`、`istesso deploy` として移します。

依存は、足しません。必要条件のファイルを JSON にすれば、すでにある `serde_json` で読めます（6. の 4）。

### 4.2 口

**必要条件のファイル（プロジェクトに置く）。** 案：プロジェクトの根の `.istesso/tasks.json`。

```json
{
  "version": 1,
  "tasks": {
    "test":    { "kind": "build",  "needs": { "tools": ["cargo"] },
                 "command": ["cargo", "test", "--workspace"] },
    "mac-app": { "kind": "build",  "needs": { "roles": ["xcode_build"] },
                 "command": ["xcodebuild", "-scheme", "App"] },
    "encode":  { "kind": "run",    "needs": { "os": "linux", "roles": ["gpu", "hardware_encode"] },
                 "command": ["./tools/encode-check"] },
    "site":    { "kind": "deploy", "needs": { "roles": ["always_on_candidate"] },
                 "command": ["./tools/publish"] }
  }
}
```

- `needs` に書けるのは、いまの役割表にある項目だけにする：`roles`（全部を満たすこと）、`os`、`arch`、`tools`（`cargo`、`docker`、`gstreamer`、`xcode`）、`host`（人が名指しした PC）。役割表を変えずに始めるためである。
- `command` は、引数の並びで書く。シェルは通さない。
- 読む側は、知らない項目を無視する。知らない役割や道具が `needs` にあるタスクは、「この版では決められない」と答える。満たしたことにはしない。
- PC の名前を書くのは、`host` だけである。書かなくて済むなら、書かない。

**役割表（入力）。** `istesso hosts --json` の出力を、そのまま読みます。`main` にある形です。読むのは、端末の ID、名前、手元かどうか、状態、役割表、負荷、最後に答えた時刻だけで、ほかの項目は無視します。渡し方は、ファイルか標準入力から始めます（`istesso hosts --json | istesso-route where build test`）。

**コマンド（案）。**

| コマンド | 動き |
|---|---|
| `istesso-route where <build\|run\|deploy> <タスク> [--hosts <ファイル>] [--json]` | 行き先と理由を答える。何も動かさない |
| `istesso-route check deploy <タスク>` | デプロイ先が、ただ 1 つに決まり、いま答えているかを、終了コードと 1 行で答える。Gate に載せる項目のためのもの（1.3 の 1） |
| `istesso-route run <タスク>`（`build`、`deploy` も同じ） | 行き先が手元なら、手元で動かす。ほかの PC なら、行き先と理由を出して、決まった終了コードで止まる。**ほかの PC では、まだ動かさない** |

終了コードは、「決まった」「満たす PC がない」「満たす PC が答えない」「デプロイ先が 1 つに決まらない」「ファイルが読めない」を分けます。コーディングエージェントが、文を読まずに分かるようにするためです。出力には、鍵も、アドレスも出しません。

**ライブラリの形。**

```rust
// crates/istesso-route (proposal). Depends on istesso-proto and serde only.

pub enum TaskKind { Build, Run, Deploy }

/// What a task needs from the machine it runs on. Every field narrows the
/// choice; an empty `Needs` is met by any machine.
pub struct Needs {
    pub roles: Vec<Role>,
    pub os: Option<OsFamily>,
    pub arch: Option<String>,
    pub tools: Vec<Tool>,
    /// A machine the person named. Nothing else is considered.
    pub host: Option<String>,
}

/// One machine as `istesso hosts --json` shows it; other fields are ignored.
pub struct Candidate {
    pub id: String,
    pub name: String,
    pub local: bool,
    pub state: HostState,
    pub manifest: Option<HostManifest>,
    pub status: Option<HostStatus>,
    pub seen_at: Option<u64>,
}

pub enum Decision {
    /// Run it there. `because` names the needs it meets and why it came first.
    Go { place: Place, because: Vec<String> },
    /// Machines meet the needs, but none of them answers. Nothing else is tried.
    Stopped { places: Vec<Place>, wake_possible: bool },
    /// More than one machine meets the needs of a deploy task. A person picks.
    Ambiguous { places: Vec<Place> },
    /// No machine meets the needs; says what each one lacks.
    Nobody { lacking: Vec<(Place, Vec<String>)> },
}

pub fn decide(kind: TaskKind, needs: &Needs, table: &[Candidate]) -> Decision;

/// Carries out a task at the place that was decided. Until the isolation
/// (M5) and an ADR for running on other machines exist, there are two
/// implementations: this machine, and a fake for tests.
pub trait Executor {
    fn run(&mut self, place: &Place, task: &Task) -> Result<i32, ExecError>;
}
```

### 4.3 決め方

1. 必要条件を満たさない PC を外す。外した理由を、PC ごとに覚える。
2. ビルドと実行は、残った中から、「手元 → 起きているホスト → 負荷の低いホスト」の順で選ぶ。アプリの起動先（R-04）と同じ順である。決まりを 1 つにして、説明を 1 つで済ませるため。
3. 満たす PC が、どれも答えないときは、止まる。満たさない PC では、動かさない。
4. **デプロイは、順で選ばない。** 満たす PC が 2 台以上あれば、止まって、並べて見せる。人が `host` で名指しするか、必要条件を狭める。まちがった先に出す事故を防ぐのが、Gate の項目のねらいだと読んだためである（6. の 3）。
5. 答えない PC の役割表は、最後に見えた内容である。行き先の手がかりにはするが、信頼の根拠にはしない（ADR 0007 と同じ扱い）。出力に、いつの内容かを出す。

### 4.4 まだ `main` にないものの使い方

| もの | どこにあるか | この部分での扱い |
|---|---|---|
| 役割表の型、`istesso hosts --json` | `main` | そのまま使う |

## 5. 安全

### 5.1 いまの状態

- 権限は、端末ごとに付きます（R-13、[ADR 0006](adr/0006-pairing.md)）。新しくペアリングした端末は、「閲覧」と「操作」を持ちます。
- コーディングエージェントは、いま、ふだんのユーザーで動いています。そのユーザーが読める端末の鍵を、読めます。**いまは、コーディングエージェントと、その端末を使っている人を、相手の PC は区別できません。**
- だから、いまは、「エージェントにだけ与える権限」も、「エージェントからだけ外す権限」も、作れません。分けるには、エージェントが別の身元で動くことが要ります（3.2 の 3）。

これは、M6 が足すものではなく、いまの状態です。M6 のいま作れる部分は、これを広げません。

### 5.2 いま作れる部分が使う権限

- 使うのは、役割表と負荷の問い合わせだけです。どちらも、いまある「閲覧」のメッセージです（[ADR 0007](adr/0007-control-channel.md)）。役割表をファイルから渡す形では、通信もしません。
- メッセージ、権限、暗号の手順には、何も足しません。ADR 0006 と ADR 0007 は、変えません。
- root も、OS の許可も、要りません。
- ほかの PC では、何も動かしません。手元で動かすタスクは、プロジェクトのファイルに書いてあるコマンドで、コーディングエージェントが自分で打てるものと同じです。
- 表示とログに、鍵、トークン、ペアリングコードを出しません。タスクのコマンドの引数に秘密を書かない、とスキルに書きます（引数は、同じ PC のほかのユーザーから見えます）。

### 5.5 エージェントに渡さないもの

2026-11-17 に、次の 3 つが決まっています（ADR 0010 の「人が決めたこと」の 13〜15）。

- 入力を送れるのは、そのセッションを映している端末だけ。
- 入力を開くときの権限は、頼まれたときに読み直した値を使う。
- 映像を受け取れるのは、映している端末だけ。

同じ決定は、「映していない端末やエージェントからの操作」を、将来の項目として残しています。別の機能として、はっきりした権限を付けて作るもので、いまは作りません。

M6 は、これに従います。**M6 が作るどの部分も、セッションに入力を送らず、映像を受け取らず、セッションを始めも止めもしません。** 「タスク」の権限は、セッションのどの操作も許しません。窓の要るものは、人が `istesso open` で開きます。
