## 0. 決まっていること（ここでは変えない）

- セッションは、ある端末が始め、その端末がいなくなっても続く。「閲覧」と「操作」を持つ、ペアリング済みのどの端末もつなげる。同時に映すのは 1 台で、前の端末には「ほかの端末に移った」と出す。
- 入力と絵は、そのセッションを映している端末にだけ行く。
- 開くのを、セッションの数では断らない。数えるのは、同時に圧縮する絵の数（既定 8）。見られていない窓は絵を止めて枠を使わず、見られると戻る。アプリは動いたまま。**どの窓の絵が止まったかが、使う人に分かること。**
- 窓の大きさは、開くときに決まる（途中で変えるのは、あと）。開くときに大きさを選べることは、範囲に入る。閉じる、しまうは、手元の窓と同じに効く。決まった形のカーソルは、Mac のもの。
- 使う人は開発者だけではない。説明なしで使えることを重く見る。画面の文字は英語、文書は日本語。
- この画面は、別の流れが同じ週に作っている**自前のクライアントアプリ**に組み込む、独立した部品にする。ホストには、ADR 0010 が名前を挙げた操作（アプリ一覧、起動、つなぐ、離れる、閉じる。それと、すでにある状態の問い合わせ）だけで頼る。

## 1. ねらい（提案）

1. **アプリを、どの PC にあるかを見ずに開ける**（M3 の受け入れ条件）。アイコンは 1 アプリ 1 つ。どこで開くかは、小さく書くだけにする。
2. **やりかけに戻れる。** 動いたままのセッションが、どこに映っているか（この Mac、ほかの端末、どこにも）が、一目で分かる。
3. **止まっているものが分かる。** 絵が止まった窓、答えないホスト、切れた接続を、色だけでなく文字とアイコンで出す。
4. **閉じているあいだは、何も頼まない。** ランチャーが開いていなければ、ランチャーからホストへの問い合わせは 0。

「リモートだと感じない」（成功の基準）との釣り合い：アプリを開いたあとの窓では、ホストの名前を出さない（クライアントアプリの受け持ち）。ランチャーは、どこで動いているかを知りたいときに見る場所なので、ここではホストの名前を出す。

## 2. 呼び出し方（提案）

| 入口 | 何が出るか | 理由 |
|---|---|---|
| **メニューバーの項目**（Istesso のアイコン） | 小さなメニュー：「Running」の一覧（この Mac、ほかの端末、どこにも映していない）、`Open Launcher…`、`Pair a Computer…` | クライアントアプリは、窓が 0 枚のときも動いている常駐のアプリになる。Mac で常駐のものを探す場所は、メニューバーである。戻るだけなら、ここで 1 クリックで済む |
| **ランチャーの窓** | アプリの一覧、検索、Running、ホストの状態、大きさを選ぶ画面 | 探す、選ぶ、大きさを決める、には広さとキーボードが要る。メニューの中では、検索とキーボードの移動が窮屈になる |
| **キーボードの近道**：⌃⌥Space（どこからでも。変えられる。消せる） | ランチャーの窓を出す。検索欄に入力できる状態で開く | 一番速い入口。⌘Space（Spotlight）、⌃Space（入力ソースの切り替え。日本語を使う人が多い）、⌥⌘Space（Finder の検索）は避けた。「どこからでも効く近道」は、OS の許可を要しない登録の仕方（Carbon のホットキー）で作れるので、権限は増えない |

- ランチャーの窓は、アプリを開くと自動で隠れる（Spotlight と同じ）。Esc でも隠れる。⌘W で閉じる。窓の位置と大きさは覚える。
- メニューバーの項目には、印を 1 つだけ付ける：**絵が止まっている窓がある**、または**この Mac の窓がホストを見失った**とき、アイコンに小さな点を出す（VoiceOver では「Istesso, 2 windows paused」のように読む）。数字の吹き出しは出さない。
- 初めて起動したときは、ランチャーの窓を出す（下の 3.1）。

## 3. 状態ごとの見え方と操作（提案）

画面の部分の呼び名：上から、**検索欄**、**Running**（動いているセッション）、**Apps**（アプリの一覧）、**ホストの帯**（窓の下の端。ペアリングしたホストと状態）。文字は、英語で画面に出るとおりに書く。`tower`、`attic`、`laptop`、`old-laptop` は、説明のための作った名前である。

### 3.1 ホストを 1 台もペアリングしていない

| 何が出るか | 文字 | 操作 |
|---|---|---|
| 窓の真ん中に、絵と 2 行の説明と、ボタン 1 つ。検索欄、Running、Apps、ホストの帯は出さない | 見出し：`Use apps from your other computers`<br>説明：`Pair a computer that has Istesso installed. Its apps will appear here, and they open in windows on this Mac.`<br>ボタン：`Pair a Computer…`<br>小さな文字のリンク：`How do I install Istesso on another computer?` | `Pair a Computer…`（Return でも）：クライアントアプリのペアリングの画面へ渡す（ランチャーはペアリングをしない。ADR 0006 の手順は、クライアントアプリの受け持ち）。リンク：説明の文書を開く |

- ペアリングが済むと、そのまま 3.2 の画面に変わる。窓を閉じ直す必要はない。
- この状態では、ホストに何も頼まない（頼む相手がいない）。

### 3.2 ホストと、そのアプリ（ふだんの画面）

| 何が出るか | 文字 | 操作 |
|---|---|---|
| **Apps**：アイコンの格子。1 アプリ 1 つ（`istesso-catalog` の統合。R-04）。名前の下に、灰色の小さな文字で、開く先 | `Blender`<br>`on tower`<br>2 か所にあるとき：`Firefox`<br>`on tower` と、右下に小さく `+1`（VoiceOver：`Firefox, on tower and attic. Opens on tower.`） | **クリック、または Return**：開く（3.3）。そのアプリのセッションがあれば、新しく開かずに、そこへ戻る（ADR 0010 の 10 の決まり）<br>**右クリック**：`Open` / `Open on ▸ tower, attic` / `Open with Size…` / `New Window`（セッションがあっても新しく開く） |
| 名前の順。上に、最近開いたもの 8 つ（`Recent`） | 見出し：`Recent`、`All Apps` | — |
| **検索欄**：窓が出たとき、ここに入力できる | プレースホルダー：`Search apps` | 文字を打つと、その場で絞る。↓ で結果へ。Return で一番上を開く |
| **ホストの帯** | `tower · Ready`、`attic · Asleep`、`this Mac` は出さない | ホストの名前をクリック：そのホストのアプリだけに絞る（もう一度で戻す） |
| 一覧を取りに行っているあいだ | 帯に `Updating…`。格子は、前に保存した一覧（R-04「一覧は手元に保存する」）をそのまま出す | — |

- **そのアプリのセッションが動いているとき**は、名前の下を `running here`（この Mac）、`running on laptop`（ほかの端末）、`running`（どこにも映していない）に替える。クリックすると、新しく開かずに、そこへ戻る。
- **開く先の決め方**は、決まっているとおり：動いているセッション → 手元 → 起きているホスト → 負荷の低いホスト（ADR 0010 の 1 と 10、R-04）。開く前に、開く先が名前の下に見えているので、思っていない所で開いて驚くことがない。
- **一覧に出すアプリ**（提案）：ペアリングしたホストのどれかにあるアプリ。この Mac にしかないアプリは出さない（Launchpad や Spotlight と同じものを並べない）。この Mac とホストの両方にあるアプリは出し、決まりどおり手元で開く。名前の下は `on this Mac`。→ 持ち主への問い 3
- **Mac のホストのアプリ**（`.app`）は、M4 まで、ほかの Mac からは開けない（ADR 0010 の 8）。M3 の版では、リモートの Mac のアプリは一覧に出さない（`AppEntry.platform` で分ける）。
- **ホストが眠っている**とき（`HostState::Asleep`）：そのホストにしかないアプリのアイコンは薄くし、右上に `!`（R-04）。クリックすると、その場に説明を出す：`attic is asleep. Wake it to open GIMP.` ボタンは、起こす手段があるときだけ `Wake attic`（`wake_possible`）。ないとき：`Turn on attic, then try again.` 起こす操作そのものは、この画面の外（5 を参照）。
- **このホストでは「閲覧」だけの権限**（セッションの頼みが `forbidden`）：そのホストのアプリをクリックしたとき：`This Mac can view tower but not control it. To open apps, allow Control for this Mac on tower.`
- **相手の Istesso が古い**（`unsupported`）：`tower runs an older version of Istesso. Update it to open apps from here.`

### 3.3 開く（大きさを含めて）

| 段階 | 何が出るか | 文字 | 操作 |
|---|---|---|---|
| クリックした直後 | ランチャーは隠れる。代わりに、開く先の場所に、薄い枠（窓の大きさのまま）と、真ん中に小さな回る印。クライアントアプリの受け持ちで、最初の絵が出るまで、窓そのものは見せない（ADR 0010 の 9「ビューアーとの約束」の 4） | 枠の中：`Opening Blender…` | Esc：やめる（どう扱うかは問い 6。推しは、アプリに閉じるよう頼む。尋ねられたら、Running に残る） |
| 3 秒を過ぎても絵が出ない | 枠の中の文字が変わる | `Opening Blender on tower… This can take a few seconds the first time.` | — |
| 起動できなかった（`app_failed`） | 枠が消え、メニューバーの項目から小さな知らせ（ランチャーを開いていれば、その中に赤い帯） | `Blender could not start on tower.` ＋ ホストからの 1 行（`end.message`。英語） | `Try Again` / `OK` |
| 窓を出せなかった（`stream_failed`） | 同上 | `tower could not show Blender's window.` ＋ 1 行 | 同上 |
| 開いておける数に達した（`unavailable`） | 同上 | `tower already has 64 apps open, the most it allows. Quit some in Running, then try again.` | `Show Running` |
| 端末で動くアプリ（`Terminal=true`） | 同上 | `GNU Nano runs in a terminal. Open it in a terminal window instead.` | `OK` |

**大きさ**（提案）

- クリックで開くときの大きさは、**そのアプリで前回選んだ大きさ**。初めてのアプリは、**Large**。
- 右クリックの `Open with Size…`、または ⌥Return で、窓の上に小さな選択の画面（シート）を出す。

  | 選択肢 | 中身 |
  |---|---|
  | `Fill Screen` | 窓を出す画面の、メニューバーと Dock を除いた広さ |
  | `Large` | 同じ広さの 85%（縦横比は画面と同じ） |
  | `Medium` | 1280 × 800 |
  | `Small` | 960 × 600 |
  | `Custom…` | 幅と高さを打つ（ポイント） |

  数字は、その Mac の画面から計算して、選択肢の横に出す（`Large — 1250 × 813`）。単位は**ポイント**（Mac の窓の見た目の大きさ）。画素への直し方は、ビューアーの受け持ち（→ 問い 5）。
- シートの下に、1 行の説明：`The window keeps this size until you close it. To change the size, quit and open again.`（途中で大きさを変えられないことを、選ぶときに知らせる。M1 の計画の 6）
- シートのボタン：`Open`（既定。Return）、`Cancel`（Esc）。チェックボックス：`Use this size for Blender next time`（既定でオン）。
- すでに動いているセッションに戻るときは、大きさを選ばせない。開いたときの大きさのまま戻る（つなぎ直しで大きさが変えられるかは、映像の側の約束による。→ 問い 4）。

### 3.4 動いたままのセッション

**Running** は、窓の一番上に置く。セッションがないときは、この部分ごと出さない。1 行が 1 セッションで、アイコン、名前、場所、状態、右端にボタン。

| どこに映っているか | 分け方 | 行の文字 | クリック（Return） | 右端と右クリック |
|---|---|---|---|---|
| **この Mac** | クライアントアプリが持っている窓の中に、同じホストの同じ ID があり、つなぎの番号が一致する | `Firefox` / `tower · On this Mac` | その窓を前に出す（ホストには何も頼まない。前に出すと、窓は `visible` を送る） | `Quit`（窓の閉じるボタンと同じ。アプリに閉じるよう頼み、窓は開いたまま。保存するかの問いは、その窓に出る）<br>`Close Window Only`（離れる。窓は閉じる。アプリは動き続ける）<br>`Force Quit…`（確かめてから） |
| **ほかの端末** | `shown_on` があり、上の一致がない | `Kdenlive` / `tower · On laptop` | **この Mac に移す**（つなぐ。`laptop` には「ほかの端末に移った」が出る） | 右端のボタン：`Show Here`<br>右クリック：`Show Here` / `Quit` / `Force Quit…` |
| **どこにも映していない** | 状態が `detached` | `Text Editor` / `tower · Not shown` | この Mac で開く（つなぐ） | 右端：`Show`<br>右クリック：`Show` / `Quit` / `Force Quit…` |
| 解除された端末が開いた | `left_by` がある | 2 行目の後ろに：`· Opened by old-laptop (unpaired)` | 上と同じ | 上と同じ |
| 起動中 | `starting` | `Blender` / `tower · Opening…` | 何もしない | `Cancel`（→ 問い 6） |
| 閉じるよう頼んだあと | `Quit` を押してから、まだ動いている | `Text Editor` / `tower · Asked to quit…` | 開く（問いが出ていれば、それに答えるため） | — |

- **並び**：この Mac → ほかの端末 → どこにも映していない。同じ中では、最後に向いた順（向いた時刻は、クライアントアプリが知っている窓のぶんだけ。ほかは、ホストの返した順）。
- **場所の言葉**：`On this Mac`、`On <端末の名前>`、`Not shown`。「Detached」「Session」「Attach」は画面に出さない（開発者の言葉なので）。
- **Quit の言葉**：Mac の `Quit` と `Force Quit…` に合わせた。1 アプリ 1 窓なので、窓を閉じることは、アプリを終えることと同じである。`Close Window Only` は、窓だけを閉じてアプリを残す、この仕組みに特有の操作なので、言葉で中身を言う。→ 問い 2
- **ほかの端末に映っているものを Quit したとき**：アプリが保存するかを尋ねると、その問いは `laptop` の窓に出る。行の文字：`Asked to quit. It may be asking a question on laptop.` ボタン：`Show Here`（移して、ここで答える）。
- **どこにも映していないものを Quit したとき**：5 秒たっても動いていたら：`Text Editor is still open. It may be asking whether to save. Show it to answer.` ボタン：`Show` / `Force Quit…`。
- **Force Quit の確かめ**：`Force quit Text Editor on tower? Unsaved changes will be lost. It gets 3 seconds to finish.` ボタン：`Force Quit`（赤）、`Cancel`（既定）。
- **セッションが終わった**（`ended`）：行は 3 秒だけ `Closed` と出して、消える。理由が `app_exited` 以外のときは、理由を出して残る（`Firefox on tower stopped: <end.message>`。`Dismiss` で消す）。
- **メニューバーのメニュー**にも、同じ Running を出す（文字は同じ。項目を選ぶと、上の「クリック」と同じ。⌥ を押しながら選ぶと `Quit`）。

### 3.5 枠が足りずに、絵が止まっている窓（`paused: no_slot`）

この Mac の窓のどれかが止まると、次の 3 か所で分かる。止まった窓そのものの印（最後の絵を残したまま、止まっていると分かる印）は、クライアントアプリのビューアーの受け持ちで、ランチャーは、その窓を見つけて戻る道を受け持つ。

| 場所 | 何が出るか | 文字 | 操作 |
|---|---|---|---|
| Running の行 | 状態の位置に、一時停止のアイコンと文字（色はオレンジ。色だけに頼らない） | `GIMP` / `tower · On this Mac · Paused` | クリック：その窓を前に出す。前に出ると、絵が戻る（その代わりに、いちばん前に向かれた窓が止まる。ADR 0010 の 15） |
| Running の上の 1 行 | 止まっている窓が 1 つ以上あるとき | `2 windows are paused. tower updates up to 8 windows at once; the others resume when you look at them. The apps keep running.` | `Why?`：もう 1 段の説明（下） |
| メニューバーの項目 | 小さな点（2 を参照） | VoiceOver：`Istesso, 2 windows paused` | — |

- `Why?` の説明：`Each window that you can see uses one of tower's video encoders. tower has 8. When you look at a paused window, it takes one from the window you looked at least recently. Minimised and hidden windows use none.`
- 見えていないので止まっている窓（`paused: hidden`。しまった窓、ほかのデスクトップの窓）は、ふつうのことなので、印を出さない。行の文字は `Minimised` か `Hidden`。
- 動いている最中にエンコーダーを断られた（`no_encoder`）ときも、ホストは同じ `no_slot` を返すので、同じに出す。説明の `up to 8` は、そのときにホストが作れている数ではなく、設定の数になる（ホストは、下げた数を答えに載せていない）。→ 問い 7
- ほかの端末に映っているセッションが止まっていても、この Mac では出さない（その端末の窓のことである）。

### 3.6 答えないホスト

| 何が出るか | 文字 | 操作 |
|---|---|---|
| ホストの帯：名前の横に、斜線の入った印 | `tower · Not answering` | クリック：`Try Again` |
| そのホストにしかないアプリ：薄く、`!` | クリックしたとき：`tower is not answering. It may be asleep, turned off, or on another network.` | `Try Again` / `OK`。起こす手段があれば `Wake tower` |
| 2 か所にあるアプリ | 開く先が、答えるほうに替わる（`on attic`） | — |
| そのホストのセッション（前に見えていたもの） | 灰色。状態の位置に `Can't reach tower` | クリック：`tower is not answering. Your apps there keep running; they will be here when it answers again.` |
| この Mac の窓が、そのホストを見失った（15 秒。ADR 0010 の 5） | クライアントアプリが窓を閉じる。Running の行は残り、灰色で `Connection lost` | 3.8 |

- 「答えない」とする時間：1 回の問い合わせが 5 秒で答えないとき（制御チャンネルの既定）。
- 眠っていると分かっているホスト（`Asleep`）は、「答えない」ではなく `Asleep` と出し、問い合わせない。

### 3.7 ペアリングを解除したホスト、解除された端末

3 つの場合がある。

| 場合 | 何が出るか | 文字 | 操作 |
|---|---|---|---|
| **ホストが、この Mac を解除した**（ハンドシェイクで断られる。ADR 0007） | ホストの帯：`tower · Not paired`。そのホストのアプリとセッションは、一覧から外す（もう見えないし、使えない） | 帯をクリック：`tower no longer accepts this Mac. Apps this Mac opened there keep running and can be used from your other devices. To use tower here again, pair it again.` | `Pair Again…`（クライアントアプリのペアリングへ）/ `Remove tower`（この Mac の一覧から消す） |
| **この Mac で、ホストを一覧から消した** | ホストは、帯からも一覧からも消える | 消すときの確かめ（クライアントアプリの設定の画面。ランチャーは文字だけ案を出す）：`Remove tower? Apps you opened on tower keep running there. You can use them from other paired devices, or quit them on tower.` | `Remove` / `Cancel` |
| **ほかの端末が解除された。その端末が開いたアプリが残っている** | Running の行に `· Opened by old-laptop (unpaired)` | VoiceOver：`Text Editor on tower, not shown, opened by old-laptop, which is no longer paired` | ふつうのセッションと同じ（`Show`、`Quit`） |

- ホストの側で端末を解除するときに、「残す」か「閉じるよう頼む」かを画面で尋ねる形（ADR 0010 の 12）は、ホストの画面のことで、このクライアントのランチャーには入れない（5）。文字の案だけを置く：`old-laptop opened 3 apps on this computer. Keep them running, or ask them to quit?` ボタン：`Keep Running`（既定）、`Ask to Quit`。
- 「解除された」と「答えない」は、ハンドシェイクで断られたことが、クライアントに分かる形で返るときだけ分けられる。分からないなら、`Not answering` に寄せる（→ 問い 8）。

### 3.8 切れたあとの、つなぎ直し

| 起きたこと | 何が出るか | 文字 | 操作 |
|---|---|---|---|
| 短い切れ（15 秒より短い。Wi-Fi の一瞬など） | ランチャーには何も出さない。窓はそのまま続く（`session_wait` がつなぎ直しを越える。ADR 0010 の 5） | — | — |
| 長い切れ、またはスリープ。この Mac の窓が閉じた | Running の行が残る。灰色、つなぎ直しの印 | `Firefox` / `tower · Connection lost` | クリック、または `Reconnect`：同じセッションにつなぐ |
| 戻ったとき（スリープから起きた。ネットワークが戻った） | **自動で戻す**（提案。下の条件のとき）。行は `Reconnecting…` | — | — |
| 戻ってみたら、ほかの端末に映っていた | 自動では取り返さない。行は `On laptop` に替わる | 行の 2 行目：`tower · Moved to laptop while this Mac was away` | `Show Here` |
| 戻ってみたら、終わっていた | 行は理由を出して残る | `Firefox on tower ended while this Mac was away.`（`end.message` があれば、それも） | `Dismiss` |

- **自動で戻す条件**（提案）：そのセッションの状態が `detached` で、つなぎの番号が、この Mac が最後に持っていた番号と同じ（＝あいだに、ほかの端末がつないでいない）。番号が増えていれば、ほかの端末が使ったので、黙って取り返さない。
- 自動で戻すのは、スリープから起きたとき、ネットワークが戻ったときの 1 回だけ。失敗したら、`Connection lost` のまま待つ（繰り返し試さない。ホストを見回り続けない）。
- この動きは、ADR 0010 の 11「スリープから戻ったときに、開いていた窓が自分でつなぎ直すこと」に当たる。窓を作り直すのはクライアントアプリで、ランチャーは、どれを戻すかを決めて頼む。→ 問い 1

## 4. ホストに何を、どれだけ頼むか（提案）

**ランチャーが閉じていれば、ランチャーからの問い合わせは 0 である。** この Mac に映っている窓の `session_wait`（ずっと続く）は、窓の持ち主のクライアントアプリが送るもので、ランチャーは、その結果をクライアントアプリから受け取るだけにする（同じことを 2 回聞かない）。

| いつ | 何を | どのホストに |
|---|---|---|
| 閉じているとき | 何も頼まない | — |
| メニューバーのメニューを開いた | まず、手元にあるもの（クライアントアプリの窓、最後に取った一覧）で描く。同時に `session_list` を 1 回。答えが来たら、開いているメニューを書き換える | 起きているホスト |
| ランチャーの窓を出した | 保存した一覧で、すぐ描く。同時に、`status`（状態と負荷）と `session_list` を 1 回ずつ。アプリ一覧（`apps`）は、前に取ってから 10 分を過ぎていたときだけ | 起きているホスト。眠っているホストには頼まない |
| 窓が見えているあいだ | `session_list` を 5 秒おき | 同上 |
| 窓が隠れた、ほかの窓に完全に隠れた、閉じた、Mac が眠った | 止める（次に見えたときに、すぐ 1 回） | — |
| 操作のすぐあと（Quit、Show Here など） | 答えを見て、その場で `session_list` を 1 回 | そのホスト |
| ホストが答えない | 見えているあいだだけ、5 秒、10 秒、30 秒の間をあけて試す。30 秒からは延ばさない | そのホスト |
| ⌘R | `status`、`session_list`、`apps` を 1 回ずつ | 起きているホスト全部 |

- ランチャーが使う操作：アプリ一覧（`apps`）、状態（`status`）、`session_list`、`session_stop`（`Quit` と `Force Quit…` を、ほかの端末に映っているもの、どこにも映していないものに使うとき）。`session_start`、`session_attach`、`session_detach`、`session_show`、`session_wait` は、窓を持つクライアントアプリが送る。ランチャーは、どれを頼むかを決めて渡す（7 の分け方）。
- `session_list` の答えは、アプリを ID（`app`）で返すだけなので、名前とアイコンは、そのホストのアプリ一覧から引く。一覧にない ID（あとでアンインストールした、など）は、ID の末尾を名前の代わりに出す（`org.example.Tool`）。
- ホストの側の重さ：`session_list` は、ペアリングの一覧を 1 回読んで、表を並べるだけである。5 秒おきに 1 台の端末が頼んでも、ホストの見回り（1 秒おき）より軽い。
- 5 秒の理由：ほかの端末での変化（ほかの端末に移った、どこかで閉じた）は、人が 1 つずつ起こすもので、5 秒遅れても困らない。この Mac の窓の変化は、`session_wait` ですぐ分かる。→ 問い 9

## 7. どう作るか（提案）

### 部品の置き場所

| 場所 | 中身 |
|---|---|
| `crates/istesso-launcher/`（新しい） | 画面を持たない中身：状態の組み立て（3 の表をそのまま決まりにする）、文字と VoiceOver の名前、問い合わせの段取り（4）、自動でつなぎ直す条件。Rust。どの PC でもテストできる |
| `macos/launcher/`（新しい） | Mac の画面：ランチャーの窓、メニューバーの項目、大きさのシート、近道の登録。中身が作った「画面に出すもの」を描くだけで、決まりを持たない。言葉の選び方も、中身の側にある |

画面の部分を、中身から分けるのは、(1) ホストなしで、文字と状態の移り方を全部テストできる、(2) あとで Linux や Windows、AURA のクライアントの画面を作るときに、中身を使い回せる、からである。中身と Mac の画面のつなぎ方（Rust の関数を Swift や Objective-C から呼ぶ形）は、クライアントアプリの作りに合わせる（→ 問い 1）。新しい依存を入れるなら、`cargo deny check licenses` を通す（UniFFI は MPL-2.0 なので、使うなら例外の登録が要る。小さな C の関数の口を手で書けば、依存は増えない）。

### クライアントアプリとの境目

**ランチャーが、クライアントアプリからもらうもの**

| もの | 中身 |
|---|---|
| ペアリングしたホスト | ID、名前、状態（`HostRef`）。一覧の変化の知らせ |
| ホストへの口 | ADR 0010 の操作のうち、ランチャーが使う 4 つ（`apps`、`status`、`session_list`、`session_stop`）を、ホストごとに呼べる口。ランチャーは、チャンネルも鍵も持たない |
| この Mac の窓 | 窓ごとに：ホストの ID、セッションの ID、つなぎの番号、状態（`running` / 閉じた / 見失った）、`paused` とその理由、最後に向いた時刻。変化の知らせ |
| 画面の情報 | 窓を出す画面の、使える広さ（ポイント）。大きさの選択肢の計算に使う |
| 手元に保存する場所 | アプリ一覧の保存、アプリごとの大きさ、`Recent` |
| できること | 起こせるか（`Wake` を出すかどうか）。ペアリングの画面があるか |

**ランチャーが、クライアントアプリに返すもの**（どれも「頼み」で、実行するのはクライアントアプリ）

| 頼み | クライアントアプリがすること |
|---|---|
| `Open { app, host, size }` | ビューアーを用意し（`prepare`、`offer`）、`session_start`、`show` |
| `Attach { host, session }` | ビューアーを用意し、`session_attach`、`show`（`Show`、`Show Here`、`Reconnect`、自動のつなぎ直し） |
| `Focus { window }` | 窓を前に出す |
| `Quit { window }` | 窓の閉じるボタンと同じ（`session_stop`。窓は残す） |
| `CloseWindowOnly { window }` | `session_detach`。窓を閉じる |
| `Pair`、`Wake { host }`、`RemoveHost { host }` | それぞれの画面か手段へ |

そのほかに、ランチャーの窓そのもの（Mac の画面の部品）と、メニューバーのメニューの中身を返す。

**分け方の理由**：`session_start` と `session_attach` には、ビューアーの `offer` が要る。窓とその `session_wait` を持つのはクライアントアプリなので、そこに送らせる。ランチャーが決めるのは、「何を、どこで、どの大きさで」である。ADR 0010 の 11 の「クライアントの側をエージェントに持たせること」は、この境目の、クライアントアプリの側に入る。

### ホストなしで、何をテストするか

- **偽物のホスト**：ADR 0010 の操作（`apps`、`status`、`session_list`、`session_stop`）に、台本どおりに答えるもの。台本は、3 の状態を 1 つずつ作る：ペアリングなし。セッションなし。この Mac、ほかの端末、どこにも映していない。`left_by`。`paused: no_slot` が 2 つ。答えない（5 秒待たせる）。`forbidden`。`unsupported`。上限の `unavailable`。Quit したのに残る（保存するかを尋ねている）。終わった（`app_failed`、`stream_failed`）。この Mac を解除した（ハンドシェイクで断る）。
- **偽物のクライアントアプリ**：窓の一覧を台本で出し、受けた頼みを記録する。
- **偽物の時計**：5 秒おき、間をあけた再試行、3 秒で消える行を、待たずに確かめる。
- 確かめること：
  1. 状態ごとに、出る行と文字と VoiceOver の名前（表と同じか。文字の比べ合わせ）。
  2. 操作ごとに、返す頼み（`Show Here` は `Attach`、この Mac の行の `Quit` は窓への `Quit`、どこにも映していない行の `Quit` は `session_stop` など）。
  3. 問い合わせの数：閉じているあいだ 0。見えているあいだ 5 秒おき。隠れたら止まる。眠っているホストには 0。
  4. 自動のつなぎ直しの条件：番号が同じなら頼む。増えていれば頼まない。
  5. 大きさの計算：画面の広さから、選択肢の数字。前回の大きさを覚える。
- **本物のエージェントで**（どの PC でも）：`istesso-agent` のテストと同じように、手元で試験用のエージェントと偽物のランナー（`scripts/fake-session-runner.sh`）を動かし、ループバックでつなぐ。偽物のホストの答えと、本物の答えの形が同じかを確かめる。
- Mac の画面の部分は、Mac の実機で、キーボードだけ、VoiceOver で一通り触る（自動にしにくいので、手順を書く）。

### 作る順番

1. `istesso-launcher`：状態の組み立てと文字。偽物のホストと偽物のクライアントアプリで、3 の表を全部テストにする。
2. 問い合わせの段取り（4）と、自動のつなぎ直し。偽物の時計でテスト。
3. 本物のエージェント（偽物のランナー）を相手に、形を合わせるテスト。
4. `macos/launcher/`：窓、メニューバー、大きさのシート、近道。初めは、偽物のホストの台本で描く（ホストなしで見た目を確かめられる）。
5. クライアントアプリに組み込む（その流れの口ができてから）。
6. 実機 2 台で、[m3-trial.md](m3-trial.md) と同じ項目を、画面から行う。

映像・入力・音の経路には手を入れない（ランチャーは、窓が開いたあとの経路を通らない）。権限の要る処理も増えない（近道の登録は、OS の許可を要しない）。

## 8. 持ち主に決めてほしいこと（推しの案つき）

| # | 問い | 推し |
|---|---|---|
| 1 | ランチャーとクライアントアプリの境目：`session_start` と `session_attach` を送るのは、窓を持つクライアントアプリ、ランチャーは「何を、どこで、どの大きさで」を決めて頼むだけ、でよいか。中身（Rust）と Mac の画面のつなぎ方は、クライアントアプリの流れに合わせる | **そうする。** `offer` と `session_wait` を持つ所が送るのが、二重にならない。クライアントアプリの流れと、口の形（7 の表）を先に合わせる |
| 2 | 言葉：`Quit` / `Force Quit…` / `Close Window Only` / `Show Here` / `Not shown`。「Session」「Detach」は画面に出さない | **この言葉にする。** Mac の人が知っている言葉に寄せ、この仕組みに特有の操作だけ、中身を言う |
| 3 | この Mac にしかないアプリを、ランチャーに出すか | **出さない。** 両方にあるアプリは出し、決まりどおり手元で開く。名前の下の `on this Mac` で開く先が分かる。手元で開くのが嫌な人のために、右クリックの `Open on ▸` を置く |
| 4 | すでにあるセッションに戻るとき（`session_attach` の `display`）に、大きさを変えられるか。映像の側の約束による | **最初の版では、変えない**（開いたときの大きさで戻る）。変えられると分かったら、`Show` にも大きさのシートを足す |
| 5 | 大きさの単位：選択肢をポイント（窓の見た目）で決め、画素への直し（Retina の 2 倍）はビューアーに任せる。大きい窓は圧縮する画素が増える。遅延の線を満たすことを確かめた大きさを、上限にするか | **ポイントで選ぶ。** 上限は、映像の側に、確かめた最大の大きさを聞いてから決める。それまでは `Fill Screen` も出し、確かめていない大きさであることは、使う人には出さない（計測の側の課題として記録する） |
| 6 | 開いている途中で Esc（やめる）を押したとき。アプリがすでに起動していたら、閉じるよう頼むか、Running に残すか | **閉じるよう頼む。** 開いてすぐやめたのは、間違えて開いたとき。アプリが起動する前なら、何も残らない。尋ねられたら、そのまま Running に残る |
| 7 | エンコーダーを断られて、作れる数が設定より下がっているとき、ホストはその数を答えに載せていない。説明の `up to 8` が、その間だけ正しくない | **いまは、数を出さない文にする**（`tower is updating as many windows as it can at once`）。数を出したくなったら、制御の側に、ホストの答えへの項目の追加を頼む |
| 8 | 「ホストがこの Mac を解除した」と「ホストが答えない」を、クライアントが分けられるか（ハンドシェイクで断られたことが、分かる形で返るか。ADR 0007） | **分けられるなら分ける。** 分けられないなら、`Not answering` に寄せ、説明に「ペアリングが外れたかもしれない」を足す。ADR 0007 の手順は変えない |
