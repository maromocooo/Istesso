# ADR 0028：同じ PC の中で入力を渡す口の守り

- 状態：【提案】（持ち主はまだ決めていない。権限と入力の経路に触るので、別の目の見直しを受けてから）
- 日付：2026-11-20
- かかわる文書：ADR 0021「隔離と、机と同じ設定を両立させる」の「同じユーザーのほかのプログラムに対して、どこまで守るか」（`m5-design` ブランチ。閉じる順番の 2 が、この文書）、[ADR 0007](0007-control-channel.md) の「入力」、[ADR 0017](0017-mac-host-permissions.md)

## 背景

キーボードとポインターの入力は、端末のあいだでは、制御チャンネル（暗号化と認証つき。ADR 0007）で運ぶ。その前と後ろに、**同じ PC の中で、プログラムからプログラムへ渡す所**がある。

| 所 | 渡す側 | 受ける側 |
|---|---|---|
| ホスト（Linux、Mac） | エージェント（ペアの端末から届いた入力を持っている） | アプリを映すプログラム（入力をアプリに入れる。Mac では、アクセシビリティの許可を持つ） |
| 見る側（手元の Mac など） | 窓を出すプログラム（人が打ったキーを持っている） | 入力を送るプログラム（`istesso input relay`。この端末の鍵で、ホストへ送る） |

いまは、どちらも、**名前のあるソケット**（ファイルシステムの上のパス。データグラム、1 つの入力が 1 つの JSON）で渡している。守りは、ファイルとフォルダーの権限だけである。権限は、ほかのユーザーを止める。**同じユーザーのほかのプログラムは、止めない。** 同じユーザーのプログラムは、

- その名前に**書ける**：映しているアプリに、キー、文字、クリックを入れられる。ホストでは、OS がふつうは許さないこと（Mac ではアクセシビリティの許可、Linux では Wayland がクライアントどうしを分けていること）を越える。見る側では、ペアリングの信頼を借りて、ほかの PC に届く。
- その名前を**差し替えられる**（消して、同じ名前で開く）：渡す側は、そこへ送ってしまう。人が打ったキー（パスワードを含む）が、そのプログラムに届く。

ADR 0021 は、線を「OS が同じユーザーのほかのプログラムに許していないことを、Istesso を通して許さない」と決め（2026-11-19、持ち主）、閉じる順番の 2 を「入力の口（受ける側と、渡す側の両方。差し替えられないこと）」とした。この文書は、その形を決める。

## 仕組みごとに、何が守れて、何が守れないか

どれも OS の公開の口。**同じユーザーのほかのプログラム**に対して効くかどうかを、はっきり書く。

| 仕組み | ほかのユーザーに対して | 同じユーザーのほかのプログラムに対して |
|---|---|---|
| 名前のあるソケットの権限（フォルダー 0700、ソケット 0600） | 守る | **守らない。** 書ける。消して、同じ名前で開ける |
| Linux の抽象ソケット（名前だけがあって、ファイルのない口） | **守らない。** 権限というものがない。先にその名前を取った者が、受ける側になる | 守らない |
| 相手の確かめ（Linux の `SO_PEERCRED`、macOS の `LOCAL_PEERCRED`、`getpeereid`）で、ユーザーを見る | 守る（権限と同じ強さ） | **守らない。** 答えは「同じユーザー」で、区別がつかない |
| 相手の確かめで、プロセスを見て、そのプログラムのファイルを確かめる（Linux：`/proc/<番号>/exe`） | — | **速度を落とすだけ。** 同じユーザーは、そのプログラムを、自分の引数、環境変数、読み込ませるライブラリー、デバッガーの下で起動できる。プログラムのファイルを本人が書けるなら、確かめにならない（ADR 0021 の 5 と同じ） |
| 相手の確かめを、データグラムのソケットで行う | — | できない。つないだ相手、というものがない（Linux には、1 通ごとに送り主を付ける仕組みがある。macOS にはない）。行うなら、つなぐ種類のソケットに替える |
| macOS：監査トークンから相手のコード署名を確かめる（決まった証明書、識別子、hardened runtime、決まった版より新しい） | — | **守る。ただし、条件がある。** 証明書で署名した版であること。確かめを通るプログラムが、命令や行き先を外から受けないこと（受けるなら、確かめはそこで無くなる）。署名の鍵を、同じユーザーのプログラムが問いなしで使えないこと。自分で組み立てた版（ad hoc の署名）では、成り立たない |
| セッションごとの合い言葉（受ける側が決めた乱数を、送る側が付ける） | — | **足しにならない。** 合い言葉を、正しい相手にだけ渡す道が要る。同じユーザーの中では、ファイルも、起動の引数も、環境変数も、ほかのプログラムから読める。読めない道は、起動のときに受け継がせることだけで、それができるなら、ソケットそのものを受け継がせれば足りる |
| **名前のないソケットの組**（socketpair）を、起動のときに受け継がせる | 守る | **守る。** 名前がないので、つなぐ先も、差し替える物もない。限りは、下の「守れないこと」 |

## 決めること（【提案】）

### 1. 製品の形は、名前のない組

入力を渡す 2 つのプログラムは、名前で出会わない。**片方が、もう片方を起動する。** 起動する側が、つながったデータグラムのソケットの組を作り、片方の端を自分で持ち、もう片方の端を、起動するプログラムに受け継がせる（ADR 0021 の「製品で閉じる形」の 1）。運ぶものは変わらない（1 つの入力が 1 つのデータグラム、JSON）。

- **だれが起動するか。**
  - ホスト（Linux）：アプリマネージャー（エージェント）が、アプリを映すプログラムを起動して、端を渡す（M3 と合わせて作る。セッションごとに 1 組）。それまでの形として、アプリを映すプログラムが、自分のエージェントを、端を付けて起動する（`istesso agent --input-fd <番号>`）。
  - 見る側：窓を出すプログラムが、入力を送るプログラムを、端を付けて起動する（`istesso input relay --input-fd <番号>`）。窓と送るプログラムを 1 つのプロセスにできるなら、そのほうがよい（ADR 0021 の 2）。そのときは、口そのものがない。
- **番号の渡し方。** 受け継いだ端が、何番のファイル記述子にあるかを、引数で言う。番号は、起動した者が渡した記述子の中でしか意味がないので、行き先を外から受けることには当たらない（ほかの者が番号を選べるなら、その者が起動した者であり、端の持ち主である。下の「守れないこと」の 1）。
- **受け取る側の確かめ。** 受け継いだ記述子を、そのまま信じない。データグラムのソケットで、同じ PC の中の種類で、**名前がなく、名前のない相手につながっている**ときだけ、入力の端として受ける。名前のあるソケットや、名前につないだソケットを渡されたら、断る（起動する側のまちがいで、名前のある口に戻らないように）。受けたあとは、その記述子を、自分が起動するプログラムに受け継がせない。確かめは、鍵を使う前に行う。
- **相手がいなくなったとき。** エージェントは、送って「相手がいない」と分かったら、それからは `input_open` に「受け取る相手がいない」と答える（名前のある口で、だれも聞いていないときと同じ）。入力を送るプログラムは、自分を起動したプログラムがいなくなったら、終わる（端の向こうがいないのに、ホストとの接続を持ち続けない）。ホストにつなごうとしている最中でも、終わる。起動したときに、親がもうシステムの最初のプロセス（1 番）になっていたら、起動した者は先にいなくなった、として、始めない。限り：起動した者がいなくなったあと、1 番ではないプロセスが親になる機械（孤児を引き取る係がいるとき）では、起動の時点でいなくなっていたことは、分からない。
- **状態のファイルは、ない。** 名前のある口では、入力を送るプログラムが、切れた回数を、ソケットの隣の小さいファイルにも書いていた。組の形では書かない（同じユーザーのプログラムが書き換えられるファイルを、窓が読むことになるため）。起動した側は、標準出力の行を読む。

### 2. OS の許可を持つプログラム（Mac のホスト）は、起動した者から入力を受けない

名前のない組は、「起動した者が、端の持ち主」という形である。アクセシビリティや画面収録の許可を持つプログラムが、起動した者から入力を受けるなら、**そのプログラムを起動できる者はだれでも、許可を借りられる。** macOS では、`open` で起動されたプログラムの親は launchd で、記述子も受け継がれない。だから、Mac のホストには、組の形は使わない。

- 【提案】(a) **許可を持つプロセスが、ネットワークから直に受ける。** 取り込みと、入力と、通信を、1 つのプロセスにまとめる（ADR 0021 の 2）。入力は、制御チャンネルで、ペアの端末であることと権限を確かめたあとの物だけになる。同じ PC の中の口は、なくなる。鍵とペアの一覧は、そのプロセスが、守られた置き場所から読む（ADR 0021 の 6）。
- (b) 分けなければならないなら、つなぐ種類の口（XPC か、ストリームのソケット）にして、**両方の向きで**、相手を監査トークンから、コード署名で確かめる（ADR 0021 の 4。入力方式の試作が、この形を先に作っている）。データグラムの名前のある口は、使わない。
- どちらも、証明書で署名した版が前提（配り方は、ADR 0021 の問い 26）。**このブランチでは、作っていない**（署名したバンドルと、持ち主の画面が要る。試用のホストは、別のブランチにあって、試用版は変えない決まり）。

### 3. 名前のある口は、計測の道具と、試用版にだけ残す

- 計測の道具（計測のホストのスクリプト、計測のビューアー、画面のプローブ）は、最終判定まで変えない。名前のある口を使い続ける。計測は、持ち主の機械で、持ち主が入れたプログラムだけが動くときに行う（ADR 0021 の「段との関係」）。最終判定のあとで、組の形に替える（下の「採用されたら直すもの」）。
- 残っているあいだの決まり：場所は、アカウントから決まった所だけ（`sec-s3-fixed-destinations` の決まり）。フォルダーは 0700、ソケットは 0600 が、あるべき形。**このブランチのコードが自分で 0600 にするのは、入力を送るプログラムが作るソケットだけ**（起動した者の umask に任せない）。ホストの側の名前のあるソケットは、アプリを映すプログラム（計測のスクリプト）が作るもので、その権限は、そのプログラムの umask のまま。エージェントは、それを確かめない。ほかのユーザーを止めているのは、上のフォルダーの権限である（`/run/user/<番号>` は、本人のもので、ほかの人が入れないときだけ使う。`sec-s3-fixed-destinations` の決まり）。**どれも、ほかのユーザーへの守りで、同じユーザーのほかのプログラムへの守りではない。** 名前のある口を使うプログラムは、起動のときに、そのことを 1 行で言う（エージェントは、鍵とペアの一覧の置き場所の 1 行と、合わせて 1 行。書けなくても止まらない）。
- 名前のある口に、相手の確かめ（ユーザー、プロセス）や、合い言葉を足すことは、しない。上の表のとおり、同じユーザーの中では守りにならず、守っているように見えるだけになる。
- Linux の抽象ソケットは、どこにも使わない。

### 4. 端を持つプロセスを、のぞかせない（Linux）

名前のない端は、それを持つプロセスと同じだけ守られる。Linux では、同じユーザーのプログラムが、ほかのプロセスにデバッガーでつなげるなら、そのプロセスの記述子を写し取れる（`pidfd_getfd`）。メモリーも読める（鍵を使っているあいだは、鍵もそこにある）。Ubuntu の決まり（Yama の `ptrace_scope` が 1）では、つなげるのは、そのプロセスの**先祖**（親、その親、…。起動した者と、それを起動した者すべて）だけだが、決まりが 0 の機械では、同じユーザーのだれでもつなげる。

- 【提案】端を受け取ったプログラム（`--input-fd` で起動したエージェントと、入力を送るプログラム）は、自分を「のぞかせないプロセス」にする（`prctl(PR_SET_DUMPABLE, 0)`）。そのあとは、システムの権限を持たないプログラムは、同じユーザーでも、起動した者でも、デバッガーでつなげず、メモリーと環境変数を読めず、記述子を写し取れない。
- **閉じるのは、端を受け取った側だけ。** 組を作って起動した側（もう片方の端を持つプログラム）は、自分で同じことをしなければ、のぞける。ライブラリーとして端を渡されたエージェント（`AgentOptions` の `input_end`）も、自分では閉じない。渡す側のプログラムが、起動のときに、自分を閉じる（`input_end` の説明に書いた）。組は、**両方の端のプロセスが閉じているときに**、同じユーザーのほかのプログラムから届かない。
- **起動してから閉じるまでの、すきま。** プログラムが起動して、引数を読み、端を確かめ、自分を閉じるまでのあいだは、まだ閉じていない。そのあいだは、つなげる者（決まりが 1 なら先祖、0 なら同じユーザーのだれでも）が、つないで、端を写し取れる。2 度目の見直しで、起動した者として試したところ、端の写しを 1 回の起動で 600〜790 回取れて、最後に取れたのは、起動から 1.6〜7.2 ミリ秒のあとだった（数ミリ秒、長くて約 7 ミリ秒。はじめの見直しで、追跡の道具の下で計った約 3 ミリ秒より長い）。決まりが 0 の機械では、このすきまを、同じユーザーのどのプログラムも使える。
- **すきまを無くす道は、Linux にもある：本人が読めないプログラムのファイル。** 本人が読めないファイル（root が入れて、権限が 0711 のように、実行だけを許すもの）を起動すると、カーネルが、はじめから「のぞかせないプロセス」として起動する（読めないファイルの中身が、デバッガーやコアダンプから漏れないようにする、もとからの振る舞い）。2 度目の見直しで、同じプログラムを実行だけの権限（0111）にして、起動した者として試したところ、3 回とも、写しは 1 回も取れなかった（どれも断られた。1 回あたり約 33 万回試した）。`prctl` を呼ばない、名前のある口の形でも、閉じていた。root が 0711 で入れた版なら、決まりが 0 の機械でも、すきまはない。限り（考え。試していない）：
  - 閉じるのは、起動（exec）からあと。起動する側が組を作ってから、新しいプログラムが起動するまで（fork と exec のあいだ）は、起動する側のプロセスの写しなので、起動する側が自分で閉じていなければ、のぞける。
  - はじめからデバッガーの下にいる起動する側は、起動したプログラムにも、つないだまま（持ち主のまま）でいられる。下の「守れないこと」の 4。
  - 本人のもののファイル（自分で組み立てた版、ホームの下に置いた版）は、本人が、読める権限に戻せる。守りになるのは、root のもので、本人が権限を変えられないファイルだけ。
  - 入れ方（パッケージ）で決まることで、コードでは決まらない。いまのテストの版（cargo で組み立てた、本人のもののファイル）には、当たらない。
- だから、本人が読めるファイルで動かすときに、決まりが 0 の機械では、この形は「速度を落とす」までで、`istesso doctor` で言う（下の「採用されたら直すもの」）。root が 0711 で入れる入れ方は、持ち主への問いの 3 に、提案として足した。
- 閉じる呼び出しが失敗したら（Linux）、端を使わずに、エラーで終わる（閉じていないのに、閉じたつもりで進まない）。
- 引き換え：落ちたときに、メモリーの写し（コアダンプ）が残らない。同じユーザーの道具（`lsof` など）から、そのプロセスが開いているファイルが見えなくなる。名前のある口で動くとき（計測の道具）には、行わない。
- macOS では、プログラムの中から行えることは、守りにならない（デバッガーを断る呼び出しはあるが、メモリーを読む別の道を止めない。考え。試していない）。守りは、署名のしかた（hardened runtime で、デバッグを許すエンタイトルメントがないこと）である。自分で組み立てた版では、成り立たない。プログラムは、そのことを言う。

## 守れないこと（同じユーザーのほかのプログラムに対して。はっきり書く）

名前のない組にしても、次のことは残る。

1. **2 つのプログラムを自分で起動するプログラムは、端の持ち主になれる。** 組は「起動した者」を信じる形である。だから、OS の許可を持つプログラムには使わない（上の 2）。許可を持たないプログラム（Linux のエージェント、入力を送るプログラム）では、起動した者が得るのは、自分が起動したプログラムへの入力だけで、動いているほかの組には届かない。ただし、そのプログラムが、この端末の**本物の鍵**で動くなら、起動した者は、ペアリングの信頼を借りられる（次の 2）。
2. **鍵のファイルを読めるプログラムは、ネットワークから入れる。** 鍵とペアの一覧が、同じユーザーの読み書きできるファイルにあるかぎり、同じユーザーのプログラムは、鍵を写すか、自分の端末をペアの一覧に足して、正しい端末として入力を送れる。入力の口を閉じても、この道は残る。閉じるのは、鍵とペアの一覧の置き場所（ADR 0021 の問い 27、[ADR 0006](0006-pairing.md)）と、専用ユーザー（U2）。Linux では、専用ユーザーまで、閉じない。
3. **プログラムのファイルを書き換えられるなら、次に起動したときから、そのプログラムになれる。** 本人が書ける場所に入れたプログラム（自分で組み立てた版、ホームの下に置いた版）は、同じユーザーが置き換えられる。守るのは、root が入れた場所と、署名（macOS）。
4. **デバッガー。** Linux：上の 4 を入れても、**自分で起動して**、はじめからデバッガーの下に置いたプロセスや、ライブラリーを読み込ませたプロセスには、届く（届くのは、そのプロセスの端だけ。1 と同じ）。**起動してから自分を閉じるまでのすきま**（数ミリ秒。見直しで、長くて約 7 ミリ秒）には、つなげる者がつなげる：`ptrace_scope` が 1 なら先祖だけ、0 なら同じユーザーのだれでも。プログラムのファイルを本人が読めない（root が 0711 で入れた）ときは、このすきまはない（上の 4。fork と exec のあいだは、起動する側しだい）。**閉じるのは、端を受け取った側だけ**で、組を作った側と、ライブラリーとして端を渡されたプロセスは、自分で閉じなければ、のぞける。macOS：署名していない版、デバッグを許す版には、つなげる。
   - macOS では、組を作る呼び出しと、「プログラムを起動するときに閉じる」印を付ける呼び出しが、別々である。そのあいだに、同じプログラムの別のスレッドが、ほかのプログラムを起動すると、そのプログラムが両方の端を持って生まれる。組は、プログラムを起動するスレッドができる前に作る（`endpoint` の `pair` の説明に書いた）。
5. **見る側の窓に入る入力そのもの。** OS の許可（アクセシビリティ）を持つプログラムは、窓にキーを入れられる。OS が許していることなので、線の外。
6. **OS の許可を持つプログラムを、自分の行き先で起動すること**、**古い署名の版を持ち込むこと**は、この文書の範囲ではない（閉じる順番の 1 と、ADR 0021 の 8）。
7. **試用版と計測の道具の、名前のある口**は、そのまま開いている（上の 3）。入力のほかの口（クリップボードの口、言葉のパイプ）も、この文書では閉じていない。同じ形（名前のない組、または 1 つのプロセス）にするのが【提案】。
8. ユーザーそのものが乗っ取られたとき（そのユーザーで、何でも動かせるとき）は、ADR 0021 と脅威モデルのとおり、範囲の外。

## このブランチで作ったもの

- `istesso-agent` の `endpoint`：名前のない組を作る、起動するプログラムに端を受け継がせる、受け継いだ端を確かめて受け取る、プロセスをのぞかせなくする（Linux）。
- `istesso agent --input-fd <番号>`：入力を、名前のある口ではなく、受け継いだ端で渡す。ライブラリーでは `AgentOptions` の `input_end`（アプリマネージャーが、自分で作った組の端を渡すための口）。
- `istesso input relay --input-fd <番号>`：`--socket` の代わり。名前も、状態のファイルも作らない。起動した者がいなくなったら終わる（つなごうとしている最中でも。起動のときに、もういなければ、始めない）。
- `istesso input relay --socket`：作ったソケットを 0600 にする。同じユーザーのほかのプログラムは止められないことを、1 行で言う。エージェントは、名前のある口で動くとき、起動のときの 1 行（鍵とペアの一覧の置き場所の行と、合わせて 1 行）で言う。どの 1 行も、書けなくても、プログラムを止めない。`istesso doctor --json` には、何も足さない。
- 既定は変えていない（指定しなければ、いままでどおり、名前のある口）。計測の道具は、そのまま動く。
- 作っていないもの：Mac のホストの形（上の 2）、アプリマネージャーが組を作って渡す所（M3 のブランチ）、計測の道具と試用版の切り替え、クリップボードの口と言葉のパイプ。

## 遅延

- 入力の経路に触る。運び方は同じ種類（同じ PC の中のデータグラムのソケット、1 つの入力が 1 つのデータグラム）で、足したのは、起動のときの確かめと、入力を送るプログラムの、起動した者がまだいるかの確かめ（待ちの 1 周ごとに、システムコールが 1 つ。組の形のときだけ）。
- **計測していない。** 既定（名前のある口）の経路は、送るたびの処理を変えていない（エージェントは、送れなかったときの理由を見るようになった。組の形のときだけ使う）。組の形を既定にする前に、変更前後を計測する（AGENTS.md の 3）。

## 権限

増えない。root も、OS の許可（画面収録、アクセシビリティ、入力監視）も、使わない。`prctl(PR_SET_DUMPABLE, 0)` は、自分のプロセスの権利を**狭める**呼び出しで、権限は要らない。

## ライセンスと特許

使うのは OS の公開の口だけ（`socketpair`、記述子の受け継ぎ、`getsockopt`、`fcntl`、`prctl`）。仕様を借りて作り直すものはない。依存するクレートは増やしていない。特許は調べていない（ADR 0021 と同じ）。

## 確かめ

テストで見ること（Mac と、Linux のホストで動かす）：

- 名前のない組の端を受け継いだプログラムは、それを受け取れる。受け継いでいないプログラムは、同じ番号を言っても、受け取れない。
- 名前のあるソケット、名前につないだソケット、つながっていないソケット、ストリームのソケット、ネットワークのソケット、ファイル、標準入出力は、入力の端として断る。断るのは、鍵を使う前。
- エージェントに端を渡すと、入力は端に届き、名前のある口には何も届かない。向こうの端が閉じられたら、それからは、入力を開けない。
- 2 つのコマンドを、端から端までつないで、名前のあるソケットが 1 つも作られないまま、キーが届く（開発用のビルドで、自分のフォルダーの中だけで動かす）。
- 入力を送るプログラムは、起動した者がいなくなると終わる。
- Linux：のぞかせなくしたプロセスは、起動した者からも、環境変数、開いているファイルの一覧、プログラムの場所を読めない。のぞかせなくしていないプロセスは読める（比べるため）。

まだ見ていないこと：2 台をつないだ、ふだんの使い方。遅延。ADR 0021 の「確かめ」（許可を持たない、同じユーザーの試験のプログラムから、入れられない、読めないこと）のうち、Mac のホストにかかわるもの。

## 採用されたら直すもの

- 最終判定のあと：計測のホストのスクリプトが、名前のある口を作る代わりに、組を作って、エージェントを `--input-fd` で起動する。計測のビューアーと画面のプローブが、入力を送るプログラムを、端を付けて起動する。
- M3：アプリマネージャーが、セッションごとに組を作り、アプリを映すプログラムに端を渡す（ADR 0007 の「セッションを決めるときに、合わせること」と一緒に）。
- Mac のホスト：上の 2 の (a) か (b)。ADR 0017 に、口の形を書く。
- クリップボードの口、言葉のパイプ：同じ形にする。
- `istesso doctor`：Linux で、デバッガーの決まり（`ptrace_scope`）が 0 で、プログラムのファイルを本人が読めるときに言う。名前のある口で動いているときに言う。
- Linux の版を入れるとき（問いの 3 で、よいとなったら）：プログラムのファイルを、root のもの、権限 0711 にする。
