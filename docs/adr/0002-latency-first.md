# ADR 0002：遅延を最優先する（手元優先の構成）

- 状態：採用
- 日付：2026-11-15

## 背景

成功の基準は「リモートだと感じないこと」。映像の中継は、どれだけ速くしても取り込み・圧縮・転送・復号の分だけ遅れる。

## 決定

遅延の小さい順に、次の3つを使い分ける。

1. **手元で動くものは手元で動かす。** 同期するのは状態（ファイル、セッション、クリップボード）だけ。
2. **文字はターミナルで直接つなぐ。** herdr のセッションをホスト側に置き、手元の端末から入る。
3. **残りだけを映像で中継する。** 有線、120 Hz、ハードウェアエンコード。カーソルと窓の移動は手元で描く。

あわせて次を決める。

- 合格ラインは追加遅延の数値で定義し、常時計測する。
- 基準の対象は自宅の有線 LAN とする。出先は対象外。
- メインの端末は Mac とする。Mac アプリが手元でそのまま動き、中継が要るのは Linux のアプリだけで済むため。

## 根拠

- 間接操作（トラックパッド）で人が遅延の差に気づき始めるのは約 55 ms という研究がある（Deber ほか、CHI 2015）。有線 LAN の配信で加わる遅延はこれより十分小さくできる。
- 反応の速さが要るゲームは遅延に最も敏感なので、同じ基準では扱わない（配信の種類を分ける）。

## 結果

- 「同じ画面」は「同じ画素を飛ばす」ことではなく、「同じ作業状態に戻れる」ことと定義する。
- 出先でも続きをやりたいアプリは、常時稼働のホストに置く必要がある。
- 最初のマイルストーン（M1）で遅延を実機で確かめ、満たせなければ構成を見直す。
