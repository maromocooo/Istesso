# ADR 0004：USB 機器は種類ごとに扱いを分ける

- 状態：採用（2026-11-15）。2026-11-16 に決定を 5 つ足した。決定だけでは決まらないところは、ねらいに合うほうを選び、提案として書いた（下の「ねらいに照らして選んだこと」）
- 日付：2026-11-15
- 更新：2026-11-16（挿す場所の勧め、起動先の選び方、会議アプリの扱い、Mac で作らないもの、確認項目を足した。2 台の実機を調べて「権限」の節を足し、「制約」と「部品」を直した）

## 背景

Stream Deck、キーボード、マウス、オーディオ機器など、普段使っている機器をこの仕組みの中でも使いたい。全 PC の機器を一覧し、切り替えられるようにする。

USB をそのまま別の PC に付け替える方式（USB/IP）は汎用だが、次の問題がある。

- 受け側が Mac の場合、仮想 USB コントローラーの作成に Apple の個別許可が要る。各自がビルドする OSS では現実的でない。
- タイミングに厳しいオーディオ機器では、ネットワークの遅延でノイズが出やすい。
- 入力機器を付け替えると、挿してある PC では使えなくなる。

2026-11-16 の決定のねらい：Mac は、ほかの PC に挿した機器を、USB 機器として受け取れない。それでも使う人が困らないように、**機器を挿す場所と、アプリを開く場所**で解く。使う人に守ってもらうのは「どこに挿すか」だけにする。あとは、Istesso が正しい側でアプリを開く。

使う人は、開発者に限らない。導入がかんたんで、説明なしで使えることを、この文書の提案の物差しにする。

## 決定

一覧と切り替えの画面は共通にし、裏の方式を種類で分ける。

| 種類 | 方式 |
|---|---|
| キーボード、マウス | 入力の転送。USB の付け替えはしない |
| Stream Deck | このプロダクトが直接制御するモードを持つ。公式ソフトとどちらが使うかを切り替える。機器対応のフレームワーク（[ADR 0012](0012-device-framework.md)）の上に、最初のアダプターとして作る |
| オーディオ機器 | 音だけを運ぶ（[ADR 0005](0005-audio-service.md)） |
| その他 | USB/IP で付け替える |

2026-11-16 に足した決定：

1. **USB 機器は、Linux か Windows の PC に挿すことを勧める。** オーディオ機器は例外で、機器は動かさず、音として運ぶ（ADR 0005）。
2. **アプリマネージャーの起動先の選び方に、1 つ足す。** USB 機器を使うアプリは、その機器を受け取れるホストを優先する。同じアプリが Mac と Linux の両方にあるとき、機器を使うなら Linux の側で開く。
3. **会議アプリは、マイクとカメラがつながっている PC で開く。**
4. **Mac の上に、仮想のマイク、カメラ、USB 機器を作ることは、対象外とする。**
5. **確認項目を足す。** スピーカーで聞く会議で、声が回り込まないか（下の「確認項目」）。

キーボードとマウスは、この方針の対象外である。上の表のとおり、入力の転送で扱う。

例：

- マイクとカメラを Ubuntu に挿してある。会議を始めると、会議アプリは Ubuntu で開き、Mac には窓として出る。マイクもカメラも Ubuntu の中で済むので、何も運ばない。
- MacBook Air の内蔵のマイクとカメラを使うときは、会議アプリを Air でそのまま開く。

Windows をこのリリースに含めるかどうかは、まだ決まっていない。この文書の Windows についての記述は、含めると決まったときのものである。

## 理由

- **1 について。** 付け替えを受けられるのは、Linux と Windows だけである。機器が Linux か Windows に挿してあれば、その PC のアプリはそのまま使える。Mac に挿した機器をほかの PC へ出すには、root が要る。
- **2 について。** アプリのほうを、機器を使える PC で開けば、機器を Mac へ運ぶ必要がなくなる。Mac は受けられないので、これしか方法がない場面がある。
- **3 と 4 について。** Mac のアプリに、ほかの PC のマイクやカメラを見せるには、Mac の上に仮想の機器を作るしかない。仮想のカメラはシステム拡張、仮想のマイクはシステムに入れるオーディオドライバーで、どちらも使う人の承認や管理者権限での導入が要る。GPL の仮想オーディオドライバーは使わない（[components.md](../components.md)）。導入のしやすさ（R-12）に合わないので、作らない。その代わりに、会議アプリを、マイクとカメラのある PC で開く。

## 挿す場所と、使えるアプリ

| 機器を挿した PC | その PC のアプリ | ほかの Linux のアプリ | ほかの Windows のアプリ | ほかの Mac のアプリ |
|---|---|---|---|---|
| Linux | そのまま使える | 付け替えで使える | 付け替えで使える | 使えない |
| Windows | そのまま使える | まだ使えない（出す側の実装がない。下の「制約」） | 同左 | 使えない |
| Mac | そのまま使える | 付け替えで使える。出す側に root が要る | 同左 | 使えない |

この表から言えること：

- 機器が勧めのとおり Linux に挿してあれば、決定の 2 のとおり、Linux の側で開く。機器が Mac に挿してあって、そのアプリが同じ Mac にあるときは、その Mac で開く。機器が、そこでそのまま使えるからである。2 つ目の例（Air の内蔵のマイクとカメラ）と同じ考え方で、こう読んだ。
- 勧めの中でも、Linux が先になる。Windows に挿した機器は、いまはその Windows のアプリからしか使えない。
- Mac でしか動かないアプリが使う機器は、勧めの例外で、その Mac に挿す。
- 勧めのとおりに挿してあれば、付け替えが要るのは、Linux か Windows のホストが 2 台以上あるときだけになる。いまの機材（Linux は 1 台。Windows は未決）で付け替えが要るのは、Mac に挿した機器を Linux のアプリで使うときだけである。

## 制約

- 受け側が Mac の付け替えはしない。Mac のアプリで使う機器は、その Mac に直接挿す。
- Linux や Windows のアプリで使う機器は、Linux か Mac に挿してあれば、付け替えて使える。2026-11-15 の版は「どの PC に挿してあってもよい」と書いていたが、Windows に挿した機器は出せないので、こう直した。
- Mac から出す側は root 権限が前提。
- Windows から出す側の既存実装（usbipd-win）は GPL-3.0 なので使わない。必要になれば内製する。
- USB/IP の手順そのものには、認証も暗号化もない。R-13（相互認証、端末ごとの USB の権限）を満たす運び方は、まだ決めていない。付け替えを作る前に、この文書に足す。

## 権限と、使う人の手間

権限の要る処理を増やすときは、理由を ADR に残す決まりである（AGENTS.md）。2026-11-16 に、Ubuntu 24.04 のホストと、macOS 26 の Mac を、何も変えずに調べた。

| 場面 | 要る権限 | 理由 | 実機で分かったこと | 使う人の手間 |
|---|---|---|---|---|
| 機器の一覧（Linux） | なし | sysfs は誰でも読める | つながっている 23 台（ハブを含む）の ID と種類を、権限なしで読めた | ない |
| 機器の一覧（Mac） | なし | OS が持っている機器の情報は、誰でも読める | `system_profiler` と `ioreg` から読めた | ない |
| Stream Deck の直接制御（Linux） | 導入のときに 1 回、udev の決まりを入れる（root）。動かすときは要らない | HID の機器と直接話す口（hidraw）は、既定では root しか開けない | 口は 18 個すべて root だけだった。Elgato の機器のための決まりは、入っていなかった | インストーラー（M9）ができれば、ない。.deb が決まりを一緒に入れる。それまでは、`sudo` のコマンド 3 行を 1 回 |
| Stream Deck の直接制御（Mac） | 未確認 | macOS が「入力監視」の許可を求めるかもしれない | 試していない。公式ソフトが動いている | 許可が要るなら、最初に 1 回、ダイアログに応える（R-12 の案内に入れる） |
| 付け替えの受け側（Linux） | root。仮想 USB コントローラー（`vhci-hcd`）の読み込みと、付け替えのたびの操作 | カーネルの仮想コントローラーに機器をつなぐ操作は、root だけに許されている | モジュールはあるが、読み込まれていない。Secure Boot は有効で、モジュールにはカーネルの署名がある | root で動く小さな部品を、インストーラーが入れる形にできれば、ない。それがないあいだは、付け替えのたびに `sudo` |
| 付け替えの出す側（Mac） | root | OS のドライバーから、機器を取り上げるため | 試していない | 受け側と同じ |
| 付け替えの出す側（Linux） | udev の決まりで足りる見込み | 機器のデバイスノードを開ければ足りる見込み | 試していない | インストーラーが決まりを入れれば、ない |

- udev の決まりは、対応する機器が増えるたびに 1 行増える。フレームワークが、アダプターの説明から作る（ADR 0012）。
- 専用ユーザー（[ADR 0003](0003-isolation.md)）で動かすときは、その PC の前でログインしている人に与える形（`uaccess`）では届かない。グループで与える形にする。M5 と合わせて決める。
- root の要る部分（Linux の受け側、Mac の出す側）を、製品でどういう形で持つかは、まだ決めていない。付け替えを作る前に、この文書に足す。

## 部品

- 出す側：jiegec/usbip（MIT）。0.9.0 は、`rusb` クレートを通じて libusb（LGPL-2.1）を使う。libusb は動的リンクで使い、依存を足すときに components.md の「条件つきで使える」に書く（[ADR 0001](0001-license-and-components.md)）。クレートの表示は MIT なので、`cargo deny` はこれに気づかない
- Linux の受け側：カーネル標準
- Windows の受け側：usbip-win2（BSD-2-Clause）
- Stream Deck：公開されている MIT の実装を参考に内製。フレームワーク（ADR 0012）の上のアダプターとして作る

## 確認項目

### スピーカーで聞く会議で、声が回り込まないか

- **確かめること：** 会議の相手に、相手自身の声が返って聞こえないこと。
- **なぜ起きうるか：** 会議アプリは、自分が鳴らした音を手がかりにして、マイクに入った相手の声を消す。音をほかの PC のスピーカーから出すと、鳴る時刻が遅れ、時計も別になる（ADR 0005 の配信経路）。アプリの消し方がそれに追いつくかどうかは、試すまで分からない。
- **3 つの形で確かめる：**
  1. 会議アプリのある PC のスピーカーで聞く。この仕組みは音に関わらない。比べるための基準である。
  2. 会議アプリのある PC の音を、ほかの PC の「音の出口」から聞く。
  3. 2 に加えて、会議アプリの窓を、ほかの端末に映す。1 つ目の例の形で、ふだんはこの形になる。
- ヘッドホンで聞くときは、対象にしない。
- 回り込んだときの手当ては、決めていない。確かめた結果を見て、この文書に足す。

## 結果

- 起動先の選び方（R-04）は、「手元 → 起きているホスト → 負荷の低いホスト」の前に、機器の条件を見る形になる。同じアプリが手元にあっても、機器がほかの PC にあれば、そちらで開いて映像で中継する。手元で動かすより、遅延は増える。機器が要るアプリを「手元では動かないもの」として扱う、ということである（[ADR 0002](0002-latency-first.md) の順は変えない）。
- Mac の会議アプリは、ほかの PC のマイクとカメラを使えない。Mac で会議をするなら、その Mac のマイクとカメラを使う。
- 付け替えの出番が減る（上の「挿す場所と、使えるアプリ」）。
- アプリマネージャー（M3）は、起動先を選ぶときに、機器の一覧を見ることになる。会議の決まりのために、一覧には、USB でない内蔵のマイクとカメラも入れる。
- 個別に対応する機器と、その足し方は、ADR 0012 で決める。

## ねらいに照らして選んだこと（提案）

決定だけでは決まらないところを、ねらい（使う人に守ってもらうのは「どこに挿すか」だけ）に合うように選んだ。決まったものではない。

### 1. アプリが機器を使うことは、Istesso が自分で知る

使う人に、アプリごとの印を先に付けてもらう形は採らない。ねらいに合わないためである。Istesso が自分で知る手がかりを、信じる順に並べる。

| 順 | 手がかり | 分かること | 弱み |
|---|---|---|---|
| 1 | 使う人が直した結果 | 確実 | 手間がかかる。だから、外れたときにだけ使う |
| 2 | 見て覚える。アプリが機器を開いているのをエージェントが見て、その組を覚える | 実際に使われた組 | 最初の 1 回には間に合わない。OS のサービスごしに使う機器（ストレージ、プリンターなど）は見えない |
| 3 | 機器の説明（ADR 0012 のアダプター）に書いてある「この機器を使うアプリ」 | その機器とアプリの組 | 誰かが書く必要がある。プルリクエストで足せる |
| 4 | カタログにあるアプリの種類と、機器の種類の組み合わせ（ゲームパッドとゲーム、など） | 大まかな見当 | 粗い |
| — | アプリが名乗っている権限（Mac の Info.plist、snap の接続） | その機器を使えること | 使えることと、使うことは違う。絞り込みにだけ使う |

実機で見たこと（2026-11-16）：

- Mac では、機器を開いているプロセスの名前を、権限なしで読めた（Stream Deck の公式ソフトが、そう見えた）。Linux では、同じユーザーのプロセスについて読める見込みだが、調べたときには、機器を開いているプロセスがなかった。
- アプリの種類は粗い。ホストのアプリ 122 個のうち、通話らしい種類を持つものは 2 個で、会議のための種類を持つものはなかった。ブラウザーは 3 個だった。
- 名乗っている権限は広すぎる。Mac のアプリ 53 個のうち 25 個が、カメラとマイクの両方を使うと名乗っていた。

外れたときの直し方：

- 分からないアプリは、今までどおりの順で開く。
- ランチャーに「機器のある PC で開く」を出す。選ばれたら、その組を覚える。使う人の印は、こうして、要るときに 1 回の操作で付く。
- 覚えたものは、一覧で見えて、消せる。覚えた中身は、ペアリングした端末の外へ出さない。
- この選び方が効くのは、その機器が、どこかの PC に挿してあるときだけである。

### 2. 会議アプリの見分け方と、開く PC

見分け方：カメラとマイクを使うと名乗っているアプリのうち、次のどれかに当てはまるもの。

- アプリの種類が、通話や会議である。
- 本体に持つ、よく使われる会議アプリの表にある（Mac のアプリの種類は、会議を見分けられるほど細かくない）。
- カメラとマイクを同時に開いているのを、エージェントが見た。

ブラウザーは、会議アプリとして扱わない。ブラウザーごと動かすと、ふだんの閲覧まで、ほかの PC で開くことになる（R-01 は、ブラウザーを手元で動かすと決めている）。ブラウザーで開く会議のために、ランチャーに「会議」の入口を 1 つ置く。選ぶと、マイクとカメラのある PC でブラウザーが開く。弱みは、会議のときに、使う人がその入口を選ぶ必要があることである。

開く PC：

1. 挿してある（外付けの）マイクとカメラの、両方がある PC。挿してあることを、使う人の意思と読む（1 つ目の例）。
2. なければ、手元の端末。内蔵のマイクとカメラを使う（2 つ目の例）。
3. 1 に当てはまる PC が 2 台以上あれば、いつもの順（手元が先）で選ぶ。

- 仮想のカメラは、数えない。Mac には、カメラのソフトが作った仮想のカメラが見えていた。
- マイクとカメラが別々の PC にあるときは、カメラのある PC で開く。その PC にマイクがなければ、「マイクも同じ PC に挿してください」と出す。マイクの音を運ぶ仕組みは、作らない（Mac へは運べない。ADR 0005 にもない）。

### 3. 機器のある PC が止まっているとき

- 起こせるなら、Istesso が起こしてから開く（R-04 の「起こす」）。待つあいだ、何をしているかを 1 行で見せる。
- 起こせないとき：会議アプリは、手元の内蔵のマイクとカメラで開き、そうしたことを 1 行で知らせる。ほかのアプリには「！」を付け、理由を出す。
- 弱みは、止めておきたい PC が起きることである。設定で切れるようにする。

### 4. Stream Deck は、どこに挿してもよい

- Stream Deck は、付け替えない。挿した PC のエージェントの中で、アダプターが機器と話す。ボタンの知らせと絵は、フレームワークが端末のあいだを運ぶ（ADR 0012）。Mac が「USB 機器として」受け取る場面がないので、Mac に挿したままでよい。
- 公式ソフトがあるのは、Mac と Windows だけである。公式ソフトと切り替えて使うなら、Mac か Windows に挿しておく。
- 同じことが、アダプターのある機器の全部に言える。勧め（Linux か Windows に挿す）が効くのは、付け替える機器（「決定」の表の「その他」）である。

### 5. 勧めは、一覧の画面で伝える

- 「その他」の機器が Mac に挿さっているとき、一覧のその行に「Linux の PC に挿すと、ほかの PC のアプリからも使えます」と出す。
- アプリを開く PC で機器が使えないときは、開く前に、どこに挿せばよいかを出す。
- 文書を読まなくても、挿す場所が分かるようにするためである。
