# ADR 0023：Mac ホストで、変換中の文字をアプリの中に出す入力ソース

- 状態：提案（試用だけ。2026-11-19）。`main` の前に Fable の見直しを通す（どのアプリにも文字を入れられる部品のため）。
- 関わるもの：[ADR 0020](0020-japanese-input.md)（道 d）、[ADR 0007](0007-control-channel.md)（`preedit` と `text`）、[ADR 0015](0015-media-transport.md)（種類 5、文字の入力の欄）、[ADR 0017](0017-mac-host-permissions.md)。試作と手順：[m4-input-method-trial.md](../m4-input-method-trial.md)、`macos/input-method/`。

印：**見た**＝実機で自分で見た。**結論**＝Apple の文書・ヘッダーから読んだだけ。

## 状況

Mac Studio をホストにして、Air の入力方式が作る変換中の文字を、ホストのアプリの中に、そのアプリの字と下線で出したい。候補の窓は Air の入力方式が、アプリのキャレットのすぐ下に出す。Air が変換を続ける（道 d）。

別のプロセスから、アプリに変換中の文字（marked text）を渡せる公開の口は、**入力ソース（InputMethodKit）だけ**（結論）。アクセシビリティの `AXSelectedText`・`AXValue` は確定した文字だけ、`CGEventKeyboardSetUnicodeString` も確定だけ、`NSTextInputClient` と Text Services Manager のイベントはアプリの中の口。

## 決定

### 1. 入力ソースの形

- 束：`Istesso Dev Input.app`、識別子 `com.maromoco.istesso-dev.inputmethod.trial`（`.inputmethod.` を含む）、入力ソース ID も同じ。置き場所は利用者の `~/Library/Input Methods/`。足すのは持ち主の手（System Settings）。スクリプトで有効にしない。
- **Studio のキーボードは取らない**：`recognizedEvents` は空、`handle` はいつも「受けない」。
- 文字は、ホストのプログラムからだけ受ける（3.）。
- **言語は宣言しない**：`TISIntendedLanguage` を書かない。入力モード（`ComponentInputModeDict`）も持たない。理由（結論）：JIS の「かな」キーで選ばれるのは、入力モードの `kTSInputModeJISKeyboardShortcutKey`（1＝ひらがな）を持つモード（Apple の日本語入力のひらがな）。`TISCopyInputSourceForLanguage("ja")` は、その言語の有効な入力ソースのうち、最近使ったものを選ぶ。言語もモードも持たなければ、どちらにも選ばれない。
- **字の形**：渡す文字（変換中も確定も）には、Core Text の言語の属性 `ja` を付ける（`kCTLanguageAttributeName`：対応する字体で、言語に合った字形を選ぶ）。漢字が中国語の字形で出ないため。アプリがその属性を残すかはアプリしだい（TextEdit の標準テキストで確かめる）。

### 2. 切り替え（持ち主、2026-11-19）

- **ビューアーがつながっているあいだ、ずっと** Istesso の入力ソースを選ぶ。切れたら戻す。キーごと、変換ごとには切り替えない。選んだまま残さない。
- 戻すとき：切れたとき、30 秒の猶予が切れたとき、落ちたあとの次の起動のとき。そのため、切り替える前の入力ソースの ID を、ホストの状態のファイル（利用者だけが読める）に書いておき、戻したら消す。
- `TISSelectInputSource` は、日本語などの入力ソースで、メニューバーの印だけが変わり、実際には効かないことがあると言われる（未確認）。そこで、**ホストが「アプリの中に出す」形に入るのは、入力ソースが `active` を言い、その `client` が中継しているアプリで、キャレットが中継している窓の中にあるときだけ**。それまでは帯（いまの形）。`inactive` が来たら、帯に戻る。**文字を 1 つも落とさないこと**を、いちばん上に置く。
- **手元の入力**：Studio の前で打たれているあいだ（手元のキーが最近あった）は、切り替えない。そのあいだは帯。これは持ち主の言葉（「つながっているあいだずっと」）に、作業の一覧 0n の守りを足したもの。つながったあとに手元で打たれても、キーごとには戻さない（持ち主の言葉どおり）。
- **つながっているあいだ、Studio の手元のキーボードでは、日本語の変換ができない**（Istesso の入力ソースは変換しない。キーはそのまま英字で通る）。手元で日本語を打つには、ビューアーを切るか、手で別の入力ソースに切り替える（切り替えると、ホストは `inactive` を見て帯に戻る）。
- 戻したあと、いまの入力ソースを読み直し、戻ったかを記録する（「戻った：はい／いいえ」。ID そのものは記録に書かない）。

### 3. ホストと入力ソースのつなぎ方

- ホストがソケットを持つ：この利用者の一時フォルダー（`confstr(_CS_DARWIN_USER_TEMP_DIR)`）の中の自分のフォルダー（0700）に、ソケット（umask 0177 で作るので最初から 0600）。入力ソースが毎秒つなぎに来る。入力ソースは、つなぐ前に、フォルダーとソケットの持ち主・権限・種類を確かめる（リンクは不可）。
- **相手の確かめ（両方向）**：接続の相手の audit token（プロセス番号ではない）から、署名を確かめる。同じ利用者で、署名が厳密な検査（`kSecCSStrictValidate`）に通り、**自分と同じ葉の証明書**で、識別子が決まった一覧にあり、Hardened Runtime つきであること。入力ソースが受けるのは、試しのプログラム（`ime-probe`）と Mac ホスト（`daily-host`）。ホストが受けるのは入力ソースだけ。自分がアドホック署名なら、だれも受けない。
- **分かっている限界（試用）**：同じ利用者の別のプログラムは、ソケットにはつなげない（署名で断る）が、利用者の `~/Library/Input Methods/` の束を差し替えることはできる。差し替えた束は、同じ証明書で署名できなければ、ホストに断られる（証明書の秘密鍵は Studio にない）。同じ利用者のプログラムが、ほかの道（アクセシビリティなど）でアプリに文字を入れることは、この仕組みでは防げない。製品では、束の置き場所と署名（Developer ID）を見直す。
- 文字（変換中も確定も）は、どちらの側もログに書かない。数だけ。

### 4. 1 回だけ、順番どおり

- **変換の番号**：Air は、変換 1 つごとに番号を付ける（`comp`。使い回さない）。`mark` と確定（`commit`）は番号つき。入力ソースは、変換を見せているセッション（コントローラー）ごとに状態を持つ（全体で 1 つではない）。
- 変換が終わるのは 1 回だけ：Air の確定、アプリの終わらせ（ほかの所を押した、焦点が移った：入力方式のふつうのとおり、**見せていた文字をそのセッションに 1 回だけ確定し**、`ended` と番号をホストに言う）、消す（ホストが切れた）。終わった番号は覚えておき、あとから届いた同じ番号の `commit`・`mark` は捨てる（`stale`）。終わらせを受けた Air は、自分の変換を、確定し直さずに終える。
- 新しいセッションが、古いセッションの終わらせ（`deactivateServer`）より先に有効になっても、古い変換は古いセッションに確定する（新しいアプリに入らない）。
- **確定とキーの順番**：確定の文字は入力ソースの道、キーは CGEvent の道で、2 つの道のあいだに順番の保証はない。そこで、ホストは確定のあとのキーを、入力ソースの答え（`inserted`）が来るまで持つ（**長くて 50 ms**。過ぎたら送り、数える）。入力ソースは、`insertText` のあと、値を返すクライアントへの問い（範囲を読む）を済ませてから答える。アプリは前の挿入を済ませてからでないと答えないので、答えは「入った」を意味する（結論。試しで確かめる）。
- **切れたとき**：ホストが切れたら、入力ソースは見せていた変換を消す（確定しない）。ホストは Air の変換を取り消させる。

### 5. パスワードの欄

- 前面の欄がパスワードの欄（`AXSecureTextField`）なら、入力ソースで変換中の文字を出さない。ホストはアクセシビリティで見て、種類 5 の状態 2 を Air に送る。Air は入力方式を通さずに、ふつうのキーを送り、自分の側で Secure Event Input を入れる（Ubuntu の側の text-input-v3 の purpose と同じ）。
- 入力ソースも、Secure Event Input が入っているあいだは `mark` を断る（`secure`）。

### 6. キャレットの場所

- 入力ソースは、`firstRectForCharacterRange`（変換中の範囲の、選んでいる文節）を、大域の点（主画面の左下が原点）で返す。読めなければ `attributesForCharacterIndex` の行の四角。`top` は上からの y。
- ホストは、窓の左上（CGWindow の点）を引き、窓の点あたりの絵のピクセル数を掛けて、種類 5 の絵のピクセルにする。Air の文字の位置の数え方（UTF-16）と、`preedit` の範囲（UTF-8 のバイト）の直しは、入力ソースが行う。

### 7. 試しのための読み戻し（試作だけ。製品には入れない）

- `--trial-check` で作ったときだけ、`check` がある：TextEdit の中だけで、**変換中の文字の範囲だけ**のハッシュ（SHA-256）、範囲、長さ、確定が入った場所を返す。試しのプログラムは、送った文字のハッシュと比べて、**一致したかだけ**を出す。
- **製品の入力ソースには入れない**（アプリの文字を読める部品になるため）。ハッシュそのものは、どこにも書かない、出さない（短い文字のハッシュは、元の文字に戻せる）。

## 見たこと・まだのこと

- 見た：`istesso-ime-probe self-test`（Air と Studio）。相手の確かめ、知らない相手を断る、0600 でないソケットにつながない、範囲の直し、長さと制御文字の決まり。アドホック署名の写しは断られた。
- まだ（Studio に入れてから）：TextEdit で下線つきの文字が出るか、キャレットの四角、自己署名の入力ソースを足せるか、切り替えが効くか（印だけが変わらないか）、順番（確定とキーを速く何十回も）、ほかの所を押したとき 1 回だけ入るか、切れたときに何も残らないか、絵文字の位置。

## 選ばなかったもの

- アクセシビリティで文字を書く：確定しかできない。
- いつも Istesso の入力ソースを選んでおく：Studio の前で日本語が打てなくなる時間が長すぎる。
- キーごと・変換ごとの切り替え：持ち主が採らない（切り替えの遅れと、取りこぼし）。
