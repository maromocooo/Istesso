# ADR 0026：コーディングエージェントの範囲は、プロジェクトごとに決めて、OS の仕組みで守らせる

- 状態：**提案**（新しい段の設計）。方針は【決定】（持ち主、2026-11-19）。細かい所は【問い】。**守らせる仕組みは、調査の結果を待つ**（下の「守らせる仕組み」の章。いまは、問いだけを書いてある）。採用にするかは、調査と【問い】のあとで、持ち主が決める。**決まるまで、`main` と試用版には、何も入れない**
- 日付：2026-11-19
- 関係：[ADR 0025](0025-workspace-terminal-ports.md)（作業場、ターミナル、ポート。言葉は、そちらの「言葉」と同じ）、[ADR 0003](0003-isolation.md)、[ADR 0014](0014-dedicated-user-in-practice.md)、[ADR 0006](0006-pairing.md)。ADR 0021（`m5-design` ブランチ）は、まだ `main` にないので、番号で指す
- 進め方の案：[workspace-stage-plan.md](../workspace-stage-plan.md)

印の意味は、ADR 0025 と同じ。**【決定】**、**【提案】**、**【問い】**。OS のふるまいについての文には、**（資料）**、**（実機）**、**（推測）** を付ける。**この文書は、OS の囲いの仕組みを、調べずに書いた**（調査は、別の流れが受け持つ）。だから、仕組みについての文は、どれも（推測）か、問いの形である。

## 背景

- いまの決まり：コーディングエージェントが読めるのは、隔離領域だけ（R-07）。土台は、専用ユーザー（ADR 0003）。ADR 0021 で、持ち主は、herdr とコーディングエージェントを、2 つめの専用ユーザーで動かすと決めた（Linux。Mac は、Studio の herdr から考える。Air は、いまのまま）。
- この形は、どのプロジェクトにも、同じ 1 つの範囲を当てる。足りない場面がある：iOS の開発は、Xcode の道具、シミュレーター、署名の鍵が要る。Web の開発は、開発サーバーと、ブラウザーが要る。範囲を狭くして止まると、人は、範囲の外で動かすようになる（ssh で入って、持ち主のユーザーで起動する）。
- 止まったことに、気づけない場面もある：コーディングエージェントが、ホストの画面に確かめの窓を出したまま、止まる。持ち主は、Air の前にいる。
- 持ち主は、2026-11-19 に、範囲を、プロジェクトごとに決める方針を決めた。

## 言葉

| 語 | 意味 |
|---|---|
| コーディングエージェント | ターミナルで動く、AI の開発の道具。どの会社の、どれでもよい（持ち主は、道具の名前を 3 つ挙げて、「何でも」と決めた。この文書では、名前を書かない）。Istesso のエージェント（`istesso agent`）とは、別のもの |
| 範囲 | そのコーディングエージェントと、それが始めたものが、届いてよい所。フォルダー、道具、ネットワーク、資格情報 |
| 起動の係 | 開発の機械の側で、コーディングエージェントを、範囲つきで始める部分。ADR 0025 の「シェルの口」と同じ側にある |
| 囲い | OS の仕組みで、プロセスが届く所を絞ること |
| ツールの設定 | コーディングエージェント自身が持つ、許可と囲いの設定 |

## 持ち主の決定（2026-11-19）

1. 【決定】**コーディングエージェント（どの道具でも、何でも）は、Istesso を通して起動する。** そのプロジェクトで初めて起動するときに、どこまで許すかを、持ち主に聞く。答えは、プロジェクトごとに覚える。あとから変えられる。
2. 【決定】**範囲の例：** (1) プロジェクトのフォルダーだけ。(2) ＋開発の道具（xcodebuild、simctl、adb、署名など）。(3) ＋ネットワークを、決まった宛先だけ。(4) 持ち主と同じ。
3. 【決定】**範囲は、OS の仕組みで守らせる。コーディングエージェントの自己申告には、頼らない。** コーディングエージェント自身の許可や囲いの設定も、合わせて設定する。
4. 【決定】**範囲の外で止まったら、Air に、「今回だけ許す／広げる／断る」を出す。** ホストの画面に出して、気づけない、をなくす。
5. 【決定】**名前での検知は、補助。** ふつうのシェルで、コーディングエージェントが直接起動されたら、「範囲つきで開き直すか」を知らせる。守りの本体には、しない。
6. 【決定】**iOS や Web の開発を止めないことが、条件。** Mac と Linux で、どこまで守れるか（守りの強さの違い）を調べて、正直に書く。Mac は、別のユーザーで動かす形も比べる。
7. 【決定】**「シェル」を、見る・操作するとは別の権利にする案も、【問い】にする。** 端末ごとの話で、開発の妨げにはしない（Air には渡す）。M5 で決める。

## 方針を形にする（【提案】）

### 1. 起動の道

- 作業場のシェルの中で、決まったコマンド（仮：`istesso with <コーディングエージェントの名前>`。名前は、試作のときに決める）で起動する。herdr のペインからも、同じコマンドを使う。
- 起動の係が、次の順で進める。
  1. そのプロジェクトの、範囲の覚えを引く。
  2. なければ、起動を止めて、頼んだ端末に、問いを出す（下の 3）。
  3. 囲いを作る（「守らせる仕組み」の章）。
  4. ツールの設定を、範囲に合わせて作り、渡す（【問い 範9】）。
  5. コーディングエージェントを、囲いの中で始める。
- **コーディングエージェントが始めたもの（ビルド、試験、道具、別のコーディングエージェント）は、同じ囲いの中で動く。** 囲いが、子に受け継がれることが、仕組みを選ぶときの条件である。
- Istesso は、コーディングエージェントの種類ごとの対応を、守りの本体にしない。本体は、OS の囲いである。種類ごとに違うのは、ツールの設定の書き方だけにする。

### 2. 範囲の中身

持ち主の例の 4 つを、画面の選択肢にする。中身は、4 つの軸で持つ。あとから足すとき（「広げる」）は、段をまるごと上げずに、軸の中の 1 つを足せる。

| 段 | フォルダー | 道具 | ネットワーク | 資格情報 |
|---|---|---|---|---|
| (1) プロジェクトのフォルダーだけ | プロジェクトのフォルダーを、読み書き。OS と道具の置き場を、読むだけ。コーディングエージェント自身の設定のフォルダー | ふつうのコマンド | 【問い 範3】（おすすめ：コーディングエージェント自身の API の宛先だけ） | コーディングエージェント自身の API の鍵だけ |
| (2) ＋開発の道具 | ＋道具が要る所（調査を待つ） | ＋xcodebuild、simctl、adb、署名など | (1) と同じ | ＋署名の鍵（道具を通して使う） |
| (3) ＋ネットワークを、決まった宛先だけ | (2) と同じ | (2) と同じ | ＋プロジェクトごとの宛先の一覧（パッケージの置き場、Git のホストなど） | ＋その宛先のための、狭い資格情報（ADR 0021 の決定 15） |
| (4) 持ち主と同じ | 持ち主が届く所の全部 | 全部 | 全部 | 持ち主のものの全部 |

- 範囲 (1) の中からは、マウントで見える、ほかのプロジェクト（ADR 0025）も、見えない。
- **開発サーバーと、ブラウザー（Web の開発）は、範囲を広げずに通す。** 作業場の中で開いたポートは、ADR 0025 の転送で、ブラウザーの機械へ届く。コーディングエージェントのネットワークを、広げる必要はない。
- **転送と、URL を開く頼みは、範囲 (3) の「決まった宛先だけ」の外にある道である。** コーディングエージェントが出したページは、持ち主のブラウザーの中で動き、そこからは、どの宛先にも届く。URL を開く頼みに、中身を載せることもできる。ADR 0025 の【問い 作11】のおすすめ（外の URL は、知らせてから開く）は、これを小さくするためのものである。範囲 (3) の説明には、この限りを書く。
- (2) が、(4) と、どれだけ違うかは、調査を待つ。道具が要る口を開けると、ほとんど (4) と同じになるなら、そう書く（決定 6：正直に書く）。

### 3. 初めて起動するときの問い

- 問いは、**頼んだ端末の、Istesso のクライアントの窓**に出す。**ターミナルの中には、出さない。** ターミナルの中の字は、開発の機械の側のプログラムが、自由に出せる。問いに見える字を、出せる。答えを、ターミナルに打つ形にすると、コーディングエージェントが、自分で答える道が残る恐れがある（推測）。
- 窓に出すもの：プロジェクトの名前、開発の機械、コーディングエージェントの名前、選べる段。その機械で守れない段には、「この機械では、ここまでしか守れません」と出す（中身は、調査を待つ）。
- 答えるまで、起動しない。決まった時間のあいだ、答えがなければ、起動しない。**だれも見ていないときに、勝手に始まらない。**
- 流れの細かい所（初めの印を、どの段に付けるか、など）は、【問い 範1】。

### 4. 覚える所と、変え方

- 覚えるのは、プロジェクトごと（決定 1）。正本は、開発の機械に置く（プロジェクトの一覧と同じ。ADR 0025 の 1.1）。
- **コーディングエージェントが、書けない所に置く。** 自分の範囲を、自分で広げられないようにする。範囲 (4)（持ち主と同じ）のときにも書けない所が、あるかどうかは、置き場所による（【問い 範2】）。
- 一覧で、全部のプロジェクトの範囲が見える。あとから、変えられる（決定 1）。狭めるのは、すぐ効かせる。広げるのは、下の 5 と同じ確かめを通す。
- だれが、いつ、何を広げたかを、記録に残す。

### 5. 範囲の外で止まったとき

「外」には、2 つの層がある。どちらも、同じ窓に出す。

| 層 | 何が止めるか | 止めて、待てるか |
|---|---|---|
| ツールの層 | コーディングエージェント自身の、許可の問い（ツールの設定） | 待てる見込み（コーディングエージェントが、自分で待つ）。問いを、外へ出す口があるかは、調査を待つ |
| OS の層 | 囲い。守りの本体（決定 3） | 仕組みによる。調査を待つ。待てない仕組みでは、断られたあとで、知らせることになる |

- 窓は、頼んだ端末（Air）に出す。ホストの画面には、出さない（決定 4）。
- 窓に出すもの：どのプロジェクトの、どのコーディングエージェントが、何をしようとして止まったか（読もうとしたファイル、つなごうとした宛先）。秘密の中身は、出さない。
- 答えは 3 つ（決定 4）。
  - **今回だけ許す**：覚えない。どこまでを「今回」とするかは、【問い 範5】。
  - **広げる**：プロジェクトの範囲に足して、覚える。持ち主がいることの確かめを通す（【問い 範6】）。
  - **断る**：コーディングエージェントに、「持ち主が断った」と伝わる形にする。
- 答えがなければ、断る。
- 同じ種類の問いを、続けて出さない（同じ宛先、同じフォルダーは、1 回にまとめる）。問いが多すぎると、人は、読まずに許すようになる。
- OS の仕組みが、動いているプロセスの範囲を、あとから広げられないときは、「広げる」は、コーディングエージェントを開き直してから効く。そのことを、窓に出す（【問い 範5】）。
- 頼んだ端末が眠っているとき、ほかの端末（AURA）に出すかは、【問い 範6】。

### 6. 名前での検知（補助）

- シェルの口が、作業場のシェルで、いま前で動いているプログラムの名前を見る。決まった名前（コーディングエージェントの道具の、コマンドの名前。一覧は、設定で足せる）が、起動の係を通らずに始まっていたら、手元に知らせる：「範囲つきで、開き直しますか」。
- **止めない。終わらせない。** 知らせるだけである（決定 5）。
- 限り：名前を変えたもの、ほかのプログラムを通して起動したもの（名前が、別のプログラムのものになる）は、見つけない。だから、補助である。
- 細かい所は、【問い 範7】。

### 7. 「シェル」の権利（M5 で決める）

決定 7 のとおり、【問い 範8】にした。この文書と ADR 0025 が足す口（シェル、コーディングエージェントの起動、転送、URL を開く頼み、マウント）に、どの権利を当てるかを、M5 で、まとめて決める。考える材料：

- 「シェル」は、その機械で、シェルのユーザーにできることの全部である。持ち主のユーザーで動く機械（Studio）では、持ち主のアカウントの全部になる。「操作」より重い。ADR 0021 の「ふだんのプロファイル」と、同じか、それより重い。
- **ターミナルのアプリを、映像の道で映して、操作できる端末は、「シェル」を持つのと、同じことができる。**「シェル」の権利は、文字で運ぶ口の門である。映像の中のターミナルは、止めない。ADR 0021 は、Studio の「操作」を、「ふだんのプロファイル」と同じ重さにして、AURA に、既定では与えないと決めた。「シェル」も、それと並べて決める。
- 権利は、端末ごと、相手のホストごとに与える（ADR 0006 の形のまま）。ホストが、ほかのホストのシェルを開く形（常時稼働のホストの herdr から、Ubuntu のシェルを開く）では、ホストの身元に、権利を与えることになる。

## 守らせる仕組み（調査の結果を待つ）

**この章は、まだ書いていない。** OS の仕組み（macOS の囲いと、別のユーザーで動かす形。Linux の Landlock、bubblewrap、seccomp、ユーザーの分け方。持ち主が使っている 2 つのコーディングエージェントの、自前の囲い）は、別の流れが調べている。結果が出たら、この章を、2 回目の作業で埋める。下は、**調査が答える問い**と、**埋める表の形**である。

## 権限

AGENTS.md：権限の要る処理を増やすときは、理由を ADR に残す。

- 囲いに要る権限は、仕組みで決まる。調査を待つ。
- 物差し：**動いているあいだに、root を使わない**（ADR 0014 のまま）。導入の 1 回で済むこと。
- Mac で、別のユーザーを作る形を採るなら、導入のときに、管理者の権限が要る（ADR 0014 の表と同じ）。採るかどうかは、調7 のあと。

## 既知の不足

- **守らせる仕組みは、まだ書いていない。** この文書の方針が、OS の上で、どこまで形になるかは、調査のあとで分かる。形にならない所は、方針のほうを、持ち主に聞き直す。
- この文書は、実機で、何も動かしていない。
- 範囲 (4) は、守りがない。選んだプロジェクトでは、コーディングエージェントは、持ち主と同じことができる。
- 範囲 (1)〜(3) でも、コーディングエージェントは、自分の API の鍵と、渡された資格情報には、届く（ADR 0021 が書いたとおり）。
- 転送と、URL を開く頼みは、範囲 (3) の外の道である（上の 2）。
- 名前での検知は、すり抜けられる。
- コーディングエージェントが、ホストの画面に出す、OS の確かめの窓（キーチェーンの問い、など）は、この文書の窓には、出てこない。進め方の案の、資格情報の段で扱う。
- 複数の人が、同じ機械を使う形は、考えていない。
