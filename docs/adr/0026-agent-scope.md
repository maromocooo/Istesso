# ADR 0026：コーディングエージェントの範囲は、プロジェクトごとに決めて、OS の仕組みで守らせる

- 状態：**提案**（新しい段の設計）。方針は【決定】（持ち主、2026-11-19）。細かい所は【問い】。守らせる仕組みは、囲いの調査の結果を入れて、【提案】にした（2 回目、2026-11-19。下の「守らせる仕組み」の章）。採用にするかは、【問い】のあとで、持ち主が決める。**決まるまで、`main` と試用版には、何も入れない**

## 背景

- いまの決まり：コーディングエージェントが読めるのは、隔離領域だけ（R-07）。土台は、専用ユーザー（ADR 0003）。ADR 0021 で、持ち主は、herdr とコーディングエージェントを、2 つめの専用ユーザーで動かすと決めた（Linux。Mac は、Studio の herdr から考える。Air は、いまのまま）。
- この形は、どのプロジェクトにも、同じ 1 つの範囲を当てる。足りない場面がある：iOS の開発は、Xcode の道具、シミュレーター、署名の鍵が要る。Web の開発は、開発サーバーと、ブラウザーが要る。範囲を狭くして止まると、人は、範囲の外で動かすようになる（ssh で入って、持ち主のユーザーで起動する）。
- 止まったことに、気づけない場面もある：コーディングエージェントが、ホストの画面に確かめの窓を出したまま、止まる。持ち主は、Air の前にいる。
- 持ち主は、2026-11-19 に、範囲を、プロジェクトごとに決める方針を決めた。

## 言葉

| 語 | 意味 |
|---|---|
| コーディングエージェント | ターミナルで動く、AI の開発の道具。どの会社の、どれでもよい（持ち主は、道具の名前を 3 つ挙げて、「何でも」と決めた。この文書では、名前を書かない）。Istesso のエージェント（`istesso agent`）とは、別のもの |
| 範囲 | そのコーディングエージェントと、それが始めたものが、届いてよい所。フォルダー、道具、ネットワーク、資格情報 |
| 起動の係 | 開発の機械の側で、コーディングエージェントを、範囲つきで始める部分。ADR 0025 の「シェルの口」と同じ側にある |
| 囲い | OS の仕組みで、プロセスが届く所を絞ること |
| ツールの設定 | コーディングエージェント自身が持つ、許可と囲いの設定 |

## 持ち主の決定（2026-11-19）

1. 【決定】**コーディングエージェント（どの道具でも、何でも）は、Istesso を通して起動する。** そのプロジェクトで初めて起動するときに、どこまで許すかを、持ち主に聞く。答えは、プロジェクトごとに覚える。あとから変えられる。
2. 【決定】**範囲の例：** (1) プロジェクトのフォルダーだけ。(2) ＋開発の道具（xcodebuild、simctl、adb、署名など）。(3) ＋ネットワークを、決まった宛先だけ。(4) 持ち主と同じ。
3. 【決定】**範囲は、OS の仕組みで守らせる。コーディングエージェントの自己申告には、頼らない。** コーディングエージェント自身の許可や囲いの設定も、合わせて設定する。
4. 【決定】**範囲の外で止まったら、Air に、「今回だけ許す／広げる／断る」を出す。** ホストの画面に出して、気づけない、をなくす。
5. 【決定】**名前での検知は、補助。** ふつうのシェルで、コーディングエージェントが直接起動されたら、「範囲つきで開き直すか」を知らせる。守りの本体には、しない。
6. 【決定】**iOS や Web の開発を止めないことが、条件。** Mac と Linux で、どこまで守れるか（守りの強さの違い）を調べて、正直に書く。Mac は、別のユーザーで動かす形も比べる。
7. 【決定】**「シェル」を、見る・操作するとは別の権利にする案も、【問い】にする。** 端末ごとの話で、開発の妨げにはしない（Air には渡す）。M5 で決める。

## 方針を形にする（【提案】）

### 1. 起動の道

- 作業場のシェルの中で、決まったコマンド（仮：`istesso with <コーディングエージェントの名前>`。名前は、試作のときに決める）で起動する。herdr のペインからも、同じコマンドを使う。
- 起動の係が、次の順で進める。
  1. そのプロジェクトの、範囲の覚えを引く。
  2. なければ、起動を止めて、頼んだ端末に、問いを出す（下の 3）。
  3. 囲いを作る（「守らせる仕組み」の章）。
  4. ツールの設定を、範囲に合わせて作り、渡す（【問い 範9】）。
  5. コーディングエージェントを、囲いの中で始める。
- **コーディングエージェントが始めたもの（ビルド、試験、道具、別のコーディングエージェント）は、同じ囲いの中で動く。** 囲いが、子に受け継がれることが、仕組みを選ぶときの条件である。
- Istesso は、コーディングエージェントの種類ごとの対応を、守りの本体にしない。本体は、OS の囲いである。種類ごとに違うのは、ツールの設定の書き方だけにする。

### 2. 範囲の中身

持ち主の例の 4 つを、画面の選択肢にする。中身は、4 つの軸で持つ。あとから足すとき（「広げる」）は、段をまるごと上げずに、軸の中の 1 つを足せる。

| 段 | フォルダー | 道具 | ネットワーク | 資格情報 |
|---|---|---|---|---|
| (1) プロジェクトのフォルダーだけ | プロジェクトのフォルダーを、読み書き。OS と道具の置き場を、読むだけ。コーディングエージェント自身の設定のフォルダー | ふつうのコマンド | 【問い 範3】（おすすめ：コーディングエージェント自身の API の宛先だけ） | コーディングエージェント自身の API の鍵だけ |
| (2) ＋開発の道具 | ＋道具が要る所（「守らせる仕組み」の調2） | ＋xcodebuild、simctl、adb、署名など | (1) と同じ | ＋署名の鍵（道具を通して使う） |
| (3) ＋ネットワークを、決まった宛先だけ | (2) と同じ | (2) と同じ | ＋プロジェクトごとの宛先の一覧（パッケージの置き場、Git のホストなど） | ＋その宛先のための、狭い資格情報（ADR 0021 の決定 15） |
| (4) 持ち主と同じ | 持ち主が届く所の全部 | 全部 | 全部 | 持ち主のものの全部 |

- 範囲 (1) の中からは、マウントで見える、ほかのプロジェクト（ADR 0025）も、見えない。
- **開発サーバーと、ブラウザー（Web の開発）は、範囲を広げずに通す。** 作業場の中で開いたポートは、ADR 0025 の転送で、ブラウザーの機械へ届く。コーディングエージェントのネットワークを、広げる必要はない。
- **転送と、URL を開く頼みは、範囲 (3) の「決まった宛先だけ」の外にある道である。** コーディングエージェントが出したページは、持ち主のブラウザーの中で動き、そこからは、どの宛先にも届く。URL を開く頼みに、中身を載せることもできる。ADR 0025 の【問い 作11】のおすすめ（外の URL は、知らせてから開く）は、これを小さくするためのものである。範囲 (3) の説明には、この限りを書く。
- (2) は、(4) と同じには、ならない。ただし、Mac では、OS のサービスを広く開けることになる（「守らせる仕組み」の調2）。問いの窓に、そう書く（決定 6：正直に書く）。

### 3. 初めて起動するときの問い

- 問いは、**頼んだ端末の、Istesso のクライアントの窓**に出す。**ターミナルの中には、出さない。** ターミナルの中の字は、開発の機械の側のプログラムが、自由に出せる。問いに見える字を、出せる。答えを、ターミナルに打つ形にすると、コーディングエージェントが、自分で答える道が残る恐れがある（推測）。
- 窓に出すもの：プロジェクトの名前、開発の機械、コーディングエージェントの名前、選べる段。その機械で守れない段には、「この機械では、ここまでしか守れません」と出す（中身は、「守らせる仕組み」の、強さの違いの表）。
- 答えるまで、起動しない。決まった時間のあいだ、答えがなければ、起動しない。**だれも見ていないときに、勝手に始まらない。**
- 流れの細かい所（初めの印を、どの段に付けるか、など）は、【問い 範1】。

### 4. 覚える所と、変え方

- 覚えるのは、プロジェクトごと（決定 1）。正本は、開発の機械に置く（プロジェクトの一覧と同じ。ADR 0025 の 1.1）。
- **コーディングエージェントが、書けない所に置く。** 自分の範囲を、自分で広げられないようにする。範囲 (4)（持ち主と同じ）のときにも書けない所が、あるかどうかは、置き場所による（【問い 範2】）。
- 一覧で、全部のプロジェクトの範囲が見える。あとから、変えられる（決定 1）。狭めるのは、すぐ効かせる。広げるのは、下の 5 と同じ確かめを通す。
- だれが、いつ、何を広げたかを、記録に残す。

### 5. 範囲の外で止まったとき

「外」には、2 つの層がある。どちらも、同じ窓に出す。

| 層 | 何が止めるか | 止めて、待てるか |
|---|---|---|
| ツールの層 | コーディングエージェント自身の、許可の問い（ツールの設定） | 待てる見込み（コーディングエージェントが、自分で待つ）。問いを、外へ出す口があるかは、まだ分かっていない |
| OS の層 | 囲い。守りの本体（決定 3） | Linux は、待てる（seccomp のユーザー通知）。Mac のファイルは、待てない。断られたあとで、知らせる。ネットワークは、どちらも、中継で待てる見込み（「守らせる仕組み」の調4） |

- 窓は、頼んだ端末（Air）に出す。ホストの画面には、出さない（決定 4）。
- 窓に出すもの：どのプロジェクトの、どのコーディングエージェントが、何をしようとして止まったか（読もうとしたファイル、つなごうとした宛先）。秘密の中身は、出さない。
- 答えは 3 つ（決定 4）。
  - **今回だけ許す**：覚えない。どこまでを「今回」とするかは、【問い 範5】。
  - **広げる**：プロジェクトの範囲に足して、覚える。持ち主がいることの確かめを通す（【問い 範6】）。
  - **断る**：コーディングエージェントに、「持ち主が断った」と伝わる形にする。
- 答えがなければ、断る。
- 同じ種類の問いを、続けて出さない（同じ宛先、同じフォルダーは、1 回にまとめる）。問いが多すぎると、人は、読まずに許すようになる。
- OS の仕組みが、動いているプロセスの範囲を、あとから広げられないときは、「広げる」は、コーディングエージェントを開き直してから効く。そのことを、窓に出す（【問い 範5】）。
- 頼んだ端末が眠っているとき、ほかの端末（AURA）に出すかは、【問い 範6】。

### 6. 名前での検知（補助）

- シェルの口が、作業場のシェルで、いま前で動いているプログラムの名前を見る。決まった名前（コーディングエージェントの道具の、コマンドの名前。一覧は、設定で足せる）が、起動の係を通らずに始まっていたら、手元に知らせる：「範囲つきで、開き直しますか」。
- **止めない。終わらせない。** 知らせるだけである（決定 5）。
- 限り：名前を変えたもの、ほかのプログラムを通して起動したもの（名前が、別のプログラムのものになる）は、見つけない。だから、補助である。
- 細かい所は、【問い 範7】。

### 7. 「シェル」の権利（M5 で決める）

決定 7 のとおり、【問い 範8】にした。この文書と ADR 0025 が足す口（シェル、コーディングエージェントの起動、転送、URL を開く頼み、マウント）に、どの権利を当てるかを、M5 で、まとめて決める。考える材料：

- 「シェル」は、その機械で、シェルのユーザーにできることの全部である。持ち主のユーザーで動く機械（Studio）では、持ち主のアカウントの全部になる。「操作」より重い。ADR 0021 の「ふだんのプロファイル」と、同じか、それより重い。
- **ターミナルのアプリを、映像の道で映して、操作できる端末は、「シェル」を持つのと、同じことができる。**「シェル」の権利は、文字で運ぶ口の門である。映像の中のターミナルは、止めない。ADR 0021 は、Studio の「操作」を、「ふだんのプロファイル」と同じ重さにして、AURA に、既定では与えないと決めた。「シェル」も、それと並べて決める。
- 権利は、端末ごと、相手のホストごとに与える（ADR 0006 の形のまま）。ホストが、ほかのホストのシェルを開く形（常時稼働のホストの herdr から、Ubuntu のシェルを開く）では、ホストの身元に、権利を与えることになる。

## 守らせる仕組み（調査の結果と、【提案】）

2 回目の作業（2026-11-19）で、囲いの調査の結果を入れた。出どころは、`research-agent-scope` ブランチの `docs/research/agent-scope.md`。**この章の印は、その調査の印を写したものである。**（実）は、調査が実機で見たこと（Mac は Air、Linux は Ubuntu のホスト）。（資）は、調査が資料で確かめたこと。（推）は、考えただけのこと。括弧の中の M と L と A の番号は、調査の文書の、事実の番号である。**Studio では、何も試していない。** この文書の流れは、囲いについて、何も動かしていない。

道具の呼び方は、調査に合わせた：Claude Code、OpenAI の CLI、Gemini CLI。

### 先に、要点

1. **Mac で、特権なしに使える囲いは、Seatbelt（`sandbox-exec`）だけである**（実）。Apple は、「非推奨」「非公開の口で、いつでも変わる」と書いている（資）。3 つのコーディングエージェントも、Swift と Xcode の道具も、同じ口を使っている（実、資）。
2. **Seatbelt は、重ねられない**（実）。Istesso が外から囲うと、コーディングエージェント自身の囲いと、Swift と Xcode の道具が自分で掛ける囲いが、動かなくなる。切る口は、ある（実）。
3. **iOS と Web のビルドは、Seatbelt の中で動いた**（実。下の調2）。実機、シミュレーターでの起動、本物の証明書での署名は、試していない。
4. **Seatbelt は、宛先を、相手の名前でもアドレスでも絞れない**（実）。段 (3) は、手元の中継だけを許し、中継が宛先を決める形になる。
5. **Linux の Landlock は、ファイルと、TCP のポートを絞れる**（実）。**同じユーザーのままだと、抜け道がある**：Docker の口（持ち主は、Docker を使えるグループにいるので、root と同じ力）と、ユーザーのサービス管理に頼んで、囲いの外でプロセスを起こすこと（どちらも実）。
6. **Ubuntu のホストでは、名前空間を使う囲い（bubblewrap）が、動かない**（実）。AppArmor が止めている。コーディングエージェントの Linux の囲いは、これを使うので、このホストでは動かない（1 つは実、1 つは資）。
7. **「止めて、待つ」ができるのは、Linux の seccomp のユーザー通知だけ**（実。特権なし）。Mac の Seatbelt は、その場で断る（実）。断られたことは、Mac では、その場で分かる（実。管理者のユーザーで）。Linux の Landlock は、このホストでは、どこにも記録しなかった（実）。

### 調査への問いと、答え

| # | 問い（短く） | 答え |
|---|---|---|
| 調1 | 外を、読むことも止められるか。開けておく所 | **止められる。** Mac の Seatbelt（実、M5）、Linux の Landlock（実、L10）。開けておく所：OS の場所（読むだけ）、そのユーザーの一時のフォルダー、コーディングエージェント自身の設定の場所と、モデルの API の宛先（資、A5）、道具を入れた場所（Air では、ホームの下にあった＝実）。**Mac では、道具の場所を開けないと、`git` も動かなかった**（実）。段 (1) の中身に関わる（【問い 範3】を直した） |
| 調2 | 段 (2) に要る口。(4) との違い | **Mac（実、Air）：** 読むだけで、Xcode、開発の道具の置き場（全体のものと、ユーザーのもの）、Xcode の使用許諾の記録。読み書きで、Swift のパッケージの置き場。いくつかの設定の読み。OS のサービス 8 つと、XPC のサービス。これで、`xcodebuild`（macOS 向け、iOS シミュレーター向け）、`swift build`、`simctl list`、その場の署名、`node`、`npm run` が通った。**(4) との違いは、残る**：持ち主の書類、ほかのプロジェクト、鍵の置き場は、閉じたまま（推）。**弱い所：** XPC のサービスが、全部引ける（実、M13）。サービスは、囲いの外で動く。開発の道具の置き場を、丸ごと読ませると、ほかのプロジェクトのビルドの結果と、シミュレーターの中のアプリのデータが読める（推）。**Linux（実）：** GPU と adb は、機器の口と、ポートの決まりを足せば、Landlock の中で動いた（L39、L40、L42） |
| 調3 | 宛先を、名前で絞れるか。途中で足せるか | **OS の囲いだけでは、絞れない。** Seatbelt は、「全部」か「この機械の中」だけ。ポートは書ける（実、M8、M9）。Landlock は、ポートだけ（資、L12）。UDP は、止まらない（実、L13）。**名前で絞るには、手元の中継が要る**（Claude Code の囲いが、この形＝資）。中継なら、許す宛先を、途中で足せる。つなぎを止めたまま、聞ける（推）。中継の限り：相手が名乗った名前で決める。暗号の中は見ない。UDP は通らない（資） |
| 調4 | 止めて、待てるか | **Mac：待てない**（実、M24）。断られたことは、`log stream` で、その場で分かる（実、M22。ふつうのユーザーで読めるかは推）。待てる仕組み（Endpoint Security）は、Apple が与える権利が要る（資）。**Linux：seccomp のユーザー通知で、待てる**（実、L28）。資料は、「守りの決まりを作るのには、使えない」と注意している（資、L31。確かめたあとで、中身を変えられうる）。監督する側が、自分でファイルを開いて渡す形なら、その心配は小さい見込み（推、L32）。ファイルを開く呼び出しの全部が、監督する側を通るので、ビルドは遅くなる恐れ（推、L33） |
| 調5 | あとから、広げられるか | **Mac：** 決まりは、変えられない。開き直す。非公開の口（囲いの外から札を渡す）では、動いている囲いを、広げて、また狭められた（実、M25）。公開の文書は、ない。**Linux：** Landlock は、狭めることしかできない（資、L19）。開き直す。seccomp のユーザー通知なら、監督する側が代わりに開いて渡せる（「今回だけ」＝実、L30）。**ネットワーク：** どちらの OS でも、中継の一覧を変えれば、その場で効く（推） |
| 調6 | 子と孫。抜ける道 | **受け継がれる**（Mac＝実、M5。Linux＝実、L10）。**抜ける道。Mac：** 許した OS のサービス（囲いの外で動く＝実、資）。ほかのアプリを起動する口を、許したとき（資）。囲う前に開いていた口（資）。OS のサービス管理に頼む道は、試した形では、塞がっていた（実、M12）。**Linux（同じユーザーのとき）：** Docker の口（実、L16）。ユーザーのサービス管理（実、L17）。名前の付いたソケットの全部（実、L15。新しいカーネルでは、絞れる＝資）。別のユーザーにして、Docker と sudo のグループに入れなければ、Docker の道はなくなり、サービス管理の道は、そのユーザーの中にとどまる（推、L35） |
| 調7 | Mac で、別のユーザー | **資料と、考えだけ。ユーザーは、作っていない。** ファイルは、OS の権限で分かれて、強い。重ねられない問題が、ない（推）。かわりに：Xcode の状態、シミュレーター、プロファイルは、ユーザーごと（場所は実、動きは推）。署名の証明書は、そのユーザーのキーチェーンに入れ直す。画面のないログインでは、キーチェーンを開ける手が要る（資）。画面のあるもの（シミュレーターの窓）は、そのユーザーの画面のセッションが要る（推）。ネットワークは、分かれない。断られたことは、記録に出ない（推）。作るのに、管理者の権限（資）。**答えが出ていないこと：** 動いているあいだに root を使わずに、別のユーザーとして起動する形 |
| 調8 | Linux の仕組みごと | 上の調1〜調6 のとおり。ホストは、カーネル 6.17、Landlock の版 7（実）。**ADR 0021 の問い 10 と、同じ壁に当たる**（AppArmor が、特権のない名前空間を止める＝実、資） |
| 調9 | ネットワークを分けたときの、ポート | 提案は、名前空間を使わないので、当面は、当たらない。Landlock は、待ち受けるポートも絞る（実、L11、L14）。開発サーバーのために、待ち受けは絞らない（ADR 0025 の 4.3） |
| 調10 | コーディングエージェントの、自前の囲いと許可 | **Claude Code**（資だけ。動かしていない）：Mac は Seatbelt、Linux は bubblewrap。**囲うのは、シェルのコマンドだけ。** ファイルの道具、MCP、フックは、囲いの外で動く（資、A3）。拒む規則は、どの許可の形でも効く（資、A1）。**OpenAI の CLI**：Mac は Seatbelt、Linux は bubblewrap と seccomp（資）。外を Seatbelt で囲うと、失敗した（実、M14）。Ubuntu のホストでは、動かなかった（実、L26）。外がすでに囲ってある所では、中を「全部許す」で動かすよう、案内している（資、A9）。**Gemini CLI**（資だけ）：Mac は Seatbelt の決まりを選ぶ形。Linux は、コンテナーだけ。**答えが出ていないこと：** 設定を、コーディングエージェントが書き換えられない所から渡せるか。許可の問いを、外へ出す口があるか |
| 調11 | 口の位置づけ | Seatbelt：「非推奨」（資、Air の説明書）。決まりの書き方は、「Apple の非公開の口。いつでも変わる」（資、Air の決まりのファイル）。札を渡す口：公開の文書がない（推）。Landlock と seccomp：カーネルの公開の口（資）。ライセンスと特許は、調査の対象に入っていなかった。作るときに見る |
| 調12 | 範囲の覚えを、書けない所に | 調査は、直接は答えていない。段 (1)〜(3) では、囲いの決まりで、覚えの場所を閉じられる見込み（推）。段 (4) は、囲いがないので、別の置き場が要る（【問い 範2】のまま） |
| 調13 | 遅さ | 測っていない。seccomp のユーザー通知は、遅くなる恐れ（推） |

### 守りの強さの違い（決定 6：正直に書く）

| 守ること | Linux（コーディングの専用ユーザーと、Landlock） | Mac（持ち主のユーザーと、Seatbelt） | Mac（別のユーザー） |
|---|---|---|---|
| プロジェクトの外のファイルを、読ませない、書かせない | 守れる（Landlock＝実。ユーザーの境目＝推） | 守れる（実） | 守れる見込み（推）。持ち主のホームの直下は、一覧できる（ADR 0014） |
| 抜ける道 | 名前の付いたソケット（実）。専用ユーザーにすれば、Docker の道はなくなる（推）。**持ち主のユーザーのまま Landlock だけ、という形は、Docker の口で、root と同じ力に届く（実）ので、採らない** | 許した OS のサービス（実）。段 (2) では、XPC のサービスの全部 | だれでも読める場所 |
| 鍵と資格情報に、届かせない | 持ち主の鍵には、届かない（推） | キーチェーンの口を許さなければ、届かない見込み（推）。段 (2) で、本物の署名のために許すと、届く。確かめの窓が出ることがある（試していない） | 持ち主のキーチェーンは、別（資） |
| ネットワークを、決まった宛先だけにする | Landlock だけでは、守れない（資）。**root で、導入のときに 1 回、ユーザーごとの決まり（nftables）を入れ、中継と組み合わせれば、守れる**（資、推） | Seatbelt と、手元の中継で、守れる（実、資）。中継の限りは、調3 | 守れない。OS のフィルターは、root が要り、効くかは確かめていない（資、推） |
| 子と孫にも、効く | 効く（実）。サービス管理に頼んだものは、専用ユーザーの中にとどまる（推） | 効く（実） | 効く（推） |
| 止まったことが、分かる | Landlock だけでは、分からない（実）。seccomp のユーザー通知を足せば、分かる（実） | 分かる（実。管理者のユーザーで） | 分からない（推） |
| 止めて、待てる | 待てる（seccomp のユーザー通知＝実。注意は、調4） | 待てない（実）。ネットワークは、中継で待てる（推） | 待てない（推） |
| あとから、広げられる | 開き直す。「今回だけ」は、監督する側が代わりに開く（実） | 開き直す。非公開の口なら、その場で（実） | 権限を変える（推） |
| コーディングエージェント自身の囲いと、重ねる | Landlock は、重ねられる（資）。ただし、コーディングエージェントの Linux の囲いは、このホストでは動かない（実、資） | **重ならない。切る**（実） | そのまま使える（推） |
| iOS の開発 | — | ビルド、`simctl list`、その場の署名は、動いた（実）。道具の自前の囲いを切ることが、条件（実）。実機、シミュレーターでの起動、本物の署名、Xcode のスクリプトの段と、Swift のマクロは、確かめていない | 証明書、プロファイル、シミュレーターを、入れ直す。画面のセッションが要る（資、推）。手間が大きい |
| Web の開発 | 動く見込み（推） | `node`、`npm run` は、動いた（実）。パッケージを取ってくるには、段 (3) が要る（推） | 道具を、入れ直す（推） |
| 導入に要る権限 | 専用ユーザー（root、1 回。ADR 0014、ADR 0021）。ネットワークの決まり（root、1 回。【問い 範11】）。Landlock と seccomp は、なし（実） | **なし**（実） | 管理者（資） |
| 長く頼れるか | カーネルの公開の口（資） | **非推奨で、非公開の口**（資）。OS の更新で、変わりうる | OS の、ふつうの権限 |

**ひとことで言うと：** Linux は、土台（ユーザーの境目）が強く、公開の口だけで作れる。ただし、ネットワークを守るのに、root が 1 回要り、名前空間は使えない。Mac の Seatbelt は、何も足さずに、ファイルも、ネットワークも、その場の知らせも作れて、iOS のビルドも通る。ただし、Apple が「使うな」と書いている口に、守りの本体を置くことになり、コーディングエージェント自身の囲いを切ることになる。Mac の別のユーザーは、ファイルの境目は強いが、iOS の開発の手間が大きく、ネットワークを守れず、止まったことが分からない。しかも、まだ、だれも試していない。

### 段ごとの仕組み（【提案】）

| 段 | Linux（Ubuntu） | Mac（Studio、Air） |
|---|---|---|
| 土台 | コーディングの専用ユーザー（ADR 0021 の決定 6 のまま）。Docker と sudo のグループに、入れない | 持ち主のユーザー（ADR 0025 の【問い 作3】）。起動の係が、起動のたびに、Seatbelt の決まりを作る。「全部断る」から始めて、要るものだけを足す |
| (1) | Landlock：プロジェクトを、読み書き。OS と道具の場所を、読むだけ。つなぐ先は、その機械の中の、中継のポート 1 つだけ。待ち受けは、絞らない。nftables（root、1 回）：専用ユーザーの通信を、その機械の中だけにする。中継：コーディングエージェント自身の API の宛先だけ | Seatbelt：同じ。つなぐ先は、その機械の中の、中継のポート 1 つだけ。中継：同じ。XPC のサービスは、要るものだけ |
| (2) | ＋GPU と、機器の口。adb のためのポートの決まり（どちらも、調査で動いた） | ＋調2 の一覧。ビルドの結果の置き場は、プロジェクトの中にする。開発の道具の置き場は、要る所だけ |
| (3) | ＋中継の一覧に、プロジェクトの宛先 | 同じ |
| (4) | 専用ユーザーのまま、Landlock なし（【問い 範4】のおすすめ） | 囲いなし |
| 止まったとき | ファイル：seccomp のユーザー通知を、測ってから使う（【問い 範14】）。ネットワーク：中継が、止めて聞く | ファイル：断られたことを、`log stream` で知り、Air に知らせる。許されたら、開き直す（【問い 範13】）。ネットワーク：中継が、止めて聞く |
| 使わないもの | bubblewrap（このホストでは動かない。root で決まりを足すことは、しない） | Apple が与える権利が要るもの（Endpoint Security、Network Extension） |

- 中継は、起動の係が、囲いの外で動かす。コーディングエージェントごとに、ポートを 1 つ。どのプロジェクトのつなぎかは、ポートで分かる。
- 起動の係は、自分が持っている口（通信路、鍵のある場所）を、コーディングエージェントに渡さない。囲う前に開いていた口は、囲いの中でも使えるためである（資）。
- Mac では、OS を更新するたびに、囲いが効いていることを確かめる試験を走らせる。**効いていないと分かったら、段 (1)〜(3) の起動を断る**（閉じる側に倒す）。
- Linux の、新しいカーネルの Landlock（名前の付いたソケットと、UDP を絞れる版）が、ホストに届いたら、足す。

### ツールの設定（【提案】）

外から囲うとき、コーディングエージェント自身の設定は、次のように合わせる（決定 3）。

| | 自前の囲い | 自前の許可の規則 | 道具の自前の囲い |
|---|---|---|---|
| Mac（Seatbelt の中） | **切る**（重ならないため。【問い 範10】）。OpenAI の CLI は、切らないと失敗した（実）。Claude Code が、切らないときにどうなるかは、確かめていない | **残す。** 外の囲いとは別に効く、二重の柵になる（推）。許可の問いは、Air の窓に出す（出す口があるかは、調10 の残り） | Swift のパッケージと、`xcodebuild` は、1 回だけ効く形の指定で、切れた（実）。Xcode のスクリプトの段と、Swift のマクロは、確かめていない。コーディングエージェントに、どうやってその指定を使わせるかは、決まっていない |
| Linux（Landlock の中） | このホストでは、もともと動かない（実、資）。切る | 残す | — |
| 段 (4) | 持ち主が選んだとおり | 持ち主が選んだとおり | そのまま |

- 外の囲いは、コーディングエージェントのプロセスの全部（ファイルの道具、MCP、フックも）を囲う。自前の囲いが、シェルのコマンドだけを囲うもの（Claude Code＝資）より、広い。
- **切ることで、弱くなる所もある。** Swift のパッケージの定義を読むときの囲いは、プロジェクトより狭い。それが、プロジェクトと同じ広さになる。

## 権限

AGENTS.md：権限の要る処理を増やすときは、理由を ADR に残す。

- Mac の Seatbelt、Linux の Landlock と seccomp には、特権が要らない（調査が、実機で見た）。
- **Linux で、ネットワークを守るための決まり（nftables）を入れるのに、root が要る。導入の 1 回。** 理由：Landlock は、宛先を絞れない。コーディングの専用ユーザーの通信を、その機械の中の中継だけにするには、OS のフィルターに、ユーザーごとの決まりを入れるしかない（【問い 範11】）。
- Linux で、止まったことを、監査の記録から読む形（【問い 範14】の (b)）を採るなら、監査を有効にするのに、root が 1 回要る。
- 名前空間のための決まり（AppArmor）は、足さない。
- 物差し：**動いているあいだに、root を使わない**（ADR 0014 のまま）。導入の 1 回で済むこと。
- Mac で、別のユーザーを作る形を採るなら、導入のときに、管理者の権限が要る（ADR 0014 の表と同じ）。採るかどうかは、調7 のあと。

## 既知の不足

- **Mac の守りの本体は、Apple が「非推奨」「非公開」と書いている口の上にある**（【問い 範12】）。
- **確かめていないもの（Mac）：** 実機（iPhone）への書き込み、シミュレーターでの起動、本物の証明書での署名、Xcode のスクリプトの段と Swift のマクロ。どれも、持ち主の機器と鍵に触れるので、持ち主の許しが要る。管理者でないユーザーで、断られた記録を読めるか。Claude Code を、外の囲いの中で動かしたときの落ち方。Studio では、何も試していない。
- **Mac の別のユーザーの形は、資料と考えだけである。** 決定 6 の「比べる」は、まだ、実機の裏づけがない。
- **Linux で、Docker を使う開発は、段 (1)〜(3) では、できない。** Docker の口は、root と同じ力なので、コーディングの専用ユーザーを、Docker のグループに入れない。Docker が要るプロジェクトの形は、調べていない。
- Linux の Landlock（ホストの版）は、名前の付いたソケットと、UDP を止めない。専用ユーザーにしても、だれでもつなげるソケットには、届く。
- 中継は、相手が名乗った名前で決める。暗号の中は、見ない。UDP は、通らない。
- コーディングエージェントに、道具の自前の囲いを切る指定を、どうやって使わせるかは、決まっていない。
- 囲いをかけたときの遅さは、測っていない。
- この文書は、実機で、何も動かしていない。
- 範囲 (4) は、守りがない。選んだプロジェクトでは、コーディングエージェントは、持ち主と同じことができる。
- 範囲 (1)〜(3) でも、コーディングエージェントは、自分の API の鍵と、渡された資格情報には、届く（ADR 0021 が書いたとおり）。
- 転送と、URL を開く頼みは、範囲 (3) の外の道である（上の 2）。
- 名前での検知は、すり抜けられる。
- コーディングエージェントが、ホストの画面に出す、OS の確かめの窓（キーチェーンの問い、など）は、この文書の窓には、出てこない。進め方の案の、資格情報の段で扱う。
- 複数の人が、同じ機械を使う形は、考えていない。
