## 背景

- 前の設計：コーディングエージェントが読めるのは、隔離領域だけ（R-07）。土台は、専用ユーザー（ADR 0003）。ADR 0021 で、持ち主は、herdr とコーディングエージェントを、2 つめの専用ユーザーで動かすと決めた（Linux。Mac は、Studio の herdr から考える。Air は、いまのまま）。
- この形は、どのプロジェクトにも、同じ 1 つの範囲を当てる。足りない場面がある：iOS の開発は、Xcode の道具、シミュレーター、署名の鍵が要る。Web の開発は、開発サーバーと、ブラウザーが要る。範囲を狭くして止まると、人は、範囲の外で動かすようになる（ssh で入って、持ち主のユーザーで起動する）。
- 止まったことに、気づけない場面もある：コーディングエージェントが、ホストの画面に確かめの窓を出したまま、止まる。持ち主は、Air の前にいる。
- 持ち主は、2026-11-19 に、範囲を、プロジェクトごとに決める方針を決めた。

## 言葉

| 語 | 意味 |
|---|---|
| コーディングエージェント | ターミナルで動く、AI の開発の道具。どの会社の、どれでもよい（持ち主は、道具の名前を 3 つ挙げて、「何でも」と決めた。この文書では、名前を書かない）。Istesso のエージェント（`istesso agent`）とは、別のもの |

| 囲い | OS の仕組みで、プロセスが届く所を絞ること |
| ツールの設定 | コーディングエージェント自身が持つ、許可と囲いの設定 |

## 持ち主の決定（2026-11-19）

1. 【決定】**コーディングエージェント（どの道具でも、何でも）は、Istesso を通して起動する。** そのプロジェクトで初めて起動するときに、どこまで許すかを、持ち主に聞く。答えは、プロジェクトごとに覚える。あとから変えられる。
2. 【決定】**範囲の例：** (1) プロジェクトのフォルダーだけ。(2) ＋開発の道具（xcodebuild、simctl、adb、署名など）。(3) ＋ネットワークを、決まった宛先だけ。(4) 持ち主と同じ。
3. 【決定】**範囲は、OS の仕組みで守らせる。コーディングエージェントの自己申告には、頼らない。** コーディングエージェント自身の許可や囲いの設定も、合わせて設定する。
4. 【決定】**範囲の外で止まったら、Air に、「今回だけ許す／広げる／断る」を出す。** ホストの画面に出して、気づけない、をなくす。
5. 【決定】**名前での検知は、補助。** ふつうのシェルで、コーディングエージェントが直接起動されたら、「範囲つきで開き直すか」を知らせる。守りの本体には、しない（作業場のふだんの起動と、知らせる回数は決定 14）。
6. 【決定】**iOS や Web の開発を止めないことが、条件。** Mac と Linux で、どこまで守れるか（守りの強さの違い）を調べて、正直に書く。Mac は、別のユーザーで動かす形も比べる（資料での比較は調7。Studio に作って試す案は決定 18 で取り下げた）。
7. 【決定】**「シェル」を、見る・操作するとは別の権利にする案も、【問い】にする。** 端末ごとの話で、開発の妨げにはしない（Air には渡す）。範8 で決まり、渡し方は 7 に記した。

## 方針を形にする（【提案】）

### 1. 起動の道

- 【決定】（2026-11-21。決定 14）作業場では、herdr のペインでも、ふだんどおり、コーディングエージェントのいつものコマンド（`claude` など）を打つ。起動の係がプロジェクトの範囲を使う。(4) なら囲いはない。
- 【提案】（読み。違えば直す）ADR 0025 の作4 で許されたシェルの設定の 1 行を、ふだんのコマンドから起動の係に渡す入口に使う。
- 起動の係が、次の順で進める。
  1. そのプロジェクトの、範囲の覚えを引く。
  2. なければ、起動を止めて、頼んだ端末に、問いを出す（下の 3）。
  3. 段 (1)〜(3) なら囲いを作る（「守らせる仕組み」の章）。
  4. 【決定】（2026-11-21。決定 15）起動のたびにツールの設定を作り、エージェントが書けない形で渡す。プロジェクトの中には書かない。
  5. コーディングエージェントを、選んだ段で始める。
- **コーディングエージェントが始めたもの（ビルド、試験、道具、別のコーディングエージェント）は、同じ囲いの中で動く。** 囲いが、子に受け継がれることが、仕組みを選ぶときの条件である。
- Istesso は、コーディングエージェントの種類ごとの対応を、守りの本体にしない。本体は、OS の囲いである。種類ごとに違うのは、ツールの設定の書き方だけにする。

### 2. 範囲の中身

【決定】（2026-11-21。決定 10）画面では 4 つの段から選ぶ。中身は下の 4 軸で持ち、「広げる」ときは、足りないものを軸の中で 1 つずつ足せる。設定はかんたんにする。TUI も候補。

| 段 | フォルダー | 道具 | ネットワーク | 資格情報 |
|---|---|---|---|---|
| (1) プロジェクトのフォルダーだけ | プロジェクトのフォルダーを、読み書き。OS と道具の置き場を、読むだけ。コーディングエージェント自身の設定のフォルダー | ふつうのコマンド | 【提案】コーディングエージェント自身の API の宛先だけ | コーディングエージェント自身の API の鍵だけ |
| (2) ＋開発の道具 | ＋道具が要る所（「守らせる仕組み」の調2） | ＋xcodebuild、simctl、adb、署名など | (1) と同じ | ＋署名の鍵（道具を通して使う） |
| (3) ＋ネットワークを、決まった宛先だけ | (2) と同じ | (2) と同じ | ＋プロジェクトごとの宛先の一覧（パッケージの置き場、Git のホストなど） | ＋その宛先のための、狭い資格情報（ADR 0021 の決定 15） |
| (4) 持ち主と同じ | 持ち主が届く所の全部 | 全部 | 全部 | 持ち主のものの全部 |

【決定】（2026-11-21。決定 11）(4) は囲いなし。AURA からも選べ、選んだプロジェクトには一覧でいつも印を付ける。既定は、どの機械でも持ち主のユーザー。

【提案】（読み。違えば直す）Ubuntu で (4) を「専用ユーザーのまま囲いなし」と読むのは、分ける設定を選んだ機械だけ。

- 範囲 (1) の中からは、マウントで見える、ほかのプロジェクト（ADR 0025）も、見えない。
- **開発サーバーと、ブラウザー（Web の開発）は、範囲を広げずに通す。** 作業場の中で開いたポートは、ADR 0025 の転送で、ブラウザーの機械へ届く。コーディングエージェントのネットワークを、広げる必要はない。
- **転送と、URL を開く頼みは、範囲 (3) の「決まった宛先だけ」の外にある道である。** コーディングエージェントが出したページは、持ち主のブラウザーの中で動き、そこからは、どの宛先にも届く。URL を開く頼みに、中身を載せることもできる。ADR 0025 の決定 16（外の URL は、知らせてから開く）は、これを小さくするためのものである。範囲 (3) の説明には、この限りを書く。
- (2) は、(4) と同じには、ならない。ただし、Mac では、OS のサービスを広く開けることになる（「守らせる仕組み」の調2）。問いの窓に、そう書く（決定 6：正直に書く）。

### 3. 初めて起動するときの問い

- 【決定】（2026-11-21。決定 8）プロジェクトで初めて起動するときだけ、問いを**頼んだ端末の、Istesso のクライアントの窓**に出す。**ターミナルの中には、出さない。** ターミナルの中の字は、開発の機械の側のプログラムが、自由に出せる。問いに見える字を、出せる。答えを、ターミナルに打つ形にすると、コーディングエージェントが、自分で答える道が残る恐れがある（推測）。
- 窓に出すもの：プロジェクトの名前、開発の機械、コーディングエージェントの名前、選べる段。その機械で守れない段には、「この機械では、ここまでしか守れません」と出す（中身は、「守らせる仕組み」の、強さの違いの表）。
- 答えるまで、起動しない。決まった時間のあいだ、答えがなければ、起動しない。**だれも見ていないときに、勝手に始まらない。**
- 【決定】（2026-11-21。決定 21）Ubuntu の既定の窓には、ほかのターミナルと、持ち主の Docker に届く穴を書く。
- 【提案】窓の文は、たとえば「この機械の範囲は、うっかり外を触ることを防ぐ柵です。ほかのターミナルは囲いの外で動きます。範囲つきのエージェントも、持ち主の Docker に届きます。名前の付いたソケットなど、ほかにも抜け道があります」。分ける設定を選んだ機械では、その機械で守れる範囲を出す。
- 【決定】（2026-11-21。決定 8）初めの印は、入れた直後は (1)。持ち主が設定で変えられる。プロジェクトに合う段を Istesso が勧めるときは、説明だけにする。

### 4. 覚える所と、変え方

- 【決定】（2026-11-21。決定 9）覚えるのは、プロジェクトごと（決定 1）。【提案】正本は、開発の機械に置く（プロジェクトの一覧と同じ。ADR 0025 の 1.1）。
- **コーディングエージェントが、書けない所に置く。** 自分の範囲を、自分で広げられないようにする。(4) でも書けないことが条件（決定 9）。具体的な置き場所は ADR 0021 の問い 27 と合わせる。
- 一覧で、全部のプロジェクトの範囲が見える。あとから、変えられる（決定 1）。狭めるのは、すぐ効かせる。広げるのは、下の 5 と同じ確かめを通す。
- だれが、いつ、何を広げたかを、記録に残す。

### 5. 範囲の外で止まったとき

「外」には、2 つの層がある。どちらも、同じ窓に出す。

| 層 | 何が止めるか | 止めて、待てるか |
|---|---|---|
| ツールの層 | コーディングエージェント自身の、許可の問い（ツールの設定） | 待てる見込み（コーディングエージェントが、自分で待つ）。問いを、外へ出す口があるかは、まだ分かっていない |
| OS の層 | 囲い。守りの本体（決定 3） | Linux は、待てる（seccomp のユーザー通知）。Mac のファイルは、待てない。断られたあとで、知らせる。ネットワークは、どちらも、中継で待てる見込み（「守らせる仕組み」の調4） |

- 窓は、頼んだ端末（Air）に出す。ホストの画面には、出さない（決定 4）。
- 窓に出すもの：どのプロジェクトの、どのコーディングエージェントが、何をしようとして止まったか（読もうとしたファイル、つなごうとした宛先）。秘密の中身は、出さない。
- 答えは 3 つ（決定 4）。
  - **今回だけ許す**：押すだけ。そのエージェントが終わるまで許し、次の起動には残さない（決定 12）。
  - **広げる**：プロジェクトの範囲に足して覚える。機械ごとに持ち主を確かめる。Touch ID がなければログインのパスワードを使う（決定 13）。
  - **断る**：押すだけ。コーディングエージェントに、「持ち主が断った」と伝わる形にする。
- 答えがなければ、断る。
- 同じ種類の問いを、続けて出さない（同じ宛先、同じフォルダーは、1 回にまとめる）。問いが多すぎると、人は、読まずに許すようになる。
- 【決定】（2026-11-21。決定 12、19）Linux のファイルと、両方の OS のネットワークは、止めたまま待つ。Mac のファイルは、断ってから知らせる。「今回だけ」も「広げる」も、許されたらエージェントを開き直す。非公開の口は足さない。
- 【提案】（読み。違えば直す）AURA はラップトップと同じく持ち歩く端末なので（範4）、AURA でも、その端末の指紋か画面ロックのコードで持ち主を確かめて「広げる」を選べる。
- 【提案】頼んだ端末が眠っている場合に、ほかの端末に知らせるなら、「今回だけ」と「断る」だけを出す（前からの案）。

### 6. 名前での検知（補助）

- シェルの口が、作業場のシェルで、いま前で動いているプログラムの名前を見る。決まった名前（コーディングエージェントの道具の、コマンドの名前。一覧は、設定で足せる）が、起動の係を通らずに始まっていたら、そのプロジェクトで 1 回だけ、手元の通知で知らせる：「範囲つきで、開き直しますか」。
- **止めない。終わらせない。** 知らせるだけである（決定 5）。
- 限り：名前を変えたもの、ほかのプログラムを通して起動したもの（名前が、別のプログラムのものになる）は、見つけない。だから、補助である。
- 【決定】（2026-11-21。決定 14）ふだんのコマンドが起動の係を通ったら知らせない。通らずに起きたときの通知だけとし、同じプロジェクトで繰り返さない。名前の一覧は Istesso が持ち、設定で足せる。ターミナルには書かない。

### 7. 「シェル」の権利

「シェル」を別の権利にすることは、範8 で決まった。ペアリングでの選び方は決定 23、24、そのあとの切り替えは決定 25 による。

- 「シェル」は、その機械で、シェルのユーザーにできることの全部である。持ち主のユーザーで動く機械（Studio）では、持ち主のアカウントの全部になる。「操作」より重い。ADR 0021 の「ふだんのプロファイル」と、同じか、それより重い。
- **ターミナルのアプリを、映像の道で映して、操作できる端末は、「シェル」を持つのと、同じことができる。**「シェル」の権利は、文字で運ぶ口の門である。映像の中のターミナルは、止めない。ADR 0021 は、Studio の「操作」を、「ふだんのプロファイル」と同じ重さにして、AURA に、既定では与えないと決めた。「シェル」は、端末の種類によらず初めは切（決定 23）。
- 【決定】（持ち主、2026-11-20。ADR 0025 の決定 8）**端末の権利を取り消したときも、herdr とコーディングエージェントは、止めない。その端末からのつなぎだけを切る。** 範囲の覚えは、プロジェクトのもので、端末のものではないので、変わらない。取り消された端末は、範囲の外で止まったときの窓（上の 5）に、もう答えられない。答える端末がなければ、「答えがなければ、断る」になる。
- 権利は、端末ごと、相手のホストごとに与える（ADR 0006 の形のまま）。ホストが、ほかのホストのシェルを開く形（常時稼働のホストの herdr から、Ubuntu のシェルを開く）では、ホストの身元に、権利を与えることになる。
- 【決定】（持ち主の決め、2026-11-21。【問い 範8】の答え。言葉のまま）**はい。「シェル」の許可（その端末からターミナルを開いてよいか）を 1 つ足す。**
  - 渡し方は、手間を増やさない形で。ペアリングのときに、渡す許可（見る、操作する、シェル）を一緒に選べる。AURA の初めの印は「シェルは切」で、その場で入れられる。
  - あとから入れたり切ったりするのは、Air の設定で、持ち主の確かめ（Touch ID）1 回。ホストの前に行かなくてよい形に（範6、ADR 0021 の決定 14 の見直しと合わせて）。
  - 自分は、あとから切り替える場面をあまり思いつかない。なので、ふだんは目に入らない所に置くだけでよい。作り込みは後回しで、ペアリングのときに選べることを先に。
- 【提案】（上の決定から）
  1. 「シェル」が含むものは、【問い 範8】の (a) のとおり：シェルを開く、コマンドを動かす、コーディングエージェントを範囲つきで起動する、転送を受ける。マウントは、「ファイル」（ADR 0013）。Studio の「シェル」は、「ふだんのプロファイル」と同じ重さで扱う。新しくペアリングした端末には、選ばなければ与えない。
  2. **先に作るのは、ペアリングのときに選べること。** ペアリングの手順（コード、SPAKE2、鍵の確かめ）は、変えない。変わるのは、記録に書く権利の初めの値の決め方である。ADR 0006 の「権限」の節を、作る前に書き直す（【提案】を ADR 0006 に書いた。ブランチ `design-user-default-1121`）。【決定】（2026-11-21。決定 23、24）どの端末も初めは「シェル」は切。持ち主がホストの側で選ぶ。ペアリングのやりとりは変えない。
  3. **あとから切り替える口は、後回し。** 作るときは、Air の設定の、ふだんは目に入らない所に置き、持ち主の確かめ（Touch ID）を 1 回通す。ホストの前に行かない形は、ADR 0006 の「許可と取り消しは、許可を与える側の PC で、人が行う」と、ADR 0021 の決定 14（与えるのは、ホストにいる持ち主だけ）を変えることになる。【決定】（2026-11-21。決定 25）Air から、持ち主のどの端末の「シェル」も切り替えられる。
  4. 続いている接続で、権利を読み直すものに、シェルを足す（ADR 0025 の 2.3。外すと 1 秒以内に切れる＝進め方の案の W2 の 3）。

## 守らせる仕組み（調査の結果と、【提案】）

2 回目の作業（2026-11-19）で、囲いの調査の結果を入れた。出どころは、`research-agent-scope` ブランチの `docs/research/agent-scope.md`。**この章の印は、その調査の印を写したものである。**（実）は、調査が実機で見たこと（Mac は Air、Linux は Ubuntu のホスト）。（資）は、調査が資料で確かめたこと。（推）は、考えただけのこと。括弧の中の M と L と A の番号は、調査の文書の、事実の番号である。**Studio では、何も試していない。** この文書の流れは、囲いについて、何も動かしていない。

道具の呼び方は、調査に合わせた：Claude Code、OpenAI の CLI、Gemini CLI。

### 先に、要点

1. **Mac で、特権なしに使える囲いは、Seatbelt（`sandbox-exec`）だけである**（実）。Apple は、「非推奨」「非公開の口で、いつでも変わる」と書いている（資）。3 つのコーディングエージェントも、Swift と Xcode の道具も、同じ口を使っている（実、資）。
2. **Seatbelt は、重ねられない**（実）。Istesso が外から囲うと、コーディングエージェント自身の囲いと、Swift と Xcode の道具が自分で掛ける囲いが、動かなくなる。切る口は、ある（実）。
3. **iOS と Web のビルドは、Seatbelt の中で動いた**（実。下の調2）。実機、シミュレーターでの起動、本物の証明書での署名は、試していない。
4. **Seatbelt は、宛先を、相手の名前でもアドレスでも絞れない**（実）。段 (3) は、手元の中継だけを許し、中継が宛先を決める形になる。
5. **Linux の Landlock は、ファイルと、TCP のポートを絞れる**（実）。**同じユーザーのままだと、抜け道がある**：Docker の口（持ち主は、Docker を使えるグループにいるので、root と同じ力）と、ユーザーのサービス管理に頼んで、囲いの外でプロセスを起こすこと（どちらも実）。
6. **Ubuntu のホストでは、名前空間を使う囲い（bubblewrap）が、動かない**（実）。AppArmor が止めている。コーディングエージェントの Linux の囲いは、これを使うので、このホストでは動かない（1 つは実、1 つは資）。
7. **「止めて、待つ」ができるのは、Linux の seccomp のユーザー通知だけ**（実。特権なし）。Mac の Seatbelt は、その場で断る（実）。断られたことは、Mac では、その場で分かる（実。管理者のユーザーで）。Linux の Landlock は、このホストでは、どこにも記録しなかった（実）。

**既定の Linux の形（持ち主の決め 2026-11-21 のあと。【提案】）。** ADR 0025 の決定 9 で、既定は、ユーザーを分けない形になった。上の表の「Linux」の列は、**分ける設定を選んだ機械**の形として残す。既定の Linux は、**持ち主のユーザーと、Landlock と seccomp**（試作 `proto-agent-scope` が動かした形）である。だから、正直に書く：

### 範10 の前の確かめ：Claude Code を、外の囲いの中で、自前の囲いを切らずに動かすと（2026-11-20）

持ち主の頼み（2026-11-20）：範10 は、切り忘れたときの動きを手で確かめる。**この流れは、Claude Code も、ほかのコーディングエージェントも、動かしていない**（持ち主の資格情報を使うため）。資料と、調査が実機で見た入れ子の失敗から、分かることを書く。そのうえで、持ち主が 2 分でできる、手の確かめを付ける。

**資料で確かめたこと**（Claude Code の公開の文書「Sandboxing」、code.claude.com/docs/en/sandboxing。2026-11-20 に読んだ）。

| # | 文書に書いてあること |
|---|---|
| C1 | 自前の囲いは、既定で切。`/sandbox` か、設定の `sandbox.enabled` で入れる。Mac は、Seatbelt |
| C2 | 囲うのは、シェルのコマンドと、その子だけ。ファイルの道具、MCP、フックは、囲いの外で動く（調査の A3 と同じ） |
| C3 | 「OS が、囲いに対応していない」か、「起動のときの、部品の確かめが失敗した」ときは、既定で、**コマンドを、囲いなしで、ふつうの許可の流れで動かす。** `sandbox.failIfUnavailable` を真にすると、起動のときに終わる |
| C4 | 起動のあとで、囲いが使えなくなったとき、`failIfUnavailable` が真なら、囲うはずのコマンドは、1 つずつ断られる（`Sandbox is required …`）。囲いなしでは、動かない |
| C5 | 囲いの中で失敗したコマンドは、Claude Code が、囲いなしでやり直そうとすることがある。やり直しを、だれが許すかは、許可の形による。`sandbox.allowUnsandboxedCommands` を偽にすると、やり直しは、できない |
| C6 | 設定のファイルを書かずに、その 1 回だけ、囲いの設定を渡せる：`claude --settings '{"sandbox": {…}}'`。起動の引数の設定は、プロジェクトの手元の設定より強く、`/sandbox` からは、変えられない |
| C7 | **Mac で、別の Seatbelt の中で動かしたときのことは、書いていない。** 入れ子について書いてあるのは、Linux のコンテナーの中の話だけである |

**実機で見たこと**（調査。Air）。Seatbelt の中で、違う決まりの囲いを掛けようとすると、`sandbox_apply: Operation not permitted` で失敗する。外が「全部許す」でも、同じである（M7）。OpenAI の CLI、`swift build`、`xcodebuild` は、この形で失敗した（M14〜M16）。

**そこから考えたこと（推測。確かめていない）。**

1. Mac の Seatbelt は、OS に付いている。だから、起動のときの「部品の確かめ」（C3）は、外の囲いの中でも、通る見込み。Claude Code は、「囲いは使える」と考えたまま、始まる。
2. そのあと、シェルのコマンドを動かすたびに、囲いを掛ける所で、`sandbox_apply: Operation not permitted` になり、**コマンドは、1 つも動かない**見込み。
3. Claude Code は、その失敗を見て、囲いなしのやり直し（C5）を出す見込み。許せば、コマンドは、自前の囲いなしで動く。**外の囲いは、効いたままである**（子に受け継がれる＝実、M5）。許可の形が、やり直しを自動で通すものなら、黙って、自前の囲いなしで動く。
4. `failIfUnavailable` を真にした設定や、`allowUnsandboxedCommands` を偽にした設定では、シェルのコマンドが、全部断られて、仕事にならない見込み（C4、C5）。
5. 別の見込み：起動のときに気づいて、C3 のとおり、囲いなしに落ちる。このときは、ふつうに動き、自前の囲いは、黙って無効になる。

**どれでも、守りの穴には、ならない。** 自前の囲いを切り忘れても、外の囲いは、破れない。起きるのは、「動かない」か、「許しの問いが、コマンドごとに出る」か、「自前の囲いが、黙って無効になる」かである。だから、**切るかどうかは、守りの問いではなく、使えるかどうかの問いである。** そして、C6 から、起動の係は、持ち主の設定のファイルに触れずに、起動の引数で、自前の囲いを切って渡せる見込みである（決定 15 の形 が、Claude Code では、できる見込み。動かしては、いない）。

**持ち主の、手の確かめ（2 分。Air で）。** Claude Code を、持ち主のログインで、3 回、短く起動する。持ち主の設定のファイルは、変えない（その 1 回だけの設定を、引数で渡す）。頼むのは、`echo hello` だけである。使う量は、ごく小さい。

```sh
cd "$(mktemp -d)"            # an empty temporary folder
claude --version             # note the version

# 1. baseline: no outer sandbox, its own sandbox on
claude --settings '{"sandbox":{"enabled":true}}'

# 2. the case in question: outer sandbox (allow everything), its own sandbox still on
sandbox-exec -p '(version 1)(allow default)' claude --settings '{"sandbox":{"enabled":true}}'

# 3. the proposed form: outer sandbox, its own sandbox off
sandbox-exec -p '(version 1)(allow default)' claude --settings '{"sandbox":{"enabled":false}}'
```

3 回とも、同じ頼みを 1 つだけ打ち、答えを見たら、`/exit` で終える。「このフォルダーを信頼するか」には、「はい」（空のフォルダーである）。「コマンドを動かしてよいか」には、「はい（今回だけ）」。

> Bash で `echo hello` を 1 回だけ実行して、出力と、エラーがあればその全文を、そのまま見せて。ほかのことは、しないで。

見る所は、2 の回である。

| 2 の回で、見えたもの | 意味 |
|---|---|
| ア. `sandbox_apply: Operation not permitted` が出て、`hello` が出ない。続けて、「囲いなしで、やり直してよいか」と聞かれることがある（**「いいえ」と答える**） | 上の 2 と 3 のとおり。切らないと、動かない。起動の係が、引数で切る |

### 試作のあと（2026-11-20。Linux の起動の係）

別の流れが、Linux の起動の係を試作した（`proto-agent-scope` ブランチの `docs/research/agent-scope-proto.md`。Ubuntu のホストで、**持ち主のユーザーのまま**。専用ユーザーは、まだない。本物のコーディングエージェントは、動かしていない）。印は、その流れのもの。上の「段ごとの仕組み」に効く所だけを書く。

- 段 (1)〜(3) の Landlock の形は、動いた：プロジェクトの外、持ち主のホーム、`/tmp` は、読めず、書けない。中継のポートのほかへの TCP は、断られた。ビルドの道具と Git は、段 (1) で動いた。GPU と adb は、段 (2) で動いた（実）。
- **Landlock は、ポートだけで決める。** 中継と同じ番号なら、よその機械へも、つなぎに行けた。UDP は、止まらない（実）。分ける設定で、導入時に root の決まりを入れる理由である（決定 17）。決まりのファイルの案は、試作の文書の 7 章にある（文法も、まだ確かめていない＝推）。
- **同じユーザーの抜け道は、開いていた**：Docker の口、ユーザーのサービス管理（実）。分ける設定を用意する理由である。
- **止めて聞く仕組み（seccomp のユーザー通知）を、ファイルを開くことについて作った。** 範囲の外の、本当にあるファイルだけを、止めて聞く。小さなビルドで、約 7 % 遅くなった（2.16 秒が、2.31 秒。実）。まず seccomp のユーザー通知を使う（決定 20）。大きなビルドでは、まだ。
- **待ち受けを、機械の中だけに移す**（持ち主の、2026-11-19 の夜の件：アドレスを指定しない開発サーバーが、家の LAN から見えた）。起動の係が、待ち受けの呼び出しを代わりに行い、全部のネットワーク（`0.0.0.0`、`::`）を、その機械の中（ループバック）に移す。root は、要らない（実）。ポートの転送の見つけ方は、変わらない。**効くのは、範囲つきで起動したものだけである。** 持ち主のシェルで、直接起動したもの（その夜の件そのもの）には、効かない。【決定】（2026-11-21。決定 22）直接始めたものが全部のネットワークで待ち受けたら、いまは知らせるだけとし、名前での検知を併用する。機械全体のファイアウォールは、M1 の確定の判定のあと、使っているポートを一覧にしてから（sudo は 1 回）。
- **囲いの中から、自分の開発サーバーにつなぐには、そのポートを、つなげる先に足す必要があった**（実）。覚えた宛先には範囲の係が代わりにつなぐ。Landlock にその番号は足さない（決定 27）。
- **Docker。** 専用ユーザーを、Docker のグループに入れると、囲いが意味をなくす。入れないと、Docker を使う開発が、できない。【決定】（2026-11-21。決定 21）分ける設定でだけ使う：**コーディングの専用ユーザーに、root なしの Docker**（持ち主の Docker とは、別のデーモン）。要る root は、`uidmap` を入れることと、linger（1 回ずつ）。AppArmor の決まりは、足さなくてよい見込み（資）。GPU は、渡せる見込み（推）。**まだ、だれも動かしていない**（`uidmap` が、ホストにないため）。残る弱さ：コンテナーは、専用ユーザーが読めるものを、どれでも差し込める。同じ専用ユーザーの中の、プロジェクトのあいだは、分かれない（推）。持ち主のユーザーのまま、Docker だけを root なしに替える形は、抜け道をふさがない（ADR 0025 の 6 章）。既定の形では、持ち主の Docker に届く（3）。
- **分ける設定だけの root の手順**は、試作の文書の 7 章に、持ち主が 1 行ずつ打つ形で、並んでいる（R1〜R7：専用ユーザー、グループ、linger、ネットワークの決まり、`uidmap`。元に戻す手順つき）。**どれも、まだ動かしていない。** M5 の専用ユーザー（ADR 0021 の U2）と、1 つの手順にまとめる。
- 試作の文書の 8 章の、残りの問い（専用ユーザーの名前、DNS と UDP、段 (4) の通信、同じ専用ユーザーの中の、プロジェクトのあいだ）は、ここには、写していない。W5 を始めるときに、問いにする。

【決定】（2026-11-21。決定 27）試作 `proto-agent-scope` のあと、次の 5 つに決めた。

1. 「今回だけ」は、この起動が終わるまで。「この操作 1 回だけ」は選択肢にしない。
2. 段 (1)〜(3) では、TCP Fast Open、MPTCP、`io_uring` を断る。
3. 覚えた宛先の番号を Landlock の許すポートに足さない。範囲の係がエージェントに代わってつなぐ。
4. ソケットの種類は UNIX、INET、INET6、NETLINK だけ。INET のストリームは TCP だけにする。
5. SMC（`AF_SMC`）の確かめは、急がない。

## 権限

AGENTS.md：権限の要る処理を増やすときは、理由を ADR に残す。

- Mac の Seatbelt、Linux の Landlock と seccomp には、特権が要らない（調査が、実機で見た）。
- **ユーザーを分ける設定の Linux で、ネットワークを守るための決まり（nftables）を入れるのに、root が要る。導入の 1 回。** 理由：Landlock は、宛先を絞れない。コーディングの専用ユーザーの通信を、その機械の中の中継だけにするには、OS のフィルターに、ユーザーごとの決まりを入れるしかない（決定 17）。
- Linux で、止まったことを、監査の記録から読む形（範14 の (b)。決定 20 では、まず (a) を使う）を採るなら、監査を有効にするのに、root が 1 回要る。
- 名前空間のための決まり（AppArmor）は、足さない。
- 物差し：**動いているあいだに、root を使わない**（ADR 0014 のまま）。導入の 1 回で済むこと。
- 【提案】（持ち主の決め 2026-11-21。ADR 0025 の決定 9）**既定の形（ユーザーを分けない）では、Linux でも、root は要らない**（Landlock と seccomp だけ）。上の root の手順（専用ユーザー、nftables、root なしの Docker のための `uidmap` と linger）は、分ける設定を選んだ人のためのものとして残す。持ち主の機械では、いまは分けない。
- Mac で、別のユーザーを作る形を採るなら、導入のときに、管理者の権限が要る（ADR 0014 の表と同じ）。Studio に別のユーザーを作って試す案は取り下げた（決定 18）。

## 既知の不足

- **Mac の守りの本体は、Apple が「非推奨」「非公開」と書いている口の上にある**（決定 18）。
- **確かめていないもの（Mac）：** 実機（iPhone）への書き込み、シミュレーターでの起動、本物の証明書での署名、Xcode のスクリプトの段と Swift のマクロ。どれも、持ち主の機器と鍵に触れるので、持ち主の許しが要る。管理者でないユーザーで、断られた記録を読めるか。Claude Code を、外の囲いの中で動かしたときの落ち方は、資料と考えだけ（「範10 の前の確かめ」。持ち主の手の確かめを待つ）。Studio では、何も試していない。
- **Mac の別のユーザーの形は、資料と考えだけである。** 決定 6 の「比べる」は、資料で比べるまで。Studio で別のユーザーを作る試しはしない（決定 18）。
- 【決定】（2026-11-21。決定 21）Ubuntu の既定では、囲いの中からも持ち主の Docker が使える。分ける設定では、専用ユーザーを持ち主の Docker のグループに入れず、そのユーザーの root なしの Docker を使う。この形は、まだ動かしていない。
- **Linux の起動の係の試作は、持ち主のユーザーのまま、動かした。** 専用ユーザーの上では、まだ。root の手順（R1〜R7）も、まだ、だれも動かしていない。2026-11-21 の持ち主の決め（既定は分けない）で、試作の形が、既定の形になった。
- **既定の Ubuntu の範囲は、うっかりを防ぐ柵で、守りの本体ではない**（上の「既定の Linux の形」）。Docker の口、ユーザーのサービス管理、名前の付いたソケット、範囲の外のほかのターミナルから、抜けられる。UDP も通る。
- 【決定】（2026-11-21。決定 28）既定の柵では、範囲の外のファイルも、権限、時刻、拡張属性を変えられる。この穴の手当ては、分ける設定で専用ユーザーを用意する手順（R1）を待つ。
- 範囲の係は、持ち主のシェルで直接始めたプログラムには、効かない（決定 22）。
- Linux の Landlock（ホストの版）は、名前の付いたソケットと、UDP を止めない。専用ユーザーにしても、だれでもつなげるソケットには、届く。
- 中継は、相手が名乗った名前で決める。暗号の中は、見ない。UDP は、通らない。
- コーディングエージェントに、道具の自前の囲いを切る指定を、どうやって使わせるかは、決まっていない。
- 囲いをかけたときの遅さは、測っていない。
- この文書は、実機で、何も動かしていない。
- 範囲 (4) は、守りがない。選んだプロジェクトでは、コーディングエージェントは、既定では持ち主と同じことができる。分ける設定で専用ユーザーが届く範囲と読むのは 2 のとおり（決定 11）。
- 範囲 (1)〜(3) でも、コーディングエージェントは、自分の API の鍵と、渡された資格情報には、届く（ADR 0021 が書いたとおり）。
- 転送と、URL を開く頼みは、範囲 (3) の外の道である（上の 2）。
- 名前での検知は、すり抜けられる。
- コーディングエージェントが、ホストの画面に出す、OS の確かめの窓（キーチェーンの問い、など）は、この文書の窓には、出てこない。進め方の案の、資格情報の段で扱う。
- 複数の人が、同じ機械を使う形は、考えていない。
