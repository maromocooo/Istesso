## 背景

2 つの決まりが、ぶつかる。

- **隔離**（R-07、ADR 0003。【決定】2026-11-15）：アプリとエージェントを、専用ユーザーで動かす。ふだんのユーザーのホームは、ほかのユーザーから読めない。2026-11-21 からは、分ける設定の決め（下の「問い 1」）。
- **机と同じ設定**（R-04。【決定】2026-11-18、持ち主）：ホストで開くアプリは、持ち主の机のログインと同じ設定（言語、入力方式、見た目、フォント、フォントの大きさ）で開く。エージェントは、机のセッションか、持ち主のアカウントの設定から受け取る。ふだんのプロファイル（ブラウザーのログイン、Blender の設定）を使うかどうかは、アプリごとに持ち主が選ぶ。試用のあいだは、試験用のプロファイルのまま。Istesso は、持ち主のふだんの設定を変えない。読むだけ。

専用ユーザーは、持ち主のホームを読めない。だから、何もしなければ、アプリは英語の、既定の見た目で開き、ふだんのプロファイルも使えない（ADR 0014 の「既知の不足」：Istesso から開いたアプリは、まっさらな状態で始まる）。

## 問い 1：アプリを、どのユーザーで動かすか

### 案

- **U1：持ち主のユーザー。** いまの試用版。
- **U2：専用ユーザー 1 つ。** ADR 0014 の A。ホストの役を丸ごと。

### 提案

**【提案】ユーザーを分ける設定では、U2 を土台にし（ADR 0014 の A を採用する）、そのあとで U5 に進む。** U3、U4、U6 は採らない。

**【決定】2026-11-19、持ち主：Linux のホストは、この提案のとおり（U2 から、そのあと U5）。** herdr とコーディングエージェントは、2 つめの専用ユーザー（下の「コーディングエージェント（herdr）」）。Mac のホストは、下の「Mac のホスト：Mac Studio と Mac mini」。

理由：

1. **持ち主のもの（資1〜資3、資10）を守ることが、いちばん重い**（脅威モデルの 2 章）。これは U2 で、OS の権限で守れる。動いているあいだの特権も要らない。
2. **アプリとアプリのあいだと、端末の鍵**は、U2 では守れない（脅威モデルの 6.2）。U3 なら OS の権限で守れるが、起動のたびに特権が要るか、ユーザーの数だけエージェントが要る。U5 は、特権なしで、ファイルについては同じところまで狭められる見込み。
3. **ふだんのプロファイル（ログインを含むもの）を置けるのは、U5 になってから**にする（下の「ふだんのプロファイル」）。U2 のままだと、写したアカウントが、同じ袋のすべてから届く。
4. 遅延：U2 と U5 は、1 フレームごとの経路を変えない見込み。それでも、映像、入力、音の経路を動かし直すので、前後で測る（AGENTS.md）。測るのは、M1 の確定の判定のあと（m5-plan.md の手順 6 のまま）。

U3 に移るとき：U5 の囲いが、ホストの OS で使えないと分かったとき（下の「確かめること」）。または、アプリとアプリのあいだを、OS の権限で分けることが要ると、持ち主が決めたとき。

#### 持ち主の決め（2026-11-21）のあと（【提案】）

Linux のホストも、既定では Studio と同じく、持ち主のユーザーでアプリを動かす（ADR 0025 の【問い 作22】）。U2 から U5 へ進むのは、導入のときに、その機械で「分ける設定」を選んだ場合である。
【提案】（読み。違えば直す）分ける設定に当てるのは、最初の答えの 2（P1・P2）、3、6〜8、2 回目の 10（作業の場所）、3 回目の 10〜12、4 回目の 22 と 24 である。

- 「操作」を持つ端末は、開いたアプリを通して、持ち主のファイル、ふだんのブラウザーのログイン、SSH と Git の鍵まで届く。U2 では専用ユーザーのホームまでだった。2026-11-19 に Studio で決めた形が、既定ではどの機械にも広がる。
- ホストの役（エージェント、ランナー）も、その鍵のファイルも、持ち主のほかのプログラムと同じユーザーに属する。間に OS のユーザーの境目はない。守りは「同じユーザーのほかのプログラムに対して、どこまで守るか」の線と、鍵の置き場所（問い 27）による。
- たとえば、遠くから開いたブラウザーが悪いページに乗っ取られると、その機械の前で開いたときと同じく、持ち主のアカウントの全部に届く。U2 では専用ユーザーの中で止まった。
- アプリがふだんの設定とログインを使うので、決定 4 の「ふだんのプロファイル」と「操作」で届く範囲の差は小さくなる。【提案】（読み。違えば直す）3 回目の答え 13 (1) の「囲いのない Mac では、操作をふだんのプロファイルと同じ重さで扱う」を、既定のホストすべてに当てる。
- 既定では、U5 の土台にしていた専用ユーザーがない。持ち主のユーザーでアプリごとの囲いを付ける方法は【調べる】調20。
- 端末ごとの権限、ペアリング、取り消しの決めは、どちらの設定でも同じ。2 回目の答え 11（Studio では、新しい端末は「閲覧」だけ）もそのまま。分ける設定の機械には、U2 と U5 が残る。

## 画面のあるアプリを専用ユーザーで動かすと、何が変わるか

持ち主から、早めに調べるよう頼まれたこと（2026-11-18）。アプリの絵は、いまも、アプリごとの隠れたコンポジターから、暗号化した通信路で手元の Mac へ届いている。その中で、アプリのユーザーが、ほかのプロセス（エージェント、机）のユーザーと違うとき、何が変わるかを並べる。

列の意味：U1（いま）、U2（専用 1 つ。ランナーもアプリも同じ専用ユーザー）、U3（アプリごと。ランナーをアプリと同じユーザーで動かす）、U4（エージェントとランナーは持ち主、アプリは専用ユーザー）。

### 手元の Mac から見て、変わること

U2 では、**絵と入力の経路は変わらない。** 絵は、専用ユーザーのランナーから、同じ通信路（ADR 0015）で届く。変わるのは、次の 3 つだけ。

1. 手元の Mac がつなぐ相手は、ホストの**専用ユーザーの身元**。ペアリングは、その身元と行う。持ち主の側の身元は、クライアントの役（ホストの机で、ほかの PC のアプリを見る）だけを持つ。
2. 一覧には、1 台の PC が 2 つの身元で出る。【提案】役割表に「同じ PC」の印（例：PC ごとに 1 つの識別子）を足し、一覧では 1 台にまとめて見せる。印は、ハンドシェイクで確かめた身元どうしの申告なので、信頼の根拠にはしない（見せ方だけに使う）。
3. ペアリングの始め方：ホストの役の身元のペアリングは、専用ユーザーのエージェントが受ける。持ち主は、ホストにいる人の口から、「ペアリングを待つ」を頼む（コードは、持ち主の画面に出す。ログには出さない）。形は、実装の前に決める。

Mac のホスト（M4）は、2 つの形がある（下の「Mac のホスト：Mac Studio と Mac mini」）。Mac mini（ホスト専用）は、専用ユーザーでログインする（ADR 0014）。アプリも、取り込み、入力の注入（ADR 0017 の許可）も、そのログインのセッションの中で動く。手元の Mac から見て、変わることは U2 と同じ。Mac Studio（持ち主のふだんの Mac で、判定のホスト）は、持ち主のユーザーで動く。

- 【調べる】Studio の上のコーディングエージェント（中6）：下の「コーディングエージェント（herdr）」の「Mac の上」。

**【調べる】Studio のホストを、専用ユーザーで動かす方法（持ち主の頼み、2026-11-19。【決定】2026-11-19、持ち主：調べてよい。文書と Apple の文書だけ。機械の上で動かすことが要るなら、先にまとめ役に聞く）：**

macOS が、持ち主のセッションの横で、ほかのユーザーの GUI のセッションを動かせるかを調べる。使えるなら、Studio も Mac mini と同じ形（専用ユーザー）にできる。今回は、文書を読むだけで、何も動かさない。調べる候補と、確かめることは次のとおり。

## 設定の渡し方（言語、入力方式、見た目、字、字の大きさ）

### 案

- **S1：専用ユーザーのエージェントが、持ち主の設定を直接読む。** 持ち主のホームを、専用ユーザーに読ませる（ACL、グループ）ことになる。
- **S2：持ち主の側の小さな係が、決めた値だけを読み、専用ユーザーへ渡す。** 係は、机のログインで動く。
- **S3：手元の端末（いま使っている Mac）から、言語などを渡す。**
- **S4：導入のときに 1 回だけ写す。**

| 観点 | S1 直接読む | S2 持ち主の側から渡す | S3 手元の端末から | S4 1 回だけ写す |
|---|---|---|---|---|
| 隔離 | 崩れる。持ち主のホームの権限を変える（ふだんの側を変えない決まりに反する） | 保つ。渡るのは、決めた値の一覧だけ | 保つ | 保つ |
| 机と同じか | 同じ | 同じ（机にログインしているあいだ） | 机とは違う。Mac の言語は渡せるが、見た目（テーマ、フォント）は OS が違う | 写したときの値のまま |
| 机にだれもいないとき | 読める | 最後に受け取った値を使う（専用ユーザーの中に残す） | 渡せる | 同じ |
| 持ち主の側に増えるもの | なし | 小さな係 1 つ。**頼みを受けない。待ち受けない** | なし | なし |
| 特権 | 持ち主のファイルの権限を変える | なし（下の「渡す道」） | なし | 導入のとき |

### 提案

**【提案】S2。机にだれもログインしていないときは、最後に受け取った値で開き、そのことを `istesso doctor` と画面に出す。** 【決定】2026-11-19、持ち主：提案のとおり（下の 7 の Mac のホストも）。

1. **係**：持ち主の机のログインで動く、小さなプログラム（ユーザーのサービス。机にログインしたときに起動する）。持ち主の設定を**読むだけ**。値が変わったら（たとえば字の大きさを変えた）、また渡す。
2. **渡すもの（一覧で決める。ほかは渡さない）**：
   - 言語：机のユーザーのサービスの環境（試用版と同じく `systemctl --user show-environment`）の `LANG`、`LANGUAGE`、`LC_*`。`XDG_CURRENT_DESKTOP`。
   - 見た目：テーマ、アイコン、カーソルとその大きさ、字（ふつう、文書、等幅）、字の大きさの倍率、濃淡（明るい、暗い）、窓のボタンの並び。GNOME の設定の、名前を決めた鍵だけ（試用版が読んでいるものと同じ）。
   - 入力方式：使っている入力ソースの一覧（どの変換を使うか）とキーボードの配列。**学習と辞書は渡さない**（ADR 0020 の【決定】：学習はホストの専用のフォルダー。机のログインの学習には触れない）。
   - 渡さないもの：鍵束、オンラインアカウント、最近使ったファイル、検索の履歴、壁紙、そのほか一覧にないもの。
3. **渡す道**（見直しの 中7 で直した。【提案】）：最初の版は、係がエージェントの口につなぐ形だった。それだと、係が、アプリの側（専用ユーザー）からの返事を読むことになり、向きが逆の道ができる。**係は、導入のときに root で作る、受け渡しのフォルダーに、値のファイルを書くだけにする。** フォルダーは、持ち主だけが書けて、アプリの専用ユーザーが読める（持ち主は持ち主のユーザー、グループは口のグループ、2750 のような形）。係は、アプリの側から何も読まない。待ち受けない（脅威モデルの守3）。エージェントは、ファイルが変わったら読み直す。書きかけを読まないように、係は別の名前で書き終えてから名前を替える。
4. **受け取る側**：値を検査する（長さ、文字の種類、知っている鍵だけ）。アプリごとの設定ファイル（試用版と同じ `keyfile` の形）と、アプリの環境に入れる。起動のたびに入れ直す。アプリが自分で変えた設定は、そのアプリのフォルダーにだけ残る。
5. **持ち主の設定は変えない。** 書き戻しはしない。
6. **フォントとテーマ**（見直しの 軽6。【提案】）：持ち主が自分のホームに入れたフォントとテーマ（`~/.local/share/fonts` など）は、専用ユーザーから読めない。名前だけ渡しても、アプリには届かない（I6 が通らない）。システムに入っているもの（`/usr/share` の下）は届く。持ち主のホームのものは、持ち主が名指ししたものだけを、受け渡しのフォルダーへ写す（フォントのライセンスは、持ち主の判断）。
7. Mac mini（ホスト専用）には、持ち主の机のログインがない。【決定】2026-11-19、持ち主：導入のときに、手元の端末の言語と字の大きさを写し、あとは持ち主が変える。Mac Studio は、持ち主のセッションそのものなので、渡すものはない。

### ホストの中の口

専用ユーザーのエージェントは、同じ PC の中の口を 1 つ持つ（いまの、ホストにいる人の口。ADR 0010 の 13）。U2 では、ここに、持ち主のユーザーからもつなぐ。

【決定】2026-11-19、持ち主：**グループつきのフォルダーを、導入のときに root で作る。** 導入はどのみち root を使う。ファイルの権限のほうが確かめやすく、Landlock とも合う。最初の版の案（抽象名前空間のソケット）は、取り下げた。

形（【提案】。名前は、実装のときに決める。下の「ユーザーとグループ」と合わせる）：

| もの | 持ち主 | グループ | 権限 | 中身 |
|---|---|---|---|---|
| 口のフォルダー（例：`/run/istesso`） | **root**（見直しの 中7。アプリの専用ユーザーが持つと、どのアプリも、フォルダーの権限を変えられる） | 口のグループ（例：`istesso-local`。持ち主とアプリの専用ユーザーが入る） | 1770 か 0770（グループの人だけが入れる。中のものは、作った人しか消せない） | エージェントの口のソケット 1 つ |
| 口のソケット | アプリの専用ユーザー（エージェントが作る） | 口のグループ | 0660 | — |
| 受け渡しのフォルダー（例：`/run/istesso/desk`。設定の係が書く） | 持ち主 | 口のグループ | 2750（持ち主だけが書け、グループが読める） | 設定の値のファイル、名指しの写し |

- `/run` は起動のたびに空になるので、フォルダーは、導入のときに置く systemd の決まり（tmpfiles）で、起動のたびに作る（root の仕事は、導入の 1 回だけ。考え）。
- **ファイルの権限に加えて、エージェントは、つないできた相手のユーザーを確かめる**（`SO_PEERCRED`）。持ち主のユーザーからの頼みだけを受ける。アプリの専用ユーザーのプロセス（つまり、アプリ）からのつなぎは、断る（グループに入っていても、アプリから口を使わせないため。脅威モデルの 6.2）。持ち主の側のコマンドは、相手がアプリの専用ユーザーのときだけ話す。
- 「持ち主のユーザー」がだれかは、つないできた相手の申告では決めない。【提案】口のグループの記録（`/etc/group`）で、アプリの専用ユーザーのほかに入っているユーザーを、持ち主とする（見直しの 中7）。1 人でないときは、閉じる側に倒す（だれも持ち主として扱わない）。
- グループに入れたことが効くのは、持ち主がログインし直したあとである（見直しの 中7）。導入の最後に、そのことを伝える。
- **権限の管理を、この口に足す**（見直しの 中2。【提案】）。いまは、`istesso peers allow`、`deny`、`remove` が、ペアリングの一覧のファイルを直接書く。専用ユーザーで動かすと、一覧は専用ユーザーのホームにあり、持ち主からは書けない。そこで、口に、権限を与える、外す、ペアリングを消す、の 3 つを足し、**持ち主のユーザーからだけ**受ける。いまの口の作り（同じユーザーの 0700 のフォルダーを前提にしている）は、この形に合わせて直す。**ADR 0006 の「権限」の節を、先に更新する**（AGENTS.md の 4）。【決定】2026-11-19、持ち主：**与えるのは、ホストにいる持ち主だけ**（SSH でホストにログインしているときを含む。どちらも、持ち主のユーザーとして、この口を使う）。**外すのは、持ち主のどの端末からでもできる**（制御チャンネルの新しい頼み。下）。
- **引き換えになること**（はっきり書く）：外すのを遠くからできるようにすると、**なくした端末、盗まれた端末も、ほかの端末の権限を外せる。** 乗っ取りにはならない（与えることはできない）が、持ち主の端末が使えなくなる迷惑になる。
- 【決定】2026-11-19、持ち主：**この引き換えを受け入れる。** 外された端末は、持ち主が元に戻せる。戻すのは、そのホストの前で行う（2026-11-21、問い 21）。**記録には、どの端末が、いつ、どの端末を外したかを残す。** 記録に、鍵もコードも入れない（AGENTS.md の 4）。
- 【提案】抑え方（上の決定に合わせた形。2、3、5 は決定と同じ向き）：
  1. （取り下げた案：遠くから外す頼みを送れるのは、新しい権限「取り消し」を持つ端末だけ。）【決定】2026-11-21（問い 17）：**新しい権限は作らない。** 抑えるのは、下の 4 の数の上限だけ。
  2. 遠くから外せるのは、**権限を外すことと、ペアリングを止めることだけ**で、記録は残す（`deny` に当たる。`remove` は、ホストにいる持ち主だけ）。だから、ホストにいる持ち主が、1 つのコマンドで元に戻せる（ペアリングのやり直しは要らない）。
  3. 外したことは、全部の持ち主の端末とホストの一覧に、どの端末が外したかと一緒に出す。
  4. 1 台の端末が外せるのは、短い時間に数台まで。超えたら、その端末から外す頼みを止めて、ホストにいる持ち主に知らせる。【決定】2026-11-21（問い 17）：**この上限だけで抑える。外したら、持ち主のほかの端末に知らせる。どの端末も、自分自身は、いつでも外せる**（上限に数えない）。
  5. 外された端末は、外す頼みを送れない。コードで読んだこと（動かして見たのではない）：ハンドシェイクが相手を信じるかは、ペアリングの一覧に**記録があるか**だけで決まる（`istesso-pair` の `is_trusted`）。だから、`remove` された端末はハンドシェイクで断られるが、`deny` で権限だけを外された端末は、ハンドシェイクは通り、頼みが権限で断られる（ADR 0006 の「閲覧も取り消せる。記録は残る」）。遠くから外すのが `deny` なら、外された端末は、つながりはするが、外す頼みも断られる形にする（外す頼みにも「閲覧」を要る、など）。
  6. 【決定】2026-11-21（問い 21）：取り消しはほかのホストに伝える。信じるのは、ペアリングしたホストの知らせだけ。眠っていたホストは、起きたらまず常時稼働のホストに尋ねる。戻したことは伝えない。持ち主が、そのホストの前で戻す。
  7. 【決定】2026-11-19、持ち主：作る前に ADR 0006 と 0007 を書き直す。コードは `main` の前に Fable が見直す。「出先で実用」の段の前に作る。制御チャンネルに頼みを足すので、先に ADR 0007（メッセージ）と ADR 0006（権限）を更新する（AGENTS.md の 4）。ペアリングと権限に触るので、`main` に入れる前に、最後の見直しを受ける（持ち主の決め。下の「状態」の見直しの決まり）。
- ペアリングのコードは、「ペアリングを待つ」の答えとして、この口を通る。ログに出さない。ほかのユーザーに見えない（ソケットは口のグループだけ）。
- コーディングエージェントの専用ユーザーは、口のグループに入れない（下の「ユーザーとグループ」）。M6 で、コーディングエージェントから頼むこと（`istesso run` など）が要ると分かったら、そのときに、受ける頼みを絞って足す。
- Landlock：アプリの囲いの決まりに、口のフォルダーを入れない。
- 受ける頼みは、持ち主のユーザーから：セッションの一覧、止める、ペアリングを待つ、権限を与える・外す・ペアリングを消す。設定は、この口ではなく、受け渡しのフォルダー（【提案】）で渡す（上の「設定の渡し方」の 3）。
- この口そのものは、制御チャンネル（`istesso-link`）の手順を変えない。**ただし、遠くから外す頼みと、ホストどうしで取り消しを伝える形は、制御チャンネルにメッセージを足すので、先に ADR 0007 を更新する**（上の 6）。

## ふだんのプロファイル

### 案

- **P1：アプリ自身のログインと同期を、専用ユーザーの中のプロファイルで使う。** 例：専用ユーザーの Firefox で、持ち主が Firefox のアカウントにログインして同期する。Istesso は、持ち主のプロファイルに触れない。
- **P2：持ち主のプロファイルを写す。** 試用版の Blender の形（1 回だけ写す。写し直すのは、持ち主が頼んだとき）。写すのは、持ち主の側の係（読むだけ）。
- **P3：そのアプリだけ、持ち主のユーザーで動かす。**
- **P4：持ち主のプロファイルを、専用ユーザーに読み書きさせる**（ACL、グループ）。

| 観点 | P1 アプリ自身のログイン | P2 写す | P3 持ち主で動かす | P4 読み書きさせる |
|---|---|---|---|---|
| 渡るもの | 持ち主がログインして選んだものだけ | プロファイルの全部（ブラウザーなら、クッキーと保存したパスワード） | なし（持ち主のもの、そのまま） | なし（持ち主のもの、そのまま） |
| 隔離 | 保つ。アカウントは専用ユーザーの袋に入る（脅威モデルの 6.3） | 保つ。アカウントは袋に入る | **そのアプリについて崩れる。** 「操作」を持つ端末が、持ち主として動ける。持ち主の側に、起動を受け付けるエージェントが要る（ADR 0014 が塞いだ穴が、また開く） | 崩れる。持ち主のファイルの権限を変える |
| 机のアプリと同時に使う | できる（別のプロファイル） | できる（写し） | **できないことがある。** Firefox は、同じプロファイルを 2 つで開かない（考え）。机の Firefox が動いていると、リモートの起動が机に窓を開くことがある（試用版が `--no-remote` を付けている理由） | 壊れる恐れ（同時に書く） |
| 鍵束に頼るもの | アプリ自身の保管（試用版の Chrome は `--password-store=basic`） | **写しても使えないことがある。** Linux の Chrome は、保存したパスワードとクッキーを、机の鍵束の鍵で暗号化している（考え）。鍵束のない所に写すと、ログインが消える | 机の鍵束を使える（机にログインしていて、鍵束が開いているとき） | P3 と同じ問題 |
| 変えた設定の行き先 | 専用ユーザーの中（同期すれば、持ち主のほかのブラウザーにも） | 写しの中だけ。持ち主のものには戻さない | 持ち主のもの | 持ち主のもの |
| 持ち主のふだんの設定を変えない決まり | 守る | 守る（読むだけ） | **アプリが、持ち主の設定を変える**（Istesso が変えるのではないが、Istesso が開いたアプリが変える） | 反する |

### 提案

**【決定】2026-11-19、持ち主：下の 1〜6 のとおり**（1 と 2：P2 と P1。2 の「U5 ができてから」。4：P3 は、要るアプリが出たときだけ。6：新しい権限。AURA には、既定で与えない）。

1. **設定だけのプロファイル**（Blender の設定など、ログインを含まないもの）は、**P2**（写す）。写すのは、持ち主の側の係。写し直すのは、持ち主が頼んだとき。書き戻さない。【提案】（見直しの 軽6）：写すかどうかは、ホストにいる持ち主が選ぶ（遠くのランチャーから選ばせない。遠くの端末が、持ち主のプロファイルを専用ユーザーへ動かせないように）。【決定】2026-11-21（軽6）：写すのは、アプリごとに決めた**ファイルの一覧**だけにする。試用版は、Blender の設定のフォルダーを丸ごと写していて、最近使ったファイルの一覧や、アドオンが保存したトークンも入りうる（【調べる】Blender の設定のファイルのうち、どれにアドオンの値が入るか）。
2. **ログインを含むプロファイル**（ブラウザー）は、**P1**（アプリ自身のログインと同期）。ただし、**U5（アプリごとの囲い）ができるまでは、使わない**（いまの【決定】のまま、試験用のプロファイル）。U2 のままだと、ログインが、同じ袋のほかのアプリ、コーディングエージェント、乗っ取られたエージェントから届く（脅威モデルの 6.3、守4）。
3. ブラウザーのプロファイルを P2 で写す形は、採らない。渡るものがいちばん多く、鍵束に頼るものは写しても使えない。
4. **P3 は、いまは採らない。** P1 では足りないアプリが出たとき（たとえば、机の鍵束にあるパスワードが要る）に、持ち主が決める（【決定】2026-11-19、持ち主：P3 は、要るアプリが出たときだけ）。採るなら、そのアプリだけ、持ち主が名指しし、画面に「このアプリは、あなたのユーザーで動きます」と出し、下の権限を要る形にする。
5. **P4 は、採らない。**
6. **新しい端末の権限「ふだんのプロファイル」を足す。** ログインを含むプロファイル（P1、P3）を使うアプリを開く、つなぐには、この権限を要る。新しくペアリングした端末には、与えない。なくした端末（攻3）が、持ち主のアカウントに届かないようにするため。**AURA には、既定で与えない**（外へ持ち出すため）。要るときだけ与え、済んだら外す（【決定】2026-11-19、持ち主）。権限の確かめ方は、ほかの権限と同じ（頼まれたときに読み直す。ADR 0010）。Mac Studio での「操作」も、同じ重さで扱う（上の「Mac のホスト：Mac Studio と Mac mini」）。
7. 【決定】2026-11-19、持ち主：**持ち主の Mac mini では、ログインを使わない**（試しのホスト）。**製品としては、囲いのないホスト（Mac）では、「操作」に「ふだんのプロファイル」と同じ重さを持たせる。** Linux では、(b) か (c) の確かめが済むまで、ログインを使わない（下の「アプリごとの囲い」の (d)。【決定】2026-11-19）。そのあいだは、同じことになる。

## アプリごとの囲い（U5）

U2 の袋の中で、アプリに、自分のフォルダーのほかを読ませない仕組み。どれも、**ライセンスは記憶によるもので、使う前に、元のライセンスの文書で確かめる。コードは読まない**（持ち主の決め、2026-11-18：ほかの人のコードは、中身を読む前にライセンスを見る。動きは公開の文書から学ぶ）。

| 仕組み | 中身 | 特権 | Ubuntu 24.04 で | ブラウザーの中の囲い | ライセンス（確かめる） |
|---|---|---|---|---|---|
| **Landlock** | カーネルの仕組み。プロセスが、自分と子孫のファイルの読み書きを、自分で狭める。外せない。子に引き継がれる。囲いの外のプロセスには、デバッガーでつなげない（考え）。ABI 6 から、合図（シグナル）と抽象名前空間のソケットを、囲いの外へ出さないスコープがある。**名前の付いたソケットへのつなぎは、止めない（ホストで見た。上の「ホストで見たこと」）** | なし | 名前空間を使わないので、Ubuntu の、名前空間を止める決まり（AppArmor。試用版の Firefox で `unshare(CLONE_NEWPID): EPERM` が出た）に当たらない見込み。**ホスト（6.17）では有効で、版は 7（見た）。** Ubuntu 24.04 の標準のカーネル（6.8）は版が低く、スコープがない（見直しの 軽2。考え） | 重ねて使える見込み（Landlock は入れ子にできる。考え） | カーネルの公開の口を呼ぶだけ。Rust から使う部品（`landlock` クレート）は、MIT と Apache-2.0 の併記だと記憶している。入れるときに `cargo deny check licenses` で確かめる |

### 提案

**【提案】Landlock を第一の候補にする。** 理由：特権が要らない。Ubuntu の名前空間の決まりに当たらない見込み。子に引き継がれて外せないので、アプリが起動したものも囲いの中に残る。1 フレームごとの経路には入らない（ファイルを開くときに確かめるだけ）。

囲いの形（案）：

- 読み書きできる：そのアプリのフォルダー（設定、データ、キャッシュ、そのセッションのランタイムのフォルダー）。隔離領域の `files/` と `inbox/` は、持ち主がアプリごとに選ぶ。
- 読むだけ：システムのファイル（`/usr`、`/etc` の要る所、フォント、テーマ）。
- 読めない：端末の鍵とペアリングの一覧、ほかのアプリのフォルダー、口のフォルダー。作業の場所（下の「コーディングエージェント（herdr）」）は、持ち主が名指ししたアプリだけが読む。アプリの専用ユーザーのアプリは、書かない。書くのは、コーディングの専用ユーザーとして開いたエディターだけ（【決定】2026-11-19、持ち主。3 回目の答えの 11）。
- 囲いを付けるのは、エージェントが起動するときの、起動する側の務め（ADR 0009 の 6 の `setsid` と同じ所）。

**囲いの決まり（見直しの 軽2。【提案】）：**

- Landlock の版の下限を決める（スコープのある 6 以上）。【決定】2026-11-21（軽1）：版が足りなければ、起動を止め、囲えないと知らせる。囲いなしで動かすのは、持ち主が囲いのない段を選んだときだけ。 【提案】この段ではログインのあるプロファイルは使わせず、囲えないことを `istesso doctor` にも出す。
- `/dev` は、`renderD*` と `nvidia*` だけを開ける。`video` のグループには入れない。デバイスの ioctl の決まり（ABI 5）は ioctl ごとに効く。
- `/tmp` と `/dev/shm` は、同じユーザーのすべてで共有になる。アプリごとに、自分の一時のフォルダーを渡し（`TMPDIR`）、`/tmp` と `/dev/shm` は決まりに入れない。共有メモリーを使うアプリが動くかは【調べる】。
- アプリだけでなく、**ランナーも囲う**（ランナーは、ネットワークからの絵の頼みと入力を受ける）。

**Landlock だけでは塞げないもの**（名前の付いたソケットへのつなぎは、ホストで見たとおり止まらない。ほかは考え）と、その手：

| 塞げないもの | 起きうること | 手（【提案】） |
|---|---|---|
| ランナーの入力の口 | ほかのアプリへ、キーを打ち込む | 【決定】2026-11-21：計測の合図が `free` のときに速さを測ってから、**起動のときに渡すソケットの組（socketpair）にする**（見直しの 軽1）。名前を持たないので、ほかのプロセスは見つけられない。最初の版の案（`SO_PASSCRED` で送り主の番号を確かめる）より、口そのものがなくなるぶん強い。入力の経路が変わるので、前後で測る。ADR 0007 の「入力」（手元のソケットで渡す）に注記する |

### コーディングエージェント（herdr）

R-07 は、コーディングエージェントが読めるのを、隔離領域だけにすると決めている。アプリと同じユーザーに置くと、コーディングエージェントは、アプリの設定、写したプロファイル、端末の鍵に届く（脅威モデルの 5 章の攻7）。

**【決定】2026-11-19、持ち主：herdr とコーディングエージェントは、2 つめの専用ユーザーで動かす。** 理由：API の鍵と Git の資格情報を持ち、外から読んだ指示で動きうる。だから、OS のユーザーの境目で、アプリと分ける。その上に、Landlock を重ねる。M6 の後半（herdr を専用ユーザーで）は、これに合わせる（【決定】2026-11-18：M6 の後半は M5 の設計に合わせる）。

**【決定】2026-11-21、持ち主（ADR 0025 の決定 9。【問い 作3】の答え。言葉のまま）：** 「既定は、ユーザーを分けない（どの機械も、持ち主のユーザーのまま）。手元のアプリと同じ感覚で、どの端末からも続きができることを優先する。守りを強くしたい人のために、専用ユーザーに分ける設定を用意する。UX との引き換えとして、この方針にする。」「前の決め（ADR 0021 の決定 6：herdr とエージェントは専用ユーザー）は、既定から外して、選べる設定の側に移す。」「root の手順（専用ユーザー、root なしの docker）は、その設定を選んだ人のためのものとして残す。自分の機械では、いまは分けない。」

**【提案】この節の読み方（2026-11-21 のあと）：**

- **既定：** herdr、コーディングエージェント、そのビルドと試験は、持ち主のユーザーで動く。作業の場所は、持ち主のもの（ホームの下でよい）。守りは、プロジェクトごとの範囲の囲い（ADR 0026。Linux は Landlock と seccomp、Mac は Seatbelt）。**Ubuntu では、範囲は「うっかりを防ぐ柵」**で、Docker の口、ユーザーのサービス管理、名前の付いたソケット、範囲の外のほかのターミナルから抜けられる。このことを、文書と、初めて起動するときの問いの窓に、正直に書く（ADR 0026）。アプリのホストも、既定は持ち主のユーザー（上の「問い 1」の「持ち主の決め（2026-11-21）のあと」）。同じユーザーのほかのプログラムに対する既定の守りは、下の「段との関係」の 2026-11-21 の【提案】。
- **分ける設定：** この節のこれから下（コーディングの専用ユーザー、作業のグループ、作業の場所、だれが何を読み書きできるか、書けるエディターの案 A、GPU）は、分ける設定を選んだ機械の形として残す。決定 11 と 24（作業の場所では、ふだんのユーザーは書かない、Git もビルドも動かさない）も、その機械の決めである。導入の root の手順も、その設定を選んだ人のためのもの。
- **既定で残る道（はっきり書く）：** 上の「重2」の危うさ（コーディングエージェントが置いたものを、持ち主が Git やビルドで動かすと、持ち主として動く）は、既定では閉じない。決定 24 が避けようとした道で、持ち主の決め（UX との引き換え）で受け入れた。コーディングエージェントに渡す API の鍵と Git の資格情報を、狭いものにする決め（決定 15、中8 への答え）は、既定でも、そのまま当てる。
- アプリのホストも、既定は持ち主のユーザーで動く（ADR 0025 の【問い 作22】の答え。上の「問い 1」）。

#### 作業の場所

コーディングエージェントが、コードを置いて、読み書きする所。どちらのホームの中にも置かない（ホームを開けずに済むように）。

| もの | 中身 |
|---|---|

| 権限 | 2770（作業のグループの人だけが入れる。中に作るものは、グループを引き継ぐ）。既定の ACL で、中に作るファイルとフォルダーにも、作業のグループの読み書きを付ける（ユーザーごとの umask に頼らない） |
| アプリに読ませるとき | 【決定】2026-11-19、持ち主：**既定では、持ち主が名指ししたアプリだけが読める**（たとえば、コードを見るためのエディター）。ACL で、アプリの専用ユーザーに読むだけを与え、Landlock で、名指ししたアプリにだけ開く。ほかのアプリは、Landlock で読めない |

**書いてよいアプリを名指ししたときに、起きうること**（はっきり書く）：アプリは、ウェブの中身や開いたファイルで乗っ取られうる（攻1）。書けるアプリが乗っ取られると、作業の場所に、`.git/config`（`core.fsmonitor`、`core.pager` など、Git が動かす命令）、Git のフック、ビルドの手順（`build.rs`、`Makefile`）、CI の設定、エディターのタスクの設定を置ける。それらは、コーディングエージェントが Git やビルドを動かしたときに、**コーディングの専用ユーザーとして動き**、API の鍵と Git の資格情報（資12）に届く。持ち主がそこで Git やビルドを動かせば、**持ち主として動く**（下の重2。【決定】2026-11-19、持ち主：持ち主は、ふだんのユーザーからは書かない）。

**書けるエディターを、コーディングの専用ユーザーとして開く（分ける設定。2026-11-21、問い 16）：**

- いまの起動の道（アプリの専用ユーザーのエージェントが、自分のユーザーでアプリを起動する）では、別のユーザーとして起動できない（ユーザーを切り替える特権が要る。U3 の費用）。
- 【決定】2026-11-21（問い 16）：案 A。**コーディングの専用ユーザーにも、小さなホストの役（エージェントとランナー。linger で常駐）を置き、名指しされたエディターの起動だけを受ける。** 特権は要らない。端末から見ると、ホストの身元が 1 つ増える（一覧では 1 台にまとめる）。
- 案 B：herdr の中から、持ち主がエディターを起動し、そのエディターの窓を Istesso のランナーで出す。ランナーもコーディングの専用ユーザーで動かすので、結局 A と同じ部品が要る。
- 案 A では、エディターはコーディングの専用ユーザーとして動くので、**API の鍵と Git の資格情報（資12）と同じ袋に入る。** エディターが開いたファイルの中身で乗っ取られると、資12 に届く。だから、エディターにも Landlock を付け、名指ししたプロジェクトのフォルダーと、エディター自身の設定だけを開かせる（下の 1〜5）。
- 【決定】2026-11-21（問い 16）：**名指しのエディターを起動する係（案 A）でよい。ただし、コーディングの専用ユーザーにも GPU を許す**（rio は GPU で描く。コーディングエージェントが、GPU で学習を動かすこともある）。

**コーディングの専用ユーザーに GPU を許すと、何が増えるか**（ホストで見たこと、2026-11-19。下の「ホストで見たこと（機器の口）」）：

- **NVIDIA の口（`/dev/nvidia0`、`nvidiactl`、`nvidia-uvm`、`nvidia-modeset`）は、いまでも、だれでも開ける**（0666。見た）。CUDA と NVENC は、グループがなくても、どのユーザーからも使える。だから、GPU を許して増えるのは、主に、描画の口（`/dev/dri/renderD*`、`render` のグループ）である。
- 乗っ取られたコーディングエージェントから届きうるもの（考え）：
  - **ドライバーへの攻撃の面。** NVIDIA のカーネルのドライバーと、描画のドライバーの口が、そのまま攻撃の入口になる（範囲の外とした OS の不具合の一つだが、入口が増える）。
  - **ほかのユーザーの GPU のメモリーと、描画の中身。** ふつうはドライバーが分ける。分け方が不十分なら、ほかのアプリの絵（アプリの専用ユーザーのランナーの絵、机の画面）が読める恐れがある。
  - **GPU を使った横の道**（時間の測り方で、ほかのプロセスの動きを推す）。範囲の外としたもの。
  - **ほかの GPU の利用者の絵を取ること。** 画面の出力の口（`/dev/dri/card*`。`video` のグループと、机の人の権限）を開ければ、机の画面を読める恐れがある。描画の口（`renderD*`）からは、画面の出力は扱えない（考え）。
  - **計測している経路の妨げ。** エンコーダーの枠（PC 全体で 12。試用版の記録）と CUDA の時間を使い切ると、ランナーの絵の圧縮が遅れ、遅延が悪くなる。断られることもある。
- 小さく保つ形（【提案】）：
  1. 与えるのは `render` のグループだけ。**`video` のグループには入れない**（画面の出力の口を開けない）。
  2. Landlock の決まりで、`/dev` は `renderD*` と `nvidia*` だけ（`nvidia-caps` と `card*` は入れない）。
  3. GPU を使う重い仕事（学習）は、**計測の合図に従う**（`busy` で止める）。エージェントのツールのひな形に、その決まりを書く。
  4. NVENC は、コーディングの専用ユーザーでは使わない決まりにする（強制はできない。使ったかは、プロセスごとの `enc` で見る）。
  5. GPU の時間の取り合いは、OS の権限では分けられない。学習を動かすときは、持ち主が分かるように、`istesso doctor` と画面に出す。

**小さく保つ形（【決定】2026-11-21、問い 23。分ける設定の書けるエディターに当てる。下の 1〜5 の守り方を採る。実現のしかたは【提案】）：**

1. 書けるのは、持ち主が名指しした**プロジェクトのフォルダーだけ**（作業の場所の全体ではない）。Landlock の書く権利を、そのフォルダーにだけ付ける。
2. そのフォルダーの中でも、**`.git/` と、ビルドと CI の手順のファイル**（`build.rs`、`Makefile`、`Cargo.toml` の build の項、`.github/`、エディターのタスクの設定など）は、アプリに書かせない。Landlock は、決まりを親のフォルダーごとに付けるので、ファイルごとに外すことはできない（考え）。そこで、`.git/` は Landlock で書く権利から外し、手順のファイルは、名前の一覧で、エージェントが前後を見比べる（下の 3）。どこまで Landlock で止まるかは【調べる】。
3. **コーディングエージェントは、アプリが書いた設定から、フックと fsmonitor を動かさない。** コーディングの専用ユーザーの Git の設定で、フックの場所と `core.fsmonitor` と `core.pager` を、作業の場所の外の決まった値に固定する（リポジトリの `.git/config` より強い所で決める。効き方の順は【調べる】）。ビルドの手順のファイルが、前の確かめのあとに、コーディングエージェントのほかから変わっていたら、ビルドの前に止めて、持ち主に見せる。
4. 書けるアプリには、ログインのあるプロファイル（P1）を持たせない。乗っ取られる道（ウェブ）と、書く権利を、同じアプリに重ねないため。
5. 書けるアプリの名指しは、ホストにいる持ち主だけができる（遠くのランチャーからは選ばせない）。名指しは、一覧で見えて、いつでも外せる。

**持ち主が作業の場所に書くと、何が起きるか（見直しの 重2）：** 最初の版は、持ち主に読み書きを与えていた。逆向きの危うさがある。

- 乗っ取られたコーディングエージェントが、作業の場所に、**持ち主のユーザーで動くもの**を置ける：`.git/config`（`core.fsmonitor`、`core.pager` など、Git が動かす命令）、Git のフック、ビルドの手順（`build.rs`、`Makefile`）、エディターのタスクの設定。持ち主が、そこで `git status`、ビルド、エディターで開く、をすると、それが**持ち主として動く**。境目 E が、逆向きに破れる。

1. 持ち主は、作業の場所に**書かない**。コードを直すのも、Git を使うのも、ビルドするのも、herdr の中で、**コーディングの専用ユーザーとして**行う。

## 計測の合図

AGENTS.md の計測の合図は、2 台それぞれの、持ち主のホームの `~/.local/state/istesso/measuring` にある。U2 では、専用ユーザーのプロセス（ビルド、試験、アプリ）が、これを読めない。合図に従えなくなる。

- 【提案】合図を、だれでも読めて、計測のスクリプトだけが書ける場所に移す（たとえば、導入のときに root で作る、持ち主だけが書けるフォルダー）。または、持ち主の側の係が、専用ユーザーの口へ、合図の変化を渡す。
- AGENTS.md を変えることになるので、まとめ役が決める（持ち主への一覧に載せる）。U2 に移るまでは、いまのまま。
- 見直しの 軽3（【提案】）：
  - 試用版は、計測の合図が `busy` になると、持ち主のスクリプトがアプリを SIGSTOP で止める。ユーザーをまたぐと、持ち主のプロセスからは止められない。**専用ユーザーのエージェントが、自分で合図を読み、自分のセッションを止める**形にする。
  - 計測の合図は、持ち主（計測のスクリプト）が持つフォルダーに置き、ほかのユーザーには読むだけを許す。`stream-test-*`（止められない長い試験の合図）は、それを書くユーザーが持つ、別のフォルダーに置く（1 つのフォルダーにすると、だれでも計測の合図を書けてしまう）。
  - `/run` の下に置くと、再起動で、落ちて残った古い `busy` が消える（AGENTS.md の「1 時間を超えた busy は持ち主に聞く」が、再起動のあとは要らなくなる）。

| ランナーとアプリを、専用ユーザーで動かす（U2） | 入らない見込み。同じプロセス、同じ GPU、同じ通信路 | 確定の判定と同じ形（85 Hz、3440×1440、有線）で、移す前と後。差の中央値、95、99 パーセンタイル |
| 専用ユーザーのプロセスが、机のセッションの外にいること | CPU の取り分（ユーザーごとの区画の重み）、リアルタイムの優先度（音）が変わることがある（考え） | 上と同じ。机で重い仕事をしているときも 1 回 |

## 同じユーザーのほかのプログラムに対して、どこまで守るか（2026-11-19）

持ち主の問い（2026-11-19）：手元の口が「同じユーザー」で確かめていても、同じユーザーのほかのプログラムは止まらない。Istesso は、それをどこまで守るのか。この節は、最初の案（【提案】）を Fable が見て、持ち主が決めたことを入れた版である。

### 線を引く所

- 脅威モデルの 7 章のとおり、**ユーザーそのものが乗っ取られたとき**（そのユーザーで、何でも動かせるとき）は、範囲の外のまま。その Mac や PC の上のファイルとセッションには、Istesso がなくても届く。
- 【決定】2026-11-19、持ち主：**Istesso は、OS が同じユーザーのほかのプログラムに許していないことを、Istesso を通して許さない。** 同じユーザーのほかのプログラムが、Istesso の口や、Istesso が持つ物を使って、次のことをできない形にする。
  1. **OS の許可の門を越える**：Istesso のプログラムが持つ許可（macOS の画面収録、アクセシビリティ、入力監視）を、許可のないプログラムが借りる。Linux では、Wayland がクライアントどうしを分けていることと、Yama の ptrace の決まりを越えて、ほかのアプリにキーを入れる、そのキーや絵を読む。
  2. **ほかの PC に届く**：ペアリングの信頼を借りて、ほかの PC のアプリに入力を送る、その絵や文字を受け取る。
  3. **長く使える秘密を持ち出す、書き換える**：端末の鍵、**ペアの一覧**、署名の鍵。プログラムを消したあとも、ペアリングを解くまで効くもの。
- **ペアの一覧は、鍵と同じ守りの中に置く。** ペアの一覧は、だれが見てよいか、だれが操作してよいかを決める。そこに自分の端末を書き足せることは、鍵を盗まれるのと同じ重さである（自分の端末が、正しい端末として、絵を受け、入力を送れる）。読めないだけでなく、持ち主の確かめなしには書けないことまでを、守りとする（下の「製品で閉じる形」の 6 と 7）。
- 引き換え：同じユーザーの中で、ここまで守れるのは、OS の手が届く所まで。届かない所（同じユーザーのファイル、デバッガー、そのユーザーのセッションそのもの）は、下の段（U2、U5）で、ユーザーの境目に移して守る。

### いまの試用版（分かっている限り）

- **試用版は、この線を満たさない。** 試用版の手元の口（ソケット、パイプ、起動の引数、鍵とペアの一覧のファイル）は、ファイルの権限と、同じユーザーかどうかだけを頼りにしていて、同じユーザーのほかのプログラムは、そこから入力を入れ、口を差し替え、鍵を読み、ペアの一覧を書ける。上の 3 つのどれにも、届く道がある。
- 試用版は、持ち主の機械で、持ち主が入れたプログラムだけが動くことを前提にした、確かめのための版で、そのまま `main` に入れない。くわしい一覧は、公開しない所に置く（開いたままの穴を書いているため）。
- 【決定】2026-11-19、持ち主：**閉じる順番**（金曜の見直しのあとの、最初のセキュリティの作業）。
  1. 許可を持つプログラムが、行き先を外から受けないこと。鍵**と**ペアの一覧を守ること。
  2. 入力の口（受ける側と、渡す側の両方。差し替えられないこと）。
  3. ペアを足すとき、権限を与えるときの、持ち主がいることの確かめ。
- 閉じたかは、下の「確かめ」で見る。

### 製品で閉じる形（【提案】）

1. **名前のない口。** 同じ PC の中の口は、起動する側（ランチャー、エージェント）がソケットの組（socketpair）を作り、子のプロセスに、ファイル記述子として渡す（起動のときに受け継がせるか、あとから `SCM_RIGHTS` で渡す）。パスがなければ、ほかのプログラムは、つなぐことも、差し替えることもできない。ランナーの入力の口をソケットの組にする決め（見直しの 軽1）を、すべての口に広げる。Wayland の `WAYLAND_SOCKET` と同じ形。macOS には区切りを保つ接続の種類（`SOCK_SEQPACKET`）がないので、データグラムの組を使う（考え）。
2. **できるところは、1 つのプロセス。** 手元の窓と中継、Mac のホストの、取り込みと入力と通信を、1 つのプロセスにまとめ、手元の口そのものをなくす。許可を持つプロセスが、ネットワークから直に受ける。
3. **許可を持つプログラムは、外から何も受けない（macOS）。** 要は、**起動の引数、環境変数、同じユーザーが書けるファイルから、行き先と決まりを受けないこと。** 設定のフォルダー、ペアの一覧、口、ポート、計測の合図の場所は、プログラムの中で決める。ペアの一覧と鍵は、6 と 7 の守りの中から読む。
   - 「ほかの者に起動されたら終わる」を、**親のプロセスを見て決めることはしない。** `open` や launchd から起動されると、親は launchd で、だれが頼んだかは分からない。
   - だれが起動できるかを絞るのは、OS の仕組みで行う。【調べる】次の 2 つ。(a) 署名に入れる起動の決まり（launch constraints、environment constraints：自分、親、責任を持つプロセスについての条件）。どの版の macOS から、Developer ID の署名で使えるか。(b) launchd に登録した口（Mach のサービスか、`Sockets` の口。`SMAppService` で、署名したバンドルの中の決まりから登録する）。その口を launchd から受け取れなかったら、何もしないで終わる。限り（考え）：同じユーザーは、自分の LaunchAgent を登録して、同じプログラムを起動できる。だから (a)(b) は補いで、守りの本体は「外から何も受けない」ことである。
4. **macOS では、XPC と、コード署名の確かめ。** 分けなければならない口（許可を持つプロセスと、持たないプロセスのあいだ、入力方式とホストのあいだ）は、XPC にする。受ける側は、つないできた相手を、**プロセスの番号ではなく監査トークン（audit token）で**見分け、そこから `SecCode` を取り、決まった条件（`SecRequirement`：Apple の証明書の連なり、チーム、識別子）で確かめる（`xpc_connection_set_peer_code_signing_requirement`、`NSXPCConnection` の `setCodeSigningRequirement`）。条件には、hardened runtime であること、デバッグを許すエンタイトルメントがないこと、**決まった版より新しいこと**（条件の言葉の `info[CFBundleVersion] >= …`。署名に縛られた Info.plist の値。考え）も入れる。古い署名の版は、相手になれない。入力方式の試作は、この形を、XPC ではない口で先に作った。ただし、確かめの強さは、入り口のいちばん弱い所で決まる：**確かめを通るプログラムが、命令を標準入力や引数から受けるなら、確かめはそこで無くなる。** 確かめを通る識別子は、命令を外から受けないプログラムだけにする。
5. **Linux では、相手のユーザーと、プログラムの確かめ。そして、その限り。** 名前の付いた口が残るなら、`SO_PEERCRED`（ユーザーとプロセス）を見て、プロセスは `pidfd`（`SO_PEERPIDFD`、新しいカーネル）でつかみ、`/proc/<pid>/exe` が、決まった場所の、そのユーザーが書けない（root が入れた）プログラムかを見る。**限り**：同じユーザーは、そのプログラムを自分で起動して、環境変数（`LD_PRELOAD` など）や引数を変えられる。Yama の決まりでも、親は子にデバッガーでつなげる。プログラムのファイルをそのユーザーが書けるなら、確かめにならない。だから、Linux で同じユーザーの中を分けるのは、ここまでは速度を落とす段で、**守りの本体は、ユーザーの境目（U2）と、名前のない口（1）と、囲い（U5）**。（2026-11-21 のあと：既定の Linux には U2 も U5 もない。下の「段との関係」の【提案】と、上の「問い 1」の「持ち主の決め（2026-11-21）のあと」）
6. **鍵とペアの一覧は、ファイルから外す。** どちらのキーチェーンを使うかで、できることが違う（どちらも考え。【調べる】）。
   - **ログインのキーチェーンの「信頼するアプリ」の決まり**（古い形のキーチェーン）：項目ごとに、問いなしで読めるプログラムを、そのコード署名の条件で決める。ほかのプログラムが読もうとすると、持ち主に問いが出る。証明書で署名した版なら、版を上げても同じ条件で通る。自分で組み立てた ad hoc の版は、条件が中身の指紋になり、組み立て直すたびに問いが出る。
   - **アクセスのグループ**（データ保護のキーチェーン）：エンタイトルメント（`keychain-access-groups`）と、チームのプロビジョニングが要る。同じグループのアプリだけが読め、ほかのプログラムは、問いもなく読めない。自分で組み立てた版（チームのない署名、ad hoc）は、このグループを使えない見込みで、その版の守りは、ログインのキーチェーンの形か、ファイルに戻る。
   - 【提案】証明書で署名して配る版は、アクセスのグループ。自分で組み立てる版の扱いは、下の【問い 26】（配り方）で決める。
   - Linux は、専用ユーザー（U2）のホームに置き、持ち主のほかのプログラムからは OS の権限で届かなくする（2026-11-21 のあと：分ける設定の形。既定の形は、下の「鍵とペアの一覧の置き場所」の【決定】：OS の守る仕組みが使えるときは使い、ないときだけファイル）。U5 で、専用ユーザーの中のアプリからも読めなくする（いまの「既知の不足」の、端末の鍵の行）。Android は、アプリの中の場所のまま、Android のキーストアで包むことを考える。
   - **署名の鍵**（Mac のアプリと Android のアプリ）も、同じユーザーのプログラムが問いなしで使えない所に置く（ビルドの専用ユーザー、問いの出るキーチェーンの決まり、ハードウェアの鍵など）。署名の鍵を使えれば、上の 3 と 4 の確かめは通ってしまうため。
   - 鍵とペアの一覧の置き場所を変えるときは、先に ADR 0006 を更新する（AGENTS.md の 4）。
7. **ペアを足す、権限を与えるときは、持ち主がいることを確かめる。** 同じユーザーであること（`SO_PEERCRED`、SSH のログイン）だけで受けると、同じユーザーのプログラムが、自分の端末を足して、線の 2 と 3 を破れる。【提案】macOS：Touch ID かパスワードで確かめる（`kSecAccessControlUserPresence` を付けたキーチェーンの鍵で、ペアの一覧に署名し、読むときに署名を確かめる、など。考え。【調べる】Secure Enclave とエンタイトルメントの要り方）。Linux：polkit の、本人のパスワードを問う決まりなどを調べる（【調べる】）。
   - **いまの【決定】とぶつかる。** 持ち主の決め（問い 14、2026-11-19）は、「与えるのは、ホストにいる持ち主だけ（SSH でログインしているときを含む）」。SSH のログインだけでは、持ち主がいることを確かめられない（同じユーザーのプログラムも、同じログインを使える）。**M5 を決めるときに、この 2 つを一緒に見直す。**（2026-11-21 のあと：答えの表の 14 の注。「シェル」の許可をペアリングのときに選び、あとの切り替えは Air の設定で Touch ID 1 回。シェルを開くときは、既定では確かめない＝ADR 0025 の決定 10）
8. **古い版は、呼び戻せない。** 手元の古い写しを消すだけでは足りない。同じ識別子と同じ署名で配った版は、だれでも持ち込んで、同じ許可で動かせる。だから、
   - 【提案】受け入れ条件：**最初に署名して配る版から、この線を守る。** 守らない版を、製品の識別子と署名で配らない。
   - 試用版の識別子（`istesso-dev`）は、製品に使わない。
   - 試用版を終えるときに、試用のホストの許可を外す手順を書く（`tccutil reset ScreenCapture <試用のホストの識別子>`、`tccutil reset Accessibility <同じ>`、試用のバンドルと、その古い写しを片づける、入力方式の試作を外す）。【提案】いまのうちに、試用版の文書に手順を書いておく（行うのは、試用版を終えるとき）。
   - 古い版が持ち込まれても、4 の「決まった版より新しい」で、相手になれない。鍵とペアの一覧は、6 と 7 の守りで、古い版からも書けない（考え）。

| 段 | 同じユーザーのほかのプログラムから、届かなくなるもの |

- 計測の道具（プローブ、計測のアプリ、計測の台本）は製品ではない。手元の口を使い続けるが、計測は、持ち主の機械で、持ち主が入れたプログラムだけが動くときに行う、という前提を、計測の手順に書く。
- 【提案】（2026-11-21 のあと。ADR 0025 の【問い 作22】の答え：アプリのホストも、既定は持ち主のユーザー）**既定の Linux のホストには、U2 も U5 もない。** 既定では、コーディングエージェント（と、その子）も、この線で言う「同じユーザーのほかのプログラム」の 1 つである（範囲の囲いは、既定の Ubuntu では柵の強さ。ADR 0026）。 同じユーザーのほかのプログラムに対して届かなくなるものは、上の表の U1 の行（なし）に、1（名前のない口）と、鍵の守りの層（問い 27。別に設計している）が足されるだけである。上の 5 が「守りの本体」とした、ユーザーの境目と囲いは、分ける設定を選んだ機械にだけある。Studio と同じく、持ち主のユーザーのままで、上の 1、2、5〜8 が、既定の Linux の目標になる。このことを、文書と、導入の画面に正直に書く。

### 配り方を先に決める

署名の確かめ（4）とキーチェーン（6）は、**だれが署名するか**で形が変わる。公式に署名して配る版と、使う人が自分で組み立てる版では、確かめの条件も、使えるキーチェーンも違う。いまの試作の確かめは、ad hoc の署名を断る（自分で組み立てた版は、そのままでは通らない）。配り方は、問い 26 の答えのとおり。

**ガイドライン 4.2.7（Remote Desktop Clients）と、Istesso**

2026-11-19 に Apple のページで読んだ文。前書き：「If your remote desktop app acts as a mirror of specific software or services rather than a generic mirror of the host device, it must comply with the following:」。Istesso は、ホストの画面の全部ではなく、アプリを 1 つずつ映す（1 アプリ = 1 窓）。**だから、この項に当たる、と読むのが安全（THINK）。**

| 項 | 文（そのまま） | Istesso | 合うか |
|---|---|---|---|
| (a) 前半 | 「The app must only connect to a user-owned host device that is a personal computer or dedicated game console owned by the user,」 | つなぐのは、自分でペアリングした、自分の PC だけ | 合う |
| (a) 後半 | 「and both the host device and client must be connected on a local and LAN-based network.」 | いまは、家の LAN だけ。**「出先で実用」の段（家の外からつなぐ）は、この文と合わない。** VPN で家の LAN に入る形が「LAN」に当たるかは、分からない | いまは合う。あとの段は、**合わない** |
| (b) | 「Any software or services appearing in the client are fully executed on the host device, rendered on the screen of the host device, and may not use APIs or platform features beyond what is required to stream the Remote Desktop.」 | 動くのは、ホストの上。ただし、Linux のホストは、画面のないコンポジターに描く（ホストの画面には出ない）。クリップボード、手元の変換、あとのファイルと USB と音が、「映すのに要るもの」に入るかは、読み方しだい | 分からない |
| (c) | 「All account creation and management must be initiated from the host device.」 | アカウントはない。ペアリングは、ホストがコードを出す。権限を与えるのは、ホストにいる持ち主だけ（問い 14）。遠くから外すこと（問い 14）が「management」に当たるかは、分からない | おおむね合う |

  2. **審査のメモ**：ホストのソフトは、無料で、公開されている。審査の人が、自分の Mac に入れて試せる。入れ方と、ペアリングの手順を書く。

**手元のアプリの中で、ホストを買うことに、どこまで触れてよいか**

- DOC（3.1.1）：アプリの中の機能を開けるものは、アプリ内課金でなければならない。ライセンスの鍵も不可。**署名したホストは、別の機械で動く、別のソフト。手元のアプリの機能を開けるものではない（THINK）。** そう言えるためには、手元のアプリが、無料のホストと有料のホストで、同じに動かなければならない。方針の 1 と同じ向き。
- DOC（3.1.1(a)）：米国のストアのほかでは、「apps and their metadata may not include buttons, external links, or other calls to action that direct customers to purchasing mechanisms other than in-app purchase」。3.1.3：「Developers can send communications outside of the app to their user base about purchasing methods other than in-app purchase.」
- 例外は、どれも当たらない（THINK）。「Reader」（3.1.3(a)）は、雑誌、新聞、本、音、音楽、動画だけ。「Multiplatform Services」（3.1.3(b)）は、ほかで買ったものを使わせてよいが、「provided those items are also available as in-app purchases within the app」。「Free Stand-alone Apps」（3.1.3(f)）は、VoIP、クラウドの保存、メール、Web のホスティングだけ。
- 日本（DOC、Apple「Changes to iOS in Japan」。スマホソフトウェア競争促進法への対応、iOS 26.2 から）：日本の iOS のアプリは、買うための Web のページへのリンクを置ける。そのとき、Apple のアプリ内課金も、同時に並べなければならない。リンクから 7 日のうちの売り上げに、手数料がかかる（15%。小さな事業者の枠で 10%）。月ごとの報告が要る。**書いてあるのは iOS だけ。macOS と visionOS は、書いていない**（THINK：対象の外）。署名したホストが、この「digital goods and services」に入るかは、分からない。
- **安全な言い方（THINK）**：
  - 手元のアプリの中と、ストアの説明：「ホストのソフトは、無料で、公開されています。入れ方は <サイト>」まで。値段、「買う」、有料の版の名前、買うページへのリンクは、入れない。
  - 有料の版の案内は、サイト、README、メールで行う（3.1.3 が、アプリの外の知らせを認めている）。
  - 手元のアプリは、ホストが署名した版かどうかで、ふるまいを変えない。「有料の版にすると、これが使えます」と、手元のアプリに出さない。

**d. ライセンス：寛容なライセンスで「売る」とは**

- DOC（MIT の文）：「to use, copy, modify, merge, publish, distribute, sublicense, and/or sell copies」。DOC（Apache-2.0 の 2 条）：複製、配布、再許諾を許す。**だれでも、組み立ててよい。配ってよい。売ってもよい。自分の証明書で署名した版を、売ることもできる。** 止める手は、ない。
- **持ち主だけが持つもの**：署名の身元（チームと証明書）。Apple が与えたエンタイトルメント（チームごと。ほかの人は、自分で申し込む）。名前と商標。更新の届け先（サイトとドメイン）。
- **だから、売るのは、コードではない。** 売るのは、持ち主の署名（公証、警告なし、作り直しても外れない許可）、Apple の許しによる便利さ、更新、問い合わせ先である。README に、そう書く（方針の 2）。
- 買った版を、買った人がほかの人に配ることも、同じライセンスのままなら、止められない（THINK）。バイナリーだけ、別の決まり（配り直さない）にすることは、著作権を持つ持ち主には、できる。依存の部品の表示は、そのまま要る。採るかは、決めていない。
- **外からの貢献**：何もしなければ、入るものは、出るものと同じ条件になる（DOC：Apache-2.0 の 5 条。GitHub の利用規約 D.6）。`MIT OR Apache-2.0` で受けた貢献は、売る版にも、そのまま入れられる。**この案のために、CLA は要らない。** CLA（著作権の許しを広く受ける約束）が要るのは、持ち主が、ソースのライセンスそのものを、いまの条件で許されない形に変えたいときだけ。DCO（`Signed-off-by`。「出す権利がある」と述べるだけ。権利は渡さない）は、軽い。
  - 【提案】CLA は置かない。DCO を置くかは、外からの貢献が来る前に決める。置くなら、CONTRIBUTING に 1 行。
- **商標**：Apache-2.0 の 6 条は、名前と商標の許しを与えない（「reasonable and customary use in describing the origin of the Work」だけ）。MIT には、商標の文がない。名前を守れるのは、商標法による（登録か、広く知られていること。THINK）。
  - 【提案】分かれた版（フォーク）は、「Istesso を元にした」と書いてよい。同じ名前、同じアイコンで配らない。公式の版と名乗らない。これを、短い文（商標の方針）として、リポジトリに置く。
  - 商標の調べ（先に登録されていないか）は、ここではしていない（名前を、外のサービスに送らないため）。登録すると、出した人の名前と住所が公報に出る見込み（THINK）。c と同じ問いになる（【調べる】調18）。

### 鍵とペアの一覧の置き場所（閉じる順番の 1。設計の下書き、2026-11-19）

【提案】ここは下書きで、何も作っていない。上の 6 を、選べる形に分けた。どれも考え（キーチェーンの動きは、機械の上で試していない。試すとキーチェーンに項目が増え、持ち主の画面に問いが出うるので、試す前に持ち主に聞く）。

- **先に済んだこと（閉じる順番の 1 の前半）**：場所を外から受けないこと。ブランチ `sec-s3-fixed-destinations`（`main` から。まだ `main` には入っていない）で、`istesso` と `istesso-media` は、設定のフォルダー、ペアの一覧、入力の口を、アカウント（ユーザーのデータベースのホーム、ユーザーの番号）から決め、環境変数と引数からは決めない。動かす場所を変えられるのは、開発用のビルド（`dev-paths`）だけ。**これだけでは、鍵とペアの一覧は守れない**：決まった場所のファイルは、同じユーザーのどのプログラムも読み書きできる。下の置き場所が、その後半。
- 試用版の鍵とペアの一覧は、試用版を終えるまで、ファイルのまま（試用版は変えない）。

**守るもの**：(1) 端末の鍵を、同じユーザーのほかのプログラムが読めないこと。(2) ペアの一覧を、同じユーザーのほかのプログラムが書き換えられないこと（足す、権限を上げる、古い一覧に戻す）。(2) は、(1) と同じだけ重い。一覧に自分の端末を足せれば、鍵を読まなくても、ホストの絵と入力に届く。

- 形ごとに何から守れて、何から守れないかの表と、作り（ブランチ `sec-same-user-1121`）は、ADR 0006 の「鍵とペアの一覧の置き場所」。鍵の守りの 4 つの層（同じ日の持ち主の決め）は、別の設計。

## 既知の不足

- ホストで見たのは、「ホストで見たこと」の 3 つの節（Landlock、snap の囲い、機器の口）だけ。ほか（snap とホームの場所、ユーザーの区画の CPU の重み、音の優先度、名前空間の決まり）は、まだ考え。
- **特許を調べていない**（上の「ライセンスと特許」）。
- 配り方と売り方の調べ（問い 26）は、文書を読んだだけ。Apple にも Google にも、申し込んでいない、聞いていない。法律の所は、専門家に確かめていない。料率と決まりは、変わりうる。
- Mac のホストのアプリごとの囲いは、ない。Mac には Landlock がなく、他社のアプリに囲いを付ける公開の方法も見当たらない（`sandbox-exec` は古い形で、試験にだけ使う。m5-plan.md の 7.）。Mac mini では、ホスト専用の Mac を専用ユーザーで使うこと（ADR 0014）が、守りのすべてになる。Mac Studio では、分けるものがなく、「操作」の権限の重さだけで守る（上の「Mac のホスト：Mac Studio と Mac mini」）。
- 設定の係が渡すのは、GNOME の机の値だけ。ほかの机（KDE など）は、扱っていない。
- P1 では、持ち主が、専用ユーザーのアプリの中で、ふだんのアカウントにログインし直す手間がある。
- U2 から U5 のあいだ、端末の鍵は、アプリから読める（ADR 0014 の「鍵に手が届くことへの備え」のまま）。
- 試用版は、同じユーザーのほかのプログラムに対する線（上の「同じユーザーのほかのプログラムに対して、どこまで守るか」）を満たさない。製品の形（名前のない口、外から何も受けない許可のプログラム、XPC と署名の確かめ、キーチェーン、ペアを足すときの持ち主の確かめ）は、まだ何も作っていない。閉じる順番は【決定】（2026-11-19、持ち主）。
- ホストにいる人の口に、持ち主のユーザーからつなげるようにすると、持ち主のユーザーで動く悪いプログラム（範囲の外）が、セッションを止められる。持ち主のユーザーは信頼する、という前提である。
- API の鍵と Git の資格情報は、コーディングエージェント自身からは届く（上の「コーディングエージェント（herdr）」）。
- 2 つのエージェント（持ち主の側と、アプリの専用ユーザー）の既定のポートが、どちらも 47801（見直しの 軽5。ADR 0014 の「既知の不足」にもある）。実装の前に決める。
- Landlock の試しは、ファイルの決まりと、抽象名前空間のスコープだけを見た（上の「ホストで見たこと」）。ネットワークの決まり、ioctl の決まり、合図のスコープは、まだ見ていない。
- snap の囲いの確かめは、AppArmor の決まりだけを当てたもので、snap の実際の起動（マウントの名前空間、seccomp）では見ていない。
- 遠くから外せるようにすると、なくした端末が、ほかの端末の権限を外せる（迷惑。乗っ取りではない）。上の抑え方で、数と戻し方を限る。
