## 背景

2 つの決まりが、ぶつかる。

- **隔離**（R-07、ADR 0003。【決定】2026-11-15）：アプリとエージェントを、専用ユーザーで動かす。ふだんのユーザーのホームは、ほかのユーザーから読めない。
- **机と同じ設定**（R-04。【決定】2026-11-18、持ち主）：ホストで開くアプリは、持ち主の机のログインと同じ設定（言語、入力方式、見た目、フォント、フォントの大きさ）で開く。エージェントは、机のセッションか、持ち主のアカウントの設定から受け取る。ふだんのプロファイル（ブラウザーのログイン、Blender の設定）を使うかどうかは、アプリごとに持ち主が選ぶ。試用のあいだは、試験用のプロファイルのまま。Istesso は、持ち主のふだんの設定を変えない。読むだけ。

専用ユーザーは、持ち主のホームを読めない。だから、何もしなければ、アプリは英語の、既定の見た目で開き、ふだんのプロファイルも使えない（ADR 0014 の「既知の不足」：Istesso から開いたアプリは、まっさらな状態で始まる）。

|---|---|

## 問い 1：アプリを、どのユーザーで動かすか

### 案

- **U1：持ち主のユーザー。** いまの試用版。
- **U2：専用ユーザー 1 つ。** ADR 0014 の A。ホストの役を丸ごと。
- **U3：アプリごとに、専用ユーザー。** 導入のときに、ユーザーを何人ぶんか作っておく形も含む。
- **U4：エージェントは持ち主、アプリだけ専用ユーザー。** ADR 0014 の B。
- **U5：U2 に、アプリごとの囲いを足す。** 専用ユーザーの中で、アプリごとに、読めるファイルを狭める（下の「アプリごとの囲い」）。
- **U6：コンテナーか仮想機械**（systemd-nspawn、podman、仮想機械）。

### 比べ

「8b の手間」は、机と同じ設定（R-04）を届けるための手間。遅延は、すべて考えで、測っていない。

### 提案

**【提案】U2 を土台にし（ADR 0014 の A を採用する）、そのあとで U5 に進む。** U3、U4、U6 は採らない。

**【決定】2026-11-19、持ち主：Linux のホストは、この提案のとおり（U2 から、そのあと U5）。** herdr とコーディングエージェントは、2 つめの専用ユーザー（下の「コーディングエージェント（herdr）」）。Mac のホストは、下の「Mac のホスト：Mac Studio と Mac mini」。

理由：

1. **持ち主のもの（資1〜資3、資10）を守ることが、いちばん重い**（脅威モデルの 2 章）。これは U2 で、OS の権限で守れる。動いているあいだの特権も要らない。
2. **アプリとアプリのあいだと、端末の鍵**は、U2 では守れない（脅威モデルの 6.2）。U3 なら OS の権限で守れるが、起動のたびに特権が要るか、ユーザーの数だけエージェントが要る。U5 は、特権なしで、ファイルについては同じところまで狭められる見込み。
3. **ふだんのプロファイル（ログインを含むもの）を置けるのは、U5 になってから**にする（下の「ふだんのプロファイル」）。U2 のままだと、写したアカウントが、同じ袋のすべてから届く。
4. 遅延：U2 と U5 は、1 フレームごとの経路を変えない見込み。それでも、映像、入力、音の経路を動かし直すので、前後で測る（AGENTS.md）。測るのは、M1 の確定の判定のあと（m5-plan.md の手順 6 のまま）。

U3 に移るとき：U5 の囲いが、ホストの OS で使えないと分かったとき（下の「確かめること」）。または、アプリとアプリのあいだを、OS の権限で分けることが要ると、持ち主が決めたとき。

## 画面のあるアプリを専用ユーザーで動かすと、何が変わるか

持ち主から、早めに調べるよう頼まれたこと（2026-11-18）。アプリの絵は、いまも、アプリごとの隠れたコンポジターから、暗号化した通信路で手元の Mac へ届いている。その中で、アプリのユーザーが、ほかのプロセス（エージェント、机）のユーザーと違うとき、何が変わるかを並べる。

列の意味：U1（いま）、U2（専用 1 つ。ランナーもアプリも同じ専用ユーザー）、U3（アプリごと。ランナーをアプリと同じユーザーで動かす）、U4（エージェントとランナーは持ち主、アプリは専用ユーザー）。

| もの | U1 | U2 | U3 | U4 |
|---|---|---|---|---|
| **Wayland のソケット** | ランナーが自分のランタイムディレクトリに作る。アプリは同じユーザーなので、つなげる | 同じ（ランナーもアプリも専用ユーザー）。持ち主のプロセスからは、つなげない | 同じ（ユーザーごと） | **つなげない。** 持ち主のランタイムディレクトリ（`/run/user/<番号>`、0700）に、ほかのユーザーは入れない。細工が要る：ソケットを両方が入れる場所に置いてグループで許す（導入に root）か、つないだソケットの番号を渡して起動する（libwayland の `WAYLAND_SOCKET`）。後者は、起動を持ち主のプロセスからするので、ユーザーを切り替える特権が要る |

| **端末の身元とペアリング** | 持ち主の鍵 1 つ | 専用ユーザーの鍵。**1 台の PC が、端末 2 つに見える**（持ち主の側：クライアントの役。専用ユーザー：ホストの役。ADR 0014 の 3）。手元の Mac は、ホストの役の身元とペアリングする | アプリごとに身元が要るか、1 つの係にまとめる | 持ち主の鍵 1 つ |

### 手元の Mac から見て、変わること

U2 では、**絵と入力の経路は変わらない。** 絵は、専用ユーザーのランナーから、同じ通信路（ADR 0015）で届く。変わるのは、次の 3 つだけ。

1. 手元の Mac がつなぐ相手は、ホストの**専用ユーザーの身元**。ペアリングは、その身元と行う。持ち主の側の身元は、クライアントの役（ホストの机で、ほかの PC のアプリを見る）だけを持つ。
2. 一覧には、1 台の PC が 2 つの身元で出る。【提案】役割表に「同じ PC」の印（例：PC ごとに 1 つの識別子）を足し、一覧では 1 台にまとめて見せる。印は、ハンドシェイクで確かめた身元どうしの申告なので、信頼の根拠にはしない（見せ方だけに使う）。
3. ペアリングの始め方：ホストの役の身元のペアリングは、専用ユーザーのエージェントが受ける。持ち主は、ホストにいる人の口から、「ペアリングを待つ」を頼む（コードは、持ち主の画面に出す。ログには出さない）。形は、実装の前に決める。

Mac のホスト（M4）は、2 つの形がある（下の「Mac のホスト：Mac Studio と Mac mini」）。Mac mini（ホスト専用）は、専用ユーザーでログインする（ADR 0014）。アプリも、取り込み、入力の注入（ADR 0017 の許可）も、そのログインのセッションの中で動く。手元の Mac から見て、変わることは U2 と同じ。Mac Studio（持ち主のふだんの Mac で、判定のホスト）は、持ち主のユーザーで動く。

## Mac のホスト：Mac Studio と Mac mini

これまでの文書（ADR 0014、脅威モデルの最初の版）は、Mac のホストを、ホスト専用の Mac としてだけ扱っていた。持ち主の答え（2026-11-19）で、形が 2 つになった。

| | Mac mini | Mac Studio |
|---|---|---|
| 役 | ほかの人のホストの代表。ホスト専用 | 持ち主がふだん使う Mac。**有線の判定の Mac のホストでもある**（【決定】2026-11-19、持ち主） |
| ホストの役のユーザー | 専用ユーザー（【決定】2026-11-19、持ち主：ADR 0014 のとおり） | **持ち主のユーザー。** GUI のセッションは 1 つで、そこに座るのは持ち主である。アプリは、ログインしているセッションの中でしか動かない（m4-plan.md の 4.2） |
| 「操作」で届く範囲 | 専用ユーザーの中まで | **持ち主のアカウントの全部**（脅威モデルの 6.1、6.6）。ふだんのブラウザー、鍵束、ファイル |
| 「操作」の扱い | ほかのホストと同じ | 【決定】2026-11-19、持ち主：**「ふだんのプロファイル」と同じ重さで扱う。AURA には既定で与えない** |
| 机と同じ設定（R-04） | 導入のときに、手元の端末の言語と字の大きさを写す（問い 5 の答え） | 持ち主のセッションそのものなので、何もしなくても同じ |
| 囲い | Mac には Landlock がない。専用ユーザーで分けることが、守りのすべて | 分けるものがない。権限の重さで守る |

**Studio での「操作」の扱い方（【提案】）：**

1. Studio のエージェントは、役割表に「このホストのアプリは、持ち主のユーザーで動く」の印を出す。手元の端末とランチャーは、Studio の窓に、そのことを出す。
2. **Studio では、新しくペアリングした端末に「操作」を与えない。** 「閲覧」だけにする（ADR 0006 の初めの権限は、「閲覧」と「操作」。Studio だけ、この例外にする）。持ち主が、端末ごとに与える。【決定】2026-11-19、持ち主。
3. **AURA には、既定で与えない。** 要るときだけ与え、済んだら外す（「ふだんのプロファイル」と同じ。【決定】2026-11-19）。外すのは、ほかの権限と同じく、すぐ効く（ADR 0010）。
4. 権限を与える画面には、「Studio で操作を与えると、その端末は、あなたのユーザーとして何でもできます」と書く（脅威モデルの守10）。
5. 判定の計測は、いまの形（持ち主のユーザー）で行う。この扱いは、計測の経路を変えない。

**見直しで分かったこと（M5）：**

- Studio のエージェントは、ネットワークに向いていて、画面収録とアクセシビリティの許可を持ち、持ち主のユーザーで動く。**乗っ取られると、持ち主のすべてに届く**（脅威モデルの 5 章の Studio の列）。
- これは、ADR 0014 の 2（ふだんのユーザーで動くエージェントは、起動も入力も受け付けない）と、受け入れ条件 I4（ふだんのユーザーで動くエージェントは、アプリの起動を断る）とぶつかる。Studio は、その例外になる。
- 【提案】**例外は、PC ごとに、持ち主が選んだときだけにする。** 持ち主が、その Mac で「この Mac を、持ち主のユーザーのホストにする」と選ぶ（ホストにいる人の口から。遠くの端末からは選ばせない）。選んでいない Mac のエージェントは、I4 のとおり、起動を断る。
- 【決定】2026-11-19、持ち主：**Mac のホストでは、新しくペアリングした端末と、ペアリングし直した端末は「閲覧」だけ。**（最初の【提案】は「ホスト専用の印がないかぎり」だった。持ち主の答えは、Mac のホストすべて） ペアリングし直したとき（ADR 0006：権限は初めの「閲覧」と「操作」に戻る）も、同じにする。上の 2 を、Studio だけでなく、ホスト専用の印のない Mac すべてに広げる形である。
- 【調べる】Studio の上のコーディングエージェント（M6）：下の「コーディングエージェント（herdr）」の「Mac の上」。

## 設定の渡し方（言語、入力方式、見た目、字、字の大きさ）

### 案

- **S1：専用ユーザーのエージェントが、持ち主の設定を直接読む。** 持ち主のホームを、専用ユーザーに読ませる（ACL、グループ）ことになる。
- **S2：持ち主の側の小さな係が、決めた値だけを読み、専用ユーザーへ渡す。** 係は、机のログインで動く。
- **S3：手元の端末（いま使っている Mac）から、言語などを渡す。**
- **S4：導入のときに 1 回だけ写す。**

| 観点 | S1 直接読む | S2 持ち主の側から渡す | S3 手元の端末から | S4 1 回だけ写す |
|---|---|---|---|---|
| 隔離 | 崩れる。持ち主のホームの権限を変える（ふだんの側を変えない決まりに反する） | 保つ。渡るのは、決めた値の一覧だけ | 保つ | 保つ |
| 机と同じか | 同じ | 同じ（机にログインしているあいだ） | 机とは違う。Mac の言語は渡せるが、見た目（テーマ、フォント）は OS が違う | 写したときの値のまま |
| 机にだれもいないとき | 読める | 最後に受け取った値を使う（専用ユーザーの中に残す） | 渡せる | 同じ |
| 持ち主の側に増えるもの | なし | 小さな係 1 つ。**頼みを受けない。待ち受けない** | なし | なし |
| 特権 | 持ち主のファイルの権限を変える | なし（下の「渡す道」） | なし | 導入のとき |

### 提案

**【提案】S2。机にだれもログインしていないときは、最後に受け取った値で開き、そのことを `istesso doctor` と画面に出す。** 【決定】2026-11-19、持ち主：提案のとおり（下の 6 の Mac のホストも）。

1. **係**：持ち主の机のログインで動く、小さなプログラム（ユーザーのサービス。机にログインしたときに起動する）。持ち主の設定を**読むだけ**。値が変わったら（たとえば字の大きさを変えた）、また渡す。
2. **渡すもの（一覧で決める。ほかは渡さない）**：
   - 言語：机のユーザーのサービスの環境（試用版と同じく `systemctl --user show-environment`）の `LANG`、`LANGUAGE`、`LC_*`。`XDG_CURRENT_DESKTOP`。
   - 見た目：テーマ、アイコン、カーソルとその大きさ、字（ふつう、文書、等幅）、字の大きさの倍率、濃淡（明るい、暗い）、窓のボタンの並び。GNOME の設定の、名前を決めた鍵だけ（試用版が読んでいるものと同じ）。
   - 入力方式：使っている入力ソースの一覧（どの変換を使うか）とキーボードの配列。**学習と辞書は渡さない**（ADR 0020 の【決定】：学習はホストの専用のフォルダー。机のログインの学習には触れない）。
   - 渡さないもの：鍵束、オンラインアカウント、最近使ったファイル、検索の履歴、壁紙、そのほか一覧にないもの。
3. **渡す道**（見直しの M7 で直した。【提案】）：最初の版は、係がエージェントの口につなぐ形だった。それだと、係が、アプリの側（専用ユーザー）からの返事を読むことになり、向きが逆の道ができる。**係は、導入のときに root で作る、受け渡しのフォルダーに、値のファイルを書くだけにする。** フォルダーは、持ち主だけが書けて、アプリの専用ユーザーが読める（持ち主は持ち主のユーザー、グループは口のグループ、2750 のような形）。係は、アプリの側から何も読まない。待ち受けない（脅威モデルの守3）。エージェントは、ファイルが変わったら読み直す。書きかけを読まないように、係は別の名前で書き終えてから名前を替える。
4. **受け取る側**：値を検査する（長さ、文字の種類、知っている鍵だけ）。アプリごとの設定ファイル（試用版と同じ `keyfile` の形）と、アプリの環境に入れる。起動のたびに入れ直す。アプリが自分で変えた設定は、そのアプリのフォルダーにだけ残る。
5. **持ち主の設定は変えない。** 書き戻しはしない。
7. **フォントとテーマ**（見直しの L6。【提案】）：持ち主が自分のホームに入れたフォントとテーマ（`~/.local/share/fonts` など）は、専用ユーザーから読めない。名前だけ渡しても、アプリには届かない（I6 が通らない）。システムに入っているもの（`/usr/share` の下）は届く。持ち主のホームのものは、持ち主が名指ししたものだけを、受け渡しのフォルダーへ写す（フォントのライセンスは、持ち主の判断）。
6. Mac mini（ホスト専用）には、持ち主の机のログインがない。【決定】2026-11-19、持ち主：導入のときに、手元の端末の言語と字の大きさを写し、あとは持ち主が変える。Mac Studio は、持ち主のセッションそのものなので、渡すものはない。

### ホストの中の口

専用ユーザーのエージェントは、同じ PC の中の口を 1 つ持つ（いまの、ホストにいる人の口。ADR 0010 の 13）。U2 では、ここに、持ち主のユーザーからもつなぐ。

【決定】2026-11-19、持ち主：**グループつきのフォルダーを、導入のときに root で作る。** 導入はどのみち root を使う。ファイルの権限のほうが確かめやすく、Landlock とも合う。最初の版の案（抽象名前空間のソケット）は、取り下げた。

形（【提案】。名前は、実装のときに決める。下の「ユーザーとグループ」と合わせる）：

| もの | 持ち主 | グループ | 権限 | 中身 |
|---|---|---|---|---|
| 口のフォルダー（例：`/run/istesso`） | **root**（見直しの M7。アプリの専用ユーザーが持つと、どのアプリも、フォルダーの権限を変えられる） | 口のグループ（例：`istesso-local`。持ち主とアプリの専用ユーザーが入る） | 1770 か 0770（グループの人だけが入れる。中のものは、作った人しか消せない） | エージェントの口のソケット 1 つ |
| 口のソケット | アプリの専用ユーザー（エージェントが作る） | 口のグループ | 0660 | — |
| 受け渡しのフォルダー（例：`/run/istesso/desk`。設定の係が書く） | 持ち主 | 口のグループ | 2750（持ち主だけが書け、グループが読める） | 設定の値のファイル、名指しの写し |

- `/run` は起動のたびに空になるので、フォルダーは、導入のときに置く systemd の決まり（tmpfiles）で、起動のたびに作る（root の仕事は、導入の 1 回だけ。考え）。
- **ファイルの権限に加えて、エージェントは、つないできた相手のユーザーを確かめる**（`SO_PEERCRED`）。持ち主のユーザーからの頼みだけを受ける。アプリの専用ユーザーのプロセス（つまり、アプリ）からのつなぎは、断る（グループに入っていても、アプリから口を使わせないため。脅威モデルの 6.2）。持ち主の側のコマンドは、相手がアプリの専用ユーザーのときだけ話す。
- 「持ち主のユーザー」がだれかは、つないできた相手の申告では決めない。【提案】口のグループの記録（`/etc/group`）で、アプリの専用ユーザーのほかに入っているユーザーを、持ち主とする（見直しの M7）。1 人でないときは、閉じる側に倒す（だれも持ち主として扱わない）。
- グループに入れたことが効くのは、持ち主がログインし直したあとである（見直しの M7）。導入の最後に、そのことを伝える。
- **権限の管理を、この口に足す**（見直しの M2。【提案】）。いまは、`istesso peers allow`、`deny`、`remove` が、ペアリングの一覧のファイルを直接書く。専用ユーザーで動かすと、一覧は専用ユーザーのホームにあり、持ち主からは書けない。そこで、口に、権限を与える、外す、ペアリングを消す、の 3 つを足し、**持ち主のユーザーからだけ**受ける。いまの口の作り（同じユーザーの 0700 のフォルダーを前提にしている）は、この形に合わせて直す。**ADR 0006 の「権限」の節を、先に更新する**（AGENTS.md の 4）。【決定】2026-11-19、持ち主：**与えるのは、ホストにいる持ち主だけ**（SSH でホストにログインしているときを含む。どちらも、持ち主のユーザーとして、この口を使う）。**外すのは、持ち主のどの端末からでもできる**（制御チャンネルの新しい頼み。下）。
- **引き換えになること**（はっきり書く）：外すのを遠くからできるようにすると、**なくした端末、盗まれた端末も、ほかの端末の権限を外せる。** 乗っ取りにはならない（与えることはできない）が、持ち主の端末が使えなくなる迷惑になる。
- 【決定】2026-11-19、持ち主：**この引き換えを受け入れる。** 外された端末は、ホストにいる持ち主（SSH でログインしているときを含む）が元に戻せる。**記録には、どの端末が、いつ、どの端末を外したかを残す。** 記録に、鍵もコードも入れない（AGENTS.md の 4）。
- 【提案】抑え方（上の決定に合わせた形。2、3、5 は決定と同じ向き）：
  1. 遠くから外す頼みを送れるのは、新しい権限「取り消し」を持つ端末だけ。持ち主の端末に与える（与えるのは、ホストにいる持ち主）。【持ち主の考え】2026-11-19：**新しい権限は作らない。** 抑えるのは、下の 4 の数の上限だけ。
  2. 遠くから外せるのは、**権限を外すことと、ペアリングを止めることだけ**で、記録は残す（`deny` に当たる。`remove` は、ホストにいる持ち主だけ）。だから、ホストにいる持ち主が、1 つのコマンドで元に戻せる（ペアリングのやり直しは要らない）。
  3. 外したことは、全部の持ち主の端末とホストの一覧に、どの端末が外したかと一緒に出す。
  4. 1 台の端末が外せるのは、短い時間に数台まで。超えたら、その端末から外す頼みを止めて、ホストにいる持ち主に知らせる。【持ち主の考え】2026-11-19：**この上限だけで抑える。外したら、持ち主のほかの端末に知らせる。どの端末も、自分自身は、いつでも外せる**（上限に数えない）。
  5. 外された端末は、外す頼みを送れない（外された時点で、ハンドシェイクで断られる）。
  6. 制御チャンネルに頼みを足すので、先に ADR 0007（メッセージ）と ADR 0006（権限）を更新する（AGENTS.md の 4）。ペアリングと権限に触るので、`main` に入れる前の見直しは、流れの決まり 19 のとおり。
- ペアリングのコードは、「ペアリングを待つ」の答えとして、この口を通る。ログに出さない。ほかのユーザーに見えない（ソケットは口のグループだけ）。
- コーディングエージェントの専用ユーザーは、口のグループに入れない（下の「ユーザーとグループ」）。M6 で、コーディングエージェントから頼むこと（`istesso run` など）が要ると分かったら、そのときに、受ける頼みを絞って足す。
- Landlock：アプリの囲いの決まりに、口のフォルダーを入れない。
- 受ける頼みは、持ち主のユーザーから：セッションの一覧、止める、ペアリングを待つ、権限を与える・外す・ペアリングを消す。設定は、この口ではなく、受け渡しのフォルダーで渡す（上の「設定の渡し方」の 3）。
- この口は、制御チャンネル（`istesso-link`）の手順を変えない。ADR 0007 の更新は要らない。

## ふだんのプロファイル

### 案

- **P1：アプリ自身のログインと同期を、専用ユーザーの中のプロファイルで使う。** 例：専用ユーザーの Firefox で、持ち主が Firefox のアカウントにログインして同期する。Istesso は、持ち主のプロファイルに触れない。
- **P2：持ち主のプロファイルを写す。** 試用版の Blender の形（1 回だけ写す。写し直すのは、持ち主が頼んだとき）。写すのは、持ち主の側の係（読むだけ）。
- **P3：そのアプリだけ、持ち主のユーザーで動かす。**
- **P4：持ち主のプロファイルを、専用ユーザーに読み書きさせる**（ACL、グループ）。

| 観点 | P1 アプリ自身のログイン | P2 写す | P3 持ち主で動かす | P4 読み書きさせる |
|---|---|---|---|---|
| 渡るもの | 持ち主がログインして選んだものだけ | プロファイルの全部（ブラウザーなら、クッキーと保存したパスワード） | なし（持ち主のもの、そのまま） | なし（持ち主のもの、そのまま） |
| 隔離 | 保つ。アカウントは専用ユーザーの袋に入る（脅威モデルの 6.3） | 保つ。アカウントは袋に入る | **そのアプリについて崩れる。** 「操作」を持つ端末が、持ち主として動ける。持ち主の側に、起動を受け付けるエージェントが要る（ADR 0014 が塞いだ穴が、また開く） | 崩れる。持ち主のファイルの権限を変える |
| 机のアプリと同時に使う | できる（別のプロファイル） | できる（写し） | **できないことがある。** Firefox は、同じプロファイルを 2 つで開かない（考え）。机の Firefox が動いていると、リモートの起動が机に窓を開くことがある（試用版が `--no-remote` を付けている理由） | 壊れる恐れ（同時に書く） |
| 鍵束に頼るもの | アプリ自身の保管（試用版の Chrome は `--password-store=basic`） | **写しても使えないことがある。** Linux の Chrome は、保存したパスワードとクッキーを、机の鍵束の鍵で暗号化している（考え）。鍵束のない所に写すと、ログインが消える | 机の鍵束を使える（机にログインしていて、鍵束が開いているとき） | P3 と同じ問題 |
| 変えた設定の行き先 | 専用ユーザーの中（同期すれば、持ち主のほかのブラウザーにも） | 写しの中だけ。持ち主のものには戻さない | 持ち主のもの | 持ち主のもの |
| 持ち主のふだんの設定を変えない決まり | 守る | 守る（読むだけ） | **アプリが、持ち主の設定を変える**（Istesso が変えるのではないが、Istesso が開いたアプリが変える） | 反する |

### 提案

**【決定】2026-11-19、持ち主：下の 1〜6 のとおり**（1 と 2：P2 と P1。2 の「U5 ができてから」。4：P3 は、要るアプリが出たときだけ。6：新しい権限。AURA には、既定で与えない）。

1. **設定だけのプロファイル**（Blender の設定など、ログインを含まないもの）は、**P2**（写す）。写すのは、持ち主の側の係。写し直すのは、持ち主が頼んだとき。書き戻さない。【提案】（見直しの L6）：写すかどうかは、ホストにいる持ち主が選ぶ（遠くのランチャーから選ばせない。遠くの端末が、持ち主のプロファイルを専用ユーザーへ動かせないように）。写すのは、アプリごとに決めた**ファイルの一覧**だけにする。試用版は、Blender の設定のフォルダーを丸ごと写していて、最近使ったファイルの一覧や、アドオンが保存したトークンも入りうる（【調べる】Blender の設定のファイルのうち、どれにアドオンの値が入るか）。
2. **ログインを含むプロファイル**（ブラウザー）は、**P1**（アプリ自身のログインと同期）。ただし、**U5（アプリごとの囲い）ができるまでは、使わない**（いまの【決定】のまま、試験用のプロファイル）。U2 のままだと、ログインが、同じ袋のほかのアプリ、コーディングエージェント、乗っ取られたエージェントから届く（脅威モデルの 6.3、守4）。
3. ブラウザーのプロファイルを P2 で写す形は、採らない。渡るものがいちばん多く、鍵束に頼るものは写しても使えない。
4. **P3 は、いまは採らない。** P1 では足りないアプリが出たとき（たとえば、机の鍵束にあるパスワードが要る）に、持ち主が決める（【決定】2026-11-19、持ち主：P3 は、要るアプリが出たときだけ）。採るなら、そのアプリだけ、持ち主が名指しし、画面に「このアプリは、あなたのユーザーで動きます」と出し、下の権限を要る形にする。
5. **P4 は、採らない。**
6. **新しい端末の権限「ふだんのプロファイル」を足す。** ログインを含むプロファイル（P1、P3）を使うアプリを開く、つなぐには、この権限を要る。新しくペアリングした端末には、与えない。なくした端末（攻3）が、持ち主のアカウントに届かないようにするため。**AURA には、既定で与えない**（外へ持ち出すため）。要るときだけ与え、済んだら外す（【決定】2026-11-19、持ち主）。権限の確かめ方は、ほかの権限と同じ（頼まれたときに読み直す。ADR 0010）。Mac Studio での「操作」も、同じ重さで扱う（上の「Mac のホスト：Mac Studio と Mac mini」）。

### 提案

**【提案】Landlock を第一の候補にする。** 理由：特権が要らない。Ubuntu の名前空間の決まりに当たらない見込み。子に引き継がれて外せないので、アプリが起動したものも囲いの中に残る。1 フレームごとの経路には入らない（ファイルを開くときに確かめるだけ）。

囲いの形（案）：

- 読み書きできる：そのアプリのフォルダー（設定、データ、キャッシュ、そのセッションのランタイムのフォルダー）。隔離領域の `files/` と `inbox/` は、持ち主がアプリごとに選ぶ。
- 読むだけ：システムのファイル（`/usr`、`/etc` の要る所、フォント、テーマ）。
- 読めない：端末の鍵とペアリングの一覧、ほかのアプリのフォルダー、口のフォルダー。作業の場所（下の「コーディングエージェント（herdr）」）は、持ち主が名指ししたアプリだけ。既定は読むだけで、持ち主が書いてもよいと名指ししたアプリだけが、名指しした所に書ける（【決定】2026-11-19、持ち主）。
- 囲いを付けるのは、エージェントが起動するときの、起動する側の務め（ADR 0009 の 6 の `setsid` と同じ所）。

**囲いの決まり（見直しの L2。【提案】）：**

- Landlock の版の下限を決める（スコープのある 6 以上）。足りないカーネルでは、囲えないとして**閉じる側に倒す**（ログインのあるプロファイルは使わせない。`istesso doctor` に出す）。黙って囲いなしで動かさない。
- `/dev` は、`renderD*` と `nvidia*` だけを開ける。`video` のグループには入れない。デバイスの ioctl の決まり（ABI 5）は ioctl ごとに効く。
- `/tmp` と `/dev/shm` は、同じユーザーのすべてで共有になる。アプリごとに、自分の一時のフォルダーを渡し（`TMPDIR`）、`/tmp` と `/dev/shm` は決まりに入れない。共有メモリーを使うアプリが動くかは【調べる】。
- アプリだけでなく、**ランナーも囲う**（ランナーは、ネットワークからの絵の頼みと入力を受ける）。

**Landlock だけでは塞げないもの**（名前の付いたソケットへのつなぎは、ホストで見たとおり止まらない。ほかは考え）と、その手：

| 塞げないもの | 起きうること | 手（【提案】） |
|---|---|---|
| ランナーの入力の口 | ほかのアプリへ、キーを打ち込む | **起動のときに渡すソケットの組（socketpair）にする**（見直しの L1）。名前を持たないので、ほかのプロセスは見つけられない。最初の版の案（`SO_PASSCRED` で送り主の番号を確かめる）より、口そのものがなくなるぶん強い。入力の経路が変わるので、前後で測る。ADR 0007 の「入力」（手元のソケットで渡す）に注記する |
| ほかのセッションのコンポジターのソケット | ほかのアプリの絵の中に、窓を出す | 案 1：つないだソケットの番号だけを渡す（`WAYLAND_SOCKET`）。アプリがあとから別の接続で開く窓（試用版の記録：Chrome のファイルを選ぶ窓）が出せなくなる。案 2：ソケットを、そのアプリだけの名前空間で隠す（下の (b)）。最初の版の案（アプリのフォルダーに置けば、ほかのアプリの囲いの外になる）は、**つなぎを止めないので効かない**（見た） |
| 専用ユーザーの systemd（ユーザーのインスタンス） | `systemd-run --user` で、囲いの外の新しいプロセスを起こす。**囲いから出られる** | 囲いの中から systemd の口（`/run/user/<番号>/systemd/private` とセッションバス）に届かないようにする必要がある。Landlock では止まらない。(b) か (c) |
| 専用ユーザーのセッションバス（`/run/user/<番号>/bus`） | 上と同じ。ほかのサービスを起こす | 同上。アプリには、試用版と同じく、何も起動できない自分のバスだけを渡す。ただし、専用ユーザーのバスの場所は、同じユーザーなら知れる |
| ほかのアプリの自分のバス（試用版では `/tmp` の下） | ほかのアプリのバスにつなぎ、そのアプリの名前を名乗る。バスは同じユーザーを受け入れる | バスの置き場所を、そのアプリのフォルダーにし、バスの決まりで、そのアプリのプロセスだけを受ける形を【調べる】。Landlock では止まらない |
| 専用ユーザーの PipeWire | ほかのアプリの音を録る。音を流し込む | PipeWire の口へのつなぎも止まらない。アプリごとの PipeWire にするか、(b) か (c) |
| セッションごとの入力方式（ADR 0020 の b） | ほかのセッションの入力方式につなぎ、打った文字を読む | **入力方式は、ランナーが起動したプロセスだけに結び付ける**（見直しの L4。input-method-v2 の口を、ランナーが渡すソケットの組で開く）。学習は、セッションのあいだで共有しない形を【調べる】（共有すると、あるアプリで打った文字が、ほかのアプリの変換の候補に出る） |
| クリップボード | ほかのセッションの写した文字を読む | まだ作っていない（M3 の宿題 7）。作る前の ADR で、セッションのあいだで渡さない形にする |
| ほかのアプリのプロセスの一覧と、引数 | 名前と引数が見える | 隔てない（ADR 0014 と同じ。引数に秘密を載せない決まり） |

**手の選び方（見直しの H1）：【決定】2026-11-19、持ち主：まず (b) を確かめ、だめなら (c)。確かめが済むまでは (d)（ログインを使わない）。**

| 手 | 中身 | 費用 |
|---|---|---|
| (a) カーネルに、名前の付いたソケットへのつなぎを止める権利があるか | **このカーネル（6.17、版 7）には、ない（見た）。** 先のカーネルに入るかは、分からない | 待つだけ |
| (b) 導入のときに AppArmor の決まりを足し、起動する係にだけ名前空間を許す。アプリから、`/run/user/<番号>`、`/tmp`、`/dev/shm` を見えなくする | 名前ごと隠すので、ソケットにもつなげない | 導入に root（決まりのファイル 1 つ）。名前空間の中で、ブラウザー自身の囲いが動くかを【調べる】。AppArmor の決まりの書き方は、公開の文書だけから学ぶ |
| (c) ログインのあるアプリだけ、アプリごとの専用ユーザーにする（U3 を、そのアプリにだけ） | OS の権限で分かれる | ユーザーが増える。起動に、ユーザーをまたぐ仕組みが要る（U3 の費用） |
| (d) (a) が来るまで、Linux のホストではログインを使わない | 何も作らない | 毎日の使い方で、ブラウザーのログインが使えない |

### snap の Firefox を外から見たこと（2026-11-19、ホストで）

持ち主の考え（snap の囲いは、ホームの隠しファイルを読ませない）を、外から、読むだけで確かめた。持ち主の snap のフォルダーと、ふだんの Firefox には、触れていない（流れの決まり 22）。snapd のコードは読んでいない。計測の合図が `free` であることを、始める前に読んだ。

- AppArmor の決まりだけを当てる試し（見た）：ホームの直下に、試しのためだけのフォルダーを 2 つ作った（ふつうの名前のフォルダー 1 つと、隠しフォルダー 1 つ）。中に、中身が 1 行だけのファイルを 3 つ置いた（ふつうのフォルダーの中のふつうのファイルと隠しファイル、隠しフォルダーの中のファイル）。snap の Firefox の AppArmor の決まり（`snap.firefox.firefox`）の下で、それぞれを読むために開いた（中身は出していない）。終わったあと、ファイルとフォルダーを名前で消した。

| 開いたもの | 結果 |
|---|---|
| ホームの直下の、ふつうの名前のフォルダーの中のふつうのファイル | **開けた** |
| 同じフォルダーの中の隠しファイル（名前が `.` で始まる） | **開けた** |

| 参考：`test -r`（`access()`） | 3 つとも「読める」。AppArmor は `access()` を見ないので、この確かめには使えない |

読み取れること（どれも、この試しの範囲。snap のマウントの名前空間と seccomp は当てていない）：

- **ホームの直下の隠しフォルダー（`~/.config` など。端末の鍵の置き場所）は、snap の決まりで読めない。** 持ち主の考えは、この形では当たっている。ただし、`personal-files` の口で、`~/.mozilla/firefox` は読める。
- **ふつうの名前のフォルダーの下は、隠しファイルでも読める。** アプリの専用ユーザーで snap の Firefox を動かすと、そのユーザーのホームのふつうの名前のフォルダー（隔離領域の `files/`、`inbox/`、ほかのアプリのフォルダーが、ふつうの名前の所にあれば）は、すべて読める。
- 【提案】アプリの専用ユーザーのホームでは、アプリのフォルダー、端末の鍵、隔離領域を、**ホームの直下の隠しフォルダーの下**に置く。snap のアプリに `files/` を見せたいときは、持ち主が名指しして、snap のフォルダー（`~/snap/<名前>/`）の下へ写す。
- つながっている口のうち、`removable-media`、`camera`、`audio-record`、`network-bind`、`cups-control` を、専用ユーザーの snap では外すか。【持ち主の考え】2026-11-19：口のつながりは PC 全体のもので、ユーザーごとではない。外すと、持ち主のふだんの snap（机の Firefox）にも効く。専用ユーザーは机の席にいないので、カメラとマイクの口にはそもそも届かないはず。確かめられたら、口はつないだままにする。下の「ホストで見たこと（機器の口）」で確かめた。

### ホストで見たこと（機器の口、2026-11-19）

読むだけで見た。sudo は使っていない。何も変えていない。ユーザー名は出していない（「机の人」と書く）。計測の合図が `free` であることを、始める前に読んだ。

囲いを付けるまでのあいだ（U2 のあいだ）は、ログインを含むプロファイルを置かない（上の「ふだんのプロファイル」の 2）。

### コーディングエージェント（herdr）

R-07 は、コーディングエージェントが読めるのを、隔離領域だけにすると決めている。アプリと同じユーザーに置くと、コーディングエージェントは、アプリの設定、写したプロファイル、端末の鍵に届く（脅威モデルの 5 章の攻7）。

**【決定】2026-11-19、持ち主：herdr とコーディングエージェントは、2 つめの専用ユーザーで動かす。** 理由：API の鍵と Git の資格情報を持ち、外から読んだ指示で動きうる。だから、OS のユーザーの境目で、アプリと分ける。その上に、Landlock を重ねる。M6 の後半（herdr を専用ユーザーで）は、これに合わせる（【決定】2026-11-18：M6 の後半は M5 の設計に合わせる）。

#### 作業の場所

コーディングエージェントが、コードを置いて、読み書きする所。どちらのホームの中にも置かない（ホームを開けずに済むように）。

| もの | 中身 |
|---|---|
| 場所（例：`/var/lib/istesso/work`） | 導入のときに root で作る。持ち主は、コーディングの専用ユーザー。グループは、作業のグループ |
| 権限 | 2770（作業のグループの人だけが入れる。中に作るものは、グループを引き継ぐ）。既定の ACL で、中に作るファイルとフォルダーにも、作業のグループの読み書きを付ける（ユーザーごとの umask に頼らない） |
| アプリに読ませるとき | 【決定】2026-11-19、持ち主：**既定では、持ち主が名指ししたアプリだけが読める**（たとえば、コードを見るためのエディター）。ACL で、アプリの専用ユーザーに読むだけを与え、Landlock で、名指ししたアプリにだけ開く。ほかのアプリは、Landlock で読めない |
| アプリに書かせること | 【決定】2026-11-19、持ち主：**既定では書けない。ただし、持ち主は、書いてもよいアプリを名指しできる**（コードを直すための GUI のエディターなど）。【決定】2026-11-19、持ち主（3 回目の答えの 11）：**その書けるアプリは、アプリの専用ユーザーではなく、コーディングの専用ユーザーとして動かす**（Istesso から開いたエディター）。アプリの専用ユーザーは、作業の場所に書かない |

**書いてよいアプリを名指ししたときに、起きうること**（はっきり書く）：アプリは、ウェブの中身や開いたファイルで乗っ取られうる（攻1）。書けるアプリが乗っ取られると、作業の場所に、`.git/config`（`core.fsmonitor`、`core.pager` など、Git が動かす命令）、Git のフック、ビルドの手順（`build.rs`、`Makefile`）、CI の設定、エディターのタスクの設定を置ける。それらは、コーディングエージェントが Git やビルドを動かしたときに、**コーディングの専用ユーザーとして動き**、API の鍵と Git の資格情報（資12）に届く。持ち主がそこで Git やビルドを動かせば、**持ち主として動く**（下の H2。【決定】2026-11-19、持ち主：持ち主は、ふだんのユーザーからは書かない）。

**書けるエディターを、コーディングの専用ユーザーとして開く（【提案】）：**

- いまの起動の道（アプリの専用ユーザーのエージェントが、自分のユーザーでアプリを起動する）では、別のユーザーとして起動できない（ユーザーを切り替える特権が要る。U3 の費用）。
- 案 A：**コーディングの専用ユーザーにも、小さなホストの役（エージェントとランナー。linger で常駐）を置き、名指しされたエディターの起動だけを受ける。** 特権は要らない。端末から見ると、ホストの身元が 1 つ増える（一覧では 1 台にまとめる）。
- 案 B：herdr の中から、持ち主がエディターを起動し、そのエディターの窓を Istesso のランナーで出す。ランナーもコーディングの専用ユーザーで動かすので、結局 A と同じ部品が要る。
- 案 A を提案する。どちらでも、エディターはコーディングの専用ユーザーとして動くので、**API の鍵と Git の資格情報（資12）と同じ袋に入る。** エディターが開いたファイルの中身で乗っ取られると、資12 に届く。だから、エディターにも Landlock を付け、名指ししたプロジェクトのフォルダーと、エディター自身の設定だけを開かせる（下の 1〜5）。
- エディターは GPU のグループを持たないコーディングの専用ユーザーで動くので、ソフトウェアで描くことになる（考え）。【持ち主の考え】2026-11-19：**名指しのエディターを起動する係（案 A）でよい。ただし、コーディングの専用ユーザーにも GPU を許す**（rio は GPU で描く。コーディングエージェントが、GPU で学習を動かすこともある）。

**コーディングの専用ユーザーに GPU を許すと、何が増えるか**（ホストで見たこと、2026-11-19。下の「ホストで見たこと（機器の口）」）：

- **NVIDIA の口（`/dev/nvidia0`、`nvidiactl`、`nvidia-uvm`、`nvidia-modeset`）は、いまでも、だれでも開ける**（0666。見た）。CUDA と NVENC は、グループがなくても、どのユーザーからも使える。だから、GPU を許して増えるのは、主に、描画の口（`/dev/dri/renderD*`、`render` のグループ）である。
- 乗っ取られたコーディングエージェントから届きうるもの（考え）：
  - **ドライバーへの攻撃の面。** NVIDIA のカーネルのドライバーと、描画のドライバーの口が、そのまま攻撃の入口になる（範囲の外とした OS の不具合の一つだが、入口が増える）。
  - **ほかのユーザーの GPU のメモリーと、描画の中身。** ふつうはドライバーが分ける。分け方が不十分なら、ほかのアプリの絵（アプリの専用ユーザーのランナーの絵、机の画面）が読める恐れがある。
  - **GPU を使った横の道**（時間の測り方で、ほかのプロセスの動きを推す）。範囲の外としたもの。
  - **ほかの GPU の利用者の絵を取ること。** 画面の出力の口（`/dev/dri/card*`。`video` のグループと、机の人の権限）を開ければ、机の画面を読める恐れがある。描画の口（`renderD*`）からは、画面の出力は扱えない（考え）。
  - **計測している経路の妨げ。** エンコーダーの枠（PC 全体で 12。試用版の記録）と CUDA の時間を使い切ると、ランナーの絵の圧縮が遅れ、遅延が悪くなる。断られることもある。
- 小さく保つ形（【提案】）：
  1. 与えるのは `render` のグループだけ。**`video` のグループには入れない**（画面の出力の口を開けない）。
  2. Landlock の決まりで、`/dev` は `renderD*` と `nvidia*` だけ（`nvidia-caps` と `card*` は入れない）。
  3. GPU を使う重い仕事（学習）は、**計測の合図に従う**（`busy` で止める）。エージェントのツールのひな形に、その決まりを書く。
  4. NVENC は、コーディングの専用ユーザーでは使わない決まりにする（強制はできない。使ったかは、プロセスごとの `enc` で見る）。
  5. GPU の時間の取り合いは、OS の権限では分けられない。学習を動かすときは、持ち主が分かるように、`istesso doctor` と画面に出す。

**小さく保つ形（【提案】。書けるエディターに当てる）：**

1. 書けるのは、持ち主が名指しした**プロジェクトのフォルダーだけ**（作業の場所の全体ではない）。Landlock の書く権利を、そのフォルダーにだけ付ける。
2. そのフォルダーの中でも、**`.git/` と、ビルドと CI の手順のファイル**（`build.rs`、`Makefile`、`Cargo.toml` の build の項、`.github/`、エディターのタスクの設定など）は、アプリに書かせない。Landlock は、決まりを親のフォルダーごとに付けるので、ファイルごとに外すことはできない（考え）。そこで、`.git/` は Landlock で書く権利から外し、手順のファイルは、名前の一覧で、エージェントが前後を見比べる（下の 3）。どこまで Landlock で止まるかは【調べる】。
3. **コーディングエージェントは、アプリが書いた設定から、フックと fsmonitor を動かさない。** コーディングの専用ユーザーの Git の設定で、フックの場所と `core.fsmonitor` と `core.pager` を、作業の場所の外の決まった値に固定する（リポジトリの `.git/config` より強い所で決める。効き方の順は【調べる】）。ビルドの手順のファイルが、前の確かめのあとに、コーディングエージェントのほかから変わっていたら、ビルドの前に止めて、持ち主に見せる。
4. 書けるアプリには、ログインのあるプロファイル（P1）を持たせない。乗っ取られる道（ウェブ）と、書く権利を、同じアプリに重ねないため。
5. 書けるアプリの名指しは、ホストにいる持ち主だけができる（遠くのランチャーからは選ばせない）。名指しは、一覧で見えて、いつでも外せる。

**持ち主が作業の場所に書くと、何が起きるか（見直しの H2）：** 最初の版は、持ち主に読み書きを与えていた。逆向きの危うさがある。

- 乗っ取られたコーディングエージェントが、作業の場所に、**持ち主のユーザーで動くもの**を置ける：`.git/config`（`core.fsmonitor`、`core.pager` など、Git が動かす命令）、Git のフック、ビルドの手順（`build.rs`、`Makefile`）、エディターのタスクの設定。持ち主が、そこで `git status`、ビルド、エディターで開く、をすると、それが**持ち主として動く**。境目 E が、逆向きに破れる。
- Git は、ほかのユーザーが持つリポジトリを、既定では開かない（`safe.directory`）。持ち主がそこで Git を使うには、それを切ることになる。
- 既定の ACL は、思ったとおりに効かないことがある：0600 で保存するアプリ、`mv`、`cp -p`、`rsync` は、元の持ち主と権限を保つ。`chmod` は setgid を落とす。ACL を付け直せるのは、ファイルの持ち主だけ（考え）。

**【提案】（最初の版の「持ち主は読み書き」を取り下げる。【問い 11】）：**

1. 持ち主は、作業の場所に**書かない**。コードを直すのも、Git を使うのも、ビルドするのも、herdr の中で、**コーディングの専用ユーザーとして**行う。
2. 持ち主のホームへ持ち出すのは、Istesso の取得（ADR 0013 の名指しのコピー）で、中身の写しだけ（Git の設定やフックは、実行されない形で）。
3. どうしても持ち主が作業の場所を見たいときは、**読むだけ**（持ち主を作業のグループに入れず、ACL で読むだけを与える）。「持ち主は、作業の場所で、Git もビルドもエディターのタスクも動かさない」という決まりを、文書と画面に書く。

#### だれが、何を、読み書きできるか（【提案】）

| | 持ち主 | アプリの専用ユーザー（アプリ、エージェント） | コーディングの専用ユーザー（herdr、コーディングエージェント） |
|---|---|---|---|
| 持ち主のホーム | 読み書き | 読めない | 読めない |
| アプリの専用ユーザーのホーム（アプリのフォルダー、端末の鍵、隔離領域） | 直接は読めない。Istesso の操作で取得と受け渡し（ADR 0013） | 読み書き（U5 では、アプリごとに自分のフォルダーだけ） | 読めない |
| コーディングの専用ユーザーのホーム（API の鍵、Git の資格情報） | 直接は読めない（herdr の中から、持ち主が操作する） | 読めない | 読み書き（Landlock で、ツールの設定と、要るものだけ） |
| 作業の場所 | 【決定】2026-11-19、持ち主：**ふだんのユーザーからは読むだけ。** 直すときは、コーディングの専用ユーザーとして（上の H2） | 既定は読めない。名指ししたアプリだけが読む。書いてよいと名指ししたアプリだけが、名指ししたプロジェクトのフォルダーに書く（`.git/` と手順のファイルを除く。【決定】と【提案】は上） | 読み書き |
| 口のフォルダー | つなげる | 口を作る（エージェント）。アプリからのつなぎは、エージェントが断る | 入れない |

- **Landlock を重ねる**：herdr とコーディングエージェントは、作業の場所、ツールの設定、システムのファイルだけを読み書きできるようにする。ツールのサンドボックス（二重の柵）も残す。
- 正直に言うと、**API の鍵と Git の資格情報は、コーディングエージェント自身からは届く**（エージェントが、それを使って動くため）。ユーザーを分けて守るのは、アプリ、アプリを操作する端末、乗っ取られた Istesso のエージェントから、である。
- 隔離領域の `files/` と、作業の場所のあいだで、ファイルを動かすのは、持ち主が Istesso の操作で行う。自動では写さない。
- ADR 0013 と m6-plan.md の E は、作業の場所を、隔離領域（アプリの専用ユーザーのホーム）の中に置いている（見直しの L7）。この文書の形（作業の場所は、どちらのホームの外。コーディングの専用ユーザーのもの）に合わせて、2 つを直す（下の「採用されたら直すもの」）。
- 【決定】2026-11-19、持ち主（見直しの M8 への答え）：コーディングエージェントに渡す API の鍵と Git の資格情報は、**持ち主のふだんのものと別の、狭いもの**にする（そのリポジトリだけ、書き込みの範囲を絞ったトークン、使える額に上限のある API の鍵）。漏れたときに届く範囲を、渡したものだけにする。
- 隔てないもの（ADR 0014 と同じ）：同じ PC のネットワーク。コーディングの専用ユーザーも、同じ PC の待ち受けにつなげる。ただし、Istesso の制御チャンネルは、ペアリングした鍵がないとつなげない。
- 持ち主が herdr にどう入るか（端末を、コーディングの専用ユーザーとして開く方法）は、M6 で決める。その道（SSH の鍵など）は、ペアリングの解除では切れない（見直しの M4）。なくした端末に、その鍵があれば、別に外す（脅威モデルの 6.7）。

## 計測の合図

AGENTS.md の計測の合図は、2 台それぞれの、持ち主のホームの `~/.local/state/istesso/measuring` にある。U2 では、専用ユーザーのプロセス（ビルド、試験、アプリ）が、これを読めない。合図に従えなくなる。

- 【提案】合図を、だれでも読めて、計測のスクリプトだけが書ける場所に移す（たとえば、導入のときに root で作る、持ち主だけが書けるフォルダー）。または、持ち主の側の係が、専用ユーザーの口へ、合図の変化を渡す。
- AGENTS.md を変えることになるので、まとめ役が決める（持ち主への一覧に載せる）。U2 に移るまでは、いまのまま。
- 見直しの L3（【提案】）：
  - 試用版は、計測の合図が `busy` になると、持ち主のスクリプトがアプリを SIGSTOP で止める。ユーザーをまたぐと、持ち主のプロセスからは止められない。**専用ユーザーのエージェントが、自分で合図を読み、自分のセッションを止める**形にする。
  - 計測の合図は、持ち主（計測のスクリプト）が持つフォルダーに置き、ほかのユーザーには読むだけを許す。`stream-test-*`（止められない長い試験の合図）は、それを書くユーザーが持つ、別のフォルダーに置く（1 つのフォルダーにすると、だれでも計測の合図を書けてしまう）。
  - `/run` の下に置くと、再起動で、落ちて残った古い `busy` が消える（AGENTS.md の「1 時間を超えた busy は持ち主に聞く」が、再起動のあとは要らなくなる）。

## 遅延

AGENTS.md：映像、入力、音の経路に手を入れる変更は、前後の計測値を PR に書く。この文書は設計だけで、何も測っていない。

## ライセンスと特許

流れの決まり 20：仕組み（仕様、手順、形式）を借りる前に、ライセンスと特許を見る。はっきりしなければ、採らない（【決定】2026-11-18、持ち主）。

- この文書が使う仕組みは、OS の公開の口（ユーザーとグループの権限、`SO_PEERCRED`、ソケットの組（socketpair）、ACL、systemd の tmpfiles、Landlock、linger）と、libwayland の公開の変数（`WAYLAND_SOCKET`）である。**仕様書を借りて、自分で作り直すものはない。**
- **特許は、調べていない。** OS の口を呼ぶことは、仕様を借りることとは違うと考えるが、それも確かめていない。採用の前に、次を見る：Landlock（カーネルの文書に、特許の扱いの書き方があるか）、`WAYLAND_SOCKET`（wayland の文書）、GNOME の設定の鍵の名前（設定を読むだけで、仕組みは借りない）。はっきりしなければ、その仕組みは採らない。
- ライセンスは、上の表のとおり、記憶によるもので、使う前に元の文書で確かめる。GPL、AGPL、LGPL、分からないもののコードは、開かない（流れの決まり 23）。bubblewrap、systemd、Flatpak、snapd は、別のプログラムとして動かすか、OS の部品として使うだけで、このリポジトリに入れない。
- Rust の部品を足すとき（`landlock` クレートなど）は、`cargo deny check licenses` を通す（AGENTS.md）。

## 確かめること（どれも、ホストで、読むだけ）

結果を記録するときは、ユーザー名、ホスト名、アドレスを伏せる。計測の合図が `busy` のあいだは、動かさない。

```sh
ls -l /dev/dri/ /dev/nvidia*                # 描画のデバイスのグループと、NVIDIA のデバイスの権限
getfacl /dev/dri/renderD128                  # 机の人に付く権限（uaccess）
cat /sys/kernel/security/lsm                 # Landlock が有効か（2026-11-19 に見た：有効）
sysctl kernel.apparmor_restrict_unprivileged_userns kernel.yama.ptrace_scope
snap get system homedirs 2>/dev/null         # ホームを /home の外に置いたときの snap の設定
stat -c '%a' /home                           # ほかのユーザーのホームの親
```

Landlock の版（7）と、名前の付いたソケットへのつなぎを止めないことは、2026-11-19 に、ホストの小さな試しで見た（上の「ホストで見たこと」）。H1 の (b) を選んだときの AppArmor の決まりと名前空間は、まだ見ていない。

## 既知の不足

- **実機で、何も確かめていない。** OS のふるまい（NVIDIA のデバイスの権限、Landlock の有効と版、snap とホームの場所、ユーザーの区画の CPU の重み、音の優先度）は、すべて考え。
- **特許を調べていない**（上の「ライセンスと特許」）。
- Mac のホストのアプリごとの囲いは、ない。Mac には Landlock がなく、他社のアプリに囲いを付ける公開の方法も見当たらない（`sandbox-exec` は古い形で、試験にだけ使う。m5-plan.md の 7.）。Mac mini では、ホスト専用の Mac を専用ユーザーで使うこと（ADR 0014）が、守りのすべてになる。Mac Studio では、分けるものがなく、「操作」の権限の重さだけで守る（上の「Mac のホスト：Mac Studio と Mac mini」）。
- 設定の係が渡すのは、GNOME の机の値だけ。ほかの机（KDE など）は、扱っていない。
- P1 では、持ち主が、専用ユーザーのアプリの中で、ふだんのアカウントにログインし直す手間がある。
- U2 から U5 のあいだ、端末の鍵は、アプリから読める（ADR 0014 の「鍵に手が届くことへの備え」のまま）。
- ホストにいる人の口に、持ち主のユーザーからつなげるようにすると、持ち主のユーザーで動く悪いプログラム（範囲の外）が、セッションを止められる。持ち主のユーザーは信頼する、という前提である。
- API の鍵と Git の資格情報は、コーディングエージェント自身からは届く（上の「コーディングエージェント（herdr）」）。
- 2 つのエージェント（持ち主の側と、アプリの専用ユーザー）の既定のポートが、どちらも 47801（見直しの L5。ADR 0014 の「既知の不足」にもある）。実装の前に決める。
- Landlock の試しは、ファイルの決まりと、抽象名前空間のスコープだけを見た（上の「ホストで見たこと」）。ネットワークの決まり、ioctl の決まり、合図のスコープは、まだ見ていない。
- snap の囲いの確かめは、AppArmor の決まりだけを当てたもので、snap の実際の起動（マウントの名前空間、seccomp）では見ていない。
- 遠くから外せるようにすると、なくした端末が、ほかの端末の権限を外せる（迷惑。乗っ取りではない）。上の抑え方で、数と戻し方を限る。
