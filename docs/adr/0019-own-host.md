## 背景

関門の判定は、計測用のスクリプト（`scripts/m1-step3-host.py`）で通った。確定の判定は、自前のホストで測り直す。自前のホストは、スクリプトがしていることを、エージェントがランナーとして起動する **1 つのプログラム**で行い、次を足す：エンコーダーを断られたときの動き、止めるときにエンコーダーを 0.3 秒以内に手放すこと、試して測る切り替え（変わらない絵を送り続ける、「起きる時間」）。

関門の数値の回で、ホストの受け持ちは、平均で次のとおりだった（[記録](../measurements/2026-11-17-m1-gate.md)）。

| 区間 | 値 | このプログラムの中身 |
|---|---|---|
| 入力がホストに届いてから、アプリに届くまで | 0.31 ms | エージェント → ソケット → スクリプトのメインループ → コンポジターのスレッド → アプリ |
| コンポジター（確定からフレームが出るまで） | 0.98 ms（負荷つきの回は 0.63） | コンポジターの修正版のプラグインの中 |
| 色の変換と圧縮 | 4.03 ms（うち、圧縮 3.92） | GStreamer の要素と、NVENC の中 |
| 暗号化して、通信路に書く | 0.17 ms（負荷つきの回は 0.07） | スクリプトのコールバックと、`istesso-media` |

**作り直して縮められるのは、合わせて 0.1〜0.2 ms ほどの見込みである**（測っていない）。圧縮の 3.9 ms は、作り直しでは動かない（ADR 0016）。この束でのねらいは、速くすることより、**製品に残せる形にして、遅くしないこと**と、切り替えを 1 つずつ測れるようにすることである。

## 比べる案

| 観点 | A：Python のまま、入力だけ中へ | B：Rust のプログラムが、GStreamer を Rust の束縛で動かす | C：Rust のプログラムが、コンポジターの本体（`wayland-display-core`）を直接呼ぶ |
|---|---|---|---|
| フレームの通り道 | 関門で測ったものと同じ。フレームごとに、Python のコールバックが 4 つ残る | **要素も設定も、関門で測ったものと同じ。** コールバックが Rust になる。ライブラリーは、C の口を通さずに呼ぶ | コンポジターの要素（描く拍、フレームの受け渡し）を、作り直すことになる |
| 遅延 | 変わらない | 同じか、0.1 ms ほど短い見込み。入力が、メインループのほかの仕事（4 ms ごとの見回り、1 秒ごとの記録の書き出し）のうしろに並ばなくなる | B より、入力 1 回あたり数 µs 短い見込み |
| 危うさ | いちばん小さい（いま）。あとで大きい：変わらない絵の送り直しは、コンポジターのスレッドと順番をそろえる必要があり、プローブでは書きにくい。インタープリターの止まり（メモリーの掃除、ロック）が、通り道に残る | 通り道に、新しいコードが入る。**スクリプトと並ぶことを、測って確かめるまで、置き換えない** | いちばん大きい。4 つの修正を当てた版を、依存として抱える。関門で測った形と、比べられなくなる |
| 依存 | Python、GObject の束縛（入っている） | `gstreamer` のクレート（MIT OR Apache-2.0 の見込み。`cargo deny` で確かめる）。GStreamer そのものは、入っているライブラリーに動的にリンクする（[components.md](../components.md)）。ビルドに、GStreamer の開発用のパッケージが要る | B のものに加えて、Smithay と、修正を当てたコンポジターの git の依存（`deny.toml` は、知らない git を断る） |
| ランナーの約束、配布（M9） | Python で書ける。配布物に、Python と束縛が要る | 実行ファイル 1 つ | 同じ |

ほかの形：

- **エージェントの中に入れる**（ADR 0010 の B）。入力は、関数の呼び出しで渡せる。ADR 0010 が退けた形で、わけは変わっていない（エージェントが GStreamer を抱える。落ちたときに、全部のセッションを巻き込む）。
- **パイプラインを 2 つに分けて、あいだを待ち行列でつなぐ**（`appsink` → `appsrc`）。送り直しや止める処理は書きやすいが、フレームの通り道に、スレッドの受け渡しが 1 回増える。採らない。

## 入力の受け渡し：減らせるのか

いまの受け渡しは、エージェント →（ソケット）→ スクリプトのメインループ →（要素のイベント）→ コンポジターのスレッド → アプリ。ランナーの約束の決まり 4 は、「入力は、`input_socket` からだけ受け取る」である。この決まりの下では、**エージェントとランナーのあいだのソケットは、なくせない。**

| 形 | ホストの中で、起こされるスレッド | 要るもの |
|---|---|---|
| I-0：ソケットのまま。受けるのは、それだけを待つ Rust のスレッド | エージェント、入力のスレッド、コンポジター（いまと同じ数。1 回ずつが軽い） | なし。約束のとおり |
| I-1：ランナーが、入力の接続を自分で受ける（エージェントの入力の関数を、ランナーのプロセスで動かす。ポートは `answer` で知らせる） | 入力のスレッド、コンポジター（**1 つ減る**） | 決まり 4 と ADR 0007 の書き換え。クライアントが、入力をランナーのポートへつなぐ。「入力を送れるのは、映している端末だけ」（ADR 0010 の 13）を確かめる場所が、エージェントからランナーへ移る |
| I-2：コンポジターのスレッドが、ソケットを自分で読む | エージェント、コンポジター（**1 つ減る**） | コンポジターへの 5 つ目の修正（入力の通り道）。Istesso のイベントの形を、プラグインが知ることになる |

1 つ減らして縮むのは、静かなときで 0.05〜0.15 ms の見込みである（測っていない）。

## 決定（提案）

**B を採る。入力は、I-0 で作る。** 入力の出どころは、1 つの口のうしろに置く。I-1 は、この束では、何も作らない。I-1 にするかどうかは、I-0 で「エージェントが手にしてから、コンポジターに渡すまで」を測ってから（下の計測の 4）、持ち主が決める。**この束では、ホストの側の入力の受け渡しは、減らない**（数は同じで、1 回が軽くなる）。

わけ：

1. 通り道の要素と設定が、関門で測ったものと同じなので、「並んだ」と言うための比べが、作り直しの違いに埋もれない。
2. エンコーダーを断られたとき、止めるとき、送り直すとき、のどれも、「コンポジターと、エンコーダーのあいだ」に自分のコードが要る。それを、Rust で 1 か所に置ける（下の「関」）。
3. I-1 は、アプリマネージャーとつなぐ作業（束の 5）の形を変える。だれが入力を送ってよいかは、いまある関数（エージェントの入力の確かめ）のうしろに置いたままにする。

### 作り

- 新しいクレート `crates/istesso-host-linux`。GStreamer を使う部分は、**既定では切ってある feature** に入れる。ワークスペースのビルドと試験は、これまでどおり、GStreamer のない PC でも通る（ADR 0010 が境界を決めたわけの 1 つ）。feature を入れたビルドと試験は、ホストで行う。
- 状態の動き（ランナーの行、止める・戻す、断られたとき、送り直しの時刻、入力の変換、カーソルの突き合わせ）は、GStreamer に触らない部分に置き、どの PC でも試験する。
- 起動の形は 2 つ。中身は 1 つ。
  - **ランナーの形**（引数なし）：ADR 0010 の行を、標準入力と標準出力で話す。切り替えは、環境変数で渡す。
  - **計測の形**（`measure`）：スクリプトと同じ引数、同じ語（`pause`、`resume`、`detach`、`admit`、`close`）、同じ答え、同じフレームの記録。計測の道具と `scripts/m1-step3-breakdown.py` が、そのまま使える。暗号化していない UDP の経路（`--to`）は、移さない。その比べには、スクリプトを使い続ける。
- パイプラインは、スクリプトと同じ文字列から作る（`waylanddisplaysrc` → CUDA のフレーム → `cudaconvert` → `nvcudah265enc` → `h265parse` → 取り出し口）。同じ文字列になることを、試験で確かめる。
- **関**：コンポジターの要素と、色の変換のあいだに、このプログラムの小さな通り抜けの要素を 1 つ置く。フレームは、コンポジターのスレッドのまま、関数の呼び出しで通る（スレッドの受け渡しは、増えない）。関は、次を受け持つ。
  - 最後のフレームを持っておく（送り直しと、戻すときの最初の 1 枚のため）。
  - 止めているあいだ、フレームを先へ通さない。コンポジターへの見え方は、いまと同じにする（確定のたびに描く形では、描かせない）。
  - **エンコーダーの側の失敗を、コンポジターへ返さない。** コンポジターが失敗を知ると、パイプラインごと終わって、アプリが表示先を失う。
  - 送り直しのフレームと、コンポジターのフレームを、1 本の順番にそろえる。
- 関のうしろ（色の変換、エンコーダー、取り出し口）は、「エンコーダーの側」として、まとめて足し、まとめて外す。

### スレッドと優先度

既定は、**関門で測った形と同じ**（どのスレッドも、ふつうの優先度）。はじめの比べが、「Rust にした」ことだけの違いになるように。

| スレッド | 仕事 | 通り道か | 切り替え `sched` を入れたとき |
|---|---|---|---|
| 制御 | 標準入力の行を読む。標準出力に書く。止める・戻す。4 ms ごとに、キーフレームが要るかを見る（いまと同じ） | いいえ | そのまま |
| 入力 | `input_socket` を待つ → イベントにして、コンポジターの要素へ渡す（その場で、コンポジターのスレッドへ送られる） | 入力 | 上げる |
| コンポジター（プラグインの中） | アプリの確定を受けて、描く | 入力と絵 | 上げる（外から、スレッドの番号で） |
| フレームを運ぶ（コンポジターの要素の流れのスレッド） | 関 → 色の変換 → エンコーダーへ渡す | 絵 | 上げる |
| エンコーダーの出口（NVENC の要素の中） | 圧縮の済んだフレーム → `istesso-media` で封をして書く（いまと同じく、このスレッドの上で） | 絵 | 上げる |
| 送り直し | 最後のフレームから 50 ms たったら、関に 1 枚渡す | いいえ（順番は、関がそろえる） | そのまま |
| 知らせ | GStreamer のバス：カーソル、窓の数、失敗 | いいえ | そのまま |
| 記録 | フレームの記録を、ファイルに書く | いいえ | そのまま |
| `istesso-media` の中 | 受け付け、ペアリングの見回り、見る側ごとのスレッド | 変えない | そのまま |

- 通り道のスレッドは、ファイルに書かない、標準出力に書かない、通り道でないスレッドが長く持つロックを取らない。記録の行は、メモリーの中の待ち行列に入れ、記録のスレッドが書く（スクリプトは、1 秒ごとの書き出しのあいだ、通り道も待たせうる）。
- 「上げる」は、実時間の優先度の低い値（案：10。音より下、ふつうのプログラムより上）。暴走の歯止め（`RLIMIT_RTTIME`）を付ける。権限がなくて上げられなかったときは、そのまま動き、**上げられなかったことを、フレームの記録の先頭に書く**（切り替えが効いていない回を、効いた回として読まないため）。

### エンコーダーを断られたとき、止めるとき（計画の行 4）

- **起動のとき**：コンポジターの側を先に動かして、`ready` と言う。そのあとで、エンコーダーの側を足す。開けなければ、足したものを外して、`no_encoder` と言う。終了しない。
- **`resume`、`attach` のとき**：同じ。開けなければ `no_encoder`。次の `resume` で、もう一度試す。
- **動いている最中**：エンコーダーの側が失敗を返したら、関がそれを受け止めて、エンコーダーの側を外し、`no_encoder` と言う。コンポジターとアプリは、気づかない。見る側は、つないだままで、「いま出す絵がない」（0.5 秒おき）を受ける。
- 失敗の出どころが、エンコーダーの側の要素なら `no_encoder`、コンポジターなら `error`（このあと終了）。スクリプトは、「断られてから 2 秒以内の失敗」という時間で見分けていた。
- **`pause`**：語を読んでから 0.3 秒以内に、エンコーダーの要素を閉じ終える。絵が止まっていても、すぐ閉じる（スクリプトは、次のフレームが来てから閉じる。確定のたびに描く形で、絵が止まっていると、閉じないままになる）。かかった時間を答えに書き、試験で確かめる。
- **`detach`**：先に、見る側を切る（0.1 秒以内）。そのあとで、エンコーダーを閉じる。
- 試験：断られることは、エンコーダーの名前を差し替える切り替えで作る（まねるだけ）。**本物の枠を使い切る試しは、持ち主の動いているセッションを止めうるので、この流れでは行わない。** 本線が、持ち主と時間を決めて行う。

### 切り替え（どれも、既定は「切」。入っているものは、フレームの記録の先頭に書く）

| 切り替え | すること | 前と後で比べるもの |
|---|---|---|
| `keep-awake <毎秒の回数>`（案：20）と `keep-awake-hold <ms>`（案：50） | 映している端末がつないでいて、絵を作っているあいだ、最後のフレームからも、最後の入力からも 50 ms たったら、最後のフレームを、もう一度エンコーダーに通して送る。描き直しはしない（GPU の上の同じ絵を、時刻だけ替えて渡す） | 止まっている画面の回の、圧縮の 95% と 99%（流れている絵：4.04 / 4.14 ms、止まっている絵：5.66 / 6.69 ms）。差の 3 つの値 |
| `sched off\|rt` | 上の表の「上げる」 | 差の 3 つの値、「2 回以上遅れ」、区間ごとの値。負荷つきでも 1 回 |
| `spin-after-input <ms>` | 入力のスレッドが、入力のあと、この長さだけ、眠らずに次の入力を見る。**効くのは、続けて来る入力（ポインターの動き、押しっぱなし）だけ。** 間のあいた 1 回のキーには、効かない（そのあと待つのは、プラグインとドライバーの中のスレッドで、このプログラムのものではない） | 入力の区間。ポインターを動かす回が要る |
| `cpu-latency shown:<µs>` | `/dev/cpu_dma_latency` を、映している端末がつないでいるあいだだけ開いて、値を書く。深い眠りを、PC 全体で止める | 静かなときの、差の 3 つの値と区間ごとの値。**消費電力**（値 0 は、全部のコアが眠らない） |
| `cpu-latency input:<µs>:<ms>` | 同じ口を、入力のあとの短いあいだだけ使う。「入力の直後だけ眠らない」を、このプログラムのものでないスレッド（コンポジター、アプリ、ドライバー）にも効かせる形 | 同じ。止まっている画面の回で |

- 毎秒 85 枚の決まり（ADR 0002）：数えるのは、コンポジターが描き始める回数で、送り直しは、描かない。送り直しは、50 ms のあいだ何も出なかったときだけ出るので、流れている絵の回には、1 枚も入らない。
- 送り直しの 1 枚がエンコーダーの中にあるあいだに、アプリのフレームが来ると、そのフレームは、最大で 1 枚ぶん（4 ms 弱）待つ。入力のあと 50 ms は送り直さないので、入力に答えるフレームは、待たない。入力によらないフレーム（点滅、動画）は、8% ほどが待ちうる（毎秒 20 回 × 4 ms）。測って、記録に書く。

### 変えないもの

コンポジターのプラグイン（同じコミット、同じ 4 つの修正、同じビルド）とその設定。色の変換とエンコーダーの設定（`scripts/m1_encoder.py` と同じ文字列）。`istesso-media` のライブラリー（1 フレームを、エンコーダーの出口のスレッドの上で、1 回の呼び出しで渡す）。キーフレームの求め方（4 ms ごとに見る。50 ms に 1 枚まで）。コンポジターへ渡す入力のイベントの形。カーソルと窓の数の知らせの受け方。**フレームの記録の形**と、計測の形の語と答え。

### クライアントの流れとの境目

**セッションのメッセージ**（エージェントとランナーのあいだは、ADR 0010 の行。標準入力と標準出力、1 行に 1 つの JSON）

| 用件 | クライアント → エージェント（制御チャンネル。ADR 0010 の 4。束の 5） | エージェント → ランナー | ランナーがすること | ランナー → エージェント | 見る側の接続に見えること（ADR 0015） |
|---|---|---|---|---|---|
| 閉じるよう頼む | `session_stop`（`force` なし） | `{"v":1,"cmd":"close"}` | コンポジターが、全部の窓に「閉じてほしい」と伝える。力ずくでは閉じない | なし（閉じ終われば、下の `empty`） | 何も変わらない。アプリが尋ねたら、その窓が映る |
| 窓をしまった | `session_show`（見えていない） | `{"v":1,"cmd":"pause"}` | 0.3 秒以内に、エンコーダーを閉じる | `{"v":1,"event":"paused","took_ms":T}`（足す提案） | つないだまま。0.5 秒おきに「いま出す絵がない」 |
| 窓を出した | `session_show`（見えている） | `{"v":1,"cmd":"resume"}` | エンコーダーを開き直す。最初は、キーフレーム | `{"v":1,"event":"resumed","opened_ms":T,"encoded_ms":T,"written_ms":T}`（足す提案）。開けなければ `{"v":1,"event":"no_encoder","message":…}` | キーフレームが、ふつうのフレームとして届く。断られたときは、「いま出す絵がない」が続く |
| 最後の窓が閉じた | （`session_wait` の答えで知る） | — | 窓の数が 0 になったと、コンポジターが知らせる | `{"v":1,"event":"empty"}`。数が変わるたびに `{"v":1,"event":"windows","count":N}`（足す提案） | エージェントがセッションを終え、ランナーの標準入力が閉じる。ランナーは「終わり」（わけ 0）を送って切る |
| 窓だけ閉じる（離れる） | `session_detach` | `{"v":1,"cmd":"detach"}` | 0.1 秒以内に見る側を切り、エンコーダーを閉じる | `{"v":1,"event":"paused","took_ms":T}`（足す提案） | 「終わり」（わけ 2） |
| つなぐ | `session_attach` | `{"v":1,"cmd":"attach","peer":{…}}` | その端末だけを名指して、絵を作り直す | `{"v":1,"event":"attached","display":{…},"answer":{"transport":"channel","channel_port":N}}`。開けなければ、続けて `no_encoder` | `watch` に `stream` と答える。最初は、キーフレーム |

- 「足す提案」と書いた行と項目は、知らない行と項目を読み飛ばすエージェント（ADR 0010 の約束）には、害がない形で作る。下の表にまとめる。
- 束の 5 が入るまで：クライアントからは、届かない（ADR 0018 のとおり）。計測の形では、スクリプトと同じ語を、標準入力で受ける。

**アプリマネージャーの流れと、つなぐとき（束の 5）に合わせるもの**

| 足すもの | 向き | 形 | 古いエージェントでは |
|---|---|---|---|
| `paused` | ランナー → エージェント | `{"v":1,"event":"paused","took_ms":T}`。`pause` と `detach` に答える。`took_ms` は、語を読んでから、エンコーダーを閉じ終えるまで | 読み飛ばされる |
| `resumed` | ランナー → エージェント | `{"v":1,"event":"resumed","opened_ms":T,"encoded_ms":T,"written_ms":T}`。`resume` のあと、最初のフレームを渡し終えたとき | 読み飛ばされる |
| `windows` | ランナー → エージェント | `{"v":1,"event":"windows","count":N}`。窓の数が変わるたび。0 になったときは、続けて `empty`（約束にある行） | 読み飛ばされる |
| `answer` の中身 | ランナー → エージェント → クライアント | `{"transport":"channel","channel_port":N}`。予行のブランチ（`m3-join-rehearsal`）の包みと同じ項目。エージェントは、書き換えずに運ぶ | そのまま運ばれる |

**カーソルの名前**

| アプリがすること | コンポジター | ホスト（このプログラム） | 見る側に届くもの（ADR 0015 の種類 4） |
|---|---|---|---|
| 形を名前で言う（cursor-shape の口） | **口を開ける（修正に足す）。** 名前を、そのまま知らせる | 名前が「名前で送る集合」にあれば、名前で送る。なければ、ホストのテーマからその形の画像を読んで、画像で送る。テーマにもなければ `default` | 形 1 と名前。または、形 2 と画像 |
| 画像を渡す（テーマの画像を、自分で読むアプリ） | これまでどおり、画像を知らせる | 画像を、ホストのテーマの画像と突き合わせる（大きさ、ホットスポット、画素が、全部同じ）。合えば名前、合わなければ、これまでどおり画像 | 同上 |
| 隠す | 隠れている、と知らせる | そのまま | 形 0 |

- 名前は、cursor-shape の口と同じ名前（CSS の名前）にする。「名前で送る集合」のはじめの案：`default`、`text`、`pointer`、`ew-resize`、`ns-resize`、`col-resize`、`row-resize`、`nesw-resize`、`nwse-resize`。**集合は、クライアントの流れが決めて、ADR 0018 に書く**（Mac のカーソルに置き換えられるもの）。ホストは、それを 1 か所の表に写す。
- **受け持ち**：口を開けるのは、コンポジターの修正（Wayland の口は、コンポジターにしか開けられない）。カーソルを絵から外す設定のときだけ開ける（絵の中に描く形では、名前の形を描き分けられないため）。突き合わせは、ホスト。どちらも、ホストの流れが作る。修正は、これまでの 4 つと同じく、`scripts/patches/` に置く（もとのプロジェクトは、MIT ライセンス）。コンポジターが使っている Smithay には、この口の実装がある（ホストで、読むだけで確かめた）。
- **フレームの通り道に足すもの：なし。** 突き合わせは、「知らせ」のスレッドで行う。テーマの画像の表は、起動のときに、通り道でないスレッドで作る。コンポジターのスレッドの仕事は、いまより増えない（名前で言うアプリでは、画像を写して比べる仕事が、なくなる）。
- 依存：テーマのファイルを読む部分（小さいので、クレートを足すか、自分で書くかは、ライセンスの検査を見て決める）。

### root の設定が要るもの（インストーラーの仕事として書く。ここでは、設定しない）

| 切り替え | 要るもの | インストーラー（M9）がすること（案） |
|---|---|---|
| `sched rt` | 実時間の優先度を使う許し（`RLIMIT_RTPRIO`）。Ubuntu の既定では、ふつうのユーザーにはない見込み | エージェントのサービスに、上限を付ける（`LimitRTPRIO`）。または、ユーザーの上限の設定を 1 行 |
| `cpu-latency` | `/dev/cpu_dma_latency` に書く許し。既定では、root だけの見込み | udev の決まりを 1 つ（専用のグループに、書くことを許す） |

ホストでの試しのために、持ち主の手で入れるもの（2026-11-17。このプログラムは、設定しない）：

- **優先度**：音の試しのために、持ち主が、ユーザーの上限の設定（実時間の優先度と、nice）を入れる。再起動のあとに効く。それが残っていれば、`sched` は、ほかに何も足さずに測れる。
- **`/dev/cpu_dma_latency`**：ホストでは、root だけが開ける（`crw------- root root`）。この口に触る udev の決まりは、ない（どちらも、読むだけで確かめた）。入れる形は、いちばん狭いもの：**持ち主のユーザーだけ**に、開くことを許す。

  ```text
  SUBSYSTEM=="misc", KERNEL=="cpu_dma_latency", OWNER="<ユーザー>", MODE="0600"
  ```

  これを、udev の決まりのファイル 1 つ（`/etc/udev/rules.d/71-istesso-cpu-dma-latency.rules`）に置く。次の起動から効く。戻すには、そのファイルを消して、口の持ち主を root に戻す。
  - 許されること：そのユーザーのプログラムが、この口を開いて値を書いているあいだ、起きるのにその値より長くかかる眠りを、PC 全体で止められる（0 なら、どのコアも眠らない。そのあいだ、電力と熱が増える）。閉じるか、プログラムが終われば、戻る。Istesso でなくても、そのユーザーのプログラムなら、できる。ほかのこと（ファイル、優先度）は、何も許さない。

製品では、`cpu-latency` を持つのは、映している端末を知っているエージェントのほうが合う（セッションをまたいで 1 つで済む）。試しは、ランナーで行う。

## 計測で確かめること（本線が測る）

1. **ホストだけで**（Mac は使わない）：スクリプトと自前のホストで、フレームの記録の区間（コンポジターを出る → 色の変換 → 圧縮 → 渡す）を比べる（[圧縮の内訳](../measurements/2026-11-16-encode-split.md) と同じ形、45 秒）。関が何も足していないことを、ここで見る。`pause` から閉じ終えるまでの時間。断られたときの動き。
2. **並ぶこと**：切り替えを全部切った自前のホストと、スクリプトを比べる。**「並んだ」とする線（2026-11-17 に、どの計測よりも前に、本線が決めた）**：
   - 測り方：入力は、それぞれ 2,000 回。同じ日、同じ置き方。切り替えは、全部「切」。
   - ホストの区間（入力、コンポジター、変換と圧縮、封と書き込み）の平均が、どれも、スクリプトより 0.1 ms を超えて悪くない。
   - 差（中継した窓 − 手元の窓）が、スクリプトの値より、中央値で 0.5 ms、95 パーセンタイルで 0.5 ms、99 パーセンタイルで 1.0 ms を超えて悪くない。
   - 「2 回以上遅れ」の入力の割合が、スクリプトより 2 ポイントを超えて高くない。
   - 入力が、全部、両方の窓に出た。つなぎ直しは 0。
   - 全部を満たして、「並んだ」とする。
3. **切り替えを 1 つずつ**：上の表のとおり。既定に入れるのは、効いたものだけ（計画の 3）。
4. 入力の「エージェントが手にしてから、コンポジターに渡すまで」（エージェントの `--input-timings` と、フレームの記録の `key_in`）。I-1 を作るかどうかの材料。
