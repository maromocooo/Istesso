## 持ち主の決定（2026-11-19）

1. 【決定】**プロジェクトのフォルダーは、必ず 1 台の持ち物。**「ここで開発する」と決めた機械のもので、操作している端末のことではない。そこで始めたもの（シェル、エージェント、ビルド、開発サーバー）は、その機械で動く。同期や複製はしない。ほかの機械からは、マウントで見える・開けるだけ。
2. 【決定】**ターミナルは、文字で運ぶ。** ターミナルのアプリごとの対応はしない。どのターミナル（rio、ghostty、hyper など）でも動く、シェルの代わりの小さなプログラム 1 つで、相手の機械のシェルを、Istesso の暗号の道で運ぶ。タブや herdr のペインは、プロジェクトを指定して開く。cd で別の持ち主のフォルダーに入ったときは、新しいタブと同じ扱い。
3. 【決定】**ターミナル以外のアプリは、いまの道（持ち主の機械で動かして、映像で映す）が既定。** アプリごとの対応は作らない。
4. 【決定】**ブラウザー。** 既定のブラウザーを決める（どの機械の、どのブラウザーか）。作業場の中で開いたポートだけを、その機械の 127.0.0.1 に、自動で転送する。番号がぶつかったら、ずらして知らせる。固定もできる。URL を開く頼みは、既定のブラウザーへ。http と https だけ。転送中の一覧と、止めるスイッチ。

## 1. 作業場（決定 1）

### 1.1 プロジェクトの一覧（【提案】）

- **正本は、開発の機械が持つ。** 項目は、プロジェクトの ID（作るときに、開発の機械が決める、でたらめな値）、名前、その機械でのフォルダーの場所。
- ほかの機械は、制御チャンネルで聞いて、覚える。作りは、アプリ一覧（`istesso-catalog`）と同じにする。覚えたものは、信頼の根拠にしない（ADR 0007）。
- 開発の機械は、鍵の指紋（見せてよい値）で覚える。名前は、表示のためだけに使う（M6 の「覚えた行き先」と同じ覚え方）。
- **ほかの機械から頼めるのは、プロジェクトの ID だけ。** フォルダーの場所を、頼む側から受け取らない。開発の機械が、自分の一覧から引く。ADR 0010 の「頼めるのは、一覧にある ID だけ」、ADR 0021 の「行き先を外から受けない」と、同じ考えである。
- 「どの機械の持ち物か」は、フォルダーの中には書かない。フォルダーは Git で分け合うことがあり、機械の ID が公開の場所に載る。フォルダーを写せば、持ち主を名乗れることにもなる。フォルダーの中（`.istesso/`。M6 の `tasks.json` がある所）に置くのは、名前だけにする。
- 同じ ID、同じ名前のプロジェクトを、2 台目に登録させない。プロジェクトは、ADR 0013 の「同じ相対パスのフォルダーは 1 つに重ねる」の対象にしない（下の 1.4）。

### 1.2 「ここで開発する」を決める（【提案】）

- 決めるのは、人である。人が機械を名指しするか、コーディングエージェントが、機械の「できること」の一覧（GPU、入っている道具、つないである実機。別の流れが作っている）から選び、人が確かめる。
- いちど決めたら、勝手に変わらない。開発の機械が止まっているときは、プロジェクトに「！」と「起こす」を出す。**黙って、ほかの機械で始めない**（R-04 と、M6 の受け入れ条件 B と同じ決まり）。
- 開発の機械を替えること（引っ越し）は、いまは作らない。別の機械でも開発したいときは、Git で持っていく。そのときは、別のプロジェクトとして、その機械の持ち物になる（下の「既知の不足」）。

### 1.3 そこで始めたものは、その機械で動く（【提案】）

- Istesso の口（シェル、コーディングエージェントの起動、タスク）は、プロジェクトの ID を受けたら、必ず、開発の機械で動かす。ほかの機械で動かす道を、持たない。
- 手元の端末が開発の機械でもあるとき（Air のプロジェクトを Air で開く）は、同じ口を、その機械の中で使う。使う人から見て、形が変わらない。
- **同期や複製はしない。** Istesso は、プロジェクトのフォルダーを、ほかの機械へ写し続ける操作を持たない。ビルドの生成物も写さない。

### 1.5 マウントの方式（調査の結果と、【提案】）

方式は、別の流れが調べて、小さな試作まで進めた（`research-unified-mount` ブランチの `docs/research/unified-mount.md`）。この節の印は、その調査の印を写したものである：（実）は、調査が実機（Air、Ubuntu）で見たこと。（資）、（推）も同じ。この文書の流れは、マウントについて、何も動かしていない。

**条件（この文書から、調査に渡したもの）。**

1. 全部の機械で、同じ場所に見える（持ち主の頼み）。
2. ほかの機械からは、読むだけ（【問い 作2】のおすすめ）。
3. 相手の確かめ方、失効、端末ごとの権利は、ペアリングのものを、そのまま使う。別の信頼の仕組み（パスワード、アドレス、SSH の鍵）を増やさない（ADR 0013 が A を採らなかった理由）。
4. 開発の機械が止まっているとき、開こうとしたアプリが固まらない。
5. root も、他社のカーネル拡張も要らない。Mac は、追加の部品を入れずにできるもの。
6. プロジェクトの外を指すリンクの先を、見せない。
7. 大文字と小文字だけが違う名前が、Mac と Linux で、取り違えにならない。
8. ライセンスと特許を、先に見る（持ち主の頼み）。

**候補を、条件に当てる。**「手元だけの NFS」は、見る側の機械の中（127.0.0.1）で、Istesso が小さな NFS のサーバーを動かし、OS が持っている NFS のクライアントでマウントする形である。中身は、Istesso の道で、開発の機械に聞く。

**おすすめ（【提案】）。**

1. **Linux の見る側は、FUSE。** 条件を、いちばんよく満たす。ポートがなく、マウントしたユーザーだけが入れる。
2. **Mac の見る側は、製品では、FSKit を目指す。** ポートがなく、Apple の公開の仕組みである。条件は、署名した配り方が決まること（M9、ADR 0021 の問い 26）と、使う人が、システム設定で 1 回、有効にすること（【問い 作16】）。まだ、だれも試していない。配り方が決まったら、小さく試す。
3. **それまでのつなぎは、手元だけの NFS（読むだけ）。** 今日、sudo も、署名も、追加の部品もなしで動く、ただ 1 つの形である。**穴がある**（条件 3 の行）。だから、使う所を絞る（【問い 作13】）。
   - ほかのユーザー（別のユーザーで動くコーディングエージェントを含む）がいない、見る側の機械でだけ使う。いまは、Air。
   - 同じユーザーで、囲いの中で動くコーディングエージェントには、囲いの決まりで、このポートを閉じる（ADR 0026 の形では、囲いは、手元の中継のポートだけを許す）。
   - 開いているプロジェクトだけを、マウントする。一覧と、止めるスイッチを持つ（転送と同じ。【問い 作14】）。
   - マウント先の親のフォルダーは、持ち主だけが入れる権限（0700）にする（調査：ホームは、グループに開いていた＝実）。
   - 穴を小さくする手を、試作で試す：マウントの頼みを、最初の 1 回だけ受ける。ファイルを指す札を、当てられない値にする。**これは、この文書の考えで、確かめていない（推測）。** 効くと分かるまで、守りには数えない。
4. 手元だけの WebDAV は、予備にする。FSKit が使えないと分かったときに、資格を付ける形を試す。ファイルの全体を取ること、リンクを表せないことが、弱みである。
5. **機械のあいだは、自前の小さな頼み（一覧、属性、読む、リンクの行き先）で運ぶ。** NFS の手続きを、機械のあいだでは運ばない。開発の機械の側は、読む手続きしか持たないので、読むだけであることが、作りで決まる。ADR 0013 の `files` のメッセージと、「ファイル」の権利に合わせる。
6. プロジェクトの外を指すリンクは、リンクとしては見せず、「開けない項目」として見せる（条件 6。調査では、リンクが、見る側の機械の別のファイルを指した＝実）。
7. 見る側のアプリには、macOS が、最初に、「ネットワーク上のボリューム」の許可を尋ねる見込みである（推）。使う人向けの文書に書く。
8. 開発のあいだは、マウントの係も、計測の合図に従う（見る側の操作で、開発の機械に読み込みが起きるため）。

**同じ場所。** 方式とは別の話である（調査の 6 章）。

| 形 | 場所 | 要る手 | 弱み |
|---|---|---|---|
| ア | `~/Istesso/<機械>/<プロジェクト>` | なし | ホームの場所が、Mac と Linux で違うので、絶対の場所は、そろわない（推） |
| イ | `/Istesso/<機械>/<プロジェクト>`。`/Istesso` は、ホームの `Istesso` へのリンク | 機械ごとに 1 回、管理者の権限。Mac は、決まった設定のファイルに 1 行書いて、再起動する（資：`man synthetic.conf`）。Linux は、リンクを 1 つ作る（推） | プログラムが、リンクを解決した場所を書き残すと、機械ごとに違う（推） |
| ウ | `/Istesso` を、リンクではなく、本物のフォルダーにする | 機械ごとに、管理者の権限で数手（推） | 手が多い |

どれにするかは、【問い 作15】。開発の機械でも、プロジェクトを、同じ場所に置く（その機械では、本物のフォルダー。ほかの機械では、マウント先）。

## 2. ターミナル（決定 2）

### 2.1 形（【提案】）

2 つの部分でできている。

**手元の側：シェルの代わりのプログラム。** ターミナルが、シェルの代わりに起動する。rio でも、ghostty でも、herdr のペインでも、同じプログラムである。

1. 手元のターミナルを、打った字をそのまま通す状態にする。
2. 開発の機械の「シェルの口」へ、Istesso の通信路（`istesso-link`。ADR 0007）でつなぐ。相手は、ペアリングした鍵で確かめる。
3. 打った字を送り、届いた字を、そのままターミナルに出す。窓の大きさが変わったら、知らせる。
4. 終わったら、ターミナルを元に戻し、相手のシェルの終了コードで終わる。

ターミナルのアプリごとの対応は、しない。色、カーソル、画面を使うプログラム（エディター、herdr）のための文字の並びは、手を加えずに通す。ターミナルが持つ機能は、ターミナルと、相手のプログラムのあいだで、そのまま働く。

**開発の機械の側：シェルの口。**

1. つないできた端末の権利を確かめる（どの権利かは、ADR 0026 の【問い 範8】）。
2. プロジェクトの ID から、フォルダーを引く（1.1）。
3. 擬似端末（PTY。プログラムから見て、ターミナルに見える口）を作り、その機械のユーザーのシェルを、プロジェクトのフォルダーで始める。どのユーザーかは、【問い 作3】。
4. 字を、両方向に運ぶ。

### 2.2 手元から受け取るもの、受け取らないもの（【提案】）

| もの | 扱い |
|---|---|
| プロジェクトの ID | 受け取る。フォルダーの場所は、受け取らない |
| 窓の大きさ（行と桁） | 受け取る |
| ターミナルの種類（`TERM`）と、色の対応（`COLORTERM`） | 受け取る。開発の機械が、その種類の説明（terminfo）を持っていなければ、広く通じる種類（`xterm-256color`）に替えて、そのことを 1 回知らせる。新しいターミナルの種類を、相手の機械が知らなくて、画面が崩れることを防ぐ |
| そのほかの環境変数 | **受け取らない。** シェルの環境は、開発の機械のユーザーのものを使う |
| 動かすコマンド（`istesso sh <プロジェクト> -- <コマンド>` の形） | 【問い 作4】。シェルを開ける端末は、打てば同じことができる。だから、シェルと同じ権利で受ける案である。M6 の決め（頼めるのは、タスクの名前だけ）とのずれがある |
| 打った字、出力 | 運ぶだけ。**ログに書かない。** 記録するのは、いつ、どの端末が、どのプロジェクトのシェルを開いたか、終了コード、まで |

### 2.3 通信路とメッセージ（【提案】）

- **通信路の手順（`istesso-link`。ハンドシェイク、封のしかた）は、変えない。** 暗号の部品も足さない。映像と同じく、通信路をそのまま使う、長く続く接続にする（ADR 0007 の「映像」）。
- 足すのは、ハンドシェイクのあとのメッセージである。メッセージの追加なので、先頭の版（`ISC1`）は上げない。**作る前に、ADR 0007 のメッセージの一覧を、先に更新する**（AGENTS.md の 4）。
- 足すものの案（形は、試作の流れが決める）：プロジェクトの一覧。シェルを開く、字を運ぶ、窓の大きさ、終わり、「まだここにいる」。転送の一覧、転送の接続を 1 本開く（4 章）。URL を開く頼み（4 章）。
- **権利は、流れているあいだも、1 秒より長くは空けずに読み直す。** 外されたら、接続を切る。映像と入力が、同じことをしている（ADR 0006、ADR 0007）。ADR 0006 の「続いている接続のあいだに読み直すもの」に、シェルと転送を足す。
- 同時に開ける接続の数の枠を、制御と入力のぶんと、分ける。転送の接続が枠を使い切って、入力がつなぎ直せなくなることを防ぐ。
- 待ち受けるポートを分けるかは、M9 の「音、映像、入力を 1 つのポートに寄せるか」と合わせて決める。

### 2.4 タブと、herdr のペイン（【提案】）

- タブも、ペインも、「プロジェクトを指定して、シェルの代わりのプログラムを起動する」だけである（決定 2）。ターミナルの側の設定は、起動するコマンドを 1 行書くことだけになる。
- herdr を、どの機械で動かすかは、決定に入っていない。R-01 は「herdr のセッションは、ホスト側に常駐」と書いている。【問い 作5】。
- herdr が、ペインごとに起動するコマンドを指定できるかは、確かめていない（herdr のソースは、ライセンスを確かめるまで読まない。ヘルプの表示で確かめる）。

### 2.5 cd で、別の持ち主のフォルダーに入ったとき（【提案】）

決定 2：新しいタブと同じ扱い。つまり、そのプロジェクトを指定して開いたのと同じになる（権利の確かめ、どの機械で動くか、が同じ）。

- **見つけ方。** シェルの口が、シェルの今のフォルダーを見る。Linux では `/proc/<番号>/cwd`（資料：proc_pid_cwd(5)）。macOS では `proc_pidinfo` の `PROC_PIDVNODEPATHINFO`（実機：Air の SDK のヘッダーに、この定数がある。ふるまいは推測）。シェルが入力を待っているときにだけ見る。シェルの設定ファイルは、変えない。
- **起きること。** 今のフォルダーが、マウントの下の、別の機械の持ち物だと分かったら、シェルの口が、手元の側に知らせる。手元の側は、その機械へ、そのプロジェクトのシェルを開き、同じタブを、そちらへ切り替える。切り替えたことを、1 行で知らせる（どの機械に移ったか）。そのシェルを終えると、元のシェルに戻る。
- 新しいタブと同じなので、シェルの中の状態（変数、履歴）は、持っていかない。
- 自動で切り替えるか、聞いてからにするかは、【問い 作6】。
- **限り。** 見つけるのは、人がシェルで cd したときだけである。スクリプトの中の cd、フォルダーを指定して動かすコマンド（`make -C` など）は、見つけない。そのコマンドは、元の機械で動く。マウントを読むだけにしておけば（【問い 作2】）、まちがった機械でのビルドは、書けずに止まって、目に見える。書かないコマンドは、止まらない（下の「既知の不足」）。

### 2.6 切れたとき、戻るとき（【提案】）

- **シェルは、開発の機械の側で生き続ける**（R-03 の考えを、ターミナルにも当てる）。手元の端末が眠っても、ビルドやコーディングエージェントは止まらない。
- 接続が切れたら、手元の側が、すぐにつなぎ直して、同じシェルに戻る。速さと数は、入力のつなぎ直し（ADR 0007）と、同じにする。つなぎ直すたびに、権利を確かめる。
- 切れているあいだの出力は、シェルの口が、決まった量まで取っておき、戻ったときに流す。
- **切れているあいだに打った字は、送り直さない。** 入力と同じ決まりである（ADR 0007。遅れて届いた字は、変わってしまった画面に打たれる）。切れていることを、手元の側が見せる。
- 権利を外された端末が開いたシェルを、どうするかは、【問い 作8】。

### 2.7 許可を持つプログラムと、分ける（【提案】）

- Mac のホストのプログラムは、画面収録とアクセシビリティの許可を持つ（ADR 0017）。ADR 0017 は、開発の形について、「そのターミナルから起動したものは、どれも画面を読めて、入力を送れる」と書いている。許可を持つプログラムから始めたシェルが、同じ許可で動くなら、シェルの中のコマンドとコーディングエージェントが、画面を読めて、入力を送れることになる（推測。macOS が、許可を、起動した側のプログラムに結び付ける見込みのため）。
- これは、同じユーザーの線の 1 番（OS の許可の門を越える）と、ADR 0017 の「使わないこと」に反する。
- **シェルの口は、画面収録とアクセシビリティの許可を持つプログラムとは、別のプログラムにする。その子として始めない。** シェルの中から、画面が読めないこと、入力を送れないことを、Mac の実機で確かめる（進め方の案の受け入れ条件）。

### 2.8 同じユーザーの線と、シェルを開くこと

**はっきり書く。** シェルの代わりのプログラムは、どのターミナルからでも起動できる、コマンドである。持ち主が打って起動したのか、同じユーザーのほかのプログラムが起動したのかを、このプログラムは見分けられない（ADR 0024 が、URL について書いたことと同じ。ADR 0021 も、「確かめを通るプログラムが、命令を引数から受けるなら、確かめはそこで無くなる」と書いている）。

- つまり、「シェル」の権利を持つ端末では、**同じユーザーのどのプログラムも、ほかの機械でシェルを開ける。** ssh の鍵を持つ端末で、どのプログラムも `ssh` を起動できるのと、同じ強さである。
- 同じユーザーの線の 2 番（ペアリングの信頼を借りて、ほかの PC に届く）に、そのまま当たる。
- 【提案】形の土台：
  1. **シェルの代わりのプログラムは、端末の鍵を持たない。** 鍵を使い、通信路を張るのは、手元の Istesso のクライアント（鍵を守っている側。ADR 0021 の「鍵とペアの一覧は、ファイルから外す」）である。シェルの代わりのプログラムは、クライアントに頼む。
  2. こうすると、LAN につなぐのは、クライアントだけになる。macOS では、ターミナルから起動したプログラムが LAN につなぐには、起動元に、ローカルネットワークの許可が要る（ADR 0024 の記述。この文書では確かめていない）。クライアントが張る形なら、ターミナルのアプリごとに許可を出さずに済む見込みである（推測）。
  3. 開いているシェルは、いつも、手元の一覧で見える。新しく開いたら、手元に小さく知らせる。
  4. 開発の機械の側で届く範囲を、小さくする。シェルが、専用ユーザーの中で始まる機械（Ubuntu）では、届くのは、専用ユーザーの中までである。持ち主のユーザーで始まる機械（Studio）では、持ち主のアカウントの全部に届く（【問い 作3】）。
- そのうえで、**持ち主がいることを、いつ確かめるか**が、決めごとになる。【問い 作7】。ADR 0021 の「ペアを足す、権限を与えるときは、持ち主がいることを確かめる」と同じ部品を使うので、M5 と一緒に決める。

## 3. ターミナル以外のアプリ（決定 3）

- いまの道（開発の機械で動かして、映像で映す。ADR 0009、ADR 0010）を、変えない。この文書は、映像の道に、何も足さない。
- コードを直すための、画面のあるエディターも、この道で開く。ADR 0021 の決め（書けるエディターは、コーディングの専用ユーザーとして、開発の機械で動かす）と、合っている。
- ほかの機械の、画面のあるアプリで、プロジェクトの中身を**見る**ことは、マウントでできる（決定 1）。
- ブラウザーだけは、4 章の形で、別に扱う。R-01 の 1（手元で動くものは、手元で動かす。ブラウザ）と合っている。

## 4. ブラウザー、ポートの転送、URL を開く頼み（決定 4）

### 4.1 既定のブラウザー（【提案】）

- 設定は、「どの機械の、どのブラウザーか」の 1 組（決定 4）。初めの値は、手元の端末の、OS の既定のブラウザーにする。
- 決める単位（全体で 1 つか、プロジェクトごとか）と、開発のための別のプロファイルを選べるようにするかは、【問い 作9】。
- ブラウザーの機械が、開発の機械と同じなら、転送は要らない（その機械の中で、そのまま開く）。そのブラウザーの窓を、ほかの端末で見るときは、映像の道（決定 3）になる。
- ブラウザーの機械が止まっているときは、転送も、URL を開く頼みも、止まる。一覧に、そう出す。黙って、ほかの機械のブラウザーで開かない。

### 4.2 どのポートが、「作業場の中で開いた」ものか（【提案】）

次の全部を満たすもの。

1. TCP で、待ち受けている。
2. 待ち受けているプロセスが、その作業場で始めたものである。シェルの口が始めたシェルと、そこから始まったもの（コーディングエージェント、ビルド、開発サーバー）。
3. 待ち受けるアドレスが、その機械の中だけ（127.0.0.1、::1）か、全部（0.0.0.0、::）である。
4. Istesso 自身のポートではない。

入れないもの：UDP。ファイルの形の口（Unix ソケット）。作業場の外で始まったプログラムのポート（その機械のデータベース、ほかのプロジェクトの開発サーバー）。

### 4.3 開発の機械での見つけ方（【提案】）

どちらの OS でも、**見分けであって、守りではない。** 同じユーザーのプログラムは、印を外すことも、付けることもできる（下の表）。見つけるのは、シェルの口で、作業場のプロセスと同じユーザーで動く。root は使わない。

| | Linux | macOS |
|---|---|---|
| 作業場のプロセスを見分ける | シェルの口が、作業場ごとに、プロセスのまとまり（cgroup）を 1 つ作り、その中でシェルを始める。子は、親のまとまりを受け継ぐ（資料：cgroups(7)）。作り方は、ユーザーのサービス管理に、一時のまとまり（scope）を頼む（資料：systemd-run(1) の `--user --scope`）。専用ユーザーのサービス管理が、ログインなしで動いていること（linger。ADR 0014）が前提。Ubuntu の実機で、root なしにできるかは、確かめていない（推測） | まとまりの仕組みがない。**環境変数の印**を主にする：シェルの口が、シェルの環境に、作業場の ID を入れる。子は受け継ぐ。同じユーザーのプロセスの環境は、読める（実機：Air で、`ps -E` が、自分のプロセスの環境を表示した）。補いに、親子のつながりをたどる（実機：Air の SDK に `proc_listchildpids` と `PROC_PIDTBSDINFO` がある。親が先に終わったプロセスは、たどれなくなる＝推測） |
| 待ち受けているポートを知る | まとまりの中のプロセスの番号を並べ、それぞれが開いているソケットを `/proc/<番号>/fd` で見て（資料：proc_pid_fd(5)。ソケットは `socket:[番号]` の形で見える）、待ち受け中のソケットの一覧と照らす。`ss` も、待ち受け（`-l`）、プロセス（`-p`）、まとまり（`--cgroup`）を表示できる（資料：ss(8)） | プロセスごとに、開いているソケットを聞く（実機：Air の SDK に `PROC_PIDLISTFDS` と `PROC_PIDFDSOCKETINFO` がある。Air で `lsof -nP -iTCP -sTCP:LISTEN` を root なしで動かすと、待ち受けが 33 行出て、どれも自分のユーザーのものだった） |
| ほかのユーザーのプロセス | 見えない。`/proc/<番号>/fd` を読めるかは、OS の確かめ（ptrace の読む権利）で決まる（資料：proc_pid_fd(5)） | 見えない見込み（推測。上の `lsof` の結果と合う） |
| 印を外したプログラム | まとまりから出るには、行き先のまとまりへの書き込みの権利が要る（資料：cgroups(7)）。同じユーザーのまとまりのあいだなら、動ける見込み（推測）。出たものは、転送されない | 環境変数を消せば、印はなくなる。転送されない |
| 印を付けたプログラム | 同じユーザーのプログラムが、作業場のまとまりに入れば、そのポートは転送される（推測） | 同じユーザーのプログラムが、同じ環境変数を付ければ、そのポートは転送される |

- 見る間隔は、1 秒ほど（待ち受けが始まったことを知らせる、権利なしで使える仕組みは、見当たらない＝推測）。URL を開く頼みが来たときは、その場で見直してから、開く（開発サーバーが、待ち受けてすぐに「開く」を呼ぶため）。
- 待ち受けが消えたら、転送も消す。
- **コーディングエージェントの囲いと、ポート。** 囲いが、ネットワークを分ける形（別のネットワークの名前空間）になると、囲いの中の 127.0.0.1 は、外の 127.0.0.1 と別のものになり、ここの見つけ方も、運び方も、そのままでは届かない（推測）。囲いの調査（ADR 0026）によると、Ubuntu のホストでは、その形は、root で決まりを足さないかぎり使えない。ADR 0026 の提案は、名前空間を使わない形（Linux は Landlock、Mac は Seatbelt）なので、当面は、当たらない。かわりに、囲いが、**待ち受けること**を止めないようにする：Landlock は、待ち受けるポートも絞れる（ADR 0026）。開発サーバーの番号は、先に分からないので、待ち受けは絞らず、つなぐ側だけを絞る（【提案】）。

### 4.4 運び方（【提案】）

1. 開発の機械（シェルの口）が、見つけたポートの一覧を、ブラウザーの機械へ知らせる。1 行は、転送の ID、プロジェクト、ポートの番号、待ち受けているプロセスの名前（表示のため）。
2. ブラウザーの機械の Istesso のクライアントが、127.0.0.1 で待ち受ける（4.5）。
3. ブラウザーがつなぐと、クライアントは、通信路で、「この転送の ID に、接続を 1 本」と頼む。**番号も、アドレスも、送らない。**
4. 開発の機械は、ID から、自分の一覧を引き、自分の中のそのポートへつなぐ。一覧にない ID と、消えたポートは、断る。

- **行き先を決めるのは、いつも、開発の機械である。** 頼む側が、行き先を名指しできる形（何でも通す中継）にしない。ブラウザーの機械のプログラムが、この口を使って、開発の機械のほかのポートや、LAN のほかの機器に届くことはない。
- 中身には、触らない。HTTP の中身も、Host の行も、書き換えない。HTTPS も、WebSocket（開発サーバーが、画面の差し替えに使う）も、そのまま通る。
- 最初は、「ブラウザーの接続 1 本につき、通信路の接続 1 本」にする。自前で束ねる仕組みを作らない。ページを開くのが遅ければ、測ってから、束ねることを考える。
- 開発の機械から見ると、接続の出どころは、自分の 127.0.0.1 になる。「localhost からだけ受ける」開発サーバーにも、届く。望む動きだが、4.8 の危うさのもとでもある。

### 4.5 ブラウザーの機械での待ち受け（【提案】）

- **127.0.0.1 だけ**（決定 4）。0.0.0.0 では待ち受けない。LAN のほかの機器からは、届かない。::1 でも待ち受けるかは、【問い 作10】。
- **番号は、開発の機械と同じにする。** 開発サーバーが表示する URL が、そのまま使える。
- **ぶつかったら、ずらして、知らせる**（決定 4）。
  - ぶつかるとは：その番号を、ブラウザーの機械のだれかが使っている。または、その番号を、root なしでは開けない。Linux は、既定で、1024 より小さい番号を、ふつうのユーザーに開かせない（資料：カーネルの文書の `ip_unprivileged_port_start`、既定 1024）。macOS は、確かめていない（推測：版によって違う）。
  - 使っているかどうかは、127.0.0.1 と ::1 の両方で見る。片方だけを見ると、もう片方で待ち受けている別のプログラムに、ブラウザーがつながる恐れがある（推測。Vite の文書は、ブラウザーが、サーバーの待ち受けと違うアドレスを引くことがある、と書いている＝資料）。
  - ずらし方：次に空いている番号へ。root は、使わない。
  - 知らせ方：ブラウザーの機械の通知と、一覧（4.7）。**ターミナルの中には、書かない**（画面を使うプログラムの絵を壊す）。コーディングエージェントは、一覧を、読める形（JSON）で引ける。正しい URL を、人に伝えられる。
  - いちど割り当てた番号は、作業場が生きているあいだ、変えない。次に開くときも、同じ番号を先に試す。
  - 番号がずれると、ブラウザーが送る Host の行の番号も変わる。Vite は、`localhost` と IP アドレスの Host を、既定で受ける（資料：Vite の `server.allowedHosts`）。ほかのサーバーは、確かめていない。
- **固定もできる**（決定 4）。プロジェクトごとに、「開発の機械の番号 → ブラウザーの機械の番号」を決めておける。**固定した番号が使えないときは、ずらさずに、その転送を止めて、知らせる。** ログインの戻り先や、ページの出どころ（オリジン）の決まりが、番号に結び付いていることがあるので、黙って別の番号にしない。

### 4.6 URL を開く頼み（【提案】）

**頼みの出どころ（開発の機械）。**

- 作業場のシェルの環境に、`BROWSER` を、Istesso の小さなコマンドに向けて入れる。`BROWSER` を見る道具は、これで通る（資料：Vite は `BROWSER` を見る。ほかの道具は、確かめていない）。
- OS の「開く」のコマンド（Linux の `xdg-open`、macOS の `open`）を名前で呼ぶ道具のために、作業場の中でだけ、同じ名前の小さな代わりを、先に見つかる場所に置く。http と https の URL だけを受け取り、ほかの使い方は、元のコマンドへそのまま渡す。アプリごとの対応ではなく、OS の「開く」の口 2 つへの対応である。この 2 つを通らない開き方は、拾えない（下の「既知の不足」）。

**受ける側（ブラウザーの機械）。**

1. **http と https だけ**（決定 4）。ほかの種類は、断る。ファイルも、アプリを起動する種類の URL も、開かない。
2. 厳しく読む。制御文字、空白、長すぎるもの、ユーザー名やパスワードの入ったものは、断る。
3. 行き先が、開発の機械自身（`localhost`、`127.0.0.1`、`[::1]`、`0.0.0.0`）のとき：
   - その番号が、そのプロジェクトの転送にあれば、ブラウザーの機械の側の番号に置き換えて、開く。
   - 転送になければ、開かずに、知らせる。ブラウザーの機械の、関係のないポートを、開かせない。
4. それ以外の http と https は、既定のブラウザーで開く。自動で開くか、知らせてから開くかは、【問い 作11】。
5. 開くときは、OS の「開く」の口に、URL を、引数として渡す。シェルは、通さない。macOS の `open` は、URL を、既定のブラウザーで開く（実機：Air の `man open`）。
6. 続けて何度も頼まれたときのために、回数の上限を持つ。
7. 頼みを受けるのは、ブラウザーの機械が、そのプロジェクトの既定のブラウザーとして、その機械の持ち主に選ばれているあいだだけである。

**危うさ。** URL を開く頼みは、開発の機械のプログラム（コーディングエージェントを含む）が、持ち主のブラウザーを動かす口である。ADR 0024 が書いたとおり、URL からは、だれが頼んだかは分からない。

- 持ち主がログインしているブラウザーで、好きなページを開かせられる。
- URL に中身を載せれば、外へ出せる。コーディングエージェントのネットワークを「決まった宛先だけ」に絞っていても（ADR 0026 の範囲 (3)）、ここが抜け道になる。
- ブラウザーが前に出て、手元で打っているキーを取る。

【問い 作11】のおすすめは、これを小さくする形である。

### 4.7 一覧と、止めるスイッチ（【提案】）

- **一覧**（コマンドと、ランチャーの画面）：プロジェクト、開発の機械、向こうの番号、こちらの番号、ずらしたか、固定か、待ち受けているプロセスの名前、いま開いている接続の数、最後に使われた時刻。読める形（JSON）でも出す。
- **止める**：1 本だけ。プロジェクトの転送の全部。全部の転送（大きなスイッチ 1 つ）。止めると、待ち受けを閉じ、開いている接続を、1 秒以内に切る。**止めた状態は、覚える。勝手に戻らない。**
- プロジェクトごとに、「自動では転送しない（聞いてから）」を選べる。
- 新しいポートが転送に加わったら、知らせる。黙って増えない。
- 開発の機械の側でも、そこにいる持ち主が、「このプロジェクトのポートを、外へ出さない」を選べる。
- 転送が、いつまで続くかは、【問い 作10】。

### 4.8 同じユーザーの線との関係

**何が起きるか。**

- ブラウザーの機械の 127.0.0.1 で待ち受けているものには、**その機械の、どのプロセスからも届く。** 同じユーザーのほかのプログラムからも、ほかのユーザーのプログラムからも届く（推測：ループバックは、ユーザーで分かれない。ADR 0014 の「同じ PC のネットワークは、隔てない」と同じ）。ブラウザーの中のページと、拡張機能からも届く。
- つまり、転送のあいだは、**開発の機械の中だけで開いていたポートに、ブラウザーの機械のどのプログラムからも届く。** Istesso がなければ、届かなかったものである。同じユーザーの線の 2 番（ペアリングの信頼を借りて、ほかの PC に届く）に、そのまま当たる。
- これは、決定 4 の働きそのものでもある。ブラウザーが届くなら、同じ機械のほかのプログラムも届く。ブラウザーだけを通す仕組みは、OS にはない見込みである（推測）。ssh の、ポートを手元に引く機能と、同じ性質である。
- とくに重いのは、「localhost から来たものは信頼する」作りのサービス（デバッガーの口、管理の画面）が、作業場の中で開いたときである。ブラウザーの機械のプログラムが、開発の機械の上で、コードを動かせる口になりうる。開発の機械が、持ち主のユーザーで動く Mac（Studio）なら、届く先は、持ち主のアカウントの全部になる。
- ブラウザーの側の守り：Chrome は、公開のサイトのページが、ループバックや家の中のネットワークへ求めを送るときに、許可を尋ねるようになった（資料：Chrome for Developers の「Local Network Access」。Chrome 142 で、問いが入る。WebSocket などは、まだ対象の外、と書いてある）。ほかのブラウザーは、確かめていない。Istesso の守りとしては、数えない。

**小さく保つ形（【提案】）。** 線の「例外」として、範囲を書き、次で小さくする。

| # | 手 | 効くこと | 効かないこと |
|---|---|---|---|
| 1 | 行き先は、開発の機械が決める。頼む側は、ID だけ（4.4） | 開発の機械のほかのポート、LAN のほかの機器には、届かない | 一覧にあるポートには、届く |
| 2 | 作業場の中で開いたポートだけ（決定 4）。Istesso のポートは運ばない | その機械のほかのサービスは、出ない | 4.3 のとおり、見分けは、守りではない |
| 3 | 127.0.0.1（と ::1）だけ | LAN には、出ない | 同じ機械のプログラム |
| 4 | 一覧に全部見える。新しいポートは知らせる。止めるスイッチ。止めたら戻らない（4.7） | 気づける。すぐ閉じられる | 気づく前 |
| 5 | 転送は、セッションがあるあいだだけ（【問い 作10】） | 使っていない時間に、口が開いていない | 使っているあいだ |
| 6 | HTTP か、HTTPS の始まりの形をした接続だけを通す（【問い 作10】） | データベースなど、ブラウザーの使わない口が、まちがって出ることを減らす | **守りではない。** 害のあるプログラムは、HTTP を話せる |
| 7 | つないできたプログラムが、既定のブラウザーかを確かめる | 同じユーザーのほかのプログラムを、遅らせる | 確かめ方が弱い（推測：ほかのユーザーのプロセスは見えない。ブラウザーの中のページと拡張機能は、区別できない）。調べてから（【問い 作10】） |
| 8 | 開発のための、別のブラウザーのプロファイルを選べる（【問い 作9】） | 開発中のページが、ふだんのログインに届かない | ポートそのものには、届く |

- **この例外を受け入れるかどうか、どこまで小さくするか**は、持ち主が決める（【問い 作10】）。
- 開発の機械の側：転送は、開発の機械の同じユーザーのプログラムに、新しいものを与えない（もともと、その機械の 127.0.0.1 には届く）。ただし、4.3 の印を付ければ、自分のポートを、ブラウザーの機械へ出せる。出た先で、人がそれを開くかどうかは、URL を開く頼み（4.6）の話になる。

## 既知の不足

- **この文書は、実機で確かめていない。** Air で、読むだけのコマンドを動かした以外は、文書と、いまの ADR から書いた。Ubuntu と Studio は、見ていない。印が（推測）の文は、上の「確かめること」で確かめる。
- 作業場のプロセスの見分け（4.3）は、守りではない。同じユーザーのプログラムは、すり抜けられる。
- cd の切り替え（2.5）は、人がシェルで cd したときだけである。別の持ち主のフォルダーを指して動かしたコマンドは、元の機械で動く。書かないコマンドは、読むだけのマウントでも止まらない。
- URL を開く頼み（4.6）は、`BROWSER`、`xdg-open`、`open` を通らない開き方を、拾えない。拾えなかったものは、開発の機械のブラウザーで開くか、どこにも出ない。
- 番号がずれると、動かなくなるものがある（ログインの戻り先、ページの出どころの決まり）。固定で避ける。戻り先の番号が URL の中に書かれている場合、Istesso は、そこを書き換えない。
- ターミナルには、相手のプログラムが、手元のクリップボードに書く機能を持つものがある。通すかどうかは、ターミナルのアプリの設定で決まる（推測）。文字のコピーの決まり（ADR 0022、`trial-daily` ブランチ。この文書では、読んでいない）と、合わせて見る。
- 開発の機械を替える操作（引っ越し）は、ない。
- **Mac のつなぎの形（手元だけの NFS）には、マウントの相手の確かめがない**（1.5、【問い 作13】）。FSKit の形は、まだ、だれも試していない。
- マウントでは、開発の機械の側の変更が、見る側のアプリに、知らせとして届かないことがある（調査が、Air で見た）。見直せば、見える。
- Mac のフォルダーを、Linux で見るとき、大文字と小文字だけが違う名前を、取り違えうる。
- マウントを Istesso の道につなぐ所は、まだ作られていない（試作は、SSH の上で動かした）。Linux の見る側（FUSE）も、マウントを確かめただけである。
- 既定のブラウザーが AURA にあるときの形（Android の上の待ち受け）は、考えていない。M8 のあと。
- 出先（VPN 越し）で、文字が遅れるときの手（手元で先に字を出すなど）は、入れていない。
- Windows は、扱っていない。
- ADR 0010、0021、0024 は、`main` にない。それぞれのブランチの、2026-11-19 の時点の文面と突き合わせた。そのあとで変わったぶんは、見ていない。
