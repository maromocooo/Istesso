## 持ち主の決定（2026-11-19）

1. 【決定】**プロジェクトのフォルダーは、必ず 1 台の持ち物。**「ここで開発する」と決めた機械のもので、操作している端末のことではない。そこで始めたもの（シェル、エージェント、ビルド、開発サーバー）は、その機械で動く。同期や複製はしない。ほかの機械からは、マウントで見える・開けるだけ。
2. 【決定】**ターミナルは、文字で運ぶ。** ターミナルのアプリごとの対応はしない。どのターミナル（rio、ghostty、hyper など）でも動く、シェルの代わりの小さなプログラム 1 つで、相手の機械のシェルを、Istesso の暗号の道で運ぶ。タブや herdr のペインは、プロジェクトを指定して開く。cd で別の持ち主のフォルダーに入ったときは、新しいタブと同じ扱い。
3. 【決定】**ターミナル以外のアプリは、いまの道（持ち主の機械で動かして、映像で映す）が既定。** アプリごとの対応は作らない。
4. 【決定】**ブラウザー。** 既定のブラウザーを決める（どの機械の、どのブラウザーか）。作業場の中で開いたポートだけを、その機械の 127.0.0.1 に、自動で転送する。番号がぶつかったら、ずらして知らせる。固定もできる。URL を開く頼みは、既定のブラウザーへ。http と https だけ。転送中の一覧と、止めるスイッチ。

## 持ち主の決定と要件（2026-11-20）

6. 【決定】**メインのエディターは、形 A。** Istesso の設定で、メインのエディターを決めておく。ファイルを開くと、そのファイルがある機械でエディターが立ち上がり、窓が、映像の道で手元に出る。持ち主は、どの機械のファイルかを意識しない。書くのは、いつも、ファイルがある機械の側なので、切れても壊れない。設計は、3.1。
   - エディターのリモート機能を、Istesso の道で運ぶ形（B）は、いまは作らない。あとの候補。
7. 【決定】**マウントは、読むだけのまま。**（【問い 作2】の答え：(a)）
8. 【決定】**権利を取り消したときも、herdr とコーディングエージェントは止めない。その端末からのつなぎだけを切る。** 窓を閉じたとき、つながりが切れたときに残るものは、いまの設計のまま。（【問い 作8】の答え。2.6）

**要件（2026-11-20）：どこから使っても、同じ作業の続きができること。** Ubuntu や Studio の前に座って作業することもある。ふだんは、Air から Istesso で使う。どちらから入っても、同じ herdr のセッション、履歴、コーディングエージェントの会話、同じファイルの続きができること。この要件を足して、【問い 作3】を比べ直した（6 章）。

## 1. 作業場（決定 1）

### 1.1 プロジェクトの一覧（【提案】）

- **正本は、開発の機械が持つ。** 項目は、プロジェクトの ID（作るときに、開発の機械が決める、でたらめな値）、名前、その機械でのフォルダーの場所。
- ほかの機械は、制御チャンネルで聞いて、覚える。作りは、アプリ一覧（`istesso-catalog`）と同じにする。覚えたものは、信頼の根拠にしない（ADR 0007）。
- 開発の機械は、鍵の指紋（見せてよい値）で覚える。名前は、表示のためだけに使う（M6 の「覚えた行き先」と同じ覚え方）。
- **ほかの機械から頼めるのは、プロジェクトの ID だけ。** フォルダーの場所を、頼む側から受け取らない。開発の機械が、自分の一覧から引く。ADR 0010 の「頼めるのは、一覧にある ID だけ」、ADR 0021 の「行き先を外から受けない」と、同じ考えである。
- 「どの機械の持ち物か」は、フォルダーの中には書かない。フォルダーは Git で分け合うことがあり、機械の ID が公開の場所に載る。フォルダーを写せば、持ち主を名乗れることにもなる。フォルダーの中（`.istesso/`。M6 の `tasks.json` がある所）に置くのは、名前だけにする。
- 【決定】（2026-11-21。決定 22、持ち主の足し）同じリポジトリを 2 台にクローンしたら、別々のプロジェクトになる。各機械で ID を作り、同じ名前なら機械の名前を添えて並べる。Istesso は同期しない。
- 【提案】（読み。違えば直す）同じ ID は 2 台目に登録させない。ID が違えば、同じ名前でも登録できる。ADR 0013 のように、同じ場所のフォルダーを重ねることはしない（1.4）。

### 1.2 「ここで開発する」を決める（【提案】）

- 決めるのは、人である。人が機械を名指しするか、コーディングエージェントが、機械の「できること」の一覧（GPU、入っている道具、つないである実機。別の流れが作っている）から選び、人が確かめる。
- いちど決めたら、勝手に変わらない。開発の機械が止まっているときは、プロジェクトに「！」と「起こす」を出す。**黙って、ほかの機械で始めない**（R-04 と、M6 の受け入れ条件 B と同じ決まり）。
- 開発の機械を替えること（引っ越し）は、いまは作らない。別の機械でも開発したいときは、Git で持っていく。そのときは、別のプロジェクトとして、その機械の持ち物になる（下の「既知の不足」）。
- 【問い 作24】引っ越しの手順を作るか。いまのおすすめは、上の形。古い機械のプロジェクトは、人が外す。選ぶものは末尾の表。

### 1.3 そこで始めたものは、その機械で動く（【提案】）

- Istesso の口（シェル、コーディングエージェントの起動、タスク）は、プロジェクトの ID を受けたら、必ず、開発の機械で動かす。ほかの機械で動かす道を、持たない。
- 手元の端末が開発の機械でもあるとき（Air のプロジェクトを Air で開く）は、同じ口を、その機械の中で使う。使う人から見て、形が変わらない。
- **同期や複製はしない。** Istesso は、プロジェクトのフォルダーを、ほかの機械へ写し続ける操作を持たない。ビルドの生成物も写さない。

**方式と、残る提案。**

1. 【決定】（2026-11-21。決定 18）**Linux の見る側は、FUSE。** 条件を、いちばんよく満たす。ポートがなく、マウントしたユーザーだけが入れる。
2. 【決定】（2026-11-21。決定 21）**Mac の見る側は、製品では FSKit にする。** ポートがなく、Apple の公開の仕組みである。条件は、署名した配り方が決まること（M9、ADR 0021 の問い 26）と、使う人が、システム設定で 1 回、有効にすること（決定 21）。まだ、だれも試していない。配り方が決まったら、小さく試す。
3. 【決定】（2026-11-21。決定 18）手元だけの NFS は、持ち主 1 人の機械での試用だけ。ほかの人も使う Mac では、FSKit が使えないあいだ、既定ではマウントを出さない。相手を確かめる仕組みがないため（条件 3）。
   - 試すのは、見る側の機械にほかのユーザーがいないときだけ（別のユーザーのエージェントも含む）。
   - 同じユーザーで、囲いの中で動くコーディングエージェントには、囲いの決まりで、このポートを閉じる（ADR 0026 の形では、囲いは、手元の中継のポートだけを許す）。
   - 【決定】（2026-11-21。決定 19）同じユーザーの全部のプログラムに見える例外は、読むだけ、開いているプロジェクトだけに限る。一覧から止められる。囲いの中のエージェントには、マウントも見せない。
   - マウント先の親のフォルダーは、持ち主だけが入れる権限（0700）にする（調査：ホームは、グループに開いていた＝実）。
   - 穴を小さくする手を、試作で試す：マウントの頼みを、最初の 1 回だけ受ける。ファイルを指す札を、当てられない値にする。**これは、この文書の考えで、確かめていない（推測）。** 効くと分かるまで、守りには数えない。
4. 【調べる】つなぎに、合言葉つきの WebDAV などが使えるか。WebDAV はファイルの全体を取り、リンクを表せない弱みがある。
   - 【調べる】自分でビルドした版で FSKit を使うには、どの署名が要るか。
5. **機械のあいだは、自前の小さな頼み（一覧、属性、読む、リンクの行き先）で運ぶ。** NFS の手続きを、機械のあいだでは運ばない。開発の機械の側は、読む手続きしか持たないので、読むだけであることが、作りで決まる。ADR 0013 の `files` のメッセージと、「ファイル」の権利に合わせる。
6. プロジェクトの外を指すリンクは、リンクとしては見せず、「開けない項目」として見せる（条件 6。調査では、リンクが、見る側の機械の別のファイルを指した＝実）。
7. 見る側のアプリには、macOS が、最初に、「ネットワーク上のボリューム」の許可を尋ねる見込みである（推）。使う人向けの文書に書く。
8. 開発のあいだは、マウントの係も、計測の合図に従う（見る側の操作で、開発の機械に読み込みが起きるため）。

**試作のあと（2026-11-20）。** 別の流れが、Mac のつなぎの形（手元だけの NFS、読むだけ）を、Istesso の道につないだ（`proto-mount-channel` ブランチ。ADR 0007 の「フォルダーを読むだけで見せる」の節）。

- 機械のあいだは、SSH を使わずに、Istesso の道で運べた（試作・実機：Air から Ubuntu）。上の 5 の形である（自前の小さな頼み。書く頼みは、ない）。上の表の、条件 3 の「運べる見込み」は、「運べた」になった。
- 書く操作は、どれも断られ、開発の機械のフォルダーは変わらなかった（試作・実機）。決定 7 と合う。
- 【決定】（持ち主、2026-11-19 の夜。試作の ADR 0007 に記録）**Git が無視するものは、既定で見せない。`.git` も見せない。迷ったら、隠す。** `.env` のような秘密を、見る側の機械に出さないため。一覧に出ず、名指ししても「ない」と答える。大文字と小文字、Unicode の形だけが違う綴りでも、隠したものに届かなかった（試作・実機：Air の、大文字と小文字を区別しないボリュームと、Ubuntu）。持ち主は、フォルダーごとに「見せる」を選べる。**無視の規則は、秘密を守る仕組みではなく、出さないものを減らす目安である。** 規則に入れていない秘密は、見える。Git と違う所（Git が見せるものを隠すことがある、など）は、試作の ADR 0007 に並んでいる。

## 2. ターミナル（決定 2）

### 2.1 形（【提案】）

2 つの部分でできている。

**手元の側：シェルの代わりのプログラム。** ターミナルが、シェルの代わりに起動する。rio でも、ghostty でも、herdr のペインでも、同じプログラムである。

1. 手元のターミナルを、打った字をそのまま通す状態にする。
2. 開発の機械の「シェルの口」へ、Istesso の通信路（`istesso-link`。ADR 0007）でつなぐ。相手は、ペアリングした鍵で確かめる。
3. 打った字を送り、届いた字を、そのままターミナルに出す。窓の大きさが変わったら、知らせる。
4. 終わったら、ターミナルを元に戻し、相手のシェルの終了コードで終わる。

ターミナルのアプリごとの対応は、しない。色、カーソル、画面を使うプログラム（エディター、herdr）のための文字の並びは、手を加えずに通す。ターミナルが持つ機能は、ターミナルと、相手のプログラムのあいだで、そのまま働く。

**開発の機械の側：シェルの口。**

1. つないできた端末の権利を確かめる（「シェル」。決定 12、ADR 0026 の範8）。
2. プロジェクトの ID から、フォルダーを引く（1.1）。
3. 擬似端末（PTY。プログラムから見て、ターミナルに見える口）を作り、その機械のユーザーのシェルを、プロジェクトのフォルダーで始める。既定は持ち主のユーザー。分ける設定の機械だけ専用ユーザー（決定 9）。
4. 字を、両方向に運ぶ。

### 2.2 手元から受け取るもの、受け取らないもの（【提案】）

| もの | 扱い |
|---|---|
| プロジェクトの ID | 受け取る。フォルダーの場所は、受け取らない |
| 窓の大きさ（行と桁） | 受け取る |
| ターミナルの種類（`TERM`）と、色の対応（`COLORTERM`） | 受け取る。【提案】（2026-11-21、ブランチ `proto-shell-terminfo`。ADR 0007 の「ターミナルの種類の説明を送る」）手元は、その種類の説明（terminfo）の原文（手元の `infocmp -x` の出力）も送る。開発の機械が、その種類の説明を持っていなければ（開発の機械の `infocmp` に聞く）、送られた説明を、開発の機械の `tic` で組み立てて、エージェントの、持ち主だけが入れるフォルダーに置き、そのシェルの `TERMINFO_DIRS` の頭に入れる。`TERM` は替えない。この説明は `~/.terminfo` にも、シェルの設定ファイルにも書かない。導入時の 1 行は別（決定 12）。組み立てられないとき（説明が来ない、32 KiB を超える、`tic` がない、組み立てられない）は、広く通じる種類（`xterm-256color`）に替えて、そのことを 1 回知らせる。【決定】（2026-11-21。決定 30）エージェントの範囲の中では、説明が読めれば `TERM` を保つ。読めないときだけ `xterm-256color` に替えて 1 行知らせる。`--quiet` は、この行も隠す。新しいターミナルの種類を、相手の機械が知らなくて、画面が崩れることを防ぐ（2026-11-21 の朝、Studio で、Rio の `rio` が知られず、行の編集が崩れた） |
| そのほかの環境変数 | **受け取らない。** シェルの環境は、開発の機械のユーザーのものを使う |
| 動かすコマンド（`istesso sh <プロジェクト> -- <コマンド>` の形） | 【決定】（2026-11-21。決定 12）「シェル」と同じ権利で受ける。「タスク」の権利は、名前だけを受ける |
| 打った字、出力 | 運ぶだけ。**ログに書かない。** 記録するのは、いつ、どの端末が、どのプロジェクトのシェルを開いたか、終了コード、まで |

### 2.3 通信路とメッセージ（【提案】）

- **通信路の手順（`istesso-link`。ハンドシェイク、封のしかた）は、変えない。** 暗号の部品も足さない。映像と同じく、通信路をそのまま使う、長く続く接続にする（ADR 0007 の「映像」）。
- 足すのは、ハンドシェイクのあとのメッセージである。メッセージの追加なので、先頭の版（`ISC1`）は上げない。**作る前に、ADR 0007 のメッセージの一覧を、先に更新する**（AGENTS.md の 4）。
- 足すものの案（形は、試作の流れが決める）：プロジェクトの一覧。シェルを開く、字を運ぶ、窓の大きさ、終わり、「まだここにいる」。転送の一覧、転送の接続を 1 本開く（4 章）。URL を開く頼み（4 章）。
- **権利は、流れているあいだも、1 秒より長くは空けずに読み直す。** 外されたら、接続を切る。映像と入力が、同じことをしている（ADR 0006、ADR 0007）。ADR 0006 の「続いている接続のあいだに読み直すもの」に、シェルと転送を足す。
- 同時に開ける接続の数の枠を、制御と入力のぶんと、分ける。転送の接続が枠を使い切って、入力がつなぎ直せなくなることを防ぐ。
- 待ち受けるポートを分けるかは、M9 の「音、映像、入力を 1 つのポートに寄せるか」と合わせて決める。

### 2.4 タブと、herdr のペイン（【提案】）

- タブも、ペインも、「プロジェクトを指定して、シェルの代わりのプログラムを起動する」だけである（決定 2）。ターミナルの側の設定は、起動するコマンドを 1 行書くことだけになる。
- 【決定】（2026-11-21。決定 12）本体に herdr 専用の作りは入れない。入ったときに開く会は設定で選ぶ。机の前のターミナル、ssh、`ish` のどこからでも、同じ会、転送、ページやエディターの開き方を使う。外すものだけ一覧で選ぶ。
- 【決定】（2026-11-21。決定 13）herdr の会は開発の機械で動く。Air の herdr に各機械の会をまとめて見せる形を目指し、herdr 本体に提案する方向で進める。
- 【決定】（2026-11-21。herdr の機械の見え方への持ち主の答え）見え方は、herdr の試しの版で見たときと同じ。機械ごとに 1 つのまとまり（開け閉めできる）にして、その下に、その機械のものが全部並ぶ。機械は名指ししない。いつも全部を出し、切れた機械は薄く出て、ほかを止めない。1 つの機械にセッションが 2 つあっても、同じ機械のまとまりの下に並べる（進め方の案の W2 の 21）。
- herdr が、ペインごとに起動するコマンドを指定できるかは、確かめていない（herdr のソースは、ライセンスを確かめるまで読まない。ヘルプの表示で確かめる）。

### 2.5 cd で、別の持ち主のフォルダーに入ったとき（【提案】）

決定 2：新しいタブと同じ扱い。つまり、そのプロジェクトを指定して開いたのと同じになる（権利の確かめ、どの機械で動くか、が同じ）。

- **見つけ方。** シェルの口が、シェルの今のフォルダーを見る。Linux では `/proc/<番号>/cwd`（資料：proc_pid_cwd(5)）。macOS では `proc_pidinfo` の `PROC_PIDVNODEPATHINFO`（実機：Air の SDK のヘッダーに、この定数がある。ふるまいは推測）。シェルが入力を待っているときにだけ見る。この見つけ方には、シェルの設定の変更は要らない。導入のときだけ、持ち主の許しを得て、シェルの設定に 1 行足す。足すものは README に書く（決定 12）。
- **起きること。** 今のフォルダーが、マウントの下の、別の機械の持ち物だと分かったら、シェルの口が、手元の側に知らせる。手元の側は、その機械へ、そのプロジェクトのシェルを開き、同じタブを、そちらへ切り替える。切り替えたことを、1 行で知らせる（どの機械に移ったか）。そのシェルを終えると、元のシェルに戻る。
- 新しいタブと同じなので、シェルの中の状態（変数、履歴）は、持っていかない。
- 自動で切り替えるか、聞いてからにするかは、【問い 作6】。**持ち主は、試作に 2 分触ってから決める**（2026-11-20）。下に、試作の報告を入れた。

**試作の報告（2026-11-20。`proto-remote-shell` ブランチの `39d95b0`。ADR 0007 の「cd で、別の機械のフォルダーに入ったとき」の節）。** 印は、その流れのもの。**この節のはじめの案（シェルの口が、今のフォルダーを見る）とは、仕組みが違う。** 試作は、手元のシェル（zsh）に、持ち主が自分で読み込む、短いファイル 1 つである。試作は設定ファイルに書かず、読み込んだシェルでだけ効いた。導入のときだけ、持ち主の許しを得て、シェルの設定に 1 行足す。足すものは README に書く（決定 12）。【提案】何を足すかは、コードができたときに決める（読み。違えば直す）。

| 見たいこと | 試作で、どうなったか |
|---|---|
| 何が起きるか | プロンプトで打った `cd` で、別の機械のマウントの場所（`~/Istesso/<機械>/<場所>`）の下に入ると、同じタブが、その機械のシェルになる。`exit` で、手元のシェルに戻る。戻ったシェルは、cd の前の場所にいる。`cd -` で、その機械のフォルダーに入り直すことはない（試作・実機：Air から Ubuntu。マウントは、まだないので、代わりのフォルダーで確かめた） |
| 環境変数 | **何も渡らない。** 手元のプログラムが送るのは、窓の大きさ、`TERM`、言語、フォルダーだけ（2.2 と同じ）。手元で設定した、鍵の係の口、トークン、設定の場所は、渡らなかった（試作・実機）。相手から手元へも、何も戻らない |
| 履歴 | 手元の履歴には、打った `cd` の行だけが残る。相手で打ったものは、相手のシェルの履歴に入る（試作・実機） |
| スクリプトの中の cd | **切り替わらない。** スクリプト（別のプロセス）は、このファイルを読み込まない。関数の中、`source` したファイルの中、サブシェルと `$(…)` の中、`pushd` と `popd`、`cd -q`、出力を向け直した cd、Tab の補完も、切り替わらない（試作・実機） |
| 1 行に続けたとき | `cd x && make` をプロンプトで打つと、切り替わる。戻ったあとに、`make` は、**手元で**動く（試作の流れの推測）。マウントは読むだけなので、書くビルドは、止まって、目に見える |
| フォルダーの名前だけを打つ設定（`AUTO_CD`） | 切り替わる（試作・実機） |
| 失敗したとき | その機械の口がない、相手にフォルダーがない、相手が答えない：1 行知らせて、手元にとどまる（試作・実機） |
| herdr のペイン | 試していない。読み込んだシェルのペインでだけ、切り替わる見込み（試作の流れの推測） |

- 限りは、下の「限り」と同じである：見つけるのは、人がプロンプトで打った cd だけ。
- 試作の流れは、マウントの場所と、機械の名前（短い呼び名）を、1.5 の「同じ場所」と、プロンプトの問い（試作の ADR 0007）に合わせることを、【問い】にしている。マウントの場所は、試すあいだは (ア)、製品は (イ) に決まった（決定 20）。

### 2.6 切れたとき、戻るとき、権利を取り消したとき（【決定】8 と、【提案】）

- 【決定 8】**権利を取り消したとき（ペアリングの解除を含む）は、その端末からのつなぎだけを切る。herdr とコーディングエージェントは、止めない。** 切るもの：その端末の、シェルの接続、転送の接続、マウントの接続。1 秒以内（2.3）。残るもの：窓を閉じたとき、つながりが切れたときに残るものと、同じ。
- **何が残るか（試作で見た形。`proto-remote-shell` ブランチ）。** 試作は、接続が終わると、その接続のシェルに、端末が閉じた合図を送る。窓を閉じたときも、長く切れたときも、権利を外したときも、同じである。そのシェルと、その端末を持っていたものは、終わる。herdr のように、端末から離れて動くものは、残る（試作・実機：持ち主が、Air から Ubuntu で使った。ターミナルを閉じても、herdr とコーディングエージェントは残った）。
- **前の提案（取り下げた）。** **同じシェルへ戻る仕組みは、作らない。続きを持つのは、開発の機械の上の herdr。** この節のはじめの案（シェルそのものが生き続け、つなぎ直して、同じシェルに戻る。切れているあいだの出力を、取っておく）は、取り下げる。試作の流れのおすすめ（「同じシェルへ戻る形は、作らない。続ける役は、herdr に任せ、Istesso は、開き直すだけ」）に合わせる。理由：決定 8 の「いまの設計のまま」が指すのは、持ち主が使った、この形である。要件（どこから使っても、同じ続き。6 章）も、続きが herdr にあることで満たせる。作るものが、減る。herdr を使わない素のシェルは、窓と一緒に終わる（ssh と同じ）。
- 【提案】（持ち主の決め 2026-11-21、決めること 5「作る」）**上の「同じシェルへ戻る仕組みは、作らない」は、取り下げる。herdr を使わない素のシェルも、同じシェルへ戻れるようにする。** 持ち主の形：新しい窓で `ish` と打ったとき、持ち主を待っているシェルがあれば、それに戻る（なければ新しく作る）。`ish <プロジェクトの名前>` は、そのプロジェクトで最後に使っていたシェルに戻る。何も付けなければ、最後に閉じたシェルに戻る。わざと新しいシェルが欲しいときは `--new`。窓を 1 つ閉じて 1 つ開く、ふだんの使い方では、ホストのシェルが増えない（試験に入れる）。待つ時間と数の上限は、取りこぼしを片付ける安全網として置く。試作は `proto-shell-resume`（ADR 0007「同じシェルに戻る（herdr なし）」）。【決定】（2026-11-21。決定 29）待つのは最大 8 時間、端末ごとに 4 つ、ホストごとに 8 つまで。無通信の接続は 25 秒で切る。待つシェルのスコープは、そのシェルに戻るまで止める。転送の預かり手を組み合わせたあとで見直す。長い仕事の続きを持つのは、これまでどおり herdr である。
- 【提案】（別の見直しの指摘）**待っているシェルに戻ることと、権利の取り消し。** 待っているシェルに戻るときも、開き直すときと同じく、その端末の「シェル」の権利を確かめる（2.3）。権利を取り消された端末は、自分が残したシェルにも戻れない。【決定】（2026-11-21。決定 32）取り消しでは、待っているシェルも、herdr とペインも、止めない。待っているシェルは、上限（8 時間）で終わる。持ち主は、ホストの一覧から終えられる。【提案】（読み。違えば直す）持ち主のほかの端末から、取り消された端末が残したシェルに戻れるかは、tmux と同じく戻れる形と、開いた端末だけに結ぶ形（「端末ごとに 4」と同じ単位）がある。おすすめ：開いた端末だけに結ぶ。なくした端末で打たれたものに、ほかの端末で気づかずに続けて打つことを避けるため。
- 手元の端末が眠っても、herdr の中のビルドやコーディングエージェントは、止まらない（R-03 の考え）。
- 切れたら、手元の側は、切れたことを見せて終わる。**開き直すと、何も打たずに、前のプロジェクトに戻る**（試作は、端末ごとに、最後に開いたフォルダーを、手元に覚える。覚えは、手元の便利のためで、開発の機械の側の確かめには、関わらない）。開き直すたびに、権利を確かめる。
- **切れているあいだに打った字は、送り直さない。** 入力と同じ決まりである（ADR 0007。遅れて届いた字は、変わってしまった画面に打たれる）。
- **決定 8 で、残るもの。** 取り消された端末（なくした端末）が始めたビルドやコーディングエージェントは、動き続ける。止めるのは、ホストにいる持ち主か、権利のある、ほかの端末である。Istesso が出せるのは、「その端末が、いつ、どのプロジェクトのシェルを開いたか」の記録までで、herdr の中の、どれが、その端末から始まったかは、分からない（推測：herdr の中は、Istesso からは見えない）。

### 2.7 許可を持つプログラムと、分ける（【提案】）

- Mac のホストのプログラムは、画面収録とアクセシビリティの許可を持つ（ADR 0017）。ADR 0017 は、開発の形について、「そのターミナルから起動したものは、どれも画面を読めて、入力を送れる」と書いている。許可を持つプログラムから始めたシェルが、同じ許可で動くなら、シェルの中のコマンドとコーディングエージェントが、画面を読めて、入力を送れることになる（推測。macOS が、許可を、起動した側のプログラムに結び付ける見込みのため）。
- これは、同じユーザーの線の 1 番（OS の許可の門を越える）と、ADR 0017 の「使わないこと」に反する。
- **シェルの口は、画面収録とアクセシビリティの許可を持つプログラムとは、別のプログラムにする。その子として始めない。** シェルの中から、画面が読めないこと、入力を送れないことを、Mac の実機で確かめる（進め方の案の受け入れ条件）。

### 2.8 同じユーザーの線と、シェルを開くこと

**はっきり書く。** シェルの代わりのプログラムは、どのターミナルからでも起動できる、コマンドである。持ち主が打って起動したのか、同じユーザーのほかのプログラムが起動したのかを、このプログラムは見分けられない（ADR 0024 が、URL について書いたことと同じ。ADR 0021 も、「確かめを通るプログラムが、命令を引数から受けるなら、確かめはそこで無くなる」と書いている）。

- つまり、「シェル」の権利を持つ端末では、**同じユーザーのどのプログラムも、ほかの機械でシェルを開ける。** ssh の鍵を持つ端末で、どのプログラムも `ssh` を起動できるのと、同じ強さである。
- 同じユーザーの線の 2 番（ペアリングの信頼を借りて、ほかの PC に届く）に、そのまま当たる。
- 【提案】形の土台：
  1. **シェルの代わりのプログラムは、端末の鍵を持たない。** 鍵を使い、通信路を張るのは、手元の Istesso のクライアント（鍵を守っている側。ADR 0021 の「鍵とペアの一覧は、ファイルから外す」）である。シェルの代わりのプログラムは、クライアントに頼む。
  2. こうすると、LAN につなぐのは、クライアントだけになる。macOS では、ターミナルから起動したプログラムが LAN につなぐには、起動元に、ローカルネットワークの許可が要る（ADR 0024 の記述。この文書では確かめていない）。クライアントが張る形なら、ターミナルのアプリごとに許可を出さずに済む見込みである（推測）。
  3. 開いているシェルは、いつも、手元の一覧で見える。新しく開いたら、手元に小さく知らせる。
  4. 開発の機械で届くのは、シェルを始めたユーザーの範囲まで。
     - 【提案】（持ち主の決め 2026-11-21、決定 9 のあと）**既定では、どの機械でも、シェルは持ち主のユーザーで始まる。だから、「シェル」の権利を持つ端末は、開発の機械の、持ち主のアカウントの全部に届く**（ssh で入るのと同じ）。専用ユーザーの中までに小さくなるのは、分ける設定を選んだ機械だけである。
- 持ち主を確かめるときは、ADR 0021 の「ペアを足す、権限を与えるときは、持ち主がいることを確かめる」と同じ部品を使う案である。シェルを開くときの既定は決定 10、設定で確かめるときは決定 28。
- 【提案】（持ち主の決め 2026-11-21。決定 10）**既定では、シェルを開くときに、持ち主がいることを確かめない。** 強さは、ssh の鍵を持つ端末と同じである。【提案】（別の見直しの指摘）ただし、端末の鍵がファイルに置かれているあいだ（ADR 0021 の問い 27 の、鍵の守りの層が入るまで）は、そのファイルを写した者は、ほかの所からも、その端末としてシェルを開ける。合言葉のない ssh の鍵を、ファイルに置いたときと同じで、端末を外すまで効く。写しを見つける仕組みは、ADR 0021 の問い 27 の層 1（ブランチ `m5-design` の系列で設計している）。これは、ADR 0021 の同じユーザーの線（2 番：ペアリングの信頼を借りて、ほかの PC に届く）の**例外**として、はっきり書く：「シェル」の権利を持つ端末の上では、同じユーザーのどのプログラムも、確かめなしに、ほかの機械でシェルを開ける。
  - 席を離れるときの守りは、手元の端末の画面のロックである（持ち主の考え）。ロックしている端末の上で動いている、同じユーザーのプログラムは、止まらない（ロックは、人の手を止めるもので、プログラムを止めない）。そのことも、例外の文に書く。
  - **「確かめる」は、選べる設定として残す**（持ち歩く端末や、心配な人のため）。【決定】（2026-11-21。決定 28）端末ごとに選ぶ。確かめたら、開いてよい時間を設ける。画面をロックしたら、その時間は終わる。
  - ペアを足す、権利を与えるときの確かめ（ADR 0021 の線の 7）は、この決定とは別のもので、変わらない。
  - 上の形の土台（1〜4）は、変わらない。開いているシェルは、手元の一覧で見え、新しく開いたら、手元に小さく知らせる（3）。
- 【決定】（2026-11-21。決定 31）**範囲の中からの頼み。** 範囲の中のコーディングエージェントが、`ish` で別の機械のシェルを開こうとしたら、段 (1)〜(3) では、断るか、持ち主に聞く。`istesso open`（3.1 の入口 3：範囲つきのコーディングエージェントからの頼みは、すぐには開かず、手元に知らせを出し、持ち主が押したら開く）と同じ扱いである。範囲の中から、別の機械や、範囲のないシェルを開けると、範囲の外に出られるためである。
  - 【提案】同じ扱いを、転送の頼みと、コーディングエージェントを起こす頼みにも当てる。範囲の中で動くプロセス（コーディングエージェントと、その子）からの頼みを、範囲の係が見分ける。手元の端末の「シェル」の権利は、範囲の中のプロセスには渡らない。
  - 範囲の外で始めたもの（持ち主のシェルで直接始めたもの）からの頼みは、持ち主が打ったものと見分けられない（上の「はっきり書く」と同じ）。ADR 0026 の「既知の不足」に書いた。

## 3. ターミナル以外のアプリ（決定 3）

- いまの道（開発の機械で動かして、映像で映す。ADR 0009、ADR 0010）を、変えない。この文書は、映像の道に、何も足さない。
- コードを直すための、画面のあるエディターも、この道で開く。ADR 0021 の決め（書けるエディターは、コーディングの専用ユーザーとして、開発の機械で動かす）と、合っている。

- ブラウザーだけは、4 章の形で、別に扱う。R-01 の 1（手元で動くものは、手元で動かす。ブラウザ）と合っている。

### 3.1 メインのエディターで開く（決定 6。形 A）

**形。** メインのエディターは、ファイルがある機械（開発の機械）で動く。窓は、いまの映像の道（決定 3）で、手元に出る。書くのは、開発の機械の中だけなので、マウントは、読むだけのままでよい（決定 7）。つながりが切れても、ファイルは壊れない。新しい道は、作らない。足すのは、「このファイルを、メインのエディターで開いて」という頼み 1 つである。

**設定（【提案】）。**

- 「メインのエディター」は、Istesso の設定に 1 つ。値は、アプリの一覧（`istesso-catalog`）の ID である。コマンドの行は、設定に書かない（ADR 0010：頼めるのは、一覧にある ID だけ）。機械ごとに、その ID が、その機械に入っているエディターを指す。
- プロジェクトごとに、上書きできる（iOS のプロジェクトは、Xcode、など）。
- エディターが動くユーザーは、作業場のユーザーである（【問い 作3】。6 章）。【提案】（決定 9 のあと）既定では、持ち主のユーザー。分ける設定を選んだ機械では、コーディングの専用ユーザー（ADR 0021 の問い 16 の案 A）。

**頼みの形（【提案】）。**

- 頼みが運ぶのは、**プロジェクトの ID、プロジェクトの中での相対の場所、（あれば）行の番号**だけ。絶対の場所も、コマンドも、運ばない。開発の機械が、自分の一覧からフォルダーを引き（1.1）、その下の場所を、名前 1 つずつ、リンクをたどらずに確かめる（試作のマウントの、受け側と同じ確かめ方）。プロジェクトの外に出る場所は、断る。
- 開発の機械は、メインのエディターを、アプリを起動するいまの口（ADR 0010）で始め、ファイルの場所を、引数 1 つとして渡す。シェルは、通さない。ADR 0010 の「引数は、受け取らない」に、1 つだけ足すことになる：**渡す引数は、頼む側の文字ではなく、開発の機械が、自分で引いて確かめた場所である。** 採用されたら、ADR 0010 に書く。
- 窓は、頼んだ端末に、映像の道で出す。エディターがすでに動いていれば、そのエディターに渡る見込み（推測：2 つめの起動を、動いている窓に渡すかは、エディターによる）。
- 要る権利：窓を出して操作するので、「操作」。それと、そのプロジェクトが見えること（「ファイル」か「シェル」。ADR 0026 の範8 の決定）。
- ファイルが、手元の端末のもの（Air のプロジェクトを、Air で開く）なら、同じ頼みが、その機械の中で済む。映像は、使わない。持ち主が打つものは、同じである。

**開き方は、3 つ（持ち主の頼み）。** どれも、同じ頼みに行き着く。入口のコマンドは 1 つ（仮の名前：`istesso open <ファイル>[:<行>]`）。

| 入口 | 流れ | 限り |
|---|---|---|
| 1. マウントの中のファイルを、手元で開く | 手元の Istesso が、マウントの下の場所を、（機械、プロジェクト、相対の場所）に直して、頼む。入口は 3 つ：(ア) `istesso open <マウントの下の場所>`。(イ) Finder の「このアプリケーションで開く」に、Istesso のクライアントを出す。(ウ) Istesso のランチャーの窓に、ファイルを落とす | **ふつうのダブルクリックは、手元の機械の、その種類の既定のアプリで開く**（推測：macOS は、開くアプリを、ファイルの種類で決め、置いてある場所では決めない）。読むだけなので、見るには足りる。保存は断られて、目に見える。ダブルクリックでメインのエディターに行かせるには、その種類の既定のアプリを、持ち主が、自分で Istesso のクライアントに替える。**Istesso は、持ち主の既定のアプリを、替えない。**（イ）は、クライアントが、「どの種類のファイルも開ける、別のアプリ」として名乗ればできる見込み（推測）。【決定】（2026-11-21。決定 23）入口は (a)。ふだんのダブルクリックの行き先は替えない。 |
| 2. ターミナルから開く | 作業場のシェルの中で、`istesso open <ファイル>`。開発の機械の側のコマンドなので、その機械の Istesso に、機械の中の口で頼む（URL を開く頼みと同じ口。4.6）。窓は、そのシェルをつないでいる端末に出る。手元のシェルで、マウントの下の場所を渡したときは、入口 1 の (ア) と同じ | `EDITOR` と `VISUAL` は、Istesso からは入れない。`git commit` などは、終わるまで待つ、ターミナルの中のエディターを当てにしている（推測）。持ち主の設定のままにする |
| 3. コーディングエージェントが、「このファイルを見て」と出したとき | コーディングエージェントが、同じコマンドを呼ぶ（`istesso open <ファイル>:<行>`）。使い方は、起動の係が、ツールの設定で教える（ADR 0026 の決定 15）。【決定】（2026-11-21。決定 23）**範囲つきで起動したコーディングエージェントからの頼みは、すぐには開かない。** 手元に、知らせを出す：「（プロジェクト）のコーディングエージェントが、`src/…` を見てほしいと言っています。［開く］」。持ち主が押したら、開く | ターミナルに出た場所の文字を、押せるようにする形は、ターミナルのアプリによる。頼らない（決定 2：アプリごとの対応はしない）。起動の係を通さずに動いているコーディングエージェントからの頼みは、持ち主が打ったものと、見分けられない（2.8 と同じ）。そのときは、すぐ開く |

**入口 3 を、知らせにする理由。** 開く頼みは、開発の機械のプログラムが、手元の画面に窓を出す口である。URL を開く頼み（4.6）と、同じ性質を持つ：窓が前に出て、手元で打っているキーを取る。続けて頼まれると、仕事にならない。だから、決定 16 の外の URL と同じく、押してから開く。回数の上限を持つ。開けるのは、そのプロジェクトの中の場所だけである。

**各機械に、同じエディターと設定が要ること。どう知らせるか（【提案】）。** W6 の「足りないものを知らせる」と、1 つの仕組みにする。

1. **あるか、ないか。** 機械の「できること」の一覧（W1。入っている道具）に、メインのエディターを入れる。プロジェクトの一覧に、開発の機械ごとの印を出す：ある／ない／版が違う。プロジェクトを開く前の「足りないもの」（W6）に、「この機械に、メインのエディターがない。この機械で、これを 1 回」と、1 行で出る。開こうとしたときにも、同じ 1 行が、手元に出る。黙って、別のエディターや、別の機械で開かない。
2. **設定が同じか。** Istesso は、エディターの設定を、機械のあいだで写さない（決定 1：同期や複製はしない。持ち主のエディターの設定に、Istesso は書かない）。知らせるだけにする。どのファイルが「エディターの設定」かは、エディターごとに違い、Istesso は、エディターごとの対応を持たない（決定 3）。だから、**持ち主が、設定の置き場を名指しする**（機械ごとに、フォルダーかファイルの一覧。初めは、空）。Istesso は、その中身の指紋（ハッシュ）だけを、機械のあいだで比べ、「同じ／違う／ない」と、どの機械が新しいかを出す。中身は、機械の外へ出さない（設定に、トークンが入っていることがある）。そろえるのは、持ち主である（エディター自身の同期の機能か、Git で持つ）。
3. **作業場のユーザーが、持ち主のユーザーと違う機械**（6 章の a か b を選んだ機械）では、同じ機械の中でも、設定は 2 か所になる。エディターは、作業場のユーザーの設定で動く。上の 1 と 2 は、「機械」ではなく、「機械とユーザーの組」ごとに見る。
4. 順番：1 は、W2b と W6 に入れる。2 は、持ち主が、設定の違いで困った場面を書き出してから（W7）。

**どの段に入れるか（【提案】）。** 芯（設定、頼み、入口 2、「エディターがない」の知らせ）は、W2 の後半（W2b）。入口 1 は、W3。入口 3 の知らせは、W5。進め方の案に書いた。

**エディターのリモート機能を、Istesso の道で運ぶ形（B）は、いまは作らない。あとの候補。**

**限り。**

- エディターは、プロジェクトの中のものを動かすことがある（タスク、拡張機能、プロジェクトごとの設定＝推測）。エディターが動くユーザーの力で動く。Ubuntu で、作業場のユーザーが専用ユーザーなら、その中にとどまる。Studio では、持ち主のアカウントの全部に届く。【提案】（決定 9 のあと）既定では、どの機械でも、持ち主のアカウントの全部に届く。専用ユーザーの中にとどまるのは、分ける設定を選んだ機械だけ。
- 窓は、映像の道で出る。字の見え方と遅延は、映像の道のものである（M1 の基準）。
- 開発の機械が止まっているときは、開けない。「！」と「起こす」を出す（1.2）。

## 4. ブラウザー、ポートの転送、URL を開く頼み（決定 4）

### 4.1 既定のブラウザー（【提案】）

- 設定は、「どの機械の、どのブラウザーか」の 1 組（決定 4）。初めの値は、手元の端末の、OS の既定のブラウザーにする。
- 【決定】（2026-11-21。決定 14）全体で 1 つ、プロジェクトごとに上書きできる。既定はふだんのプロファイルで、開発用も選べる。持ち主のふだんの設定は変えない。
- 【提案】（読み。違えば直す）どの端末からも同じログインとタブの続きを使うには、その機械のブラウザーを、持ち主のユーザーで動かす（作22、決定 27）。
- ブラウザーの機械が、開発の機械と同じなら、転送は要らない（その機械の中で、そのまま開く）。そのブラウザーの窓を、ほかの端末で見るときは、映像の道（決定 3）になる。
- ブラウザーの機械が止まっているときは、転送も、URL を開く頼みも、止まる。一覧に、そう出す。黙って、ほかの機械のブラウザーで開かない。

### 4.2 どのポートが、「作業場の中で開いた」ものか（【提案】）

次の全部を満たすもの。

1. TCP で、待ち受けている。
2. 待ち受けているプロセスが、その作業場で始めたものである。シェルの口が始めたシェルと、そこから始まったもの（コーディングエージェント、ビルド、開発サーバー）。
3. 待ち受けるアドレスが、その機械の中だけ（127.0.0.1、::1）か、全部（0.0.0.0、::）である。
4. Istesso 自身のポートではない。

入れないもの：UDP。ファイルの形の口（Unix ソケット）。作業場の外で始まったプログラムのポート（その機械のデータベース、ほかのプロジェクトの開発サーバー）。

### 4.3 開発の機械での見つけ方（【提案】）

どちらの OS でも、**見分けであって、守りではない。** 同じユーザーのプログラムは、印を外すことも、付けることもできる（下の表）。見つけるのは、シェルの口で、作業場のプロセスと同じユーザーで動く。root は使わない。

| | Linux | macOS |
|---|---|---|
| 作業場のプロセスを見分ける | シェルの口が、作業場ごとに、プロセスのまとまり（cgroup）を 1 つ作り、その中でシェルを始める。子は、親のまとまりを受け継ぐ（資料：cgroups(7)）。作り方は、ユーザーのサービス管理に、一時のまとまり（scope）を頼む（資料：systemd-run(1) の `--user --scope`）。専用ユーザーのサービス管理が、ログインなしで動いていること（linger。ADR 0014）が前提。Ubuntu の実機で、root なしにできるかは、確かめていない（推測） | まとまりの仕組みがない。**環境変数の印**を主にする：シェルの口が、シェルの環境に、作業場の ID を入れる。子は受け継ぐ。同じユーザーのプロセスの環境は、読める（実機：Air で、`ps -E` が、自分のプロセスの環境を表示した）。補いに、親子のつながりをたどる（実機：Air の SDK に `proc_listchildpids` と `PROC_PIDTBSDINFO` がある。親が先に終わったプロセスは、たどれなくなる＝推測） |
| 待ち受けているポートを知る | まとまりの中のプロセスの番号を並べ、それぞれが開いているソケットを `/proc/<番号>/fd` で見て（資料：proc_pid_fd(5)。ソケットは `socket:[番号]` の形で見える）、待ち受け中のソケットの一覧と照らす。`ss` も、待ち受け（`-l`）、プロセス（`-p`）、まとまり（`--cgroup`）を表示できる（資料：ss(8)） | プロセスごとに、開いているソケットを聞く（実機：Air の SDK に `PROC_PIDLISTFDS` と `PROC_PIDFDSOCKETINFO` がある。Air で `lsof -nP -iTCP -sTCP:LISTEN` を root なしで動かすと、待ち受けが 33 行出て、どれも自分のユーザーのものだった） |
| ほかのユーザーのプロセス | 見えない。`/proc/<番号>/fd` を読めるかは、OS の確かめ（ptrace の読む権利）で決まる（資料：proc_pid_fd(5)） | 見えない見込み（推測。上の `lsof` の結果と合う） |
| 印を外したプログラム | まとまりから出るには、行き先のまとまりへの書き込みの権利が要る（資料：cgroups(7)）。同じユーザーのまとまりのあいだなら、動ける見込み（推測）。出たものは、転送されない | 環境変数を消せば、印はなくなる。転送されない |
| 印を付けたプログラム | 同じユーザーのプログラムが、作業場のまとまりに入れば、そのポートは転送される（推測） | 同じユーザーのプログラムが、同じ環境変数を付ければ、そのポートは転送される |

- 見る間隔は、1 秒ほど（待ち受けが始まったことを知らせる、権利なしで使える仕組みは、見当たらない＝推測）。URL を開く頼みが来たときは、その場で見直してから、開く（開発サーバーが、待ち受けてすぐに「開く」を呼ぶため）。
- 待ち受けが消えたら、転送も消す。
- **コーディングエージェントの囲いと、ポート。** 囲いが、ネットワークを分ける形（別のネットワークの名前空間）になると、囲いの中の 127.0.0.1 は、外の 127.0.0.1 と別のものになり、ここの見つけ方も、運び方も、そのままでは届かない（推測）。囲いの調査（ADR 0026）によると、Ubuntu のホストでは、その形は、root で決まりを足さないかぎり使えない。ADR 0026 の提案は、名前空間を使わない形（Linux は Landlock、Mac は Seatbelt）なので、当面は、当たらない。かわりに、囲いが、**待ち受けること**を止めないようにする：Landlock は、待ち受けるポートも絞れる（ADR 0026）。開発サーバーの番号は、先に分からないので、待ち受けは絞らず、つなぐ側だけを絞る（【提案】）。

### 4.4 運び方（【提案】）

1. 開発の機械（シェルの口）が、見つけたポートの一覧を、ブラウザーの機械へ知らせる。1 行は、転送の ID、プロジェクト、ポートの番号、待ち受けているプロセスの名前（表示のため）。
2. ブラウザーの機械の Istesso のクライアントが、127.0.0.1 で待ち受ける（4.5）。
3. ブラウザーがつなぐと、クライアントは、通信路で、「この転送の ID に、接続を 1 本」と頼む。**番号も、アドレスも、送らない。**
4. 開発の機械は、ID から、自分の一覧を引き、自分の中のそのポートへつなぐ。一覧にない ID と、消えたポートは、断る。

- **行き先を決めるのは、いつも、開発の機械である。** 頼む側が、行き先を名指しできる形（何でも通す中継）にしない。ブラウザーの機械のプログラムが、この口を使って、開発の機械のほかのポートや、LAN のほかの機器に届くことはない。
- 中身には、触らない。HTTP の中身も、Host の行も、書き換えない。Web のほかは、持ち主が名指しして許した番号だけ（決定 15）。HTTPS も、WebSocket（開発サーバーが、画面の差し替えに使う）も、そのまま通る。
- 最初は、「ブラウザーの接続 1 本につき、通信路の接続 1 本」にする。自前で束ねる仕組みを作らない。ページを開くのが遅ければ、測ってから、束ねることを考える。
- 開発の機械から見ると、接続の出どころは、自分の 127.0.0.1 になる。「localhost からだけ受ける」開発サーバーにも、届く。望む動きだが、4.8 の危うさのもとでもある。

### 4.5 ブラウザーの機械での待ち受け（【提案】）

- 【決定】（2026-11-21。決定 15）待ち受けは手元だけ。LAN のほかの機械には出さない。
- 【提案】（読み。違えば直す）「手元（127.0.0.1）だけ」は、LAN に出さない意味と読む。同じ機械の `::1` でも待ち受ける（前のおすすめ (g)）。
- **番号は、開発の機械と同じにする。** 開発サーバーが表示する URL が、そのまま使える。
- **ぶつかったら、ずらして、知らせる**（決定 4）。
  - ぶつかるとは：その番号を、ブラウザーの機械のだれかが使っている。または、その番号を、root なしでは開けない。Linux は、既定で、1024 より小さい番号を、ふつうのユーザーに開かせない（資料：カーネルの文書の `ip_unprivileged_port_start`、既定 1024）。macOS は、確かめていない（推測：版によって違う）。
  - 使っているかどうかは、127.0.0.1 と ::1 の両方で見る。片方だけを見ると、もう片方で待ち受けている別のプログラムに、ブラウザーがつながる恐れがある（推測。Vite の文書は、ブラウザーが、サーバーの待ち受けと違うアドレスを引くことがある、と書いている＝資料）。
  - ずらし方：次に空いている番号へ。root は、使わない。
  - 知らせ方：いまは一覧（4.7）。Mac の通知はランチャーの束ができてから（決定 25）。**画面の全部を使うあいだは、ターミナルに書かない。** その画面を出たときの知らせ方は 4.10。コーディングエージェントは、一覧を、読める形（JSON）で引ける。正しい URL を、人に伝えられる。
  - いちど割り当てた番号は、作業場が生きているあいだ、変えない。次に開くときも、同じ番号を先に試す。
  - 番号がずれると、ブラウザーが送る Host の行の番号も変わる。Vite は、`localhost` と IP アドレスの Host を、既定で受ける（資料：Vite の `server.allowedHosts`）。ほかのサーバーは、確かめていない。
- **固定もできる**（決定 4）。プロジェクトごとに、「開発の機械の番号 → ブラウザーの機械の番号」を決めておける。**固定した番号が使えないときは、ずらさずに、その転送を止めて、知らせる。** ログインの戻り先や、ページの出どころ（オリジン）の決まりが、番号に結び付いていることがあるので、黙って別の番号にしない。

### 4.6 URL を開く頼み（【提案】）

**頼みの出どころ（開発の機械）。**

- 作業場のシェルの環境に、`BROWSER` を、Istesso の小さなコマンドに向けて入れる。`BROWSER` を見る道具は、これで通る（資料：Vite は `BROWSER` を見る。ほかの道具は、確かめていない）。
- OS の「開く」のコマンド（Linux の `xdg-open`、macOS の `open`）を名前で呼ぶ道具のために、作業場の中でだけ、同じ名前の小さな代わりを、先に見つかる場所に置く。http と https の URL だけを受け取り、ほかの使い方は、元のコマンドへそのまま渡す。アプリごとの対応ではなく、OS の「開く」の口 2 つへの対応である。この 2 つを通らない開き方は、拾えない（下の「既知の不足」）。

**受ける側（ブラウザーの機械）。**

1. **http と https だけ**（決定 4）。ほかの種類は、断る。ファイルも、アプリを起動する種類の URL も、開かない。
2. 厳しく読む。制御文字、空白、長すぎるもの、ユーザー名やパスワードの入ったものは、断る。
3. 行き先が、開発の機械自身（`localhost`、`127.0.0.1`、`[::1]`、`0.0.0.0`）のとき：
   - その番号が、そのプロジェクトの転送にあれば、ブラウザーの機械の側の番号に置き換えて、開く。
   - 転送になければ、開かずに、知らせる。ブラウザーの機械の、関係のないポートを、開かせない。
4. 【決定】（2026-11-21。決定 16）そのプロジェクトの転送中の URL は自動で開く。外の http と https は、URL を知らせ、持ち主が押したら既定のブラウザーで開く。
5. 開くときは、OS の「開く」の口に、URL を、引数として渡す。シェルは、通さない。macOS の `open` は、URL を、既定のブラウザーで開く（実機：Air の `man open`）。
6. 続けて何度も頼まれたときのために、回数の上限を持つ。
7. 頼みを受けるのは、ブラウザーの機械が、そのプロジェクトの既定のブラウザーとして、その機械の持ち主に選ばれているあいだだけである。

**危うさ。** URL を開く頼みは、開発の機械のプログラム（コーディングエージェントを含む）が、持ち主のブラウザーを動かす口である。ADR 0024 が書いたとおり、URL からは、だれが頼んだかは分からない。

- 持ち主がログインしているブラウザーで、好きなページを開かせられる。
- URL に中身を載せれば、外へ出せる。コーディングエージェントのネットワークを「決まった宛先だけ」に絞っていても（ADR 0026 の範囲 (3)）、ここが抜け道になる。
- ブラウザーが前に出て、手元で打っているキーを取る。

外の URL は、開く前に知らせる（決定 16）。

### 4.7 一覧と、止めるスイッチ（【提案】）

- **一覧**（コマンドと、ランチャーの画面）：プロジェクト、開発の機械、向こうの番号、こちらの番号、ずらしたか、固定か、待ち受けているプロセスの名前、いま開いている接続の数、最後に使われた時刻。読める形（JSON）でも出す。
- **止める**：1 本だけ。プロジェクトの転送の全部。全部の転送（大きなスイッチ 1 つ）。止めると、待ち受けを閉じ、開いている接続を、1 秒以内に切る。**止めた状態は、覚える。勝手に戻らない。**
- プロジェクトごとに、「自動では転送しない（聞いてから）」を選べる。
- 新しいポートが転送に加わったら、知らせる。黙って増えない。
- 開発の機械の側でも、そこにいる持ち主が、「このプロジェクトのポートを、外へ出さない」を選べる。
- 【決定】（2026-11-21。決定 15）そのプロジェクトのセッションがあるあいだ転送する。窓を閉じたあとは、サーバーが動くあいだ、最長 12 時間（4.11）。

### 4.8 同じユーザーの線との関係

**何が起きるか。**

- ブラウザーの機械の 127.0.0.1 で待ち受けているものには、**その機械の、どのプロセスからも届く。** 同じユーザーのほかのプログラムからも、ほかのユーザーのプログラムからも届く（推測：ループバックは、ユーザーで分かれない。ADR 0014 の「同じ PC のネットワークは、隔てない」と同じ）。ブラウザーの中のページと、拡張機能からも届く。
- つまり、転送のあいだは、**開発の機械の中だけで開いていたポートに、ブラウザーの機械のどのプログラムからも届く。** Istesso がなければ、届かなかったものである。同じユーザーの線の 2 番（ペアリングの信頼を借りて、ほかの PC に届く）に、そのまま当たる。
- これは、決定 4 の働きそのものでもある。ブラウザーが届くなら、同じ機械のほかのプログラムも届く。ブラウザーだけを通す仕組みは、OS にはない見込みである（推測）。ssh の、ポートを手元に引く機能と、同じ性質である。
- とくに重いのは、「localhost から来たものは信頼する」作りのサービス（デバッガーの口、管理の画面）が、作業場の中で開いたときである。ブラウザーの機械のプログラムが、開発の機械の上で、コードを動かせる口になりうる。開発の機械が、持ち主のユーザーで動く Mac（Studio）なら、届く先は、持ち主のアカウントの全部になる。
- ブラウザーの側の守り：Chrome は、公開のサイトのページが、ループバックや家の中のネットワークへ求めを送るときに、許可を尋ねるようになった（資料：Chrome for Developers の「Local Network Access」。Chrome 142 で、問いが入る。WebSocket などは、まだ対象の外、と書いてある）。ほかのブラウザーは、確かめていない。Istesso の守りとしては、数えない。

### 4.9 試作のあと（2026-11-20。`proto-port-forward` ブランチ）

別の流れが、この章の形を、Air と Ubuntu のあいだで試作した（ADR 0007 の「ポートの転送と、URL を開く頼み」の節）。この章と違う所、足された所だけを書く。

- 試作の守りの見直しは、まだ、だれもしていない。試用のブランチで毎日使う前に、1 回通す（進め方の案）。

### 4.10 画面を使うプログラムのあいだは、ターミナルに知らせを書かない（【提案】、2026-11-21）

持ち主の試用（2026-11-21 の朝と 14 時ごろ。`ish <project>` で、herdr に、そのまま入った）：入ったすぐあと、転送の知らせ（`istesso: port …`）が、herdr の横の一覧（スペース）の上に描かれた。窓の大きさを変えると、消えた。**望む形**：画面の全部を使うプログラム（別の画面。alternate screen）が動いているあいだは、転送の知らせを、ターミナルに書かない。知らせは、いまは一覧のコマンド（`ish-forwards`）で見る。

- 手元のプログラム（`istesso shell`）は、受け側のシェルの出力を、そのまま流しながら、別の画面に入ったこと、出たことだけを見る。見るのは、`ESC [ ? <番号> h` と `ESC [ ? <番号> l` の、番号 1049、1047、47（どれも、同じ別の画面の切り替え。`ESC [ ? 1 ; 1049 h` のように、ほかの番号と並んでいても）と、全部を戻す `ESC c`。並びが、読み込みの境目で切れていても、つなげて読む。出力は、書き換えない。入る、出るは、数えない（入れ子にしない）。ターミナルと同じく、最後の切り替えが、いまの状態である。並びの読み方は、xterm とその仲間の、DEC と ECMA-48 の読み手に合わせる（2 回目の見直し、2026-11-21）：並びの中の C0 の制御文字は、その場で行い、並びは続く（CAN、SUB、ESC のほかの全部。NUL、BEL、BS、LF、CR など）。DEL は読み飛ばし、並びは続く。CAN と SUB は並びを終える。ESC は新しい並びを始める。そのうえで、疑わしいときは、もとの画面に戻ったとみなす：切り替えの番号を含みながら、切り替えで終わらなかった並び（CAN、SUB、ESC、ほかの終わりの字）、256 バイトを超える並び、軽いリセット `ESC [ ! p`、全部を戻す `ESC c`。戻る（`l`）は、並びのどの番号からでも取る。入る（`h`）は、はじめの 16 個の番号からだけ取る（ターミナルが読む番号の数には限りがある。xterm は 30、ほかは 16 から 32）。8 ビットの CSI は、UTF-8 の形（`C2 9B`）のときだけ、戻るほうにだけ数える。シェルの出力は UTF-8（シェルの言葉は手元のもの）なので、ひとつだけの `9B` のバイトは、ターミナルにとって制御ではなく、ここでも読まない。限り：ターミナルによって読み方が違う並び（8 ビットの CSI で入る、など）では、知らせが、見えている画面に出ないことがある。そのときも、知らせは一覧に、すぐ出る。
- 別の画面のあいだは、転送の知らせ（と、窓の知らせ）を、ターミナルに書かずに、取っておく。別の画面から出たときに、1 回だけ、いまの状態を 1 行で書く：取っておいた知らせの数と、いま転送しているもの（全部のネットワークで待ち受けているものには、その印）。
- 試作は `--attach herdr:` で開いたときは、はじめから、別の画面として扱う。herdr は、ずっと画面の全部を使う。つなぎ直したあとは、前の herdr の別の画面のまま、始まる。製品の本体は herdr 専用にしない（決定 12）。
- 知らせは、どれも、取っておくかどうかの前に、すぐ一覧（`istesso forwards`、`ish-forwards`）の「最近の知らせ」に入る。手元のメモリーの中だけで、ファイルには書かない。別の画面が長く続いても、時間や数でターミナルに書き出すことはしない（持ち主の望みは「画面を使うプログラムのあいだは書かない」。herdr は一日中、別の画面を使う）。中身は、これまでの知らせと同じ（ポートの番号、機械の名前、プロセスの名前、URL なら主の名前まで）。
- 【決定】（2026-11-21。決定 25）**Mac の通知は、試作では出さない。一覧だけにする。** 束（アプリの形）のないプログラムから通知を出す口（`osascript` の `display notification`）は、初めてのときに、通知の許可を聞く画面が出るおそれがある（考え。確かめていない。確かめると、持ち主の画面に出る）。通知のための新しい束は、登録すると、Air の LAN の接続が切れる（2026-11-20 に見た）。通知は、ランチャーの束（4.7 の画面）ができたときに、そこから出す（決定 25）。
- ターミナルの中の知らせが信用できないこと（ADR 0007）は、変わらない。信用できるのは、一覧だけである。
- 限り：別の画面を、ほかの並びで使うプログラムは、見分けない。そのときは、これまでどおり、知らせが、絵の上に出る。
- 遅延（AGENTS.md の 3）：出力の道に足したのは、バイトを 1 つずつ見る読み手と、取り合いのない錠 1 つである。Air で測った（リリースのビルド、`the_cost_on_the_echo_path`）値は、ADR 0007 の同じ節にある。変更の前は、この 2 つがなかった。

### 4.11 窓を閉じたあとも、転送を続ける（転送の預かり手）（決定 15、24 と【提案】）

持ち主の試用（2026-11-21 の 14 時ごろ）：ish のタブを閉じたあと、Air のブラウザーで 5175 を読み直すと、開かなかった。`ish <project>` で入り直すと、開いた。サーバーは、Ubuntu の上で動き続けていた（シェルより長く残るものの引き継ぎ。ADR 0007 の「作業場」）。【決定】（2026-11-21。決定 15）窓を閉じても、サーバーが動くあいだは転送を続ける。窓を閉じて最長 12 時間。止めるスイッチでも閉じる。【提案】転送は、ブラウザーの機械で裏で動く係（預かり手）が持つ。

**だれが持つか（ブラウザーの機械。Air）。**

- ユーザーごとに（Istesso の設定のフォルダーごとに）1 つの**預かり手**（`istesso forwards keeper`。人が打つコマンドではない）。転送つきの `istesso shell` が、動いていなければ、起こす。端末から離した（新しいセッションの）裏のプロセスで、標準入出力は、何にもつながない。同じユーザーで動き、新しい許可は要らない。待ち受けるのは、持ち主だけが入れるフォルダー（0700）の Unix ソケットと、転送の待ち受けだけである。
- 転送つきのシェルは、開いているあいだ、預かり手に「この端末（受け側の機械）のシェルが開いている」と届けて、そのつなぎを開いたままにする。シェルが終わると（窓を閉じた、`exit`、切れた。どの終わり方でも）、そのつなぎが閉じる。預かり手は、それで知る。
- その機械の、届いているシェルが、ほかになければ、預かり手は、その機械に、**預かりの会話**（`forward_keep`）を 1 本開く。受け側は、その端末のために取っておいたスコープ（ADR 0007 の「シェルより長く残るもの」）のポートを、この会話で知らせる。預かり手は、試作では、シェルと同じ形で転送する：127.0.0.1 と ::1、同じ番号（ぶつかったら、ずらす）、シェルの固定、このユーザーのプログラムだけ、Host の確かめ、1 本 64 接続、頭は 10 秒。
- 同じ機械の新しいシェルが、預かり手に届けると、預かり手は、その機械の転送を閉じて（待ち受けを閉じ終えてから答える）、預かりの会話を閉じる。新しいシェルが、同じ番号で引き継ぐ。受け側でも、新しいシェルが、取っておいたスコープを、預かりの会話から引き取る。
- 【決定】（2026-11-21。決定 24）**窓がないあいだに転送するのは、窓が開いていたあいだに転送していたポートだけ**（見直しの指摘、2026-11-21）。【提案】シェルは、転送しているポートが変わるたびに、預かり手に知らせる。最後に閉じたシェルが、閉じたときに転送していたものだけを、預かり手は続ける。窓がないあいだに現れた新しいポートは、待ち受けを開かず、次の窓を待つ（次のシェルの知らせで出る）。何も転送していなかったシェルが閉じたときは、預からない。
- **上限**：受け側のエージェントが止まれば、預かりも終わる（その日の終わりの時刻）。そのうえで、窓が閉じてから 12 時間で、どんなときも終える。12 時間は、Air の 2 つの時計の、早く着くほうで数える：眠っているあいだも進む時計（壁の時計）と、起きているあいだだけ進む時計。数えるのは Air だけで、受け側の上限は、エージェントの終わりである（2 回目の見直し、2026-11-21）。
- **止めるスイッチと窓**：窓が開いているあいだに止めたポートは、窓を閉じたあとも止まったまま（預からない。一覧には「止めた」で出る）。シェルは、止めたときにも、預かり手に知らせる。預かっているあいだに、続けてよいポートを全部止めると、預かりは終わる（2 回目の見直し、2026-11-21）。
- **預かり手は、1 つの持ち主だけのフォルダーに 1 つ**：Mac では、そのフォルダーは `TMPDIR` の下にある。だから、`TMPDIR` が違うところから起こすと（エージェントのシェルの中など）、同じ設定のフォルダーでも、2 つ目の預かり手になりうる。同じ端末の新しい預かりの会話が来ると、受け側は前のものに「ほかの預かり手が引き継いだ」（`exit` の 2）を送る。それを受けた預かり手は、戻ってこない（取り合いにならない）。
- **預かり手が書くもの**：持ち主だけのフォルダーの、空の錠のファイル 1 つ。身元（鍵）は作らない（身元がなければ、預からない）。
- 預かりは、始めたときから一覧に「kept」で出る。次のシェルは、窓がないあいだのこと（何を、何分、何本の接続、待たせた新しいポート）を 1 行で知らせる（別の画面のあいだは取っておく）。
- 預かり手は、ページを開かない。窓も出さない。そのスコープのプログラムからの、ページを開く頼み、メインのエディターで開く頼みは、シェルが開いていないときと同じく、受け側で断る。
- 何も預かっていなくて、シェルも届いていなければ、預かり手は終わる。

**受け側（開発の機械。Ubuntu）。**

- 新しい頼み `forward_keep`。権利は、シェルと同じ：`--allow-shell` で名指しされ、ペアリング一覧で、同じ鍵のまま「操作」を持つ端末。**開くときと、開いているあいだ 1 秒おきに、読み直す。** エージェントが `--keep-scopes` で動いているとき（Linux）だけ。そうでなければ、断る。
- 受け側は、預かりの会話を、シェルのない作業場として持つ。その端末のために取っておいたスコープを引き取る。そのあとで取っておくもの（その端末の、最後のシェルが終わったとき）も、これが引き取る。ポートの見つけ方、ID、`forward_open` の確かめ（その端末の作業場の一覧にある ID、つなぐ前とあとの読み直し、全体で 32 本・1 台 16 本、120 秒で閉じる）は、シェルと同じである。
- 1 つの端末に、預かりの会話は 1 本。同じ端末から新しいものが来たら、前のものは終える。
- 終わるとき：
  - **サーバーが終わった**：スコープにプロセスがなくなると、スコープを忘れ、そのポートは、一覧から消える（転送も、0.5 秒ほどで消える）。何も預かっていない状態が 15 秒続いたら、受け側が、会話を終える（`exit`、終了コード 0）。
  - **権利を外した**：`exit`（権利を外された）を送って、切る。その端末のために取っておいたものは、全部忘れる（権利を外されて終わったシェルと同じ）。預かり手は、つなぎ直さない。
  - **止めるスイッチ**：`istesso forwards stop <番号>` は、その転送だけを止め、預かっているあいだ、覚える。`stop --all` は、その端末の預かりを終える（預かりの会話を閉じる）。受け側は、スコープを、また、その端末のために取っておく（次のシェルが引き継ぐ）。プロセスは、止めない。
  - **エージェントが止まる（23:59 の停止を含む）**：取っておいたものは、忘れる（いまと同じ）。会話が閉じる。預かり手は、つなぎ直しを試みる。新しいエージェントは、何も預かっていないので、15 秒で終わる。つながらなければ、3 分で、あきらめる。
  - **切れた（Wi-Fi、ふた）**：預かり手は、30 秒何も届かなければ、切れたとみなす。転送の待ち受けを、すぐ閉じる（届かない先を、開いたままにしない）。1、2、4、8、16、30 秒の間をあけて、3 分まで、つなぎ直す。受け側は、60 秒何も届かなければ、会話を終え、スコープを、その端末のために、また取っておく。つなぎ直せたら、同じ番号を先に試して、また転送する。
- 記録：受け側は、預かりの会話を開いた、終えた（理由）、ポートの番号。預かり手は、ファイルに何も書かない（知らせは、一覧の「最近の知らせ」だけ）。

**権利と、続く長さで、変わること（見直しのため）。**

- 権利の形は、変わらない：同じ端末（ID と鍵）、シェルを開ける端末だけ、1 秒おきの読み直し、外したら切る。試作で待ち受けるアドレス（127.0.0.1、::1）も、だれの接続を受けるか（このユーザーのプログラムだけ）も、変わらない。ほかの端末、ほかのユーザーのプログラムには、広がらない。新しい待ち受けのアドレスはない。
- **変わるのは、続く長さである。** これまでは、ターミナルの窓が開いているあいだだけだった。これからは、取っておいたスコープのプロセスが動いているあいだ（と、預かり手と、その会話が続いているあいだ）になる。窓がなくても、4.8 の表の 5 のセッションは続く。上限は窓を閉じてから 12 時間（決定 15）。窓を閉じても、Air の 127.0.0.1 には、ホストのポートが開いたままである。
- 窓がないあいだに増えたポートは、次の窓を待つ（決定 24）。
- サーバーが動き続けても、窓を閉じてから 12 時間で終える（決定 15）。

## 6. どこから使っても、同じ作業の続き（要件 2026-11-20。【問い 作3】の比べ直し）

**要件。** 開発の機械の前に座って使うときも、Air から Istesso で使うときも、同じ herdr のセッション、同じ履歴、同じコーディングエージェントの会話、同じファイルの続きができること。

**続きは、どこにあるか。** 4 つとも、開発の機械の上の、あるユーザーの持ち物である。

**前のおすすめ（2026-11-20。【提案】）。** 決定 9（持ち主の決め、2026-11-21）で、既定ではなくなった。1（Studio と Air は c）は、新しい既定と同じ。W5 全体が M5 を待つ順番は取り下げた（進め方の案の 2 章）。2〜5 は、**分ける設定を選んだ Ubuntu の形**として読む。新しい形は、この章の末尾の「持ち主の決め（2026-11-21）のあとの形」。

1. **Studio と Air は、c**（いまの提案のまま）。要件は、満たせる。
2. **Ubuntu は、a。** 要件と、守りを、両方とも保てるのは、a だけである。持ち主が心配した「切れる」は、入口が 2 つあるときに起きる。a は、入口を 1 つにする：機械の前でも、同じ 1 語で、同じ作業場に入る。b は、シェルと herdr の続きを、楽に保てる。かわりに、コーディングエージェントが書いたものを、持ち主のアカウントの力で動かすことになり（決定 24 を、やめる）、フォルダーの分け合い、2 つの Docker、転送の見つけ方と、作るものが、いちばん多い。c は、このホストでは、まだ、囲いにならない（Docker を root なしに替えても、届く先が、root から、持ち主のアカウントの全部に下がるだけ）。
3. **a の費用を、先に小さくする。** (1) 機械の前での入り方を、ターミナルの設定 1 行にする（W2 の受け入れ条件）。(2) 作業場のユーザーに足りない道具、設定、ログインを、W6 の仕組みで、1 行ずつ知らせる。(3) 機械の前の GUI のアプリは、(i) にする（保存は、書いてよい。動かすのは、作業場の中だけ）。アプリが、開いたファイルの中のスクリプトを、自動で動かす設定は、切っておく（Blender、エディター。既定の値は、確かめていない＝推測）。
4. **W5（M5 のあと）までは、いまのまま**：Ubuntu でも、持ち主のユーザーで、囲いなし（今夜の試用の形）。要件は、満たせている。守りは、ない。そのことを、試用の文書に書く。a への引っ越しは、W5 で、1 回。
5. **a を試して、費用が大きすぎたら、次は b。c ではない。** c に戻れるのは、名前の付いたソケットを止められるようになってから（新しいカーネルの Landlock が、ホストに届いたとき）。そのとき、もう一度、比べる。

**残る弱さ（a）。** 機械の前で、持ち主が、作業場の入口を通さず、herdr やコーディングエージェントを直接始めると、続きは、分かれる。囲いも、ない（持ち主の、2026-11-19 の夜の場面と、同じ形）。止める仕組みは、ない。名前での検知（ADR 0026 の決定 5）が、「作業場で開き直しますか」と同じプロジェクトで 1 回だけ知らせる（ADR 0026 の決定 14）。

### 持ち主の決め（2026-11-21）のあとの形（【提案】）

決定 9 の既定の形に、分ける設定を選ぶ単位（決定 26）と、アプリのホストの扱い（決定 27）を加えた。

**既定：どの機械も、c（全部、持ち主のユーザー。守りは、範囲の囲い）。**

- 要件「どこから使っても、同じ作業の続き」は、何もしなくても満たせる。機械の前のふつうのターミナルからでも、Air からでも、持ち主のユーザーの、同じ herdr、履歴、コーディングエージェントの会話、ファイルに着く。入口は 1 つで、引っ越しもない。作業場のユーザーに、道具、設定、ログインを、もう 1 組入れる手間もない。
- 機械の前の GUI のアプリ（Blender、エディター）は、そのまま開けて、保存できる。2 つのユーザーが同じフォルダーを書くこともない（(i) と (ii) の選びは、分ける設定のときだけ）。
- **コーディングエージェントに対する守りは、範囲の囲い（ADR 0026。OS の仕組み）だけ。** 範囲つきで起動したコーディングエージェントと、その子を、OS の仕組みで止める。
- **Ubuntu では、範囲は「うっかりを防ぐ柵」である。** 上の表の c の列のとおり、抜け道が残る：Docker の口（持ち主が Docker のグループにいれば、root と同じ力）、ユーザーのサービス管理、名前の付いたソケット（持ち主のセッションのバス、鍵の係、herdr 自身の口）、範囲の外で動いているほかのターミナル（持ち主のシェルで直接始めたもの。ADR 0026 の決定 22）。止められるのは、コーディングエージェントが、気づかずに外を触ること（まちがって消す、書き換える）である。わざと抜けることは、止められない。このことを、この文書と、初めて起動するときの問いの窓（ADR 0026 の 3）に、正直に書く。
- Mac（Studio、Air）は、前からの提案どおり（持ち主のユーザーと Seatbelt）。強さと限りは、ADR 0026 の「守りの強さの違い」の表のまま。
- **コーディングエージェントが書いたものは、持ち主の力で動く。** 持ち主が、そのシェルで、ビルド、試験、Git のフック、パッケージのスクリプトを動かせば、持ち主のアカウントの全部の力で動く（上の表の「だれの力で動かすか」の行）。ADR 0021 の決定 24 が避けようとした道は、既定では残る。UX との引き換えとして、受け入れた形である（決定 9）。
- いまの試用（Ubuntu でも、持ち主のユーザーで、囲いなし）は、既定の形のうち、囲いがまだ入っていないもの。W5 で囲いが入っても、ユーザーの引っ越しはない（前のおすすめ 4 の「a への引っ越し」は、分ける設定を選んだ機械だけのこと）。

**分ける設定（選べる。守りを強くしたい人のため）。**

- 【決定】（2026-11-21。決定 26）分けるかは機械ごとに、導入のときに選ぶ。
- 前のおすすめの a（どこから使うときも、作業場＝コーディングの専用ユーザーに入る）を、設定として残す。ADR 0021 の決定 6（herdr とコーディングエージェントは、2 つめの専用ユーザー）は、この設定の側に移す。決定 11 と 24（作業の場所では、ふだんのユーザーは書かない、Git もビルドも動かさない）も、この設定を選んだ機械の決めとして残す（ADR 0021 の書き直しは、ブランチ `m5-design`）。
- root の手順（専用ユーザー、ネットワークの決まり、root なしの Docker のための `uidmap` と linger。試作の文書の手順 R1〜R7）は、この設定を選んだ人のためのものとして残す。**持ち主の機械では、いまは分けない**（決定 9）。
- この設定を選んだ機械では、上の表の a の列と、前のおすすめ 3（費用を小さくする手）が、そのまま当てはまる。共通の入口を通らず、機械の前で持ち主のユーザーとして直接始めると、続きが分かれる（上の「残る弱さ（a）」）。

**アプリを動かすホストで、守れる範囲。**

【決定】（2026-11-21。決定 27）アプリのホストも、既定は持ち主のユーザーで動く。メインのエディターも同じ。ユーザーを分けることは、設定で選べる。

【提案】（読み。違えば直す）前の設計（ADR 0014 の A、ADR 0021 の決定 1）では、Linux のアプリは専用ユーザー U2 で動く。既定の形との違いは、次のとおり。

- 「操作」を持つ端末は、開いたアプリから、持ち主のアカウント全体に届く。ファイル、ふだんのブラウザーのログイン、SSH と Git の鍵も含む。前は専用ユーザーのホームまでだった。Studio のいまの形が、どの機械にも当たる。
- ホストの係（エージェント、ランナー）と鍵のファイルは、持ち主のほかのプログラムと同じユーザーになる。OS のユーザーの境目はない。残る守りは、ADR 0021 の同じユーザーの線と、鍵の置き場所（同じ ADR の問い 27）。
- 映像の道で開いたブラウザーなどを、悪いページに乗っ取られると、機械の前で開いたときと同じく、持ち主のアカウント全体に届く。前は専用ユーザーまでだった。
- アプリは、持ち主のふだんの設定とログインを使う。「ふだんのプロファイル」の権利（ADR 0021 の決定 4）と「操作」の差が小さくなる。

## 既知の不足

- **この文書は、実機で確かめていない。** Air で、読むだけのコマンドを動かした以外は、文書と、いまの ADR から書いた。Ubuntu と Studio は、見ていない。印が（推測）の文は、上の「確かめること」で確かめる。
- 作業場のプロセスの見分け（4.3）は、守りではない。同じユーザーのプログラムは、すり抜けられる。
- cd の切り替え（2.5）は、人がシェルで cd したときだけである。別の持ち主のフォルダーを指して動かしたコマンドは、元の機械で動く。書かないコマンドは、読むだけのマウントでも止まらない。
- URL を開く頼み（4.6）は、`BROWSER`、`xdg-open`、`open` を通らない開き方を、拾えない。拾えなかったものは、開発の機械のブラウザーで開くか、どこにも出ない。
- 番号がずれると、動かなくなるものがある（ログインの戻り先、ページの出どころの決まり）。固定で避ける。戻り先の番号が URL の中に書かれている場合、Istesso は、そこを書き換えない。
- ターミナルには、相手のプログラムが、手元のクリップボードに書く機能を持つものがある。通すかどうかは、ターミナルのアプリの設定で決まる（推測）。文字のコピーの決まり（ADR 0022、`trial-daily` ブランチ。この文書では、読んでいない）と、合わせて見る。
- 開発の機械を替える操作（引っ越し）は、ない。同じリポジトリを 2 台にクローンしても、機械ごとに別の ID になる。同名なら機械の名前を添えて並べ、同期はしない（決定 22）。引っ越しの手順は【問い 作24】。
- **Mac のつなぎの形（手元だけの NFS）には、マウントの相手の確かめがない**（1.5、決定 18。持ち主 1 人の機械での試用だけ）。FSKit の形は、まだ、だれも試していない。
- マウントでは、開発の機械の側の変更が、見る側のアプリに、知らせとして届かないことがある（調査が、Air で見た）。見直せば、見える。
- Mac のフォルダーを、Linux で見るとき、大文字と小文字だけが違う名前を、取り違えうる。
- マウントは、試作で、Istesso の道につながった（1.5）。守りの見直しは、まだ。Linux の見る側（FUSE）は、マウントを確かめただけである。
- **形 A では、各機械（と、作業場のユーザー）に、同じエディターと設定が要る。** Istesso は、そろえない。知らせるだけである（3.1）。
- **Air から開いた GUI のアプリの窓の続きを、開発の機械の前で見る道は、ない**（6 章。作業場のユーザーが、持ち主のユーザーと違う機械）。ファイルの続きは、できる。
- 権利を取り消された端末が始めたものは、動き続ける（決定 8）。herdr の中の、どれが、その端末から始まったかは、Istesso には分からない。
- 6 章の比べは、資料と、ほかの流れの試作からである。専用ユーザーも、root なしの Docker も、まだ、だれも動かしていない。
- 既定のブラウザーが AURA にあるときの形（Android の上の待ち受け）は、考えていない。M8 のあと。
- 出先（VPN 越し）で、文字が遅れるときの手（手元で先に字を出すなど）は、入れていない。
- Windows は、扱っていない。
- ADR 0010、0021、0024 は、`main` にない。それぞれのブランチの、2026-11-19 の時点の文面と突き合わせた。そのあとで変わったぶんは、見ていない。
