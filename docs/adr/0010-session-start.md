## 背景

M3（アプリマネージャー）の最初の一切れとして、次の 2 つを作る。

- ある端末が別の端末に、アプリの起動と終了を頼むメッセージ。
- 窓が 1 枚開くコマンド（`istesso open <アプリ>`）。ホストがアプリを配信用に起動し、クライアントがそれを映す窓を開く。

映像と入力の経路は、M1 で作っている途中である（`m1-latency` ブランチ。`main` にはまだない）。いまの形は次のとおり。

- ホスト：1 つのプロセスが、仮想コンポジター、エンコーダー、送信を受け持つ（いまは計測用のスクリプト。あとで `istesso-media-linux`）。絵の大きさ、フレームレート、圧縮の設定、送り先を渡されて動き、Wayland のソケットの名前を知らせる。アプリは、`WAYLAND_DISPLAY` をその名前にして起動する。
- クライアント：1 つのプロセスが窓を開いて映す（いまは計測用のビューアー。あとで `istesso-media-macos`）。窓の位置、受信するポート、キーフレームを求める先のポートを渡されて動く。
- 入力は、制御チャンネル（`istesso-link`、[ADR 0007](0007-control-channel.md)）で運ぶ（`m1-latency` にある）。セッションに属する。映像は、いまは計測用の暗号化していない RTP で、あとで暗号化した経路に替わる。

2 つの作業が並んで進むので、実装の前に境目を決める。分け方は次のとおり。

- **制御の側**（この ADR）：どのアプリを、どのホストで、どの端末に向けて、いつまで動かすか。セッションの識別、渡す値、寿命。
- **映像の側**（M1）：絵と入力をどう運ぶか。コーデック、圧縮の設定、経路、ポート、鍵、入力のメッセージ。

## 人が決めたこと（2026-11-16）

1. コマンドの名前は `istesso open`。
2. ペアリング済みの端末（「閲覧」と「操作」を持つ）は、アプリを起動してよい。
3. **クライアントがいなくなっても、アプリを終わらせない。** ふたを閉じたせいで、作業が消えてはいけない。動いているセッションの一覧、つなぎ直し、止める操作が要る。
4. **窓を閉じるのは、アプリへの「閉じてほしい」という頼みで、アプリを殺すことではない。** アプリは、保存するかどうかを尋ねられなければならない。

5. **ペアリングを解除した端末からは、すぐに何もできなくする。** 解除した時点で、その端末とつながっている接続（制御、映像、入力、音）を切る。
6. **その端末が起動していたアプリは、自動では閉じない。** 解除の操作のときに、その端末が開いたアプリを見せて、残す（既定）か、閉じるよう頼むかを選べるようにする。残したアプリは、一覧で「解除した端末が開いた」と分かるようにし、権限のあるほかの端末と、ホストにいる人が、つなぎ直すことも、止めることもできる。
7. **ホストは、前にだれも座っていない状態がふつうである。** 起動した直後（ログイン画面のまま、SSH だけ）の状態で動くことを、受け入れの条件にする。動かないものは、理由と、インストーラー（M9）が何を入れれば動くかを書く。
8. Windows は、今回の公開に含めない。
9. **ほかの端末が起動したセッションに、つないでよい。** 「どの端末でも、同じ画面が見える」が、この仕組みのねらいである（家で開いたアプリを、出先の端末で続ける）。つなげるのは、「閲覧」と「操作」の両方を持つ端末だけ。同時に映すのは、1 台だけ。つないだら、前の端末からは切り離して、「ほかの端末に移った」と出す。
10. **開いておけるセッションの数は、6 で止めない。** 1 台の PC のアプリを 6 つ以上開くのは、ふつうのことである。上限は、事故を防ぐための高い値にして、設定で変えられるようにする。達したら、理由を出す。数えて制限するのは、同時に圧縮している映像の数のほうである。見えていない窓は、映像を止めて、枠を使わない。枠を超えそうなときも、開くのを断らない（15 は、その案）。
11. 解除のときに「閉じるよう頼む」のは、`--close-apps` と書いたとき。書かなかったときは、その端末が開いたアプリがいくつ残ったかと、あとから閉じる方法を表示する。
12. 「何枚かの窓をまとめて送る」「枠を配り直す」は、いまは作らない。ただし、見えていない窓が枠を使わないようにするときに、**「セッションはあるが、エンコーダーを持っていない」状態を許す形にする。** これが、将来の項目への入口になる（15）。
13. **入力を送れるのは、そのセッションを映している端末だけ。**
14. **入力を開くときの権限は、頼まれたときに読み直した値を使う。**
15. **映像を受け取れるのは、映している端末だけ。**
    - 13 から 15 のねらい：見えていない所に、入力や映像が届かないようにする。権限を変えたら、すぐ効くようにする。本線と合わせる予行（`m3-join-rehearsal`）で見つかった 3 つの食い違いを、どれも、きびしいほうで決めたものである。
    - 将来の項目として残す（いまは作らない）：映していない端末やエージェントからの操作。ほかの人に画面を見せること。どちらも、別の機能として、はっきりした権限を付けて作る。
16. **圧縮の枠の既定は、8 のまま。** インストーラーが、映像が流れていないときに 1 回数えて、数えた値より 2 つ少ない値を設定する（同じ PC での録画や配信のぶんを残すため）。動いている最中にエンコーダーを断られることは、設定の値より少ない数でも起きうる。そのときは、落ちずに、見えていない窓の映像を止めて、使う人に知らせる。

3 と 4 は、はじめの提案（クライアントがいなくなったら 15 秒でアプリごと終わらせる。窓を閉じたら SIGTERM を送る）を取り下げるものである。5 と 6 は、このブランチのレビューで見つかった不足への答えでもある：離れているセッションには、ペアリングの解除が効いていなかった（見回りが、映しているセッションの持ち主しか確かめていなかった）。

## 用語

| 語 | 意味 |
|---|---|
| セッション | ホストで動くアプリ 1 つと、その仮想ディスプレイ（R-02 の「1アプリ = 1仮想ディスプレイ = 手元の1窓」）。アプリが動いているあいだ、ホストにある |
| ホスト、クライアント | アプリが動く端末、窓を出す端末 |
| つなぐ、離れる | クライアントが、セッションの絵を受け取り始めること、やめること。離れても、アプリは動き続ける |
| ランナー | ホストで、セッション 1 つぶんの仮想ディスプレイと送信を受け持つプロセス。映像の側が作る |
| ビューアー | クライアントで、セッション 1 つぶんの窓を受け持つプロセス。映像の側が作る |

## 決定

### 1. だれがだれに頼むか

- 頼むのはクライアントで、頼まれるのはホストのエージェント。制御チャンネルの、いまと同じ形（聞いて、答える）を使う。ホストからクライアントへは接続しない。
- どのホストで起動するかは、クライアントが決める。`istesso-catalog` がすでに出している `preferred_host`（手元 → 起きているホスト → 負荷の低いホスト。R-04）に従う。手元にあるアプリは、中継せずに手元で起動する。すでに動いているセッションがあるときの決まりは、10 にある。
- 頼めるのは、**そのホストのアプリ一覧にある ID** だけ。コマンドライン、引数、環境変数は、相手から受け取らない。

### 2. セッションの識別と、持ち主

- ID はホストが決める。OS の乱数から作った 64 ビットを、16 桁の 16 進数で書く。全体では「ホストの端末 ID ＋ セッション ID」で 1 つに決まる。
- **ID は秘密ではない。** 知っていても、何もできない。だから、ID はログや画面に出してよい。
- セッションには持ち主がいる。それを始めた端末である。確かめるのは、制御チャンネルのハンドシェイクで分かった身元（端末の ID と公開鍵）。
- **一覧に出て、つなげて、止められるのは、「閲覧」と「操作」の両方を持つ、ペアリング済みのどの端末でもよい**（人の決定の 9）。始めた端末かどうかは、問わない。権限の足りない端末には、どのセッションについても同じように断る。ホストにいる人は、そのホストのセッションを全部見て、止められる（13）。この決まりは、コードの 1 か所（`session::policy::may_use`）にある。
- **同時に映すのは、1 台だけ。** ほかの端末がつなぐと、ランナーは送り先を替え、前の端末への絵は止まる。前の端末は、次の問い合わせで、つなぎの番号が増えていることと、いま映している端末の名前（`shown_on`）を知り、「ほかの端末に移った」と表示して窓を閉じる。
- セッションは、いまどの端末に映しているかも覚えている。ふつうは持ち主だが、解除された端末が残したセッションでは、別の端末になる。絵を止めるかどうかは、映している端末の権限で決める。
- つなぐたびに、セッションの「つなぎの番号」（`attachment`）が 1 つ増える。いま絵を受け取っているクライアントが、どれかを表す。自分の番号より大きくなっていたら、ほかの窓に移った、と分かる。
- **つなぎは、それを受け取った端末のものである。** 番号は順に増えるだけで、秘密ではない。どの端末も、どのセッションも使えるので、番号を言えるだけでは、映している端末とは扱わない。番号が合い、かつ、その番号でつないだ端末（端末の ID と公開鍵）からのリクエストだけを、映している端末からのものとして扱う（`session_wait` の「まだいる」の知らせと `answer`、`session_detach`、`session_show`）。

### 3. セッションの寿命

**セッションは、アプリが終わるか、だれかが止めるまで続く。** クライアントがいるかどうかは、寿命に関係しない。

```text
 starting ──▶ running ◀──▶ detached ──▶ stopping ──▶ ended
              （映している）  （離れている）      │          ▲
                                                ▼          │
                                            left_over ─────┘
                                     （頼んでも、プロセスが残った）
```

| 状態 | 意味 |
|---|---|
| `starting` | ランナーが仮想ディスプレイを作り、エージェントがアプリを起動している |
| `running` | アプリが動いていて、クライアントがつながっている。`display` と `answer` は、そのクライアントのもの。ふつうは絵を受け取っているが、`paused` が付いているあいだは、絵が止まっている（窓が見えていない。または、圧縮の枠が足りない）。そのあいだ、セッションは、エンコーダーを持っていない（15） |
| `detached` | アプリは動いている。絵は、だれにも送っていない |
| `stopping` | アプリとランナーを止めている。`end` に理由がある |
| `left_over` | セッションは終わった（ランナーも、表示先も、圧縮の枠もない）。ただ、アプリのプロセスが、終わるよう頼まれても残っている。`left_over` に、そのプロセスグループの番号がある。グループがなくなれば `ended` になる。人が `--force` で終わらせることもできる（下の「力ずくにしない」） |
| `ended` | 終わった。60 秒は覚えておき、遅れて届いた問い合わせに、理由を答える |

離れる（`running` → `detached`）のは、次のとき。どれも、アプリには触らない。

| 起きたこと | 気づく側と、その方法 |
|---|---|
| クライアントが「離れる」と言った（`istesso open` を Ctrl-C で止めた。ビューアーが終わった） | クライアントが `session_detach` を送る |
| クライアントがいなくなった（スリープ、電源、ネットワーク） | ホスト。絵を受け取っているクライアントからの `session_wait` が、15 秒来ない |
| 映している端末のペアリングが解除された。権限を外された | ホスト。解除のコマンドが、その場でエージェントに知らせる。知らせがなくても、セッションごとに 1 秒おきに、ペアリングの一覧を読み直す（12） |
| ランナーが、送れなくなったと知らせた（`detached`） | ホスト |

終わる（→ `stopping` → `ended`）のは、次のときだけ。

| 起きたこと | 理由（`end.reason`） |
|---|---|
| アプリが自分で終わった。「閉じてほしい」と頼まれて終わった場合を含む | `app_exited` |
| 持ち主が、力ずくで終わらせた（`session_stop` の `force`） | `stopped` |
| アプリを起動できなかった | `app_failed` |
| ランナーが始まらない。途中で落ちた。アプリは表示先を失うので、一緒に終わる | `stream_failed` |
| 起動の途中で、頼んだ端末のペアリングが解除された。権限を外された。アプリは、まだ起動していない | `stopped` |

止める順は、アプリが先で、ランナーがあと。アプリが、表示先のあるうちに終われるようにする。

**力ずくにしない（2026-11-17 の持ち主の決定。2026-11-19 に入れた）。** セッションが終わるとき、アプリのプロセスに力ずくの合図（SIGKILL）を送るのは、人が `--force` と書いたときだけである。ほかのどの道でもない。そうした道は、たとえば次のとおり。

- 最後の窓が閉じた（`empty`）
- 最初の窓が出ないまま時間がたった（`no_window_yet`）
- ランナーが落ちた
- 起動したプロセスは終わったが、それが起動したものが残っている

| アプリのプロセスグループ | エージェントがすること | セッション |
|---|---|---|
| もうない | 何も送らない | `ended`。理由は、終わった道のとおり（`app_exited` など） |
| まだある | グループに、終わるよう頼む合図（SIGTERM）を 1 度送り、5 秒まで待つ。そのあいだは、ランナー（表示先）を残す。保存して終われるようにするためである | 終われば `ended`。`end.message` に「頼んだあとで終わった」と書く |
| 5 秒たっても、まだある | **力ずくでは終わらせない。** ランナーは止める | `left_over`。`left_over` に、グループの番号。`end.message` に、何が残ったかと、終わらせ方を書く（始めた端末からは `istesso sessions stop <ID> --force`、ホストにいる人は、それに `--local` を足す） |

- `left_over` のセッションは、`session_list` とホストにいる人の一覧に出る。ランチャーは、そこから見せる。
  - ランナーも表示先もないので、つなぐこと（`session_attach`）はできない。
  - 圧縮の枠は使わない。開いておける数（64）には数える。プロセスが動いているためである。
- `left_over` のセッションへの `session_stop`：
  - `force` なし：もう 1 度、SIGTERM で頼む。
  - `force` あり：人が選んだ力ずくの終わり。SIGTERM のあと、3 秒たっても残っていれば SIGKILL を送る（上と同じ）。
- エージェントは、`left_over` のセッションのグループを見張る。なくなったら `ended` にする。グループの番号が、ほかのプロセスに渡ったあとで、合図を送らないようにするためである。グループの頭のプロセスはエージェントの子なので、これを確かめられるのはエージェントだけである。
- **最初の窓が出るまで**（持ち主の決定の 1）。
  - ランナーが `opening` と言ってから、窓が出る（`windows` の数が 1 以上になる）までは、セッションに `opening: true` が付く。クライアントは、そのあいだ「開いています」と出す。
  - ランナーが `no_window_yet`（60 秒たっても窓がない）と言ったとき、プロセスがまだ生きていれば、エージェントは `empty` と同じ道で終える（頼む。力ずくにはしない。残れば `left_over`）。これは、持ち主の「プロセスが生きているかぎり、長めに待つ（たとえば 60 秒）」の読み方の案である。
- アプリのプロセスが自分で終わったら（グループがなくなったら）、`empty` を待たずに、すぐにセッションを閉じる（持ち主の決定の 2。前からこの形）。
- 記録のための 1 行（持ち主の決定の 5）：「最後の窓を閉じたら、アプリを終える」は、最初の版の割り切りである。Mac では、窓を閉じても、アプリはふつう動き続ける。裏で動くアプリを残すかどうかは、その知らせ（通知）を運ぶことと合わせて、あとで決める。
- 試験（持ち主の決定の 4）：人が `--force` を選んだ道のほかは、どの終わり方でも、力ずくの合図が送られないことを確かめる。

**終わらせ方は 2 つあり、混ぜない。**

- **閉じるよう頼む**（既定）。エージェントがランナーに `close` を伝え、ランナー（コンポジター）がアプリの窓に「閉じてほしい」と伝える。アプリは、ふつうは自分で終わる。保存するかを尋ねる窓を出したら、アプリはそのまま残り、セッションも続く。つながっているクライアントには、その窓が映る。
- **力ずくで終わらせる**。そう書いたとき（`--force`）だけ。アプリのプロセスグループに SIGTERM を送り、3 秒後に SIGKILL を送る。コマンドは、その時間を先に表示する。ほかの道では、力ずくにしない（下の「力ずくにしない」）。

時間と数（どれも、使ってみて直す）：

| 値 | いま | 理由 |
|---|---|---|
| `session_wait` で答えを待たせる時間 | クライアントは 2 秒を頼む。ホストは 3 秒までにする | エージェントが次のメッセージを待つ時間（5 秒）より短くする |
| クライアントからの `session_wait` が来なくなってから、絵を止めるまで | 15 秒 | Wi-Fi の短い切れは越える。いない相手に、絵を送り続けない。**止めるのは絵だけで、アプリではない** |
| ランナーの `ready` を待つ時間 | 15 秒 | GPU とエンコーダーの初期化 |
| ランナーの `attached` を待つ時間 | 10 秒 | 過ぎたら、つなぐ頼みを断る。セッションは `detached` のまま続く |
| 力ずくのとき、SIGTERM から SIGKILL まで | 3 秒 | |
| 力ずくでないとき、SIGTERM のあと、終わるのを待つ時間 | 5 秒 | ランナーの「窓がないまま 5 秒」（ADR 0019）と同じ長さ。過ぎたら `left_over` にする。力ずくにはしない |
| 終わったセッションを覚えておく時間 | 60 秒 | |
| 1 台のホストで開いておけるセッション | 64 まで。離れているものも数える。設定で変えられる（`istesso agent --max-sessions <数>`、または `ISTESSO_MAX_SESSIONS`。1 から 1024） | ふだんの使い方を止めるための数ではない（人の決定の 10）。スクリプトや不具合が、アプリを際限なく起動するのを止めるための値である。セッション 1 つは、ランナー（仮想ディスプレイ）1 つとアプリ 1 つで、64 は、人が開いておく数の何倍かであり、ホストが動かなくなる数よりは、ずっと少ない。**上限に達したら、新しい起動を断り、数と、変え方と、離れているセッションの名前を答える。何かを黙って終わらせることはしない** |
| 同時に圧縮している映像の数 | まだ数えていない（15 の案） | 本当に足りなくなるのは、こちらである |
| ペアリングの解除から、その端末の接続を切り、絵を止めるまで | 解除のコマンドから：コマンドが戻るまでに接続を閉じ、0.1 秒以内にランナーへ伝える。ほかの方法で一覧が変わったとき：1 秒以内 | 12 |

### 4. メッセージ

制御チャンネルのメッセージ（JSON。`type` で種類を表す）に、リクエストを 7 つ、レスポンスを 2 つ、エラーの種類を 2 つ足す。チャンネルの版（`ISC1`）は上げない。古いホストは `unsupported` と答えるので、クライアントは「相手の `istesso` が古い」と表示できる。

| リクエスト | 意味 | 送れる端末 | 答え |
|---|---|---|---|
| `session_start` | アプリを起動して、呼び出した端末につなぐ | 「閲覧」と「操作」を持つ端末 | `session`（状態は `starting`、つなぎの番号は 1）。準備を待たずに、すぐ答える |
| `session_list` | 呼び出した端末が使えるセッション（自分が始めたものと、解除された端末が残したもの）のうち、終わっていないものを並べる | 同上 | `sessions` |
| `session_attach` | 動いているセッションを、呼び出した端末につなぐ。新しい `display` と `offer` を渡す。いま絵を受け取っているクライアントがいれば、そこからは離れる | そのセッションを使える端末（上の 2） | ランナーが送り始めてから、`session`（状態は `running`、新しい番号と `answer`）。つなげなければ、理由を付けて断る。セッションは `detached` で続く |
| `session_wait` | セッションの状態を答える。`after` より新しい変化がなければ、`timeout_ms` まで答えを待たせる。**`attachment` がいまのつなぎの番号と同じなら、そのクライアントがまだいることの知らせになる** | 同上 | `session` |
| `session_detach` | 離れる。絵を止める。アプリは動き続ける。`attachment` がいまの番号と違えば、何もしない（もう、ほかの窓に移っている） | 同上 | `session` |
| `session_stop` | `force` がなければ、アプリに閉じるよう頼む。あれば、力ずくで終わらせる | 同上 | `session`。頼んだだけのときは、状態は変わらない |
| `session_show` | 映している窓が、見えているか、見えていないかを知らせる（`visible`）。見えていなければ、ホストは絵を作るのをやめて、枠をほかの窓に回す。つなぎは、そのまま。人がその窓に向いたときにも、`visible` で送る | 映している端末 | `session`（`paused` が付くことがある） |

**セッションのリクエストは、どれも「閲覧」と「操作」の両方が要る。** ホストは、リクエストが届くたびに、ペアリングの一覧を読み直して確かめる。解除された端末が残したセッションの答えには、`left_by`（その端末の名前）が付く。映しているあいだは、`shown_on`（映している端末の名前）が付く。

`answer` を答えるのは、絵を受け取っているクライアントにだけである（`session_attach` の答えと、つなぎの番号を名乗った `session_wait` の答え）。一覧と、ほかからの問い合わせには付けない。1 つのセッションを、いくつかの端末が使えることがあるためである。

`session_attach` だけは、すぐには答えない。起動と違って、失敗してもセッションを終わらせてはいけないので、「断る」という答えが要る。アプリはもう動いていて、待つのはランナーが送り始めるまでである。

| エラー | 意味 |
|---|---|
| `forbidden`（いまもある） | 権限がない |
| `not_found`（新しい） | そのアプリが一覧にない。または、その端末のセッションに、その ID がない |
| `unavailable`（新しい） | このホストでは、いまはできない。ランナーが設定されていない、窓として出せないアプリ、開いているセッションが上限に達した、ランナーがつなげなかった、ペアリングの一覧が読めない、など |

置き場所は、いまの決まりに合わせる。端末やプロセスの境目を越える型は `istesso-proto` に、リクエストとレスポンスは `istesso-link` の `message` に置く。新しい項目は、どの列挙でも末尾に足す（`ErrorCode` は、`other` の手前。serde が、受け皿を最後に置くことを求める）。`m1-latency` が同じ列挙に足した入力のメッセージと、並べるだけで合わせられるようにするためである。

// istesso-proto

/// Names one session on the host that runs it. The host makes it up: 16
/// lower-case hexadecimal digits from the system's random source. It is not
/// a secret. Knowing it grants nothing, so it may be shown and logged.
#[derive(Debug, Clone, PartialEq, Eq, Hash, Serialize, Deserialize)]
#[serde(transparent)]
pub struct SessionId(pub String);

/// Size and rate of a session's virtual display: the picture the client's
/// window shows, pixel for pixel.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
pub struct DisplayMode {
    pub width: u32,
    pub height: u32,
    /// Most frames a second the host sends: the refresh rate of the display
    /// the client's window is on.
    pub fps: u32,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum SessionState {
    /// The host is setting up the virtual display and starting the application.
    Starting,
    /// The application runs and a client is shown it; `display` and `answer`
    /// are that client's.
    Running,
    /// The application runs; nobody is shown it.
    Detached,
    /// The host is stopping the application and the stream; `end` says why.
    Stopping,
    /// (2026-11-19) The session is over, and the application's processes
    /// are still there after they were asked to end: `left_over` says
    /// which group. Nothing ends them by force but a person's `force`.
    LeftOver,
    /// Over.
    Ended,
    #[serde(other)]
    Unknown,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum EndReason {
    /// Its owner ended it by force.
    Stopped,
    /// The application ended by itself, asked to close or not.
    AppExited,
    /// The application could not be started.
    AppFailed,
    /// The host's side of the stream could not be started, or it failed.
    StreamFailed,
    #[serde(other)]
    Other,
}

#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct SessionEnd {
    pub reason: EndReason,
    /// One line for a person, in English. Programs go by `reason`.
    #[serde(default)]
    pub message: String,
}

/// One session as its host reports it.
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct SessionInfo {
    pub id: SessionId,
    /// The application's id on the host.
    pub app: String,
    pub kind: StreamKind,
    pub state: SessionState,
    /// Goes up by one with every change of this record.
    pub revision: u64,
    /// Counts the clients that were shown this session. The one that is
    /// shown it now has this number; a client with a lower one has been
    /// replaced.
    #[serde(default)]
    pub attachment: u64,
    /// What the host produces. Set once the session has run.
    #[serde(default)]
    pub display: Option<DisplayMode>,
    /// From the host's media path, for the client that is shown the
    /// session. Set while `running`. The control plane does not look inside.
    #[serde(default)]
    pub answer: Option<serde_json::Value>,
    /// Why the session ends. Set from `stopping` on.
    #[serde(default)]
    pub end: Option<SessionEnd>,
    /// Set when the device that started the session was unpaired while it
    /// ran: the name that device had. The application was kept, and the
    /// session is open to every device that may start applications on the
    /// host.
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub left_by: Option<String>,
    /// The name of the device that is shown the session. Set while
    /// `running`. One device is shown a session at a time; a client that
    /// finds another name here has been replaced by that device.
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub shown_on: Option<String>,
    /// (2026-11-19) The application has been started and has no window yet:
    /// a client can show that it is opening.
    #[serde(default, skip_serializing_if = "std::ops::Not::not")]
    pub opening: bool,
    /// (2026-11-19) Set while `left_over`: the process group of the
    /// application, still there after it was asked to end.
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub left_over: Option<u32>,
}

### 5. 流れ

始める：

```text
 ビューアー     istesso open（クライアント）      エージェント（ホスト）     ランナー     アプリ
     │◀─ prepare ───│                               │                    │
     │── offer ────▶│                               │                    │
     │              │── session_start ─────────────▶│                    │
     │              │◀─ session（starting）─────────│── start ──────────▶│
     │              │── session_wait ──────────────▶│◀─ ready ───────────│
     │              │                               │── 起動（ready の環境変数つき）───▶│
     │              │◀─ session（running、answer）──│                    │
     │◀─ show ──────│                               │                    │
     │◀════════ 映像と入力（映像の側。制御の側は通らない）════════════▶│
     │              │── session_wait（繰り返す）───▶│                    │
```

離れて、戻る：

```text
     │              │── session_detach ────────────▶│── detach ─────────▶│   （または、15 秒のあいだ session_wait が来ない）
     │ （窓は閉じる） │                               │       アプリは動き続ける。状態は detached
     ：              ：                               ：
     │◀─ prepare ───│  （別のとき、istesso open をもう一度）
     │── offer ────▶│── session_list ──────────────▶│
     │              │◀─ sessions ───────────────────│
     │              │── session_attach ────────────▶│── attach ─────────▶│
     │              │◀─ session（running、新しい answer）│◀─ attached ────────│
     │◀─ show ──────│                               │                    │
```

閉じる：

```text
     │── close ────▶│  （人が、窓を閉じようとした。窓は、まだ閉じない）
     │              │── session_stop ──────────────▶│── close ──────────▶│── 窓に「閉じてほしい」──▶│
     │              │                               │                    │   アプリが終わる。または、保存するかを尋ねて残る
     │              │◀─ session（stopping、app_exited）│  （終わったとき）
     │ （窓を閉じる） │                               │
```

- `session_start` には、すぐ `starting` と答える。仮想ディスプレイとエンコーダーの準備には数秒かかることがあり、制御チャンネルで答えを待つ時間（既定 5 秒）を超えうるためである。途中で失敗したときも、同じ形（`ended` と理由）で伝えられる。
- クライアントは、つながっているあいだ `session_wait` を送り続ける。ホストは、変化があればすぐ答え、なければ頼まれた時間だけ答えを待たせる。これが 2 つの役を兼ねる。
  - **ホストからの知らせ。** アプリが終わったら、待たせていた答えがすぐ返るので、手元の窓をすぐ閉じられる。ほかの窓に移ったことも、ホストが絵を止めたことも、これで分かる。
  - **クライアントがいることの知らせ。** どの接続から来てもよいので、Wi-Fi が一瞬切れてつなぎ直しても続く。
- エージェントは、動いているセッションを短い間隔で見回る。確かめるのは、アプリとランナーが動いているか、クライアントの知らせが来ているか、持ち主の権限が残っているか。
- ホストがいなくなったとき（`session_wait` が失敗し、15 秒のあいだつなぎ直せない）、クライアントはビューアーを閉じて、理由を表示する。アプリがどうなったかは、ホストが戻ってから `istesso sessions` で分かる。

### 6. 交渉する値と、決める側

| 値 | 決める側 | 運び方 |
|---|---|---|
| どのアプリを、どのホストで | クライアント（アプリ一覧と `preferred_host`） | `session_start` の `app` と、接続先 |
| 配信の種類 | クライアント。最初は `app_window` だけを受ける | `kind` |
| 絵の大きさと、フレームレートの上限 | クライアントのビューアーが望む（窓を出すディスプレイを知っている）。ホストのランナーは、出せる値に下げてよい。実際の値はランナーが決めて返す | `display`（行きと帰り） |
| コーデック、色の間引き、ビットレート、キーフレームの出し方、経路、ポート、鍵 | 映像の側。ビューアーが受けられるものを `offer` に書き、ランナーが選んで `answer` に書く。既定は ADR 0002 で決めた設定 | `offer` と `answer`。制御の側は中を見ない |
| 映像の送り先のアドレス | 制御の側。**制御チャンネルの接続元**を、そのまま使える文字にしてランナーに渡す。相手が申告したアドレスへは送らせない。IPv6 のリンクローカルのアドレスには、ゾーン（受け付けたソケットのスコープ ID）を付ける（`fe80::…%4`）。IPv6 に包まれた IPv4 は、IPv4 の形に戻す | ランナーへの `peer.address` |
| 窓の位置 | ビューアー。コマンドラインで指定されたら、望みとして渡す | ビューアーへの `wish` |
| セッションの ID と寿命 | ホスト | `session` |

クライアントが、ホストのどのアドレスへつなぐか（有線を先に試す、など）は、ここでは決めない。映像は制御チャンネルと同じ経路を通るので、遅延に効く。映像の側の課題として残す。

圧縮の設定を制御の側の項目にしないのは、遅延と画質を一緒に測って決めた値だからである（ADR 0002）。セッションごとに外から変えられる形にすると、測っていない組み合わせが増える。

### 7. 権限

- 話せるのは、ペアリング済みの端末だけ（制御チャンネルは、ほかの端末と何もやり取りしない。ADR 0007）。
- **セッションのリクエストは、どれも「閲覧」と「操作」の両方が要る。** プログラムを起動するのも、その窓を手元に出して操作するのも、終わらせるのも、操作であり、閲覧だけの端末にはさせない。新しくペアリングした端末は両方を持つので（ADR 0006）、何も変えなければ、ペアリング済みの端末はアプリを起動できる（人の決定の 2）。この決まりは、`session::policy::START_NEEDS` にある。
- セッションを見られるのも、動かせるのも、その権限を持つ端末なら、どれでもよい（上の 2）。
- **失効は、すぐに効かせる。ただし、アプリは終わらせない**（12）。確かめる場所は 3 つある。リクエストが届いたとき。セッションの見回り（映していても、離れていても、1 秒おき。つなぐ頼みを実行する直前にも）。開いている接続（1 秒おき）。どれも、ペアリングの一覧をその場で読み直し、ハンドシェイクのときの権限を使わない。いまの決まり（接続のたびに読み直す。ADR 0007）だけでは、開いたままの接続に失効が効かないためである。
- ランナーには、相手の端末の ID と公開鍵、制御チャンネルの接続元のアドレスを渡す（公開鍵は、絵をその 1 台にだけ送るため。人の決定の 15）。秘密の鍵と、権限は渡さない。
- `offer` と `answer` は、書き換えずに運び、ログに出さない（あとで鍵を含みうる）。大きさは 64 KiB までにする。ランナーとビューアーへは標準入力で渡し、引数や環境変数には載せない（引数は、同じ PC のほかのユーザーから見える）。
- 権限の要る処理は増えない。root も、新しい種類の OS の許可も要らない。アプリは、エージェントと同じユーザーで動く。Mac のビューアーは、ホストと通信するので「ローカルネットワーク」の許可が要る。制御チャンネルですでに要る許可で、種類は増えない。ただし、ビューアーを独立したアプリとして起動する形にすると、そのアプリに人が改めて許可を出すことになる。

### 8. アプリ一覧の項目に要るもの

相手に見せる項目（`AppEntry`）は変えない。クライアントが使うのは `id` だけで、起動のしかたは、ホストが自分の一覧から決める。ホストは、起動のときに、その ID の desktop entry を読み直す。

| 要るもの | いま | 最初の一切れでの扱い |
|---|---|---|
| `Type=Application` で、`Exec` がある | 読んでいる | 変えない |
| `Exec` を、仕様の決まり（引用符とエスケープ）どおりに引数へ分ける。シェルは通さない。`%f` などは取り除く | 文字列のまま持っている。引用符の中の続いた空白は、1 つに詰まる | 起動のときに、元のファイルから読んで分ける |
| `Terminal=true` でない | 読んでいない。一覧には載る | 起動を断る（`unavailable`）。文字のアプリは、R-01 の 2 番目の道（ターミナルで直接つなぐ） |
| `Path=`（作業ディレクトリ） | 読んでいない | 読んで使う |
| `TryExec=` の実行ファイルがある | 読んでいない | なければ断る |
| Wayland で窓を出せる | 項目からは分からない | 下のとおりに環境を整えて起動する。出せないアプリは自分で終わるので、`app_exited` になる |
| macOS のアプリ（`.app`） | 一覧に載る | ホストとしては断る（M4）。手元にあるものは、手元で開く |

アプリの環境は、エージェントの環境に、ランナーが `ready` で返した変数を足して作る。ランナーが `WAYLAND_DISPLAY` を返して `DISPLAY` を返さないときは、`DISPLAY` を外し、主なツールキットに Wayland を選ばせる変数を足す（案：`GDK_BACKEND`、`QT_QPA_PLATFORM`、`SDL_VIDEODRIVER`、`MOZ_ENABLE_WAYLAND`、`ELECTRON_OZONE_PLATFORM_HINT`。まだ試していない。実機で確かめて決める）。`DISPLAY` を外すのは、窓が黙ってホストのデスクトップに出るのを防ぐためである。

分かっている限界：

- 1 つしか動かない作りのアプリが、ホストのデスクトップですでに動いていると、新しい窓がそちらに出ることがある。D-Bus を通して起動し直すアプリも同じ。どちらも、起動したプロセスはすぐ終わるので、`app_exited` になる。
- X11 だけのアプリは映らない（いまのコンポジターに XWayland がない。`m1-latency` の ADR 0009）。
- 「窓として出せるか」は、頼んでみるまでクライアントには分からない。

### 9. 境界：映像と入力がつながる場所

映像の側は、ホストの**ランナー**と、クライアントの**ビューアー**の 2 か所でつながる。その形を 2 つ比べた。

- **A：プロセスで分ける。** エージェントがランナーを、`istesso open` がビューアーを、別のプロセスとして起動する。やり取りは、決めた形の行（標準入力と標準出力）で行う。
- **B：プロセスの中で、トレイトでつなぐ。** `istesso-media-*` のクレートがトレイトを実装し、エージェントとコマンドにリンクする。

| 観点 | A：プロセスで分ける | B：トレイトでつなぐ |
|---|---|---|
| いま映像の側にあるもの（Python のスクリプト、Objective-C のビューアー） | 数十行の包みでつながる | つながらない。Rust に書き直してから |
| `main` のビルド | 変わらない。GStreamer、Wayland、CUDA の開発用パッケージが要らないまま（共通コアは、どの PC でもビルドできる） | エージェントが映像の依存を抱える。OS ごとに feature で分ける |
| 落ちたとき | そのセッションだけが終わる。エージェントは理由を相手に伝えられる | エージェントごと落ちる。ほかのセッションと、役割表や発見も止まる。GPU のドライバーの中で落ちることもある |
| Mac のクライアント | 窓を持つプログラムは、別のプロセスが自然（メインスレッド、Dock のアイコン、OS の許可が、アプリごとに付く） | `istesso` コマンド自身が、窓を持つアプリになる |
| 入力の遅延 | 入力は、エージェントが受けて、ランナーのソケットへ渡す（下の「入力」）。同じ PC の中の受け渡しが 1 回増える。0.1 ms 未満の見込みだが、測っていない | 関数の呼び出しで渡せる |
| 約束を守らせる方法 | 行の形と版の番号。偽物を使ったテスト | コンパイラー |
| ライセンス | エージェントとコマンドは、GStreamer（LGPL）にリンクしない | エージェントが GStreamer にリンクする。動的リンクを保つ必要がある（`components.md`） |
| 専用ユーザーでの隔離（R-07）を、あとで足す | プロセスの境目に挟める | 挟めない |
| 鍵の受け渡し | 標準入力で渡す。引数に載せない決まりが要る | メモリの中で済む |
| 起動の時間 | プロセスの起動が 1 回ぶん増える。GPU の初期化は、どちらでも要る | 少し短い |

**決定：A を境界にする**（2026-11-16、映像の側と合意）。理由は 3 つある。いまある計測の道具がそのままつながること。`main` が映像の依存を持たずに済むこと。落ちたときに巻き込む範囲が、セッション 1 つで済むこと。

エージェントとコマンドの中では、小さなトレイト（ランナーを始める・止める、ビューアーを始める・止める）を通して使う。標準の実装は、下の約束でプロセスを起動する。テストでは、偽物を差し込む。あとで B のほうがよいと分かったら、同じトレイトに、プロセスを作らない実装を足せばよく、メッセージは変わらない。

#### ホスト：ランナーとの約束

- エージェントに、実行ファイルを 1 つ教える（`istesso agent --session-runner <プログラム>`、または環境変数 `ISTESSO_SESSION_RUNNER`）。引数は渡さない。設定がなければ、そのホストは `session_start` に `unavailable` と答える。何を動かすかを決めるのは、ホストを使っている人であり、相手の端末からは選べない。
- セッション 1 つにつき、1 つ起動する。セッションが続くあいだ、動き続ける。
- 標準入力と標準出力で、1 行に 1 つの JSON をやり取りする。標準エラーは人が読むログで、エージェントが自分のログに回す（鍵やトークンを出さない）。知らない行と、知らない項目は、読み飛ばす。

```text
→ {"v":1,"cmd":"start","session":"5b0c9e3a7f21d684","kind":"app_window","display":{"width":1720,"height":720,"fps":85},"peer":{"id":"1a2b-3c4d-5e6f-7a8b","address":"192.0.2.10"},"input_socket":"/run/user/1000/istesso/input-5b0c9e3a7f21d684.sock","offer":{"rtp_port":50004}}
← {"v":1,"event":"ready","env":{"WAYLAND_DISPLAY":"wayland-3"},"display":{"width":1720,"height":720,"fps":85},"answer":{"key_request_port":50005}}
→ {"v":1,"cmd":"application","pid":4711}
→ {"v":1,"cmd":"detach"}
→ {"v":1,"cmd":"attach","peer":{"id":"1a2b-3c4d-5e6f-7a8b","address":"192.0.2.10"},"display":{"width":1280,"height":720,"fps":60},"offer":{"rtp_port":50010}}
← {"v":1,"event":"attached","display":{"width":1280,"height":720,"fps":60},"answer":{"key_request_port":50011}}
→ {"v":1,"cmd":"close"}
← {"v":1,"event":"empty"}
← {"v":1,"event":"detached","message":"the encoder is busy"}
← {"v":1,"event":"error","message":"no encoder"}
```

| 行 | 向き | 内容 |
|---|---|---|
| `start` | エージェント → ランナー | 仮想ディスプレイを作り、最初のクライアントへ送り始める。セッションの ID、種類、望まれた `display`、相手の端末（ID、公開鍵、制御チャンネルの接続元のアドレス）、入力を受け取るソケットの場所（`input_socket`）、クライアントのビューアーからの `offer` |
| `ready` | ランナー → エージェント | アプリを受け入れられるようになり、`input_socket` にソケットを作り終えた。`env` は、アプリをこの仮想ディスプレイに出すための環境変数。`display` は、実際に出す大きさとフレームレート。`answer` は、クライアントのビューアーへの返事 |
| `application` | エージェント → ランナー | アプリを起動した。そのプロセスの番号。アプリの窓を自分で探さなければならないランナー（Mac のホスト）のためのもので、アプリのほうからつなぎに来る仮想ディスプレイ（Wayland）のランナーは、読み飛ばしてよい |
| `detach` | エージェント → ランナー | クライアントが離れた。または、離された（ペアリングの解除）。**そのクライアントとのやり取りを、全部やめる**：絵と音を送るのをやめ、そのクライアントから届くものを受け付けるのをやめ、そのクライアントと決めた宛先や鍵を捨てる。仮想ディスプレイとアプリは、そのままにする。次に送るのは、新しい `attach`（新しい `offer`）が来てから |
| `attach` | エージェント → ランナー | このクライアントへ送り始める。相手の端末、望まれた `display`、新しい `offer`。ほかのクライアントへ送っていたら、それはやめる |
| `attached` | ランナー → エージェント | `attach` のとおりに送り始めた。実際の `display` と、新しい `answer` |
| `detached` | ランナー → エージェント | いまは、だれにも送っていない。`attach` に応えられなかったとき、または、送れなくなったときに出す。理由を 1 行付ける。仮想ディスプレイとアプリは続いている |
| `close` | エージェント → ランナー | アプリの窓に、閉じるよう頼む（Wayland なら `xdg_toplevel.close`）。アプリがどうするかは、アプリが決める |
| `pause` | エージェント → ランナー | 絵を作るのをやめて、エンコーダーを手放す。クライアントはつないだまま。仮想ディスプレイとアプリは、そのまま |
| `resume` | エージェント → ランナー | 絵を作り直す。前の絵に頼らないフレームから始める。`attach` を受けたときも、止めていた絵は作り直す |
| `empty` | ランナー → エージェント | 最後の窓が閉じた。エージェントは、セッションを終える。アプリのプロセスが残っていれば、終わるよう頼み、力ずくにはしない（3 の「力ずくにしない」） |
| `windows` | ランナー → エージェント | （2026-11-19 に読むようにした。ADR 0019）アプリの窓の数（`count`）。数が変わるたび。1 以上になったら、`opening` の印を外す |
| `opening` | ランナー → エージェント | （同）アプリを起動したと伝えられたとき、窓がまだない。セッションに `opening: true` を付ける |
| `no_window_yet` | ランナー → エージェント | （同）`opening` から長くたっても（`after_s`。60 秒）、窓がない。プロセスが生きていれば、`empty` と同じ道で終える |
| `error` | ランナー → エージェント | 続けられない。このあと終了する。アプリも終わる |
| `no_encoder` | ランナー → エージェント | エンコーダーを断られた（絵を作り直そうとしたとき。または、動いている最中）。絵は、いまは作っていない。仮想ディスプレイとアプリは、そのまま。クライアントも、つないだまま。`resume` を受けたら、もう一度試す。理由を 1 行付けてよい |

決まり：

1. `ready` は 15 秒以内に、`attached`（か `detached`）は 10 秒以内に出す。
2. **標準入力が閉じたら、送信をやめて、2 秒以内に終了する。** これがセッションを終える合図で、エージェントが落ちたときにも同じことが起きる。終わらなければ、エージェントが SIGTERM、SIGKILL の順に送る（ランナーはこちらのプログラムなので、力ずくにしてよい。アプリには、しない）。
3. ポートは固定しない。使うポートは自分で選び、`answer` で知らせる。セッションを並べて動かせるようにするためである。
4. 映像は、最後の `start` か `attach` で名指された端末（`peer` の ID と公開鍵の両方が合う端末）にだけ送る。ほかの端末は、ペアリング済みで「閲覧」を持っていても、断る（人の決定の 15）。入力は、`input_socket` からだけ受け取る。
5. `detach` のあとも、`attach` に応えられなかったあとも、仮想ディスプレイとアプリを保つ。
6. 終了コードの 0 は「頼まれて止まった」で、それ以外は失敗。
7. `detach` を読んだら、0.1 秒以内に、送るのも受けるのもやめる（提案）。ペアリングを解除した端末を、すぐに切るための決まりである（12）。音を運ぶ経路がランナーの外にできるなら、その経路も、同じ合図で止まる必要がある。
8. エンコーダーを開けなかったときは、終了せずに、`no_encoder` と言う（人の決定の 16）。起動のときに開けなかった場合も、仮想ディスプレイは作って `ready` と言い、そのあとで `no_encoder` と言う。 `pause` を読んだら、0.3 秒以内にエンコーダーを閉じる（提案。エージェントは、枠を譲らせた 0.5 秒後に、断られたランナーへ `resume` を伝えるため）。

#### クライアント：ビューアーとの約束

- `istesso open --viewer <プログラム>`、または環境変数 `ISTESSO_VIEWER` で教える。行の形は、ランナーと同じ。

```text
→ {"v":1,"cmd":"prepare","title":"Firefox","kind":"app_window","wish":{"width":1720,"height":720,"fps":null,"x":null,"y":null}}
← {"v":1,"event":"offer","display":{"width":1720,"height":720,"fps":85},"offer":{"rtp_port":50004}}
→ {"v":1,"cmd":"show","session":"5b0c9e3a7f21d684","host":{"id":"9f8e-7d6c-5b4a-3921","address":"192.0.2.20"},"display":{"width":1720,"height":720,"fps":85},"answer":{"key_request_port":50005}}
← {"v":1,"event":"shown"}
← {"v":1,"event":"close"}
```

| 行 | 向き | 内容 |
|---|---|---|
| `prepare` | コマンド → ビューアー | 窓の題名、種類、コマンドラインで指定された望み（大きさ、フレームレート、位置。なければ `null`） |
| `offer` | ビューアー → コマンド | 望む `display`（窓を出すディスプレイの画素とリフレッシュレートから決める）と、ホストのランナーへの `offer`。5 秒以内に出す |
| `show` | コマンド → ビューアー | セッションの ID、ホスト（ID と、制御チャンネルがつながったアドレス）、実際の `display`、ランナーからの `answer` |
| `shown`（任意） | ビューアー → コマンド | 最初の絵が画面に出た。起動にかかった時間を測るために使う |
| `close` | ビューアー → コマンド | 人が、窓を閉じようとした |
| `hidden` | ビューアー → コマンド | 窓が見えなくなった（最小化した。ほかの窓に完全に隠れた。別のデスクトップにある） |
| `visible` | ビューアー → コマンド | 窓が、また見えるようになった。または、人がその窓に向いた（前面にした） |
| `paused` | コマンド → ビューアー | ホストが絵を止めた。理由（`hidden`、`no_slot`）が付く。窓は、最後の絵を出したまま、止まっていると分かる印を出す |
| `resumed` | コマンド → ビューアー | 絵が、また来る |

決まり：

1. **人が窓を閉じようとしたら、`close` と言うだけで、窓は閉じない。** コマンドが、ホストのアプリに閉じるよう頼む。アプリが終われば、コマンドが標準入力を閉じる。アプリが「保存しますか」と尋ねたら、その窓が、開いたままのこの窓に映る。
2. 標準入力が閉じたら、窓を閉じて終了する。
3. ビューアーが自分で終わったら（人がビューアーを終了させた。落ちた）、コマンドは離れる。アプリは動き続ける。
4. 窓は、最初の絵が出るまで見せないのが望ましい。起動に失敗したときに、空の窓が一瞬出るのを避けられる。

Mac で、ビューアーを独立したアプリとして `open` で起動するとき（アプリとしての優先度と許可で動かすため）は、包みが標準入出力を名前つきパイプでつなぐ（`open --stdin`、`--stdout`）。まだ試していない。

#### 入力

**入力は、制御チャンネルで、エージェントを通して運ぶ**（2026-11-16、映像の側の決定）。経路は `m1-latency` にあり、ADR 0007 の「入力」に書いてある。

- クライアントは、`input_open` で許しを得てから、`input` でイベントを送る。エージェントは、相手に「操作」の権限があることを確かめ、入力が続くあいだも 1 秒おきに確かめ直す。
- エージェントは、イベントを 1 つずつ、ランナーが作ったデータグラムのソケットへ渡す。ソケットの場所は、エージェントがセッションごとに決めて（`$XDG_RUNTIME_DIR/istesso/input-<セッションの ID>.sock`。本人しか入れない場所）、`start` の `input_socket` でランナーに知らせる。ランナーは、`ready` を出す前に、そこへソケットを作る。つなぎ直しても、場所は変わらない。
- セッションが終わったら、エージェントは、そのソケットを消す。
- **入力を渡すのは、そのセッションを映している端末のぶんだけにする**（人の決定の 13）。**これは、まだできていない**（2026-11-19 の見直しで確かめた）。いまの入力は、ADR 0007 のとおり、「操作」の権限を確かめたうえで、ホストに 1 つだけの入力の受け口（`input.sock`）へ渡る。セッションの表は答えを用意してある（`Sessions::shown_to`、`input_socket_of`。試験は、表の答えだけを確かめる）が、入力の経路からは、まだ使っていない。できたときの形：離れた（離された）時点で、エージェントは、その端末の入力を渡すのをやめる。ペアリングを解除した端末は、制御チャンネルの接続ごと切られるので、入力も届かない（12）。映している端末かどうかは、セッションの表が答える（`Sessions::shown_to`。端末の ID と公開鍵で確かめる）。入力を開くときの「操作」の権限は、ハンドシェイクのときの値ではなく、頼まれたときに読み直した値で確かめる（人の決定の 14）。`input_open` にセッションを名乗らせて、この 2 つを確かめる所は、入力のメッセージを持つ本線の側の作業で、予行のブランチに形がある。「操作」の権限を頼まれたときに読み直すことは、できている（`m3-app-manager` に main を取り込んだとき。ADR 0007 の「入力」）。

ここまでで作ったのは、`input_socket` を決めてランナーに渡すところまでである。入力は、まだセッションを名乗らない（`input_open` に `session` を足すのは、映像の側があとで行う）。それまでは、ADR 0007 のとおり、1 台のホストが映すアプリは 1 つ、という前提で動く。

こうした理由：作って、確かめ終えた経路がすでにある。ハンドシェイクの新しい使い方が要らない。受け渡しが 1 回増えるぶんは、0.1 ms 未満の見込みである（測っていない）。

制御の側が保証することは、変わらない。**`offer` と `answer` は、認証済みの制御チャンネルを通って、書き換えられずに相手に届く。** 映像の経路が、あとで鍵を交わすときに使える。

#### いまの計測の道具をつなぐには

`m1-latency` の送信側のスクリプトとビューアーは、変えずに使える見込みである（引数と出力を読んで確かめた。動かしてはいない）。包みを 1 つずつ書けばよい（置き場所は、映像の側のブランチ）。

- ランナーの包み：`start` を読み、送り先を `peer.address` と `offer` のポートにして、大きさとフレームレートを渡して、スクリプトを起動する。再生が始まったら、ソケットの名前をログから読んで `ready` を出す。標準入力が閉じたら、スクリプトを止める。
- ビューアーの包み：空いているポートを選んで `offer` を出す。`show` を読んで、ビューアーを起動する。

`main` には、映像を何も運ばない偽物のランナーとビューアーを置く。テストと、実機 2 台での確認に使う。

包みは、`detach`、`attach`、`close` にも応える必要がある。`close` には、コンポジターへの小さな追加が要る（アプリの窓に、閉じるよう伝える）。これも、映像の側の作業である。

### 10. コマンド

| コマンド | 動き |
|---|---|
| `istesso open <アプリ>` | 下の決まりで、つなぐか、起動する |
| `istesso sessions` | 起きているホストで開いているセッションを、全部並べる（ID、アプリ、ホスト、状態。映しているときは、どの端末にか）。どの端末が始めたものでも出る。解除された端末が残したものには、「解除された <端末> が開いた」と付く |
| `istesso sessions stop <ID>` | そのアプリに、閉じるよう頼む。数秒待って、終わったか、まだ動いているか（保存するかを尋ねているかもしれない）を表示する |
| `istesso sessions stop <ID> --force` | 力ずくで終わらせる。アプリが自分で終わるまでに 3 秒ある、と先に表示する |
| `istesso sessions --local` | ホストにいる人が、そのホストのセッションを、だれが始めたものでも並べる（ID、アプリ、始めた端末、状態）（13） |
| `istesso sessions stop <ID> --local [--force]` | ホストにいる人が、閉じるよう頼む。または、力ずくで終わらせる |
| `istesso peers remove <端末> [--close-apps]` | ペアリングを解除する。その端末をすぐに切り、その端末がこの PC で開いたアプリを表示する。アプリは残す。`--close-apps` を付けると、閉じるよう頼む（12） |

**`istesso open` が、つなぐか、起動するか**（提案。R-03「窓はホスト側で生き続ける。端末は接続し直すだけ」に合わせた）：

1. そのアプリのセッションが、起きているホストにあるかを調べる。どの端末が始めたものでもよい。
2. 1 つあれば、それにつなぐ。離れていたものは戻り、ほかの窓に映っていたものは、こちらの窓に移る。解除された端末が残したものにつなぐときは、だれが開いたものかを表示する。
3. いくつもあれば、並べて見せて、選んでもらう（`--session <ID>`）。
4. なければ、起動する。行き先は、これまでどおり（手元 → 起きているホスト → 負荷の低いホスト）。
5. `--new` を付けると、セッションを調べずに、新しく起動する。`--host <端末>` を付けると、その端末だけを見る。

セッションがあるときに、手元のアプリより先にそちらを選ぶのは、やりかけの作業がそこにあるからである。新しく空のアプリを開くより、続きに戻るほうが、頼まれたことに近い。

**止め方と、その理由**（提案）：

| 人がしたこと | 起きること | 理由 |
|---|---|---|
| 窓を閉じようとした | アプリに、閉じるよう頼む。窓は、アプリが終わるまで開いている | 人の決定の 4。手元のアプリの窓を閉じるのと同じ動きにする。アプリが保存するかを尋ねたとき、答える窓が要る |
| `istesso open` を Ctrl-C で止めた。端末を閉じた | 離れる。アプリは動き続ける。戻り方と、止め方を表示する | Ctrl-C が止めるのは、コマンドである。ふたを閉じるのと同じで、作業を消してはいけない（人の決定の 3）。ここで閉じるよう頼むと、アプリが尋ねても、答える窓がもうない |
| ビューアーが終わった（終了させた。落ちた） | 離れる。アプリは動き続ける | 同上 |
| スリープした。ネットワークが切れた | 15 秒後に、ホストが絵を止める。アプリは動き続ける。戻ったら、`istesso open` をもう一度実行する | 人の決定の 3 |

### 12. ペアリングを解除したとき

解除は、端末をなくしたときだけでなく、入れ直しや、ペアリングのやり直しでも起きる。解除した端末からは、すぐに何もできなくする。一方で、その端末から始めた作業（長く動かしているもの）は消さない。

**何が起きるか**

1. 解除のコマンド（`istesso peers remove`）は、ペアリングの一覧から消したあと、同じ PC のエージェントに、その場で知らせる（13 の口）。
2. エージェントは、知らせに答える前に、その端末と開いている制御チャンネルの接続を、全部閉じる。待たせていた答え（`session_wait`）も送らない。
3. セッションの見回りは、知らせで起こされて、ペアリングの一覧を読み直す。その端末に映していたセッションは、ランナーに `detach` を伝えて、絵と音を止める（9）。入力は、制御チャンネルの接続が切れたので、もう届かない。
4. その端末は、つなぎ直せない。ハンドシェイクは、接続のたびにペアリングの一覧を読むので（ADR 0007）、知らない端末として断られる。
5. その端末が始めたセッションには、印が付く（`left_by` に、その端末の名前）。アプリは動き続ける。

**「すぐ」とは、何秒か**

| 何が | いつまでに | 理由 |
|---|---|---|
| 制御チャンネルの接続を閉じる | 解除のコマンドが戻るまでに | エージェントは、閉じ終えてから、コマンドに答える。解除した人が、コマンドの戻りを見た時点で、もう切れている |
| ランナーに `detach` を伝える | 知らせから 0.1 秒以内 | 見回りの 1 回ぶん。見回りは、知らせで起こされる |
| ランナーが、送るのと受けるのをやめる | `detach` を読んでから 0.1 秒以内（9 の決まり 7。映像の側が守る） | 絵の数コマぶん。これより短い約束は、守れたかを確かめにくい |
| その端末からの、次のリクエスト | 届いた時点で、答えずに接続を閉じる | リクエストが届くたびに、一覧を読み直す |
| コマンドを使わずに一覧が変わったとき（ファイルを直接書き換えた。エージェントに知らせが届かなかった） | 1 秒以内 | エージェントは、開いている接続と、セッションのそれぞれについて、1 秒おきに一覧を読み直す。もっと短くすると、何も起きていないあいだも、ホストがファイルを読み続ける。ふつうの道（コマンド）は、これを待たない |

解除された端末の側では、窓の絵が止まり、ホストが答えなくなったと分かった時点（15 秒）で、窓が閉じる。その窓をホストから閉じる手段はない（もう信頼していない相手である）。ホストが止めるのは、ホストから出ていくものと、ホストが受け取るものである。

**アプリは、残す**

- 解除した端末が起動していたアプリは、自動では閉じない。
- 解除のコマンドは、その端末がこの PC で開いたアプリを表示する。何もしなければ、残る。`--close-apps` を付けると、それぞれに閉じるよう頼み、5 秒待って、終わったものと、まだ動いているもの（保存するかを尋ねているかもしれない）を表示する。力ずくでは終わらせない。
- 残したセッションは、「閲覧」と「操作」を持つ、ペアリング済みのどの端末からも使える。一覧に出て、つなげて、閉じるよう頼めて、終わらせられる。一覧には、「解除された <端末の名前> が開いた」と出る。ホストにいる人も、同じことができる（13）。
- この印は、消えない（下の「同じ端末を、ペアリングし直したとき」）。
- 起動の途中だったセッション（アプリを、まだ起動していない）は、起動せずに終わらせる（理由は `stopped`）。失われる作業がないからである。
- 残したセッションも、開いておける数（64）に数える。空けるには、だれかが終わらせる。

**何を引き換えにしたか**（人の決定、2026-11-16）

- 解除したあとも、その端末が開いていたアプリは、人が「閲覧」と「操作」の両方を与えてペアリングした、ほかのどの端末にも映せる。これは、解除する前からそうである（人の決定の 9）。解除で変わるのは、その端末自身が届かなくなることと、アプリに印が付くことである。
- それでも残すのは、作業を消さないためである。解除の操作は、そのアプリを表示し、閉じるよう頼むこともできる（`--close-apps`）。ほかの端末に見せたくないアプリは、そこで閉じるよう頼む。
- 権限を持たない端末には、何も渡らない。閲覧だけの端末も、ペアリングしていない端末も、残ったセッションについて、ほかのセッションと同じように断られる。

**権限を確かめる場所**（残ったセッションについても、ほかのセッションと同じ）

| リクエスト | 届いたとき | そのあと |
|---|---|---|
| `session_list` | ペアリングの一覧を読み、ペアリング済みで、「閲覧」と「操作」を持つことを確かめる（`Sessions::admit`）。そのうえで、使えるセッションだけを並べる（`session::policy::may_use`。ここでも、同じ権限を確かめる） | — |
| `session_attach` | 同上 | 見回りが、ランナーに伝える直前に、一覧を読み直す。つないでいるあいだも読む。答える直前にも読む |
| `session_wait` | 同上 | 答えを待たせたあと、答える直前に、一覧を読み直す |
| `session_stop` | 同上 | — |

- ペアリング済みで、権限が足りない端末には、`forbidden` と答える。セッションがあってもなくても、同じ答えなので、あるかどうかは伝わらない。`not_found` にしなかったのは、足りないのが権限だと、人に分かるようにするためである。
- ペアリングしていない端末には、何も答えない。新しい接続は、ハンドシェイクで断られる。開いていた接続は、答えずに閉じる。

**ペアリングの一覧が読めないとき**

- ファイルがない。途中までしか書かれていない。壊れている。読む権限がない。どれも、**解除とは扱わない**。分かっていることが、何もないからである。
- **全部、閉じる側に倒す**（人の確認、2026-11-16）。読めないあいだは、どの端末にも、映すことも、操作することも、つなぎ直すことも許さない。

| 何が | 読めないあいだ | 場所 |
|---|---|---|
| `session_start`、`session_list`、`session_attach`、`session_wait`、`session_detach`、`session_stop` | 断る。セッションの表は `unavailable` と答え、エージェントは、それも送らずに接続を閉じる | `Sessions::admit`、`serve.rs` の `handle()` |
| そのほかのリクエスト（役割表、アプリ一覧、あとで入る入力） | 答えずに、接続を閉じる | `serve.rs` の `handle()` |
| 新しい接続 | 受け付けない | ハンドシェイク（ADR 0007） |
| 映しているセッション | 絵を止める（`detach`）。1 秒以内（見回りが一覧を読むのは、1 秒おき）。アプリは動き続ける | 見回り（`Inner::round`） |
| つないでいる途中のクライアント | つながない。断る | 同上 |
| 起動の途中のセッション | アプリを起動せずに終わらせる（`app_failed`） | `Inner::supervise` |

- 決めつけないこと：印を付けない。外さない。使える端末を広げない。アプリを終わらせない。何もしていない接続を、こちらからは切らない（その接続で何かを頼めば、そこで閉じる）。
- 一覧が読めるようになれば、権限のある端末が、またつなげる。
- 「ない」と「空」を分ける理由：最後のペアリングを解除したときは、空の一覧が残る。ファイルがないのは、何かが起きたときである。

**同じ端末を、ペアリングし直したとき**

| し直し方 | 起きること |
|---|---|
| 前と同じ鍵で | 印（`left_by`）は残る。その端末は、権限のあるほかの端末と同じ立場で、そのセッションを使える |
| 新しい鍵で（入れ直した） | 別の端末として扱う。残ったセッションは、「解除された <名前> が開いた」ものとして、ほかの端末と同じように使える |

印を外さない理由：解除されたことは、起きたことである。そのアプリを、解除された端末が開いたことは、あとから使う人が知っていてよい。

**権限を外されただけの端末**（ペアリングは残っている）

- 絵は、同じように、すぐ止める。セッションのリクエストは、どれも断る。
- その端末が始めたセッションは、権限のあるほかの端末から、これまでどおり使える。印は付かない（解除ではないため）。権限を戻せば、その端末もまた使える。
- ホストにいる人の一覧（`istesso sessions --local`）には、「その端末は、いまは使えない」と出る。いまは、権限を外すコマンドがないので、ペアリングの一覧を手で書き換えたときにしか起きない。

**解除の操作での選ばせ方**（作ったものと、その理由）

- 「何もしなければ残す。`--close-apps` と書けば、閉じるよう頼む」にした。解除したあとでも、表示された ID を使って、1 つずつ閉じるよう頼める（`istesso sessions stop <ID> --local`）。
- その場で尋ねる形（「残しますか」と聞いて、答えを待つ）にしなかった理由：ホストには、ふつう、人がいない（人の決定の 7）。解除は、SSH の先や、スクリプトや、あとで作るランチャーの画面から行われる。答えを待つコマンドは、そこで止まる。ランチャーの画面では、同じ 2 つの選択肢を、画面で尋ねればよい。

**確かめ方**（自動のテスト）

- 解除する → 開いていた接続が切れる。つなぎ直せない。窓は閉じる。アプリは動いている。
- 離れているセッションの持ち主を解除する → 見回りの 1 回で印が付く。その端末は、見ることも、映すことも、止めることもできない。
- 権限のあるほかの端末は、一覧で見て、つないで、止められる。閲覧だけの端末は、できない。
- 知らせがなくても、1 秒おきの読み直しで、接続が切れる。

### 13. ホストにいる人

セッションは、権限を持つ端末にしか見えない。それだけだと、権限を持つ端末が手元に 1 台もないとき（最後の 1 台を解除した。持って出た）に、ホストで動いているアプリを見て、片づける人がいない。そこで、**ホストにログインしている人は、そのホストのセッションを全部見て、止められる**ようにした。

- コマンドは、`istesso sessions --local`（一覧。始めた端末と、印が出る）と、`istesso sessions stop <ID> --local [--force]`。
- コマンドは、同じ PC で動いているエージェントに、Unix ドメインソケットで尋ねる。場所は、エージェントのランタイムディレクトリの `agent.sock`（14 に、もう 1 つの場所がある）。
- **だれが尋ねてよいかは、ファイルシステムが決める。** ソケットを置くディレクトリは、エージェントを動かしているユーザーだけが入れる（モード 0700）。エージェントは、ソケットを開く前に、ディレクトリが自分のもので、ほかのユーザーに開いていないことを確かめる。開いていたら閉じる。自分のものでなければ、ソケットを開かない。ソケット自身も 0600 にする。カーネルが、そのユーザー（と root）にしか接続させない。root は、もともと、その PC で何でもできる。
- エージェントは、相手がだれかを、ほかの方法では確かめない。ソケットに届いたものは、同じユーザーからのものとして扱う。暗号化もしない。通るのは、セッションの一覧と、止める頼みと、「ペアリングの一覧が変わった」という知らせだけで、鍵も、`offer` と `answer` も通さない。
- 尋ねる側も、同じことを確かめる。ディレクトリが自分のもので、ほかのユーザーに開いていないときだけ、そこのソケットを信じる。ほかのユーザーが置いた偽物に、尋ねないためである。
- やり取りは、ランナーと同じ形である（1 行に 1 つの JSON。`v` は 1）。知らない頼みには、`unsupported` と答える。

```text
→ {"v":1,"ask":"sessions"}
← {"v":1,"answer":"sessions","sessions":[{"info":{"id":"5b0c9e3a7f21d684","app":"org.gnome.TextEditor.desktop","state":"detached","left_by":"laptop"},"app_name":"Text Editor","started_by":{"id":"1a2b-3c4d-5e6f-7a8b","name":"laptop"},"revoked":true}]}
→ {"v":1,"ask":"session","session":"5b0c9e3a7f21d684"}
→ {"v":1,"ask":"stop","session":"5b0c9e3a7f21d684","force":false}
← {"v":1,"answer":"session","session":{"info":{"id":"5b0c9e3a7f21d684","state":"detached"},"app_name":"Text Editor","started_by":{"id":"1a2b-3c4d-5e6f-7a8b","name":"laptop"},"revoked":true}}
→ {"v":1,"ask":"pairings_changed"}
← {"v":1,"answer":"done"}
← {"v":1,"answer":"refused","code":"not_found","message":"no such session"}
```

（`info` は、制御チャンネルの `session` と同じ形で、`answer` を除いたもの。上では、項目を省いている。`revoked` は、始めた端末が、いまはそのセッションを使えないことを表す。）

- 1 人のユーザーが、同じ PC でエージェントを 2 つ動かすときは、2 つめに `ISTESSO_RUNTIME_DIR` で別の場所を与える。同じ場所では、あとから始めたほうは、ソケットを開かない（先のものを奪わない）。
- 権限の要る処理は、増えていない。root も、新しい種類の OS の許可も要らない。
- 採らなかった形：制御チャンネルに、その PC 自身の鍵でつなぐ（「自分の鍵を読める」ことを、ホストにいる証拠にする）。メッセージをそのまま使えるが、ハンドシェイクで受け入れる相手を増やすことになり、ADR 0007 の手順の変更になる。ネットワークの口が、止める操作を受け付ける相手も増える。ファイルの権限だけで決まるほうが、小さく、確かめやすい。

### 14. ホストの前に、だれもいないとき

人の決定の 7 のとおり、ホストは、起動した直後（ログイン画面のまま、SSH だけ）の状態でも動かなければならない。制御の側について、その状態でどうなるかを書く。

| 事柄 | その状態で | 要るもの |
|---|---|---|
| エージェントが動いていること | **動かない。** いまは、人がログインして、手で `istesso agent` を起動している。ホストを起動し直すと、だれかがそうするまで、エージェントがいない | インストーラー（M9）が、ユーザーの常駐サービス（systemd のユーザーユニット）として登録し、ログインしていなくても動くようにする（`loginctl enable-linger`。管理者の権限が要ることがある）。Mac のクライアントは、ログインして使うものなので、LaunchAgent でよい。Mac をホストにするとき（M4）は、画面の取り込みがログインのあとでないとできないので、そのときに決める |
| ランタイムディレクトリ（ソケットの置き場所） | **条件つきで動く。** `$XDG_RUNTIME_DIR` は、そのユーザーがログインしているあいだだけある。常駐の設定（lingering）がなければ、最後のログインが終わったときに消え、SSH から手で起動したエージェントのソケットも一緒に消える | 上と同じ（lingering があれば、起動から終了まである）。それとは別に、エージェントは、ランタイムディレクトリを使えないとき、キャッシュの隣（`~/.cache/istesso/run`。同じく 0700）にソケットを置く。尋ねる側は、両方を探す。エージェントが、ランタイムディレクトリのない状態で始まり、人があとからログインして尋ねても、見つかる |
| セッションの表、見回り、ペアリングの読み直し、制御チャンネル、ホストにいる人の口 | 動く。デスクトップに頼るものがない | — |
| アプリの起動 | **エージェントの受け持ちは、動く。** アプリは、ランナーが返した環境変数で、ランナーの仮想ディスプレイに出る。ホストのデスクトップは使わない（`DISPLAY` は外す）。ただし、アプリが表示先を見つけるのに要るものを、ランナーが全部返す必要がある。ランタイムディレクトリがない環境では、`WAYLAND_DISPLAY` に名前だけを返しても、アプリはソケットを見つけられない | ランナー（映像の側）：`WAYLAND_DISPLAY` を絶対パスで返すか、`XDG_RUNTIME_DIR` も `env` で返す。インストーラー（M9）：ユーザーの D-Bus（セッションバス）がある状態にする（lingering があれば、ある）。設定の保存や、1 つしか動かないアプリの仕組みが、これに頼る |
| GPU（描画とエンコード） | 制御の側は使わない | 映像の側が調べる。描画用のデバイスは、その PC の前でログインしている人にしか開けない設定（`uaccess`）のことがある |

ホストを起動し直すことはできないので、確かめたのは、「ランタイムディレクトリも、デスクトップの変数もない環境で、エージェントを起動する」ところまでである。結果と、人と一緒に確かめることは、「確かめたこと」に書く。

### 15. 圧縮の枠（制御の側は作った。映像の側は、まだ）

人の決定の 10 のとおり、数えて制限するのは、開いているセッションではなく、同時に圧縮している映像の数である。人の決定の 12 のとおり、**セッションは、あるが、エンコーダーを持っていない、という状態を取れる。** その状態は 3 つある。

| 状態 | エンコーダー | 戻り方 |
|---|---|---|
| `detached`（だれにも映していない） | 持たない | つなぐ（`session_attach`。新しい `offer` と `answer`） |
| `running` で `paused: hidden`（つないでいるが、窓が見えていない） | 持たない | 窓が見える（`session_show`）。つなぎは、そのまま |
| `running` で `paused: no_slot`（つないでいるが、枠が足りない） | 持たない | 人がその窓に向く。または、ほかの窓が枠を手放す |

制御の側（この流れのクレートとメッセージ）は、ここまでを作った。エンコーダーを実際に閉じて開くこと、窓が見えているかを知ること、止まっている印を出すことは、映像の側の作業で、要るものを下に書いた。

**NVIDIA の文書で確かめたこと**（2026-11-17 に読んだ）

| 文書 | 書いてあること |
|---|---|
| NVENC Application Note（Video Codec SDK 12.1 の版）、「NVENC Licensing Policy」 | 認定外の GPU（GeForce）では、同時のエンコードは、システムで 5 本まで |
| 同（SDK 12.2 と 13.0 の版） | システムで 8 本まで。認定外のカードを何枚挿しても、合わせて 8 本（例：Quadro 1 枚と GeForce 3 枚なら、N + 8 本） |
| 同（SDK 13.1 の版） | システムで 12 本まで。文は同じで、数だけが違う |
| Video Encode and Decode GPU Support Matrix（同じ日に読んだ版） | GeForce の行の「Max # of concurrent sessions」は、12 |

- 「8 本」という理解は、SDK 12.2 と 13.0 の版の記述と合う。**いちばん新しい版（13.1）と対応表は、12 本と書いている。** どちらが効くかは、入っているドライバーで決まるはずだが、どのドライバーから 12 本なのかは、読んだ範囲には書かれていなかった。ホストのドライバー（590 系）で実際に何本開けるかは、まだ試していない。
- 「同じ PC での録画や配信も、同じ枠に入る」：文書は、「システムごと」「認定外のカード全部の合計」と書いている。ほかのアプリのぶんを含む、という文は見つからなかったが、アプリごとではなく、システムごとの数なので、含むと読むのが自然である。試して確かめる。
- だから、枠の数は、決め打ちにせず、設定にする。初めの値は 8 にする（少ないほうに倒す）。ホストで試して 12 本開けたら、上げる。

**作ったもの**

- 数えるのは、「つないでいて、窓が見えているセッション」である。離れているセッションと、窓が見えていないセッションは、数えない。
- **見えていない窓は、止める。** ビューアーが `hidden` と `visible` をコマンドに知らせ、コマンドがホストに `session_show` を送る。エージェントは、ランナーに `pause` と `resume` を伝える。つなぎは保ったままで、新しい `offer` と `answer` は要らない。アプリは、動かしたままにする。
- **枠が足りなくなっても、開くのを断らない。** 数えたセッションが枠の数を超えたら、エージェントが、向かれたのがいちばん前の窓から順に、枠を外す。その窓のランナーに `pause` を伝え、セッションの答えに `paused: no_slot` を載せる。コマンドは、ビューアーに `paused` を伝え、「映像を止めています。その窓に向くと、戻ります」と表示する。人がその窓に向くと（ビューアーが `visible` を送る）、その窓が枠を取り、代わりに、いちばん前に向かれた窓が止まる。`istesso sessions` にも、止まっている窓と理由が出る。
- 枠の数は、設定である（`istesso agent --encoder-slots <数>`、または `ISTESSO_ENCODER_SLOTS`。初めの値は 8。人の決定の 16）。インストーラー（M9）が、映像が流れていないときに、そのホストで開ける数を 1 回数えて、2 つ少ない値を設定に書く。カードから数を読むことはできない（このホストのドライバーでは、カード自身の数えが 0 を返す）。
- **動いている最中に、エンコーダーを断られたとき。** 設定の値より少ない数でも、起きうる（ほかのアプリが使った。カードが、言っている数より少なくしか出さない）。ランナーは、終了せずに `no_encoder` と言う。エージェントは、何も終わらせない。そのホストが同時に作る絵の数を、いま作れている数まで下げて、いちばん前に向かれた窓（いま見られていない窓）の絵を止める。その窓のセッションの答えに `paused: no_slot` が載るので、クライアントが、使う人に知らせる。断られたランナーには、枠を譲った窓がエンコーダーを手放すのを 0.5 秒待ってから、`resume` を伝える。下げた数は、60 秒たったら、設定の値に戻して、もう一度試す。 枠を持っていないセッション（だれにも映していない、窓が見えていない、止めるよう伝えたばかり）のランナーが `no_encoder` と言っても、数は下げない。

**夜のあいだに選んだこと**（どれも、あとで変えられる）

| 選んだこと | 理由 | ほかの案 |
|---|---|---|
| 枠の数の初めの値は 8（人の決定の 16 で、このまま） | 文書が 8 と 12 に分かれている。少ないほうなら、足りなくなったときに、決めたとおりの止まり方をする。多いほうにして外れると、エンコーダーが開けずに失敗する | 12 |
| 断られたあと、下げた数を保つのは 60 秒 | 短いと、開けないエンコーダーを何度も開こうとして、窓の絵が出たり止まったりする。長いと、ほかのアプリが録画をやめたあとも、止まったままになる | 断られなくなるまで、少しずつ試す |
| 断られたときに止めるのは、いちばん前に向かれた窓 | 見えていない窓は、もともと枠を使っていない。残りの中では、いちばん長く見られていない窓が、「見られていない窓」にいちばん近い | 断られた窓そのものを止める（どの窓かは、たまたまで決まる） |
| 枠を譲るのは、向かれたのがいちばん前の窓 | 人が見ている窓を止めないため。「向いた」は、つないだときと、ビューアーが `visible` を送ったとき | 最後に操作された時刻で決める。入力がセッションを名乗るようになれば、そちらに替える（入力は、エージェントを通る） |
| 止めるときに、つなぎを保つ（`pause`） | 見えるようになったときに、`offer` と `answer` をやり直さずに済む。番号も変わらないので、窓はそのまま使える | 離して、つなぎ直す（`detach` と `attach`）。作るものは減るが、戻るのが遅くなる |
| 止まっていることは、セッションの答えの項目（`paused`）で知らせる | 一覧にも、窓にも、同じ言い方で出せる。状態（`running`）は変えないので、古いクライアントは、これまでどおり動く | 状態を足す。古いクライアントが、知らない状態を受け取る |

**映像の側に要るもの**（ここで止めた）

| 側 | 要るもの |
|---|---|
| ランナー（ホスト） | `pause` で、エンコーダーを閉じる。`resume` で、開き直して、前の絵に頼らないフレームから送る。`detach` でも、エンコーダーを閉じる。`attach` を受けたら、止めていても送り始める。開き直しにかかる時間を測る（戻るまでの待ちになる）。エンコーダーを開けなかったとき（起動のとき、`resume` のとき、動いている最中）は、終了せずに、`no_encoder` と言う。名指された 1 台にだけ送る（`start` と `attach` の `peer` の ID と公開鍵。予行のブランチの `Host::admit`） |
| ビューアー（クライアント） | 窓が見えなくなったら `hidden`、見えるようになったら `visible`。人がその窓を前面にしたときも `visible`。`paused` を受けたら、最後の絵を出したまま、止まっていると分かる印を出す。`resumed` で消す |
| 入力 | セッションごとに、最後に操作された時刻を、エージェントが分かること |
| 計測 | ホストのドライバーで、同時に開けるエンコーダーの数（8 か、12 か）。ほかのアプリの録画が、同じ数に入るか |

偽物のランナーとビューアーは、これらの行を受けて、記録するだけである。

**あとから足すものを、いまの作りが難しくしないか**

| 足すもの | いまの作りとの関係 |
|---|---|
| 枠を、「いま絵が変わっている窓」に配る | 妨げるものはない。枠の出し入れは、`pause` と `resume` と同じ口でできる。きっかけが、ランナーの側（絵が止まった、動き出した）になるだけで、ランナーからの行を足せばよい。ランナーはセッションごとに別のプロセスで、互いが見えないので、枠を配るのは、エージェントになる |
| 何枚かの窓を 1 本の映像にまとめ、クライアントで切り分ける | **ここは、1 対 1 の決めごとに当たる。** いまは、セッション 1 つ ＝ ランナーのプロセス 1 つ ＝ 仮想ディスプレイ 1 つ ＝ 映像 1 本 ＝ ビューアーのプロセス 1 つ、である（9 の境界。`offer` と `answer` も、セッションごと）。まとめるには、いくつかのセッションの絵を、1 つのプロセスが扱う必要がある。エージェントの中の口（`Runner`）は、セッションごとに「始める」を呼ぶだけなので、裏で 1 つのプロセスに束ねる実装に替えられる。`offer` と `answer` は中を見ないので、「どの映像の、どの部分か」を載せられる。変わるのは、ランナーとビューアーとの行の約束と、ビューアーが窓ごとのプロセスである、という点である |
| 別の圧縮の口（内蔵グラフィックス、CPU） | 妨げるものはない。制御の側は、エンコーダーの種類を知らない。枠の数を、口ごとに持てるようにしておく |

セッションと圧縮の枠を、1 対 1 で固定している場所は、制御の側のコードにはない（枠を数えていない。これまでの「8 つまで」は、開いているセッションの数で、今回やめた）。約束の上では、上の 2 行目のとおり、セッションと映像が 1 対 1 である。

## 映像の側と決めたこと（2026-11-16）

1. 境界は A（プロセス）。ランナーとビューアーは別のプロセスで、標準入出力に、1 行に 1 つの JSON。
2. アプリを起動するのは、エージェント（ランナーではない）。
3. 標準入力が閉じたら終わる。ポートは固定しない。`ready` で環境変数を返す。
4. `offer` と `answer` は、1 往復で足りる（つなぐたびに 1 往復）。
5. 入力は、制御チャンネルで、エージェントを通す（上の「入力」）。`start` の `peer` は ID とアドレスだけにして、`input_socket` を足す。
6. `peer.address` は、制御チャンネルの接続元。IPv6 のリンクローカルには、ゾーンを付ける。
7. `istesso_link::Session`（1 回の会話を指す型）は、いまは改名しない。
8. いまの送信側のスクリプトとビューアーを、この約束に合わせる包みは、映像の側が書く。閉じるよう頼むための、コンポジターへの追加も同じ。

## 決めてほしいこと

1. 圧縮の枠（15）の、決定が触れていない細部：断られたあと、下げた数を保つ時間（60 秒にした）。断られたときに止める窓の選び方（いちばん前に向かれた窓にした）。
2. `detach` を読んでから 0.1 秒以内に止める、という数（9 の決まり 7）。映像の側の確認待ちである。

決まったこと（2026-11-16、17）：ほかの端末が始めたセッションにも、つなげる（人の決定の 9）。端末ごとの上限は、やめる（10）。解除のときの選ばせ方は、`--close-apps`（11）。入力と映像は、映している端末だけ。入力の権限は、頼まれたときに読み直す（13 から 15）。圧縮の枠の既定は 8（16）。

映像の側に、確かめたいこと：

- `detach` の意味を強めた（そのクライアントとのやり取りを全部やめ、決めた宛先や鍵を捨てる）。エンコーダーも手放す必要がある（15）。
- 音の経路がランナーの外にできるなら、同じ合図で止まる必要がある。
- ランタイムディレクトリがない環境でもアプリが表示先を見つけられるように、`ready` の `env` を返す（14）。
- `SessionInfo` に `left_by` と `shown_on` を足した。`serve.rs` の `handle()` に、開いている接続の一覧と、リクエストごとの読み直しを足した。

### ホストの前に、だれもいないとき

ホストを起動し直すことはできないので、次のことまでを確かめた。

- 空の環境で起動したエージェントで、上の表の 7 行目が通る。制御の側に、デスクトップのセッションに頼るところはない。
- ホストの設定を、読むだけで調べた（何も変えていない）。そのユーザーの常駐の設定（lingering）は、すでに有効である。自分のぶんを有効にするのに、管理者の権限は要らない設定になっている。ユーザーのセッションバスがある。エージェントは、常駐サービスとして登録されておらず、手で起動されている。
- **確かめた時点で、ホストには、画面の前のログイン（X11）が 1 つあった。** だから、「だれもログインしていない」状態そのものでは、何も確かめていない。

人と一緒に確かめること：

1. ホストを起動し直し、だれもログインしないまま、クライアントから `istesso open` を実行する。いまは、エージェントが動いていないので、「応答しない」になるはずである。
2. エージェントを常駐サービスにしてから（M9）、同じことをして、通ること。そのとき、`istesso sessions --local` を SSH から実行して、見つかること。
3. 画面の前のログインがない状態で、本物のランナーが仮想ディスプレイを作り、本物のアプリがそこに出ること（映像の側と一緒に）。

### 確かめていないこと

- 手元のアプリを `istesso open` で開くこと（Mac に窓が開くので、遅延の計測の邪魔にならないよう、実機では動かしていない）。
- 本物のコンポジターの中でのアプリの起動と、本物の「閉じてほしい」。本物のランナーが、`detach` で 0.1 秒以内に止まること。
- `istesso peers remove` を、実機で実行すること（上のとおり）。コマンドが表示する文は、テストで確かめている。

## 結果

- 映像の側は、ランナーとビューアーを、この約束に合わせて作る。制御の側は、映像の中身を知らないまま、始めと終わり、つなぐと離れるを受け持つ。
- `main` では、偽物のランナーとビューアーで動く。本物は、映像の側がつなぐ。
- 制御チャンネルに、「頼むと、相手の PC でプログラムが動く」メッセージがある。頼めるのはアプリ一覧にあるものだけで、「閲覧」と「操作」の権限が要る。
- ホストには、だれにも映っていないアプリが残りうる。`istesso sessions` で見えて、止められる。開いておける数（64。設定で変えられる）に達したら、新しい起動を断って、理由と、離れているものを知らせる。
- ペアリングを解除した端末は、その場で切られる。その端末が開いたアプリは残り、権限のあるどの端末からも、ホストにいる人からも、見えて、つなげて、止められる。
- ホストのエージェントは、同じユーザーにだけ開いたソケットを 1 つ持つ。
- 型の名前が紛らわしい。`istesso-link` の `Session` は 1 回の会話を指し、この ADR の `Session…` は配信セッションを指す。前者は、いまは改名しない（映像の側と決めた）。

## 変更の手順

- メッセージを足すのは、制御チャンネルの版を上げずにできる（ADR 0007）。意味を変えるときは、先にこの文書を更新する。
- ランナーとビューアーの約束を変えるときも、先にこの文書を更新する。項目や行を足すのは、`v` を上げずにできる。互換性のない変更では、`v` を上げる。
