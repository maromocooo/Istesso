# ADR 0010：アプリの起動と、配信セッションの始め方・終わり方

- 状態：採用。映像の経路との境界は、映像の側と合意した（2026-11-16）。寿命と終わらせ方は、人の決定に合わせて作り直した（同日）。未決は、下の「決めてほしいこと」の 1 つ
- 日付：2026-11-16
- 更新：2026-11-16（映像の側の決定を入れた。入力は、制御チャンネルでエージェントを通す）
- 更新：2026-11-16（人の決定を入れた。クライアントがいなくなっても、アプリは終わらせない。窓を閉じるのは、アプリへの頼みにする。セッションの一覧、つなぎ直し、止める操作を足した）

## 背景

M3（アプリマネージャー）の最初の一切れとして、次の 2 つを作る。

- ある端末が別の端末に、アプリの起動と終了を頼むメッセージ。
- 窓が 1 枚開くコマンド（`istesso open <アプリ>`）。ホストがアプリを配信用に起動し、クライアントがそれを映す窓を開く。

映像と入力の経路は、M1 で作っている途中である（`m1-latency` ブランチ。`main` にはまだない）。いまの形は次のとおり。

- ホスト：1 つのプロセスが、仮想コンポジター、エンコーダー、送信を受け持つ（いまは計測用のスクリプト。あとで `istesso-media-linux`）。絵の大きさ、フレームレート、圧縮の設定、送り先を渡されて動き、Wayland のソケットの名前を知らせる。アプリは、`WAYLAND_DISPLAY` をその名前にして起動する。
- クライアント：1 つのプロセスが窓を開いて映す（いまは計測用のビューアー。あとで `istesso-media-macos`）。窓の位置、受信するポート、キーフレームを求める先のポートを渡されて動く。
- 入力は、制御チャンネル（`istesso-link`、[ADR 0007](0007-control-channel.md)）で運ぶ（`m1-latency` にある）。セッションに属する。映像は、いまは計測用の暗号化していない RTP で、あとで暗号化した経路に替わる。

2 つの作業が並んで進むので、実装の前に境目を決める。分け方は次のとおり。

- **制御の側**（この ADR）：どのアプリを、どのホストで、どの端末に向けて、いつまで動かすか。セッションの識別、渡す値、寿命。
- **映像の側**（M1）：絵と入力をどう運ぶか。コーデック、圧縮の設定、経路、ポート、鍵、入力のメッセージ。

## 人が決めたこと（2026-11-16）

1. コマンドの名前は `istesso open`。
2. ペアリング済みの端末（「閲覧」と「操作」を持つ）は、アプリを起動してよい。
3. **クライアントがいなくなっても、アプリを終わらせない。** ふたを閉じたせいで、作業が消えてはいけない。動いているセッションの一覧、つなぎ直し、止める操作が要る。
4. **窓を閉じるのは、アプリへの「閉じてほしい」という頼みで、アプリを殺すことではない。** アプリは、保存するかどうかを尋ねられなければならない。

3 と 4 は、はじめの提案（クライアントがいなくなったら 15 秒でアプリごと終わらせる。窓を閉じたら SIGTERM を送る）を取り下げるものである。

## 用語

| 語 | 意味 |
|---|---|
| セッション | ホストで動くアプリ 1 つと、その仮想ディスプレイ（R-02 の「1アプリ = 1仮想ディスプレイ = 手元の1窓」）。アプリが動いているあいだ、ホストにある |
| ホスト、クライアント | アプリが動く端末、窓を出す端末 |
| つなぐ、離れる | クライアントが、セッションの絵を受け取り始めること、やめること。離れても、アプリは動き続ける |
| ランナー | ホストで、セッション 1 つぶんの仮想ディスプレイと送信を受け持つプロセス。映像の側が作る |
| ビューアー | クライアントで、セッション 1 つぶんの窓を受け持つプロセス。映像の側が作る |

## 決定

### 1. だれがだれに頼むか

- 頼むのはクライアントで、頼まれるのはホストのエージェント。制御チャンネルの、いまと同じ形（聞いて、答える）を使う。ホストからクライアントへは接続しない。
- どのホストで起動するかは、クライアントが決める。`istesso-catalog` がすでに出している `preferred_host`（手元 → 起きているホスト → 負荷の低いホスト。R-04）に従う。手元にあるアプリは、中継せずに手元で起動する。すでに動いているセッションがあるときの決まりは、10 にある。
- 頼めるのは、**そのホストのアプリ一覧にある ID** だけ。コマンドライン、引数、環境変数は、相手から受け取らない。

### 2. セッションの識別と、持ち主

- ID はホストが決める。OS の乱数から作った 64 ビットを、16 桁の 16 進数で書く。全体では「ホストの端末 ID ＋ セッション ID」で 1 つに決まる。
- **ID は秘密ではない。** 知っていても、何もできない。だから、ID はログや画面に出してよい。
- セッションには持ち主がいる。それを始めた端末である。確かめるのは、制御チャンネルのハンドシェイクで分かった身元（端末の ID と公開鍵）。
- **一覧に出るのも、つなげるのも、止められるのも、いまは持ち主だけ。** ほかの端末には「ない」と答え、あるかどうかを教えない。ペアリング済みのほかの端末にも広げるかどうかは、下の「決めてほしいこと」にある。この決まりは、コードの 1 か所（`session::policy::may_use`）にある。
- つなぐたびに、セッションの「つなぎの番号」（`attachment`）が 1 つ増える。いま絵を受け取っているクライアントが、どれかを表す。自分の番号より大きくなっていたら、ほかの窓に移った、と分かる。

### 3. セッションの寿命

**セッションは、アプリが終わるか、だれかが止めるまで続く。** クライアントがいるかどうかは、寿命に関係しない。

```text
 starting ──▶ running ◀──▶ detached ──▶ stopping ──▶ ended
              （映している）  （離れている）
```

| 状態 | 意味 |
|---|---|
| `starting` | ランナーが仮想ディスプレイを作り、エージェントがアプリを起動している |
| `running` | アプリが動いていて、クライアントが絵を受け取っている。`display` と `answer` は、そのクライアントのもの |
| `detached` | アプリは動いている。絵は、だれにも送っていない |
| `stopping` | アプリとランナーを止めている。`end` に理由がある |
| `ended` | 終わった。60 秒は覚えておき、遅れて届いた問い合わせに、理由を答える |

離れる（`running` → `detached`）のは、次のとき。どれも、アプリには触らない。

| 起きたこと | 気づく側と、その方法 |
|---|---|
| クライアントが「離れる」と言った（`istesso open` を Ctrl-C で止めた。ビューアーが終わった） | クライアントが `session_detach` を送る |
| クライアントがいなくなった（スリープ、電源、ネットワーク） | ホスト。絵を受け取っているクライアントからの `session_wait` が、15 秒来ない |
| 持ち主のペアリングが解除された。権限を外された | ホスト。動いているセッションについて、1 秒おきにペアリングの一覧を読み直す |
| ランナーが、送れなくなったと知らせた（`detached`） | ホスト |

終わる（→ `stopping` → `ended`）のは、次のときだけ。

| 起きたこと | 理由（`end.reason`） |
|---|---|
| アプリが自分で終わった。「閉じてほしい」と頼まれて終わった場合を含む | `app_exited` |
| 持ち主が、力ずくで終わらせた（`session_stop` の `force`） | `stopped` |
| アプリを起動できなかった | `app_failed` |
| ランナーが始まらない。途中で落ちた。アプリは表示先を失うので、一緒に終わる | `stream_failed` |

止める順は、アプリが先で、ランナーがあと。アプリが、表示先のあるうちに終われるようにする。

**終わらせ方は 2 つあり、混ぜない。**

- **閉じるよう頼む**（既定）。エージェントがランナーに `close` を伝え、ランナー（コンポジター）がアプリの窓に「閉じてほしい」と伝える。アプリは、ふつうは自分で終わる。保存するかを尋ねる窓を出したら、アプリはそのまま残り、セッションも続く。つながっているクライアントには、その窓が映る。
- **力ずくで終わらせる**。そう書いたとき（`--force`）だけ。アプリのプロセスグループに SIGTERM を送り、3 秒後に SIGKILL を送る。コマンドは、その時間を先に表示する。

時間と数（どれも、使ってみて直す）：

| 値 | いま | 理由 |
|---|---|---|
| `session_wait` で答えを待たせる時間 | クライアントは 2 秒を頼む。ホストは 3 秒までにする | エージェントが次のメッセージを待つ時間（5 秒）より短くする |
| クライアントからの `session_wait` が来なくなってから、絵を止めるまで | 15 秒 | Wi-Fi の短い切れは越える。いない相手に、絵を送り続けない。**止めるのは絵だけで、アプリではない** |
| ランナーの `ready` を待つ時間 | 15 秒 | GPU とエンコーダーの初期化 |
| ランナーの `attached` を待つ時間 | 10 秒 | 過ぎたら、つなぐ頼みを断る。セッションは `detached` のまま続く |
| 力ずくのとき、SIGTERM から SIGKILL まで | 3 秒 | |
| 終わったセッションを覚えておく時間 | 60 秒 | |
| 1 台のホストで同時に動かすセッション | 8 つまで。離れているものも数える | エンコーダーにも、メモリにも限りがある。**上限に達したら、新しい起動を断り、頼んだ端末の、離れているセッションの名前を答える。何かを黙って終わらせることはしない** |

### 4. メッセージ

制御チャンネルのメッセージ（JSON。`type` で種類を表す）に、リクエストを 6 つ、レスポンスを 2 つ、エラーの種類を 2 つ足す。チャンネルの版（`ISC1`）は上げない。古いホストは `unsupported` と答えるので、クライアントは「相手の `istesso` が古い」と表示できる。

| リクエスト | 意味 | 送れる端末 | 答え |
|---|---|---|---|
| `session_start` | アプリを起動して、呼び出した端末につなぐ | 「閲覧」と「操作」を持つ端末 | `session`（状態は `starting`、つなぎの番号は 1）。準備を待たずに、すぐ答える |
| `session_list` | 呼び出した端末の、終わっていないセッションを並べる | ペアリング済みの端末 | `sessions` |
| `session_attach` | 動いているセッションを、呼び出した端末につなぐ。新しい `display` と `offer` を渡す。いま絵を受け取っているクライアントがいれば、そこからは離れる | 持ち主で、「閲覧」と「操作」を持つ端末 | ランナーが送り始めてから、`session`（状態は `running`、新しい番号と `answer`）。つなげなければ、理由を付けて断る。セッションは `detached` で続く |
| `session_wait` | セッションの状態を答える。`after` より新しい変化がなければ、`timeout_ms` まで答えを待たせる。**`attachment` がいまのつなぎの番号と同じなら、そのクライアントがまだいることの知らせになる** | 持ち主 | `session` |
| `session_detach` | 離れる。絵を止める。アプリは動き続ける。`attachment` がいまの番号と違えば、何もしない（もう、ほかの窓に移っている） | 持ち主 | `session` |
| `session_stop` | `force` がなければ、アプリに閉じるよう頼む。あれば、力ずくで終わらせる | 持ち主 | `session`。頼んだだけのときは、状態は変わらない |

`session_attach` だけは、すぐには答えない。起動と違って、失敗してもセッションを終わらせてはいけないので、「断る」という答えが要る。アプリはもう動いていて、待つのはランナーが送り始めるまでである。

| エラー | 意味 |
|---|---|
| `forbidden`（いまもある） | 権限がない |
| `not_found`（新しい） | そのアプリが一覧にない。または、その端末のセッションに、その ID がない |
| `unavailable`（新しい） | このホストでは、いまはできない。ランナーが設定されていない、窓として出せないアプリ、セッションが多すぎる、ランナーがつなげなかった、など |

置き場所は、いまの決まりに合わせる。端末やプロセスの境目を越える型は `istesso-proto` に、リクエストとレスポンスは `istesso-link` の `message` に置く。新しい項目は、どの列挙でも末尾に足す（`ErrorCode` は、`other` の手前。serde が、受け皿を最後に置くことを求める）。`m1-latency` が同じ列挙に足した入力のメッセージと、並べるだけで合わせられるようにするためである。

```rust
// istesso-proto

/// Names one session on the host that runs it. The host makes it up: 16
/// lower-case hexadecimal digits from the system's random source. It is not
/// a secret. Knowing it grants nothing, so it may be shown and logged.
#[derive(Debug, Clone, PartialEq, Eq, Hash, Serialize, Deserialize)]
#[serde(transparent)]
pub struct SessionId(pub String);

/// Size and rate of a session's virtual display: the picture the client's
/// window shows, pixel for pixel.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
pub struct DisplayMode {
    pub width: u32,
    pub height: u32,
    /// Most frames a second the host sends: the refresh rate of the display
    /// the client's window is on.
    pub fps: u32,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum SessionState {
    /// The host is setting up the virtual display and starting the application.
    Starting,
    /// The application runs and a client is shown it; `display` and `answer`
    /// are that client's.
    Running,
    /// The application runs; nobody is shown it.
    Detached,
    /// The host is stopping the application and the stream; `end` says why.
    Stopping,
    /// Over.
    Ended,
    #[serde(other)]
    Unknown,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum EndReason {
    /// Its owner ended it by force.
    Stopped,
    /// The application ended by itself, asked to close or not.
    AppExited,
    /// The application could not be started.
    AppFailed,
    /// The host's side of the stream could not be started, or it failed.
    StreamFailed,
    #[serde(other)]
    Other,
}

#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct SessionEnd {
    pub reason: EndReason,
    /// One line for a person, in English. Programs go by `reason`.
    #[serde(default)]
    pub message: String,
}

/// One session as its host reports it.
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct SessionInfo {
    pub id: SessionId,
    /// The application's id on the host.
    pub app: String,
    pub kind: StreamKind,
    pub state: SessionState,
    /// Goes up by one with every change of this record.
    pub revision: u64,
    /// Counts the clients that were shown this session. The one that is
    /// shown it now has this number; a client with a lower one has been
    /// replaced.
    #[serde(default)]
    pub attachment: u64,
    /// What the host produces. Set once the session has run.
    #[serde(default)]
    pub display: Option<DisplayMode>,
    /// From the host's media path, for the client that is shown the
    /// session. Set while `running`. The control plane does not look inside.
    #[serde(default)]
    pub answer: Option<serde_json::Value>,
    /// Why the session ends. Set from `stopping` on.
    #[serde(default)]
    pub end: Option<SessionEnd>,
}
```

```rust
// istesso-link, message.rs. The variants are appended to the enums that are there.

pub enum Request {
    // Ping, Manifest, Apps, Status
    SessionStart {
        /// The application's id on the host, as `apps` lists it.
        app: String,
        #[serde(default = "app_window")]
        kind: StreamKind,
        /// What the caller's window shows.
        display: DisplayMode,
        /// From the caller's media path, for the host's. Carried as it is.
        #[serde(default)]
        offer: serde_json::Value,
    },
    SessionWait {
        session: SessionId,
        /// The revision the caller has seen; 0 for none.
        #[serde(default)]
        after: u64,
        /// 0 asks for an answer at once.
        #[serde(default)]
        timeout_ms: u32,
        /// The attachment the caller is; 0 when it only asks.
        #[serde(default)]
        attachment: u64,
    },
    SessionStop {
        session: SessionId,
        /// End the application instead of asking it to close.
        #[serde(default)]
        force: bool,
    },
    SessionList,
    SessionAttach {
        session: SessionId,
        display: DisplayMode,
        #[serde(default)]
        offer: serde_json::Value,
    },
    SessionDetach {
        session: SessionId,
        /// The attachment that leaves.
        attachment: u64,
    },
}

pub enum Response {
    // Pong, Manifest, Apps, Status, Error
    /// The state of one session.
    Session { session: Box<SessionInfo> },
    /// The caller's sessions that are not over, oldest first.
    Sessions { sessions: Vec<SessionInfo> },
}

pub enum ErrorCode {
    // Unsupported, Forbidden, Internal
    NotFound,
    Unavailable,
    #[serde(other)]
    Other,
```

- `offer` と `answer` の中身（上の `rtp_port` など）は例で、決めるのは映像の側である。
- 版がずれたとき：読む側は、知らない項目を無視する。知らない状態は `unknown`、知らない理由と知らないエラーは `other` として読む。`kind`、`offer`、`after`、`timeout_ms`、`attachment`、`force` は省ける。知らない `kind` のリクエストは、知らないリクエストと同じく `unsupported` になる。

### 5. 流れ

始める：

```text
 ビューアー     istesso open（クライアント）      エージェント（ホスト）     ランナー     アプリ
     │◀─ prepare ───│                               │                    │
     │── offer ────▶│                               │                    │
     │              │── session_start ─────────────▶│                    │
     │              │◀─ session（starting）─────────│── start ──────────▶│
     │              │── session_wait ──────────────▶│◀─ ready ───────────│
     │              │                               │── 起動（ready の環境変数つき）───▶│
     │              │◀─ session（running、answer）──│                    │
     │◀─ show ──────│                               │                    │
     │◀════════ 映像と入力（映像の側。制御の側は通らない）════════════▶│
     │              │── session_wait（繰り返す）───▶│                    │
```

離れて、戻る：

```text
     │              │── session_detach ────────────▶│── detach ─────────▶│   （または、15 秒のあいだ session_wait が来ない）
     │ （窓は閉じる） │                               │       アプリは動き続ける。状態は detached
     ：              ：                               ：
     │◀─ prepare ───│  （別のとき、istesso open をもう一度）
     │── offer ────▶│── session_list ──────────────▶│
     │              │◀─ sessions ───────────────────│
     │              │── session_attach ────────────▶│── attach ─────────▶│
     │              │◀─ session（running、新しい answer）│◀─ attached ────────│
     │◀─ show ──────│                               │                    │
```

閉じる：

```text
     │── close ────▶│  （人が、窓を閉じようとした。窓は、まだ閉じない）
     │              │── session_stop ──────────────▶│── close ──────────▶│── 窓に「閉じてほしい」──▶│
     │              │                               │                    │   アプリが終わる。または、保存するかを尋ねて残る
     │              │◀─ session（stopping、app_exited）│  （終わったとき）
     │ （窓を閉じる） │                               │
```

- `session_start` には、すぐ `starting` と答える。仮想ディスプレイとエンコーダーの準備には数秒かかることがあり、制御チャンネルで答えを待つ時間（既定 5 秒）を超えうるためである。途中で失敗したときも、同じ形（`ended` と理由）で伝えられる。
- クライアントは、つながっているあいだ `session_wait` を送り続ける。ホストは、変化があればすぐ答え、なければ頼まれた時間だけ答えを待たせる。これが 2 つの役を兼ねる。
  - **ホストからの知らせ。** アプリが終わったら、待たせていた答えがすぐ返るので、手元の窓をすぐ閉じられる。ほかの窓に移ったことも、ホストが絵を止めたことも、これで分かる。
  - **クライアントがいることの知らせ。** どの接続から来てもよいので、Wi-Fi が一瞬切れてつなぎ直しても続く。
- エージェントは、動いているセッションを短い間隔で見回る。確かめるのは、アプリとランナーが動いているか、クライアントの知らせが来ているか、持ち主の権限が残っているか。
- ホストがいなくなったとき（`session_wait` が失敗し、15 秒のあいだつなぎ直せない）、クライアントはビューアーを閉じて、理由を表示する。アプリがどうなったかは、ホストが戻ってから `istesso sessions` で分かる。

### 6. 交渉する値と、決める側

| 値 | 決める側 | 運び方 |
|---|---|---|
| どのアプリを、どのホストで | クライアント（アプリ一覧と `preferred_host`） | `session_start` の `app` と、接続先 |
| 配信の種類 | クライアント。最初は `app_window` だけを受ける | `kind` |
| 絵の大きさと、フレームレートの上限 | クライアントのビューアーが望む（窓を出すディスプレイを知っている）。ホストのランナーは、出せる値に下げてよい。実際の値はランナーが決めて返す | `display`（行きと帰り） |
| コーデック、色の間引き、ビットレート、キーフレームの出し方、経路、ポート、鍵 | 映像の側。ビューアーが受けられるものを `offer` に書き、ランナーが選んで `answer` に書く。既定は ADR 0002 で決めた設定 | `offer` と `answer`。制御の側は中を見ない |
| 映像の送り先のアドレス | 制御の側。**制御チャンネルの接続元**を、そのまま使える文字にしてランナーに渡す。相手が申告したアドレスへは送らせない。IPv6 のリンクローカルのアドレスには、ゾーン（受け付けたソケットのスコープ ID）を付ける（`fe80::…%4`）。IPv6 に包まれた IPv4 は、IPv4 の形に戻す | ランナーへの `peer.address` |
| 窓の位置 | ビューアー。コマンドラインで指定されたら、望みとして渡す | ビューアーへの `wish` |
| セッションの ID と寿命 | ホスト | `session` |

クライアントが、ホストのどのアドレスへつなぐか（有線を先に試す、など）は、ここでは決めない。映像は制御チャンネルと同じ経路を通るので、遅延に効く。映像の側の課題として残す。

圧縮の設定を制御の側の項目にしないのは、遅延と画質を一緒に測って決めた値だからである（ADR 0002）。セッションごとに外から変えられる形にすると、測っていない組み合わせが増える。

### 7. 権限

- 話せるのは、ペアリング済みの端末だけ（制御チャンネルは、ほかの端末と何もやり取りしない。ADR 0007）。
- `session_start` と `session_attach` には、「閲覧」と「操作」の両方が要る。プログラムを起動するのも、その窓を手元に出して操作するのも、操作であり、閲覧だけの端末にはさせない。新しくペアリングした端末は両方を持つので（ADR 0006）、何も変えなければ、ペアリング済みの端末はアプリを起動できる（人の決定の 2）。この決まりは、`session::policy::START_NEEDS` にある。
- セッションを見られるのも、動かせるのも、持ち主だけ（上の 2）。
- **失効は、すぐに効かせる。ただし、アプリは終わらせない。** エージェントは、セッションを見回るたびにペアリングの一覧を読み直し、持ち主が消えていたり、権限を失っていたりしたら、絵を止める（離れた状態にする）。セッションのリクエストも、届くたびに読み直して確かめる。いまの決まり（接続のたびに読み直す。ADR 0007）だけでは、開いたままの接続に失効が効かないためである。入力は、エージェントが別に確かめている（ADR 0007 の「入力」）。持ち主を失ったセッションは、同じ鍵の端末をペアリングし直せば、また使える。
- ランナーには、相手の端末の ID と、制御チャンネルの接続元のアドレスを渡す。鍵と権限は渡さない。
- `offer` と `answer` は、書き換えずに運び、ログに出さない（あとで鍵を含みうる）。大きさは 64 KiB までにする。ランナーとビューアーへは標準入力で渡し、引数や環境変数には載せない（引数は、同じ PC のほかのユーザーから見える）。
- 権限の要る処理は増えない。root も、新しい種類の OS の許可も要らない。アプリは、エージェントと同じユーザーで動く。Mac のビューアーは、ホストと通信するので「ローカルネットワーク」の許可が要る。制御チャンネルですでに要る許可で、種類は増えない。ただし、ビューアーを独立したアプリとして起動する形にすると、そのアプリに人が改めて許可を出すことになる。

### 8. アプリ一覧の項目に要るもの

相手に見せる項目（`AppEntry`）は変えない。クライアントが使うのは `id` だけで、起動のしかたは、ホストが自分の一覧から決める。ホストは、起動のときに、その ID の desktop entry を読み直す。

| 要るもの | いま | 最初の一切れでの扱い |
|---|---|---|
| `Type=Application` で、`Exec` がある | 読んでいる | 変えない |
| `Exec` を、仕様の決まり（引用符とエスケープ）どおりに引数へ分ける。シェルは通さない。`%f` などは取り除く | 文字列のまま持っている。引用符の中の続いた空白は、1 つに詰まる | 起動のときに、元のファイルから読んで分ける |
| `Terminal=true` でない | 読んでいない。一覧には載る | 起動を断る（`unavailable`）。文字のアプリは、R-01 の 2 番目の道（ターミナルで直接つなぐ） |
| `Path=`（作業ディレクトリ） | 読んでいない | 読んで使う |
| `TryExec=` の実行ファイルがある | 読んでいない | なければ断る |
| Wayland で窓を出せる | 項目からは分からない | 下のとおりに環境を整えて起動する。出せないアプリは自分で終わるので、`app_exited` になる |
| macOS のアプリ（`.app`） | 一覧に載る | ホストとしては断る（M4）。手元にあるものは、手元で開く |

アプリの環境は、エージェントの環境に、ランナーが `ready` で返した変数を足して作る。ランナーが `WAYLAND_DISPLAY` を返して `DISPLAY` を返さないときは、`DISPLAY` を外し、主なツールキットに Wayland を選ばせる変数を足す（案：`GDK_BACKEND`、`QT_QPA_PLATFORM`、`SDL_VIDEODRIVER`、`MOZ_ENABLE_WAYLAND`、`ELECTRON_OZONE_PLATFORM_HINT`。まだ試していない。実機で確かめて決める）。`DISPLAY` を外すのは、窓が黙ってホストのデスクトップに出るのを防ぐためである。

分かっている限界：

- 1 つしか動かない作りのアプリが、ホストのデスクトップですでに動いていると、新しい窓がそちらに出ることがある。D-Bus を通して起動し直すアプリも同じ。どちらも、起動したプロセスはすぐ終わるので、`app_exited` になる。
- X11 だけのアプリは映らない（いまのコンポジターに XWayland がない。`m1-latency` の ADR 0009）。
- 「窓として出せるか」は、頼んでみるまでクライアントには分からない。

### 9. 境界：映像と入力がつながる場所

映像の側は、ホストの**ランナー**と、クライアントの**ビューアー**の 2 か所でつながる。その形を 2 つ比べた。

- **A：プロセスで分ける。** エージェントがランナーを、`istesso open` がビューアーを、別のプロセスとして起動する。やり取りは、決めた形の行（標準入力と標準出力）で行う。
- **B：プロセスの中で、トレイトでつなぐ。** `istesso-media-*` のクレートがトレイトを実装し、エージェントとコマンドにリンクする。

| 観点 | A：プロセスで分ける | B：トレイトでつなぐ |
|---|---|---|
| いま映像の側にあるもの（Python のスクリプト、Objective-C のビューアー） | 数十行の包みでつながる | つながらない。Rust に書き直してから |
| `main` のビルド | 変わらない。GStreamer、Wayland、CUDA の開発用パッケージが要らないまま（共通コアは、どの PC でもビルドできる） | エージェントが映像の依存を抱える。OS ごとに feature で分ける |
| 落ちたとき | そのセッションだけが終わる。エージェントは理由を相手に伝えられる | エージェントごと落ちる。ほかのセッションと、役割表や発見も止まる。GPU のドライバーの中で落ちることもある |
| Mac のクライアント | 窓を持つプログラムは、別のプロセスが自然（メインスレッド、Dock のアイコン、OS の許可が、アプリごとに付く） | `istesso` コマンド自身が、窓を持つアプリになる |
| 入力の遅延 | 入力は、エージェントが受けて、ランナーのソケットへ渡す（下の「入力」）。同じ PC の中の受け渡しが 1 回増える。0.1 ms 未満の見込みだが、測っていない | 関数の呼び出しで渡せる |
| 約束を守らせる方法 | 行の形と版の番号。偽物を使ったテスト | コンパイラー |
| ライセンス | エージェントとコマンドは、GStreamer（LGPL）にリンクしない | エージェントが GStreamer にリンクする。動的リンクを保つ必要がある（`components.md`） |
| 専用ユーザーでの隔離（R-07）を、あとで足す | プロセスの境目に挟める | 挟めない |
| 鍵の受け渡し | 標準入力で渡す。引数に載せない決まりが要る | メモリの中で済む |
| 起動の時間 | プロセスの起動が 1 回ぶん増える。GPU の初期化は、どちらでも要る | 少し短い |

**決定：A を境界にする**（2026-11-16、映像の側と合意）。理由は 3 つある。いまある計測の道具がそのままつながること。`main` が映像の依存を持たずに済むこと。落ちたときに巻き込む範囲が、セッション 1 つで済むこと。

エージェントとコマンドの中では、小さなトレイト（ランナーを始める・止める、ビューアーを始める・止める）を通して使う。標準の実装は、下の約束でプロセスを起動する。テストでは、偽物を差し込む。あとで B のほうがよいと分かったら、同じトレイトに、プロセスを作らない実装を足せばよく、メッセージは変わらない。

#### ホスト：ランナーとの約束

- エージェントに、実行ファイルを 1 つ教える（`istesso agent --session-runner <プログラム>`、または環境変数 `ISTESSO_SESSION_RUNNER`）。引数は渡さない。設定がなければ、そのホストは `session_start` に `unavailable` と答える。何を動かすかを決めるのは、ホストを使っている人であり、相手の端末からは選べない。
- セッション 1 つにつき、1 つ起動する。セッションが続くあいだ、動き続ける。
- 標準入力と標準出力で、1 行に 1 つの JSON をやり取りする。標準エラーは人が読むログで、エージェントが自分のログに回す（鍵やトークンを出さない）。知らない行と、知らない項目は、読み飛ばす。

```text
→ {"v":1,"cmd":"start","session":"5b0c9e3a7f21d684","kind":"app_window","display":{"width":1720,"height":720,"fps":85},"peer":{"id":"1a2b-3c4d-5e6f-7a8b","address":"192.0.2.10"},"input_socket":"/run/user/1000/istesso/input-5b0c9e3a7f21d684.sock","offer":{"rtp_port":50004}}
← {"v":1,"event":"ready","env":{"WAYLAND_DISPLAY":"wayland-3"},"display":{"width":1720,"height":720,"fps":85},"answer":{"key_request_port":50005}}
→ {"v":1,"cmd":"application","pid":4711}
→ {"v":1,"cmd":"detach"}
→ {"v":1,"cmd":"attach","peer":{"id":"1a2b-3c4d-5e6f-7a8b","address":"192.0.2.10"},"display":{"width":1280,"height":720,"fps":60},"offer":{"rtp_port":50010}}
← {"v":1,"event":"attached","display":{"width":1280,"height":720,"fps":60},"answer":{"key_request_port":50011}}
→ {"v":1,"cmd":"close"}
← {"v":1,"event":"empty"}
← {"v":1,"event":"detached","message":"the encoder is busy"}
← {"v":1,"event":"error","message":"no encoder"}
```

| 行 | 向き | 内容 |
|---|---|---|
| `start` | エージェント → ランナー | 仮想ディスプレイを作り、最初のクライアントへ送り始める。セッションの ID、種類、望まれた `display`、相手の端末（ID と、制御チャンネルの接続元のアドレス）、入力を受け取るソケットの場所（`input_socket`）、クライアントのビューアーからの `offer` |
| `ready` | ランナー → エージェント | アプリを受け入れられるようになり、`input_socket` にソケットを作り終えた。`env` は、アプリをこの仮想ディスプレイに出すための環境変数。`display` は、実際に出す大きさとフレームレート。`answer` は、クライアントのビューアーへの返事 |
| `application` | エージェント → ランナー | アプリを起動した。そのプロセスの番号。アプリの窓を自分で探さなければならないランナー（Mac のホスト）のためのもので、アプリのほうからつなぎに来る仮想ディスプレイ（Wayland）のランナーは、読み飛ばしてよい |
| `detach` | エージェント → ランナー | クライアントが離れた。送るのをやめる。仮想ディスプレイとアプリは、そのままにする |
| `attach` | エージェント → ランナー | このクライアントへ送り始める。相手の端末、望まれた `display`、新しい `offer`。ほかのクライアントへ送っていたら、それはやめる |
| `attached` | ランナー → エージェント | `attach` のとおりに送り始めた。実際の `display` と、新しい `answer` |
| `detached` | ランナー → エージェント | いまは、だれにも送っていない。`attach` に応えられなかったとき、または、送れなくなったときに出す。理由を 1 行付ける。仮想ディスプレイとアプリは続いている |
| `close` | エージェント → ランナー | アプリの窓に、閉じるよう頼む（Wayland なら `xdg_toplevel.close`）。アプリがどうするかは、アプリが決める |
| `empty` | ランナー → エージェント | 最後の窓が閉じた。エージェントは、アプリが終わったものとして扱う |
| `error` | ランナー → エージェント | 続けられない。このあと終了する。アプリも終わる |

決まり：

1. `ready` は 15 秒以内に、`attached`（か `detached`）は 10 秒以内に出す。
2. **標準入力が閉じたら、送信をやめて、2 秒以内に終了する。** これがセッションを終える合図で、エージェントが落ちたときにも同じことが起きる。終わらなければ、エージェントが SIGTERM、SIGKILL の順に送る。
3. ポートは固定しない。使うポートは自分で選び、`answer` で知らせる。セッションを並べて動かせるようにするためである。
4. 映像は、最後の `start` か `attach` の `peer.address` へだけ送る。入力は、`input_socket` からだけ受け取る。
5. `detach` のあとも、`attach` に応えられなかったあとも、仮想ディスプレイとアプリを保つ。
6. 終了コードの 0 は「頼まれて止まった」で、それ以外は失敗。

#### クライアント：ビューアーとの約束

- `istesso open --viewer <プログラム>`、または環境変数 `ISTESSO_VIEWER` で教える。行の形は、ランナーと同じ。

```text
→ {"v":1,"cmd":"prepare","title":"Firefox","kind":"app_window","wish":{"width":1720,"height":720,"fps":null,"x":null,"y":null}}
← {"v":1,"event":"offer","display":{"width":1720,"height":720,"fps":85},"offer":{"rtp_port":50004}}
→ {"v":1,"cmd":"show","session":"5b0c9e3a7f21d684","host":{"id":"9f8e-7d6c-5b4a-3921","address":"192.0.2.20"},"display":{"width":1720,"height":720,"fps":85},"answer":{"key_request_port":50005}}
← {"v":1,"event":"shown"}
← {"v":1,"event":"close"}
```

| 行 | 向き | 内容 |
|---|---|---|
| `prepare` | コマンド → ビューアー | 窓の題名、種類、コマンドラインで指定された望み（大きさ、フレームレート、位置。なければ `null`） |
| `offer` | ビューアー → コマンド | 望む `display`（窓を出すディスプレイの画素とリフレッシュレートから決める）と、ホストのランナーへの `offer`。5 秒以内に出す |
| `show` | コマンド → ビューアー | セッションの ID、ホスト（ID と、制御チャンネルがつながったアドレス）、実際の `display`、ランナーからの `answer` |
| `shown`（任意） | ビューアー → コマンド | 最初の絵が画面に出た。起動にかかった時間を測るために使う |
| `close` | ビューアー → コマンド | 人が、窓を閉じようとした |

決まり：

1. **人が窓を閉じようとしたら、`close` と言うだけで、窓は閉じない。** コマンドが、ホストのアプリに閉じるよう頼む。アプリが終われば、コマンドが標準入力を閉じる。アプリが「保存しますか」と尋ねたら、その窓が、開いたままのこの窓に映る。
2. 標準入力が閉じたら、窓を閉じて終了する。
3. ビューアーが自分で終わったら（人がビューアーを終了させた。落ちた）、コマンドは離れる。アプリは動き続ける。
4. 窓は、最初の絵が出るまで見せないのが望ましい。起動に失敗したときに、空の窓が一瞬出るのを避けられる。

Mac で、ビューアーを独立したアプリとして `open` で起動するとき（アプリとしての優先度と許可で動かすため）は、包みが標準入出力を名前つきパイプでつなぐ（`open --stdin`、`--stdout`）。まだ試していない。

#### 入力

**入力は、制御チャンネルで、エージェントを通して運ぶ**（2026-11-16、映像の側の決定）。経路は `m1-latency` にあり、ADR 0007 の「入力」に書いてある。

- クライアントは、`input_open` で許しを得てから、`input` でイベントを送る。エージェントは、相手に「操作」の権限があることを確かめ、入力が続くあいだも 1 秒おきに確かめ直す。
- エージェントは、イベントを 1 つずつ、ランナーが作ったデータグラムのソケットへ渡す。ソケットの場所は、エージェントがセッションごとに決めて（`$XDG_RUNTIME_DIR/istesso/input-<セッションの ID>.sock`。本人しか入れない場所）、`start` の `input_socket` でランナーに知らせる。ランナーは、`ready` を出す前に、そこへソケットを作る。つなぎ直しても、場所は変わらない。
- セッションが終わったら、エージェントは、そのソケットを消す。

ここまでで作ったのは、`input_socket` を決めてランナーに渡すところまでである。入力は、まだセッションを名乗らない（`input_open` に `session` を足すのは、映像の側があとで行う）。それまでは、ADR 0007 のとおり、1 台のホストが映すアプリは 1 つ、という前提で動く。

こうした理由：作って、確かめ終えた経路がすでにある。ハンドシェイクの新しい使い方が要らない。受け渡しが 1 回増えるぶんは、0.1 ms 未満の見込みである（測っていない）。

制御の側が保証することは、変わらない。**`offer` と `answer` は、認証済みの制御チャンネルを通って、書き換えられずに相手に届く。** 映像の経路が、あとで鍵を交わすときに使える。

#### いまの計測の道具をつなぐには

`m1-latency` の送信側のスクリプトとビューアーは、変えずに使える見込みである（引数と出力を読んで確かめた。動かしてはいない）。包みを 1 つずつ書けばよい（置き場所は、映像の側のブランチ）。

- ランナーの包み：`start` を読み、送り先を `peer.address` と `offer` のポートにして、大きさとフレームレートを渡して、スクリプトを起動する。再生が始まったら、ソケットの名前をログから読んで `ready` を出す。標準入力が閉じたら、スクリプトを止める。
- ビューアーの包み：空いているポートを選んで `offer` を出す。`show` を読んで、ビューアーを起動する。

`main` には、映像を何も運ばない偽物のランナーとビューアーを置く。テストと、実機 2 台での確認に使う。

包みは、`detach`、`attach`、`close` にも応える必要がある。`close` には、コンポジターへの小さな追加が要る（アプリの窓に、閉じるよう伝える）。これも、映像の側の作業である。

### 10. コマンド

| コマンド | 動き |
|---|---|
| `istesso open <アプリ>` | 下の決まりで、つなぐか、起動する |
| `istesso sessions` | 自分のセッションを、起きているホストのぶん全部、並べる（ID、アプリ、ホスト、状態） |
| `istesso sessions stop <ID>` | そのアプリに、閉じるよう頼む。数秒待って、終わったか、まだ動いているか（保存するかを尋ねているかもしれない）を表示する |
| `istesso sessions stop <ID> --force` | 力ずくで終わらせる。アプリが自分で終わるまでに 3 秒ある、と先に表示する |

**`istesso open` が、つなぐか、起動するか**（提案。R-03「窓はホスト側で生き続ける。端末は接続し直すだけ」に合わせた）：

1. そのアプリの、自分のセッションが、起きているホストにあるかを調べる。
2. 1 つあれば、それにつなぐ。離れていたものは戻り、ほかの窓に映っていたものは、こちらの窓に移る。
3. いくつもあれば、並べて見せて、選んでもらう（`--session <ID>`）。
4. なければ、起動する。行き先は、これまでどおり（手元 → 起きているホスト → 負荷の低いホスト）。
5. `--new` を付けると、セッションを調べずに、新しく起動する。`--host <端末>` を付けると、その端末だけを見る。

セッションがあるときに、手元のアプリより先にそちらを選ぶのは、やりかけの作業がそこにあるからである。新しく空のアプリを開くより、続きに戻るほうが、頼まれたことに近い。

**止め方と、その理由**（提案）：

| 人がしたこと | 起きること | 理由 |
|---|---|---|
| 窓を閉じようとした | アプリに、閉じるよう頼む。窓は、アプリが終わるまで開いている | 人の決定の 4。手元のアプリの窓を閉じるのと同じ動きにする。アプリが保存するかを尋ねたとき、答える窓が要る |
| `istesso open` を Ctrl-C で止めた。端末を閉じた | 離れる。アプリは動き続ける。戻り方と、止め方を表示する | Ctrl-C が止めるのは、コマンドである。ふたを閉じるのと同じで、作業を消してはいけない（人の決定の 3）。ここで閉じるよう頼むと、アプリが尋ねても、答える窓がもうない |
| ビューアーが終わった（終了させた。落ちた） | 離れる。アプリは動き続ける | 同上 |
| スリープした。ネットワークが切れた | 15 秒後に、ホストが絵を止める。アプリは動き続ける。戻ったら、`istesso open` をもう一度実行する | 人の決定の 3 |

## 検討したほかの形

| 形 | 採らなかった理由 |
|---|---|
| クライアントがいなくなったら、15 秒でアプリごと終わらせる（はじめの提案） | 人の決定の 3。ふたを閉じただけで、作業が消える |
| 窓を閉じたら、アプリに SIGTERM を送る（はじめの提案） | 人の決定の 4。アプリが、保存するかを尋ねられない |
| 「閉じるよう頼む」を、エージェントがシグナルで行う | シグナルでは、窓を閉じる頼みにならない。SIGTERM は、多くのアプリにとって「いますぐ終われ」である。頼めるのは、窓を管理しているコンポジターだけ |
| 力ずくで終わらせる前に、いつも閉じるよう頼む | 2 つの終わらせ方が混ざる。`--force` と書いた人は、尋ねる窓を望んでいない。SIGTERM のあとの 3 秒が、アプリが自分で片づける時間になる |
| `session_attach` にも、すぐ答える（`session_start` と同じ） | つなげなかったことを伝えるのに、状態がもう 1 つと、理由を運ぶ項目が要る。起動と違って、失敗してもセッションは続くので、「断る」という答えで足りる |
| Ctrl-C で、アプリに閉じるよう頼む | 上の 10 |
| セッションを 1 本の長い接続にして、ホストから出来事を送り、入力も同じ接続で運ぶ | `istesso-link` を、両方向にいつでも送れる形に作り替えることになる。答えを待たせる形なら、型を足すだけで済み、つなぎ直しもそのまま通る。両方向の接続ができたら、知らせをそちらに移せる |
| `session_start` が、動き出すまで答えを待つ | 準備に数秒かかることがある。制御チャンネルで答えを待つ時間は 5 秒 |
| 状態を 1 秒おきに聞く（答えを待たせない） | アプリを終えてから窓が消えるまでに、最大で 1 秒かかる。手元のアプリなら、すぐ消える |
| ランナーがアプリを起動する | アプリの起動（一覧、環境、あとで専用ユーザー）は、制御の側の仕事である。OS ごとのランナーが、同じことを書くことになる。Mac のホスト（M4）では、アプリの窓を仮想ディスプレイへ移すのがランナーの仕事になるので、そのときに見直す |
| セッションの ID を、知っていれば操作できる鍵にする | ログに出せなくなる。身元の確認は、制御チャンネルにすでにある |
| 圧縮の設定を、`session_start` の項目にする | 上の 6 |
| 入力を、ビューアーからランナーへ直接運ぶ。ランナーとビューアーが、セッションごとに使い捨ての鍵を作り、公開鍵を `answer` と `offer` に書く。その鍵だけを相手として受け入れる通信路（`istesso-link` の `Channel`）を、2 つのあいだに張る | エージェントを通す経路が、すでに作ってあり、確かめてある。こちらは、ハンドシェイクの新しい使い方になり、確かめ直しが要る。得るものは、受け渡し 1 回ぶん（0.1 ms 未満の見込み）である。**見直すとき**：エージェントを通す受け渡しが、95 パーセンタイルで 0.5 ms 以上かかると測れたとき。または、暗号化した映像の経路を設計するとき（そこで鍵を交わすなら、入力も同じ仕組みに載せられる） |

## 映像の側と決めたこと（2026-11-16）

1. 境界は A（プロセス）。ランナーとビューアーは別のプロセスで、標準入出力に、1 行に 1 つの JSON。
2. アプリを起動するのは、エージェント（ランナーではない）。
3. 標準入力が閉じたら終わる。ポートは固定しない。`ready` で環境変数を返す。
4. `offer` と `answer` は、1 往復で足りる（つなぐたびに 1 往復）。
5. 入力は、制御チャンネルで、エージェントを通す（上の「入力」）。`start` の `peer` は ID とアドレスだけにして、`input_socket` を足す。
6. `peer.address` は、制御チャンネルの接続元。IPv6 のリンクローカルには、ゾーンを付ける。
7. `istesso_link::Session`（1 回の会話を指す型）は、いまは改名しない。
8. いまの送信側のスクリプトとビューアーを、この約束に合わせる包みは、映像の側が書く。閉じるよう頼むための、コンポジターへの追加も同じ。

## 決めてほしいこと

**ペアリング済みのほかの端末も、セッションを見て、つないで、止めてよいか。**

- いま作ってあるのは、「始めた端末だけ」である。
- 提案は、「閲覧」と「操作」を持つ、ペアリング済みの端末なら、どのセッションにも、である。理由：R-03 は、自宅の実機で始めた窓に、出先の端末から戻ることを求めている。ペアリングした端末は、どれも同じ人のものである。その端末は、すでにアプリを起動でき、入力を送れるので、新しく得るのは、ほかの端末が始めた窓に届くことだけである。
- 広げると、持ち主を失ったセッション（上の 7）にも、ほかの端末から届く。
- 決まったら、`session::policy::may_use` を変える。メッセージは変わらない。

## 実装

| 場所 | 内容 |
|---|---|
| `istesso-proto`（`session`） | セッションの型と、ランナーとビューアーの行の型。行の読み書き。アドレスを文字にする決まり |
| `istesso-link` | リクエスト 6 つ、レスポンス 2 つ、エラー 2 つ。`Client` の呼び出し。`Error::Remote` が、エラーの種類を持つ |
| `istesso-catalog`（`launch`） | desktop entry から、プログラム、引数、作業ディレクトリ、起動できない理由を出す |
| `istesso-agent`（`session`） | セッションの表、状態の進み方、見回り。ランナーとアプリを、プロセスとして起動して止める実装。クライアントの側（`session::client`：ビューアーの起動、ホストへの問い合わせ、離れ方、閉じるよう頼むこと） |
| `istesso-cli` | `istesso open <アプリ> [--host <端末>] [--new] [--session <ID>] [--viewer <プログラム>] [--size <幅>x<高さ>] [--fps <数>] [--position <X>,<Y>]`、`istesso sessions`、`istesso sessions stop <ID> [--force]`、`istesso agent --session-runner <プログラム>` |
| `scripts/` | 映像を運ばない偽物：ランナー（`fake-session-runner.sh`）、ビューアー（`fake-viewer.sh`）、アプリ（`fake-application.sh`）。実機 2 台での確認を通しで行うスクリプト（`m3-trial.sh`。手順は [m3-trial.md](../m3-trial.md)） |

- 人が決める決まりは、1 か所ずつに書いてある：`session::policy` の `START_NEEDS`（起動と、つなぐのに要る権限）、`CLIENT_LOST_AFTER`（絵を止めるまでの 15 秒）、`may_use`（セッションを使える端末）。コマンドの名前は `istesso-cli` の `open::COMMAND`。
- 偽物での「閉じるよう頼む」：偽物のランナーには、頼む相手の窓がない。代わりに、`application` の行で知ったプロセスに、シグナル（USR1）を送る。偽物のアプリは、それを「閉じてほしい」と受け取り、そのまま終わるか、`--unsaved` を付けて起動されていれば「保存しますか」と尋ねたことにして残る。本物のランナーは、コンポジターから窓に伝える。
- 依存を 2 つ足した。`rustix`（プロセスグループへのシグナル）と `signal-hook`（Ctrl-C を受けて、ホストに離れると伝える）。どちらも、`unsafe` を書かないためである。
- 遅延：映像・入力・音の経路には、手を入れていない。制御の側が足すのは、始めるときの往復 2 回（つなぎ直すときは 2 回）と、プロセスの起動である。

## 確かめたこと（2026-11-16）

実機 2 台（クライアントは Mac、ホストは Ubuntu）で、偽物のランナー、ビューアー、アプリを使って確かめた。ホストでは、試験用のエージェントを別のポートで動かし、試験用のアプリ 2 つを、そのエージェントの一覧にだけ足した。手順は [m3-trial.md](../m3-trial.md) にあり、`scripts/m3-trial.sh` がそのまま実行する。

| 確かめたこと | 経路 | 結果 |
|---|---|---|
| 起動する。Ctrl-C で離れる。アプリはホストで動き続け、`istesso sessions` に「映っていない」と出る | IPv4（有線）と、IPv6 のリンクローカル（有線） | そのとおり |
| 同じコマンドをもう一度実行すると、新しく起動せずに、同じセッションに戻る | 同上 | そのとおり |
| 窓を閉じようとすると、アプリに頼みが届く。保存するものがないアプリは終わり、窓が閉じる。力ずくでは終わらせていない | 同上 | そのとおり |
| 保存するものがあるアプリは、尋ねたまま残る。窓も残る。別のところから `istesso sessions stop` で頼んでも残り、「まだ動いている」と表示される | 同上 | そのとおり |
| `--force` を付けると、3 秒の猶予を表示してから終わらせる。開いていた窓も閉じる | 同上 | そのとおり |
| コマンドを強制終了する（ホストには何も伝わらない）。8 秒後は、まだ絵を送っている。20 秒後は、絵が止まっていて、アプリは動いている。ランナーには、クライアントがいなくなったと伝わっている | IPv4（有線） | そのとおり |
| ランナーが途中で落ちると、コマンドが理由を表示して、エラーで終わる。アプリも終わっている | IPv4（有線） | そのとおり |

- Mac の有線のアダプターを通る経路で確かめた。IPv6 のリンクローカルのアドレスを指したときも、クライアントは、ホストが役割表で申告したほかのアドレスを覚えるので、あとの接続が IPv4 になることがある（3 回のうち 1 回）。どの経路を選ぶかは、5 に書いたとおり、映像の側の課題である。
- 自動のテスト：Mac と Ubuntu の両方で、`cargo test --workspace` が通る（214 件）。プロセスを実際に起動して止めるテストと、偽物のスクリプトを両側に置いて、起動、離れる、戻る、閉じる、を通すテストを含む。IPv6 は、ループバックでも通している。
- 依存のライセンス：`cargo deny check licenses` が通る（ホストで実行）。
- 確かめていないこと：手元のアプリを `istesso open` で開くこと（Mac に窓が開くので、遅延の計測の邪魔にならないよう、実機では動かしていない）。本物のコンポジターの中でのアプリの起動と、本物の「閉じてほしい」。

## 結果

- 映像の側は、ランナーとビューアーを、この約束に合わせて作る。制御の側は、映像の中身を知らないまま、始めと終わり、つなぐと離れるを受け持つ。
- `main` では、偽物のランナーとビューアーで動く。本物は、映像の側がつなぐ。
- 制御チャンネルに、「頼むと、相手の PC でプログラムが動く」メッセージがある。頼めるのはアプリ一覧にあるものだけで、「閲覧」と「操作」の権限が要る。
- ホストには、だれにも映っていないアプリが残りうる。`istesso sessions` で見えて、止められる。上限（8 つ）に達したら、新しい起動を断って、離れているものを知らせる。
- 型の名前が紛らわしい。`istesso-link` の `Session` は 1 回の会話を指し、この ADR の `Session…` は配信セッションを指す。前者は、いまは改名しない（映像の側と決めた）。

## 変更の手順

- メッセージを足すのは、制御チャンネルの版を上げずにできる（ADR 0007）。意味を変えるときは、先にこの文書を更新する。
- ランナーとビューアーの約束を変えるときも、先にこの文書を更新する。項目や行を足すのは、`v` を上げずにできる。互換性のない変更では、`v` を上げる。
