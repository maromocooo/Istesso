## 背景

ペアリング（ADR 0006）を終えた端末は、互いの公開鍵を固定して持っている。これを土台に、役割表・アプリ一覧・負荷をやり取りする通信路が要る。将来はアプリの起動や入力の制御もここを通るので、「相手が誰か」の確認は最初から厳密に作る。

あわせて、IP アドレスが変わっても相手を見つけられる仕組みが要る。リンクのしやすさは必須要件（R-13）である。

## 決定

### 通信路

- TCP（既定のポート 47801）の上で Noise XX（`Noise_XX_25519_ChaChaPoly_SHA256`）を実行する。実装は `snow` を使い、暗号の手順は自作しない。
- 端末の身元は Ed25519 の鍵で、**署名にしか使わない**。鍵交換用の X25519 鍵はプロセスごとに作ってメモリにだけ置き、その公開鍵に身元の鍵で署名したもの（以下「証明」）をハンドシェイクの中で送る。libp2p の Noise ハンドシェイクと同じ考え方である。
  - 身元の鍵を鍵交換に流用する案（Ed25519 から X25519 への変換）は採らない。`ed25519-dalek` の文書が勧めておらず、鍵を分けても実装は増えない。

| 順 | 向き | 内容 |
|---|---|---|
| 1 | 接続側 → 受け側、受け側 → 接続側 | `ISC1`（プロトコル名と版）。違えば、その旨を表示して切る |
| 2 | 接続側 → 受け側 | Noise メッセージ 1（`e`） |
| 3 | 受け側 → 接続側 | Noise メッセージ 2（`e, ee, s, es`）＋受け側の証明 |
| 4 | 接続側 | 証明を検証し、ペアリング済みの相手かを確かめる。違えばここで切る |
| 5 | 接続側 → 受け側 | Noise メッセージ 3（`s, se`）＋接続側の証明 |
| 6 | 受け側 → 接続側 | 判定（受け入れる／信頼していない）。ここから暗号化済み |
| 7 | 双方向 | メッセージ |

性質：

| 脅威 | 対応 |
|---|---|
| 記憶したアドレスや発見したアドレスに別の端末がいる | ハンドシェイクで弾く。相手を指定して接続した場合は、ペアリング済みの別の端末でも弾く |
| 他人の身元を名乗る | 証明は鍵交換用の鍵に結び付いており、その秘密鍵がなければハンドシェイクが完了しない。他人の証明を写しても通らない |
| ペアリングを解除した端末がつなぎ続ける | 受け側は接続のたびにペアリング一覧を読み直す。解除は次の接続から効く |
| 知らない相手に身元を明かす | 接続側は、相手を確かめてから自分の身元を送る |
| 認証前に資源を使わせる | 認証前に受け付けるのは 512 バイトまでのハンドシェイクだけ。**ハンドシェイクの全体に期限がある**（待ち受ける側。既定 5 秒）。1 バイトずつ、待ち時間が切れる直前に送ってくる相手も、期限で切る。同時接続数に上限がある |
| 途中で書き換える、順序を変える | Noise の認証つき暗号と連番で検出し、その接続を捨てる |

### メッセージ

- JSON。`type` で種類を表す。いまは `ping`、`manifest`（役割表）、`apps`（アプリ一覧）、`status`（負荷と空きメモリ）。どれも「閲覧」の権限が要る。
- 端末は1台ずつ更新されるので、版のずれに寛容にする。
  - 知らないリクエストには `unsupported` を返し、接続は続ける。
  - 読む側は知らない項目を無視する。知らない列挙値は「不明」に落とすか、その要素だけ読み飛ばす（`istesso_proto::known_only`）。
  - 互換性のない変更をするときは、先頭の `ISC1` の版を上げる。
- 1メッセージは最大 16 MiB。Noise の上限（65535 バイト）を超える分は分割して送る。
- 待ち時間は2種類に分ける。相手が現れるまで（接続とハンドシェイク）は短く（既定 0.8 秒）、眠っている端末1台のために待つのはこれだけ。現れた相手の答えは長く待つ（既定 5 秒）。答えが遅いことと、いないことは別である。
- エージェントは役割表をメモリから答える。PC の調査（macOS では 1 秒以上かかる）は裏で定期的に行い、問い合わせを待たせない。
- いまは短い接続（つないで、聞いて、切る）。入力と映像は例外で、流れているあいだ開いたままになる（下の「入力」と「映像」）。

### 入力（2026-11-16 に追加）

キーボードとポインターの入力は、この制御チャンネルで運ぶ。打ったキーが、暗号化されずに LAN を流れることがないようにするためである。新しい暗号の部品は足していない。

- `input_open`：「入力を送ってよいか」。「操作」の権限が要る。受け側は、入力を受け取るアプリを映しているときに `input_open` と答える。権限がなければ `forbidden`、受け取る相手がいなければ `internal`。
- `input`：入力のイベントの並び（`events`）。`input_open` が通った接続でだけ受け付ける。**答えは返さない。** 打ったキーを、往復のぶん待たせないため。空の並びは「まだここにいる」の合図で、送る側が 2 秒おきに送る（受け側は、5 秒黙った相手を切る）。
- イベントは `istesso_proto::InputEvent`：`key`（キーが下がった、上がった）、`pointer_at`（ポインターの位置。絵の画素で、左上から）、`button`、`scroll`。キーとボタンは、Linux の番号（`input-event-codes.h`）で表す。文字ではなく、キーボードの上の場所である。その場所に何の字があるかは、アプリを動かしている側が決める。知らないイベントは、その 1 つだけ読み飛ばす。
- 受け側のエージェントは、イベントを、アプリを映しているプログラムへ、手元のソケットで渡す（Linux では `$XDG_RUNTIME_DIR/istesso/input.sock`。本人しか開けない場所）。
- この接続は、入力が続くあいだ開いたままになる。短い接続、という上の説明の例外である。
- 送る側は、相手を覚えているアドレスのうち、どれでつなぐかを指定できる（`istesso input relay --address`）。ホストが有線と Wi-Fi の両方でつながっているとき、入力を有線に通すためである。つながる相手がペアリング済みの端末であることの確認は、変わらない。
- Mac の Command キーは、既定では Control として送る（Mac で Command を使う操作は、Linux のアプリでは Control を使うため）。Super として送る設定も残す。これは送る側（クライアント）の決まりで、メッセージの形は変わらない。
- 修飾キーは、押した知らせが来なくても、キーに付いた印から補う。キーを送るプログラム（ボタンにホットキーを割り当てる道具など）は、修飾キーを押した知らせを出さず、キーに「Command つき」の印だけを付けて送ることがある。印にあって、押されていない修飾キーは、そのキーの前に押し、あとで離して送る（2026-11-16。Command-A が「a」として届いた不具合の直し）。これも送る側の決まりで、メッセージの形は変わらない。
- 修飾キーの状態は、送る側が、決まったときに、Mac の印と合わせ直す（2026-11-18 に決定。Blender で、Shift-A、Option でのドラッグ、修飾キーつきのスクロールが、修飾キーなしとして働いた試用のあと。原因は分かっていない）。合わせ直すのは、キー、修飾キーの知らせ、ボタン、スクロール、ポインターの動き、窓がキーを受けるかどうかが変わったとき、である。それ以外のとき（たとえばドラッグの途中）は、合わせない。メッセージの形は変わらない。
  - 修飾キーの知らせに、その修飾キーの印があり、左右どちらのキーかを示す印がないときは、左のキーとして送る（これまでは、送らなかった）。
  - 比べるのは、イベントの印と、ホストへ「押した」と送ってある修飾キーである。押したと送ってあるのに印にないものは、離したと送る。離したと送るのは、押したと送ってあるものだけである。
  - 印にあるのに押したと送っていないものは、イベントによって扱いが違う。キーでは、上の「補う」のとおり、前に押してあとで離す。修飾キーの知らせでは、ほかの修飾キーも合わせ、左のキーで押したと送る。ボタンとスクロールでは、窓がキーを受けているとき（作業中のアプリのキーの窓のとき）は、左のキーで押したと送り、押したままにする。受けていないとき（macOS は、スクロールや、アプリを前に出すクリックを、ポインターの下の窓へ送る）は、前に押してあとで離す。離した知らせは、別のアプリへ行き、ホストで押されたままになるからである。ポインターの動き（窓に入ったときも）では、離すだけで、押さない。合っていれば、何も送らない。
  - 窓がキーを受けなくなったら（別の窓、別のアプリ、Command-Tab、そして、たぶん画面を撮るキー。撮る画面が窓からキーを取るかどうかは、実機で確かめていない）、押したと送ってあるキーをすべて離したと送り、覚えを消す。窓がまたキーを受けるようになったら、そのときの修飾キーを読み、押されているものを押したと送る（絵がつなぎ直しの最中なら送らない。つながったときに、窓がキーを受けていれば、合わせ直す）。キーを取ったことを窓に知らせないもの（Spotlight、入力方式のパレット、メニューなど）のあとは、次のポインターの動きか、キーか、ボタンか、スクロールで、離すほうだけ合う。
  - 分かっていて、残したこと。
    - プログラムのホットキーが、Command の印だけを付けてくると、人が手で押している Shift を、離したと送る。そのあとの Shift つきのキーは、Shift を借りて送る。クリックかスクロールで、押したままに戻る。
    - 押した知らせが失われたのか、プログラムのホットキーなのかは、イベントの印からは分からない。だから、キーでは借りる（押したままにはしない）。手元のキーボードの本当の状態（`CGEventSourceFlagsState`）を読めば分かるが、キーの経路に呼び出しが 1 つ増える。計測なしには入れない。
    - Command を Control として送るとき、Command と手の Control は、ホストでは同じキーになる。左右が違って届くことがある。押されたままには、ならない。
- 計測のために、入力が通った時刻を書き出せる（`istesso input relay --timings`、`istesso agent --input-timings`）。書くのは、メッセージを受け取った時刻、渡し終えるまでの時間、イベントの数だけで、何が入力されたかは書かない。時刻だけでも、いつ打ったかが分かるので、指定したときにだけ書き、ファイルは持ち主だけが読める。ふだんは使わない。
- セッション（どのアプリへの入力か）の区別は、まだない。1 台のホストが映すアプリは 1 つ、という前提で動く。アプリマネージャー（M3）がセッションを決めたら、それに合わせる。

### 切れたあとの、つなぎ直し（入力）（2026-11-17）

送る側（`istesso input relay`。中身は `istesso-agent` の `relay`）と、受け側（`istesso agent`）に入れた。セッション（どのアプリへの入力か）とは、関係なく作ってある。2 台でも確かめた（[記録](../measurements/2026-11-17-reconnection-check.md)）。

送る側は、接続が切れた回数を、いつも言う（標準出力、時間の記録、ソケットの隣の小さいファイル。0 回のときも言う）。2026-11-17 に決まった。

入力の接続は、流れているあいだ開いたままなので、切れることがある。両端が生きていても、切れる（Mac で、アプリが新しく登録されたときに、macOS が、つながっている接続に届くパケットを黙って捨て始めることがある。[ADR 0015](0015-media-transport.md) の「切れたあとの、つなぎ直し」）。切れたら、**送る側（`istesso input relay`。あとでは、クライアント）が、すぐにつなぎ直す。** 映像、音と、同じ決まり、同じ数にする。

**通信路の手順（`istesso-link`。ハンドシェイク、封のしかた）は、変えない。** つなぎ直しは、新しい接続を、いつもの手順で開いて、`input_open` をやり直すだけである。足すのは、ハンドシェイクのあとのメッセージ 1 つ（`input_alive`）と、`input_open` の項目 1 つである。先頭の版（`ISC1`）も、プロローグも、上げない（下の「変更の手順」の「メッセージの追加は版を上げずに行える」にあたる）。

直す前の動き：

- 送る側は、受け側から何も読まない（`input` に、答えは返らない）。そのため、**黙って切られたことに、気づけない。** 書き込みが失敗するのは、OS が再送をあきらめたあとで、何分もかかる。
- 書き込みが失敗すると、送る側のプログラムは、終わる。つなぎ直さない。
- 受け側は、接続が終わっても、押されたままのキーやボタンを離さない。

#### 何を「切れた」とみなすか

- 書き込みか読み込みが、失敗した。
- **1 秒のあいだ、受け側から何も届かない。** 数え方は、「まだここにいる」と言ってから 0.5 秒、答えが来ないこと（0.5 秒おきに言うので、前の答えから数えて 1 秒になる）。自分が言った時刻から数えるので、送る側のプログラムがしばらく動けなかったとき（Mac が忙しかった、一瞬眠った）に、それを相手の沈黙と取り違えない。そのために、受け側が「ここにいる」と答えるようにする：
  - 送る側は、`input_open` に `"alive": true` を付けて、「空の `input` には答えてほしい」と言う。受け側は、それを知っていれば、答えの `input_open` に `"alive": true` を付ける。
  - そう決まった接続では、送る側は、打っているあいだも、0.5 秒おきに空の `input`（「まだここにいる」）を送る。受け側は、**空の `input` にだけ**、`{"type":"input_alive"}` と答える。
  - **キーやポインターを運ぶ `input` には、これまでどおり答えない。** 打ったキーを、往復のぶん待たせない、という決まりは変わらない。送る側は、答えを、送るのとは別に読む（送るのを、読むことで待たせない）。
  - 古い受け側は、知らない項目を無視するので、答えに `alive` が付かない。そのときは、沈黙では見分けない（空の `input` は、これまでどおり 2 秒おき）。書き込みの失敗でだけ、つなぎ直す。古い送る側は、頼まないので、新しい受け側も答えない（読まれない答えを、ためない）。
- 受け側は、`alive` と決まった接続では、**2 秒**黙った相手を切る（これまでは 5 秒）。切るとき、その接続が押したままにしていたキーとボタンを、離す（下）。

#### どれだけ速く、つなぎ直すか

- 切れたと分かったら、待たずに 1 回め。だめなら 0.25 秒おき。10 秒たったら 1 秒おき。1 回には、接続、ハンドシェイク、`input_open` の答えを合わせて 1 秒。
- 相手は、はじめに指定した端末だけ（`--to`）。アドレスの選び方（`--address`）も、はじめと同じ。
- 目安：失敗が見えた切れ方では 0.25 秒以内、黙って切られたときは、最後に答えが届いてから 1.25 秒以内に、入力がまた通る。Mac の中だけ（ループバック）で試すと、黙って止めてから 0.6 秒で切れたと分かり、0.01 秒後に、また通った。

#### つなぎ直したあと

- `input_open` は、**やり直すたびに、そのときの権限で確かめられる。** 受け側は、頼まれたときにペアリング一覧を読み直した値を使い、入力を受け取るのは、そのセッションを映している端末からだけである（どちらも、2026-11-17 に決まった。書き込みは、アプリマネージャーの流れが、この文書の「入力」に行う）。つなぎ直しは、解除や、権限の取り消しを、すり抜けない。
- **受け側は、入力の接続が終わったら（切れた、黙った、同じ端末の新しい接続に替わった）、その接続で押されたままのキーとボタンを、離す。** キーが押されたままになって、字が打たれ続けることがないようにする。
- **同じ端末が `input_open` をやり直したら、受け側は、その端末の古い入力の接続を、その場で終える。** 死んだ接続が、2 秒のあいだ残らないように。
- **送る側は、切れているあいだに打たれたキーと、押されたボタンを、あとから送らない。** 1 秒遅れて届くキーは、もう変わってしまった画面に打たれる。また、黙って切られたときは、こちらからのパケットが、相手に届いていたかどうかが分からない。送り直すと、同じキーが 2 度打たれうる。
- つながったら、送る側は、**修飾キーとボタンの状態を、合わせ直す**（2026-11-17 に決定）。**いま押されている修飾キー**（Shift、Control、Alt、Super）は、押し直す（Shift を押したまま、切れ目をまたいで打った字が、小文字にならないように）。ボタンは、ホストの側を、すべて離れた状態にそろえる（受け側が、接続の終わりで離している。「合わせ直す」をこう読むことは、ADR 0015 で、人の確認を待っている）。押されたままのボタンを押し直すことは、しない（ドラッグが、別の場所で始まる）。ふつうのキーも、押し直さない（字が 1 つ余分に打たれる）。ポインターの位置は、最新の 1 つを送る。
- 将来の候補（いまは作らない）：ごく短い切れ目（0.5 秒未満）で、同じ窓が前に出たままなら、打った文字を送り直す。

#### つなぎ直さないとき

| 起きたこと | 送る側に、どう見えるか | すること |
|---|---|---|
| ペアリングを解除された | つなぎ直すと、ハンドシェイクで「信頼していない」 | やめる |
| 「操作」を外された。セッションを映している端末ではなくなった | 切られる。`input_open` に `forbidden` | やめる。取り返しには行かない |
| 入力を受け取る相手がいない（アプリを映すプログラムが、動いていない） | `input_open` に `internal` | 1 秒おきに、やり直す。映すプログラムが起動し直されるあいだを、またぐため |
| 版が合わない | `unsupported` | やめる |
| 受け側が落ちた、眠った | 何も言われずに切れる。つながらない | やり直し続ける |
| 起動した側が、止めた | — | やめる |

やめるとき、送る側は、わけを 1 行で言って終わる（鍵、打たれた内容、アドレスは、言わない）。

#### セッションの話と合わせるとき

この節のものは、セッションを知らない。アプリマネージャー（M3）の入力（`input_open` がセッションを名乗る、映している端末だけが送れる）と合わせるときに、決めること：

- 受け側が「同じ端末の古い接続を終える」ときの「同じ」は、いまは端末ごとである。セッションごとの入力になったら、端末とセッションの組ごとにする（1 台が、2 つのセッションに、別々の接続で入力を送れるように）。
- 送る側がつなぎ直すときの `input_open` に、セッションを付ける。

#### 映像との関係

- 映像と入力は、別々の接続で、別々に切れ、別々につなぎ直す。
- 絵が古いと分かっているあいだ、キーとボタンの「押した」を渡さない、という決まりは、窓を持つ側（見る側のプログラム）のものである（ADR 0015 の「そのあいだのキーとボタン」。2026-11-17 に決定。計測の道具のビューアーには、入れてある）。打った文字が落ちていることを人に知らせるのも、窓を持つ側である。入力の接続は、それとは関係なく、つないだままにする。

### 映像（2026-11-17 に追加。[ADR 0015](0015-media-transport.md)）

映像は、この文書の通信路を、映像のための TCP の接続（既定のポート 47803）でそのまま使って運ぶ。`istesso-link` の `Channel` を呼ぶだけで、ハンドシェイクにも暗号にも、何も足していない。`istesso-link` のコードも、変えていない。

- 違うのは、ハンドシェイクのあとに流れるメッセージの中身（最初のやり取りと、フレーム）と、接続が長く続くことである。求める権限は「閲覧」。
- 接続が長く続くので、「解除は次の接続から効く」では足りない。映像を出す側は、流しているあいだ、1 秒より長くは空けずにペアリング一覧を読み直し、解除されたか、権限を外された相手の接続を切る。一覧が読めないときは、何も送らない。入力の接続が、同じことをしている（上の「入力」）。
- 待ち受ける側は、ハンドシェイクと最初のメッセージを合わせて 3 秒で締め切る。待ち時間を、読み書きのたびに数え直さないことは、制御チャンネルと同じである。
- キーフレームの求めは、同じ接続を逆向きに流れる。
- 1 メッセージが Noise の上限を超えるときに分けて送る決まり（上の「メッセージ」）を、大きなフレームが使う。
- 映像の接続が切れたあとのつなぎ直しも、新しい接続を、この文書の手順で開くだけである。手順は、変えない（ADR 0015 の「切れたあとの、つなぎ直し」）。
- 通信路の手順を変えるときは、映像も同じ変更を受ける。映像をデータグラム（UDP）に移すときは、手順の変更になるので、先にこの文書を更新する（ADR 0015 の「データグラムに移る条件」）。

### 文字のシェル（`shell_open`）【提案】（2026-11-19）

この節は【提案】で、決めるのは持ち主である。試作（ブランチ `proto-remote-shell`）だけにあり、試用版と `main` には入れない。`main` の前に、別のモデルが守りの面から見直す。

ねらい：持ち主の決め（2026-11-19 の 2）「ターミナルは、文字で運ぶ」。どのターミナルのアプリ（Terminal、rio、ghostty、hyper など）でも、シェルの代わりに起動できる小さなプログラム 1 つで、相手の機械のシェルを、Istesso の暗号の道で開く。ssh は使わない。アプリごとの対応はしない。

- **プログラム**：`istesso shell <端末> [--project <相手の機械のフォルダー> | --home] [--address <アドレス>[:<ポート>]]`、または `istesso shell --project-name [<機械>:]<プロジェクトの名前>`（下の「プロジェクトの名前で開く」）。ターミナルのアプリの「起動するコマンド」に、そのまま書ける。終わるときの終了コードは、相手のシェルの終了コード。相手のシェルが信号で終わったら 128＋信号の番号。つながらない、断られた、切れたときは 255（ssh と同じ）。
- **通信路の手順は、変えない。** 先頭の版（`ISC1`）、プロローグ、ハンドシェイク、封のしかたは同じである。足すのは、ハンドシェイクのあとのメッセージ（`shell_open` と、そのあとのシェルの枠）だけで、下の「変更の手順」の「メッセージの追加は版を上げずに行える」にあたる。知らないエージェントは、これまでどおり `unsupported` を返す。ポートも、エージェントのポート（既定 47801）のまま。
- **読む側と書く側を分ける口を、`istesso-link` の Rust の口に足す**（`Channel::split`）。シェルは、画面への出力とキーボードが、同時に、別々に流れるためである。線の上の形と暗号の手順は、変わらない。暗号の状態（`snow` の `TransportState`）を 1 つの錠で守り、錠を持つのは、封をするあいだと、開くあいだだけである。連番（nonce）は、これまでどおり `snow` が向きごとに持つ。書く側は 1 つだけで、封をした順に送る。新しい暗号の部品は足さない。

#### メッセージ

| 順 | 向き | 形 | 中身 |
|---|---|---|---|
| 1 | 接続側 → 受け側 | JSON `shell_open` | `cols`、`rows`（端末の大きさ。1〜1000 に丸める）。`term`（任意。`TERM` にする。英数字と `-._+` だけ、64 字まで。既定 `xterm-256color`）。`locale`（任意。`LANG` にする。同じ字種の検査。受け側の機械にないときは `C.UTF-8`）。`project`（任意。受け側の機械の上の、絶対パスか `~/` で始まるパス。または、受け側の機械に登録したプロジェクトの名前（2026-11-20 に足した。下の「プロジェクトの名前で開く」）。フォルダーでなければ、名前の登録がなければ、断る） |
| 2 | 受け側 → 接続側 | JSON | 開いたら `shell_open`。断るときは `error`：`forbidden`（下の「だれが開けるか」）、`internal`（シェルを起動できない、フォルダーがない、数の上限） |
| 3 | 双方向 | バイナリの枠 | 2 で開いたあと、この接続には、下の枠だけが流れる（映像の接続と同じく、JSON に戻らない） |

シェルの枠は、1 バイトの種類と、その中身である。

| 種類 | 向き | 中身 |
|---|---|---|
| `0x01` data | 双方向 | 端末のバイト。接続側から受け側へはキーボード、受け側から接続側へは画面への出力。送る側は 1 枠 32 KiB まで。受け側は 64 KiB を超える枠を受けたら切る |
| `0x02` resize | 接続側 → 受け側 | `cols`、`rows`（それぞれ 2 バイト、ビッグエンディアン） |
| `0x03` exit | 受け側 → 接続側 | 終わり方（1 バイト：0 終了コード、1 信号、2 権利を外された、3 受け側の都合）と、値（4 バイト、ビッグエンディアン）。このあと受け側が閉じる |
| `0x04` alive | 双方向 | 接続側が、10 秒おきに送る。受け側は、同じ `alive` で答える |

- 知らない種類の枠は、読み飛ばす（版のずれに寛容に、の決まりのとおり）。
- Ctrl-C、Ctrl-Z、Ctrl-D、Esc の並び、日本語の UTF-8 は、すべて data のバイトとして、そのまま運ぶ。信号に直すのは、受け側の疑似端末（PTY）の仕事で、ローカルのシェルと同じになる。接続側は、手元の端末を raw にして、何も解釈しない。

#### だれが開けるか

- **受け側の機械で、明示して入れたときだけ。既定は切。** `istesso agent --allow-shell <端末の指紋>`（何度でも書ける）。**名前は受けない**：名前は、端末がペアリングのときに自分で名乗るもので、鍵ほどには何も言わない（見直しの指摘、2026-11-19）。名前を渡すと、その名前の指紋を示して断る。起動のときに、ペアリング一覧の鍵に直し、許した端末を、名前と指紋で表示する。名がない端末からの `shell_open` は `forbidden`。
- **root では開かない。** エージェントが root で動いているときは、`--allow-shell` を断り、シェルも起動しない（見直しの指摘）。
- そのうえで、ペアリング一覧で、その端末が同じ鍵のまま「操作」の権利を持っていること。**開くときと、開いているあいだ 1 秒おきに、一覧を読み直す。** 解除されたか、「操作」を外されたら、`exit`（権利を外された）を送って切り、シェルを止める。入力と映像と同じ決まりである。
- 【提案】M5 で、「シェル」を、「見る」「操作」とは別の権利にする（持ち主の決め 5 の最後の問い。「端末ごとの話で、開発の妨げにはしない。Air には渡す」）。試作では足さない。いまのペアリング一覧の形は、知らない権利の名を読み飛ばせないので、権利を足すと、古い版が一覧を読めなくなる。足すときは、ADR 0006 を先に更新し、一覧の版の扱いを決める。
- 【問い】スイッチを、エージェントの起動の引数に置くか、持ち主の確かめつきの設定に置くか。ADR 0021（`m5-design` ブランチ）の「許可を持つプログラムは、外から何も受けない」に合わせるなら、後のほう。おすすめ：M5 で「シェル」の権利にまとめ、スイッチはなくす（権利を与えるのが、ホストにいる持ち主だけ、の決めに乗る）。

#### 受け側で、何が動くか

- **エージェントと同じユーザーで、そのユーザーのログインシェル**（ユーザーのデータベースの shell）を、ログインシェルとして（`argv[0]` の頭に `-`）、新しい疑似端末の上で動かす。root も、ユーザーの切り替えも使わない。新しいセッションを作り、その疑似端末を制御端末にする。
- 環境変数は、エージェントから受け継がず、作り直す：`HOME`、`USER`、`LOGNAME`、`SHELL`、`PATH`（OS の既定。ログインのファイルが足す）、`TERM`、`LANG`、それに、あれば `TMPDIR`（macOS）と `XDG_RUNTIME_DIR`（Linux）。エージェントの設定の場所などは、シェルに渡らない。
- 始まる場所は、`project` があればそこ（名前なら、その登録のフォルダー）、なければホーム。cd で別の持ち主のフォルダーに入ったときの決まり（持ち主の決め 2）は、まだない。
- 手元のプログラムは、端末ごとに、最後に開いたフォルダーを覚える（受け側がそのフォルダーでシェルを起動したと答えたときに、手元のキャッシュのフォルダーに、持ち主だけが読める形で書く）。`--project` なしで開くと、そこで開く。`--home` は、ホームで開いて、覚えを消す。新しいタブを開くたびにフォルダーを打たなくてよいように（持ち主の試用、2026-11-19 夜）。覚えは手元の便利のためで、受け側の決まりには関わらない。
- 疑似端末のファイル記述子は、ほかの子のプロセスに受け継がれないようにする（close-on-exec）。シェルどうしが、互いの端末を読めないようにするためである。

#### プロジェクトの名前で開く【提案】（2026-11-20、ブランチ `proto-ish-projects`）

- **ねらい**：`ish <プロジェクトの名前>` で、W1 のプロジェクトの一覧（`istesso projects`）が「その名前がある」と言う機械の、そのフォルダーでシェルを開く。
- **フォルダーの場所は、開発の機械だけが知っている**（W1 の決め。一覧の `projects` には、id、名前、種類だけが載る）。だから、名前をフォルダーに直すのは受け側である。接続側は、`shell_open` の `project` に、名前をそのまま入れる。
- **線の上の形は、変えない。** 足すのは、`project` の値の読み方だけである。名前は英数字で始まり、`/` を含まない（`istesso projects add` の決まり）。パスは `/` か `~` で始まる。だから、2 つは取り違えない。いままで、それ以外の値（相対のパス）は断っていたので、これまでの接続側の求めの意味は、変わらない。
- **名前を知らない受け側は、断る**（「絶対パスか `~/` で始まるパス」）。黙ってホームで開くことはない。別の欄を足すと、知らない受け側はその欄を読み飛ばして、ホームで開いてしまう。そのため、新しい欄にはしなかった。
- **受け側**：自分の登録（`istesso projects add` の記録）を、名前で引く（大文字と小文字は区別しない）。登録がなければ「その名前のプロジェクトは、この機械に登録されていない」で断る。登録のフォルダーがなくなっていれば、それも断る。断りの文に、送られた名前は入れない。記録にも、名前とフォルダーは書かない（「プロジェクトのフォルダーで開いた」とだけ書く）。
- **権利は、増えない。** パスの形で、受け側のユーザーが入れるフォルダーは、もともと、どこでも開ける。名前は、登録したフォルダーのどれかに、決まるだけである。
- **接続側**（`istesso shell --project-name`）：ペアリングしたすべての機械に、`istesso projects` と同じ問い合わせをして、名前の持ち主を決める。手元の機械は、調べない（機械の名前は `istesso doctor` と同じ求め方で、プロジェクトは手元の登録から取るだけ。道具を動かす調べは、しない）。決まった機械には、その問い合わせで答えたアドレスでつなぐ。`--address` を付けると、決まった機械がそのアドレスで覚えられているとき（`istesso peers address`）だけ、そこでつなぐ（有線の道を選ぶため）。ほかの機械に決まったときは、答えたアドレスでつなぐ。ほかの機械のためのアドレスへは、送らない。決まらないときは、シェルを開かずに、わけを 1 行目に出して 255 で終わる。当て推量はしない。
  - 2 台以上にある（一覧の `?`）：候補を `<機械>:<名前>` の形で並べる。表示名が同じ機械は、id で並べる。`<機械>:<名前>` で選ぶ。機械は、表示名（大文字と小文字は区別しない）、id、id の頭（4 文字以上）で指す。
  - 答えない機械にしかない（一覧の `!`）：「その機械は、いま答えていない」と、答えなかったわけ。
  - どこにもない：近い名前を 5 つまで。近いとは、足す、消す、変える、隣どうしを入れ替えるの数が、長いほうの名前の 3 分の 1（少なくとも 1）まで、または、一方が他方を含む（2 文字以上）こと。答えず、一覧も覚えていない機械があれば、その名前も出す。
  - 手元の機械にある：「この機械にある」。`istesso shell` は、ほかの機械でシェルを開くものである。
  - ほかの機械が送ってきた名前のうち、プロジェクトの名前の決まりに合わないもの（長すぎる、制御文字を含むなど）は、比べず、出さない。名前で選べないので、開くこともない。機械の表示名と、答えなかったわけは、制御文字を `\u{1b}` の形に書き換えて出す（端末の表示を書き換えさせないため）。`istesso projects` の一覧の行も、同じ（見直しの指摘、2026-11-20）。
- **覚え**：`--project` と同じく、開けた機械に、名前を覚える。次に `--project` なしで開くと、その名前で開く（受け側が、そのときの登録で引き直す）。
- `--project` には、フォルダーだけを渡す（`/` か `~` で始まるもの）。それ以外は手元で断り、`--project-name` を示す。受け側が名前を知るようになったので、相対のパスのつもりの語が、名前に取られないようにするためである。
- **確かめ（2026-11-20 07:52〜07:55、Air から Ubuntu のホストへ、有線。見たこと）**：ホストに、自分の試しのエージェント（ポート 26920、試しの身元の写し、`--allow-shell` は Air の試しの身元だけ）と、試しのフォルダー 3 つの登録（`alpha`、`beta`、`gamma`）。Air で、試しの身元の写しを使い、`scripts/ish` を擬似端末の上で動かした。開いたシェルで、フォルダーごとの印のファイルを読み、`exit 7` を打った。
  - `ish alpha` は `alpha` のフォルダーで開き、手元の終了コードは 7。引数なしの `ish` は、覚えた `alpha` で開いた。`ish <ホストの名前>:beta` と `ish BETA` は `beta` で開いた。パスの形（`ish <相対のパス>`、`ish ~/…`）と `ish --home` は、これまでどおり、そのフォルダーとホームで開いた。
  - `ish alpah` は、シェルを開かずに「どの機械にもない」と「did you mean: alpha」を出して 255。`gamma` を Air の写しとホストの両方に登録すると、`istesso projects` の 2 行に `?` が付き、`ish gamma` は、候補 2 つ（この機械、ホスト）を出して 255。`ish <ホストの名前>:gamma` で開いた。`ish <Air の表示名>:gamma` は「この機械にある」で 255。
  - ホストのエージェントを止めると、`ish alpha` は「いま答えていない」とそのわけを出して 255（0.8 秒）。`istesso projects` の行は `!`、`gamma` は `!?`。ホストの記録では、「プロジェクトのフォルダーで開いた」が 7 回あり、プロジェクトの名前の入った行はなかった。

#### 数と時間の上限

- 同時に開けるのは、端末ごとに 8、受け側の機械で 16。エージェントの同時接続の上限（64）の内側である。
- シェルの中のプログラムが入力を読まないあいだも、受け側は端末を読み続ける。打たれたものは、1 MiB まで受け側で待ち、プログラムが読むぶんだけ端末へ渡す。だから、そのあいだに端末が去っても、黙っても、受け側は気づく。1 MiB を超えたら、端末を読むのをやめ、シェルが 60 秒何も読まなければ、シェルを終える（見直しの指摘：読まないプログラムに貼り付けて端末が去ると、シェルと枠が残り続けた）。
- 端末から届く枠は、長さを読んだところで、64 KiB を超えるものを断る（それまでは、通信路の上限の 16 MiB まで受け取ってから断っていた）。
- 終えるときに、読まない端末を待たない。権利を外したときは、すぐに接続を切る（端末が読んでいれば、その前に「権利を外された」を送る）。シェルが自分で終わったときは、最後の出力に 1 秒、終わり方の枠に 1 秒を与える（見直しの指摘：読まない端末への書き込みが 60 秒の期限まで待ち、権利を外してから終わるまで 45 秒かかった）。
- 受け側は、60 秒何も届かない相手を切り、シェルに SIGHUP を送る（2 秒で終わらなければ SIGKILL）。接続側は、30 秒何も届かなければ「切れた」と言って、255 で終わる。Air のふたを 1 分閉じると、シェルは終わる。続けたいものは、ホストの上の herdr や tmux の中で動かす。

#### ish とマウント（試作、【提案】、2026-11-20。守りの見直しのあと）

上の cd の切り替えの「マウントの場所」を、本物のマウント（下の「フォルダーを読むだけで見せる」）にする試作。ブランチ `proto-ish-mount`（`proto-ish-forward` に `proto-mount-channel` を合わせたもの）だけにある。メッセージも、通信路の手順も、受け側も変えない。変えたのは、見る側の試作のプログラム（`research/unified-mount-proto` の `ensure`、`release`、`--machine-folder`）と、手元の zsh のファイル（`scripts/dev/cd-switch.zsh`）と、呼び出しの短いスクリプト（`scripts/dev/ish`、`scripts/dev/ish-mount`）だけ。

- **何が起きるか**：プロンプトで打った行の最初のコマンドが `cd <フォルダー>`（`AUTO_CD` のときは、フォルダーの名前だけの行）で、行き先が `<根>/<機械>/<フォルダーの ID>/…` のとき、cd が動く前に（`preexec`）、`ISTESSO_MOUNT_FOR[<機械>]` のプログラム（ubuntu は `ish-mount`）が、そのフォルダーをマウントする。マウントずみなら、何もしない。マウントができてから cd が動き、上のとおり、その端末が相手のシェルになる。`<根>` は `ISTESSO_MOUNT_ROOT`（なければ `~/Istesso`）。
- **マウントのしかた**：`ish-mount <ID>` は `unified-mount-proto ensure` を呼ぶ。`ensure` は、`mount` を別のセッションで始め（端末の信号が届かない。記録は状態のフォルダーに）、中身を答えはじめた（`mount` の記録に「mounted」が出て、カーネルのマウントの表に載った）ところで戻る。20 秒で済まなければ、`mount` に SIGTERM を送って（自分のマウントを外して終わる）、失敗とする。状態のフォルダー（ロック、プロセスの番号、記録）は、このユーザーの一時フォルダーの `istesso-mounts`（0700。Mac の起動で空になる）。マウントの場所ごとにロックを取るので、2 つのシェルが同時に同じフォルダーに入っても、`mount` は 1 つ。
- **相手のシェルは、どのフォルダーで始まるか**：`ISTESSO_MOUNT_HOST_PATH[<機械>/<ID>]`、なければ相手の `~/<ID>`。その下の道は、そのまま足す。手元に表を置くのは、受け側がフォルダーのパスを送らない（上の「接続側は、フォルダーの ID だけを送る」）ため。【問い】受け側が、ID でシェルを開く形（`shell_open` にフォルダーの ID を足す）にするか。おすすめ：プロジェクトの一覧（ADR 0025 の 1.1）を作るときに、そちらへ移す。手元の表と受け側の `--mount-folder` が食い違うと、マウントと違うフォルダーでシェルが始まり、それを手元からは見分けられないため。
- **いつ外すか（選んだこと）**：**手元で何も使っていないとき**。そのために試すのは、下の 2 か所で、どちらも、力ずくでない unmount(2) である。手元のどれかのプログラムが、マウントの中のファイルかフォルダーを開いているあいだは、システムが断る（EBUSY）。ほかのとき（見る側のプログラムが信号で終わるとき、`ensure` が 20 秒で諦めて止めるとき、見る側のプログラムが殺されて見張りが外すとき）は、これまでの見る側の決まりのとおり、使われていても、力ずくで外す。
  1. そのマウントから開いた相手のシェルが終わったとき、cd-switch が、その場で 1 回（`ish-mount --release`、`unified-mount-proto release`）。外れたら、そのマウントの見る側のプログラムを、その場で終わらせる（SIGTERM。マウントはもうないので、終わるだけ）。使われていれば「in use on this Mac; it stays mounted」と 1 行出して、残す。
  2. 見る側のプログラム（`mount --unmount-when-unused 30`。`ensure` が付ける）が、30 秒おきに。手元のシェルの窓が閉じられて、1 が起きないときも、外れる。外れたら「nothing on this Mac used the folder; unmounted it」と記録して、終わる。
  - 手元のシェルが、マウントの中で相手のシェルを開いているあいだは、そのシェルの作業フォルダーがマウントの中にあるので、外れない。見る側のプログラムと見張りは、作業フォルダーを `/` にして始まる（マウントの場所の空のフォルダーで始まると、自分のマウントを、自分で使っていることになり、外れなかった。見直しのあとの通しの確かめで見つけた）。
  - **`~/Istesso/ubuntu/` の下の空のフォルダーは、「マウントされていない」の意味で、「空のプロジェクト」ではない**（持ち主へ）。外れたあとも、マウントの場所のフォルダーは、空のまま残る。中を見るには、もう一度 cd する。
  - 選んだ理由：(1) `ish` が終わったときに必ず外すと、そのとき Mac のエディターや Finder が読んでいるファイルを、足元から抜くことになる（力ずくの unmount）。(2) ずっと付けたままにすると、手元だけの NFS のポートという弱いところ（下の「守りの限り」）が、そのぶん長く開いている。使われていないときだけ外せば、どちらも避けられる。2 を見る側のプログラムに置いたのは、窓を閉じたときには、手元のシェルが、もう何もできないため（はじめはプロンプトごとに試す形にしたが、それでは窓を閉じたときに、マウントが残った）。
- **相手に届かないとき**：`ish-mount` が、わけを 1 行（`cannot show ubuntu/<ID> here: cannot reach …`）、cd-switch が「`ubuntu/<ID>` is not shown on this Mac; the cd goes nowhere」と出し、cd はどこにも行かない（フォルダーがなければ zsh の「ない」、空のフォルダーがあれば、もとの場所に戻す）。相手のシェルは開かない。
- **マウントのあいだに、接続が切れたとき**：読み込みは EIO（上の「見る側」のとおり）。そのマウントから開いたシェルが終わると、使われていなければ外れる。見る側が「切れた」と記録したマウントに、もう一度入るときは、外してから、マウントし直す（使われていれば、そう言って断る）。ただし、その記録をした見る側のプログラムがまだ動いていて、表のマウントがそのプログラムのもの（下の「自分のマウント」）のときだけ。
- **自分のマウント**（見直しのあと、2026-11-20）：見直しで、「自分のマウント」をマウントの場所（パス）だけで見分けていたことが指摘された（見た）。前のマウントのプログラムが、同じ場所の新しいマウントを自分のものと取って、中にプロセスがいるのに力ずくで外しうる。古い「切れた」の記録で、`ensure` が健やかなマウントを外しうる。きっかけになりうるのは、前のプログラムが終わる前の、接続を閉じる待ち（5 秒まで）が、`ensure` の待ち（4 秒）より長いこと。直したこと：
  - 見る側のプログラムは、`mount_nfs` のあと、カーネルの表の、そのマウントの識別（`f_fsid`）を覚え、記録に書き（`fsid: …`）、見張りに伝える。そのあとは、見る側のプログラムも見張りも、**その識別のマウントだけを、それがその場所のいちばん上にあるときだけ**外す。ほかのマウントがあれば、触らない。伝える前に殺されたときだけ、見張りは、これまでどおり、その場所のマウントを外す。マウントの前に失敗したときは、見張りに「何もない」と伝える。
  - `ensure` は、そのマウントの見る側のプログラムがまだ動いていて、表のマウントの識別が記録のものと同じときだけ、そのマウントを使う（切れていれば、上のとおり、外してから作り直す）。そうでないときに、前の見る側のプログラムか見張りがまだ動いていれば、8 秒まで待ち、まだなら「an earlier mount of this folder is still ending; try again in a moment」と言って、新しいマウントを始めない。
  - マウントの前に失敗した回は、自分で作ったマウントの場所のフォルダー、記録、プロセスの番号のファイルを消す（ロックのファイルは残す。消すと、ほかのシェルが待っているロックと別のものになる）。
  - 状態のファイルの名前は、根の本当のパスの短いハッシュ（8 桁）から始める。根が 2 つあっても、混ざらない。
  - 二度目の見直し（同じ日）のあと：この流れが自分のものと見分けられない、生きているマウント（同じ根に状態のフォルダーが 2 つ、古い版のマウント、一時のファイルが消えたあと）が、使われているのに、見る側のプログラムの始めの「残ったマウントを外す」で、力ずくで外されうることが見つかった（見た）。始めの「外す」は、力ずくでない unmount(2) だけにした。使われていれば、「a mount is at … already and a program on this Mac uses it」と言って、マウントしない。**相手のいなくなった残りのマウントが、使われたままのときは、持ち主が手で `umount -f <場所>` で外す**（使っているプログラムを閉じれば、ふつうの `umount` でも外れる）。
  - `release` は、終わらせた見る側のプログラムの番号のファイルを消し、`ensure` も、終わっていたプログラムの番号のファイルを見つけたら消す（番号は、ほかのプログラムに配られうる）。見る側のプログラムは、自分の番号も記録に書き（`process: …`）、`ensure` は、それと見張りの番号で、前のものが終わるのを待つ。
- **cd-switch の、見直しのあとの直し**：`AUTO_CD` のとき、コマンド、別名、関数、組み込みの名前だけの行（`ls` など）は、フォルダーと取らない（持ち主のログインの zsh の設定は `AUTO_CD` を入れている。見直しで、`ls` でマウントのプログラムが動くことが見つかった）。`=~` は、シェルの設定にかかわらず ERE で読み（`REMATCH_PCRE` では、`$` が終わりの改行の前でも当たる）、改行を含むフォルダーは取らない。`AUTO_CD` の、引用符で囲んだコマンドの名前（`'true'`）も、コマンドと見る（二度目の見直しのあと）。前の段（`preexec`）が読めなかった cd（変数を使った `cd "$d"` など）が、マウントの場所の空のフォルダーに入ったときは、後の段（`chpwd`）でマウントし、入り直してから、相手のシェルを開く。

#### 作業場（どのプロセスが「中」か）

- 試作の作業場は、**`istesso shell` で開いた 1 つのシェルと、そこから始まったもの全部**である。
- **Linux（開発の機械）では、シェルごとに、ユーザーのサービス管理の一時のまとまり（`systemd-run --user --scope`、cgroup v2 のスコープ）を 1 つ作り、その中でシェルを始める。** 中のプロセスは、そのスコープ（と、その下のまとまり）の `cgroup.procs` に並ぶものとする。
  - 選んだ理由：子は、親のまとまりを、自分では抜けないかぎり受け継ぐ。`setsid` をして親から離れたもの（デーモンの形の開発サーバー、端末を多重化するプログラムのサーバー）、親が先に終わって、親が付け替えられたものも、中に残る。プロセスの親子の木や、セッションの番号では、これらがこぼれる（考え。cgroups(7) の「子は親のまとまりに入る」による）。
  - root は使わない。ユーザーのサービス管理は、Ubuntu の実機で、ssh で入ったプロセスから使えた（2026-11-19、`systemd-run --user --scope` が、`user@<番号>.service/app.slice/` の下にスコープを作った）。ログインのファイルを通すため、シェルは `-l` を付けて始める（スコープの道では、`argv[0]` の頭の `-` を付けられないため）。
  - サービス管理が使えないとき（試しのとき、管理のない機械）は、**シェルのセッション（シェルが `setsid` で作った番号）のプロセスと、その子孫**に落とす。どちらで見ているかは、一覧に出す。
- macOS（開発の機械）では、試作は、ポートを見つけない。`shell_open` は通り、ポートの一覧は「見ていない」と答える（下の `ports`）。
- **見分けであって、守りではない**（ADR 0025 の 4.3）。同じユーザーのプログラムは、スコープから出ることも、入ることもできる見込み（考え）。

#### ポートの見つけ方（Linux）

- 0.5 秒おきに、作業場のプロセスの `/proc/<番号>/fd` の `socket:[<inode>]` を集め、`/proc/net/tcp` と `/proc/net/tcp6` の、待ち受け（状態 `0A`）の行と照らす。root は要らない。同じユーザーのプロセスしか読めない（proc_pid_fd(5)）。
- 転送するのは、待ち受けのアドレスが `127.0.0.0/8`、`0.0.0.0`、`::1`、`::`（と、その IPv4 の写し）のものだけ。UDP、Unix ソケットは、見ない。
- **全部のネットワークで待ち受けているもの（`0.0.0.0`、`::`）や、LAN のアドレスでも待ち受けているものは、そのことを、ブラウザーの機械に知らせる**（持ち主の足し、2026-11-19。持ち主の実際の場面：シェルの中のコーディングエージェントが `python3 -m http.server 8000` を始めた。既定で全部のネットワークで待ち受けるので、フォルダーが、家の LAN のほかの機器から見えていた）。知らせは、ポートごとに 1 回：「ポート 8000 は、全部のネットワークで待ち受けている。転送には 127.0.0.1 だけで足りる（たとえば `--bind 127.0.0.1` で始める）」。**転送は、そのまま 127.0.0.1 で行う。** 待ち受けを変えるのは、Istesso ではなく、始めた人かエージェントである。
- LAN のアドレスだけで待ち受けるもの（127.0.0.1 では届かない）は、運ばない。そのことと、そのネットワークのほかの機器から届くことを、ポートごとに 1 回、知らせる。
- 一覧が変わったら、すぐに、変わった一覧の全部を送る。URL を開く頼みが来たときは、0.5 秒を待たずに見直してから、頼みを送る（開発サーバーが、待ち受けてすぐに「開く」を呼ぶため）。

#### メッセージ

| 順 | 向き | 形 | 中身 |

| 1 | 接続側 → 受け側 | JSON `shell_open` | これまでの項目に、`forward`（任意、真偽。既定は偽）を足す。真なら、作業場のポートの一覧と、URL を開く頼みを、このシェルの接続で送ってほしい、の意味。知らない受け側は、読み飛ばす |
| 2 | 受け側 → 接続側 | シェルの枠 `0x05` ports | JSON：`watching`（真偽。見ていないときは、`reason` に短い理由）、`how`（`cgroup` か `session`）、`ports`（並び。1 つは `id`、`port`、`family`（`4` か `6`）、`process`（待ち受けているプロセスの名前。表示のため、32 字まで。ASCII の見える字と空白だけで、ほかの字は `?` にする。向きを変える字や、幅のない字で、表示をだまさないため）、`exposed`（任意、真偽。全部のネットワーク、または LAN のアドレスでも待ち受けている））、`elsewhere`（任意。LAN のアドレスだけで待ち受けていて、転送できないポートの番号の並び）。**毎回、一覧の全部**。64 項目まで。開いた直後に 1 回、そのあとは変わるたびに送る |
| 3 | 受け側 → 接続側 | シェルの枠 `0x06` open_url | URL の UTF-8。4096 バイトまで。受け側でも、http と https で、形が正しいものだけを送る |
| 4 | 接続側 → 受け側（新しい接続） | JSON `forward_open` | `forward`：2 の `id`。**番号もアドレスも送らない** |
| 5 | 受け側 → 接続側 | JSON | つないだら `forward_open`。断るときは `error`（`forbidden`：シェルの権利がない、その端末の作業場の一覧にない ID。`internal`：受け側の中のポートにつなげない、数の上限） |
| 6 | 双方向 | 転送の枠 | 5 のあと、この接続には、下の枠だけが流れる |

- `id` は、受け側が決める、でたらめな 128 ビット（16 進）。シェルの接続ごと、ポートごとに作り、そのシェルが続くあいだ、同じポートには同じ `id` を使う。
- **行き先を決めるのは、いつも受け側である。** 受け側は、`id` を、その端末が開いているシェルの作業場の一覧から引き、**そのソケットが待ち受けているアドレス**の、その番号につなぐ：`127.x.x.x` はそのアドレス、`0.0.0.0` は `127.0.0.1`、`::1` と `::` は `::1`、IPv6 の形で書いた IPv4 は、その IPv4。頼む側は、行き先を名指しできない。だから、この口は、受け側のほかのポートや、LAN のほかの機器への中継にならない。
  - （見直しの指摘で直した。2026-11-20）はじめは、`127.0.0.0/8` のどれでも、`::` でも、`127.0.0.1` につないでいた。作業場が `127.0.0.2` だけで待っているとき、ほかのプログラム（ほかのユーザーのものもありうる）が `127.0.0.1` の同じ番号で待っていると、転送が、そちらに届いていた。
- `id` は、ポートごとに作る。作業場のソケットのどれかが、そのポートで待ち受けているあいだ、同じ `id` を使う（サーバーが、同じポートのソケットを足したり、作り直したりしても、続いている接続を切らない。見直しの指摘で直した。2026-11-20）。作業場のソケットが、そのポートで 1 つも待ち受けなくなったら、`id` を捨てる。
- **つなぐ前と、つないだあとに、待ち受けを読み直す。** 一覧は、0.5 秒まで古いことがあるからである。そのポートの待ち受けの行（`/proc/net/tcp{,6}`）から、その接続を受け取るソケット（行き先のアドレスそのものに待つもの。なければ、全部のアドレスに待つもの。IPv6 の全部のアドレスは、IPv4 も受けうるので数に入れる）を選び、それが 1 つ以上あって、**どれも作業場のプロセスが持つソケット**のときにだけ、つなぐ。そうでなければ、つながずに断る（`internal`）。
  - 全部の IPv6 アドレス（`::`）で待つソケットは、`::1` につなぐ。IPv6 を切った機械で `::1` に届かないときは、`127.0.0.1` を、同じ確かめのうえで試す（`::` は IPv4 も受けうるため）。
  - 転送の枠（下の 32 本と 16 本）は、この読み直しの前に取る。端末が、枠の数を超えて、受け側に `/proc` を読ませないためである。
- 転送の枠は、1 バイトの種類と、その中身：`0x01` data（バイトのまま。送る側は 1 枠 32 KiB まで、受ける側は 64 KiB を超えたら切る）、`0x02` end（こちらからは、もう送らない。TCP の片側の閉じにあたる）。知らない種類は、読み飛ばす。
- 中身には触らない。受け側でも、接続側でも、書き換えない（下の Host の確かめは、見るだけ）。
- **通信路の手順は、変えない。** 足すのは、ハンドシェイクのあとのメッセージと、シェルの枠の種類だけで、「変更の手順」の「メッセージの追加は版を上げずに行える」にあたる。知らないシェルの枠は、これまでの版でも読み飛ばす決まりである。
- ブラウザーの接続 1 本につき、通信路の接続 1 本（ADR 0025 の 4.4）。束ねない。

#### だれが使えるか

- `forward_open` を通すのは、シェルを開ける端末（`--allow-shell` で名指しされ、ペアリング一覧で「操作」を持つ）で、その `id` が、**その端末が、いま開いているシェル**の作業場の一覧にあるときだけ。
- 開くときと、開いているあいだ 1 秒おきに、権利を読み直す。外されたら切る。シェルが終わったら、そのシェルの転送の接続を、1 秒以内に全部切る。**その `id` が一覧から消えたとき**（ソケットが待ち受けをやめた）も、受け側の転送の接続を切る。
- 受け側の転送の接続は、全体で 32 本まで（エージェントの同時接続の上限 64 の半分）。転送が枠を使い切って、入力やシェルがつなげなくなることを防ぐ。**1 台の端末は、そのうち 16 本まで**（見直しの指摘で足した。2026-11-20）。接続をたくさん開くページ 1 つが、ほかの端末の転送の枠を使い切らないためである。
- **転送の接続は、どちらの向きにも何も流れないまま 120 秒たったら、閉じる**（両方の側。見直しの指摘で足した。2026-11-20）。ブラウザーは、次の求めのために接続を開いたままにするので、閉じないと、受け側の 1 台 16 本の枠が、使っていない接続で埋まる。開発サーバーの、静かに開いたままの接続（画面の差し替えを知らせる WebSocket など）も、120 秒で切れる。ページの側が、つなぎ直す見込みである（考え。確かめていない）。
- ブラウザーの機械の側では、**転送 1 本につき、同時に 64 接続まで**。それを超える接続は、すぐに閉じる。**最初の求めの頭は、接続してから 10 秒以内に、全部届かなければ切る**（1 バイトずつ送り続ける相手が、スレッドを持ち続けないため）。数えて、`istesso forwards` の一覧に出す。スレッドを作れないときも、閉じて数える。シェルを運ぶ流れの中では、どこでも、パニックで止まらない（止まると、手元のターミナルが、打った字をそのまま通す状態のまま残る）。（どれも、見直しの指摘で足した。2026-11-20）

#### ブラウザーの機械（接続側）での待ち受け

- `127.0.0.1` で待ち受ける。**同じ番号を `::1` でも待ち受ける**（ADR 0025 の【問い 作10】のおすすめ (g) を、試作で先に入れた）。`localhost` は、Mac で `::1` にも引かれるので、`::1` の同じ番号にほかのプログラムがいると、ブラウザーがそちらにつながる恐れがあるためである。`::1` が使えない機械では、`127.0.0.1` だけ。0.0.0.0 では待ち受けない。
- 番号は、受け側と同じ。**ぶつかったら（どちらかのアドレスで使われている、開けない）、上へ 1 つずつずらして、空いた番号を使い、知らせる。** いちど決めた番号は、そのシェルのあいだ、変えない。
- **固定**：`istesso shell --forward-pin <受け側の番号>[:<こちらの番号>]`（何度でも）。固定した番号が使えないときは、ずらさずに、その転送をしないで、知らせる。
- 知らせは、ターミナルに 1 行（`istesso: …`）。画面を使うプログラムの絵を、少し崩す。ADR 0025 の 4.5 は、ターミナルの外（通知、一覧）を勧めている。試作は、1 行で済ませた。
  - **ターミナルの中の知らせは、信用できない**（見直しの指摘で直した。2026-11-20）。受け側のシェルの出力は、同じターミナルに流れるので、受け側のプログラムは、知らせを消す（画面を書き換えて流す）ことも、`istesso: …` の偽の行を書くこともできる。信用できるのは、`istesso forwards` の一覧だけである。`main` に入れるには、ターミナルの外の知らせ（ADR 0025 の 4.5）が要る。
- **このユーザーのプログラムからの接続だけを受ける。** Air のほかのユーザーからの接続は断る（持ち主の決め、11-20）。受けた接続ごとに、1 バイトも読まないうちに、相手の端（この接続と同じ 2 つのアドレスと 2 つの番号を、逆の向きに持つソケット）を、OS に聞く。4 つが全部ぴったり合うものだけを、相手の端とする（IPv6 の形で書いた IPv4 は、その IPv4 として比べる）。
  - Linux：`/proc/net/tcp` の、その行の `uid`（ソケットの持ち主。資料：proc(5)）が、このユーザーか。IPv4 の接続は、IPv6 のソケットから来ることもあるので、見つからなければ `/proc/net/tcp6` も見る。どのプロセスも持たなくなったソケット（`inode` が 0。閉じかけのもの、終わりを待つもの）の行は、数に入れない。root は要らない。
  - macOS：システムの TCP 接続の表（`sysctl net.inet.tcp.pcblist64`。`netstat` が読むもの）の、その接続の項目の、ソケットを作ったユーザー（`so_uid`）が、このユーザーか。どの記述子も持たなくなったソケット（`so_state` のいちばん下のビット。閉じて、終わりを待つだけのもの）の項目は、数に入れない。root は要らない。表には、ほかのユーザーの接続も載る（Air で見た：root の待ち受けが載っていた。root でないほかのユーザーの接続は、Air にないので、見ていない）。項目の中の位置は、SDK の `<netinet/in_pcb.h>`、`<netinet/tcp_var.h>`、`<sys/socketvar.h>` に合わせた（Air の SDK で、C の小さなプログラムで出した値。arm64）。項目は、自分の長さを先頭に持つので、長さで次へ進む。短すぎる項目、途中で切れた表は、そこで読むのをやめる（読めなかったものは、見つからないので、断る）。**プロセスのソケットを 1 つずつ見る方法（`proc_pidfdinfo` の `PROC_PIDFDSOCKETINFO`。11-20 の朝の作り）は、やめた。** 見ているあいだ、相手のプロセスの記述子を一瞬つかむので、その一瞬に記述子が閉じられると、そのソケットで待っている読み込みが、`EBADF` で失敗するようになる。このユーザーの、ほかのプログラムのソケットでも起きる（下の「EBADF の原因」）。
  - 見つからない、ほかのユーザーのもの、のどちらも、すぐに閉じる。受け側には、何も送らない。ターミナルに 1 回だけ知らせ、`istesso forwards` の一覧の数に出す（JSON の `other_user`。表では REFUSED に足す）。
  - macOS と Linux のほか（BSD など）では、相手が分からないので、どの接続も断る。
  - 費用は、下の「守りの限り」。
- **Host の確かめ（DNS の付け替えへの守り。持ち主の足し、2026-11-19）**：入ってきた接続の最初の求めが HTTP のときは、`Host` が `localhost:<こちらの番号>`、`127.0.0.1:<こちらの番号>`、`[::1]:<こちらの番号>` のどれか（大文字と小文字は区別しない。こちらの番号が 80 のときは、番号を書かないものも）でなければ、受け側へつながずに、`403` を返して閉じる。`Host` がない、2 つある、ASCII の外の字を含む、求めの行が HTTP/1.x でない、求めの行にタブなどの制御文字がある、行の中に CR、LF、NUL がある、16 KiB 以内に頭が終わらない、も断る。ほかの見出しの値の中の、ASCII の外のバイトは通す。悪いページが、自分の名前を 127.0.0.1 に引かせて（DNS の付け替え）、転送の口に届くのを止める。中身は、見るだけで、書き換えない。見た分も、そのまま受け側へ送る。
  - 見るのは、接続ごとに、**最初の求めだけ**である。ブラウザーは、名前（オリジン）が違う求めに、同じ接続を使い回さない見込み（考え。接続のまとめ方の鍵に、名前が入るため）。
  - 最初のバイトが TLS の始まり（`0x16`）のものは、試作では、**見ずに通す**（下の【問い】）。HTTP でも TLS でもないものは、断る（ADR 0025 の【問い 作10】(d) のおすすめ。守りではなく、事故を減らすため）。
- 【問い】HTTPS（TLS）の接続を、Host の確かめと同じ考えで絞るか。TLS では、`Host` は暗号の中にあって、終端しないと見えない。見えるのは、ClientHello の SNI（つなぎたい名前）だけである。選ぶもの：
  - **(a) SNI を見る。** SNI がない（IP アドレスで開いたとき、ブラウザーは送らない）か、`localhost` のときだけ通す。費用：ClientHello を読む小さな読み手が要る（中身は書き換えない）。効くこと：DNS の付け替えで来る接続は、SNI に悪いページの名前が載るので、止まる（考え）。
  - **(b) 転送したポートでは、HTTP だけを通し、TLS は断る。** 開発サーバーを HTTPS で動かす使い方（Vite の `--https` など）が使えなくなる。
  - **(c) 見ずに通す**（いまの試作）。DNS の付け替えで来たブラウザーは、証明書の名前が合わないので、ふつうは、TLS のところで止まる（考え。開発サーバーの証明書が、悪いページの名前を含まないかぎり）。証明書の確かめを無視させる設定や、だれの名前でも通す証明書を使う開発サーバーには、効かない。
  - **おすすめ：(a)。** 見るだけで、書き換えず、HTTPS の開発を止めない。(c) が頼る証明書の確かめは、開発用の自己署名の証明書では、人が「進む」を押して外していることが多い（考え）。
- 一覧と止めるスイッチ：`istesso forwards [--json]`、`istesso forwards stop <こちらの番号>`、`istesso forwards stop --all`。シェルのプロセスごとに、持ち主だけが入れるフォルダー（0700）の Unix ソケットで聞く。止めると、待ち受けを閉じ、開いている接続を、すぐに切る。**止めたものは、そのシェルのあいだ、覚える。** 同じポートが、また開いても、転送しない。`--all` で止めたシェルは、新しいポートも転送しない。`istesso shell --no-forward` で、はじめから転送しない。

#### URL を開く頼み

- 受け側は、作業場のシェルの環境に、`BROWSER` を、小さなコマンド（`istesso-open`）に向けて入れる。Linux では、同じ場所に `xdg-open` の代わりも置き、`PATH` の先に足す。代わりの `xdg-open` は、引数が 1 つで、http か https の URL のときだけ頼みにする。それ以外は、`PATH` の後ろの、元の `xdg-open` にそのまま渡す。
- `istesso-open` は、エージェントの Unix ソケット（持ち主だけが入れるフォルダー、0700）に、URL を 1 行で送る。エージェントは、**つないできたプロセスの番号を OS に聞き（`SO_PEERCRED`）、そのプロセスが作業場の中のときだけ**、その作業場のシェルの接続に `open_url` を送る。中でなければ断る。同じユーザーかも見る。1 つの作業場につき、5 秒に 5 回まで。
- 接続側（ブラウザーの機械）は、もう一度、厳しく読む：http か https。RFC 3986 の字だけ（空白、制御文字、`\`、`"<>^`{|}` を含むものは断る）。ユーザー名やパスワードの入ったもの（`@` を含む主の部分）は断る。4096 バイトまで。主の名前は、最後に `.` の付いたもの、最後の区切りが数のもの（`0x7f.1`、`example.1`。ブラウザーは IPv4 として読む）、`127.1` のような略した IPv4 を断る。
  - 行き先が `localhost`、`127.0.0.1`、`[::1]`、`0.0.0.0` のとき：その番号（書いていなければ、http は 80、https は 443）が、このシェルの転送にあれば、こちらの番号に置き換える（`0.0.0.0` と `[::1]` は `127.0.0.1` にする）。なければ、開かずに知らせる。ブラウザーの機械の、関係のないポートを開かせない。
  - **ブラウザーの機械そのものや、家の中のネットワークを指すもの**（上の 4 つの形のほかの、ループバック、プライベート、リンクローカル、共有、全部のアドレス。`[::ffff:127.0.0.1]` や `[::]` のような IPv6 の書き方も。`*.localhost`、`*.local`、`*.home.arpa`、`*.internal`、`*.lan`、`.` のない名前）は、**どの設定でも開かない**。ブラウザーの機械の、関係のないサービスや、家の中の機器に届かないためである（見直しの指摘で足した。2026-11-20）。
  - そのほかの http と https：試作では、**開かずに、主の名前だけを知らせる**（`istesso shell --open-urls all` で開く）。ADR 0025 の【問い 作11】のおすすめ (b)（外の URL は、知らせて、持ち主が押してから）に寄せた。押して開く画面は、試作にはない。
  - 受け側の上限（5 秒に 5 回）とは別に、接続側でも、5 秒に 5 回まで。
  - 開くのは、OS の「開く」の口に、URL を引数 1 つで渡す（macOS は `/usr/bin/open -u`。`-u` で、引数をファイルの名前ではなく、URL として渡す。Linux は `xdg-open`）。シェルは通さない。`ISTESSO_URL_OPENER` に、代わりのプログラムを書ける（試しでは、URL を書き留めるだけのものを使い、持ち主のブラウザーを起こさない）。

#### 何を記録するか

- 受け側：作業場ごとに、見つけたポートの番号と、増えた・消えた、転送の接続ごとに、ポートの番号、続いた時間、行き来したバイト数。URL の頼みは、受けた・断った、の数と、断った理由の種類だけ。
- 接続側：知らせの行に、番号と、外の URL なら主の名前（`https://例の名前`）まで。
- **URL のパスと問い合わせ（`?` のあと）、運んだ中身のバイトは、どこにも書かない。**

#### 守りの限り（分かっていること）

- **ブラウザーの機械の 127.0.0.1 には、その機械の、このユーザーのどのプログラムも届く。** 転送のあいだは、受け側の中だけで開いていたポートに、ブラウザーの機械の、同じユーザーのほかのプログラムが届く。ssh のポートを引く機能と同じ性質で、ADR 0025 の 4.8 の「同じユーザーの線の例外」そのものである。Host の確かめは、ブラウザーの中のページ（DNS の付け替え）を止めるだけで、ほかのプログラムは、正しい `Host` を書いて通れる。
- **ほかのユーザーのプログラムからの接続は、断る**（上の「ブラウザーの機械（接続側）での待ち受け」）。見直しの指摘の【問い】（2026-11-20）の選びのうち、(b) である。Air のほかのユーザーからの接続は断る（持ち主の決め、11-20）。採らなかったもの：(a) 例外として受け入れる。(c) 127.0.0.1 の TCP をやめて、このユーザーだけが入れる Unix ソケットにする（ブラウザーが、つなげない）。
- この確かめが**守らないもの**：
  - **同じユーザーのプログラム**：どれでも通る（上の行）。
  - **root**：root のプログラムからの接続そのものは、断る（ソケットのユーザーが 0）。けれども root は、このユーザーとして動くことも、どのプロセスの中を読むこともできるので、root に対しては、守りにならない。
  - **短い競り合い**：見るのは、接続を受けたときの、1 回の写しである。そのあいだに相手の端が閉じたら（どのプロセスも持たなくなったら）、断る（分からないときは、断る側に倒す）。こちらの端が開いているあいだは、同じ 4 つの組の接続は、ほかに作れない（考え。TCP の決まりから）ので、閉じた相手の番号を、ほかのユーザーが引き継ぐことはない。ソケットを、プロセスからプロセスへ渡したもの（fork、Unix ソケットでの受け渡し）は、作ったユーザーのものとして扱う（Linux も macOS も）。渡すには、持っていた側の手助けが要る。見たあとで渡されたものは、見ない。
  - **費用**：接続 1 本ごとに、1 回見る。macOS（Air。表の項目 約 270〜320。リリースのビルド、200 回）：見つかるとき、中央 0.15 ms、最大 0.49 ms。見つからないとき、中央 0.11 ms、最大 0.14 ms。表を 1 回まるごと読むので、相手がどのプロセスでも、同じくらいである（プロセスのソケットを 1 つずつ見ていた朝の作りでは、見つからないとき、中央 1.5〜1.9 ms だった）。Linux は、`/proc/net/tcp`（と `tcp6`）を読む手間で、下の「確かめ」に測った値を書いた。ブラウザーが一度に開く数本は、それぞれのスレッドで、並んで見る。ほかのユーザーのプログラムは、見て断るまでのあいだ（ms の単位）だけ、64 の枠の 1 つを使う。
  - Linux の、ほかのネットワークの名前空間（コンテナーなど）のプログラムは、そもそも、この 127.0.0.1 に届かない（考え）。
  - **macOS で、見る手順と同時に、受けたばかりの接続が `EBADF` になることがあった**：原因は、見る手順が、プロセスの記述子を一瞬つかむことだった（下の「EBADF の原因」）。接続の表を読む方法に替えて、起きなくなった。朝の作りのままだと、転送の接続だけでなく、このユーザーのほかのプログラムの、待っている読み込みも、まれに壊すおそれがあった（子プロセスを起こすプログラム、記述子の写しを閉じるプログラム）。
  - ほかのユーザーからの接続を断ることは、合成の表（テストで作った `/proc/net/tcp` の行と、macOS の接続の表）でしか確かめていない。Air にもホストにも、試しに使える 2 人目のユーザーがなく、作るには sudo が要るためである。実機では、同じユーザーの接続が通ること（同じプロセスから、ほかのプロセスから）と、閉じた相手が「見つからない」になることを確かめた。転送の側で断るふるまいは、OS への問いの答えを差し替えたテストで確かめた（下の「確かめ」）。
- 作業場の見分けは、守りではない。受け側の同じユーザーのプログラムは、作業場のスコープに入って、自分のポートを転送させることができる（考え）。URL を開く頼みも、作業場の中のプロセスに見せかけて送れる。
- URL を開く頼みは、受け側のプログラム（コーディングエージェントを含む）が、持ち主のブラウザーを動かす口である。試作は、外の URL を既定では開かない（上）。**ただし、これは、外へ出す道を塞がない**（見直しの指摘で直した。2026-11-20）：受け側のプログラムは、自分のポート（作業場の中なので転送される）で、ほかの場所への移り先（リダイレクト）を返すだけのページを出し、`http://localhost:<その番号>/` を開く頼みを出せる。この頼みは、既定の形で開かれ、ブラウザーは移り先へ進む。移り先の URL に中身を載せれば、外へ出せる。ADR 0026 の範囲 (3)（ネットワークを決まった宛先だけ）の抜け道になることは、既定の形でも変わらない。**同じ移り先で、「ブラウザーの機械や家の中のネットワークを指す URL は開かない」も越えられる**：転送されたページが、ブラウザーの機械の `127.0.0.1` や、LAN のアドレスへ移らせれば、ブラウザーはそこへ進む（見直しの指摘、2026-11-20）。
- 転送の接続は、シェルの接続と同じく、打った間隔とバイト数が、ネットワークの上で見える。
- Host の確かめは、接続ごとの最初の求めだけを見る。TLS は見ずに通す（上の【問い】）。
- ブラウザーの機械の側で、転送 1 本に開ける接続は 64 までだが、同じ機械の、同じユーザーのプログラムは、それを使い切れる。そのあいだ、その転送は、ブラウザーの接続を断る。ほかのユーザーのプログラムも、見て断るまでの短いあいだ、枠を使うので、たくさんつなぎ続ければ、ブラウザーの接続が断られることは、ありうる（考え）。
- `SO_PEERCRED` で得るのは、ソケットをつないだときのプロセスの番号である。そのプロセスが終わり、同じ番号がほかのプロセスに使われると、取り違える見込みがある（考え。頼みは 1 行で、2 秒で締め切るので、時間は短い）。
- エージェントの頼みの口（`open.sock`）と、`istesso-open` へのリンクは、受け側のユーザーの実行時のフォルダー（`$XDG_RUNTIME_DIR` の下、持ち主だけが入れるフォルダー）に置く。

### フォルダーを読むだけで見せる（`mount_open`）【提案】（2026-11-19）

この節は【提案】で、決めるのは持ち主である。試作（ブランチ `proto-mount-channel`。`proto-remote-shell` の上）だけにあり、試用版と `main` には入れない。`main` の前に、別のモデルが守りの面から見直す。

ねらい：持ち主の決め（2026-11-19 の 1）「プロジェクトのフォルダーは 1 台の持ち物。ほかの機械からは、マウントで見える・開けるだけ」。ADR 0025（ブランチ `design-workspace-stage`）の 1.5 のおすすめ 3 と 5：Mac の見る側は、手元だけの NFS（読むだけ）をつなぎにする。機械のあいだは、NFS の手続きを運ばず、自前の小さな頼み（一覧、属性、読む、リンクの行き先）で運ぶ。調査（ブランチ `research-unified-mount` の `docs/research/unified-mount.md`）の試作は、持ち主の機械の係を ssh の標準入出力で動かしていた。それを、この通信路に移す。

- **通信路の手順は、変えない。** 足すのは、ハンドシェイクのあとのメッセージ（`mount_open` と、そのあとの問いと答えの枠）だけで、「変更の手順」の「メッセージの追加は版を上げずに行える」にあたる。知らないエージェントは、これまでどおり `unsupported` を返す。ポートも、エージェントのポート（既定 47801）のまま。
- 読む側と書く側を分ける口（`Channel::split`）は、シェルが足したものを使うだけで、変えない。

#### だれが、どのフォルダーを

- **受け側（フォルダーの持ち主の機械）で、明示して入れたときだけ。既定は切。** `istesso agent --mount-folder <ID>=<フォルダー> --allow-mount <端末の ID>`（どちらも何度でも書ける）。端末は、ペアリング一覧の ID（指紋）だけで名指しし、名前は受け付けない（名前は、ペアリングする人が付けられるため。`--allow-shell` と同じ。2026-11-20、見直しのあと）。名前を渡すと、その端末の ID を示して断る。始まるときに、見せる端末を「名前 (ID)」で出す。両方がそろわなければ、どの `mount_open` も `forbidden`。
- **接続側は、フォルダーの ID だけを送る。パスは送らないし、受け側も受け取らない。** ID は、英小文字、数字、`-` の 1〜32 字。名指しされていない ID は、ない ID と同じ答え（`forbidden`、同じ文）にして、どの ID があるかを漏らさない。
- 端末は、`--allow-mount` で名指しされ、同じ鍵のまま、ペアリング一覧で「操作」の権利を持っていること。**開くときと、開いているあいだ 1 秒おきに、一覧を読み直す。** 解除されたか、「操作」を外されたら、接続を切る。シェル、入力、映像と同じ決まりである。
- 「操作」を求めるのは、ファイルの中身を読めることが、「見る」（役割表とアプリの一覧）よりずっと大きいからである。【提案】M5 で、ADR 0013 の「ファイル」の権利にする。権利を足すときは、ADR 0006 を先に更新する（シェルの節と同じ理由）。
- 【問い】試作では、名指しした端末のどれもが、名指ししたフォルダーのどれでも開ける。フォルダーごとに端末を分けるか。おすすめ：プロジェクトの一覧（ADR 0025 の 1.1）ができたら、プロジェクトごとに持つ。
- 【問い】スイッチを、エージェントの起動の引数に置くか、持ち主の確かめつきの設定に置くか。シェルの節の問いと同じで、答えも同じにする。

#### メッセージ

| 順 | 向き | 形 | 中身 |
|---|---|---|---|
| 1 | 接続側 → 受け側 | JSON `mount_open` | `folder`（ID） |
| 2 | 受け側 → 接続側 | JSON | 開いたら `mount_open`：`root`（根の属性）、`max_read`（1 回に読めるバイト数）。断るときは `error`：`forbidden`（上）、`internal`（フォルダーを開けない、数の上限） |
| 3 | 双方向 | 枠 | 2 で開いたあと、この接続には、下の枠だけが流れる。接続側が 1 つ問い、受け側が 1 つ答える。同時に 1 つだけ |

枠は、4 バイト（ビッグエンディアン）の JSON の長さ、JSON、残りが生のバイト（`read` の答えだけ）。

| 問い（`op`） | 答え（`ok`） |
|---|---|
| `stat`：`id` | `attr`：`attr` |
| `lookup`：`dir`、`name`（バイト列） | `found`：`id`、`attr` |
| `read_dir`：`id`、`start` | `entries`：`entries`（名前、`id`、属性）、`more`、`next`。1 回 1024 件まで。受け側が 1 回に見る項目は 4096 まで（隠すものが多いと、空のページもある）。`start` は、受け側の一覧（隠すものも含めて、名前の順）の中の場所で、はじめは 0、次は前の答えの `next`（`next` を言わない古い受け側には、見せた数を足す） |
| `read`：`id`、`offset`、`count` | `data`：`eof`。中身は枠の残り。`count` は 1 MiB に切り詰める |
| `read_link`：`id` | `link`：`target`（リンクの文字。辿らない） |
| `alive` | `alive` |
| 誤り | `failed`：`no_ent`、`not_dir`、`is_dir`、`access`、`invalid`、`loop`、`stale`、`io`、`too_many` |

- `id` は、受け側がその接続のあいだだけ配る番号で、根は 1。接続が変われば、前の番号は `stale` になる。属性は、種類（ファイル、フォルダー、リンク、そのほか）、権限のビット、リンクの数、大きさ、変更の時刻。持ち主の機械のユーザー番号は送らない。
- 知らない `op` には `failed`（`invalid`）を返して、接続は続ける。知らない答えは、接続側では誤り（`io`）にする。
- 書く問いは、ない。**読むだけであることは、受け側の作りで決まる。** 見る側が何を頼んでも、受け側は、書く手続きを持っていない。

#### 受け側で、何をするか

- 名指ししたフォルダーを、エージェントの起動のときではなく、`mount_open` のたびに開く（ディレクトリーの記述子）。その下は、名前を 1 つずつ `openat(…, O_NOFOLLOW)` で開く。`..`、`.`、`/` や NUL を含む名前、空の名前、255 バイトを超える名前は断る（`invalid`）。リンクは、リンクとして一覧に出し、辿らない。読むときに出会えば `loop`。パイプ、デバイス、ソケットは、一覧に出すが開かない（**開く前に種類を見て**、ふつうのファイルだけを `O_NONBLOCK`、`O_NOCTTY` で開き、開いたものが見たものと同じふつうのファイルかを確かめる）。調査の試作（`export.rs`）の作りをもとにした。
- **名指ししたフォルダーと違うファイルシステムのもの（フォルダーの中にマウントされたボリューム）は、見せない**（一覧に出さず、`lookup` も読むことも「ない」）。
- エージェントと同じユーザーで読む。root も、ユーザーの切り替えも使わない。
- **Git が無視するファイルは、既定で見せない**（持ち主の決め、2026-11-19 に追加。`.env` のような秘密を、見る側の機械に出さないため。`node_modules`、`target` のような大きいものを、一覧に出さないため）。
  - 見る規則：フォルダーの中の `.gitignore`（その名前のあるフォルダーと、その上のフォルダーの、名指ししたフォルダーまで。深いものが勝つ）、名指ししたフォルダーの `.git/info/exclude`、受け側のユーザーの全体の除外ファイル（`core.excludesFile`、なければ `~/.config/git/ignore`。`mount_open` のたびに読み、その接続のあいだは変えない）。規則の読み方は `ignore` クレート（ripgrep のもの。Unlicense か MIT）の `gitignore` を使い、自分では書かない。`.gitignore` そのものは、`O_NOFOLLOW` で読む（リンクの `.gitignore` は読まない。Git 2.32 からの Git と同じ）。
  - **規則のファイルが読めないときは、隠す**（2026-11-20、見直しのあと）。ないときだけが「規則なし」。あるのに丸ごと読めないとき（リンク、ふつうのファイルでないもの、権限がない、1 MiB より大きい、読み込みの誤り、途中のフォルダーがリンクや別のファイルシステム）は、そのファイルが決めるはずだったものを、すべて隠す：`.gitignore` なら、そのフォルダーの下のすべて。`.git/info/exclude` と全体の除外ファイルなら、すべての項目。**Git との違い**：Git は、リンクの `.gitignore` を読まず、それが隠すはずだったものを見せる。こちらは、迷ったら隠す（持ち主の決め）ので、隠す。
  - **`.git` も見せない**（その名前のフォルダーとファイル、どの深さでも。どの綴りでも）。歴史には、消したはずの秘密が残り、`.git/config` には、リモートの資格が入ることがある。
  - **隠すことは、秘密を守るための仕組みなので、迷ったら隠す**（持ち主の決め、2026-11-19）。Mac のふつうの APFS は、大文字と小文字を区別せず、Unicode の合成形と分解形（NFC と NFD）を同じ名前として扱う。そこでは `.GIT/config`、`.Env`、分解形で書いた名前が、隠したファイルに届く（2026-11-19、自動の見直しが、バイトで比べる規則との食い違いを見つけた）。だから：(1) `lookup` は、そのフォルダーの一覧に、**同じバイト列で載っている名前だけ**を受け、番号は、ディスクの上の綴りにだけ配る。(2) 配った番号でも、問いのたびに、道のすべての名前が、同じバイト列で、まだ一覧に載っているかを確かめる。載っていなければ（綴りを変えて名前を付け替えた、など）、ないものとして答える。(3) 規則は、名前を 2 通りに当てる：そのまま（Linux の Git と同じ）と、たたんで（合成形にし、大文字と小文字をそろえる。ASCII だけでなく、`É`、`ſ` なども）。どちらかで隠れるなら隠す。たたんだときにだけ当たる `!` の規則では、出さない。これは、どのボリュームでも同じにした（Linux でも、`.env` の規則は `.ENV` を隠す。Git より隠す）。たたむのは `unicode-normalization` クレート（MIT か Apache-2.0）と、Rust の大文字・小文字の変換で、APFS のたたみ方と同じだとは確かめていない。同じでなくても、(1) と (2) で、ほかの綴りからは入れない。テストは、Air の一時フォルダー（大文字と小文字を区別しない APFS。`pathconf` で確かめた）と Ubuntu で動かした。
  - 見せないものは、一覧に出ず、`lookup`、`stat`、`read`、`read_link` には、ないのと同じ答え（`no_ent`）を返す。すでに配った番号でも、問いのたびに、その道のすべての段を確かめ直す（あとから `.gitignore` が変わったときのため。規則は 2 秒まで覚える）。
  - 持ち主が、フォルダーごとに「見せる」を選べる：`--mount-show-ignored <ID>`。そのときは `.git` も見せる。
  - 限り（分かっていること）：Git そのものを呼ばないので、Git と違うことがある。(0) ユーザーの Git の設定の `include.path`、`includeIf` は辿らない（そこに書いた `core.excludesFile` は見ない。見せすぎになりうる）。中のリポジトリー（サブモジュールなど）の `.git/info/exclude` は見ない（見せすぎ）。UTF-8 でない規則の文字は、置き換え文字にして読む（その規則は当たらないことがある）。(1) 名指ししたフォルダーが、リポジトリーの途中のフォルダーのとき、それより上の `.gitignore` と `.git/info/exclude` は見ない（見せすぎになる）。(2) worktree のように `.git` がファイルのとき、本体の `info/exclude` は見ない（見せすぎ）。(3) リポジトリーの設定（`.git/config`）の `core.excludesFile` は見ず、ユーザーの全体の設定だけを見る（見せすぎになりうる）。(4) Git のリポジトリーでないフォルダーでも、`.gitignore` があれば当てる（Git より隠す。ripgrep の `--no-require-git` と同じ）。(5) Git に登録済み（追跡している）ファイルが、規則に当たると隠れる（Git は、追跡しているファイルを無視しない。こちらは隠す）。(6) 中に別のリポジトリー（サブモジュール）があると、外の `.gitignore` も当てる。(7) 迷ったら隠すので、Git が見せるものも隠すことがある（上の、たたんだときに当たる名前）。(8) 秘密を、無視の規則に入れていないファイル（追跡している `config.json` の中のトークンなど）は、守れない。**無視の規則は、秘密を守る仕組みではなく、出さないものを減らす目安である。**
- 数の上限：同時のマウントは、端末ごとに 8、受け側の機械で 16（シェルとは別に数える。エージェントの同時接続の上限 64 の内側）。シェル（16）、転送（32）、マウント（16）を合わせると 64 になり、入力や問いの場所がなくなるので、この 3 つを合わせて 48（64 の 4 分の 3）までにした（2026-11-20、見直しのあと）。1 つの接続で配る番号は 100,000 まで。そこに達したら、古いほうから 1 割を手放す（その番号は `stale` になり、見る側は名前から引き直す。番号は二度と使わない）。問いの JSON は 64 KiB まで（超えたら切る）。60 秒何も届かない相手は切る（接続側は 10 秒おきに `alive`）。受け側で待てる問いは 2 つまでで、答えを読まずに問いを送り続ける相手は、接続そのものが止める。1 つの答えを送るのに 5 秒より長くかかったら、接続を切る（ソケットの書き込みの期限は、少しでも進むと数え直すので、見張りを別に置いた）。終わるときは、待っている読み手も、問いを渡そうとしている読み手も、必ず止まる。
- 一覧は、フォルダーごとに覚え、フォルダーが変わったとき（装置、i ノード、時刻、大きさ）だけ読み直す。問いのたびの綴りの確かめも、ページも、これを使う。
- 記録：開いたとき、終わったときに 1 行ずつ。端末の名前、フォルダーの ID、続いた時間、問いの数、読んだバイト数、終わり方。**パス、ファイルの名前、中身は書かない。**

#### 見る側（Mac）で、何をするか

- 試作のプログラム（`research/unified-mount-proto`。製品のワークスペースの外）：`unified-mount-proto mount <端末> <フォルダーの ID>`。相手に `mount_open` を頼み、開いたら、127.0.0.1 の空いたポートで読むだけの NFSv3 のサーバー（`nfsserve`、BSD-3）を開き、OS の `mount_nfs` で、`~/Istesso/<端末の名前>/<フォルダーの ID>` にマウントする（`vers=3,tcp,rdonly,nobrowse,nolocks,soft`）。`~/Istesso` と、その下の端末のフォルダーは、持ち主だけが入れる権限（0700）で作る。すでにあって、0700 でなければ断る。
- **マウントの場所に、前の実行が残したマウントがあれば、相手に何かを尋ねる前に外す**（場所は、ペアリングの一覧の端末の名前から決める。相手に届かなくても外す）。外し方は、力ずくでない unmount(2) だけで、手元のプログラムが使っていれば、そう言って、マウントしない（2026-11-20、二度目の見直しのあと。自分のものと見分けられない、生きているマウントを抜かないため）。相手のいなくなった残りが使われたままのときは、持ち主が `umount -f` で外す。
- **見張りのプロセス**：マウントするプログラムは、同じプログラムを「見張り」として、別のセッション（端末の信号が届かない）で起動し、パイプの読む側を渡す。書く側は、マウントするプログラムだけが持つ。マウントするプログラムが、どう終わっても（SIGKILL、落ちたときも）、パイプが閉じ、見張りが、残ったマウントを外す（30 秒まで、やり直す）。launchd の仕事にしなかったのは、持ち主の `LaunchAgents` にファイルを置くことになるからである。見張りそのものを SIGKILL されたら、働かない。
- **信号は、`mount_nfs` を動かす前から受け取る**。マウントの途中に来た信号には、マウントが済んでから、外して答える。
- **マウントしたまま終わらない**（2026-11-20、見直しのあと）。マウントされているかは、カーネルのマウントの表（`getfsstat`、`MNT_NOWAIT`。ファイルのサーバーに聞かない）で見る。読めなければ「マウントされている」とみなす。SIGINT、SIGTERM、SIGHUP、SIGQUIT、外からの取り外し、`mount_nfs` の失敗、パニックのどれでも、外す（使われていて外れなければ力ずくで）。外れるまで 1 秒おきにやり直し、そのあいだポートを持ち続ける。終わったあとにマウントが残ると、空いたポートを別のプロセスが取り、カーネルが、そのプロセスにこのフォルダーのファイルを尋ねるからである（見直しで見つかった）。SIGKILL は受け取れないので、そのときは残る。次に同じ場所で動かしたとき、マウントの場所を見る前に、残ったマウントを外す。
- **相手の答えを、カーネルに渡す前に確かめる**：一覧の名前は 1 つの項目の名前（`/`、NUL、`.`、`..` なし、255 バイトまで）、番号は 0、根、そのフォルダー自身でないこと（違うものは捨てる。同じ名前の 2 つめも）。`lookup` の番号も同じ。読んだ量は、頼んだ量を超えないこと。リンクの文字は 1024 バイトまで、NUL なし。
- **`nfsserve` に、ローカルの相手が言うままに確保させない**（2026-11-20、見直しのあと）。`nfsserve` 0.11.0 は、相手が告げた大きさ（記録の断片は 2 GiB まで、中のバイト列やリストは 4 GiB まで）を、読む前に確保し、接続と呼び出しの数にも上限がなかった。試作のワークスペースに写し（`vendor/nfsserve`、BSD-3、もとの LICENSE と README を添えて。`publish = false`。[部品の採否](../components.md)に載せた）、手を入れた（「Istesso patch」の印）：1 つの呼び出しの記録は 256 KiB まで（確保する前に断る）、その中のバイト列とリストも記録より長くできない、同時の接続は 8（それより後は、すぐ閉じる）、5 秒のうちに扱える呼び出しを 1 つも送らない接続は閉じる（何も送らない接続で、場所を埋められないように）、1 つの接続で同時に答える呼び出しは 16、呼び出しの読み手が止まった接続は終える、受け付ける前に去った相手で受け付けが止まらない（もとは `peer_addr` で落ちた）。配る前に、BSD-3 の文面を `third-party-licenses/` に置く。
- 見る側は、札を 250,000 まで覚え、それを超えたら古いほうから 1 割を忘れる（フォルダーそのものの札は忘れない）。形の合う札で、番号を知らないものには `STALE` と答え（カーネルが名前から引き直す）、乱数が合わないものは `BADHANDLE`。
- 相手の答えが途絶えたら（接続が切れた、`alive` に答えない）、そのあとの読み込みは、すぐに「入出力の誤り」（EIO）になる。固まらない。つなぎ直しはしない（試作。番号が接続ごとなので、つなぎ直すと、開いていたファイルは `stale` になる）。マウントを外して、もう一度動かす。
- **手元だけの NFS には、マウントの相手の確かめがない**（調査の 5.1。ADR 0025 の 1.5 の「穴」）。見る側の機械のどのプロセスも、127.0.0.1 のポートにつなげる。試作は、ADR 0025 が挙げた 2 つの手当てと、もう 1 つを入れる：
  1. **マウントの頼み（MOUNT の MNT）は、最初の 1 回だけ受ける。** 2 回目からは「ない」（`MNT3ERR_NOENT`）と答える。
  2. **ファイルを指す札（NFS のファイルハンドル）を、当てられない値にする。** 札は、番号と、その番号ごとに作る 16 バイトの乱数（OS の乱数）。知らない札、乱数の合わない札は `BADHANDLE`。
  3. **自分の `mount_nfs` が成功するまでは、中身を答えない。** 根の属性（OS のマウントが聞く）だけを答え、`lookup`、`read_dir`、`read`、`read_link` は、断る（`ACCES`）。1 で先に MNT を取った者がいれば、自分の `mount_nfs` は失敗し、プログラムは中身を一度も答えずに終わる。
- 何を止めて、何を止めないかは、下の「確かめ」に、見たことを書く。

#### 確かめ（2026-11-19、試作。見たことと、考えたことを分ける）

見る側は Air、フォルダーの持ち主は Ubuntu のホスト（有線）。試しの身元とペアリングの一覧は、両方の機械の、それぞれの自分のフォルダーに作り、本物の手順（`istesso pair host`、`pair join`）でペアにした。ホストのエージェントは、この流れのポート（26870）、有線のアドレスだけで待ち、発見なし、問い合わせなし。マウント先は、Air の自分のフォルダーの下（`--base`）。

実機で見たこと：

- マウントまで 0.03 秒（プログラムの中で計った。そのうち `mount_open` まで 0.005 秒）。起動から一覧が返るまで 0.05〜0.07 秒（3 回）。作り直した直後の 1 回目だけ 0.53 秒だった。`mount` の表示は `nfs, nodev, nosuid, read-only, nobrowse`。マウント先の上の 2 つのフォルダーは `drwx------`。
- 一覧（名前、大きさ、リンクの行き先）と中身が見えた。3 MB のファイルを 0.26 秒で読み、SHA-256 がホストの `sha256sum` と一致した。`rsize` は 1 MiB になった（`nfsstat -m`）。大文字と小文字だけが違う 2 つのファイルが、別々に見えた。
- `.env`、`target`（と、その中）、`.git`（と `.git/config`）は、一覧になく、名指ししても「ない」。`.ENV`、`.GIT/config`、`.Env` も「ない」。
- 書く操作（`touch`、上書き、`mkdir`、`rm`、`mv`、`xattr -w`）は、どれも「Read-only file system」。ホストのフォルダーは変わらなかった。
- 手当ての確かめ。マウントのあと、Air の別のプロセス（自分で書いた小さな RPC の道具。マウントしない）がポートにつないだ：`EXPORT` は `/` を答えた。MNT は断られた（`MNT3ERR_NOENT`）。作った札（番号 1 と乱数、ライブラリーのもとの形、乱数 24 バイト、空）は、`GETATTR` も `READDIR` も `BADHANDLE`。**先取り**：プログラムに、ポートを開いてから 3 秒待たせ（試しのためだけのスイッチ）、そのあいだに別のプロセスが MNT をした。根の札を受け取り、`GETATTR` は通った（根の属性は見えた）。`READDIR` と `LOOKUP` は `ACCES` で、名前は 1 つも出なかった。自分の `mount_nfs` は失敗し、プログラムは止まった。止まったあと、その札でつなぐと、つなぎが断られた。
- ホストのエージェントを止めると、Air で、まだ読んでいなかった `ls src`、`cat src/main.rs` は、0.05〜0.06 秒で「Input/output error」。固まらなかった。読み込んだばかりの根の一覧は、NFS のクライアントの覚え（`actimeo=2`）から出た。
- SIGTERM で外れ、プログラムは終わり、`mount` に残らなかった。
- テスト（`cargo test`）は Air と Ubuntu で通り、`cargo clippy -D warnings` と `cargo fmt` も通った。`cargo deny check licenses` は、製品のワークスペースと試作のワークスペースの両方で、Ubuntu で通った。
- Air の `/dev/bpf*` は、root だけが開ける（`crw-------`）。

考えたこと（確かめていない）：

- 手当ては、**ほかのユーザー**と、**マウント先を読めないが、ループバックにはつなげるプログラム**（囲いの中のエージェントなど）に対してだけ意味がある。同じユーザーのふつうのプログラムは、マウントそのものを読める。
- 札を手に入れる残りの道は、ループバックの盗み見（root、またはこの Mac で `/dev/bpf*` を開けるように変えた者）と、カーネルやこのプロセスの記憶を読むこと。
- 止めないもの：ポートへの接続、NFS の手続きの送りつけ（`nfsserve` の、読み解きの不具合は、認証の前に届く）、つなぎの使い切り、先取りでマウントを失敗させること（妨げ。気づける）、根の属性（大きさ、時刻、権限）を先取りで見ること。
- 1 回目の 0.53 秒の理由は、分かっていない。

#### 守りの限り（分かっていること）

- **見る側の、同じユーザーのすべてのプログラム**は、マウントを通して読める（マウントの形からして。調査の 5.2）。ADR 0021 の線の 2 の例外になる。【問い】受け入れるか（調査の問い 2）。
- **見る側の、ほかのユーザー**：マウント先の親は 0700 なので、マウントを通しては読めない（考え）。ポートには、つなげる。上の 3 つの手当てで、札を手に入れる道は、MNT（最初の 1 回は自分のもの）と、ループバックの盗み見（root か、`/dev/bpf*` を読める者）と、カーネルやこのプロセスの記憶を読むこと（root）だけになる、と考える。ポートにつなぐこと、NFS の手続き（`NULL`、`EXPORT`、壊れた頼み）を送ること、つなぎを使い切ることは、止めない。`EXPORT` は、出しているパス（`/`）を、誰にでも答える。
- **相手の確かめは、機械のあいだだけ**（Noise とペアリング）。見る側の手元の NFS の段には、ない。手当ては、それを補う「目安」で、確かめた範囲（下）を超えては、守りに数えない。
- **接続側の鍵**：見る側の同じユーザーのどのプログラムも、試作のプログラムを起動して（鍵のファイルを読んで）、許されたフォルダーをマウントできる。シェルの節と同じ穴である。
- 受け側では、エージェントのユーザーが読めるものは、名指ししたフォルダーの中で、Git の無視の規則に当たらないかぎり、見える。ハードリンクは、パスでは見分けられない（調査の 5.4）。
- リンクは、見る側で解決される（調査の 5.4。見る側の機械の、別のファイルを指すことがある）。ADR 0025 の 1.5 のおすすめ 6（外を指すリンクを「開けない項目」として見せる）は、試作には入れていない。
- 中身は暗号化されるが、読んだ量と時刻は、ネットワークの上で見える。
- 見直し（2026-11-20、別のモデル）で直したことは、上のそれぞれに書いた。残る限り：マウントするプログラムが終わってから、見張りが外すまで（ふつうは 1 秒より短い）と、見張りも殺されたときは、マウントが残り、空いたポートを取ったプロセスが、そのマウントに偽の中身を見せられる。中身を盗むことはできない（札はそのプロセスのものではない）が、**偽の中身を、ビルドの道具やコーディングエージェントが読めば、それはこのユーザーとして動くコードになりうる**（スクリプト、設定、依存の定め）。守りとして軽くは扱えない。`ls -l` のように、項目ごとに属性を聞く使い方は遅い（3 万項目のフォルダーで 39 秒。1 問いに往復 1 回）。`nfsserve` の手を入れていないところ（記録の中の読み解き）は、まだローカルの誰にでも届く。

#### 見直しのあとの確かめ（2026-11-20）

実機で見たこと（見る側は Air、持ち主は Ubuntu のホスト。前と同じ置き方）：

- ホストのエージェントを止めたあと 6 秒、プログラムは動き続け、マウントは表に残った（読み込みは EIO）。SIGTERM でも SIGHUP でも、外れて終わり、表に残らなかった。マウントの中に作業フォルダーを置いたプロセスがあっても、SIGTERM で外れた。
- SIGKILL のあと、マウントは表に残った。同じ場所でもう一度動かすと、「残ったマウントを外す」と言って外し、マウントし直した（一覧まで 2.0 秒）。

- フォルダーの中のマウントの場所（Air の上で、マウントの上のフォルダーを `Export` で直接開いた）は、`lookup` が「ない」、一覧は 0 件だった。

### メインのエディターで開く頼み（`istesso-edit`、シェルの枠 `0x07` open_window）【提案】（2026-11-20）

この節は【提案】で、決めるのは持ち主である。試作（ブランチ `proto-main-editor`。`proto-port-forward` の上）だけにあり、試用版と `main` には入れない。設計の元は ADR 0025 の 3.1（持ち主の決め 6、形 A。`design-workspace-stage` ブランチ）。2026-11-20 の夜に、別の目（Fable）が守りの面から見直した。判定は「持ち主の試し（試しの身元、端末 1 つ、試しのフォルダー）には、よい。`main` には、直してから」。指摘の 5 つと、小さな指摘を、同じ夜に直した（下の「見直しで直したこと」）。

ねらい：持ち主の決め（2026-11-20 の 6）「メインのエディターは、形 A」。ファイルを開くと、そのファイルがある機械でエディターが立ち上がり、窓が、映像の道で手元に出る。持ち主は、どの機械のファイルかを意識しない。この試作では、ADR 0025 の 3.1 の入口 2（ターミナルから開く）だけを作る：`istesso shell` で開いたシェルの中で `istesso-edit <ファイル>` と打つと、開発の機械（Ubuntu）が、自分の設定のエディター（GNOME Text Editor）を、映像の道の合成の係（コンポジター）の中で始め、その窓の映像を、シェルをつないでいる端末（Air）へ出す。

足すのは、次の 3 つだけである。

1. 開発の機械の中の頼みの口（URL を開く頼みと同じ `open.sock`）に、2 つめの頼みの形「このファイルを、メインのエディターで開いて」。
2. `shell_open` に、任意の項目 `windows`（真偽）。
3. シェルの枠に、`0x07` open_window。

映像と入力の道は、変えない。窓の映像は、いまの映像の道（ADR 0015）の接続で、入力は、いまの入力の接続で運ぶ。

#### 頼みの口（開発の機械の中）

- `istesso-edit <ファイル>`：`istesso` を、別の名前で起動したもの。`istesso-open` と同じ、持ち主だけが入れるフォルダー（0700）の `bin` に置く。シェルの `PATH` の先に、そのフォルダーがある（URL の頼みと同じ）。`EDITOR` と `VISUAL` は、入れない（ADR 0025 の 3.1。`git commit` などは、終わるまで待つエディターを当てにしている）。
- `istesso-edit` は、引数 1 つを、自分の今いるフォルダーにつないで、絶対の場所にする。それより先の確かめは、しない（確かめるのは、エージェントである）。
- 頼みは、`open.sock` に 1 行：`file <絶対の場所>`。これまでの頼み（URL の 1 行）は、そのまま。URL は `file ` で始まらないので、取り違えない。
- 答えは、これまでと同じ 1 行：`ok`、または `refused: <理由>`。

#### だれが頼めるか

- URL の頼みと同じ：つないできたプロセスの番号とユーザーを、OS に聞く（`SO_PEERCRED`）。同じユーザーで、**開いているシェルの作業場の中のプロセス**のときだけ。作業場の数え方（スコープ、なければセッション）は、上の「作業場」のとおり。
- そのシェルの端末が、`shell_open` で `windows: true` と言ったときだけ。言わない端末（古い版、`--no-windows`）のシェルからの頼みは、断る。試作では、`windows` は `forward` と一緒のときだけ効く（作業場を作るのが、`forward` のときだけのため）。
- 頼みの数は、作業場ごとに 5 秒に 5 回まで。URL の頼みとは、別に数える。エディターは、開発の機械で、同時に 1 つ（試作）。**エディターは、頼んだシェル 1 つのもの**：同じシェルからの 2 つめからのファイルは、動いているエディターに渡る（同じ窓の、新しいタブ）。ほかのシェルから頼まれたら、前のシェルに警告せずにエディターを終え、そのあと、新しいエディターを始める。前のシェルで開いたものを次の端末に見せないため、試作ではこうする。**保存していない文字は、エディターからは失われる**（次のエディターに戻らない）。**ただし、エディターが書いた下書き（変更したファイルの全文）は、その回のフォルダーに残る**（下の「守りの限り」）。
- シェルを開く権利（`--allow-shell` と「操作」）は、シェルの接続が、開いているあいだ 1 秒おきに確かめている。外されたら、シェルが終わり、作業場も終わるので、頼めなくなる。**頼んだシェルが終わったら（終えた、端末が去った、権利を外された）、エージェントは、そのエディター、合成の係、入力のエージェントを終える。** エージェントが終わったときも、起動の係の見張りが、2 秒おきに見て、終える。

#### どの場所か：作業場のフォルダーの中だけ

- **作業場のフォルダー**は、`shell_open` の `project` で開いたフォルダーである（シェルを開いたときに、本当の場所に直して覚える）。`project` なしで開いたシェルからの頼みは、断る。`project` が `/`、ユーザーのホームのフォルダーそのもの、またはその上のフォルダー（`/home` など）なら、断る（「中だけ」が、意味をなさないため）。
- 頼みの場所は、厳しく読む：絶対の場所。UTF-8。制御文字がない。4096 バイトまで。`..` を含まない（`.` は読み飛ばす）。作業場のフォルダーの下にあること（名前の区切りで比べる。`/a/bc` は `/a/b` の下ではない）。作業場のフォルダーそのものは、開かない。
- **ルートから、名前 1 つずつ、リンクをたどらずに確かめる**（`openat` に `O_NOFOLLOW` と `O_DIRECTORY`。作業場のフォルダーそのものの名前も、ルートから 1 つずつ見る。シェルを開いたあとに、作業場のフォルダーやその上がリンクに替えられていれば、断る）。途中は、どれもフォルダーで、シンボリックリンクでないこと。最後の名前は、ふつうのファイルで、リンクの数が 1 つ（ハードリンクで、作業場の外のファイルを指していないこと）。まだないファイルの名前は、受ける（エディターが、保存のときに作る。その前のフォルダーは、上の確かめを通ること）。フォルダー、装置、FIFO、ソケット、シンボリックリンクは、断る。
- 作業場の外を指すものは、どの形でも断る。

#### エディターを決めるのは、開発の機械の設定だけ

- **頼みが運ぶのは、場所 1 つだけ**。プログラムの名前、引数、環境変数、エディターの種類は、運ばない。受け取らない。
- どのエディターを、どう始めるかは、開発の機械の持ち主が、エージェントを始めるときに決める：`istesso agent --main-editor <起動の係のプログラム>`（絶対の場所の、実行できるファイル。始めるときに確かめる）。入れないときは、頼みを断る（「この機械には、メインのエディターがない」）。
  - ADR 0025 の 3.1 は、設定の値を、アプリの一覧（`istesso-catalog`）の ID にする案である。試作は、ADR 0010 の起動の口に乗らず、エージェントの起動の引数に、起動の係のプログラムを書く。どちらも、頼む側からは、変えられない。
- 起動の係に渡す場所は、**頼む側の文字ではなく、エージェントが、作業場のフォルダーと、確かめた名前から、自分で組み立てた場所**である。**引数ではなく、環境変数**（`EDITOR_WINDOW_PLACE`）で渡す。引数は、同じ機械のどのプログラムからも見える（`ps`）。起動の係への引数は、`open` か `stop` の 1 語だけ。シェルは、通さない。頼んだシェルの端末（ホストのペアリングの一覧の ID と公開鍵）も、環境変数で渡す。
- 起動の係は、映像の道の合成の係と符号化の係（ポート 1 つ）、入力を受けるエージェント（ポート 1 つ）、合成の係の中のエディターを始める。**どちらのポートも、ホストの設定の 1 つのアドレス（有線のアドレス）だけで待つ**（`EDITOR_WINDOW_BIND`）。**映像は、頼んだ端末だけに見せる**（映像の係の `admit`。始めは、だれにも見せない）。**入力のエージェントは、頼んだ端末だけを知る**（その端末だけを書いた、ペアリングの一覧。ホストの身元の鍵は、写さずにリンクする）。エディターは、**始めるたびに新しい**、自分だけのフォルダー（`XDG_*`。設定、データ、状態、キャッシュ）と、自分だけのセッションのバスで動く（ユーザーの実行時のフォルダーの下。前の回のタブや下書きは、戻らない。持ち主のエディターの状態に、触らない）。エディターは、ファイルなしで始め、ファイルは、エディター自身のバスで渡す（GApplication の open。場所は、ここでも引数にならない）。窓ができたら、標準出力に 1 行 `window <映像のポート> <入力のポート>` を書いて、終わる。同じ端末のエディターが動いていれば、起動時に記録したエージェントのプロセス番号と開始時刻を確かめる。今のエージェントと一致したときだけ、そのエディターにファイルを渡し、同じ 1 行を書く。エディターにファイルを渡せなかったときは、答えの `fail` の行に、理由と、見る記録の名前を書く（`run/bus.log`：エディターのセッションのバスの出力。次の起動まで残す。ファイルの名前は出ない。`run/app.log`：エディター自身の出力。ファイルの名前が出うるので、`EDITOR_WINDOW_APP_LOG=1` のときだけ残す）。たとえば、バスのソケットの場所が長すぎてバスが始まらないと、「バスが始まらなかった（`run/bus.log` を見る）」と答える。30 秒で答えなければ、エージェントは、起動の係のプロセスのまとまりを止め、起動の係に `stop` を頼んで、断る。
- 計測の合図が `busy` のあいだは、起動の係は、何も始めない。始めたあとに `busy` になったら、その窓のもの（合成の係、エージェント、エディター）を、数秒で止める（2 秒おきに合図を読み、終わるように言い、2 秒たっても残るものは止める。下の「確かめ」）。

#### 何を記録するか

- 受け側：頼みを受けた・断った、と、断った理由の種類。窓の映像のポート。起動の係が答えるまでの時間。
- エージェントと起動の係は、頼みの記録にファイルの場所や名前を書かない（作業場の中の相対の場所も）。エディター自身は、開いたファイルの場所と名前を、その回のフォルダーのセッションと最近使ったファイルの一覧に書く（下の「守りの限り」）。エディターの出力も、設定で残すと（`EDITOR_WINDOW_APP_LOG=1`）、ファイルの名前を含むことがある。エディターのバスの出力（`run/bus.log`）は、次の起動まで残す（ファイルの名前は出ない）。
- 接続側：知らせの行に、ポートの番号と、表示の名前だけ。

#### 守りの限り（分かっていること。はっきり書く）

- **作業場の見分けは、守りではない**（上の「作業場」と同じ）。同じユーザーのプログラムは、作業場のスコープに入って、頼みを出せる。
- **確かめてから、エディターが開くまでのあいだに、入れ替えられる。** 作業場の中のプログラムが、確かめたフォルダーを、作業場の外へのシンボリックリンクに、すばやく替えると、エディターは、外のファイルを開く（確かめた時と、使う時のずれ）。ただし、それができるプログラムは、もともと同じユーザーなので、そのファイルを、自分で書ける（同じユーザーの線。ADR 0021）。この頼みで、新しく得るのは、「Air の画面に、窓を出す」ことだけである。確かめは、まちがいと、競わない頼みを止める。競うプログラムは、止めない。
- **エディターは、エージェントと同じユーザーで動く**（いまは、持ち主のユーザーそのもの）。エディターが、プロジェクトの中のものを動かす種類（タスク、拡張機能）なら、そのユーザーの力で動く。GNOME Text Editor は、動かさない見込み（推測）。
- **初めの窓は、手元の画面の前に出て、キーを取る。** 押してから開く形（ADR 0025 の 3.1 の入口 3）は、試作にない。上限は、5 秒に 5 回と、エディター 1 つだけ。2 つめからのファイルでは、窓を前に出さない。**シェルの中のプログラム（コーディングエージェントなど）が頼んだ初めの窓も、前に出て、キーを取る**（題名と知らせの行で、プログラムが頼んだと分かるだけ。下）。持ち主がターミナルで打っている途中なら、その字が、エディターに入りうる。
- **映像と入力のポートは、ホストの有線のアドレスで待つので、その LAN の機械からは届く。** 通るのは、頼んだ端末だけである（映像は `admit`、入力は、その端末だけの一覧。通信路のハンドシェイクで確かめる）。
- **エディターの中からは、持ち主のユーザーのどのファイルも開ける。** エディター自身の「開く」（Control-O。ポータルを使わない、エディターの中の窓）で、作業場の外のファイルを選べる。頼みの確かめは、`istesso-edit` で渡す場所だけを絞る。窓を操作できる端末は、もともと、そのユーザーのシェルを開ける端末なので、新しい力ではない（同じユーザーの線）。だから、エディターの命を、頼んだシェルに結んだ（上）。
- **始めるたびの新しいフォルダーは、消さない。** このプロジェクトのスクリプトは、変数で組み立てた名前のフォルダーを、消さない（持ち主の決め）。ユーザーの実行時のフォルダーの下（持ち主だけが入れる、メモリーの上のフォルダー）に置き、ログアウトと再起動で、システムが消す。それまでは、エディターの下書き（打った文字）が残る。常時稼働のホストでは、ログアウトしないので、長く残りうる。
- **起動ごとのフォルダーには、ファイルの場所と名前、変更したファイルの全文が残る。保存していない文字は、エディターからは失われるが、下書きとしては、ここに残る。** セッション、最近使ったファイルの一覧、下書きがある（エディター自身の「開く」で選んだ、作業場の外のファイルも含む）。入力用の一覧には、頼んだ端末の ID、公開鍵、名前、権利が残る。ホストの身元の秘密鍵は写さない（鍵の置き場所を指すシンボリックリンクが残る）。
- 起動の係は、エージェントの環境で動く。頼みが決めるのは、確かめた場所 1 つだけである。
- 制御文字のある名前や、UTF-8 でない名前のファイルは、開けない（断る）。
- 窓の題名には、エディターが、ファイルの名前を出す。これは、映像の中身で、記録ではない。

| `xdg-open` のほかのもの（絵、PDF、フォルダー、ほかの機械の `file:`、`mailto:` など） | 受けない（これまでどおり） | 後ろの本物の `xdg-open` に渡す。開くのは、開発の機械の上で、Air ではない |
| `EDITOR`、`VISUAL` | 受けない | これらを使うプログラム（`git commit`、`crontab -e`、エージェントの「エディターで書く」）は、エディターが閉じるまで待って、それからファイルを読む。`istesso-edit` は、窓を出したら、すぐ終わる。入れると、空の文で commit が止まるなど、こわれる（ADR 0025 の 3.1 と同じ）。待つ形（タブを閉じたら終わる `istesso-edit --wait`）には、エディターから「タブを閉じた」を知る道が要る。GNOME Text Editor の GApplication の口には、ない。あとで |
| `code <ファイル>` など、ほかのエディターの名前 | 受けない | 開発の機械に、本物の `code` があれば、その名前を奪う。`code` には、開く以外のスイッチが多い（`--install-extension`、`--diff`、`--wait`、`-r`）。「開く」だけを受けて、ほかを黙って変えると、まちがえる。エージェントに使わせたいときは、プロジェクトの `AGENTS.md` などに `istesso-edit` と書く |
| 出力に、場所を書くだけ | 受けない（この試作では） | 文字を読んで開くのは、Air の端末の側の仕事で、持ち主が押してから開く形（ADR 0025 の 3.1 の入口 3）になる。試作には、ない |

だれが頼んだかを、見えるようにする：

- エージェントは、頼んだプロセス（`SO_PEERCRED` の番号）が、**シェルそのものが、端末の前のジョブで始めたものか**を見る：親がシェルそのもので、プロセスのまとまりが、端末の前のまとまりと同じ（`/proc/<番号>/stat`）。プロンプトで打ったコマンドは、こちらになる。ただし、**プロンプトで打ったものだけではない**：プロンプトのたびに動く仕掛け（`PROMPT_COMMAND`、`precmd`）、シェルが読み込んだファイル、シェルの関数、`$(…)` から始まったものも、こちらになる。そうでなければ、「シェルの中のプログラムが頼んだ」とする（エージェントのコマンド、スクリプト。シェルの中の tmux の中で打ったものも、こちら）。Linux でないホストでは、見分けられないので、プログラムとする。
- 窓の枠 `0x07` の項目 `asked_by_program`（上の「メッセージ」）。この版の受け側は、いつも送る。前の版の端末は、知らない項目を読み飛ばす。項目のない枠（前の版の受け側）は、「分からない」とする。
- 端末の側（Air）：
  - プログラムが頼んだとき：知らせの行に「シェルの中のプログラムが頼んだ。シェルそのものではない」と書く（`asked by a program in the shell, not by the shell itself`）。窓の題名を `(from a program) ` で始める。窓を出すプログラムには、`ISTESSO_WINDOW_ASKED_BY=program` を渡す。
  - 分からないとき：知らせの行に「だれが頼んだかを言わないホスト」と書き（`from a host that does not say who asked`）、題名を `(asker unknown) ` で始め、`unknown` を渡す。
  - シェルそのもののとき：題名はそのまま。`shell` を渡す。
  - **題名の印は、窓を作るときだけ付く。** 窓が開いているときの 2 つめからのファイルは、開いている窓に渡るので、題名は変わらない（知らせの行だけが、だれが頼んだかを言う）。
  - **知らせの行は、シェルの端末に書く。頼んだプログラムも、同じ端末に書けるので、その行を消したり、まねたりできる。**
- ホストの記録：「シェルの前のジョブから」（`from the shell's foreground job`）か「プログラムが頼んだ」か。場所も名前も、書かない。
- **これは、守りではない。** 見せるためだけである。同じユーザーのプログラムは、シェルに打たせるなどして、シェルの前のジョブから頼んだように見せかけうる。上限（5 秒に 5 回、エディター 1 つ）と、作業場の確かめは、同じ。
- まだのこと：プログラムが頼んだ初めの窓を、前に出さない（キーを取らない）こと。試用版のビューアーに、その切り替えがない（上の「守りの限り」）。

### 発見とアドレスの記憶

- 各エージェントが mDNS（DNS-SD）で `_istesso._tcp` を広告し、他の広告を聞く。実装は `mdns-sd`。
- 広告は**アドレスの手がかり**としてだけ使う。広告は誰でも出せるので、何の証明にもならない。接続先が本物かどうかは、通信路のハンドシェイクだけが決める。
- 手がかりとして受け入れるのは、ペアリング済みの端末の指紋を名乗り、かつ自分が直接つながっているネットワーク上のアドレスだけ。
- 手がかりは他に、ペアリングのときに使ったアドレス、相手から接続が来たときの送信元、相手が役割表で申告したアドレス、`istesso peers address` での手動指定がある。最後に通じたアドレスを先頭に置き、複数あれば同時に試す。
- 応答しない端末は、最後に応答したときの役割表とアプリ一覧をキャッシュから表示する。エージェントは定期的に相手へ問い合わせて、この記憶を更新する。キャッシュは信頼の根拠にしない。

## 既知の不足（公開前に対応する）

- `snow` は第三者の監査を受けていない。ペアリング（ADR 0006）と合わせて外部レビューを受ける。
- 受け側の身元（公開鍵）は、接続してきた誰にでも見える。Noise XX の性質である。
- mDNS の広告に含まれる指紋は、同じネットワークの誰にでも見える固定の識別子になる。信頼できないネットワークでは `istesso agent --no-discovery` を使う。識別子を回す方式は未検討。
- IPv4 のみ。
- 同じネットワークからの大量接続への対策は、同時接続数の上限と、ハンドシェイク全体の期限だけ。期限は、読み書きのたびに数え直さない（2026-11-16 に直した。それまでは、待ち時間が読み込み 1 回ごとだったので、1 バイトずつ送る相手が、接続の枠を何十分も占められた）。接続を開き続ける相手は、そのあいだ、ほかの端末がつなぐのを妨げられる。これは受け入れている。
- 相手の待ち受けポートは、発見できたとき以外は既定値を仮定している。
- エージェントはまだ常駐サービスではない（手で `istesso agent` を起動する）。launchd / systemd への登録は M9。
- ペアリングは別のポート（47800）で、エージェントとは別に動く。エージェントへの統合と、ペアリング相手の自動発見・QR はこれから。
- 出先（VPN 越し）では発見が届かない。`istesso peers address` で指定する。
