# ADR 0018：自前のクライアント（Mac）

- 状態：提案（2026-11-17。設計のメモ。本線の見直しを受けながら進める）
- 日付：2026-11-17
- もとになる決まり：[ADR 0002](0002-latency-first.md)（関門の判定と確定の判定）、[ADR 0007](0007-control-channel.md)（入力、つなぎ直し）、[ADR 0015](0015-media-transport.md)（映像、カーソル、つなぎ直し）、[関門のあとの計画](../m1-final-verdict-plan.md) の 2、3、6

## 背景

関門の判定は、試作のビューアー（`macos/gst-viewer`）と、別のプログラムの入力の中継（`istesso input relay`）で通った。確定の判定は、自前のクライアントで測り直す。自前のクライアントは、この 2 つがしていることを、**1 つのアプリ、1 つのプロセス**で行う。

## 決めること

### 作り

| 部分 | 中身 | どこから来るか |
|---|---|---|
| アプリ（Objective-C、AppKit） | 窓、キーボードとポインターの受け取り、VideoToolbox での復号、層への表示、カーソルの層、切れたときの印 | 試作のビューアーから、**そのまま移す**（下の「変えないもの」）。GStreamer は、使わない |
| 中身のライブラリー（Rust、新しいクレート `istesso-client`、静的ライブラリー 1 つ） | 映像の接続（`istesso-media` の、つなぎ直す見る側）と、入力の接続（`istesso-agent` の `relay` の `InputLine`）を、C の口で出す | どちらも、関門を通ったコードを、そのまま呼ぶ。新しい外部の依存は、足さない |
| バンドル | `Istesso.app`。識別子、名前、実行ファイルの名前は、**1 つのファイル**（`macos/client/identity`）に置き、Info.plist と署名は、そこから作る | 新しく作る |

- 置き場所：`macos/client/`（アプリ）と `crates/istesso-client/`（ライブラリー）。試作のビューアーと `scripts/try.sh` は、新しいクライアントが計測で並ぶまで、変えずに残す。キーの決まり（`keys.h`）は、写さずに、同じファイルを使う。
- Objective-C のままにするわけ：復号と表示の通り道が、関門で測ったコードと同じになる。「並んだ」と言うための比べが、作り直しの違いに埋もれない。

### プロセスの中に入るもの

- **入力**：これまでは、ビューアーが、手元のソケットに 1 イベントずつ書き、別のプログラム（中継）が読んで、制御チャンネルに送っていた。これからは、アプリの中の入力のスレッドが、制御チャンネルの接続を持つ。メインのスレッドは、イベントを、プロセスの中の待ち行列に入れて、入力のスレッドを起こす。**プログラムをまたぐ受け渡しが、1 回減る。**
- 入力の接続の見守り（「まだここにいる」、沈黙の見分け、開き直し、修飾キーの押し直し）は、`InputLine` のまま。
- つなぎ直した回数は、映像も入力も、同じプロセスが持つ。窓の題と、フレームの記録に出す（中継の小さいファイルは、要らなくなる）。

### スレッドと優先度

既定は、**関門で測った形と同じ**にする。はじめの比べが、「1 つのプロセスにした」ことだけの違いになるように。

| スレッド | 仕事 | 既定 | 計測のための切り替え |
|---|---|---|---|
| メイン（AppKit） | 窓のイベント、キーとポインターの受け取り、カーソルの層、印と題 | AppKit のまま | — |
| 映像 | 接続から受け取る → VideoToolbox で復号（その場で）→ 層に渡して、すぐ出す。**復号と表示は、同じスレッド** | 指定なし（試作と同じ） | `picture-qos`：対話用のいちばん高い QoS。`picture-realtime`：音のスレッドと同じ、時間の決まった扱い（試作の `ISTESSO_RECEIVE_REALTIME`） |
| 入力 | 待ち行列を待つ → 封をして書く。0.1 秒に 1 回、接続を見る | 指定なし | `input-qos`：対話用のいちばん高い QoS |
| プロセス全体 | — | 何もしない | `latency-critical`：遅れに厳しい作業だと、OS に伝える（`NSProcessInfo` の `beginActivity`） |

- 切り替えは、起動の引数 `--wake <名前,名前,…>` で、1 つずつ入れられる。入っているものは、フレームの記録の先頭に書く（`{"kind":"wake",…}`）。**既定に入れるのは、測って効いたものだけ**（計画の 3）。
- メインのスレッドでは、接続に書かない。書き込みが待たされたときに、窓が固まるためである。

### 変えないもの（試作から、そのまま移す）

復号（Annex B の分け方、VideoToolbox のセッション、キーフレームの求め）、表示（復号器の面を、そのまま層に渡して、すぐ出す）、sRGB の指定、カーソルの層、キーの決まり（`keys.h`：Command を Control に、修飾キーを貸す、切れているあいだは「押した」を渡さない、戻ったら修飾キーを合わせ直す）、切れたときの印と数、全画面の形、**フレームの記録の形**（計測の道具が、そのまま読める）、入力の時刻の記録（`passed` の行）。

### この束で足すもの

- **決まった形のカーソルを、Mac のカーソルで出す。** カーソルの知らせは、画像の代わりに名前を運べる（ADR 0015）。クライアントは、名前（矢印、I 字、手、大きさを変える矢印）を、Mac のカーソルに置き換える。名前のないものは、これまでどおり、画像を描く。**ホストの側に要るもの**：コンポジターが、名前を伝えること（アプリが形を名前で言う口を開ける。画像しか渡さないアプリは、テーマの画像と突き合わせて名前にする）。ホストの流れと、受け持ちを決める。
- **閉じる、しまう**：赤いボタンは、ホストのアプリに「閉じてほしい」と頼み、窓は、ホストが「最後の窓が閉じた」と言うまで残す（アプリが「保存しますか」と尋ねたら、それが映る）。黄色いボタンは、窓をしまい、ホストに絵を止めてもらう。出したら、戻してもらう。**頼む口**は、アプリマネージャーのセッションのメッセージ（束の 5）。それが入るまでは、窓だけが閉じ、しまわれる。緑のボタンは、効かない（途中で大きさを変えることは、この束に入れない）。
- **大きさは、開くときに決める**（`--size`）。セッションを開くメッセージで、ホストに伝える。計測用のホストが相手のときは、ホストの絵の大きさに合わせる。
- **ホストが、変わらない絵を送り続けても、乱されない。** ふつうのフレームとして、復号して出す。沈黙の見分けには、届いたものとして数える。
- **色**：中継の窓に残っている 1〜3 レベルのずれを調べて、直す（ストリームの色の指定、復号した絵の指定、層の色の順に見る）。画面での測り直しは、本線に頼む。

### バンドルと署名

- 識別子の案は `com.maromoco.istesso`、名前は「Istesso」（持ち主が決めている途中）。**変えるのは 1 か所**で済むようにする。許可（ローカルネットワーク）は、識別子に付く。
- 署名できる形にする：識別子がバンドルの識別子と同じ、Info.plist が封の中、実行ファイルの名前が分かる（`Istesso`）、実行ファイルが自分のビルドの UUID を持つ。ビルドのスクリプトが、手元の署名（その場かぎり）を付ける。配布の署名は、同じスクリプトに、署名の名前を渡す（M9）。
- **新しいバンドルを、はじめて起動する時刻は、本線が決める。** Mac は、アプリが新しく登録されると、つながっている接続を切ることがある。

### ランチャー（あとで、このアプリに入る）との境目

アプリが持つもの：セッションを開く、つなぐ、窓を前に出す、「窓だけ閉じる」、アプリを終える。ランチャーの画面は、これを呼ぶだけにする。

| ランチャーが呼ぶ | アプリがすること |
|---|---|
| 開く（ホスト、アプリ、大きさ） | セッションを頼み、窓を作る |
| つなぐ（セッション） | 動いているセッションの窓を作る。もう窓があれば、前に出す |
| 窓だけ閉じる（セッション） | 窓を閉じて、離れる。ホストのアプリは、動き続ける |
| 閉じるよう頼む（セッション） | 赤いボタンと同じ |
| 終える | 全部の窓を「窓だけ閉じる」にして、終わる |

アプリが知らせるもの：セッションごとの状態（つないでいる、映している、つなぎ直している、終わった（わけ））、つなぎ直した回数。この束では、ランチャーはなく、起動の引数で、セッションを 1 つ開く。

## この束に入れないもの

途中で窓の大きさを変えること。ランチャーの画面。音。1 つのアプリの複数の窓を、別々の窓にすること。暗号化していない UDP の経路。設定の画面、自動の更新。Mac 以外のクライアント。

## 計測で確かめること（本線が測る）

1. **並ぶこと**：切り替えを全部切った自前のクライアントと、試作（ビューアーと中継を、アプリとして起動）を、同じ日に、同じ置き方で。差の 3 つの値と、区間ごとの値。入力の区間（キーを出してから、アプリに届くまで）が、短くなっているはず。
2. **切り替えを 1 つずつ**：`picture-qos`、`input-qos`、`latency-critical`、`picture-realtime`。前と後で。
3. 当てるテストは、カーソルと窓が変わるので、やり直す（計画の 2）。

## 既知の不足

- 閉じる、しまうがホストに届くのは、セッションのメッセージが入ってから（束の 5）。
- カーソルの名前は、ホストが伝えるようになってから効く。
- 自前のクライアントの中身は、試作と同じく、1 つのホスト、1 つのセッションを前提にしている。セッションを並べるのは、ランチャーと一緒に。
