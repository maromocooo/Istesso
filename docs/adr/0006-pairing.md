# ADR 0006：ペアリングの方式

- 状態：採用（公開前に外部レビューを受ける）
- 日付：2026-11-15

## 背景

端末同士のリンクは、簡単で、かつ安全でなければならない。この仕組みは入力の送信やアプリのインストールまでできるので、信頼の入口は最も慎重に作る。

## 決定

### 手順

1. ホスト側が8文字のコードを表示する（Crockford base32、40 ビット。`ABCD-EFGH` の形）。
2. 両者がそのコードで SPAKE2 を実行する。コードが同じときだけ同じ共有鍵になる。
3. 共有鍵から、方向ごとの鍵を HKDF で導く。
4. 各端末が、長期公開鍵（Ed25519）と、手順の写し（transcript）への署名を、方向ごとの鍵で暗号化して送る。
5. 受け取った側は、復号と署名の検証に成功したら、相手の公開鍵を固定して保存する。
6. 以後の接続は、固定した公開鍵で相互認証する。保存した記録を消すと失効する。

### 性質

| 脅威 | 対応 |
|---|---|
| 盗聴してコードを総当たりする | SPAKE2 は、盗聴した内容からオフラインで推測を試す手段を与えない |
| コードを知らずに割り込む | 共有鍵が一致せず、復号に失敗する |
| オンラインで何度も試す | 1つのコードで受け付けるのは1回だけ。失敗したらコードを作り直す。有効期限あり |
| 送ったメッセージを送り主に送り返す | 鍵が方向ごとに違うので復号できない。SPAKE2 のメッセージの反射も拒否する |
| 他人の公開鍵を自分のものとして登録する | 手順の写しへの署名で、秘密鍵を持っていることを証明させる |
| 別の回の署名を使い回す | 署名は、その回の手順の写しと役割に結び付いている |
| 表示名に制御文字などを入れる | 名前は長さと文字種を検査する |

### 権限

新しくペアリングした端末の権限は「閲覧」と「操作」だけ。インストール、USB、音は個別に許可する。

許可と取り消しは、許可を与える側の PC で、人が行う（`istesso peers allow <端末> <権限>`、`istesso peers deny <端末> <権限>`。`istesso peers list` で、いまの権限を見られる）。

- 書き換えるのは、その PC が保存している相手の記録だけである。相手の端末とは通信しない。ペアリングの手順（プロトコル）は変わらない。
- 相手を、指紋か名前で指定する。同じ名前の端末が複数あるときは、指紋で指定する。
- 変更は、遅くとも相手の次の接続から効く。接続が続いているあいだも記録を読み直すのは、いまは次の二つだけである。
  - 映像の送り出し（`istesso-media` のホスト）。0.25 秒ごとに「閲覧」を確かめ、なくなっていたら切る。
  - エージェントが入力を受け取る接続。1 秒ごとに「操作」と「閲覧」を確かめ、どちらかがなくなっていたら切る（「閲覧」を確かめるのは、2026-11-20 から）。
- エージェントのそのほかの問い合わせ（一覧など、「閲覧」で答えるもの）は、接続を受け付けたときに読んだ記録で答え続ける。そこでの「閲覧」の取り消しは、その端末の次の接続から効く。続いている接続のあいだにも読み直すのは、これからの課題である。
- 「閲覧」も取り消せる。取り消すと、その端末は何もできなくなる。ペアリングそのものを消す（`istesso peers remove`）のとは違い、記録は残る。
- 同じ端末をペアリングし直すと、記録は新しく作り直され、権限は初めの「閲覧」と「操作」に戻る。それまでに与えた権限や取り消した権限は引き継がない。
- 記録を書き換える処理（ペアリング、`peers allow`・`deny`・`remove`）は、記録のファイルの錠を取り、ファイルを読み直したうえで変えて書き戻す。`istesso pair host` が相手を待つあいだに `peers deny` で権限を取り消しても、ペアリングが済んだときに、その取り消しが元に戻ることはない。錠を取るのは、macOS と Linux（Unix）だけである。ほかの OS では錠がなく、書き戻す直前に読み直すだけなので、同時に書くと、あとから書いたほうが残る。

## 既知の不足（公開前に対応する）

- `spake2` クレートは第三者の監査を受けていない（作者が明記している）。外部レビューを受ける。
- 端末の秘密鍵を、所有者だけが読めるファイルに置いている。OS のキーチェーンへ移す。
  - 鍵とペアリングの一覧を置く設定のフォルダーは、ないときに作るとき、所有者だけのもの（0700）にする（2026-11-20）。すでにあるフォルダーは変えない。グループやほかの人が書き込めるときは、プロセスごとに 1 度、標準エラーに警告を出す（書き込める人は、一覧に自分の端末を足せる）。
- ペアリングの手順は平文の TCP の上を流れる（手順そのものが内容を守る）。ペアリング後の通信は ADR 0007 の制御チャンネルを使う。
- 最後の確認応答（`OK`）は認証していない。割り込まれると、片方だけが相手を保存した状態になり得る。相手の鍵の検証は済んでいるので安全性には影響しないが、認証つきの応答へ置き換える。
- ペアリング相手の自動発見と QR はまだない（ペアリング後のアドレスの発見は ADR 0007）。
- 出先からのペアリングは想定しない（VPN 越しの LAN 内だけ）。
