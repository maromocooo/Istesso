# ADR 0006：ペアリングの方式

- 状態：採用（公開前に外部レビューを受ける）
- 日付：2026-11-15

## 背景

端末同士のリンクは、簡単で、かつ安全でなければならない。この仕組みは入力の送信やアプリのインストールまでできるので、信頼の入口は最も慎重に作る。

## 決定

### 手順

1. ホスト側が8文字のコードを表示する（Crockford base32、40 ビット。`ABCD-EFGH` の形）。
2. 両者がそのコードで SPAKE2 を実行する。コードが同じときだけ同じ共有鍵になる。
3. 共有鍵から、方向ごとの鍵を HKDF で導く。
4. 各端末が、長期公開鍵（Ed25519）と、手順の写し（transcript）への署名を、方向ごとの鍵で暗号化して送る。
5. 受け取った側は、復号と署名の検証に成功したら、相手の公開鍵を固定して保存する。
6. 以後の接続は、固定した公開鍵で相互認証する。保存した記録を消すと失効する。

### 性質

| 脅威 | 対応 |
|---|---|
| 盗聴してコードを総当たりする | SPAKE2 は、盗聴した内容からオフラインで推測を試す手段を与えない |
| コードを知らずに割り込む | 共有鍵が一致せず、復号に失敗する |
| オンラインで何度も試す | 1つのコードで受け付けるのは1回だけ。失敗したらコードを作り直す。有効期限あり |
| 送ったメッセージを送り主に送り返す | 鍵が方向ごとに違うので復号できない。SPAKE2 のメッセージの反射も拒否する |
| 他人の公開鍵を自分のものとして登録する | 手順の写しへの署名で、秘密鍵を持っていることを証明させる |
| 別の回の署名を使い回す | 署名は、その回の手順の写しと役割に結び付いている |
| 表示名に制御文字などを入れる | 名前は長さと文字種を検査する |

### 権限

新しくペアリングした端末の権限は「閲覧」と「操作」だけ。インストール、USB、音は個別に許可する。

許可と取り消しは、許可を与える側の PC で、人が行う（`istesso peers allow <端末> <権限>`、`istesso peers deny <端末> <権限>`。`istesso peers list` で、いまの権限を見られる）。

- 書き換えるのは、その PC が保存している相手の記録だけである。相手の端末とは通信しない。ペアリングの手順（プロトコル）は変わらない。
- 相手を、指紋か名前で指定する。同じ名前の端末が複数あるときは、指紋で指定する。
- 変更は、遅くとも相手の次の接続から効く。接続が続いているあいだも記録を読み直すのは、いまは次の二つだけである。
  - 映像の送り出し（`istesso-media` のホスト）。0.25 秒ごとに「閲覧」を確かめ、なくなっていたら切る。
  - エージェントが入力を受け取る接続。1 秒ごとに「操作」を確かめ、なくなっていたら切る。
- エージェントのそのほかの問い合わせ（一覧など、「閲覧」で答えるもの）は、接続を受け付けたときに読んだ記録で答え続ける。そこでの「閲覧」の取り消しは、その端末の次の接続から効く。続いている接続のあいだにも読み直すのは、これからの課題である。
- 「閲覧」も取り消せる。取り消すと、その端末は何もできなくなる。ペアリングそのものを消す（`istesso peers remove`）のとは違い、記録は残る。
- 同じ端末をペアリングし直すと、記録は新しく作り直され、権限は初めの「閲覧」と「操作」に戻る。それまでに与えた権限や取り消した権限は引き継がない。
- 記録を書き換える処理（ペアリング、`peers allow`・`deny`・`remove`）は、記録のファイルの錠を取り、ファイルを読み直したうえで変えて書き戻す。`istesso pair host` が相手を待つあいだに `peers deny` で権限を取り消しても、ペアリングが済んだときに、その取り消しが元に戻ることはない。錠を取るのは、macOS と Linux（Unix）だけである。ほかの OS では錠がなく、書き戻す直前に読み直すだけなので、同時に書くと、あとから書いたほうが残る。

## 既知の不足（公開前に対応する）

- `spake2` クレートは第三者の監査を受けていない（作者が明記している）。外部レビューを受ける。
- 端末の秘密鍵を、所有者だけが読めるファイルに置いている。OS のキーチェーンへ移す。
- ペアリングの手順は平文の TCP の上を流れる（手順そのものが内容を守る）。ペアリング後の通信は ADR 0007 の制御チャンネルを使う。
- 最後の確認応答（`OK`）は認証していない。割り込まれると、片方だけが相手を保存した状態になり得る。相手の鍵の検証は済んでいるので安全性には影響しないが、認証つきの応答へ置き換える。
- ペアリング相手の自動発見と QR はまだない（ペアリング後のアドレスの発見は ADR 0007）。
- 出先からのペアリングは想定しない（VPN 越しの LAN 内だけ）。

## 写しを見つける（層 1）との関わり（【提案】、2026-11-21）

【提案】ペアリングのときに、2 台だけが持つ最初の合言葉を作る。
理由と、つなぐたびに合言葉を進める手順は、[ADR 0021 の「鍵の守りの 4 つの層」](0021-isolation-and-settings.md#鍵の守りの-4-つの層配272026-11-21) にある。

### 最初の合言葉

- 版を `istesso-pair-v1` から `istesso-pair-v2` に上げる。両方が合言葉を作って保存する必要がある。層 2 の調べで提案された P-256 の身元の鍵も、この 1 回の版上げにまとめる。v1 と v2 は混在させない。
- 方向ごとの鍵に使っている HKDF-SHA256 から、もう 1 つ値を取り出す。salt はペアリングの文脈（`istesso-pair-v2`）、入力は SPAKE2 の共有秘密である。
- Expand の info は、`istesso-pair-v2 pair-state seed` のバイト列に、手順の写しのハッシュをつないだもの。初めの合言葉 S_0 として 32 バイト取り出す。回数は 0。
- ペアリングのメッセージは増えない。相手の身元を確かめ、ペアリングが済んだときに、両方が相手用の新しい `pair_state` に S_0 と回数 0 を保存する。

### 相手の記録

両方の機械で、ペアの一覧とは別に、相手ごとに `pair_state` を 1 項目持つ。合言葉と `stopped` はこの項目に置く。
2 台の身元の公開鍵（いまは Ed25519）を先頭から 1 バイトずつ比べる。小さいほうが進める側、もう片方が受ける側である。
P-256 を加えたら、鍵の種類を含めて保存した形で比べる。両方が同じ規則を使えば、どちらが接続を開いても役はそろう。

| 持つ側 | 記録に置くもの |
|---|---|
| 両方 | いまの回数（`u64`）と、いまの合言葉（32 バイト） |
| 受ける側 | 次の回数と合言葉を候補として 8 組まで持つ。いまの値を替えるたびに、それまでの回数と合言葉も 1 組残す。以前の値は直近の 8 組まで。候補も以前の値も、別々に古い組から外す |
| 両方 | `stopped`。ふだんは空。止めた時刻と理由、自分の回数を残す。自分で不一致を見つけたときは、相手が示した回数と、その接続の接続元アドレスも残す |
| 両方 | 最後に進めた時刻と、最後に確かめた結果 |

この項目は一覧や鍵と同じように守る。受ける側は、今と同じ保存先の錠を取り、ひとまとまりの変更を 1 回で保存する。
受ける側が接続ごとに覚えるのは、手順 6 に達した時点の自分の回数（開いたときの回数）だけである。以前の値に合う証明で接続を通すことはない。
候補も以前の値も、いまの合言葉と同じく秘密である。どの値も `istesso peers list` やログ、診断には出さない。
【問い 写3】OS でできるなら、候補も以前の値も含めて、この項目だけをバックアップから外す案である。そうして復元すると、相手は一覧にいるが合言葉はない（`missing`）。その接続は断る。ペアは止めず、ペアリングし直す。

### 持ち主が使い直すとき

身元を確かめた相手から `state_mismatch` か手順 6 の「止めている」を受けた側も、そのペアに `stopped` を保存する。
理由は「相手から不一致の知らせを受けた」とし、その鍵で開いている接続を切って「相手で止まった」と知らせる。
同じ相手とペアリングし直すと、両方の記録と合言葉が新しくなり、止めた印が消える。
古い記録の接続は切る。持ち主がホストに出たコードを端末に入れるのが、止めたあとに使い直す道である。
端末の鍵が写されたおそれがあれば、端末で新しい鍵を作り、すべてのホストとペアリングし直す。古い鍵はどのホストからも外す。
ホストの鍵なら、そのホストで新しい鍵を作り、すべての端末とペアリングし直す。どの端末からも古いホストを外す。

層 1 より前のペアには合言葉がない。ペアリングし直すのを勧める。
【決定】2026-11-21、持ち主（同じユーザーに対する守りの答え）。ファイルからキーチェーンに移る端末は、新しい鍵を作ってペアリングし直す。その 1 回で層 1 も始める。
更新後の初めの接続から合言葉を取ると、すでにある写しのほうが先につないでしまいうる。

### この案に残る不足

写した鍵と合言葉でよそから先につなぐことは防げない。本物が次に同じ相手につないだときに気づき、ペアを止める。
悪いプログラムが同じユーザーで本物の機械にいる間は、その場で鍵を使え、合言葉もそろえられる。層 1 では見つけられない。
層 1 は一覧の書き換えも検出しない。足された端末には、その端末自身の正しい鍵と合言葉がある。
一覧を守る方法と、追加や権限の引き上げをほかの端末に知らせる案も、ADR 0021 にある。
