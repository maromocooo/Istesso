# ADR 0006：ペアリングの方式

- 状態：採用（公開前に外部レビューを受ける）
- 日付：2026-11-15

## 背景

端末同士のリンクは、簡単で、かつ安全でなければならない。この仕組みは入力の送信やアプリのインストールまでできるので、信頼の入口は最も慎重に作る。

## 決定

### 手順

1. ホスト側が8文字のコードを表示する（Crockford base32、40 ビット。`ABCD-EFGH` の形）。
2. 両者がそのコードで SPAKE2 を実行する。コードが同じときだけ同じ共有鍵になる。
3. 共有鍵から、方向ごとの鍵を HKDF で導く。
4. 各端末が、長期公開鍵（Ed25519）と、手順の写し（transcript）への署名を、方向ごとの鍵で暗号化して送る。
5. 受け取った側は、復号と署名の検証に成功したら、相手の公開鍵を固定して保存する。
6. 以後の接続は、固定した公開鍵で相互認証する。保存した記録を消すと失効する。

### 性質

| 脅威 | 対応 |
|---|---|
| 盗聴してコードを総当たりする | SPAKE2 は、盗聴した内容からオフラインで推測を試す手段を与えない |
| コードを知らずに割り込む | 共有鍵が一致せず、復号に失敗する |
| オンラインで何度も試す | 1つのコードで受け付けるのは1回だけ。失敗したらコードを作り直す。有効期限あり |
| 送ったメッセージを送り主に送り返す | 鍵が方向ごとに違うので復号できない。SPAKE2 のメッセージの反射も拒否する |
| 他人の公開鍵を自分のものとして登録する | 手順の写しへの署名で、秘密鍵を持っていることを証明させる |
| 別の回の署名を使い回す | 署名は、その回の手順の写しと役割に結び付いている |
| 表示名に制御文字などを入れる | 名前は長さと文字種を検査する |

### 権限

新しくペアリングした端末の権限は「閲覧」と「操作」だけ。インストール、USB、音は個別に許可する。

## 既知の不足（公開前に対応する）

- `spake2` クレートは第三者の監査を受けていない（作者が明記している）。外部レビューを受ける。
- 端末の秘密鍵を、所有者だけが読めるファイルに置いている。OS のキーチェーンへ移す。
- 現在の通信路は平文の TCP で、ペアリングの手順だけを運ぶ。固定した鍵で相互認証する制御チャンネルは M0 の残り。
- 最後の確認応答（`OK`）は認証していない。割り込まれると、片方だけが相手を保存した状態になり得る。相手の鍵の検証は済んでいるので安全性には影響しないが、制御チャンネルの実装時に認証つきの応答へ置き換える。
- LAN 内の自動発見と QR はまだない。
- 出先からのペアリングは想定しない（VPN 越しの LAN 内だけ）。
