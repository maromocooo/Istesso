# ADR 0022：文字のコピーと貼り付け（試用版）

- 状態：提案（2026-11-19。別の目のレビューを待つ。**試用版だけ**。`main` には入れない）
- 日付：2026-11-19

## 背景

持ち主は、金曜日（11-20）から、試用版を、ふだんの使いみち全部に使う。そこで、Air とホストのアプリのあいだで、文字をコピーして貼り付けたい（持ち主、2026-11-19）。ホストは 2 つある。Ubuntu のホスト（試用のコンポジター）と、Mac Studio（試用の Mac のホスト）。

いまの動き（コードから。見ていない）：

- Air の ⌘C と ⌘V は、ふつうのキーとして、ホストへ送られる（Ubuntu には Control として。[ADR 0007](0007-control-channel.md) の「入力」）。ホストのアプリの中のコピーと貼り付けは、そのため、もう効く。
- ホストのクリップボードと、Air のペーストボードのあいだで、文字を運ぶものは、どの層にもない（[m3-everyday-apps.md](../m3-everyday-apps.md) の 6.2）。Ubuntu の試用のコンポジターは、アプリどうしのクリップボード（`wl_data_device`）を持っている。それは、机のセッションのクリップボードとは別のものである。

クリップボードには、パスワードが通りうる。中身が端末をまたぐので、運ぶ前に、何を、いつ、どの権限で運ぶかを、この文書で決める（m3-everyday-apps.md の宿題 10 の a）。

持ち主が決めたこと（2026-11-19）：

- 試用版だけ。
- 運ぶのは、**人がコピーか貼り付けのキーを押したときだけ**。自動で合わせることは、しない。
- 文字だけ。ファイルと絵は運ばない。
- パスワードの欄からは、運ばない。

## 決定（案）

### 何を運ぶか

- 文字だけ（UTF-8）。書式（RTF、HTML）、絵、ファイル、URL の印は、運ばない。Air では、ペーストボードの「文字」（`public.utf8-plain-text`）だけを読む。ホストでは、選択の「文字」（Ubuntu は `text/plain;charset=utf-8`、無ければ `UTF8_STRING`、`text/plain`。Mac は `public.utf8-plain-text`）だけを読む。
- 上限は **64 KiB（65536 バイト、UTF-8）**。超えたものは、**切り詰めずに、運ばない**（切り詰めた文字は、気づかれずに壊れているため）。
- 制御文字は、タブ、改行（LF、CR）のほかは、含むものを運ばない（U+0000〜U+001F のうち U+0009、U+000A、U+000D のほか、U+007F〜U+009F）。空の文字も運ばない。
  - 確定した文字（ADR 0007 の「確定した文字」）と違って、改行とタブを文字のまま運ぶ。貼り付けは、何行もの文字であることが多いため。
  - ほかの制御文字を断るのは、JSON に直したときの大きさを 2 倍までに抑えるためと、端末のような受け手に、思わぬ操作の文字を渡さないためである。

### いつ運ぶか

人が、**ホストのアプリを映している Air の窓が打ち込む窓のときに**、次のキーを押したときだけ。

| Air で押す | 向き | 起きること |
|---|---|---|
| ⌘C | ホスト → Air | ホストが、そのアプリに、ホストのふだんのコピーのキーを押す（Ubuntu は Control-C、Mac は ⌘C）。そのアプリが新しく置いた選択の文字を、Air のペーストボードに置く |
| ⌘V | Air → ホスト | Air のペーストボードの文字を、ホストのそのセッションのクリップボードに置き、ホストが、そのアプリに、ふだんの貼り付けのキーを押す（Ubuntu は Control-V、Mac は ⌘V） |

- 引き金にするのは、**Command だけを押した C と V**。Shift、Option、Control が一緒のとき（⌘⇧V など）は、これまでどおり、ふつうのキーとして送る。
- ⌘C と ⌘V のときは、C と V のキーそのものは送らない。代わりに、下の `copy` と `paste` を送る。ホストが、自分でキーを押す。コピーの結果が、どのキーの結果かを、ホストがまちがえないようにするためである。
- ホストのメニューの「コピー」をポインターで選んだときは、運ばない（ホストの中だけのコピーになる）。キーだけを引き金にする。
- ホストが受けると言わないとき（下の「受け側が受けると言うとき」）は、⌘C と ⌘V を、これまでどおり、ふつうのキーとして送る。動きは、いまと同じになる。
- ⌘V で、Air のペーストボードに文字が無いとき（空、絵だけ、ファイルだけ）は、貼り付けのキーだけを送る（文字を付けない `paste`）。ホストのアプリは、自分の持っているものを貼る（Blender で、物体をコピーして貼るときなど。Blender は、物体をクリップボードではなく自分の場所に置く。コードと文書から。見ていない）。
- ⌘V で、文字が上限を超えるか、パスワードの印があるとき（下）は、**何も送らない**。貼り付けのキーも送らない。ホストに残っている古い文字が、思いがけず貼られないようにするためである。窓の題に、短く理由を出す（2 秒）。

### パスワードからは運ばない

**Air の側**（⌘V で読むとき）：

- ペーストボードの項目に、次の印のどれかがあれば、運ばない。nspasteboard.org の取り決めで、パスワードの道具などが付ける印である。
  - `org.nspasteboard.ConcealedType`（隠すべき中身）
  - `org.nspasteboard.TransientType`（すぐ消える中身）
  - `org.nspasteboard.AutoGeneratedType`（プログラムが作った中身）
- そのため、Air のパスワードの道具からコピーしたパスワードは、ホストのアプリに貼れない。手で打つ。これは受け入れる（決めること 5）。

**ホストの側**（⌘C のとき）：

- Ubuntu（試用のコンポジター）：
  - キーボードを持っているクライアントが、text-input-v3 を有効にしていて、その欄の目的（`content_type` の purpose）が `password` か `pin` なら、**コピーのキーを押さずに**断る。
  - 置かれた選択の種類（MIME）に `x-kde-passwordManagerHint` があれば、中身を読まずに断る（KDE の取り決めで、パスワードの道具が付ける印。印の名前だけを使う。実物で確かめる）。
- Mac のホスト：
  - そのアプリのフォーカスのある要素が、パスワードの欄（アクセシビリティの `AXSecureTextField`）なら、または、安全なキー入力が有効（`IsSecureEventInputEnabled()`）なら、**コピーのキーを押さずに**断る。
  - コピーのあと、ペーストボードの項目に、上の 3 つの印のどれかがあれば、断る。
- どちらも、断ったときは、Air のペーストボードを変えない。答えは `refused`（下）。窓の題に「パスワードの欄からはコピーしません」と出す。
- これは、欄が自分でパスワードだと名乗っているときにしか効かない。名乗らない欄（ふつうの文字の欄に打った鍵など）は、運ばれる。人が選んで ⌘C を押したものだけが運ばれる、という引き金の決まりが、残りを受け持つ。

### 権限と行き先

- 権限は、**キーと同じ「操作」**。`input_open` が通った入力の接続でだけ受け付ける。つなぎ直しのたびに確かめ直し、ペアリングの解除と権限の取り消しで切れる（ADR 0007 の「切れたあとの、つなぎ直し」）。新しい権限は作らない。
  - ⌘C は、ホストの文字を Air へ読み出す。それでも「閲覧」ではなく「操作」にする。ホストのアプリにキーを押すことだからである。また、「操作」を持つ端末は、いまでも、選んで絵で読める。
- 行き先は、その入力の接続が渡すセッション（いまの試用版では、アプリごとに 1 つのエージェントと、1 つのコンポジターか Mac のホスト）の中の、**キーボードを持っているクライアントだけ**。
  - Ubuntu：コピーで受け取る選択は、キーボードを持っているクライアントが、こちらがキーを押したあとに置いたものだけ。ほかのクライアントが置いたものは、待つあいだに来ても、取らない。
  - Mac：これまでのキーの決まりと同じ。アプリの窓の形では、そのアプリが前面で、キーの窓が範囲の中のときだけ、キーを押す（`m4-daily-host` ブランチの `docs/m4-daily-host.md` の「入力が届く範囲」）。前面でなければ、何もせず `none` と答える。
- コピーの答えは、**頼んだ接続にだけ**返す。頼んだあとに、その接続が終わった（切れた、つなぎ直した）ら、答えは捨てる。
- Air では、答えの文字を、**いちばん新しい頼みの答えで、頼んでから 2 秒以内で、窓がまだ開いているときだけ**、ペーストボードに置く。古い頼みの答えは捨てる。

### メッセージ（ADR 0007 に足すもの）

入力の接続（ADR 0007 の「入力」）に、イベントを 2 つと、受け側からの答えを 1 つ足す。通信路の手順（`istesso-link` のハンドシェイク、封のしかた）と、先頭の版（`ISC1`）、プロローグは、変えない（メッセージの追加）。

- イベント（`input` の `events` に入る。キーと同じ並びで、届いた順に渡す）：
  - `{"kind":"copy","id":N}`：コピーして、その文字を返してほしい。
  - `{"kind":"paste","id":N,"text":"…"}`：この文字を置いて、貼り付けのキーを押してほしい。`text` が無いときは、置かずに、貼り付けのキーだけを押す。
  - `id`：1 以上の整数（32 ビット）。窓を持つ側が、1 つの窓のあいだ、増やしながら付ける。
- 答え（受け側 → 送る側。`input_alive` と同じ向き）：
  - `{"type":"clipboard","id":N,"result":"…","text":"…"}`。`text` は `result` が `text` のときだけ付く。
  - `result`：`text`（コピーした文字。コピーのときだけ）、`pasted`（貼り付けのキーを押した。貼り付けのときだけ）、`none`（新しい選択が来なかった、文字が無かった、キーを押せる相手がいなかった）、`refused`（パスワード）、`too_large`（上限を超えた）。知らない値は `none` として読む。
  - 1 つの `id` に、答えは 1 つまで。受け側は、2 秒のうちに答えられなければ、答えない。
  - **キーやポインターを運ぶ `input` には、これまでどおり答えない。** 答えるのは、`copy` と `paste` にだけ。
- 受け側が受けると言うとき：受け側（エージェント）は、クリップボードを渡せる相手と起動されたとき（試用版で、`--clipboard` を付けたとき）だけ、`input_open` の答えに `"clipboard": true` を付ける（`alive`、`text` と同じ形の、項目の追加）。送る側は、付いていなければ「受けない」とみなし、`copy` と `paste` を送らない（窓を持つ側は ⌘C、⌘V をふつうのキーとして送る）。知らないイベントで `input` をまるごと断る古い受け側（ADR 0007 の「確定した文字」の、知らない受け側）に、送らないためである。つなぎ直しのたびに、答えを読み直す。

手元の口（どれも、本人だけが開ける場所）：

| 区間 | 道 |
|---|---|
| 窓を持つ側 → 中継（Air） | いまの中継の口（データグラム）。64 KiB の文字は、macOS のデータグラムの上限（既定で 2 KiB ほど。調べて確かめる）を超えるので、送り方を変える（送る側の受け口の大きさを上げるか、分けて送る） |
| 中継 → 窓を持つ側（Air） | 窓を持つ側が開く答えの口（中継の口の隣）。`clipboard` の答えだけを渡す |
| エージェント → クリップボードを渡す相手（ホスト） | いまの入力の口（データグラム）。順番は、キーと同じ道で守る |
| クリップボードを渡す相手 → エージェント（ホスト） | エージェントが開く答えの口（入力の口の隣）。エージェントは、自分が待っている `id` の答えだけを受け取り、2 秒で忘れる |

- 中継の状態のファイルに `"clipboard"` を足し、窓を持つ側は、それを見て ⌘C と ⌘V の扱いを決める（`"text"` と同じ）。
- Ubuntu では、パイプライン（`daily-pipeline.py`）が、入力の口から `copy` と `paste` を受け取る。**文字そのものは、GStreamer のイベントやメッセージに載せない**（GStreamer のデバッグ出力に、中身が出るため。ADR 0007 の「`main` に入れる前に直すこと」の 2 つめと同じ心配）。順番を守るための、中身の無い合図（`id` だけ）を、キーと同じ道でコンポジターへ渡し、文字は、コンポジターが自分で開く手元の口で受け渡す。コピーの答えも、コンポジターがエージェントの答えの口へ、自分で送る。

### 記録に出さない

- **コピーした文字も、貼り付けた文字も、どこにも書かない**（ログ、標準出力、標準エラー、記録のファイル、`--timings`、`DAILY_KEY_RECORD`、GStreamer のデバッグ出力）。AGENTS.md の 4 と、確定した文字と同じ。
- 書いてよいのは、数だけ：頼んだ回数、答えの種類ごとの回数、文字を付けた貼り付けと、付けない貼り付けの回数、断った回数。**大きさも書かない**（パスワードの長さが分かるため）。
- `InputEvent` の `Debug` の表示で、`paste` の文字を隠す。答えの型も同じ。

### 遅延

- ふつうのキーの道は、変わらない。⌘C と ⌘V だけが、キーの代わりにイベントになる。
- コピーの答えは、受け側から送る側への向きで、キーの送りを待たせない。中継は、答えを、いまの「まだここにいる」の答えと同じところで読む（0.1 秒おき）。そのため、Air に文字が置かれるまでに、最大 0.1 秒ほど足される。人がコピーのあとに貼るまでの時間に比べて、小さいと見る。
- 64 KiB の貼り付けは、入力の接続の上で、そのあとのキーを、送り終えるまで待たせる。有線の LAN では 1 ミリ秒ほど（計算から。測っていない）。
- 試用版だけで、計測の道具、関門で測ったプラグイン、判定の計測が使うエージェントには、入れない。測れていないことを、PR に書く（AGENTS.md の 3）。

- 修飾キーの扱い：⌘C を押したとき、Command は、もうホストへ送られている（Ubuntu には Control として）。ホストがコピーのキーを押すときは、自分の側の修飾キーの状態に合わせる（押されていればそのまま C だけ、押されていなければ前後に押して離す）。キーが押されたまま残らないこと。
- Mac のホストで貼り付けたあと、Studio のペーストボードは、元に戻さない（決めること 3）。

## 脅威と、その扱い

| 脅威 | 扱い |
|---|---|
| 乗っ取られたホストのアプリが、Air のペーストボードを読む | 読めるのは、人がそのアプリの窓で ⌘V を押したときの文字だけ。そのときの、キーボードを持っているクライアントだけ。パスワードの印のあるものは送らない。人が貼ると決めた文字が、そのアプリに渡るのは、ふつうの貼り付けと同じで、受け入れる |
| 乗っ取られたホストのアプリが、⌘C のときに、選んだものと違う文字を置く（貼った先で、思わぬコマンドになる文字など） | 防げない。⌘C を押したときだけ、文字だけ（書式やファイルの印は運ばない）、制御文字を断る、で小さくする。ウェブのページからのコピーと同じ扱いで、受け入れる |
| 同じセッションの、ほかのクライアントが、文字を取る、置く | Ubuntu：コピーで取るのは、キーボードを持つクライアントが、キーのあとに置いた選択だけ。貼り付けた文字は、そのセッションの選択に残り、あとでキーボードを持ったクライアントが読める（Wayland の決まり）。いまの試用版は、セッションにアプリ 1 つなので、受け入れる。セッションに何個もアプリを入れるときに、見直す |
| Mac のホストで、Studio のほかのアプリやクリップボードの道具が、貼り付けた文字を読む | Studio のペーストボードは、Studio のすべてのアプリが読める。Studio の前には、遠くから使うあいだ誰もいない（持ち主）。この Mac だけ（Universal Clipboard に乗せない）で置く。受け入れる（決めること 3） |
| Air のクリップボードの道具（履歴を取るもの）が、ホストからコピーした文字を取っておく | Air に置いた文字は、Air でふつうにコピーしたものと同じに扱われる。パスワードの欄からのコピーは、ホストで断っている。欄が名乗らないものは、履歴に残りうる。受け入れる。印（Transient など）は付けない（人がコピーしたものなので） |
| Air のほかのアプリが、ペーストボードを読む | Air のペーストボードの性質で、この仕組みとは関係ない。この仕組みが置くのは、人が ⌘C を押したときだけ |
| Universal Clipboard（同じアカウントの端末のあいだで、OS がペーストボードを渡すもの） | Air に置くときは、この Mac だけにする（決めること 2）。Studio で、アプリが ⌘C で置いたものは、Universal Clipboard が効いていれば、この仕組みと関係なく、OS が渡すかもしれない。それは Istesso の外で、ここでは止めない |
| ネットワークで盗み見る、書き換える | 入力の接続（Noise、ペアリング済みの相手、「操作」）の中だけを通る。新しい暗号の部品は足さない |
| 記録から読まれる | 文字も大きさも書かない（上の「記録に出さない」） |
| 権限を外された端末が、つなぎ直して読む | `input_open` を、つなぎ直すたびに確かめ直す。答えは、頼んだ接続にだけ返す |
| 人の知らないうちに運ばれる | 運ぶのは ⌘C と ⌘V のときだけ。自動では合わせない |

## 採らなかった案

- **自動で合わせる**（窓が打ち込む窓になったときに Air の文字を送る。ホストで選択が変わるたびに返す。m3-everyday-apps.md の 6.2 の d）：持ち主が断った（2026-11-19）。Air でコピーしたものが、全部ホストのアプリへ渡る。
- **⌘C と ⌘V をふつうのキーとして送り、ホストで選択の変化を見張って返す**：変化が、人のキーの結果か、アプリが自分で置いたものかを、分けられない。
- **外の道具の口（Wayland の data-control、`wl-clipboard` のような道具）**：セッションのすべてのクリップボードを、外から読み書きできる口を開くことになる。コンポジターの中だけのほうが、狭い。
- **別の接続で運ぶ**：キーとの順番が崩れる（打ったすぐあとの ⌘V が、打った文字を追い越す）。
- **ほかの遠隔の仕組みのクリップボードの形を借りる**：読んでいない。自分の小さなメッセージにする（下の「特許とライセンス」）。
- **絵とファイル**：ストレージ（M5）のあと（[m1-plan.md](../m1-plan.md) の 8）。
- **⌘X（切り取り）**：持ち主の決めは ⌘C と ⌘V。ただし、決めること 1。

## 特許とライセンス

仕組みを借りる前に、ライセンスと特許を見る（持ち主の決め、2026-11-18）。

| 使うもの | ライセンス | 特許 |
|---|---|---|
| Wayland の `wl_data_device`（Wayland の本体の取り決め） | MIT 系（Expat）。試用のコンポジターは、もう使っている（[ADR 0009](0009-host-compositor.md)） | 何も書いていない。Wayland の土台全体と同じ立場で、新しく足すものはない |
| text-input-v3 の `content_type`（パスワードの欄の目印として読むだけ） | MIT 系 | **はっきりしていない**（ADR 0020 の「特許」。`m3-ime-route-d` ブランチ）。試用版の確定した文字と同じく、「試す」だけ |
| Smithay の選択の部品（コンポジターが選択を読む、置く） | MIT | 部品のコードで、仕様ではない |
| macOS の `NSPasteboard`、アクセシビリティ、`IsSecureEventInputEnabled` | OS の公開の API を呼ぶだけ | 仕組みを借りない |
| nspasteboard.org の印、KDE の `x-kde-passwordManagerHint` | 印の名前（文字列）を読むだけ。コードは読まない、写さない | 手順を借りない |

- 使わないもの：ほかの遠隔の仕組みのクリップボードの仕様（特許を並べている仕様がある）は、読まない、従わない。Sunshine、Moonlight、xpra などのクリップボードのコードも、読まない（AGENTS.md の 1）。
- メッセージの形（`copy`、`paste`、`clipboard`）は、この文書で決めた、自分のものである。

## 動かして確かめること

1. Air で、ビューアーがペーストボードを読むとき、macOS がペーストの許可を尋ねるか（m3-everyday-apps.md の宿題 10 にもある）。尋ねるなら、ビューアーの「編集」メニューの「ペースト」（`paste:`）から読む形にすれば、人の貼り付けとして扱われるか。**尋ねる画面は、持ち主の画面に出るので、出す前にまとめ役に知らせる。**
2. Studio で、Mac のホストがペーストボードを読むとき、尋ねる画面が出るか。出るなら、誰もいない Studio の画面に出る。持ち主の手の項目になる。
3. Ubuntu：Firefox、Blender、Text Editor で、Control-C のあと、キーボードを持つクライアントが選択を置くまでの時間（0.5 秒で足りるか）。
4. Ubuntu：パスワードの欄で、Firefox と GTK が text-input-v3 の目的を `password` として送るか。送らないなら、ほかに目印があるか（なければ「名乗らない欄」として、上の脅威の表に残す）。
5. Air の 64 KiB の貼り付けが、窓を持つ側 → 中継 → ホストを、切れずに通るか。
6. ⌘C と ⌘V のあと、ホストで、Control（Command）と C、V が押されたまま残らないか。
7. 記録のファイル、標準出力、GStreamer のデバッグ出力に、文字が出ないか（決めた文字で試して、探す）。

## 決めること（持ち主）

1. ⌘X（切り取り）も、⌘C と同じにするか。推し：する（`copy` に「切り取り」の印を足し、ホストは Control-X、⌘X を押す）。しないと、ホストで切り取ってから ⌘V を押すと、Air の古い文字が貼られる。
2. Air に置く文字を、この Mac だけにするか（Universal Clipboard で iPhone などへ渡さない）。推し：この Mac だけ。
3. Mac のホストで貼り付けたあと、Studio のペーストボードを、前の中身に戻すか。推し：戻さない（アプリが貼り付けの中身を読む時刻が分からず、戻すのが早すぎると、貼り付けが壊れる）。
4. 上限 64 KiB でよいか。
5. Air のパスワードの道具からコピーしたものを、貼れない（印で断る）でよいか。
