- 状態：**設計（2026-11-18 の朝）。まだ、作っている途中で、動かしていません。** 下の「作る順」の、どこまで済んだかを、この行に書き足していきます。
- ブランチ：`trial-daily`（`main` の `f5c2391` から）。**どこにもマージしません。** 判定用のビルドとは、別のものです。
- ねらい：持ち主が、毎日さわって、気づいたことを宿題にするための版。粗くてよい。ランチャー（最初は、窓 1 枚）、アプリを 2 つか 3 つ同時に、アプリごとに Mac の窓 1 枚、切り替え、ていねいな終わらせ方。

## いまの部品で、何が足りなかったか

`scripts/try.sh` は、アプリを 1 つ映します。`ISTESSO_TRY_NAME` を付けると、2 つめを横で動かせますが、キーボードとマウスは届きません。ホストのエージェントが、入力を、ふだんのパイプラインの口 1 つにだけ渡すためです。

入力を、窓ごとに正しいアプリへ届ける道は、3 つあります。

| 道 | 中身 | いまあるか | 試用版で |
|---|---|---|---|
| エージェントが、セッションごとに振り分ける | `input_open` にセッションの名前を足す（ADR 0010、予行の `m3-join-rehearsal`） | 予行のブランチにだけある。本線には入っていない。入れるには、ADR 0007 の更新と、アプリマネージャー（PR #2）の合わせ直しが先 | 使わない。製品の形は、これ |
| 自前のクライアントが、窓ごとに、入力の接続を自分で持つ | `Istesso --input-address <アドレス>:<ポート>`（ADR 0018） | クライアントの側は、ある。ホストの側の行き先（振り分けか、エージェントをもう 1 つ）は、別に要る。人の手のキーボードでは、まだ試していない | あとで、切り替えとして足す |
| **アプリごとに、試用のエージェントを 1 つ** | 試用のエージェントを、専用のポートと、専用の入力の口で起動する。Mac の中継は、`--address <アドレス>:<ポート>` で、そのエージェントにだけつなぐ | **コードを変えずに、できる**（`istesso agent --port`、`--no-discovery`、入力の口は、ランタイムディレクトリーから決まる） | **これを使う** |

3 つめを選んだわけ：コードを 1 行も変えない。ふだんのエージェント（判定の計測が使う）に、何も足さない。番号だけで止められる。まちがっているところは、「エージェントがアプリの数だけある」ことと、「入力を送れるのは、映している端末だけ」（ADR 0010 の 13）を確かめていないこと（本線のいまの決まりと同じ：「操作」を持つ、ペアリング済みの端末なら送れる）。どちらも、製品の形（1 つめの道）になれば、消えます。

## 形

```text
Mac                                              ホスト（Ubuntu）
ランチャーの窓（一覧、開く、前に出す、閉じる）
  │  scripts/daily.sh を呼ぶ
  ├─ 窓 Firefox ── 絵（暗号化、47911）────────── パイプライン 1（隠れたコンポジター、エンコーダー）── Firefox
  │   └ 中継 ───── 入力（制御チャンネル、47921）── 試用のエージェント 1 ─ 入力の口 1 ─┘
  ├─ 窓 Blender ── 絵（47912）────────────────── パイプライン 2 ── Blender
  │   └ 中継 ───── 入力（47922）──────────────── 試用のエージェント 2 ─ 入力の口 2 ─┘
  └─ 窓 Text Editor（3 つめ。47913、47923）
```

- 絵は、ADR 0015 の暗号化した経路。入力は、ADR 0007 の制御チャンネル。どちらも、ペアリング済みの相手にだけ。暗号の部品は、何も足していません。
- ホストのパイプラインは、昨夜の試用と同じ `scripts/m1-step3-host.py`（修正 4 つのコンポジター）。Mac の窓は、試作のビューアー（`macos/gst-viewer`）と、`istesso input relay`。どれも、昨夜、人の手で使ったものです。
- 自前のホスト（ADR 0019）、自前のクライアント（ADR 0018）、アプリマネージャーのメッセージ（ADR 0010）は、まだ使いません。「あとで替えるもの」に書きます。

## 計測の合図

- 始める前に `scripts/measuring.sh status` を読みます。`busy` なら、始めません。
- 動いているあいだ、見張りが 5 秒おきに読みます。`busy` になったら、10 秒以内に、次のとおりにします。
  1. Mac の窓と中継を、番号で止める。
  2. ホストのパイプラインに `detach` と言う（エンコーダーを手放し、絵を止める）。
  3. アプリと、パイプラインと、試用のエージェントのプロセスを、止めたままにする（SIGSTOP。CPU も GPU も使わない。保存していないものは、そのまま残る）。
- `free` に戻っても、自動では戻しません。ランチャーに「計測のために止めている」と出ます。「前に出す」で、続きから動きます。
- **決めてほしいこと**：上の 3 は、「力ずくで終わらせない」と「10 秒以内に止める」の両方を守るための案です。アプリを終わらせるほうがよければ、変えます。
- 合図のファイルは、読むだけです。書きません。消しません。

## アプリと、切り離し

| 名前 | 起動 | 切り離し | 音 |
|---|---|---|---|
| `firefox` | snap の Firefox。昨夜の試し用のプロファイル（snap のデータの中の `istesso-try-profile`）。`--no-remote` | ふだんのプロファイルとは別。ファイルを選ぶ窓は、アプリの窓の中 | プロファイルの設定で無音。**無音の設定が読めなければ、起動しない** |
| `blender` | ホームの下に展開してある Blender 5.3（場所は `DAILY_BLENDER` で言う。なければ探す） | 設定のフォルダーは、昨夜と同じ専用のもの（`XDG_CONFIG_HOME`）。持ち主が昨夜入れた設定（テンキーの代わり、3 ボタンの代わり）が、残っている | `-noaudio` |
| `editor` | `gnome-text-editor --standalone --ignore-session` | データ、設定、状態、キャッシュを、試用版のフォルダーへ。設定はメモリーの中だけ（`GSETTINGS_BACKEND=memory`）、`GIO_USE_VFS=local` | 出さない |

- どのアプリも、`DISPLAY` を外し、隠れたコンポジターの `WAYLAND_DISPLAY` だけを持ちます。机の画面には、何も出ません。
- 同じアプリを 2 つは、開きません（もう開いていれば、その窓を前に出します）。

## 始め方（予定の形）

```sh
scripts/daily.sh setup     # 1 回だけ：Mac でビルドし、ホストに写してビルドする（15 分ほど）
scripts/daily.sh           # ランチャーの窓を出す
```

ランチャーを使わずに、コマンドだけでも同じことができます。

```sh
scripts/daily.sh open firefox     # 起動して、窓を出す。もう動いていれば、前に出す
scripts/daily.sh open blender
scripts/daily.sh list             # アプリと、開いているもの、その状態
scripts/daily.sh close blender    # 閉じるよう頼む。残ったら、残ったと言う
scripts/daily.sh stop             # 全部に閉じるよう頼み、窓と中継を止める。残ったアプリを表示する
scripts/daily.sh note "気づいたこと"
```

持ち主の Mac に窓が初めて出るときは、まとめ役が、先に知らせます。

## ランチャー（A の最初の一歩）

- 窓 1 枚。上に、開けるアプリ（Firefox、Blender、Text Editor）。下に、開いているものと、その状態（映している／窓を閉じた（アプリは動いている）／閉じるよう頼んだ／保存を尋ねて残っている／計測のために止めている）。行ごとに「前に出す」と「閉じる」。下の端に、気づきを書く欄。
- **Dock のタイルは、ランチャーの 1 つだけ**にします（A の形）。アプリの窓のプロセスは、Dock に出ない形（`accessory`）で起動します。そのために、試作のビューアーに、環境変数の切り替えを 1 つ足します（このブランチだけ。判定用のビルドのビューアーは、変わりません）。
- 切り替え：窓をクリックする。ランチャーの行をクリックする。ランチャーの Dock のメニューから選ぶ。キーでの切り替え（⌘Tab のようなもの）は、最初の版には、ありません（宿題）。
- ランチャーは、包みではなく、シェルから起動するプログラムです（新しい包みを登録すると、Mac がネットワークの決まりを作り直して、ほかの接続を切ることがあるため）。Dock のアイコンは、当面、ふつうのプログラムの絵です。
- 本当の A（`Istesso.app` 1 つが、全部の窓を持つ）は、自前のクライアントが、1 つのプロセスで複数の窓を持てるようになってからです。

## 終わらせ方

- 「閉じる」は、パイプラインに `close` と言います。コンポジターが、アプリの全部の窓に、閉じるよう頼みます（窓の閉じるボタンと同じ）。保存するものがないアプリは終わり、パイプラインが `empty` と言います。そのあとで、パイプライン、試用のエージェント、Mac の窓と中継を、番号で止めます。
- 保存するかを尋ねるアプリは、**残ります**。窓も残します。一覧に「閉じるよう頼んだ。まだ開いている」と出ます。力ずくでは、終わらせません（その口を、作りません）。
- Mac の窓の赤いボタンは、いまは「窓だけ閉じる」です（アプリは動き続ける。「前に出す」で戻る）。
- `stop` のあと、残っているものを、番号つきで表示します。

## 危うさ

- **エンコーダーの数**：このホストのカードとドライバーでは、同時に開けるのは、PC 全体で 12（映像の流れが、開けなくなるまで開いて数えた。NVENC の Application Note の新しい版と、対応表も 12。カード自身の数えは、開いていても 0 を返すので、頼れない）。試用版は、アプリ 1 つにつき 1 つ使います。ふだんの試用のパイプライン、ほかの流れの試験、机の人の録画も、同じ 12 の中です。断られたときは、パイプラインが「エンコードできない」と言って、その窓だけ絵が出ません。
- **GPU のメモリー**：24 GB のうち、朝の時点で使っているのは 1 GB ほど。セッション 1 つがどれだけ使うかは、測っていません。Blender の重い場面は、別です。
- **修飾キーが Blender で効かない**（別の流れが調べている）。直ったら、ホストの写しとプラグインを替えるだけで、試用版に入ります。
- **2 枚目の窓を見失う**、**最初の窓に「全画面」と伝えている**：そのままです（ブランチ `m3-everyday-apps` の `docs/m3-everyday-apps.md` の 9 章にある「いま、何も変えずにできること」を使ってください）。
- Mac のビューアーと中継は、シェルから起動します。**遅延は、判定の値ではありません。** 感じを見るためのものです。
- ホストの机には、人がいます。画面にも、音にも、何も出しません。試用のアプリは、隠れたコンポジターの中だけで動きます。

## 作る順

1. ホストに、このブランチの写しを置いて、ビルドする。プラグインを写す。
2. `scripts/daily.sh`：`open`、`list`、`close`、`stop`、見張り。
3. 窓を出さない確認（実機 2 台）：絵が届いて復号できる（`scripts/m1-channel-check.py`）。入力の口に書いたキーが、そのアプリにだけ届く（2 つ同時に）。`close` で `empty` になる。`busy` の代わりの合図で、10 秒以内に止まる。
4. ランチャーの窓。
5. 持ち主の手での確認（まとめ役が、窓が出ることを先に知らせる）。
