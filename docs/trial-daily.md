## いまの部品で、何が足りなかったか

`scripts/try.sh` は、アプリを 1 つ映します。`ISTESSO_TRY_NAME` を付けると、2 つめを横で動かせますが、キーボードとマウスは届きません。ホストのエージェントが、入力を、ふだんのパイプラインの口 1 つにだけ渡すためです。

入力を、窓ごとに正しいアプリへ届ける道は、3 つあります。

| 道 | 中身 | いまあるか | 試用版で |
|---|---|---|---|
| エージェントが、セッションごとに振り分ける | `input_open` にセッションの名前を足す（ADR 0010、予行の `m3-join-rehearsal`） | 予行のブランチにだけある。本線には入っていない。入れるには、ADR 0007 の更新と、アプリマネージャー（PR #2）の合わせ直しが先 | 使わない。製品の形は、これ |
| 自前のクライアントが、窓ごとに、入力の接続を自分で持つ | `Istesso --input-address <アドレス>:<ポート>`（ADR 0018） | クライアントの側は、ある。ホストの側の行き先（振り分けか、エージェントをもう 1 つ）は、別に要る。人の手のキーボードでは、まだ試していない | あとで、切り替えとして足す |
| **アプリごとに、試用のエージェントを 1 つ** | 試用のエージェントを、専用のポートと、専用の入力の口で起動する。Mac の中継は、`--address <アドレス>:<ポート>` で、そのエージェントにだけつなぐ | **Rust のコードを変えずに、できる**（`istesso agent --port`、`--no-discovery`、入力の口は、ランタイムディレクトリーから決まる） | **これを使う** |

3 つめを選んだわけ：Rust のコードを 1 行も変えない。ふだんのエージェント（判定の計測が使う）に、何も足さない。番号だけで止められる。まちがっているところは、「エージェントがアプリの数だけある」ことと、「入力を送れるのは、映している端末だけ」（ADR 0010 の 13）を確かめていないこと（本線のいまの決まりと同じ：「操作」を持つ、ペアリング済みの端末なら送れる）。どちらも、製品の形（1 つめの道）になれば、消えます。

## 形

```text
Mac                                              ホスト（Ubuntu）
ランチャーの窓（一覧、開く、前に出す、閉じる）※まだない
  │  scripts/daily.sh を呼ぶ
  ├─ 窓 Firefox ── 絵（暗号化、4791N）────────── パイプライン（隠れたコンポジター、エンコーダー）── Firefox
  │   └ 中継 ───── 入力（制御チャンネル、4792N）── 試用のエージェント ─ 入力の口 ─┘
  ├─ 窓 Blender ── 絵 ─────────────────────────── パイプライン ── Blender
  │   └ 中継 ───── 入力 ───────────────────────── 試用のエージェント ─ 入力の口 ─┘
  └─ 3 つめ（Text Editor か Chrome）
```

- 同時に開けるのは 3 つまで。開くたびに、空いている枠（1〜3）を 1 つ取ります。枠 N の絵は 4791N、試用のエージェントは 4792N（持ち主の決めた 47911〜47913 と 47921〜47923）。ほかのものがそのポートを使っていれば、開きません。
- 絵は、ADR 0015 の暗号化した経路。入力は、ADR 0007 の制御チャンネル。どちらも、ペアリング済みの相手にだけ。暗号の部品は、何も足していません。中継とビューアーは、ホストの試用のエージェントの装置の番号（`istesso id` の指紋）を名指しして、つなぎます（Mac に、ペアリング済みの相手が何台あっても、まちがえない）。
- ホストのパイプラインは、`scripts/m1-step3-host.py`（このブランチの写しを、そのまま使う）。コンポジターは、窓の扱いを直した試用のビルド（下）。Mac の窓は、試作のビューアー（`macos/gst-viewer`）と、`istesso input relay`。
- 自前のホスト（ADR 0019）、自前のクライアント（ADR 0018）、アプリマネージャーのメッセージ（ADR 0010）は、まだ使いません。「あとで替えるもの」に書きます。

## 計測の合図

持ち主の決め：**終わらせずに止める。`free` で戻す。戻せなければ「戻せなかった」と出す。**

- 始める前（`setup`、`bundle`、`open`）に、合図を読みます。`busy` なら、始めません。`setup` のビルドは、動いているあいだも 2 秒おきに読み、`busy` で cargo を止めます。
- 開いているあいだ、見張りが、2 台それぞれで、自分の PC の合図を 2 秒おきに読みます。
- `busy` になったら：
  1. Mac の見張りが、窓（ビューアー）と中継を、番号で止める。**合図が `busy` のあいだ、Mac の見張りは、ほかに何もしない**（ssh もしない。AGENTS.md と、ルールの 18）。
  2. ホストの見張りが、全部のパイプラインに `detach` と言う（絵を止め、エンコーダーを手放し、見ている端末を切る）。答え（`paused`、`offered:false`）を、まとめて 3 秒まで待つ。
  3. アプリ、試用のエージェント、パイプラインのプロセスを、止めたままにする（SIGSTOP。CPU も GPU も使わない。保存していないものは、そのまま残る）。tmux の窓の最初のシェル（待っているだけ）だけは、止めない。tmux は、そのシェルが止まると、窓のプロセスを全部動かし直すため。
  4. ホストが静かかを確かめて、ホストの見張りの記録に 1 行書く：「絵が止まり、エンコーダーを手放した」か、「止まったと言わなかった」か。止めたプロセスの数と、止まっていない数。
- `free` に戻ったら：
  1. ホストの見張りが、止めたプロセスを動かし直す（SIGCONT）。絵は、まだ出さない（エンコーダーは、窓が戻るまで手放したまま）。
  2. Mac の見張りが、`busy` のときに開いていた窓を、同じ設定で開き直す。ホストに `resume` と言い、エンコーダーが開いたこと（`resumed`）を確かめてから、中継とビューアーを起動する。包みのときは、前に出さずに（`open -g`）。
  3. 戻せなかったとき（エンコーダーが開けなかった `refused`、ホストに届かなかった、窓が起動しなかった）は、その理由を書き留め、`list` の窓の欄に `not-back: <理由>` と出す。ランチャーができたら、そこに「戻せなかった」と出す。
- 合図のファイルは、読むだけです。書きません。消しません。確かめのための代わりの合図（`DAILY_TEST_SIGNAL=1` のときの `test-signal`）は、本物の合図に**足して**読むもので、本物を読むのをやめる口はありません。

### 言葉と見た目

持ち主の指摘（2026-11-18）：アプリが英語で出る。試用版が、自分のコマンドのために付けた `LC_ALL=C` を、アプリにも渡していたためです（ホストの tmux の全体の環境にも `LC_ALL=C` が入っている。tmux のサーバーは、ほかのセッションと共用なので、試用版は、そこを変えません）。

- アプリには、机のログインの言葉を渡します。起動のたびに、ホストの `systemctl --user show-environment` から `LANG`、`LANGUAGE`、`LC_*`、`XDG_CURRENT_DESKTOP` を読みます（読むだけ。読めなければ `/etc/default/locale`）。いまの値は `LANG=ja_JP.UTF-8`、`XDG_CURRENT_DESKTOP=ubuntu:GNOME`。アプリの起動の中で、`LC_ALL` と、ほかの `LC_*` を外してから、これを入れます。試用版の自分のコマンド（ホストの出力を読むもの）は、`LC_ALL=C` のままです。
- 見た目（テーマ、アイコン、カーソル、字、字の大きさ、濃淡、窓のボタンの並び）は、机が見せている値を読みます：持ち主の設定と、`ubuntu` のデスクトップの既定（Ubuntu は、`XDG_CURRENT_DESKTOP` が `ubuntu` のときだけ Yaru と Ubuntu Sans を既定にする）。読むだけで、持ち主の dconf と gsettings には、何も書きません。
- 読んだ値は、アプリごとの、**試用版の設定ファイル**（`<XDG_CONFIG_HOME>/glib-2.0/settings/keyfile`、`GSETTINGS_BACKEND=keyfile`）に、起動のたびに入れ直します。アプリが自分で変えた設定も、そのファイルにだけ残ります。Text Editor は `apps/editor/config`、Chrome は `apps/chrome/config`。
- **Firefox だけは違います。** snap が `XDG_CONFIG_HOME` を、自分のフォルダー（持ち主のふだんの Firefox と同じ所）に替えるので、そこへ試用版のファイルは置きません。設定はメモリーの中だけ（`GSETTINGS_BACKEND=memory`。どこにも書かない）で、デスクトップの既定を読みます。テーマは `GTK_THEME`（机が濃い色を選んでいれば `Yaru:dark` の形）で、机に合わせます。**字と字の大きさは、デスクトップの既定だけ**です（いまは机と同じ。持ち主が机で字を変えても、試用版の Firefox には届きません）。Firefox の画面の言葉は、試用のプロファイルの言語の設定（`ja`）によります。
- Blender は、自分の設定（言語を含む）で見た目が決まります。写した持ち主の設定が、日本語でした（下の「確かめたこと（2 回目）」）。
- 日本語の入力（IME）は、ここには入れていません（別の ADR で決める）。

### Blender の設定

- **持ち主のふだんの設定のフォルダー**（`~/.config/blender/<版>/config/`）を、**1 回だけ**、試用版のフォルダー（`~/.cache/istesso-daily-wip/apps/blender/config/blender/<版>/config/`）へ写します。最初の起動のときです。写したことは、`apps/blender/config/copied-<版>` に書き留めます。そのあとの起動は、その写しを使い、**写し直しません**（試用版の Blender で変えた設定は、写しに残る）。Blender は `XDG_CONFIG_HOME` を、その写しの上に向けて起動します。ふだんの設定のフォルダーは、読むだけです。
- 写し直したいとき（ふだんの Blender で変えた設定を入れたいとき）は、持ち主が `apps/blender/config` を別の名前に移します。次の起動で、もう 1 度写します。ふだんの設定をそのまま使う形は、製品の選択肢として、あとで決めます（いまは入れない）。
- **Blender が終わるたびに**（`close`、`stop`、計測のための一時停止が終わったとき、Blender がひとりでに終わったとき）、持ち主のふだんの `userpref.blend` の更新時刻、大きさ、i ノードを、起動したときと比べます。結果は、コマンドの出力と、ホストの `~/.cache/istesso-daily-wip/blender-settings.log` に 1 行ずつ。変わっていれば `WARNING … THE OWNER'S NORMAL BLENDER SETTINGS CHANGED` と、大きく出ます（試用版の Blender か、机のふだんの Blender のどちらかが変えた）。
- **前の版の誤り**：この文書の前の版は、「昨夜（11 月 18 日の 0 時台）の Blender は専用の設定フォルダーで動き、持ち主が入れた設定が、そこに残っている」と書いていました。これは確かめていませんでした。分かっていること：Blender 5.3 は `XDG_CONFIG_HOME` に従います（今日、背景モードで確かめた）。持ち主のふだんの設定のフォルダー（5.3）は 0:21 に作られ、そこの `userpref.blend` は 0:21 のままです。専用のフォルダーの `userpref.blend` は、今日の 15:45 に書かれたもので、昨夜のものではありません（同じフォルダーに、昨夜 0:32 の、音のライブラリーの cookie だけがある）。昨夜の Blender が、どちらの設定で動いたかは、記録からは決められません。まとめ役の見立ては「ふだんの設定で動いた。何も保存されていない」です。どちらにしても、「昨夜の設定が専用のフォルダーに残っている」とは言えません。その専用のフォルダー（`~/.cache/istesso-try-blender`）は、もう使いません（触ってもいません）。

### Blender のイベントの記録（確かめのときだけ）

- `DAILY_BLENDER_EVENTS=1` を付けて `open blender` したときだけ、Blender を `--debug-events` で起動し、Blender の出力を、ホストの試用版のフォルダーの `run/blender/blender-events.log`（持ち主のアカウントだけが読める）に、1 行ずつ書きます。**打ったキーが残るので、試しのキーのときだけ。人が打つときには使いません。** リポジトリにも、コミットにも入れません。
- この設定は、書き留めません（見張りが開き直すときも、付かない）。付けずに起動した Blender は、記録を書きません。前の記録は、次に付けて起動するまで残ります。
- 前に記録が残らなかったわけ：Blender は、イベントの行を標準出力に書きます。標準出力がファイルのとき、C のライブラリーは、ある量がたまるまで書き出しません。Blender が、たまった分を書き出す前に番号で終わらされる（閉じるよう頼んで 10 秒残ったとき）と、その分は消えます。いまは、`stdbuf -oL` で 1 行ずつ書き出させます（確かめは、下の表）。
- `DAILY_KEY_RECORD`（Wayland のキーの行）も、同じ理由で、書き留めないようにしました。

- Mac の窓の Dock のタイルは、いまは窓ごとに 1 つです（窓 2 枚の形）。ランチャーができたら、`DAILY_DOCK_TILE=none` で、タイルをランチャーの 1 つだけにします。
- 持ち主の Mac に窓が初めて出るときは、まとめ役が、先に知らせます。

## 持ち主が自分で開け閉めするとき（毎日）

持ち主の求め（2026-11-18）：エージェントに頼まずに、毎日、自分で開け閉めできること。

**選んだ形：持ち主のターミナルで打つ、上と同じコマンド。** ランチャーの窓は、まだ作りません。わけ：いまのコマンドが、そのまま使える（今日、持ち主が手で通した形）。新しい包み（アプリ）を登録しない（Mac で新しい包みを登録すると、シェルから起動したプログラムの接続が切れることがあり、2 回見た。ローカルネットワークの問いも、1 つ増える）。ランチャーの窓は、「作る順」の 4 のままです。

使い方（試用版のワークツリー、`trial-daily` のチェックアウトで）：

```sh
scripts/daily.sh                 # いま開いているものと、使い方の 5 行
scripts/daily.sh open blender    # 開く。もう開いていれば、窓を前に出す。窓を閉じていれば、絵を戻して窓を出す
                                 # （窓の赤いボタン：窓だけ閉じる。アプリは動いたまま。数秒で、ホストは絵を止める）
scripts/daily.sh close blender   # アプリを閉じる。まず頼み、10 秒で残っていれば番号で終わらせる
scripts/daily.sh list            # 何が開いているか（アプリ、枠、状態、窓の数、絵、Mac の窓）
scripts/daily.sh stop            # 全部を閉じて、2 台の上の試用版を止める
```

開けるのは `firefox`、`blender`、`editor`（Text Editor）、`chrome`。同時に 3 つまで。

- 前もって：ホストへの、いつもの ssh のログインを、別のタブで開いたままにしておく。閉じていると、`the host could not be reached over ssh` と出ます。
- 計測の合図が `busy` のあいだは、`open` などは始まりません（`a latency measurement is running` と出る）。開いていたものは、いままでどおり止まり、`free` で戻ります。
- **同時に 2 つ動かそうとしたとき**（持ち主とエージェントが、同時に `open` するなど）：2 台それぞれに、鍵が 1 つあります（Mac は `~/Library/Caches/istesso-daily/lock`、ホストは `~/.cache/istesso-daily-wip/run/lock`）。`open`、`close`、`stop`、`setup`、`bundle` は、1 台の上で、1 つずつしか動きません。あとから来たほうは `another command of the trial is running (…): waiting for it, up to a minute` と出して、1 分まで待ちます。空かなければ、何もせずに終わります（`Try again`）。鍵は、コマンドが終われば、落ちたときも、ひとりでに外れます。空いている枠（1〜3）は、ホストの鍵の中で選ぶので、同じ枠を 2 つが取ることも、同じアプリを 2 つ起動することもありません。窓を閉じたことに気づく見張りも、同じ鍵を使います（空いていなければ、2 秒後にもう 1 度見る）。計測の合図で止めるところだけは、鍵を待ちません。
- 止め方は、いままでどおりです：まず頼み、10 秒ほどで残っていれば、書き留めたプロセスの番号で終わらせる。名前では、何も止めません。

**はじめてのときに出るかもしれない問い**（エージェントは、どれも出していません）：

1. ターミナルの「ローカルネットワーク」：中継（`istesso input relay`）は、打ったターミナルから起動され、LAN の上のホストへつなぎます。そのターミナルが、まだ LAN に出たことがなければ、macOS が 1 度だけ尋ねるかもしれません。持ち主は、そのターミナルから、ホストへの ssh をいつも使っているので、出ない見込みです。許可しないと、キーとマウスが届きません（`keyboard and mouse: NOT passed on` と出る）。
2. 窓の包み（`Istesso Dev Daily Viewer`）の「ローカルネットワーク」：今日、持ち主が許可しました。包みを作り直さないかぎり、もう出ません（`setup` か `bundle` をやり直して `bundle --finish` したときは、また出る）。
3. 画面収録、アクセシビリティ、入力監視：出ません。窓は、自分の窓の中のキーとマウスだけを受け取ります。
4. ターミナルを閉じても、窓、中継、見張りは動き続けるはずです（ターミナルの切断の合図を受けない形で起動する。コードから。確かめていない）。止めるのは `close` か `stop` です。

## ランチャー（A の最初の一歩）※まだ作っていない

- 窓 1 枚。上に、開けるアプリ（Firefox、Blender、Text Editor、Chrome）。下に、開いているものと、その状態（映している／窓を閉じた（アプリは動いている）／閉じるよう頼んだ／計測のために止めている／戻せなかった）。行ごとに「前に出す」と「閉じる」。下の端に、気づきを書く欄。
- **Dock のタイルは、ランチャーの 1 つだけ**にします（A の形）。アプリの窓のプロセスは、Dock に出ない形（`accessory`）で起動します。そのためのビューアーの切り替え（`ISTESSO_DOCK_TILE=none`）は、このブランチに足してあります。
- 切り替え：窓をクリックする。ランチャーの行をクリックする（`open` と同じ。ビューアーに USR2 を送ると、窓が前に出る）。キーでの切り替え（⌘Tab のようなもの）は、最初の版には、ありません（宿題）。
- ランチャーは、包みではなく、シェルから起動するプログラムです。Dock のアイコンは、当面、ふつうのプログラムの絵です。
- 本当の A（`Istesso.app` 1 つが、全部の窓を持つ）は、自前のクライアントが、1 つのプロセスで複数の窓を持てるようになってからです。

## 終わらせ方

持ち主の決め：**まず頼む。10 秒ほどで残っていれば、番号で終わらせる。**（Blender は、ていねいに終わったときだけ、設定を保存するため）

- 「閉じる」は、パイプラインに `close` と言います。コンポジターが、アプリの全部の窓に、閉じるよう頼みます（窓の閉じるボタンと同じ `xdg_toplevel.close`）。
- 10 秒のうちに、アプリのプロセスが全部いなくなれば、「頼んで終わった」。残っていれば（保存するかを尋ねている、など）、アプリのセッションのプロセスに SIGTERM、2 秒で残ったものに SIGKILL。**保存していないものは、なくなります。** どちらになったかと、パイプラインが `empty` と言ったかを、1 行で言います。
- そのあとで、パイプライン（SIGINT、4 秒で残れば番号で）、試用のエージェント、Mac の窓と中継を、番号で止めます。
- `stop` は、開いている全部に、同時に頼みます（待つのは、全部で 10 秒）。
- Mac の窓の赤いボタンは「窓だけ閉じる」です。ビューアーが終わり、**アプリは動き続けます**（止めない。終わらせない）。2 秒ほどで Mac の見張りが気づき、ホストのパイプラインに `detach` と言います（計測の合図のときと同じ言葉）：**絵を止め、エンコーダーを手放します。** その窓の中継も、番号で止めます。`list` には `picture paused`、`window closed` と出ます。`open` で、ホストに `resume` と言い、エンコーダーが開いたこと（`resumed`）を確かめてから、窓を出します。
  - 見張りが ssh をするのは、合図が `free` のときだけで、6 秒で打ち切ります（そのあいだに `busy` になっても、10 秒以内に従える）。ホストに届かなかったときは、2 秒ごとにやり直します。
  - 見張りは、「ビューアーは終わったのに、中継は動いている」ものだけを、赤いボタンで閉じた窓と見ます。試用版が自分で止めた窓（`close`、`stop`、計測の合図）は、そう見ません。

| 7. 計測の道に触れていない | 変えたファイルは `scripts/daily.sh` と、この文書だけ。`scripts/m1-step3-host.py` は、このブランチのものも、ホストの試用版の写しも、前と同じ中身（SHA-256 の頭 `b9acf2eb`）。計測が使う写し（`m1-latency` のもの、ホストの計測の作業フォルダーのもの）は、別のファイルで、試用版は読みも書きもしない（ホストの計測の写しの更新時刻は 11 月 17 日のまま）。パイプラインに、新しい言葉もフラグも足していない（窓を閉じたときは、前からある `detach` と `resume` を使うだけ）。計測のスクリプト（`m1-*.py`、`measuring.sh`、`try.sh`）は `daily` を含まない | 通った |

途中で見つけて、直したもの：

- アプリの起動の中で、言葉を日本語にしたあとに、プロセスの起動時刻を書き留めていた。`ps` が日本語の日付を書くので、照らし合わせが合わず、「アプリが残らなかった」と誤って言った（アプリは動いていた）。起動時刻は、`LC_ALL=C` で書くようにした。アプリの終わり方を書くファイル（`app.exit`）が、前の回のまま残っていたので、起動のたびに空にする。
- Firefox を、最初は `keyfile` で起動した。snap が `XDG_CONFIG_HOME` を替えるので、snap の中のフォルダー（持ち主のふだんの Firefox と同じ所）に、空のフォルダーが 2 つ（`glib-2.0/settings`）できた。ファイルはなかった。この確かめで作ったものなので、消した。Firefox は `memory` にした。

## 危うさ

- **エンコーダーの数**：このホストのカードとドライバーでは、同時に開けるのは、PC 全体で 12。試用版は、アプリ 1 つにつき 1 つ使います（多くて 3）。ふだんの試用のパイプライン、ほかの流れの試験、机の人の録画も、同じ 12 の中です。断られたときは、パイプラインが `refused` と言い、その窓だけ「戻せなかった」になります。
- Mac の窓を赤いボタンで閉じると、2 秒ほどで、エンコーダーを手放します（2 回目から）。Mac の見張りが動いていないとき（たとえば、Mac が眠っていた、ホストに届かない）は、届くまで手放しません。
- **エンコーダーを数える `nvidia-smi --query-gpu=encoder.stats.sessionCount` は、このカードとドライバーでは、試用版のエンコーダーを数えません**（絵を作っているときも 0。`nvidia-smi -q -d ENCODER_STATS` も `Active Sessions: 0`）。手放したかは、パイプラインの `paused` の行と、`nvidia-smi pmon -s um` のプロセスごとの `enc` とフレームバッファで見ます。
- **机のセッションバスから、切り離せていません。** アプリから `DBUS_SESSION_BUS_ADDRESS` を外しても、GLib は、`$XDG_RUNTIME_DIR/bus` にあるバスへ、自分でつなぎます。Text Editor は、机のセッションバスにつながっていました（`busctl --user list` で見た）。ポータルの問いや鍵束の問いが机に出る道が、まだあります（いま知っているものは、`GTK_USE_PORTAL=0` と Chrome の `--password-store=basic` で塞いでいる）。設定の書き込みは、`GSETTINGS_BACKEND`（`keyfile` か `memory`）で、持ち主の dconf には行きません。バスを切るか（アプリによっては、バスがないと起動しない）は、まとめ役と決めます。
- 試用版の Blender は、持ち主のふだんの設定の写しで動きます。写したあとに、ふだんの Blender で変えた設定は、試用版には入りません（写し直すときは、上の「Blender の設定」）。
- **絵は、次の 1 枚が来たときに止まる。** 何も描かないアプリでは、`detach` の答えが来ないことがありえます（今日の 3 つは、どれも 33 ms 以内に答えた。Blender も）。そのときは、見張りの行が「止まったと言わなかった」と言い、プロセスは止めます（エンコーダーは開いたまま）。
- **GPU のメモリー**：24 GB のうち、朝の時点で使っているのは 1 GB ほど。セッション 1 つがどれだけ使うかは、測っていません。
- **修飾キーが Blender で効かない**件は、別の流れが調べています。2 回目の確かめで、試用版の入力の口に書いた試しの Shift＋A は、Blender に `modifier={SHIFT}` の付いた A として届いていました（Blender のイベントの記録で見た。人の手の Mac のキーボードからの道は、通していない）。直ったら、ホストの写しとプラグインを替えるだけで、試用版に入ります。コンポジターの流れは、`trial-windows` の修正を、見直しのあとで直しています。直ったビルドができたら、`DAILY_PLUGIN_FROM` でそこを指して、`setup` をやり直します。
- 中継は、シェルから起動します。Mac で新しいアプリが登録されると、シェルから起動したプログラムの接続が切られることがあります（持ち主の Mac で 2 回見た）。中継は、切れたらつなぎ直します（コードから。今日は、切れるところを見ていない）。包みを `--finish` して初めて起動するときも、登録が起きます。そのとき動いている、シェルから起動したプログラム（昨夜の `try.sh` の窓と中継を含む）が、切られるかもしれません。
- Mac のビューアーと中継は、計測のビルドではありません。**遅延は、判定の値ではありません。** 感じを見るためのものです。
- ホストの机には、人がいます。画面にも、音にも、何も出しません。試用のアプリは、隠れたコンポジターの中だけで動きます。
- Text Editor は、番号で終わらせると、打ちかけの文を下書きとして、試用版のフォルダーに残します（今日の確かめで残ったものは、消しました）。次に開くと、それが出ることがあります。
