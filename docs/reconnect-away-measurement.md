## (a) 狭い形：Istesso のポートだけを、N 秒、捨てる

**仕組み。** 自分だけのテーブル（`inet istesso_away`）に、ポートの集まりを置き、そのポート宛てに来るパケットと、そのポートから出るパケットを、捨てる（断らない。黙って捨てる）。集まりの中身には、**カーネルの中の期限**（N 秒）を付ける。期限が来ると、カーネルが中身を消し、決まりは、何にも当たらなくなる。**戻すことが、起動したシェルにも、ssh にも、タイマーにも、寄りかからない。** 30 秒あとに、空になったテーブルを、systemd のタイマーが片づける（片づけに失敗しても、通信は、もう通っている）。ホストを再起動しても、消える。

- **測るもののポートを入れる。** 前の確認（[記録](measurements/2026-11-17-reconnection-check.md)）と同じく、この計測のためのエージェントとパイプラインを、**ふだんとは別のポート**で動かせば、持ち主の試している窓（47801、47803）と、夜の音（47822）には、1 つも当たらない。下の例は、そのポートを 47811（エージェント）、47813（映像）とした。
- **口は、有線と無線の両方を書く。** 持ち主は「有線の口で」と言ったが、上の表のとおり、2 つの口は同じネットワークにあり、ホストは、有線のアドレス宛てのパケットを、無線の口で受けることがありうる。有線だけに絞ると、捨てたつもりの通信が、通りうる。ssh（22 番）は、ポートで絞っているので、どちらの口でも当たらない。

**持ち主が実行する 1 行**（`N` は秒：60、3600。`P` は、捨てるポート）：

```sh
sudo sh -c 'N=60; P="47811, 47813"; date +%s.%N; nft "add table inet istesso_away; add set inet istesso_away away_ports { type inet_service; flags timeout; timeout ${N}s; }; add element inet istesso_away away_ports { $P }; add chain inet istesso_away arriving { type filter hook input priority -300; policy accept; }; add chain inet istesso_away leaving { type filter hook output priority -300; policy accept; }; add rule inet istesso_away arriving iifname { enp5s0, wlp7s0 } tcp dport @away_ports counter drop; add rule inet istesso_away leaving oifname { enp5s0, wlp7s0 } tcp sport @away_ports counter drop" && date +%s.%N && systemd-run --quiet --collect --unit=istesso-away-tidy --on-active=$((N+30)) /usr/sbin/nft delete table inet istesso_away'
```

- 出る 2 つの数（1970 年からの秒）のあいだに、決まりが入った。**道が開く時刻は、その N 秒あと**（ホストの時計で）。
- `nft` の行は、全部が入るか、何も入らないか、のどちらかである。テーブルがまだ残っているとき（片づけの前に、もう 1 度実行したとき）は、断られて、何も変わらない。
- ほかのテーブル（Docker、Tailscale）には、触れない。足すのも、消すのも、`inet istesso_away` だけである。

| したいこと | 行 | 見えるもの |
|---|---|---|
| 入っていることを見る | `sudo nft list table inet istesso_away` | ポートごとに `expires 41s…`（残り）。2 つの決まりの `counter packets …`（捨てた数） |
| 途中でやめる | `sudo sh -c 'nft delete table inet istesso_away; systemctl stop istesso-away-tidy.timer'` | すぐ通る |
| なくなったことを見る | 同じ `list` の行 | N 秒あと：ポートが 1 つもない（決まりは、何にも当たらない）。N＋30 秒あと：`No such file or directory` |
| 何もしない | — | **N 秒で、ひとりでに通るようになる。** 30 秒あとに、テーブルも消える |

**はじめに、5 秒で試す**（行が、このホストの `nft` で通ることを見るため。だれも使っていないポートで）：上の行の `N=60; P="47811, 47813"` を `N=5; P="47999"` に替えて実行し、`list` の行で、5 秒あとにポートが消えるのを見る。

## (b) (a) では見えないこと

(a) のあいだも、ホストは、LAN の上にいる。Mac が「このアドレスの機械は、どれか」と聞けば、答える。**Mac の OS は、ホストがいなくなったことを、知らない。** だから、ADR 0007 が分からないとしたこと（OS が、いなかったホストへの送信を、どれだけ速く始め直すか）は、(a) では測れない。(a) が測るのは、こちらの試みの間隔と、締め切りの働きである。

- 1 分では、差は出ない見込み（確かめていない）：Mac は、1 分前に覚えたホストの機械のアドレスを、まだ使う。
- 1 時間では、違う：ケーブルが抜けていれば、Mac は、覚えを捨てて、聞き直す。(a) では、聞き直しに、ホストが答え続ける。

**2 つめの形（有線の口を、N 秒、落とす）は、ssh 越しには、勧めない。** 書いておくと：

```sh
sudo sh -c 'N=3600; systemd-run --quiet --collect --unit=istesso-link-back --on-active=$N /usr/bin/nmcli device connect enp5s0 && date +%s.%N && nmcli device disconnect enp5s0'
```

（戻すタイマーを先に置いてから、落とす。早く戻すには `sudo sh -c 'nmcli device connect enp5s0; systemctl stop istesso-link-back.timer'`。`ip link set down` ではなく `nmcli` を使うのは、アドレスも外すためである。アドレスが残ると、無線の口が、有線のアドレスへの問い合わせに答えてしまう。）

そのあいだ、持ち主が失うもの：

- **ホストの既定の経路**（有線）。無線に移る。Tailscale と Docker の通信も、移るか、切れる。有線を通っている接続は、切れる（いま 11 本。夜の音の計測も、試している窓も）。
- **ssh が切れないとは、言えない。** ssh の返事は、いま、有線から出ている見込みで、落とした瞬間に無線へ移る。Mac が覚えているホストの機械のアドレスが、有線の口のものなら、Mac が聞き直すまで、ssh は止まる。読むだけでは、どちらか分からない。
- 戻すのは、systemd のタイマーである。(a) のような、カーネルの中の期限ではない。タイマーが動かなければ、有線は、だれかが戻すまで（または再起動まで）、落ちたままになる。
- 戻ったあと、アドレスをもらい直すのに数秒かかる。「道が開いた」時刻は、口が上がった時刻ではなく、NetworkManager がつなぎ終えた時刻で読む。

**勧め：OS の問いは、ケーブルを抜ける日に残す**（ホストの側で抜く。持ち主が、ホストの前にいる日）。抜き差しの時刻は、ホストのカーネルの記録で読める。上の行は、その日に、手で抜く代わりに使える（時間が正確になる）。今回は、(a) だけを、1 分と 1 時間で測る。

## (c) 計測のしかた

**前の日までに**（いまは、していない）：道具に、時刻と回数を書かせる。入力の中継（`istesso input relay`）は、切れた時刻と戻った時刻を、もう書く（`unix_ns`）。足すもの：窓のない見る側（`picture stay`）の行に 1970 年からの時刻、両方の「戻った」の行に、試みの数（このブランチには `tries()` がある）。**本線のコードには、試みの数がない。** 本線の回では、ホストの決まりの `counter`（捨てたパケットの数）で比べる。

**Mac で、前に始めるもの**（前の確認と同じ形。鍵とペアリングは、この計測のためのもの）：

1. ホストで：この計測のためのエージェント（47811）と、映像のパイプライン（47813）。ホストの記録の行に、時刻を付ける。
2. Mac で：`picture stay`（窓なし）と `istesso input relay`。どちらも、ホストの有線のアドレスへ。シェルから起動する（Mac のアプリが新しく登録されると、接続が切られることがある。そういう切れが混じった回は、切れた回数が 1 でないので、分かる。その回は、捨てる）。
3. 時計のずれ：Mac から、開いたままの ssh で、ホストの時刻を 10 回聞き、往復が最も短かった回で、ずれを出す（誤差は、その往復の半分）。**計測の前とあとの、2 度。**
4. 2 台の合図（`measuring`）が `free` で、夜の音の計測が動いていないことを見る。
5. 持ち主が、(a) の 1 行を実行する。

**あとで読むもの：**

| 値 | 出どころ |
|---|---|
| 道が開いた時刻 | (a) の行が出した数＋N（ホストの時計）。Mac の時計に直すのに、ずれを使う |
| 切れたと分かった時刻、つながった時刻 | Mac の道具の行（映像：`Cut`、`Connected`、最初のキーフレーム。入力：`cut`、`back`） |
| **道が開いてから、つながるまで** | 上の 2 つの差。映像、入力、（あとで）音のそれぞれ |
| ずれを使わない確かめ | ホストの記録の「映し始めた」の行の時刻と、道が開いた時刻の差（どちらも、ホストの時計） |
| 試みの数 | このブランチ：道具の行。本線：なし。両方：ホストの `counter`（決まりを片づける前に `list` で読む） |
| 切れた回数 | 道具の行。1 でなければ、その回は使わない |

**回：** 1 分と 1 時間。それぞれ、本線のコード（`origin/main`）と、このブランチ（`reconnect-within-a-second`）。1 分は、3 回ずつ（道が開く時刻が、試みの間隔のどこに当たるかで、値が動くため）。1 時間は、1 回ずつ。音は、音に入れたあとで、同じ形で足す。

**見込み（測る前に書いておく）：** このブランチは、道が開いてから 0.5 秒あまりまで。本線は、ホストが 10 秒いなかったあとは、試みの 1 回（締め切りまでの 1 秒）と、次までの待ち（1 秒）で、2 秒おきになるので、2 秒ほどまで。これは、(a) の形での話で、OS の問い（(b)）は、入っていない。
