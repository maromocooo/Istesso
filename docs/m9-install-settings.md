# M9 インストーラーが整える設定

Ubuntu は署名付きリポジトリの .deb、Mac は署名と公証を通した pkg で配る。初回起動で利用者の操作が要る設定もここに載せる。権限の欄は、その設定を導入するときのもの。根拠は [要件 R-05、R-12][req] と [進め方の M9][milestones]。

表の読み方

- 「決定」は要件か採用済みの方針。「提案」は計画や ADR にある採用前の案。「未決」は方法や要否が決まっていないもの。
- 「見込み」は出典が示した見通し。「推測」は出典をもとにこの表で補った判断。「未確認」はまだ確かめていないこと。「記載なし」は出典に説明がないこと。
- 「試験値」は実機試験で使った設定値。「現行の接続先」は今の実装が使うポート。

## 両 OS で共通の設定

| 設定と理由 | 導入時の権限 | 状態と出どころ |
|---|---|---|
| 専用ユーザーを作り、そのホームを隔離領域にする。アプリ、herdr、コーディングエージェントをそこで動かし、ふだんのホームを読めないようにする。 | Ubuntu は root、Mac は管理者 | 隔離は決定。[要件 R-06、R-07][req]、[ADR 0003「決定」][isolation]。作成時の権限は [ADR 0014「権限の要るものと、その理由」][account]。 |
| ホストのエージェント、ランナー、音の取り込みも専用ユーザーで動かす案。ふだんのユーザーはクライアントの役を持つ。専用ユーザーには管理者、sudo、Docker の権限を渡さない。専用ユーザーの名前は未決。同名の既存ユーザーがあれば導入を止める。削除時は専用ユーザーとホームを残す。 | ユーザー作成時に root または管理者。実行時の特権は不要 | 提案。[ADR 0014「提案」1〜8][account]、[M5 計画 10.2 の 5][m5]。 |
| 入れないもの。専用ユーザーでホストを動かす案では、root で動き続けるプログラム、パスワードなしの `sudo` の規則、ユーザーを切り替えるための特権付きプログラムを置かない。 | 実行時の特権は不要 | 提案。[ADR 0014「権限の要るものと、その理由」][account]。 |
| 隔離領域に印 `.istesso-area` を置く。一覧に出すファイルは `files/`、受け取るものは `inbox/` に置く。端末の鍵とペアリング一覧は共有の外に置く。 | ユーザー作成後、一覧と名指しのコピーには不要 | 提案。マウントは方式も権限も未決。[ADR 0013「比べる案」「何を、どこに置くか」][storage]。 |
| 手元の OS で開けないインストーラーを Istesso で「開く」ように登録する。例えば Mac で .deb を開くと、Ubuntu に渡せる。行き先の sudo や Gatekeeper の確認は残す。 | ファイルの種類を登録する権限は記載なし | 振り分けは決定。「開く」を入口にするのは M5 の方針。[要件 R-05][req]、[M5 計画 9、10.1][m5]。 |
| コーディングエージェントのサンドボックスを OS の権限と併用する。専用ホームにひな形を置き、端末の鍵やペアリング一覧を読み取りの対象から外す案。 | ひな形は不要 | 二重の柵は決定。ひな形は提案。[ADR 0003「決定」][isolation]、[ADR 0014「二重の柵」][account]。 |
| herdr を専用ユーザーに入れ、手元からは herdr の SSH 接続を使う。ペアリングを解除しても、この接続は切れないことを伝える。 | SSH の鍵を置く手順で管理者が要るかは未確認 | 接続方法は決定。専用ユーザーへの入口を足す手順は M5 と ADR を待つ。[M6 計画 5.4、6.2 の 9、7][m6]。 |
| 映像の窓を閉じても音が続くように、音を独立した常駐サービスにする。再生中はホストを眠らせない。DAC のある PC でのローカル再生は OS の標準経路を保つ。 | 音サービス固有の登録に root が要るかは記載なし。ユーザーサービスの登録は下記 | 決定。[要件 R-08][req]、[ADR 0005「決定」「手を入れない経路」][audio]。 |

### 通信とファイアウォール（両 OS）

| 用途 | 文書にある接続先と理由 | 導入時の権限と状態 |
|---|---|---|
| ペアリング、制御、入力 | ペアリングは TCP 47800。ペアリング後は、制御と入力を TCP 47801（既定）で受ける。 | 現行の接続先。ペアリングのエージェントへの統合は未決。ポートのための OS 設定や root の要否は記載なし。ペアリングの TCP は [ADR 0006「既知の不足」][pair]。47800 は [ADR 0007「既知の不足」][control]、47801 は [同「通信路」][control]。 |
| 音と映像 | 音は TCP 47802、映像は TCP 47803（既定）。接続を分けると、大きな映像フレームが入力を待たせない。 | 現行の接続先。音・映像・入力を一つのポートに寄せるかは M9 で決める。同じ PC でエージェントを二つ動かす場合のポートも未決。導入時の root の要否は記載なし。[ADR 0015「音と入力にとって」][media]、[ADR 0014「既知の不足」][account]。 |
| LAN 内の自動発見 | エージェントは mDNS で `_istesso._tcp` を広告し、相手の広告を聞く。信頼できないネットワークでは `istesso agent --no-discovery` で発見を止める。出先からは VPN 経由に限る。 | 発見方法は決定。**推測**：通信を遮るファイアウォールがあれば、使う役に応じて通す必要がある。インストーラーが例外を追加するか、その規則と権限は未決。[ADR 0007「発見とアドレスの記憶」「既知の不足」][control]、[要件 R-13][req]。 |

## Ubuntu（.deb）

ホストはデスクトップに誰もログインしていなくても応答する。LUKS を使う PC は、人がディスクを解除するまで OS が起動しない。導入時にこの制約を伝える。[進め方「受け入れ条件に足すもの」][milestones]、[M5 計画 4.4][m5]、[M6 計画の条件 H][m6]。

| 設定と理由 | 導入時の root | 状態と出どころ |
|---|---|---|
| 専用ユーザーをログイン画面に出さず、パスワードでのログインを無効にする。ふだんのホームが読める場合は本人に尋ねる。 | 専用ユーザー作成は必要。ふだんのホームを直すなら本人が行える | 提案。[ADR 0014「Linux での作り方」「権限の要るものと、その理由」][account]。 |
| `istesso agent` を systemd のユーザーサービスに登録する。専用ユーザーに linger を設定し、ログイン前から起動できるようにする。端末の鍵も、ログイン前に専用ユーザーが読める場所に置く。 | ユーザー内のサービス登録は不要。linger は必要 | 常駐化は M9 で行うと決定。専用ユーザー、linger、鍵の置き方は提案。[ADR 0007「既知の不足」][control]、[ADR 0014「提案」3、「権限の要るものと、その理由」][account]、[M5 計画 4.4][m5]。 |
| GPU のレンダーノード（`/dev/dri/renderD*`）をエージェントのユーザーが開けるようにする。仮想コンポジターはこれで描画する。再起動試験では `render` だけで動き、`video` の画面出力ノードは不要だった。NVIDIA のエンコーダーの口もその実機では既に開けた。 | グループへの追加は必要。コンポジターの実行は不要 | 描画の口へのアクセスは決定。[ADR 0009「比べる案」の権限][compositor]。[再起動の記録「見つかったこと 1」][restart] では、.deb は実行ユーザーが分からないため、追加用のコマンドを表示するだけにする。[ADR 0014「Linux での作り方」「権限の要るものと、その理由」][account] の案では、インストーラーが専用ユーザーを作る。これで追加先が決まるので、インストーラーが root でそのユーザーをグループに入れる。どちらを採るかは未決。ADR 0014 の採用を待つ。 |
| NVIDIA のモジュールが**次に起動するカーネル**用にあるか確かめる。なければ、再起動すると映せなくなると伝える。カーネル更新後も再起動前に `istesso doctor` で確認できるようにし、導入文書に書く。 | M1 の実機で起動設定を読むには root が必要だった。製品での確認方法は未決 | 確認と案内は決定。DKMS の自動導入は決まっていない。[進め方「インストーラー（M9）と、ホストの準備で気を付けること」][milestones]、[M1 計画「ホストを再起動したあとに、確かめ直すこと」][m1]。 |
| キーボードとマウスの入力はコンポジターへ直接渡す。`uinput` の機器や権限を追加する設定は要らない。 | 不要 | 決定。ゲームパッドが要るときに再検討する。[ADR 0009「提案」の B の進め方][compositor]。 |
| Stream Deck の直接制御用に、アダプターが名乗る機器 ID から作った hidraw の udev 規則を同梱する。エージェントのグループに読み書きを許す。`uaccess` だけではログイン前に開けない。 | 規則の導入とグループ変更は必要。実行時は不要 | グループで許可する方針は決定。M7 の規則は `0660` と `plugdev`。製品のグループは M5 と合わせて決める。機器を一覧するだけなら sysfs を読める。[ADR 0012「決定」9][devices]、[ADR 0004「権限と、使う人の手間」][usb]、[M7 計画の手順 5 と 5 章][m7]。 |
| 会議アプリがログイン前にカメラとマイクを開けるようにする。実機ではカメラの口は `video`、音の口は `audio` が持ち、机でログインした人は `uaccess` で使えていた。 | グループに権限を与えるなら必要 | ADR 0004 の見込みでは、カメラにはグループ向けの規則が要る。音の権限は M2 で決める。[ADR 0004「ホストの前に誰もいない状態」][usb]、[ADR 0014「権限の要るものと、その理由」][account]。 |
| PipeWire でアプリの音を取り込み、再生する。専用ユーザーの PipeWire から取り込み、スピーカーや DAC を使う出口はふだんのユーザーで動かす案。 | ユーザーごとの音の設定に root が要るかは記載なし | PipeWire は決定。取り込みと出口を動かすユーザーは提案。[ADR 0005「部品」][audio]、[ADR 0014「Linux での作り方」][account]。 |
| 音の優先度の上限（rlimit）。ログイン前でも PipeWire がリアルタイム優先度を得られるよう、試験では対象ユーザーに `rtprio 95`、`nice -19` を `/etc/security/limits.d/50-istesso-rt.conf` で許した。固定できるメモリの上限は変えていない。 | この設定ファイルを置くには必要 | 試験値。優先度が上がったことは確認済み。音切れは変更前も 0 で、効果と製品の既定値は未決。[再起動の記録「置いた 3 つの設定」「音」][restart]。 |
| 映している間だけ CPU の深い眠りを抑える候補。試験では udev で `/dev/cpu_dma_latency` を対象ユーザー所有の `0600` にした。開くと電力と熱が増える。 | この udev 規則を置くには必要 | 未決。試験ではどのプログラムもこの口を使っておらず、効果は未確認。[確定の判定の計画 3][m1final]、[再起動の記録「置いた 3 つの設定」「確かめていないこと・限り」][restart]。 |

## Mac（pkg）

初回起動では署名したアプリが、必要な許可の理由と「システム設定」の場所を示す。許可は人がその Mac で出す。更新後も許可が残るよう、同じ署名を使う。[要件 R-12、6.3][req]、[ADR 0017「守ること」「結果」][mac]。

| 設定と理由 | 導入時の root・管理者認証 | 状態と出どころ |
|---|---|---|
| 専用ユーザーを標準ユーザーとして作る。ふだんのホームの直下を読めないよう、まず `staff` とは別のグループを試す。足りなければ、本人に尋ねてホームを `700` にする案。 | 作成は管理者。本人のホームの変更は管理者不要 | 提案。[ADR 0014「macOS での作り方」「権限の要るものと、その理由」][account]。 |
| 人がふだん使う Mac はクライアント専用にする。ふだんのユーザーがログインしている間に、別のセッションから配信できるかは未確認。 | クライアント専用にするための権限は不要 | 提案。M4 で確認できたら見直す。[ADR 0014「macOS での作り方」][account]。 |
| エージェント、取り込み、入力、音を launchd でログイン時に起動する。GUI アプリにはログイン済みのセッションが要る。再起動後は人が一度ログインする。FileVault は有効のまま使う。自動ログインは説明だけにする。 | ユーザー内の登録と案内は不要 | ログイン時の起動と制約の案内は決定。専用ユーザーのセッションへの登録は提案。ロック中とスリープ復帰直後が受け入れ条件。[M4 計画 4.4][m4]、[ADR 0007「既知の不足」][control]、[ADR 0014「macOS での作り方」][account]。 |
| 「画面収録とシステムオーディオ録音」を案内する。ScreenCaptureKit で配信対象のアプリの窓を読むため。 | 本人がその Mac で管理者認証をして許可する | 決定。[ADR 0017「決定」「結果」][mac]。 |
| macOS が画面収録の許可を定期的に確かめ直すことがある。無人のホストでは確認に応える人がおらず、その間は映像が止まるおそれがある。 | 再確認には人の操作が要る | 決定。M4 の手順 1 で確認画面が出たら、使う人向けの文書に既知の制約として書く。画面収録を保ち続けるための Apple への許可申請は持ち主の作業一覧に載せ、その時点で申請する。[ADR 0017「採用の条件」2、「結果」][mac]、[M4 計画 3.6、6.1 の 7][m4]。 |
| 「アクセシビリティ」を案内する。対象のアプリにキーとマウスの入力を届け、窓を前に出し、位置や大きさを変えるため。 | 本人の操作と管理者認証 | 決定。入力を届けるための「入力監視」は不要。[ADR 0017「決定」「結果」][mac]。 |
| 音を配信するホストには「システムオーディオ録音のみ」を案内する。Core Audio のタップで音を取る。仮想ドライバーは不要。録音の理由を示す説明文（`NSAudioCaptureUsageDescription`）が要るため、取り込みプログラムはアプリの形（バンドル）にする見込み。 | 初回の録音時に本人が許可。専用セッションでの管理者認証は ADR 0014 の案 | 許可と取り込み方式は決定。[ADR 0017「決定」][mac]、[ADR 0005「部品」][audio]、[M4 計画 3.6][m4]、[ADR 0014「権限の要るものと、その理由」][account]。 |
| ホストと受信側で「ローカルネットワーク」を案内する。アプリや launchd のエージェントが LAN で相手を見つけ、接続するため。 | ユーザーごとに本人が許可。root での設定は記載なし | 決定。[ADR 0017「決定」][mac]、[M4 計画 3.6][m4]。 |
| 入れないもの。Mac ホストは画面の取り込み、入力、音のために root、フルディスクアクセス、入力監視、マイク、カメラの許可を求めない。 | いずれも不要 | 決定。[ADR 0017「決定」][mac]。 |
| Apple 向けのビルドと署名を専用ユーザーで行う場合は、そのユーザーのキーチェーンに署名用の証明書を入れる。 | 証明書の登録に管理者認証が要るかは記載なし | 決定。専用ユーザーに渡す証明書は必要なものに限る。[ADR 0003「結果」][isolation]、[M6 計画 7][m6]。 |
| 配信中はホストのスリープを抑え、使っていない間は眠れるようにする。ネットワーク経由で起こす設定を案内する。 | 配信中の抑止と案内は不要 | 音の再生中にホストを眠らせないことは決定。配信中の抑止とネットワークから起こす設定の案内は提案。[要件 R-08][req]、[ADR 0005「決定」][audio]、[M4 計画 4.4][m4]。 |
| Stream Deck の直接制御に別の許可が要るか。実機では機器を開けたが、許可の表示の有無は確認できていない。 | 未確認 | 未決。入力監視を製品の既定の許可に含める根拠はない。[ADR 0004「権限と、使う人の手間」][usb]、[機器の実機記録「確かめたこと」][deck]。 |
