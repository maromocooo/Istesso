# 要件

この文書が要件の正本です。変更するときは、理由を `docs/adr/` に残してください。

## 1. 目的

手元にある複数の PC を、台数を意識せずに1つの環境として使えるようにする。

- アプリが「どの PC に入っているか」を意識しない。入っていれば使える。
- 自宅では実機（Mac、Ubuntu）から、出先では XR グラス（XREAL AURA）から、同じ窓に戻れる。
- 再現できる形で OSS として公開する。

## 2. 成功の基準

**「これはリモートにつながっている」と感じる場面があれば失敗。**

- 対象は自宅の有線 LAN。合格ラインは、追加遅延（入力から画面が変わるまでの時間のうち、中継が足した分）を、手元の窓と比べた差で定義する。2台とも有線、85 Hz のディスプレイ、3440×1440 の絵、文字がスクロールする画面で、中継した窓と手元の窓の差が、中央値で 12 ms 以下、95 パーセンタイルで 24 ms 以下、99 パーセンタイルで 47 ms 以下（2026-11-16 に決定。測り方と経緯は [ADR 0002](adr/0002-latency-first.md)）。
- 出先（インターネット越し）は回線の往復とゆらぎが乗るため、この基準の対象外とする。目標は「快適に作業できること」。
- 音は、何時間流しても途切れないこと。

## 3. 想定する環境

| 役割 | 機器 | メモ |
|---|---|---|
| 常時稼働のホスト | Mac Studio | Mac アプリの置き場所。Xcode ビルド |
| GPU ホスト | Ubuntu（RTX 4090） | GPU 処理、Linux 専用アプリ |
| 任意参加 | MacBook Air | 持ち運ぶ。スリープするので常時ホストにはしない |
| 出先の端末 | XREAL AURA（Android XR） | VPN 越しに自宅へ接続 |
| 将来 | Windows | ゲーム用途。今回の公開には含めない。次の大きな目標とする（2026-11-16 に決定） |

## 4. 必須要件

### R-01 つなぎ方の優先順

遅延の小さい順に使い分ける。

1. 手元の PC で動くものは手元で動かす（Mac アプリ、ブラウザ）。同期するのは状態だけ。
2. 文字はターミナルで直接つなぐ（rio + herdr。herdr のセッションはホスト側に常駐）。
3. 残りだけを映像で中継する。

### R-02 映像の中継

- 有線、120 Hz、ハードウェアエンコード。
- カーソルと窓の移動・リサイズは手元側で描く。
- アプリごとに仮想ディスプレイを割り当てる（1アプリ = 1仮想ディスプレイ = 手元の1窓）。
- 配信の種類を2つ持つ：アプリ窓（絶対座標、手元カーソル）とゲーム（相対マウス、ゲームパッド、全画面）。後者は Windows 対応のために語彙だけ先に用意する。
- 遅延を常時計測して表示できること。

### R-03 同じ画面に戻れる

- 窓はホスト側で生き続ける。端末は接続し直すだけ。
- 出先でも続きをやりたいアプリは、常時稼働のホストか GPU ホストに置く。

### R-04 アプリマネージャー

- 全 OS を横断して、同じアプリは1つのアイコンにまとめる。
- 一覧は手元に保存する。停止中のホストにしかないアプリには「！」を付け、可能なら「起こす」操作を出す。
- 起こす手段（Wake-on-LAN など）は差し替え式。出先からは常時稼働のホストが代わりに起こす。
- 起動先は「手元 → 起きているホスト → 負荷の低いホスト」の順で自動選択する。
- ただし、次の2つを先に見る（R-09、[ADR 0004](adr/0004-usb-devices.md)）。USB 機器を使うアプリは、その機器を受け取れるホストを優先する。同じアプリが Mac と Linux の両方にあるとき、機器を使うなら Linux の側で開く。会議アプリは、マイクとカメラがつながっている PC で開く。
- 寄せるのは、分かっているときだけにする。分からないときは、今までどおり手元で開く。項目ごとに、どの PC で開くかと、その理由が分かり、使う人が指定し直せる。
- 機器のために選ばれた PC が止まっているときは、「！」と「起こす」操作を出す。自動では、ほかの PC で開かない。
- ホストで開くアプリは、持ち主の机のログインと同じ設定で開く。言語、入力方式、見た目（テーマ）、フォント、フォントの大きさ（2026-11-18 に持ち主が依頼。M3）。
  - エージェントは、これらの設定を、机のセッションか、持ち主のアカウントの設定から受け取る。
  - アプリが持ち主のふだんのプロファイル（ブラウザーのログイン、Blender の設定）を使うかどうかは、アプリごとに持ち主が選ぶ。試用のあいだは、試験用のプロファイルのままにする。
  - Istesso は、持ち主のふだんの設定を、変えない。読むだけにする。
  - 日本語入力の経路は、[ADR 0020](adr/0020-japanese-input.md)（提案）で比べている。

### R-05 インストールの振り分け

- ダウンロードを拡張子で判定する。`.deb` / `.AppImage` は Linux ホストへ、`.dmg` / `.pkg` は Mac を選ばせる。
- sudo や Gatekeeper の確認は省略しない。

### R-06 統合ストレージ

- 各 PC に、この仕組み専用の隔離領域を用意する。
- 隔離領域を束ね、合計容量として見せる。
- 実体のある PC が停止中のファイルは「取得できない」と分かる表示にする。

### R-07 隔離

- ストレージだけでなく、アプリとエージェントのプロセスごと専用ユーザーで動かす。
- コーディングエージェント（herdr 上の Claude Code / Codex）が読めるのは隔離領域だけにする。
- ツール側のサンドボックス設定は二重の柵として併用する。

### R-08 オーディオ

音を聴きながら作業できることは必須。

- 映像と独立した常駐サービスにする。窓を閉じても端末を替えても止まらない。
- 「音の出口」を1つ選ぶ。全ホストの音を非圧縮でそこへ集める。
- 時計のずれ補正と欠落の補完を行い、長時間でも途切れないこと。
- 再生中はそのホストを眠らせない。
- DAC が挿さっている PC でローカル再生する経路には手を入れない（ビットパーフェクトを保つ）。

### R-09 USB 機器

- 全 PC の USB 機器を一覧し、この仕組みで使う形に切り替えられる。
- 種類ごとに方式を分ける。

| 種類 | 方式 |
|---|---|
| キーボード、マウス | 入力の転送（USB の付け替えはしない） |
| Stream Deck | このプロダクトが直接制御するモード。公式ソフトと切り替える |
| オーディオ機器 | 音だけを運ぶ（R-08） |
| その他 | USB/IP で付け替える。今回の公開では作らない。挿した PC のアプリから使う |

- 使う人に守ってもらうのは「どこに挿すか」だけにする。あとは、この仕組みが正しい側でアプリを開く。
- USB 機器は、Linux か Windows の PC に挿すことを勧める。オーディオ機器は例外で、機器は動かさず、音として運ぶ（R-08）。キーボードとマウスは、この方針の対象外で、入力の転送で扱う。Stream Deck は、この勧めに入れない（付け替えず、挿した PC のエージェントが直接制御するため）。
- USB 機器を使うアプリは、その機器を受け取れるホストで開くことを優先する。会議アプリは、マイクとカメラがつながっている PC で開く（R-04）。マイクとカメラを Linux の PC に挿してあれば、会議アプリはそこで開き、手元には窓として出る。手元の内蔵のマイクとカメラを使うときは、手元でそのまま開く。ブラウザーそのものは、寄せない。会議のページを、1つの項目としてランチャーに登録できるようにする。
- Mac の上に、仮想のマイク、カメラ、USB 機器を作ることは、対象外とする。
- 個別に対応する機器は、まず、作者が持っているものだけにする。ほかの機器は、使う人が自分のエージェントに作らせたプルリクエストを受け付ける。そのために、機器対応のフレームワークを用意する。機器1種類につきアダプターを1つ書き、本体を変えずに足せるようにする。Stream Deck は、最初のアダプターとして、その上に作る。Stream Deck のための特別なコードは、本体に書かない（[ADR 0012](adr/0012-device-framework.md)）。アダプターのための口を固める前は、外からの機器のプルリクエストを受け付けない。
- ホストを起動した直後（ログイン画面のまま、SSH だけ）の状態でも、機器を使えること。
- 確認項目：スピーカーで聞く会議で、声が回り込まないこと（相手に、相手自身の声が返って聞こえない）。
- 制約：受け側が Mac の付け替えはできない（6.1 を参照）。

### R-10 エージェント連携

- 各ホストが `istesso doctor` で役割表を出す。
- ビルド・実行・デプロイは振り分けコマンド経由にし、必要条件から行き先を自動で決める。
- AGENTS.md / CLAUDE.md には入口だけを書く。
- herdr の Gate（必須要件リスト）に「デプロイ先を確認済み」を常設できるようにする。

### R-11 リソース管理

- CPU・メモリ・GPU の使用状況を全ホスト分まとめて見られる。
- 起動先の自動選択に使う。
- 複数台のメモリや CPU を1つのアプリに束ねることはしない（できない）。

### R-12 導入のしやすさ

- Mac：Developer ID で署名し公証を通した pkg。
- Ubuntu：署名付きリポジトリの .deb。Docker を必須にしない。
- リリースは CI で自動生成する。
- 初回起動時に、OS の許可（画面収録、アクセシビリティなど）を案内する。

### R-13 安全なリンク

- 同じ LAN の PC は自動で一覧に出る。
- QR か短いコードでつなぐ。短いコードから強い共有鍵を導く PAKE を使う。
- 端末ごとの鍵を固定して相互認証する。一覧からいつでも失効できる。
- 端末ごとに権限（閲覧、操作、インストール、USB、音）を分ける。
- 出先からの接続は VPN 越しに限定する。

### R-14 公開

- ライセンスは MIT と Apache-2.0 の併記。
- 自分の OSS として取り込んでも問題ない技術だけを使う。それ以外は内製する（`docs/components.md`）。
- Windows を後から追加できる構成にする。

## 6. 制約

### 6.1 USB の付け替え

- 受け側（その機器を使うアプリが動く PC）が Mac の場合、付け替えはできない。仮想 USB コントローラーに Apple の個別許可が要るため。Mac の上に仮想のマイクやカメラを作って代わりにすることも、対象外とする。
- したがって、Mac のアプリで使う機器はその Mac に直接挿す。それ以外の機器は、Linux か Windows の PC に挿すことを勧める。
- 付け替えは、今回の公開では作らない。機器は、挿した PC のアプリから使い、その窓をほかの端末に出す。
- 付け替えを作ったあとは、Linux や Windows のアプリが、Linux か Mac に挿してある機器を使えるようになる。Windows に挿した機器は、出す側の実装がないので、その Windows のアプリからしか使えない。
- キーボード、マウス、Stream Deck、オーディオは別方式なので対象外。
- Mac から出す側は root 権限が前提。Linux の受け側でも、付け替えのたびに root 権限が要る（ADR 0004 の「権限と、使う人の手間」）。

### 6.2 出先

- インターネット越しでは R-01 の基準を満たせない。
- AURA の SDK（Jetpack Compose for XR）はベータ段階。

### 6.3 Mac ホスト

- 画面の取り込みは最難関。既製の部品に頼れないため内製する。
- 画面収録・アクセシビリティの許可は利用者の操作が必要。
