## ビルドの分け方

コンポジターのプラグインは、`scripts/build-compositor.sh` で、自分のフォルダーにビルドします。ホストで動かします。

```sh
# 判定で測るビルド（4 つの修正。関門で測ったものと同じ）
scripts/build-compositor.sh <フォルダー>

# 試用と、毎日使う形のビルド（4 つ + trial-windows）
ISTESSO_COMPOSITOR_TRIAL=1 scripts/build-compositor.sh <フォルダー> --test
```

- スイッチは `ISTESSO_COMPOSITOR_TRIAL=1` です。**既定は切**で、切のときに当てるのは、関門で測った 4 つ（render-on-commit、cursor-messages、windows、dialogs）だけです。入れると、`gst-wayland-display-trial-*.patch` を、名前の順に足します。
- フォルダーに、gst-wayland-display の `1301f86` を取り出し、修正を当て、`--features cuda` でビルドします。プラグインは `<フォルダー>/target/release` にできます。`--test` を付けると、コンポジターのテスト（`cargo test -p wayland-display-core`）も通します。
- **すでにあるフォルダーは、このスクリプトが同じ修正で作ったときだけ使い直します**（フォルダーの `.istesso-patches` に、当てた修正の名前と中身のハッシュが書いてあります）。それ以外のフォルダーには、何も書きません。動いている試用や計測が使うプラグインの上に、ビルドすることはありません。
- 計測の合図（AGENTS.md）を、始める前と、cargo が動いているあいだ 5 秒おきに読みます。`busy` なら始めず、動いていれば cargo を止めます。
- 取り出し元は `ISTESSO_GWD_ORIGIN` で替えられます（`1301f86` を持つ手元の複製なら、取りに行きません）。

試用で使うときは、ビルドしたフォルダーを `ISTESSO_HOST_PLUGIN` で指します。

```sh
ISTESSO_HOST_PLUGIN='<フォルダー>/target/release' TRY=channel scripts/try.sh <アプリのコマンド>
```

**判定で測るビルドが変わっていないこと**の確かめ方：

- 4 つの修正のファイルは、この作業で変えていない（`git diff origin/main -- scripts/patches/gst-wayland-display-{render-on-commit,cursor-messages,windows,dialogs}.patch` が空）。
- スイッチを切ってビルドしたフォルダーのソースが、関門で測ったプラグインのフォルダーのソースと同じであること（`diff -r -x target -x .git` で比べる）。

## 1. ポインター、ボタン、キーボードが、同じ窓へ行く

**見たこと**（`docs/input-record.md` の最後の節）：Blender の設定の窓（親のない 2 枚目の窓）が出たとき、キーボードは設定の窓へ移り、ポインターは下の主の窓に入ったままだった。動かさずにクリックすると、ボタンは主の窓へ、キーボードは設定の窓のままで、Shift+A は設定の窓へ、Shift＋スクロールと Alt＋ドラッグは主の窓へ行った。

**原因**（この作業で、テストで再現した）：コンポジターは、窓を、最初の configure のあとの確定で絵に入れる。その確定に絵が入っていなくても入れる。Blender の 2 枚目の窓は、絵を描く前に確定する。そのときにポインターの行き先を調べ直すと、新しい窓には、まだ何もない。ポインターは下の窓へ入り、動くまでそのままだった。クリックでは、キーボードを「ポインターの位置のいちばん上の窓」へ、ボタンを「ポインターがいま入っている窓」へ渡していたので、2 つが分かれた。

**直したこと**：

- 絵に入っている窓が確定するたび（新しい絵、新しい大きさ、最初の絵）、窓が出たとき・閉じたとき、クリックで窓を上げたあとに、ポインターの行き先を、いまの位置で調べ直す。行き先が変わったときだけ、出入りを送る。
- クリックでは、ポインターの下の窓を上げ（ダイアログもいっしょに、これまでどおり）、ポインターを、いまそこでいちばん上にある窓に入れ、**キーボードを、同じ窓へ渡す**。ボタンとキーが、別々の窓へ行くことはない。1 度も動かしていないポインターでのクリックも、窓に届く（これまでは、どこにも届かなかった）。
- キーボードがほかの窓へ移るたびに、どの窓が「いま使っている窓」（`xdg_toplevel` の activated）かを、全部の窓に伝える（変わったときだけ）。これまでは、どの窓にも、出たときに「使っている」と伝えたきりだった。Blender は、これを見ている：「使っていない」と言われなかった窓では、押したままの Shift が、次のキーに付かなかった（Shift+A が A として届いた。ホストの自己試験で見た。下の「ホストでの自己試験」）。

## 2. 「全画面」ではなく「最大化」と伝える

- 出力と同じ大きさにする窓には、**最大化**（`XdgState::Maximized`）と、出力の大きさ（上限があればそこまで）を伝える。アプリは、自分の帯（Firefox のタブとアドレスの帯）を残す。
- **全画面**は、アプリが頼んだとき（`xdg_toplevel.set_fullscreen`：動画、ゲーム、発表）だけ伝え、窓を左上の隅に、いちばん上に置く。頼みを取り下げたら、親のない窓は最大化に戻り、ダイアログは自分の大きさに戻る。
- アプリが最大化を頼んだら、最大化する。
- 出力の大きさが変わったら、出力いっぱいの窓（最大化、または頼まれた全画面）には新しい大きさを伝え、ほかの窓には、使える広さだけを伝える。これまでは、全部の窓に「全画面、大きさなし」を伝えていた。

## 3. 2 枚目の窓を見失わない（つなぎ）

- ほかの窓が出力いっぱいに出ているときに開く、**親のない窓は、出力いっぱいにしない**。使える広さだけを伝え、アプリの望む大きさのまま、出力のまん中に置く。出力いっぱいでない親のない窓（大きさの上限を言う窓など）も、まん中に置く。全画面を抜けても、最大化の頼みを取り下げても、自分の大きさに戻る。小さい窓（スプラッシュなど）しか出ていないときに開く窓は、これまでどおり出力いっぱいにする。
- 絵を描く前に出た窓は、最初の絵が来たときに、その大きさで置き直す。これまでは、大きさ 0 の窓として置いていたので、「まん中」が窓の角になり、残りは出力の外へはみ出していた（Blender の設定の窓。ホストの自己試験で見た）。ダイアログにも効く。
- 出力いっぱいの窓がクリックで上がったら、**同じクライアントの、親のない小さい窓を、その上に上げ直す**（もとの順のまま。そのダイアログもいっしょに）。上がった窓のダイアログは、その上に来る。ほかのクライアントの窓は、動かさない。クリックそのものは 1 のとおりで、上げ直したあとにポインターの下でいちばん上にある窓に、ボタンとキーボードが行く。
- **xdg-activation の口を出す。** アプリは、自分の窓を前に出すよう頼める（ダイアログといっしょに上がり、キーボードを持つ）。頼みのしるし（トークン）は、10 秒のあいだ、1 回だけ効く。2 回目に起動したアプリが 1 回目の窓を見せるとき、小さい窓の下になった主の窓を前に出すときに使われる。

分かっている不足：

- 外から窓を選ぶ手は、まだない。出力いっぱいの窓の下になった、出力いっぱいの窓（2 枚目のブラウザーの窓）は、上の窓が閉じるか、アプリが頼むまで、届かない（窓の一覧。m3-everyday-apps.md の 10 章）。
- 「同じクライアント」は、Wayland の接続 1 本のこと。窓を 2 本の接続で開くアプリは、2 つのクライアントになる。
- 全画面や最大化を抜けた窓は、そのとき置いた場所（左上の隅）のまま。最初の絵のあとで大きさが変わっても、置き直さない。
- 1 枚目の窓が最大化の取り下げを頼んでも、最大化のまま答える。

## テスト

`cargo test -p wayland-display-core`（`--test` を付けたビルド）。73 本のうち、この修正で足したのは 9 本（`tests/test_trial_windows.rs`。本物の Wayland クライアント）と 1 本（`comp/windows.rs`）。dialogs の修正のテストのうち 2 本を、3 の決まりに合わせて変えた（親のない 2 枚目の窓：出力の大きさではなく使える広さを伝え、隅ではなくまん中に置く）。

- 1：絵を描く前に出た 2 枚目の窓が、最初の絵からポインターを持つ。動かさずにクリックすると、ボタンもキーボードもその窓へ行き、その窓が「使っている窓」になる。1 度も動かしていないポインターでのクリックが、1 枚だけの窓にキーボードといっしょに届く。ダイアログの横のクリックで、ボタン、キーボード、「使っている窓」が親へ行く。1 つ目のテストは、確定のたびに調べ直す処理を外すと落ちる（ポインターが下の窓のまま）ことを確かめた。
- 2：1 枚目の窓は、出力の大きさで最大化と伝えられ、全画面とは伝えられない。全画面を頼んだ窓は全画面になり、取り下げると最大化に戻る。出力の大きさが変わると、最大化の窓に新しい大きさが伝わる。
- 3：2 枚目の親のない窓は、自分の大きさで、まん中に出て、そこにあったポインターとキーボードを持ち、全画面を抜けても自分の大きさに戻る。絵を描く前に出た窓は、絵の大きさでまん中に置かれる。activation で前に出た主の窓は小さい窓の上に来て「使っている窓」になり、そこをクリックすると、小さい窓が上に戻り、ボタンとキーボードは主の窓へ行き、小さい窓はその場所でクリックを受ける。
