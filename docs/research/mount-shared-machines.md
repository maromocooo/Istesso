# ほかの人も使う Mac のマウント：つなぎの WebDAV と、FSKit の条件（調査）

- 状態：調査（2026-11-21）。持ち主の決め「作13」の材料。**ここでは決めない。**
- 作13（持ち主、2026-11-21）：手元だけの NFS は、持ち主 1 人の機械での試用だけ。ほかの人も使う機械では、FSKit が使えないあいだ、**既定ではマウントを出さない**。つなぎとして、合言葉つきの仕組み（WebDAV など）が使えるかを調べる。自分でビルドした版で FSKit が使える条件（署名）も調べる。Ubuntu の FUSE は、もともとユーザーごとなので、このまま。
- 前の調査：ブランチ `research-unified-mount` の `docs/research/unified-mount.md`（以下「統合マウントの調査」）。C2（ループバックの WebDAV）、C4（FSKit）の行と、ライセンスと特許の表。そこで見たことは、ここでは「統合マウントの調査（実）」と書く。
- 印：**実**（実機で確かめた）、**資**（資料。末尾の番号）、**推**（推測）。この調査では、新しく実機で何も動かしていない。

## 0. まとめ

1. **WebDAV は、つなぎに使える見込み。ただし弱みが大きい。** 手元にループバック（127.0.0.1）の WebDAV の係を置き、マウントごとに長いでたらめの合言葉を付ければ、同じ Mac のほかのユーザーは、合言葉なしでは係に入れない（推）。マウントの場所を、持ち主だけが入れるフォルダー（0700）の中に置けば、ほかのユーザーは、マウントの中に届かない（推）。弱み：開くとファイル全体を取る（統合マウントの調査：実）、`noexec`（実）、書くには LOCK が要る（資1）、Finder の WebDAV には実装の問題が多いという報告（資4）。
2. **FSKit は、有料の開発者プログラムのチームでの署名が要る。** FSKit のモジュールの entitlement は「制限つき」で、プロファイルが要り、プロファイルを作るには有料のチームの一員である必要がある（資6：Apple の技術サポート、2026-03）。機能の表でも、FSKit Module は ADP と Developer ID だけで、無料のアカウントでは使えない（資7）。
3. だから、**自分でビルドした版で FSKit を使えるのは、ビルドする人が、自分の有料のチームを持つときだけ。** 持たない人の版は、ほかの人も使う機械では、作13 のとおりマウントを出さない（既定）。つなぎの WebDAV は、持ち主が機械ごとに選んだときだけ（案）。

## 1. つなぎ：ループバックの WebDAV に合言葉

### 1.1 形（案）

```
 Finder・アプリ ── macOS の WebDAV のクライアント（webdavfs）
                     │  http://127.0.0.1:<でたらめのポート>/  合言葉つき（Digest）
                     ▼
               Istesso の手元の係（持ち主のユーザー。127.0.0.1 だけで待つ）
                     │  Istesso の制御チャンネル（Noise。ADR 0007）
                     ▼
               フォルダーを持つ機械（決め 1：フォルダーは 1 台の持ち物）
```

- 係のサーバーは `dav-server`（Apache-2.0）が候補。認証は持っていないので、前に置く（資3）。`FakeLs` は「macOS と Windows に足りるだけの LOCK と UNLOCK」（資3）。
- 合言葉：マウントのたびに、手元の係が長いでたらめの値を作る。画面に出さない。記録に書かない（AGENTS.md の 4）。
- 合言葉の渡し方：NetFS の `NetFSMountURLSync` は、利用者名と合言葉を引数で受ける（資5：SDK のヘッダー）。問いの窓を出さない設定もある（`kNAUIOptionKey`。資5）。推：これで、キーチェーンに書かずに、合言葉をマウントに渡せる。試していない。
- マウントの場所：持ち主だけが入れるフォルダー（0700）の中。
- 特許：WebDAV（RFC 4918、RFC 2518）は、Microsoft の Open Specification Promise の一覧にある（統合マウントの調査）。

### 1.2 何から守れるか

| 相手 | 守れるか | 印 |
|---|---|---|
| 同じ Mac のほかのユーザー（root でない）が、係につなぐ | 守る。合言葉なしでは入れない | 推 |
| 同じ Mac のほかのユーザーが、マウントの中を見る | 守る。マウントの場所の上のフォルダーが 0700 なら、たどれない | 推（WebDAV のマウントの中のファイルは、だれでも読み書きできる印で見える：資1。だから、上のフォルダーで止める） |
| ほかのユーザーが、係のポートを先に取って待ち、合言葉を盗む | Digest なら、合言葉そのものは流れない。長いでたらめの合言葉なら、受け取った値から総当たりできない | 推。macOS の WebDAV のクライアントが Digest を使うかは、試していない |
| ループバックの通信をのぞく | root か、パケットを読む権限（`/dev/bpf`）を持つ人だけ。Wireshark などを入れた機械では、ほかのユーザーに許していることがある | 推 |
| 持ち主のユーザーで動く悪いプログラム | 守らない（持ち主のマウントは、持ち主のプログラムから見える） | — |
| root | 守らない | — |

手元だけの NFS（試用）との違い：NFS（AUTH_SYS）は、つないできた相手を、合言葉で確かめない。だから、ほかのユーザーが同じ係につなげば入れる（推）。作13 で、NFS を持ち主 1 人の機械に限った理由である。

### 1.3 かかるもの（遅さ、壊れにくさ）

| こと | 分かっていること | 印 |
|---|---|---|
| 開く | 10 バイト読むだけでも、ファイル全体を GET した（Range なし） | 実（統合マウントの調査、Air） |
| 書く | DAV class 1 の相手なら、読むだけでマウントされる。書くには LOCK（class 2）が要る | 資1 |
| 実行 | `noexec, nosuid, nodev` が付いた | 実（統合マウントの調査） |
| 余計な問い合わせ | マウントしたとき、`._` の名前（AppleDouble）や `.metadata_never_index` を問い合わせた | 実（統合マウントの調査） |
| リンク | WebDAV に、リンクの種類がない | 推（統合マウントの調査） |
| 相手が答えなくなったとき | `-S` を付けると、問いの窓を出さず、すぐにマウントを外す | 資1 |
| Finder の WebDAV の質 | 「実装の問題が多い。決まったサーバーの組み合わせでだけ使うように」（Nextcloud の文書） | 資4 |
| 遅れ | 一覧ごとに PROPFIND、開くごとに全体の GET。手元の係から、持ち主の機械までの往復が、そのつど足される | 推。測っていない |

壊れにくさの案（推）：係は手元（127.0.0.1）にあるので、ネットワークが切れても係は答えられる。持ち主の機械に届かないときは、係がすぐにエラーを返し、カーネルを待たせない。`-S`（または NetFS の、問いを出さない設定）で、机に窓を出さない。

### 1.4 使う前に測ること

1. Digest で合言葉を渡せるか（NetFS の引数で。キーチェーンに書かずに）。
2. 一覧（100 個、1000 個のファイル）と、1 MB・100 MB のファイルを開く時間。LAN と VPN の両方で。
3. `FakeLs` で、Finder とエディターから書けるか。`._` と `.DS_Store` を、係が断るか捨てるか。
4. 持ち主の機械に届かないときに、Finder とアプリが固まらないこと。
5. ほかのユーザー（試しのユーザーを作るには sudo が要る。持ち主の手）から、係にもマウントにも届かないこと。

## 2. FSKit を、自分でビルドした版で使う条件

| 条件 | 分かったこと | 印 |
|---|---|---|
| OS | macOS 15.4 から。ネットワークのような資源（`FSGenericURLResource`、`FSPathURLResource`）は macOS 26 から | 資8 |
| 形 | アプリの中の拡張（FSModule）。いまの FSKit は `FSUnaryFileSystem` だけ | 資8 |
| entitlement | `com.apple.developer.fskit.fsmodule`。**制限つきで、プロファイルが要る。プロファイルを作るには、有料のチームの一員であること** | 資6（Apple の技術サポートの答え、2026-03） |
| どのアカウントで使えるか | 機能の表：FSKit Module は ADP と Developer ID で可。無料の Apple Developer のアカウントでは不可 | 資7 |
| 使う人の手 | システム設定 → 一般 → ログイン項目と拡張機能 → ファイルシステム拡張 で有効にする | 資9、統合マウントの調査 |
| 手元だけの署名（Sign to Run Locally） | ビルドのたびに別のアプリに見え、有効にし直す要がある。Apple の署名なら、ふつうのアプリの更新として扱われる | 資9（Apple の技術サポートの答え、2026-06） |
| SIP を切る | プロファイルの条件を外せるかもしれないが、勧めない | 資6 |
| マウントの場所 | 書類、デスクトップ、ダウンロードの中にはマウントできなかった。ホームのほかの場所ならできた | 資10 |

まとめ：

- **自分でビルドする人が、自分の有料のチーム（Apple Developer Program）を持てば、自分のチームで署名して FSKit を使える**（資6、資7）。その人の Mac で、拡張を 1 回有効にする。
- 無料のアカウントや ad hoc の署名では、FSKit は使えない（資6、資7）。証9（自分でビルドした版は PCC を持てない）と同じく、**自分でビルドした版の手順は、既定で FSKit なし**にするのが合う（推）。
- 署名した版（Developer ID）は、FSKit を使える（資7）。M9（配る形）の署名と同じ条件である。

## 3. おすすめ（案）

| 機械 | 版 | マウント |
|---|---|---|
| 持ち主 1 人の Mac | どれでも | いまの試用（手元だけの NFS）。FSKit ができたら FSKit |
| ほかの人も使う Mac | 署名した版 | FSKit（macOS 26 から）。それまでは、既定でマウントなし |
| ほかの人も使う Mac | 自分でビルドした版（有料のチームあり） | FSKit（自分のチームで署名） |
| ほかの人も使う Mac | 自分でビルドした版（有料のチームなし） | 既定でマウントなし。持ち主が選べば、つなぎの WebDAV（1 章。読むだけから始める） |
| Linux | どれでも | FUSE（ユーザーごと。作13 のとおり、このまま） |

つなぎの WebDAV は、1.4 を測ってから入れる。それまでは、作13 のとおり、ほかの人も使う Mac にはマウントを出さない。
