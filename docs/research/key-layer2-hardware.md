# 層 2：鍵を機械の部品に結びつける（設計の案）

- 状態：設計の案（2026-11-21）。**コードはまだ書かない**（配27）。暗号の所は【Needs Fable】。持ち主が決めていない所は【問い】。
- 調べたこと（出どころ、印の意味、「資」の番号）は [key-protection.md](key-protection.md) にある。この文書の「資n」は、その 7 章の番号である。
- 層 1（写しを見つける）は ADR 0021（ブランチ `m5-clone-detect`）。層 3（鍵の番人）は [key-layer3-keeper.md](key-layer3-keeper.md)。

## 1. 目的と、守れること

配27 の層 2：「鍵を機械の部品（TPM、Mac は Secure Enclave）に結びつける」。

| 守れること | 守れないこと |
|---|---|
| 鍵を、別の機械へ持ち出すこと（ファイルを写しても、別の機械の部品では使えない：資1） | その機械の上で、同じユーザーのプログラムが、部品に署名させること（実：Air で、写した包んだ鍵でも、別のプロセスから署名できた） |
| root でも、鍵そのものは取り出せない（部品から出ない：資1） | root が、その機械の上で署名させること |
| ディスクやバックアップの写しから、鍵を使うこと | 部品のない機械 |

**ただし、同じユーザーのプログラムが部品に署名させられる形（自分でビルドした版の包んだ鍵、ユーザーが使える TPM の鍵）では、上の「持ち出せない」は、証明をつなぎごとにしたときだけ成り立つ。** いまの証明（プロセスごとの X25519 の公開鍵への 1 回の署名）は、時刻も相手も含まない。証明そのものは秘密ではない。持ち帰られるのは、そのプログラムが自分で作った X25519 の秘密鍵と、それへの証明の組で、あとで別の所から、制御チャンネル（映像と入力を含む）で、その端末として通る（key-protection.md の 0 章の 3）。署名した Mac の版で、鍵を Istesso のアクセスグループに置く形では、ほかのプログラムは部品に署名させられないので、この条件は要らない（推）。【Needs Fable】

## 2. 2 つのやり方

| | 2a：包む（封じる） | 2b：部品の中で署名する |
|---|---|---|
| 何をするか | Ed25519 の種を、部品の鍵で暗号化して置く。使うときに部品で開き、種をメモリに出す | P-256 の鍵を部品の中で作る。署名を部品にさせる。鍵はどこにも出ない |
| 例 | systemd-creds の `tpm2`（資11）、DPAPI（資18）、データ保護キーチェーン（資2） | Secure Enclave（資1、資3）、TPM の ECDSA（資8）、Windows の TPM（資19） |
| プロトコル | 変わらない（版 1） | 変わる：身元の鍵に P-256、証明をつなぎごとに（版 2）。【Needs Fable】 |
| 盗まれたディスク | 守る | 守る |
| 同じユーザーのプログラムの持ち帰り | **守らない**（開いた種がメモリにある。開く操作もできる） | 証明がつなぎごとなら守る |
| 速さ | 開くのは起動のときに 1 回 | 署名のたび。Secure Enclave 約 4.4 ms（実）、TPM 約 100〜600 ms（資12） |

結論（案）：**層 2 として名乗れるのは 2b だけ**（持ち出しを防ぐのが層 2 の目的なので）。2a は、OS の仕組みでの「置き場所」（key-protection.md の 5 章の版 1）として使う。

## 3. 機械ごとの形（案）

| 機械 | 形 | 条件 |
|---|---|---|
| Mac（Apple シリコン、Touch Bar の Mac）、署名した版 | Secure Enclave の P-256 鍵。データ保護キーチェーンの項目として、Istesso のアクセスグループに置く。使えるのは「ロック解除のあと、この機械だけ」 | entitlement とプロファイル（資2）。Developer ID の束 |
| 同じ、自分でビルドした版 | Secure Enclave の P-256 鍵を CryptoKit で作り、包んだ鍵（`dataRepresentation`）を 0600 のファイルに置く | 実：entitlement なしの ad hoc 署名で動いた（Air、macOS 26.5.1）。Rust から使うには、Swift の小さな橋が要る（推） |
| Linux、TPM あり | 層 3 の番人と組み合わせるとき：TPM は 2a（systemd-creds で包む）。2b（TPM の中の P-256）は、つなぎごとの署名の遅さを測ってから | `/dev/tpmrm0` は `tss` グループ（資10）。sudo が 1 回 |
| Windows、TPM あり（M10） | TPM の P-256 鍵（Microsoft Platform Crypto Provider）。速さを測ってから | M10 で調べ直す |
| 部品がない | 層 2 なし。key-protection.md の 5 章の置き場所 | — |

TPM の 2b を急がない理由：

- 署名 1 回が 100〜600 ms（資12）。ADR 0007 は、短い接続（つないで、聞いて、切る）を多く使い、つなぎ直しを 1 秒以内に済ませたい。つなぎごとに TPM で署名すると、これに合わない（推。測っていない）。
- 速さを補う案：部品の鍵で、短い命のソフトの鍵に「委任」の署名をする（たとえば 10 分）。持ち帰られても、その時間だけしか使えない。ただし、その時間のあいだは持ち帰れる。【Needs Fable】【問い】

## 4. プロトコルの変更（案。【Needs Fable】）

AGENTS.md の 4 のとおり、決めるときは、先に ADR 0006 と ADR 0007 を直す。ここは、その材料である。

1. **身元の鍵の種類**：`ed25519` に `p256` を足す。**P-256 は部品の鍵だけ**に使い、ソフトの鍵は Ed25519 のまま。ペアリングの `Hello` に、鍵の種類を入れる。保存するペアリングの一覧にも入れる。つなぐときは、**鍵の種類を、通信で来た印からではなく、固定した記録（ペアリングの一覧）から取る**。
2. **指紋**：鍵の種類を含めて計算する（同じバイトを別の種類として読ませないため）。いまの指紋は SHA-256 の先頭 8 バイト＝64 ビット（実：`identity.rs`）。幅を見直す。
3. **証明をつなぎごとに**：key-protection.md の 6 章の F1。受け側は、メッセージ 1 を読んだあとのハンドシェイクのハッシュに署名し、メッセージ 2 に入れる。接続側は、メッセージ 2 を読んだあとのハッシュに署名し、メッセージ 3 に入れる。**署名する中身**：役割の印（受け側か接続側か）と版、新しい区切りの文字列、ハンドシェイクのハッシュ、自分の Noise の静的鍵（X25519 の公開鍵）、署名する身元の鍵とその種類。ハッシュには相手の新しい一時鍵が入っているので、前もって作れない（推）。往復は増えない（推）。プロセスごとの証明（`LocalKeys` の使い回し）はやめる。
4. **つなぎの命**：つなぎに命の上限を置き、決まった間隔で証明をし直す（入力と映像のつなぎは長く開いたままなので、いるあいだに作ったつなぎを、いなくなったあとも使い続けられないように）。間隔は、Fable と、部品の署名の速さを見て決める。
5. **版**：ペアリング `istesso-pair-v2`、制御チャンネル `ISC2`。プロローグも新しくする。古い版の端末と混ぜない（ADR 0006 の「変更の手順」）。
6. **混ざった端末**：Ed25519 の端末と P-256 の端末が、同じ持ち主のなかにいる。確かめる側は、両方を受ける。
7. **署名の形**：P-256 は、SHA-256 で要約する。公開鍵は**圧縮の 33 バイト**、署名は **r‖s の 64 バイト**の 1 つの形だけ。作るときは S を小さい側にそろえ（low-S）、確かめるときは大きい S を断る。部品が DER で返すときは、送る前に直す。

## 5. 一生（作る、使う、移る、なくす）

| 場面 | どうなるか | 層 1 とのつながり |
|---|---|---|
| 初めて起動 | その機械で使える、いちばん上の形で鍵を作る（key-protection.md の 5 章）。外から鍵を入れる道は作らない（Secure Enclave は、もともと入れられない：資1） | 層 1 の値も、そのとき作る |
| 形を替える（ファイル → 部品） | **新しい鍵になる。ペアリングを 1 回やり直す**（11-20 の持ち主の決め：ファイルからキーチェーンに替える端末と同じ）。古い鍵は、ホストの一覧から外す | 新しいペアリングで、層 1 の値も新しくなる |
| 同じ機械をバックアップから戻した | 部品が同じなので、鍵は使える（推：Secure Enclave の中身が消えていなければ） | 層 1 の値が古い。層 1 の「持ち主が確かめて戻す道」を通る |
| 新しい機械へ移った | 部品の鍵は移らない（資1。キーチェーンの「この機械だけ」も移らない：推）。新しい機械はペアリングし直す | 古い機械の鍵は、ホストの一覧から外す |
| OS を入れ直した、部品を消した（TPM の初期化など） | 鍵は使えなくなる（推）。ペアリングし直す | 同上 |
| 機械をなくした | 部品の鍵は、その機械の上でしか使えない。ほかの機械から外す（M5 の「なくした端末を全部のホストで一度に取り消す」） | — |

## 6. 見えるところ（言葉の案）

`istesso doctor` と設定の画面に、形と、守れること・守れないことを 1 行ずつ出す。鍵、署名、層 1 の値は出さない（AGENTS.md の 4）。出すのは指紋だけ。

- Secure Enclave（署名した版）：「この端末の鍵は、この Mac の部品（Secure Enclave）の中にあります。ほかの機械へは持ち出せません。この Mac の上では、Istesso を通して使えます。」
- Secure Enclave（自分でビルドした版）：「この端末の鍵は、この Mac の部品の中にあります。ほかの機械へは持ち出せません。この Mac で、あなたのユーザーで動くプログラムは、この鍵で署名できます。」
- 部品なし：「この端末の鍵は、ファイル（または鍵束）にあります。あなたのユーザーで動くプログラムは、鍵を読んで、ほかの機械へ持ち出せます。写されたことは、次につないだときに分かります（層 1）。」

## 8. 【問い】（持ち主へ）

1. 版 2（P-256 の身元の鍵と、つなぎごとの証明）を、Fable の見直しに出してよいか。出すなら、ADR 0006 と ADR 0007 の【提案】として書く。
2. TPM の 2b（部品の中で署名）は、つなぎごとの遅さを測るまで、使わない（2a の「包む」だけ）でよいか。
3. 「委任」の案（部品の鍵で、短い命のソフトの鍵に署名する）を、考えに入れるか。持ち帰られると、その時間だけは使える。
