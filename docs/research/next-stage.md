# 新しい段の試作を、1 つの手順で入れて、1 つの手順で戻す（ブランチ `proto-next-stage`）

- 状態：試作（2026-11-20）。`main` には入れない。
- 決めるのは持ち主である。下の「持ち主が決めること」の 4 つは、既定の値（おすすめ）で書いてある。

## 何が入っているか

新しい段の試作 5 つを、1 つのブランチに合わせた。土台は `23214b8`（3 つの ish の試作の共通の土台。エディターと範囲の試作の土台も、この中にある）。どの試作のブランチも書き換えず、1 つずつ `--no-ff` で合わせた。

| 順 | ブランチ | 先頭 | 中身 |
|---|---|---|---|
| 1 | `proto-ish-forward` | `1739f45` | 転送の口は、この Mac の同じユーザーのプログラムからの接続だけを受ける |
| 2 | `proto-ish-projects` | `9372a52` | `ish <名前>` で、登録したプロジェクトのフォルダーでシェルを開く |
| 3 | `proto-ish-mount` | `d67e6b5` | `cd ~/Istesso/ubuntu/<ID>` で、ホストのフォルダーを読むだけでマウントしてから、そこでシェルを開く |
| 4 | `proto-main-editor` | `f0b2ec1` | シェルの中の `istesso-edit <ファイル>` で、ホストのメインのエディターを開き、窓を手元に出す |
| 5 | `proto-agent-scope` | `bde09a8` | コマンドを範囲の段で動かし、外のものは止めて、手元の機械に聞く |

この順にしたわけ：小さく、ほかと重ならないもの（転送）を先に。名前で開くものを、マウントより先に（マウントの `scripts/dev/ish` は古い形のままなので、入れる `ish` は名前で開く方の `scripts/ish`）。土台の古いエディターは、3 つの ish がそろってから、一度で合わせる。範囲は、ほかのクレートに触れないので、最後。

合わせたときに、ぶつかった所は、どれも両方を残した（シェルの設定の `home` と `windows`、エージェントの起動の引数、ADR 0007 の節）。**コードを 1 行足した所が 1 つある**：名前で開く試作は、始まりのフォルダーを決める関数に、名前を引く口を足した。エディターの試作も、同じ関数で、編集してよいフォルダーを決める。そこに、シェルと同じ引き方（`ShellSettings::registered`）を渡した。名前で開いたシェルでも、パスで開いたシェルと同じフォルダーが、エディターの範囲になる。

## 入れ方、戻し方

Air で、このブランチの作業ツリーから打つ。

```sh
scripts/next-stage.sh plan       # 何を、どこで、置き換えて足すかを言う。何も変えない
scripts/next-stage.sh install    # 同じことを言ってから、yes と打つと入れる
scripts/next-stage.sh rollback   # 入れる前に戻す。置き換えた各ファイルを、前の sha256 と比べる
```

`install` が変えるのは、次だけである。

- Air：`~/.local/bin/ish`、`~/.local/bin/ish-forwards`、`~/.local/share/istesso-dev/cd-switch.zsh` を置き換える（前のものは、先に `~/.local/state/istesso-next-stage/<時刻>/old/` に写す）。`~/.local/bin/ish-mount` と、`~/Library/Application Support/istesso-next-stage/`（プログラム、台本、いまの `ish` の試しの身元の写し）を足す。`~/Istesso` は、最初のマウントのときに作られる。
- ホスト：`~/.local/share/istesso-next-stage/`（プログラム、昼のエージェントの試しの身元の写し、登録したプロジェクト、範囲の試しの身元）を足し、そこからエージェントを 1 つ立てる（ポート 26980。エディターの窓は 26981〜26982、範囲の問いは 26983）。計測の合図が busy のあいだは止まり、23:59 に止まる。
- 変えないもの：Air の Istesso の本物の身元とペアリングの一覧、`ish-shell-only`、毎日の試用版、昼のエージェント（26850）とそのフォルダー。

`rollback` は、エージェントを、書き留めた番号で止める。足したものは、各機械の `~/.local/state/istesso-next-stage/<時刻>/removed/` へ移す（消さない）。置き換えたファイルは、写しを戻して、入れる前の sha256 と、権限が同じことを確かめる。シェルが開いているか、マウントが使われているときは、何もせずに、そう言って止まる。

プログラムは、先に `scripts/next-stage.sh stage` で、コミットごとの包み（Air は SSD の `istesso/next-stage/stage/<コミット>`、ホストは `~/istesso-scratch/next-stage/stage/<コミット>`）に作っておく。`install` は、包みの `SHA256SUMS` を確かめてから写すだけで、作り直さない。

## 持ち主が決めること（既定の値がおすすめ）

| 設定 | 既定 | 何か |
|---|---|---|
| `NEXT_NAME` | `ish` | コマンドの名前。`ish` 以外にすると、いまの `ish` は置き換えずに残り、cd-switch.zsh に、その名前を使う行が足される |
| `NEXT_BIN` | `~/.local/bin` | 置く場所 |
| `NEXT_MOUNT_ROOT` | `~/Istesso` | ホストのフォルダーをマウントする場所 |
| `NEXT_FOLDERS` | なし | ホストで、名前で開き、読むだけで見せるフォルダー。`ID=フォルダー` を空白で区切る（例：`link-proj=~/link-proj`）。ID が名前にもなる。なしなら、どのフォルダーも見せず、名前も引けない |

ほかの設定（場所、ポート、止まる時刻、エディターの元）は、`scripts/next-stage.sh` の頭に書いてある。`install` は、与えられた設定を記録に残す。`rollback` は、記録の設定で戻すので、設定を打ち直さなくてよい。

## 守りの限り（試すときに知っておくこと）

- **範囲（agent scope）は、持ち主のユーザーのままで動くので、範囲の中のコマンドは、ホストの持ち主のほかの端末（`/dev/pts`）を開ける。そこで打った字の一部を読み、字を書き、エコーを切れる**（見直し 7b の A1、中）。直すのは、専用のユーザーにするとき（あとで）。このユーザーは docker のグループにいるので、Docker のデーモンにも届く（範囲は、始めるたびに、そう言う）。
- **窓の題名の「(from a program)」は、その窓を開いた頼みが、だれからだったかだけを言う。** 窓が開いているあいだに、プログラムが頼んだファイルは、印なしで、その窓に入る。分かるのは、端末に出る知らせの 1 行だけである（見直し 7c の 2）。
- **はじめて試すときに、新しく開いた窓が、Air でいま打っている字を取ってしまわないかを見る**（見直し 7c の 11。だれもまだ見ていない）。取るなら、ホストのプログラムが、打っている最中に窓を出せば、打った字はホストのエディターと、その下書きに入る。
- 入れたシェルでは、窓を出すプログラムが決まっているときだけ、ホストに窓を頼む（見直し 7c の 3 を、このブランチで直した）。窓の記録はシェルごとのフォルダーに置き、シェルが終わると、そのシェルの窓を閉じる。`ps` の時刻は、いつも C のロケールで読む（7c の 1。日本語の端末と英語の端末をまたいでも、自分の窓を見失わない）。
- 転送が断るのは、Air のほかのユーザーのプログラムだけである。同じユーザーのプログラムと root は断らない（ADR 0007）。
- 名前で開くとき（と、`install` の最後の確かめ）は、プロジェクトの一覧のために、Air で道具の版を調べる（`cargo --version`、`xcodebuild -version`、`simctl list` など。doctor の仕事）。adb は、サーバーが動いているときだけ聞く。

## 予行（2026-11-20、流れのフォルダーで）

両方の機械で、HOME と、書き込む場所のすべてを、流れのフォルダーに向けて、同じ台本を通した（ポート 26985〜26989）。画面に何も出さないため、予行だけ、エディターの窓を開かない設定（`NEXT_VIEWER_DRY=1`）と、ページを開く代わりに書き留めるだけのプログラム（`NEXT_URL_OPENER`）を使った。結果は、ブランチの記録ではなく、流れの状態のファイルに書いた。
