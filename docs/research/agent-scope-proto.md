## 0. 先に結論

1. **Landlock の版 7 で、段 (1)(2)(3) の起動の係を作った。** プロジェクトの外のファイル、持ち主のホーム、`/tmp` は、読むことも書くこともできなかった。中継のポート以外への TCP のつなぎは、断られた〔実〕。
2. **開発の道具は、囲いの中で動いた。** 段 (1) で `cargo init` と `cargo build`、`python3`、`node`、`git`（init、add、commit）。段 (2) で `nvidia-smi`（GPU を数えた）と `adb`（自分のサーバーを起こして一覧）〔実〕。
3. **待ち受けのポートを絞らない形で、開発サーバーは動いた（アドレスはループバックに限る。7 番）。** 外（ポートの転送の役）からは届いた。ただし、囲いの中から自分の開発サーバーにつなぐには、そのポートを「つなげる先」に足す必要があった（`--connect-port`）〔実〕。
4. **Landlock は、ポートだけで決める。** 中継と同じ番号なら、よその機械へもつなぎに行けた（断られず、時間切れになった）。UDP は止まらない〔実〕。だから、段 (3) を守るには、専用ユーザーと nftables の決まり（root、1 回）が要る（7 章）。
5. **同じユーザーの抜け道は、この起動の係の中からも開いていた。** Docker のソケットに `_ping` が通り、`systemd-run --user` で、囲いの外のファイルを読めた〔実〕。起動の係は、ユーザーが `docker` のグループにいると、起動のたびに警告を出す。
6. **「止めて聞く」を、ファイルを開くことについて足した**（seccomp のユーザー通知）。範囲の外のファイルを開こうとすると止まり、聞く役（いまは代わりのシェルのコマンド）の答えで、今回だけ許すか、断る〔実〕。依存 3 つのビルド（約 7,600 回 開く）で、2.16 秒が 2.31 秒になった（約 7 %）〔実〕。
7. **待ち受けを、この機械の中だけにする**（持ち主の今夜の件）。起動の係が、`bind` と `listen` を代わりに行い、広いアドレス（`0.0.0.0`、`::`）をループバックに移す形を作った。`python3 -m http.server`（アドレスを指定しない）は、`127.0.0.1` だけで待ち受け、外からはループバックで届いた〔実〕。root は要らない。専用ユーザーには、7 章の nftables の決まりを重ねる。5 章。
8. **Docker（持ち主の追加の問い）：おすすめは、コーディングの専用ユーザーの rootless Docker**（持ち主の Docker とは別のデーモン）。root の手順は、`uidmap` を入れることと、linger。AppArmor の決まりは、足さなくてよい見込み〔資〕。GPU は、CDI で渡せる見込み〔推〕。比べた案は 6 章。
9. **範囲の外で止めて、Air に「今回だけ／広げる／断る」を聞く形を、端から端まで動かした**（10 章）。ホストの囲いの中で、試しのコマンドが範囲の外に触れると止まり、問いが Istesso のリンク（`istesso-link` の暗号の道。試しの鍵）で Air に届き、Air の答えで続くか失敗した。Air は、決まった答えの並びで答えた（試しの形。窓ではない）。8 つの問いと 3 つの答え（と「この実行のあいだ広げる」）が、どれも思ったとおりに効いた〔実〕。
10. **TCP Fast Open は、Landlock の「つなぐ」の決まりを通り抜けた**〔実〕。`connect` では断られたポートに、`sendto(MSG_FASTOPEN)` ではつながり、相手の答えを受け取った（カーネル 6.17、Landlock の版 7）。2 章の P6 の「ほかのポートは断られた」は、`connect` についてだけ正しかった。**MPTCP のソケット**（`IPPROTO_MPTCP`）でも、断られたポートにつながった〔実〕。起動の係は、いまは、段 (1)〜(3) のどれでも、seccomp で、`MSG_FASTOPEN` と MPTCP のソケットと `io_uring` を断る（10.5）。

## 1. 作ったもの

`crates/istesso-scope`（Rust。Linux だけで囲う。ほかの OS では `plan` だけが動く）。

```sh
istesso-scope run --level 1 --project <プロジェクト> --state <範囲のフォルダー> --relay-port 26880 -- <コマンド>
istesso-scope plan  --level 2 --project … --state …     # 何を許すかを表示するだけ
istesso-scope check [--probe-network]                   # このカーネルで何を守れるか

# 範囲の外で止めて聞く（10 章）
istesso-scope run --level 1 … --hold-files --hold-connect \
    --ask-listen <アドレス:ポート> --link-keys <鍵のフォルダー> --ask-device <端末の名前> \
    --grants <覚えのファイル> -- <コマンド>
istesso-scope answer --connect <アドレス:ポート> --keys <鍵のフォルダー> [--script once,refuse,…]
istesso-scope link-keys --dir <鍵のフォルダー>          # 試しの鍵を作る（本物の鍵ではない）
istesso-scope link-trust --dir … --name … --public-key-file …
```

| | 段 (1) | 段 (2) | 段 (3) | 段 (4) |

- 環境変数は、決まったもの（`TERM`、`LANG`、`LC_*` など）だけを渡す。`HOME`、`TMPDIR`、`XDG_*`、`CARGO_HOME` は、範囲のフォルダーの中に向ける。`http_proxy` などは、中継に向ける。ソケットの場所（`SSH_AUTH_SOCK`、`DBUS_SESSION_BUS_ADDRESS`、`XDG_RUNTIME_DIR`、`DOCKER_HOST`、`DISPLAY`）とトークンは、渡さない。**これは、守りではない。** 場所はよく知られていて、中で自分で書けば届く（4 章）。
- 閉じる側に倒す：カーネルの Landlock が版 6 より古いと、起動を断る。起動のたびに、守れるものと守れないもの（名前の付いたソケットは版 9、UDP は版 10 から）を、標準エラーに出す（`--quiet` で消せる）。
- Rust のクレート `landlock`（MIT OR Apache-2.0。依存は `enumflags2`、MIT OR Apache-2.0）を使う。新しい版の権利（版 9 の名前の付いたソケット）まで頼み、カーネルが知らない分は、クレートが落とす。だから、カーネルが新しくなれば、この係を変えずに、ソケットも絞られる見込み〔推〕。`cargo deny check licenses` は通った〔実〕。

## 3. 止めて聞く（`--hold-files`、seccomp のユーザー通知）

- 守りの本体は、Landlock のまま。seccomp の係（監督するプロセス）は、「聞くかどうか」だけを決める。
  - ファイルを開く呼び出し（`open`、`openat`、`creat`）は、全部、係に届く（BPF は、場所の文字を読めないため）。`openat2` は「ない」と返して、`openat` に戻させる。
  - 係は、場所を読み、範囲の中なら、カーネルに任せる（`CONTINUE`）。このとき、Landlock がもう一度確かめるので、読んだあとで場所の文字を変えられても、抜けない（調査 E の L31 の注意は、この形では、守りの穴にならない）〔推〕。
  - ないファイル（`O_CREAT` なし）、`/proc` と `/dev/fd` の下（パイプなどへのリンク）も、カーネルに任せる。道具は、設定のファイルを、上のフォルダーへさかのぼって探す（`rust-toolchain.toml`、`.cargo/config.toml` など）。最初の版は、これを全部聞いてしまい、「Permission denied」を返していた（ないなら「ない」が正しい答え）。直した〔実〕。
  - 範囲の外にある、本当にあるファイルだけを、止めて聞く。今回だけ許すときは、係が自分で開いて、その記述子を、止まっているプロセスに渡す（`ADDFD`）。断るときは `EACCES`。
- 聞く役は、いまは代わりのもの（`--ask-cmd`：シェルのコマンド。終わりの値 0 が「今回だけ許す」）。本物は、Air の窓になる（ADR 0026 の決定 4）。答えを待つあいだ、止まったプロセスは待っていた（`sleep 1` の答えで、1,004 ms 待った）〔実〕。
- 速さ（ホスト、32 の処理単位。依存 3 つ（clap、serde、serde_json）を手元に写したプロジェクトの、まっさらからのビルド。3 回ずつ）〔実〕：

  | 形 | 1 回目 | 2 回目 | 3 回目 |
  |---|---|---|---|
  | 囲いなし | 2.172 秒 | 2.108 秒 | 2.192 秒 |
  | 段 (1) | 2.173 秒 | 2.081 秒 | 2.174 秒 |
  | 段 (1)＋止めて聞く | 2.292 秒 | 2.329 秒 | 2.304 秒 |

  止めて聞く形では、1 回のビルドで、開く呼び出しが約 7,640 回 係に届き、聞いたものは 0。係の手間は合わせて 51〜83 ms。Python で、標準のモジュール 20 個を読む試しは、3 つの形とも 0.05 秒ほどで、差は見分けられなかった〔実〕。Landlock だけの形は、速さに差が見えなかった〔実〕。
- 限り：
  - （2026-11-20 に直した）はじめの版の係は 1 つのスレッドで、答えを待つあいだ、ほかの開く呼び出しも待たせた。いまは、聞くことを別のスレッドで行い、ほかの呼び出しは待たせない（10 章）。
  - `io_uring` で開くと、係を通らない。そのときも Landlock は効くが、聞かずに断られる〔資〕〔推〕。
  - 範囲の外か中かの見立てが外れると、聞かずに断られる（Landlock が先に断る）。逆は起きない（係は、Landlock より広くは許さない。今回だけ許すときを除く）〔推〕。
  - 係が落ちると、止まっていた呼び出しには「ない」（`ENOSYS`）が返る〔資〕。

## 4. 同じユーザーの抜け道（なぜ専用ユーザーが要るか）

持ち主のユーザーのまま囲うと、Landlock の外へ出る道が残る。この試作の起動の係の中からも、同じだった。

| 道 | このホストで | 専用ユーザーにすると | 印 |
|---|---|---|---|
| Docker のソケット（持ち主は `docker` のグループ。root と同じ力） | 囲いの中から `GET /_ping` が通った（読むだけの問い合わせ 1 回） | 専用ユーザーを `docker` のグループに入れなければ、ソケットの権限で開けない | 〔実〕〔推〕 |
| ユーザーの systemd（`systemd-run --user`） | 囲いの中から、`XDG_RUNTIME_DIR` を自分で書いて、外のファイルを読めた（一時の単位を 1 つ起こした） | その専用ユーザーの systemd になる。持ち主のファイルには届かない。**ただし、同じ専用ユーザーのほかのプロジェクトには届く** | 〔実〕〔推〕 |
| セッションバス、持ち主の ssh-agent や鍵束のソケット | 試していない。名前の付いたソケットなので、版 7 では止まらない | 専用ユーザーからは、持ち主のランタイムディレクトリ（0700）に入れない | 〔推〕 |
| UDP（DNS を含む） | 送れた（P8） | nftables の決まりで止める（7 章） | 〔実〕〔推〕 |
| 中継と同じ番号の、よその機械のポート | つなぎに行けた（P7） | nftables の決まりで止める | 〔実〕〔推〕 |

- 起動の係は、`docker`、`lxd`、`incus-admin`、`libvirt` のグループにいるユーザーで動くと、起動のたびに警告を出す。`check --probe-network` は、そのユーザーの通信を止める決まりがあるかを、どこにも届かないアドレスへ UDP を 1 つ送って確かめる（決まりがあれば、すぐに「Operation not permitted」で失敗する見込み〔推〕。持ち主のユーザーでは「ない」と出た〔実〕）。
- 専用ユーザーにしても、**同じ専用ユーザーの中の、プロジェクトとプロジェクトのあいだ**は、Landlock だけが分けている。そこには、名前の付いたソケットの道（その専用ユーザーの systemd、その専用ユーザーの rootless Docker）が残る〔推〕。閉じるには、Landlock の版 9（名前の付いたソケットを絞れる）か、プロジェクトごとのユーザーが要る。
- `sudo` は、囲いの中では特権を得られない（Landlock が `no_new_privs` を立てるため）〔資〕。だから、`sudo` のグループは、囲いの中からの抜け道ではない。ただし、専用ユーザーは、`sudo` のグループに入れない（囲わない段 (4) があるため）。

## 5. 待ち受けを、この機械の中だけにする

持ち主の今夜の件：Ubuntu の遠くのシェルで、コーディングエージェントが `python3 -m http.server 8000` を動かした。アドレスを指定しないと、すべてのアドレスで待ち受けるので、プロジェクトのフォルダーが、家の LAN のほかの機器から見えた。

- Landlock は、待ち受けのポートは絞れるが、アドレスは絞れない〔資〕（調査 E の L12）。この試作は、待ち受けのポートを絞らない（開発サーバーのため。2 章の P10）。
- このホストには、受け取りを止める決まりがない。ufw は入っているが、有効になっていない（`ENABLED=no`）〔実〕。だから、だれのプログラムでも、すべてのアドレスで待ち受ければ、LAN から届く。

### 作ったもの（起動の係の seccomp。root なし）

段 (1)〜(3) では、既定で、`bind` と `listen` を係に回す（`--listen-anywhere` で外せる）。

- `bind`（インターネットのソケット）：係が、そのソケットを `pidfd_getfd` で受け取り、**自分の持つアドレスの写し**で、自分で bind する。ループバックでないアドレスは、同じポートのループバックに替える（`0.0.0.0` → `127.0.0.1`、`::` → `::1`）。中で、読んだあとにアドレスを書き換えても、効かない。
- `listen`：係が、受け取ったソケットで、自分で listen する。まだ bind していないソケット（カーネルなら「すべてのアドレス」にする）は、先にループバックに bind する。ループバックでないアドレスに bind 済みのものは、断る。記述子の番号をすり替えても、効かない（係は、自分の手にあるソケットに対して行う）。
- `io_uring` は、bind と listen をシステムコールなしで行えるので、使えなくした（`ENOSYS`）。
- 結果：2 章の P19、P20〔実〕。ポートの転送（ADR 0025）は、ループバックの待ち受けを見つけて、つなげばよい。見つけ方は変わらない（`/proc/net/tcp` に `127.0.0.1:<ポート>` で出る）。
- 速さ：bind と listen は数が少ない。依存 3 つのビルドで、囲いなし 2.09〜2.12 秒、段 (1)（この係あり）2.12〜2.16 秒〔実〕。
- 限り：
  - 係が「0.0.0.0 に移さなかった」ことを、プログラムは知らない。表示は「0.0.0.0 で待っています」のまま〔実〕。
  - `::`（IPv6 と IPv4 の両方）を `::1` に移すと、IPv4 の `127.0.0.1` では届かない。転送の係は、両方を試す〔推〕。
  - UNIX のソケットなどの `bind` は、カーネルに任せる。その瞬間に、インターネットのソケットを同じ番号にすり替えると、そのソケットは、すべてのアドレスに bind できる。`listen` は断るので、TCP は待ち受けられない。残るのは UDP の受け取り〔推〕。わざと競争させる相手（悪意のあるエージェント）のときだけの話である。
  - 囲う前に開いていたソケット、係の外で起動されたプログラム（今夜の件そのもの）には、効かない。
  - x86-64 だけ（試作）。係（`istesso-scope` のプロセス）は、囲った側が全部終わるまで残る。係を止める合図を、子に渡す作りはまだない。

- 決まりは、ほかのユーザーの通信と、ソケットのない通信（カーネルが出すもの）には触れない。`flush ruleset` を使わないので、Docker の決まりを消さない。Ubuntu の `nftables.service`（設定の頭で全部を消す）は使わない〔推〕。
- 専用ユーザーが LAN から受けたつなぎには、返事が出ない見込み〔推〕（返事の最初の一つ（SYN-ACK）は、待ち受けのソケットの持ち主として見分けられるはずだが、確かめていない。どちらにしても、そのあとの中身は出ない）。すべてのアドレスで待ち受けても、LAN からは使えない。5 章の b。
- 決まりが入ったかは、専用ユーザーで `istesso-scope check --probe-network` を動かして見る（「present」になる見込み）。起動の係は、のちに、決まりがないと段 (1)〜(3) を断る形にする〔推〕。
- **残るもの：** この機械の中（ループバック）の TCP は、全部つなげる。段 (1)〜(3) では、Landlock がポートを絞る。段 (4) と、ホストのループバックに届く形にしたコンテナーからは、持ち主のループバックのサービス（例：持ち主の adb のサーバー）に届く〔推〕。

1. 【問い】専用ユーザーの名前（仮：`istesso-code`）。ADR 0021 の「2 つめの専用ユーザー」と同じもの、として書いた。

### 10.1 仕組みを、どれにしたか

Landlock は、断るだけで、呼び出しの途中で聞けない〔資〕。動いているプロセスの決まりを、あとから広げることもできない（狭めるだけ）〔資〕。だから、「止めて聞く」には、別の仕組みが要る。root なしで使える候補を比べた。

| 案 | 止めて待てるか | 今回だけ | この実行のあいだ広げる | 覚えて広げる | 費用 | 守らないもの |
|---|---|---|---|---|---|---|
| **A. seccomp のユーザー通知＋Landlock**（採った） | 待てる。`open`、`openat`、`creat`、`connect` を、係に回す〔実〕 | 係が、自分で開いて記述子を渡す（`ADDFD`）。つなぐのは、係が、そのプロセスのソケットを受け取って（`pidfd_getfd`）、自分でつなぐ〔実〕 | 係が、その実行が終わるまで、同じことを代わりに続ける〔実〕 | 次の起動から、ファイルとフォルダーは Landlock の決まりになる〔実〕。宛先は、係が代わりにつなぐ（Landlock はポートしか見ないため） | 開く 1 回に約 11 µs（10.4）。x86-64 だけ。係が止まると、止まっていた呼び出しは失敗する | 係に回さない呼び出し（名前の変更、リンク、消す、フォルダーを作る、プログラムを動かす、`stat` など）は、聞かずに、Landlock が断る（10.4 の E11〜E14、10.6）。同じユーザーの抜け道（4 章） |
| B. 断ってから知らせ、広い Landlock で開き直す | 待てない。何が断られたかを知るのに、Landlock の記録（監査）が要る〔推〕。このホストでは、記録は見つからなかった（調査 E） | できない。開き直すと、プロセスの中の状態がなくなる | 開き直し | 開き直し（次の起動と同じ） | 開き直すたびに、コーディングエージェントの作業が途切れる。続きから始められるかは、道具しだい | — |
| C. FUSE（プロジェクトの外を、FUSE の中だけで見せる） | 待てる（FUSE の係が答えるまで、カーネルが待つ）〔資〕 | できる | できる | できる | マウントは、Landlock を掛ける前に作る（Landlock の中ではマウントできない。調査 E の L20）。`fusermount3`（setuid）か、名前空間（このホストでは、特権のない名前空間が AppArmor で止まる。調査 E の L24）が要る。読み書きの全部が、係を通る | FUSE の中だけ。ネットワークは、別の仕組みが要る |

**A を採った。** 守りの本体は、Landlock のまま。係は、聞くかどうかを決め、許されたら、自分で、自分の持つ写しで行う。

- 範囲の中のもの：カーネルに任せる（`CONTINUE`）。Landlock が、もう一度確かめる。だから、係が読んだあとで、プロセスが、場所やアドレスの文字を書き換えても、範囲の外には出られない（調査 E の L31 の注意は、この使い方では、穴にならない）。ファイルについては、競争させて確かめた（10.4）〔実〕。アドレスについては、試していない〔推〕。
- 範囲の外のもの：Air に聞く。許されたら、**係が、Air に見せたものを、自分の写しで行う。** ファイルは、`openat2` で、リンクを 1 つもたどらずに開く（`RESOLVE_NO_SYMLINKS`）。だから、聞いたあとで、その場所をリンクにすり替えても、ほかのファイルは渡らない。開くのが失敗する（10.4 の E10）〔実〕。つなぐのは、プロセスのソケットで、係が持つアドレスの写しへ。
- 係が開いて渡すのは、ふつうのファイルとフォルダーだけ。機器、FIFO（開くと係が止まる）、ソケットは、聞かずに、Landlock に任せる（断られる）〔実〕。

### 10.2 問いと答えの道

```
Air（試しの形）                          Ubuntu のホスト
istesso-scope answer  ── Istesso のリンク ──  istesso-scope run（起動の係）
  問いを見せ、答えを返す   （Noise、試しの鍵）     └─ 囲いの中のコマンド（段 (1)）
```

- 道は、`istesso-link` の暗号の道（Noise XX と、身元の鍵の証明。ADR 0007）を、そのまま使った。鍵は、この試しのためだけのもの（`istesso-scope link-keys`、`link-trust`。公開の半分を、SSH の上で写した）。**この機械の本物の鍵と、ペアの一覧には、触れていない。**
- シェルの試作（`proto-remote-shell` ブランチ）の会話には、載せなかった。シェルの会話は、ホストのプログラムが自由に出せる端末の字を運ぶ。問いを、その中に混ぜると、コーディングエージェントが、問いに見える字を出せる（ADR 0026 の 3：ターミナルの中には出さない）。本物では、Istesso のエージェントの制御の道に、別の頼み（たとえば「範囲の問いを受ける」）を足す形になる〔推〕。
- 順番：起動の係が、待ち受け、**決まった 1 台**（`--ask-device`。頼んだ端末のつもり）がつなぐのを待ってから、コマンドを始める。ほかの端末、知らない鍵は、断る〔実：単体の試験〕。答える端末がつながらなければ、始めない。
- 問いは 1 つずつ。答えを待つあいだも、ほかの開く呼び出しは、待たせない（聞く係は、別のスレッド。作りからの見立てで、試していない〔推〕）。決まった時間（試しでは 30 秒）のあいだ答えがなければ、断る。遅れて届いた答えは、次の問いの答えにしない〔実：単体の試験〕。道が切れたら、そのあとの問いは、全部、断る。
- Air の形に出すもの：プログラムの名前（プロセスが自分で決められるので「自称」と書く）、プロセスの番号、何をしようとしたか（開くファイルとその読み書き、つなぐ宛先）、プログラムが使った名前（リンク、`..`、`/proc/self` で違うとき）、広げると何が足されるか。端末を動かす字（エスケープなど）と、見えない字、並びを変える字（Unicode の書式の字：bidi の制御、幅のない字、BOM など。普通でない空白）は、そのまま出さず、見える形（`\u{202e}` など）に直す〔実：単体の試験〕。**そういう字を含む場所は、そもそも聞かない**（カーネルに任せ、断られる）〔実：囲いの試験〕。形の似た別の文字（キリル文字の「а」など）は、見分けない。

### 10.3 答えと、それぞれが何をするか

| Air の答え | 試しの形の言葉 | 何をするか | 覚えるか |
|---|---|---|---|
| 今回だけ | `[1] allow once` | その操作 1 回だけ、係が代わりに行う | 覚えない |
| 広げる（この実行のあいだ） | `[2] widen for this run` | その操作と、同じファイル（フォルダーなら、その下全部）、同じ宛先への、その実行の終わりまでの操作を、係が代わりに行う | 覚えない |
| 広げる（覚える） | `[3] widen and keep` | [2] と同じ。加えて、範囲の覚え（`--grants` のファイル）に書く。次の起動から、ファイルとフォルダーは Landlock の決まりになる（係なしでも効く）。宛先は、係が代わりにつなぐ | 覚える |
| 断る | `[4] refuse` | 「Permission denied」（`EACCES`） | 覚えない |
| 答えがない | — | 断る | 覚えない |

- **「広げる」の 2 つを、どちらも作った**（「この実行のあいだ」と「覚える」）。ADR 0026 の【問い 範5】のおすすめ（「今回だけ」は、そのコーディングエージェントが終わるまで）は、この表の [2] にあたる。持ち主の 3 つのボタンにするなら、今回だけ＝[2]、広げる＝[3]、断る＝[4] になる。[1]（その操作 1 回）を残すかは、【問い】（10.7）。
- 覚えのファイルは、1 行に 1 つ（`read <場所>`、`write <場所>`、`connect <アドレス:ポート>`）。場所は、行の残りを、そのまま。**書いたとおりに読み戻せない場所（UTF-8 でない、制御の字、改行、`\r`、見えない字）は、覚えない。** 読むときも、そういう字のある行は、削らずに、ファイルごと誤りにする（起動を断る）〔実：単体の試験〕。はじめの版は、行の終わりの `\r` を削っていたので、`b.txt\r` を覚えると、`b.txt` を広げることになっていた（見直しの指摘。直した）。
- 覚えの置き場（`--grants`）は、囲いの中から書けない所にしか置けない（書ける所なら、起動を断る）〔実〕。リンクの鍵のフォルダーも、囲いの中から読める所なら、起動を断る。**ただし、同じユーザーの抜け道（4 章）を使えば、囲いの中から、覚えも鍵も書き換えられる**〔推〕。専用ユーザーができるまでは、守りではない。
- 「広げる」の確かめ（持ち主がいることの確かめ。【問い 範6】）は、作っていない。

  - 段 (1)、外のファイル 2 つ、1 つめだけ「今回だけ」で許し、2 つめは断る：29,952 回開き、1 つめが 14,727 回、**2 つめは 0 回**（08:11：30,080 回、2 つめは 0 回）。許したときは、係が、自分の写しの場所を開くので、文字を書き換えても、ほかのファイルは渡らない。
- 起動の係の数え（FIFO の段を足したあとの回）：開く 64 回と、つなぐ 2 回が係に届き、56 回はカーネルに任せた。問い 8（今回だけ 4、この実行のあいだ 1、覚える 1、断る 2）。広げたあとの、聞かずに代わりに行ったもの 2〔実〕。
- 答えの往復は、ホストの記録で、どれも 1 ms 未満だった（Air は、決まった答えを、すぐに返す。人が読む時間は入っていない）〔実〕。
- 2 回目（同じフォルダー、同じ覚えのファイルで、新しく起動。答えの並び：断る、断る）〔実〕：`b.txt` に書くのは、聞かれずにできた（Landlock の決まりになった）。`a.txt`（今回だけ）と `e.txt`（この実行のあいだ）は、また聞かれ、断ると `EACCES`。覚えたのは [3] だけだった。
- 単体の試験（Air とホストの両方、ループバック）：答え 3 つが道を渡る。知らない端末と、名指ししていない端末は、断られる。答えが遅れると断られ、遅れた答えは、次の問いの答えにならない〔実〕。
- 囲いの試験（ホスト）：上の E10 のほか、「今回だけ」「この実行のあいだ」「覚える」（次の起動では、係なしでも読める）、つなぐ（許す／断る）、リンクと `..` の問いが、本物のファイルを名指しすること〔実〕。

**速さ**（ホスト。読み込みが 5 前後の、ほかの作業があるときに。1 つの Python のプロセスが、プロジェクトの中の 3,000 個のファイルを 5 回ずつ開く。release のビルド。3 回）〔実〕：Landlock だけ 0.017〜0.029 秒、止めて聞く形 0.165〜0.196 秒。開く 1 回に、約 11 µs 足される。3 章の「依存 3 つのビルドで約 7 %」は、リンクを自分でたどる前の版の数で、測り直していない。

### 10.5 TCP Fast Open と MPTCP が、Landlock を通り抜けた

- ホスト（カーネル 6.17、Landlock の版 7、`net.ipv4.tcp_fastopen` は 1）で、段 (1)、係なし（Landlock だけ）：`connect` で 26887 へは「Permission denied」。同じプロセスが、`sendto(…, MSG_FASTOPEN, 127.0.0.1:26887)` では、つながり、相手の答えを受け取った〔実〕。`--hold-connect` の係も、これを見ていなかった（`sendto` は係に回していない）〔実〕。
- 見立て：Fast Open は、送る呼び出しの中で、つなぎを作る。Landlock の「つなぐ」の確かめは、`connect` の呼び出しの道にだけある〔推〕（カーネルのソースは読んでいない）。
- 直し：起動の係の seccomp の決まりで、`sendto`、`sendmsg`、`sendmmsg` に `MSG_FASTOPEN` が付いていたら、`EOPNOTSUPP` を返す。係のない形（`--listen-anywhere`、止めて聞かない）でも、同じ決まりだけを掛ける。直したあと、どちらの形でも `EOPNOTSUPP`、段 (4)（囲わない）では、これまでどおりつながった〔実〕。
- **MPTCP**（見直しの指摘を受けて、ほかの道を試したときに見つけた）：段 (1)、係なしで、`socket(AF_INET, SOCK_STREAM, IPPROTO_MPTCP)` から 26887 へ `connect` すると、つながり、相手の答えを受け取った（MPTCP は、相手が知らなければ、ふつうの TCP に戻る）。`--hold-connect` の係も、通した（TCP でないソケットは、カーネルに任せる作りだったため）〔実〕。見立て：Landlock の TCP の決まりは、TCP のソケットにだけ効く〔推〕。直し：段 (1)〜(3) のどの形でも、`socket` の 3 つめの引数が `IPPROTO_MPTCP` なら `EPROTONOSUPPORT`（使う道具は、TCP に戻る見込み〔推〕）。
- 見直しの指摘で、係を通らずに開く、つなぐ道を、ほかにも試した（段 (1)。係なし／`--hold-connect` の係あり／段 (4)。直しの前と後）〔実〕：

  | 道 | 直しの前（係なし） | 直しの後（係なし、係あり） | 段 (4) |
  |---|---|---|---|
  | ふつうの `connect` | `EACCES` | `EACCES`（係ありは、聞いてから断る） | つながる |
  | MPTCP の `connect` | **つながった** | `EPROTONOSUPPORT` | つながる |
  | `TCP_FASTOPEN_CONNECT` を立ててから `connect` | `EACCES` | `EACCES`（係ありは、聞いてから断る） | つながる |
  | つないでいない TCP のソケットへ、宛先つきの `sendto`（Fast Open なし） | `EPIPE` | `EPIPE` | `EPIPE` |
  | `io_uring_setup` | **使えた**（係ありは `ENOSYS`） | `ENOSYS` | 使える |
  | `open_by_handle_at` | `EFAULT`（引数を空にした試し。呼べた） | `ENOSYS` | `EFAULT` |

- 直しのあとの決まり：`io_uring_setup`、`io_uring_enter`、`io_uring_register`、`open_by_handle_at` は、係があってもなくても、`ENOSYS`。`io_uring` は、係を通らずに開き、つなぎ、送れる（`MSG_FASTOPEN` も）ため。`open_by_handle_at` は、場所なしで開くため（開いたものは Landlock が確かめるが、聞かれない）〔推〕。`openat2` は、係のあるときだけ `ENOSYS`（係のないときは、Landlock がそのまま確かめる）。
- 残り：SCTP、UDP、生のソケットなど、TCP でない道は、版 7 では止まらない（4 章、7 章の nftables の決まりが要る）。Landlock の版 10 以降で、Fast Open と MPTCP がどう扱われるかは、調べていない。**これは、この試作だけでなく、Landlock でポートを絞る形の全部に当たる。** 見直しの役と、ADR 0026 の「守らせる仕組み」に、伝えたい。

### 10.6 限り（守らないもの、確かめていないもの）

- 係に回すのは、`open`、`openat`、`creat`、`connect` だけ。ほかの呼び出し（名前の変更、リンク、消す、フォルダーを作る、プログラムを動かす、`stat`、`readlink`、`truncate` など）は、範囲の外なら、聞かずに Landlock が断る（E11〜E13）〔実〕。だから、「広げる」も、開くこととつなぐことにしか効かない。たとえば、広げたフォルダーに、名前の変更で移すことはできない〔推〕。
- `openat2` は、係のある形では「ない」と返す（道具は `openat` に戻る）。`io_uring` と `open_by_handle_at` は、段 (1)〜(3) のどの形でも「ない」と返す（10.5）〔実〕。
- 問いが多すぎる形（ADR 0026 の 5「同じ種類の問いを、続けて出さない」）は、[2] と [3] のほかに、作っていない。わざと問いを出し続けるコマンドは、人の注意を使い果たさせることができる〔推〕。
- 係が開いた記述子は、Landlock の外で開いたもの。そのファイルに対する、そのあとの操作（読み書き）は、Landlock が見ない〔推〕。
- `O_CREAT` で作るファイルの権限は、係の umask で決まる（コマンドの umask ではない）〔推〕。
- 同じユーザーの抜け道（4 章）があるあいだは、囲いの中から、覚えのファイルを書き換えたり、リンクの鍵を読んだりできる見込み〔推〕。そうなれば、自分の問いに自分で答えられる。専用ユーザー（7 章の R1）が要る。
- Air の側は、ターミナルの試しの形。窓、持ち主がいることの確かめ、端末が眠っているときの扱い（【問い 範6】）は、ない。人が手で答える形（`istesso-scope answer` を、`--script` なしで）は、単体の試験の中でだけ動かした（人は答えていない）。
- Mac の囲い（Seatbelt）では、止めて待てない（ADR 0026）。この試作は Linux だけ。

### 10.7 【問い】

1. 【問い】「今回だけ」の長さ。この試作には、[1] その操作 1 回と、[2] この実行のあいだ、の両方がある。おすすめ：ADR 0026 の範5 のとおり、ボタンの「今回だけ」は [2]。[1] は出さない（同じファイルを何度も開く道具が多く、[1] だと、同じ問いが続く）。
2. 【問い】TCP Fast Open と MPTCP と `io_uring` を、段 (1)〜(3) で断ってよいか（10.5）。おすすめ：断る。使う道具は少なく、使えなければ、ふつうの TCP と、ふつうの呼び出しに戻る道具が多い〔推〕。
3. 【問い】覚えた宛先（[3] のつなぐ）を、Landlock のポートにせず、係が代わりにつなぐ形でよいか。おすすめ：よい（ポートにすると、同じ番号の、どの機械へもつながる。2 章の P7）。本物では、中継の一覧に足す形にする（段 (3)）。

### 10.8 動かしたこと（記録）

- **Ubuntu のホスト**（持ち主のユーザー。sudo は使っていない。どの試しの前にも、計測の合図が `free` であることを読んだ）：この流れのフォルダー（ホームの下の、試しの置き場の中）に、リポジトリの写し、ビルドの置き場、試しの鍵、試しの実行ごとのフォルダー（`e2e-<日時>`、`tfo-<時刻>`、`perf-<時刻>`、`race-<時刻>`、`ways-<時刻>`）を作った。消していない。試しの待ち受けは、26881（問いの道。有線のアドレス、1 回の実行のあいだだけ）、26887 と 26888（ループバック、決まった時間で自分で終わり、記録した番号でも止めた）。試しのコマンドは、26889（待ち受けなし）へ、TCP のつなぎと UDP を 1 つずつ送った。
- **Air**：ビルドと試験。試しの鍵を、この流れの一時のフォルダーに作った。`istesso-scope answer` を、端から端までの試しのたびに、ターミナルの外で（窓なしで）動かした。画面には、何も出していない。
