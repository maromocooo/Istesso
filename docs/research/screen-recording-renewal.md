## 1. 記録について分かっていること

- 記録の場所：`~/Library/Group Containers/group.com.apple.replayd/ScreenCaptureApprovals.plist`。TCC で守られていて、読むにもフルディスクアクセスが要る。鍵は、画面収録を許したプログラムの**パス**、値は日付（資1、2024 年。macOS 15）。
- 2026-10 の資料：確認の間隔は 30〜90 日で、`kScreenCapturePrivacyHintPolicy` で決まる。確認は、クライアントの**パス**に結びついている。更新でパスが変わる（版ごとに場所が変わる）アプリは、更新のたびに確認が戻ってくる（資3）。
- プロジェクトで見た（2026-11-19、Studio）：記録は束の場所ごと。新しい場所で起動すると、Studio の画面に確認が出た（流れの決まりの追加、2026-11-19）。
- このプロジェクトの読むスクリプト（上）は、記録の写しから、束ごとに `kScreenCapturePrivacyHintDate` などを読む。

## 2. (1) システム設定で切→入

- 資料：見つからなかった。TidBITS の記事（資2）は、許可を取り消すには設定の切り替えを切る、とだけ書き、日付には触れていない。lapcat の記事（資1）も触れていない。
- **確かめていない。**
- 家で試す手順（案。持ち主が Studio の前で。計測が走っていないとき）：
  1. 記録を読む（読むだけ。証11 と朝の 3 で「読む」は許されている）。いまのホストの束の `kScreenCapturePrivacyHintDate` を控える。
  2. システム設定 → プライバシーとセキュリティ → 画面収録 で、Istesso のホストの切り替えを切る。ホストの絵が止まる。
  3. もう一度入れる。推：アプリを終了して開き直すよう求められる。開き直す。
  4. 絵が出ることを確かめ、記録をもう一度読む。`kScreenCapturePrivacyHintDate` が先へ動いたかを見る。
  5. 動いたら、出かける前の手はこれにする。動かなければ、(2) にする。
- 注意：切り替えは、システム設定のふつうの操作で、記録を手で書き換えることではない。ただし OS が TCC の記録を変える。持ち主の「記録は書き換えない」が、この操作も含むなら、試さない（【問い】1）。

## 3. (2) 置き場所を変える（つなぎ。文書にない動き）

- 根拠：記録の鍵がパス（資1、資3）。新しい場所では確認が出た（プロジェクトで見た）。確認で「許可」すれば、その場所の記録は新しい日付で始まる（推）。
- 手順（案）：
  1. Studio のホストの束を置く場所を、**決まった 2 か所（A と B）**にする。ふだんは A。
  2. 出かける前に、Studio の前で、ホストを止め、束を B に置き換えて起動する。確認が出るので「許可」する。
  3. 記録を読み、B の日付を控える（証11 の知らせは、B を見るように切り替える）。
  4. 次の旅行の前は、B から A へ。
- 注意：
  - **文書にない動き**で、macOS の更新で変わりうる。つなぎとしてだけ使う。
  - 流れの決まり（2026-11-19）は「Studio で、いつもと違うフォルダーから `open` しない」。この手は、持ち主が Studio の前で、わざと行うときだけの例外にする。
  - 新しい場所の束は、macOS には新しく見える。ローカルネットワークの許可など、ほかの許可がもう一度問われるかもしれない（推。確かめていない）。このプロジェクトでは、新しい束の登録のあとで LAN のつなぎが切れたことがある。旅行の直前ではなく、余裕をもって行う。
  - 古い場所の記録は残る（推）。読むスクリプトには、いまの場所を渡す。
  - 束を指している所（起動の設定、スクリプト、`studio-capture-notice.py` の `--keep-entry`）も、A／B に合わせる。

### 2'：時計を進める（勧めない）

- TidBITS の記事（資2、macOS 15.1 のベータで試した）：日付と時刻の自動設定を切り、時計を数か月進め、確認を出して許可し、時計を戻す。そのあと確認は出なかった。
- 影響：カレンダーの知らせが鳴る、サブスクリプションが一時的に切れた（記事）。推：証明書、ログインのトークン、Time Machine、このプロジェクトの記録の時刻にも響く。
- システムの設定を変える手で、計測の Mac（Studio）では、ほかへの影響が大きい。**勧めない。**

## 4. (3) 管理された Mac 向けの「確認を出さない」

- Apple の展開の手引きの制限の表：「Force bypass screen capture alert」。macOS 15.1 から。**監督（Supervised）が要る。**「画面収録の確認の窓を出さない。既定は切」（資4）。
- 監督された Mac になるのは：Automated Device Enrollment（Apple Business Manager などに登録した Mac。macOS 10.14.4 から）。または macOS 11 から、アカウントの Device Enrollment か、プロファイルの Device Enrollment で、デバイス管理のサービスに登録したとき（資5）。
- つまり、個人の Studio で使うには、**Studio をデバイス管理（MDM）のサービスに登録する**ことになる。MDM は、その Mac に広い力を持つ（設定、アプリ、消去など。推）。MDM のサーバーと、その証明書も要る（推）。
- 手で入れたプロファイル（MDM なし）で効くかは、**確かめていない**。
- おすすめ：**個人の Studio には使わない。** 得るもの（確認が出ない）に比べ、MDM に任せるものが大きい。

## 5. (4) 出先から、標準の画面共有で押す

- 画面共有は、システム設定 → 一般 → 共有 で入れる。「すべてのユーザー」か「次のユーザーのみ」を選べる。VNC の合言葉の設定もある。Apple の手引きは「ネットワーク上のほかのコンピューター」からつなぐ、とだけ書く（資6）。推：出先からは、VPN の上で届く（このプロジェクトの出先の形は VPN。ADR 0006）。
- 画面共有からのクリックで、画面収録の確認を押せるか：**確かめていない。** 参考：macOS 10.14 から、作られたクリック（synthetic events）は、許した場合を除き、OS が無視する（資7、2018 年の記事）。画面共有からの入力が、これに当たるかは書かれていない。
- 家で試す手順（案）：3 章の (2) を行う日に、Air から画面共有で Studio につないでおく。確認が出たら、まず Air から押してみる。効かなければ、Studio の前で押す。結果を記録する。
- 注意：
  - 画面共有を入れるのは、Studio のシステムの設定を変えることで、持ち主の手である。LAN と VPN に、画面共有の口が開く（推）。
  - Studio は計測の Mac でもある。計測のあいだは画面共有を使わない（流れの決まり 18：記録に、同時に動いていたものを書く）。
  - 出先で確認が出ても、画面共有が効かなければ、絵は戻るまで止まる。だから 2 章か 3 章の手で、出かける前に日付を新しくしておくのが本筋である。

## 6. PCC（これが通れば、この手は要らない）

- 「Persistent Content Capture」の entitlement：VNC のアプリが、画面を見て記録し続けるためのもの。macOS 14.4 から。使う前に、Apple に申請して許しを得る（資8）。
- 証9：ソースから自分でビルドした版は PCC を持てない。30 日ごとの確認を受ける。だから、この文書の手は、自分でビルドした版では、ずっと要る（推）。
