持ち主が毎日使いたいアプリは、**Blender**（重い。Ubuntu のホストで動かし、Mac から使う）と **Firefox** です（2026-11-18 の依頼）。
この文書は、その 2 つが「ふつうに使える」ために要るものを、いまのコードを**読むだけ**で調べた結果です。足りないものは、M3 の宿題にします。

- 書いた日：2026-11-18（00:20〜00:50 JST に読んだ）
- この文書のために、コードは 1 行も変えていません。ビルドも、計測もしていません。ホストでは、読むことと、Blender の `--version`、`--help` だけを行いました。窓は開いていません。
- 表の中で、**「読んだ」はコードにそう書いてあること、「考えた」は読んだことから導いたこと**です。考えたことは、動かして確かめるまで、事実として扱いません。
- 判定の言葉は 3 つです。**読んだかぎり動く**／**足りない**／**分からない（動かして確かめる）**。

## 4. Blender

Blender 5.3 は、Linux で **Vulkan が既定**です（出典 1）。`--gpu-backend opengl` で OpenGL にもできます（`--help`）。Wayland のライブラリーは同梱しておらず、ホストのものを使います（同梱の一覧に、Vulkan のローダーだけがある）。

Blender は、ドラッグの種類ごとに、ポインターの扱いを変えます（出典 2、3。コミットの説明文から）：

- **端で折り返すドラッグ**（視点の回転、移動・回転・拡大。設定の Continuous Grab が既定で入）：ポインターを**ロック**し、**相対移動**で動きを受け取る。終わるときに、カーソルを置きたい場所をコンポジターに伝える。
- **カーソルを隠すドラッグ**（数値の欄を左右に引く）：同じくロック。
- **折り返さないドラッグ**：窓の中に**閉じ込める**。
- relative-pointer か pointer-constraints がないコンポジターでは、この扱いをしない。

### 4.1 中ボタンのドラッグ

| | |
|---|---|
| アプリが求めるもの | 中ボタン（`BTN_MIDDLE`、0x112）の押す・離すと、そのあいだのポインターの動き。Blender の既定では、ドラッグ中にポインターをロックする（上） |
| コンポジター（読んだ） | ボタンは、番号を選ばずアプリへ渡す（gwd `comp/input.rs` 295〜313 行） |
| プロトコル・ホスト（読んだ） | `Button { code, pressed }` をそのまま `MouseButton` にする |
| 古いクライアント（読んだ） | `otherMouseDown`／`Up` を 0x112 で送る。`otherMouseDragged` で場所を送る（`gst-viewer.m` 1214、1222〜1223 行）。左と右のほかのボタンは、どれも中ボタンになる |
| 自前のクライアント（読んだ） | 同じ（`Istesso.m` 1688、1696〜1697 行）。押したままのボタンを覚え、絵が切れたら離す |
| 考えた | ボタンと動きは届く。ただし、Blender がこのドラッグでロックを使うなら、4.4 の欠けがここにも出る：離したあと、アプリの思うポインターの場所が、Mac のカーソルとずれる |
| **判定** | **読んだかぎり動く**（窓の中）。離したあとのずれは、**動かして確かめる** |

Mac のトラックパッドとマウスには、中ボタンがないものがあります。Blender には、Alt＋左ボタンを中ボタンの代わりにする設定（Emulate 3 Button Mouse）があります（出典 4）。

### 4.4 画面の端を越えて続くドラッグ（ポインターの閉じ込めと相対移動）

| | |
|---|---|
| アプリが求めるもの | pointer-constraints（ロック、閉じ込め）と relative-pointer。ロック中は、ポインターの場所のイベントは出ず、相対移動だけが出る。ロックを解くとき、アプリが伝えた場所にカーソルを置いてよい（出典 6、7） |
| コンポジター（読んだ） | 2 つの口を出している。ロック中は、ポインターを動かさず、相対移動だけを送る（gwd `comp/input.rs` 194〜247 行）。絶対座標で来た動きは、**前の絶対座標との差**を相対移動にする（278〜293 行）。アプリが伝えた場所は、Smithay のポインターにだけ入れ、コンポジター自身が覚えている場所（`pointer_location`）には入れない（`wayland/handlers/pointer_constraints.rs` 24〜46 行） |
| プロトコル・ホスト（読んだ） | 相対移動の種類がない。ロックされたことを、クライアントに伝えるものもない（カーソルの知らせは、隠れた・名前・絵の 3 つだけ。gwd `comp/cursor.rs` 28〜38 行） |
| 古いクライアント（読んだ） | 場所を、絵の中に切りつめて送る（`gst-viewer.m` 1199〜1203 行）。Mac のポインターを捕まえない |

| **判定** | **足りない**。コンポジターの口はある。クライアントの捕まえ、相対移動の種類、ロックの知らせ、解けたあとの場所合わせがない |

|---|---|

| 見た | 2026-11-16：GPU（OpenGL ES）で描くテストアプリの絵が、GPU の上のまま、コンポジターに渡った（[記録](measurements/2026-11-16-step3-85fps-gpu-app.md)）。2026-11-18：Blender のプロセスが GPU のメモリーを使い、メーカーの EGL と Vulkan のローダーを使っている（2 章） |

### 5.1 「全画面」ではなく「最大化」として伝える（案。何も変えていない）

読んだこと：

- 最初の窓（親がなく、大きさの上限を言わない窓）に、出力の大きさと、**`XdgState::Fullscreen`** を伝えている：gwd `wayland/handlers/compositor.rs` 94〜114 行（113 行）。元のプロジェクトの 2023 年のコード。
- 出力の大きさが変わるたびに、全部の窓に、もう一度 `Fullscreen` と `Activated` を伝えている：gwd `comp/mod.rs` 414〜419 行（416 行）。元のプロジェクトの 2026 年 4 月のコード。
- このプロジェクトの修正は、この 2 か所を足しても変えてもいない。ダイアログの修正のテストが、「全画面と伝えられること」を確かめている（`scripts/patches/gst-wayland-display-dialogs.patch` の 312 行）。

案：

- 2 か所の `XdgState::Fullscreen` を、`XdgState::Maximized` にする。窓は出力いっぱいのまま、アプリは帯を残す。テストの 1 行も合わせる。
- 「最大化」にすると、アプリは飾り（題名の帯、「– □ ×」）を描いてよいことになる。Blender は、いまは描いていない見込みで、描くようになるかもしれない。**飾りの口（宿題 11）と一緒に入れるか、入れたあとに Blender の見え方を確かめる。**
- **関門と確定の判定に使うビルドには、当てない。** 別のビルドで試し、判定のあとに入れる。

### 6.1 宿題 7 の中身

| 順 | 作るもの | 層 |
|---|---|---|
| a | ロックと閉じ込めが、始まった・解けたことを、外へ知らせる。解けたときは、アプリが伝えた場所も付ける | コンポジターの修正（カーソルの知らせと同じ形） |
| b | その知らせを、クライアントへ運ぶ | ホスト、知らせの形（ADR 0015 を先に更新） |
| c | 相対移動の種類を足す（`PointerBy { dx, dy }` のような形） | プロトコル |
| d | 相対移動を、コンポジターの `MouseMoveRelative` に渡す。受け口は、すでにある | ホスト |
| e | ロックの知らせで、Mac のポインターを捕まえ、相対移動を送る。解けたら、伝えられた場所へカーソルを動かして、放す。窓が前面でなくなったら、必ず放す | クライアント |

- **Mac で使う API**：`CGAssociateMouseAndMouseCursorPosition(false)` で、マウスの動きとカーソルの場所を切り離す。動きは、イベントの `deltaX`、`deltaY` で読む。カーソルは、`NSCursor` の `hide` で隠す。解けたときは、`CGWarpMouseCursorPosition` で場所を決めてから、つなぎ直す（出典 8）。
- **許可**：どれも、自分の窓が前面にあるときに、自分のイベントを扱うもので、アクセシビリティや入力監視の許可は要らない見込み。macOS 26 で問いが出ないことは、動かして確かめる。新しい許可が要ると分かったら、理由を ADR に残す。
- **気を付けること**：クライアントは、続けて来たポインターの場所を、最後の 1 つにまとめている。相対移動は、**足し合わせて**まとめる。エージェントは、切れたあとに場所を送り直す。相対移動は、送り直さない。ホストの「送り直しを待たせる入力」には入れない（ポインターの場所と同じ扱い）。
- a と b がないうちに e だけを作ると、アプリがロックしていないのに、ポインターを捕まえることになる。**a から順に作る。**

## 7. 手で試すときに、先に見ること

試すときは、アプリの設定を専用のフォルダーに置き、持ち主のふだんの設定に触れません。計測の合図が `busy` のあいだは、始めません。

Blender：

1. 設定の System で、バックエンドと、デバイスの名前を見る。NVIDIA の GPU か。ソフトウェア（llvmpipe、lavapipe）でないか。
2. 絵が乱れないか（ちらつき、古い絵が混じる）。乱れるなら、`--gpu-backend opengl` でも見る。
3. 中ボタンのドラッグで、視点が回るか。**離したあと、次のクリックが、カーソルの下に当たるか**（4.4 の c）。
4. Shift＋中ボタン、Ctrl＋中ボタン。
5. ホイールを 1 目盛り回して、拡大が 1 段動くか。何目盛りで 1 段か。トラックパッドの 2 本指では、何が起きるか。
6. G を押して動かし、ポインターを窓の端の外まで持っていく。動きが続くか、端で止まるか。数値の欄を左右に引いたあと、カーソルはどこにあるか。
7. テンキーの 1、3、7、5、0、小数点。数字として効くか。
8. Ctrl＋Shift＋Tab が届くか（届かない見込み）。
9. 重い場面を回しているあいだ、ほかの操作の遅れがどう変わるか（体感でよい）。

Firefox：

1. `about:support` の「画像処理」で、WebRender がハードウェアか。
2. 帯が消えるのは、どの操作のあとか。F11 を押すと、どうなるか。
3. 長いページのスクロールの速さと滑らかさ。トラックパッドと、ホイールで。
4. ⌘T、⌘W、⌘L、Ctrl＋Tab、Ctrl＋Shift＋Tab。
5. 2 枚目の窓、ファイルを選ぶ窓、動画の全画面。

持ち主に尋ねること：ふだんのマウスに中ボタンがあるか。テンキーのあるキーボードを使うか。なければ、Blender の 2 つの「代わりにする」設定で足りるか。Firefox で、日本語入力と、Mac とのコピー・貼り付けを、M3 の条件に入れるか。

## 8. 読むだけでは、分からなかったこと

- Blender が選んだバックエンドとデバイス。Vulkan の絵がコピーなしで渡っているか。明示的な同期がないことの影響。起動のときの警告（`wl_drm still attached`）の意味。
- Blender が、どのドラッグでロックを使うか。ロックが解けたあとのずれ（4.4 の c）が、実際に出るか。
- Blender が、ホイールの量をどう数えるか（コンポジターが「120 が 1 目盛り」の値を送る版の口を、Blender が使うかどうかで変わる）。
- NumLock が入っていないときに、Blender がテンキーを数字として読むか。
- Mac の API（6.1）が、macOS 26 で、許可の問いなしに動くか。
- Firefox（snap）の中から、GPU のドライバーが見えているか。
- Firefox（GTK）と Blender（libdecor）が、飾りについて、それぞれどの口を見るか。
- 重い場面で、描画とエンコーダーが GPU を分け合ったときの遅延。
