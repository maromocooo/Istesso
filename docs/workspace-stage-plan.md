## 1. 何のための段か

目指す体験（持ち主、2026-11-19）：Istesso の上でターミナルを開き、herdr でコーディングエージェントに「これを作りたい」と頼むだけで、つながっている機械のうち、合うもので開発が始まる。ssh を意識しない。

「ssh を意識しない」を、確かめられる形にするために、ssh が顔を出す場面を、持ち主の分け方で 7 つ並べ、段ごとに、どれが消えるかを書く。

| # | ssh が顔を出す場面 | いま、どうしているか | 消える段 |
|---|---|---|---|
| 1 | 機械に入る | `ssh` で入る。鍵を置く。ターミナルの種類が合わなくて、画面が崩れる | W2 |
| 2 | ファイルを動かす | `scp`、`rsync`。どちらが新しいか、分からなくなる | W3 |
| 3 | localhost が開かない | 開発サーバーは、向こうの機械の中。ポートを手元に引く指定を、手で書く | W4 |
| 4 | 違う認証の機械で開いてしまう | その機械には、ログインも、鍵もない。別のアカウントで、動いてしまう | W1（機械を選ぶ）、W6（足りないものを知らせる） |
| 5 | 鍵や署名で止まる | 署名の問いが、向こうの画面に出て、止まる。鍵を貸す指定を、手で書く | W6 |
| 6 | どの機械か迷う | どこに置いたか、どこで動かすかを、覚えておく | W1 |
| 7 | 範囲を狭めたせいで止まる | コーディングエージェントが、囲いに当たって止まる。確かめの窓が、向こうの画面に出て、気づけない。結局、囲いの外で動かす | W5 |

## 2. 段の並びと、いまの段とのつながり

```
金曜の試用 ─→ M1 の確定の判定 ─→ …（M2〜M10 は、いまのまま）

W1 プロジェクトの一覧と「できること」        （権利に触らない。いつでも始められる）
        │
        │   M5 の決め（「シェル」の権利、持ち主がいることの確かめ、鍵の置き場所）
        │   同じユーザーの線を閉じる作業の 1〜3（ADR 0021）
        ▼
W2 ターミナルを文字で運ぶ ──→ W4 ポートの転送と、URL
        │
        ├──→ W3 マウント（見える・開ける）      （マウントの調査のあと。W4 と並べて進められる）
        │
        └──→ W5 コーディングエージェントの範囲    （囲いの調査と、M5 の専用ユーザーのあと）
                    │
                    ▼
              W6 資格情報と署名
                    │
                    ▼
              W7 通しの確かめ（目指す体験）
```

|---|---|---|
| W1 | なし（M0 は済み）。機械の「できること」を足す流れと、合わせる | 一覧を見るだけで、「閲覧」の権利で足りる |
| W2 | 試作（相手の機械でシェルを動かす口）。**M5 の決め**（「シェル」の権利。ADR 0026 の【問い 範8】。持ち主がいることの確かめ。ADR 0025 の【問い 作7】）。ADR 0006 と ADR 0007 の更新。ADR 0021 の、同じユーザーの線を閉じる順番の 1〜3 | 権利と、鍵の使い方に触る。持ち主の決め（2026-11-19）：`main` に入れる前に、Fable が見直す |
| W3 | マウントの調査と、小さな試作。ADR 0013 の段階 3 を決める ADR。M5（「ファイル」の権利） | 方式が、まだ決まっていない |
| W4 | W2（作業場のセッション）。ADR 0025 の【問い 作10】【問い 作11】の答え | 同じユーザーの線の例外を、どこまで受け入れるかが、先に要る |
| W5 | 囲いの調査（ADR 0026 の「守らせる仕組み」）。W2。M5 の専用ユーザー（ADR 0021 の U2）。M6 の後半（herdr を、専用ユーザーで） | 守りの本体が、OS の仕組みで決まる |
| W6 | W5。ADR 0025 の【問い 作12】の答え | 資格情報は、範囲の軸の 1 つ |
| W7 | W1〜W6 | 通しで確かめる |

ほかの段との関係：

- **M5**：W2〜W5 が使う権利と、専用ユーザーを決める。M5 の設計（ADR 0021）に、この段の問い（シェルの権利、持ち主がいることの確かめ、範囲の覚えの置き場所）を足す。
- **M6**：W1 は、M6 の「行き先を決める」（役割表と、必要条件）の上に載る。W2 は、M6 の「herdr に、SSH で入る道」を置き換える案である（ADR 0025 の【問い 作4】）。W5 は、M6 の 2 段目の G（herdr を専用ユーザーで）を、プロジェクトごとの範囲に広げる。M6 の「タスク」（名前だけを頼む）は、残す。
- **M3、M4**：ターミナル以外のアプリは、いまの映像の道のまま（決定 3）。変えない。
- **M8（AURA）**：AURA は、まず、映像の道で映したターミナルから使う（ADR 0021 の決定 13）。文字で運ぶ口を、AURA の上に作るのは、あと。持ち運ぶ端末に「シェル」を渡すのは、なくした端末を、全部のホストで一度に取り消す仕組み（ADR 0021。「出先で実用」の段の前に作る、と決まっている）のあとにする。
- **M9**：インストーラーが整えるものが、増える（シェルの代わりのプログラムを置く場所、ターミナルの種類の説明、Linux のサービス管理の設定、マウントの部品）。署名した配り方が決まること（ADR 0021 の問い 26）が、W2 を製品にする条件になる。
- **M10（Windows）**：扱わない。

## 3. 段ごとの中身と、受け入れ条件（案）

どの段にも、いまの決まり（2026-11-16）を当てる：**ホストを起動した直後（ログイン画面のまま）の状態で動くこと。** Mac のホストは、「ログイン済みで、画面をロックした状態と、スリープから起こした直後」と読み替える。動かないものは、理由と、インストーラーが何を入れれば動くかを書く。

### W1 プロジェクトの一覧と、「できること」

**これで消える ssh の場面：6（どの機械か迷う）。4 の半分（合う機械を、先に選べる）。**

- プロジェクトの一覧（ADR 0025 の 1.1）。どのプロジェクトが、どの機械の持ち物かが、どの機械からも分かる。
- 機械の「できること」（GPU、入っている道具、つないである実機）を、コーディングエージェントが読める形で出す。つないである実機は、M7 の機器の一覧と、同じ出どころにする。

受け入れ条件（案）：

1. コマンド 1 つで、全部のプロジェクトと、その開発の機械が、1 つの一覧に出る。読める形（JSON）でも出る。
2. 開発の機械が止まっているプロジェクトに、「！」が付く。黙って、ほかの機械のものとして出ない。
3. 同じプロジェクトを、2 台目に登録しようとすると、断られる。
4. 軽いモデル 1 つが、機械の名前を知らないまま、一覧だけを読んで、「3D のもの」と「iOS のもの」の開発の機械を、正しく選ぶ（M6 の D と、同じ確かめ方）。
5. 一覧と記録に、鍵、アドレス、フォルダーの場所（ホームの下の道）が出ない。

### W2 ターミナルを、文字で運ぶ

**これで消える ssh の場面：1（機械に入る）。**

- シェルの代わりのプログラムと、シェルの口（ADR 0025 の 2 章）。

受け入れ条件（案）：

1. Air の、3 つの違うターミナルから、**同じプログラム**で、Ubuntu と Studio のシェルが、プロジェクトを指定して開く。ターミナルごとの対応は、ない。
2. **SSH の鍵も、SSH の接続も、使っていない。**
3. 「シェル」の権利のない端末は、断られる。権利を外すと、1 秒以内に切れる。ペアリングを解除すると、つなぎ直せない。
4. 画面を使うプログラム（エディター、herdr）、窓の大きさの変更、日本語、色が、手元のシェルと同じに見える。相手の機械が、手元のターミナルの種類を知らなくても、崩れない。
5. 接続が切れても、自分でつなぎ直して、同じシェルに戻る（入力のつなぎ直しと、同じ速さ）。Air を眠らせても、向こうのビルドは止まらない。
6. **遅延。** キーを打ってから、字が出るまでを、手元のシェル、いまの ssh と比べて測り、記録する。合格の線は、基準を測ってから決める。どのタブがリモートかを、当てるテストで、当てられない。
7. 打った字と、出力が、ログにない。
8. Mac のホストで、シェルの中から、画面が読めない。入力を送れない（ADR 0025 の 2.7）。
9. 持ち主がいることの確かめが、決めた形（【問い 作7】）で働く。開いているシェルが、手元の一覧に、全部出る。
10. `main` に入れる前の、Fable の見直しが済んでいる。

### W3 マウント（見える・開ける）

**これで消える ssh の場面：2（ファイルを動かす）。**

- 全部の機械で、同じ場所に、プロジェクトが見える（ADR 0025 の 1.5）。方式は、調査のあとで決める。

受け入れ条件（案。方式が決まったら、見直す）：

1. Ubuntu のプロジェクトのファイルを、Air と Studio のアプリで、写さずに開ける。場所は、どの機械でも同じ。
2. ほかの機械からは、書けない（【問い 作2】のおすすめのとき）。書こうとすると、断られる。元のファイルは、変わらない。破ろうとするテストを付ける。
3. 開発の機械が止まっているとき、開こうとしたアプリが、固まらない。決めた秒数のうちに、「取得できない」と分かる。
4. 権利のない端末には、見えない。権利を外すと、すぐ見えなくなる。
5. root も、他社のカーネル拡張も、使っていない。
6. プロジェクトの外を指すリンクの先が、見えない。
7. cd で、別の持ち主のフォルダーに入ると、その機械のシェルに切り替わる（W2 と合わせて。ADR 0025 の 2.5）。
8. ライセンスと特許の確かめが、文書にある。

### W4 ポートの転送と、URL を開く頼み

**これで消える ssh の場面：3（localhost が開かない）。**

- ADR 0025 の 4 章。

受け入れ条件（案）：

1. Ubuntu の作業場で、開発サーバーを始めると、手で何も打たずに、Air のブラウザーで、`http://localhost:<同じ番号>` が開く。ページの差し替え（WebSocket）も通る。
2. 作業場の外で開いたポート（目印の待ち受け）は、転送されない。
3. 番号がぶつかると、ずれて、知らせが出る。一覧に、両方の番号が出る。
4. 固定した番号は、使えないとき、ずれずに止まって、知らせが出る。
5. 道具が URL を開くと、Air の既定のブラウザーで開く。番号がずれていれば、ずれた番号で開く。
6. http と https のほかは、断られる。破ろうとするテストを付ける（ファイル、ほかの種類の URL、長すぎるもの、制御文字、転送にない番号）。
7. 一覧に、全部の転送が出る。止めるスイッチで、1 秒以内に、全部が閉じる。勝手に戻らない。
8. 待ち受けは、127.0.0.1（と、決めたなら ::1）だけ。LAN のほかの機械からは、届かない。
9. ブラウザーの機械から、開発の機械の、一覧にないポートには、届かない（何でも通す中継に、なっていない）。
10. コーディングエージェントのログイン（ブラウザーで開いて、localhost に戻る形）が、1 回、通る。
11. ページを開く速さを、測って、記録する。

### W5 コーディングエージェントの範囲

**これで消える ssh の場面：7（範囲を狭めたせいで止まる。向こうの画面に出て、気づけない）。**

- ADR 0026。守らせる仕組みは、調査のあとで決める。

受け入れ条件（案。調査のあとで、見直す）：

1. そのプロジェクトで、初めて起動すると、Air に問いが出る。答えるまで、始まらない。2 回目は、聞かれない。
2. 範囲が、一覧で見える。あとから、変えられる。
3. 範囲 (1) で、プロジェクトの外の目印のファイルが、読めない。書けない。**コーディングエージェントに頼まずに、囲いの中から直接試して、OS が止めること。** 子のプロセスからも、同じ。
4. コーディングエージェントが、自分の範囲の覚えを、書き換えられない。
5. 範囲の外で止まると、決めた秒数のうちに、Air に、「今回だけ許す／広げる／断る」が出る。ホストの画面には、出ない。
6. 「今回だけ」は、次の起動に残らない。「広げる」は、残る。「断る」は、コーディングエージェントに伝わる。答えがなければ、断る。
7. **iOS のプロジェクト**を、Studio で、範囲 (2) で：ビルド、シミュレーター、署名が通る。
8. **Web のプロジェクト**を、範囲 (1) と W4 で：開発サーバーと、ブラウザーが通る。
9. ふつうのシェルで、コーディングエージェントを直接起動すると、知らせが出る。止まらない。
10. Mac と Linux の、守りの強さの違いが、文書と、問いの窓に、書いてある。

### W6 資格情報と署名

**これで消える ssh の場面：5（鍵や署名で止まる）。4 の残り（違う認証の機械で開いてしまう）。**

- 機械ごとに、狭い資格情報を置く形（ADR 0025 の【問い 作12】のおすすめ）。Istesso は、機械のあいだで、資格情報を写さない。

受け入れ条件（案）：

1. プロジェクトを開く前に、その開発の機械に足りないもの（Git の資格情報、署名の鍵、コーディングエージェントの API の鍵）が、分かる。
2. 足りないとき、何を、どの機械で、1 回すればよいかが、1 行で出る。
3. 署名や、キーチェーンの問いが、ホストの画面に出たまま、止まらない。出るものは、手元に知らせが来る。出ないようにできるものは、導入のときの 1 回で済ませる。やり方は、調べてから決める。
4. Air から頼んで、Studio で、署名つきのビルドが通る。
5. 記録と表示に、鍵、トークンが出ない。

### W7 通しの確かめ

**目指す体験が、通ること。**

受け入れ条件（案）：

1. Air で、Istesso の上のターミナルを開き、herdr で、コーディングエージェントに、3D のものを頼む。Ubuntu で、開発が始まる。
2. 同じようにして、iOS のものを頼む。Studio で、開発が始まる。
3. 途中で、`ssh`、`scp` を、1 回も打たない。SSH の鍵を、使わない。
4. 上の「1.」の表の 7 つの場面を、1 つずつ通して、記録する。
5. 持ち主が、1 日、この形で開発して、ssh に戻りたくなった場面を、書き出す。
