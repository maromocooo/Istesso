## 1. 何のための段か

目指す体験（持ち主、2026-11-19）：Istesso の上でターミナルを開き、herdr でコーディングエージェントに「これを作りたい」と頼むだけで、つながっている機械のうち、合うもので開発が始まる。ssh を意識しない。

「ssh を意識しない」を、確かめられる形にするために、ssh が顔を出す場面を、持ち主の分け方で 7 つ並べ、段ごとに、どれが消えるかを書く。

| # | ssh が顔を出す場面 | いま、どうしているか | 消える段 |
|---|---|---|---|
| 1 | 機械に入る | `ssh` で入る。鍵を置く。ターミナルの種類が合わなくて、画面が崩れる | W2 |
| 2 | ファイルを動かす | `scp`、`rsync`。どちらが新しいか、分からなくなる | W3 |
| 3 | localhost が開かない | 開発サーバーは、向こうの機械の中。ポートを手元に引く指定を、手で書く | W4 |
| 4 | 違う認証の機械で開いてしまう | その機械には、ログインも、鍵もない。別のアカウントで、動いてしまう | W1（機械を選ぶ）、W6（足りないものを知らせる） |
| 5 | 鍵や署名で止まる | 署名の問いが、向こうの画面に出て、止まる。鍵を貸す指定を、手で書く | W6 |
| 6 | どの機械か迷う | どこに置いたか、どこで動かすかを、覚えておく | W1 |
| 7 | 範囲を狭めたせいで止まる | コーディングエージェントが、囲いに当たって止まる。確かめの窓が、向こうの画面に出て、気づけない。結局、囲いの外で動かす | W5 |

## 3. 段ごとの中身と、受け入れ条件（案）

どの段にも、いまの決まり（2026-11-16）を当てる：**ホストを起動した直後（ログイン画面のまま）の状態で動くこと。** Mac のホストは、「ログイン済みで、画面をロックした状態と、スリープから起こした直後」と読み替える。動かないものは、理由と、インストーラーが何を入れれば動くかを書く。

### W1 プロジェクトの一覧と、「できること」

**これで消える ssh の場面：6（どの機械か迷う）。4 の半分（合う機械を、先に選べる）。**

- プロジェクトの一覧（ADR 0025 の 1.1）。どのプロジェクトが、どの機械の持ち物かが、どの機械からも分かる。
- 機械の「できること」（GPU、入っている道具、つないである実機）を、コーディングエージェントが読める形で出す。つないである実機は、M7 の機器の一覧と、同じ出どころにする。

受け入れ条件（案）：

1. コマンド 1 つで、全部のプロジェクトと、その開発の機械が、1 つの一覧に出る。読める形（JSON）でも出る。
2. 開発の機械が止まっているプロジェクトに、「！」が付く。黙って、ほかの機械のものとして出ない。
3. 同じプロジェクトの ID は 2 台目に登録できない。同じリポジトリを 2 台にクローンしたら別の ID になり、同名なら機械の名前を添えて並ぶ。同期はしない（作17）。
4. 軽いモデル 1 つが、機械の名前を知らないまま、一覧だけを読んで、「3D のもの」と「iOS のもの」の開発の機械を、正しく選ぶ（M6 の D と、同じ確かめ方）。
5. 一覧と記録に、鍵、アドレス、フォルダーの場所（ホームの下の道）が出ない。

### W2 ターミナルを、文字で運ぶ

**これで消える ssh の場面：1（機械に入る）。**

- シェルの代わりのプログラムと、シェルの口（ADR 0025 の 2 章）。

受け入れ条件（案）：

1. Air の、3 つの違うターミナルから、**同じプログラム**で、Ubuntu と Studio のシェルが、プロジェクトを指定して開く。ターミナルごとの対応は、ない。
2. **SSH の鍵も、SSH の接続も、使っていない。**
3. 「シェル」の権利のない端末は、断られる。権利を外すと、1 秒以内に切れる。ペアリングを解除すると、つなぎ直せない。
   【決定】（2026-11-21。別の見直しで出た問いへの答え）「見る」の許可を外すと、「シェル」も使えなくなる（ADR 0026 の決定 30）。
   【決定】（2026-11-21。範17〜範19）どの端末も初めは「シェル」は切。ペアリングではホストの側で選び、やりとりは変えない。Air の設定から、持ち主のどの端末の権利も Touch ID 1 回で切り替えられる。
4. 画面を使うプログラム（エディター、herdr）、窓の大きさの変更、日本語、色が、手元のシェルと同じに見える。相手の機械が、手元のターミナルの種類を知らなくても、崩れない。【提案】（2026-11-21）このうち「種類を知らなくても崩れない」は、Studio で **11-21 に見た**（14:43。下の 15）。窓の大きさの変更は、下の 22 と、「外のもの」（2 つの窓）を見る。
5. 接続が切れたら、開き直せば、前のプロジェクトに戻る。herdr の中のものは、動き続けている。Air を眠らせても、herdr の中のビルドは、止まらない（ADR 0025 の 2.6。続きは、herdr が持つ。【提案】（持ち主の決め 2026-11-21、決めること 5）素のシェルも同じシェルへ戻る。下の 20）。**権利を取り消すと、その端末のつなぎだけが切れ、herdr とコーディングエージェントは、動き続ける**（決定 8）。【提案】（2026-11-21）herdr の形の「窓を閉じて、同じ herdr に戻る」は、**11-21 に見た**（下の 18）。
6. **遅延。** キーを打ってから、字が出るまでを、手元のシェル、いまの ssh と比べて測り、記録する。合格の線は、基準を測ってから決める。どのタブがリモートかを、当てるテストで、当てられない。
7. 打った字と、出力が、ログにない。
8. Mac のホストで、シェルの中から、画面が読めない。入力を送れない（ADR 0025 の 2.7）。
9. 開いているシェルが、手元の一覧に全部出る。既定では、持ち主を確かめずに開く。このことが、同じユーザーの線の例外として文書に書いてある（作7）。【決定】（2026-11-21。作23、ADR 0025 の決定 28）「確かめる」は端末ごとに選ぶ。確かめたら開いてよい時間ができ、画面をロックしたら終わる。
10. `main` に入れる前の、Fable の見直しが済んでいる。
11. **新しいタブで、何も打たずに、前のプロジェクトに戻る**（持ち主の気づき、2026-11-19 の夜）。覚えは、手元の便利のためで、開発の機械の側の確かめには、関わらない。
12. **1 語で開ける。** プロジェクトの名前 1 つ（または、決めた短い語 1 つ）で、そのプロジェクトのシェルが開く。機械の名前、アドレス、フォルダーの場所を、打たない。
13. **機械の前でも、同じ語で、同じ作業場に入る。** Air から入ったときと、同じ herdr のセッション、履歴、コーディングエージェントの会話に着く（要件 2026-11-20。作3、作4、作5）。既定では、机の前のターミナル、ssh、`ish` のどこからでも、同じ会、転送、ページやエディターの開き方が使える。入るときの会は設定で選べ、外すものだけ一覧で外せる。herdr を選んだ場合は開発の機械で動く。
