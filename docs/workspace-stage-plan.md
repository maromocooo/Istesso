## 1. 何のための段か

目指す体験（持ち主、2026-11-19）：Istesso の上でターミナルを開き、herdr でコーディングエージェントに「これを作りたい」と頼むだけで、つながっている機械のうち、合うもので開発が始まる。ssh を意識しない。

「ssh を意識しない」を、確かめられる形にするために、ssh が顔を出す場面を、持ち主の分け方で 7 つ並べ、段ごとに、どれが消えるかを書く。

| # | ssh が顔を出す場面 | いま、どうしているか | 消える段 |
|---|---|---|---|
| 1 | 機械に入る | `ssh` で入る。鍵を置く。ターミナルの種類が合わなくて、画面が崩れる | W2 |
| 2 | ファイルを動かす | `scp`、`rsync`。どちらが新しいか、分からなくなる | W3 |
| 3 | localhost が開かない | 開発サーバーは、向こうの機械の中。ポートを手元に引く指定を、手で書く | W4 |
| 4 | 違う認証の機械で開いてしまう | その機械には、ログインも、鍵もない。別のアカウントで、動いてしまう | W1（機械を選ぶ）、W6（足りないものを知らせる） |
| 5 | 鍵や署名で止まる | 署名の問いが、向こうの画面に出て、止まる。鍵を貸す指定を、手で書く | W6 |
| 6 | どの機械か迷う | どこに置いたか、どこで動かすかを、覚えておく | W1 |
| 7 | 範囲を狭めたせいで止まる | コーディングエージェントが、囲いに当たって止まる。確かめの窓が、向こうの画面に出て、気づけない。結局、囲いの外で動かす | W5 |

## 3. 段ごとの中身と、受け入れ条件（案）

どの段にも、いまの決まり（2026-11-16）を当てる：**ホストを起動した直後（ログイン画面のまま）の状態で動くこと。** Mac のホストは、「ログイン済みで、画面をロックした状態と、スリープから起こした直後」と読み替える。動かないものは、理由と、インストーラーが何を入れれば動くかを書く。

### W1 プロジェクトの一覧と、「できること」

**これで消える ssh の場面：6（どの機械か迷う）。4 の半分（合う機械を、先に選べる）。**

- プロジェクトの一覧（ADR 0025 の 1.1）。どのプロジェクトが、どの機械の持ち物かが、どの機械からも分かる。
- 機械の「できること」（GPU、入っている道具、つないである実機）を、コーディングエージェントが読める形で出す。つないである実機は、M7 の機器の一覧と、同じ出どころにする。

受け入れ条件（案）：

1. コマンド 1 つで、全部のプロジェクトと、その開発の機械が、1 つの一覧に出る。読める形（JSON）でも出る。
2. 開発の機械が止まっているプロジェクトに、「！」が付く。黙って、ほかの機械のものとして出ない。
3. 同じプロジェクトを、2 台目に登録しようとすると、断られる。
4. 軽いモデル 1 つが、機械の名前を知らないまま、一覧だけを読んで、「3D のもの」と「iOS のもの」の開発の機械を、正しく選ぶ（M6 の D と、同じ確かめ方）。
5. 一覧と記録に、鍵、アドレス、フォルダーの場所（ホームの下の道）が出ない。

### W2 ターミナルを、文字で運ぶ

**これで消える ssh の場面：1（機械に入る）。**

- シェルの代わりのプログラムと、シェルの口（ADR 0025 の 2 章）。

受け入れ条件（案）：

1. Air の、3 つの違うターミナルから、**同じプログラム**で、Ubuntu と Studio のシェルが、プロジェクトを指定して開く。ターミナルごとの対応は、ない。
2. **SSH の鍵も、SSH の接続も、使っていない。**
3. 「シェル」の権利のない端末は、断られる。権利を外すと、1 秒以内に切れる。ペアリングを解除すると、つなぎ直せない。
4. 画面を使うプログラム（エディター、herdr）、窓の大きさの変更、日本語、色が、手元のシェルと同じに見える。相手の機械が、手元のターミナルの種類を知らなくても、崩れない。
5. 接続が切れたら、開き直せば、前のプロジェクトに戻る。herdr の中のものは、動き続けている。Air を眠らせても、herdr の中のビルドは、止まらない（ADR 0025 の 2.6：同じシェルへ戻る仕組みは、作らない。続きは、herdr が持つ）。**権利を取り消すと、その端末のつなぎだけが切れ、herdr とコーディングエージェントは、動き続ける**（決定 8）。
6. **遅延。** キーを打ってから、字が出るまでを、手元のシェル、いまの ssh と比べて測り、記録する。合格の線は、基準を測ってから決める。どのタブがリモートかを、当てるテストで、当てられない。
7. 打った字と、出力が、ログにない。
8. Mac のホストで、シェルの中から、画面が読めない。入力を送れない（ADR 0025 の 2.7）。
9. 持ち主がいることの確かめが、決めた形（【問い 作7】）で働く。開いているシェルが、手元の一覧に、全部出る。【提案】（持ち主の決め 2026-11-21。ADR 0025 の決定 10）既定では、確かめずに開く。そのことが、同じユーザーの線の例外として、文書に書いてある。「確かめる」を設定で選んだ端末では、その形（【問い 作23】）で働く。
10. `main` に入れる前の、Fable の見直しが済んでいる。
11. **新しいタブで、何も打たずに、前のプロジェクトに戻る**（持ち主の気づき、2026-11-19 の夜）。覚えは、手元の便利のためで、開発の機械の側の確かめには、関わらない。
12. **1 語で開ける。** プロジェクトの名前 1 つ（または、決めた短い語 1 つ）で、そのプロジェクトのシェルが開く。機械の名前、アドレス、フォルダーの場所を、打たない。
13. **機械の前でも、同じ語で、同じ作業場に入る。** Air から入ったときと、同じ herdr のセッション、履歴、コーディングエージェントの会話に着く（要件 2026-11-20。ADR 0025 の 6 章。【問い 作3】の答えによる）。【提案】（2026-11-21、決定 9 のあと）既定（分けない）では、機械の前のふつうのターミナルのままで、同じものに着く（どちらも持ち主のユーザー）。同じ語で作業場に入る形が要るのは、分ける設定を選んだ機械だけ。
14. どの機械にいるかが、プロンプトか、タブの名前で分かる。Istesso は、持ち主のシェルの設定ファイルに、書かない（試作の ADR 0007 の【問い】の答えによる）。

### W2b メインのエディターで開く

**これで消える場面：ファイルを直すために、どの機械かを考えること（場面 2 と 6 の一部）。**

- 決定 6（形 A。ADR 0025 の 3.1）：ファイルがある機械で、メインのエディターが立ち上がり、窓が、映像の道で手元に出る。ここに入れるのは、芯である：設定、頼み、ターミナルからの入口、「エディターがない」の知らせ。マウントからの入口は W3、コーディングエージェントからの入口は W5。
- W2 の後半に置く理由：W2a（シェル）と、いまの映像の道だけで作れる。マウント（W3）も、範囲（W5）も、待たない。持ち主が、毎日使う流れである。

受け入れ条件（案）：

1. Istesso の設定に、メインのエディターが 1 つある。プロジェクトごとに、上書きできる。
2. 作業場のシェルで、決めたコマンド（仮：`istesso open <ファイル>`）を打つと、そのファイルがある機械で、メインのエディターが立ち上がり、窓が、手元に出る。Air のプロジェクトなら、Air のエディターが、そのまま開く。**打つものは、どちらも同じ。**
3. 保存したものが、開発の機械のファイルに入る。途中で接続を切っても、ファイルは壊れない（切ってから、開発の機械の側で、中身を確かめる）。
4. プロジェクトの外の場所、外を指すリンクは、断られる。破ろうとするテストを付ける（`..`、絶対の場所、リンク、長すぎるもの）。
5. その機械に、メインのエディターがないとき、黙って、別のもので開かない。「この機械で、これを 1 回」が、1 行で出る。プロジェクトの一覧にも、印が出る。
6. 頼みと記録に、絶対の場所と、ファイルの中身が出ない。

### W3 マウント（見える・開ける）

**これで消える ssh の場面：2（ファイルを動かす）。**

- 方式の案（ADR 0025 の 1.5）：Linux の見る側は、FUSE。Mac の見る側は、製品では FSKit を目指し、それまでは、手元だけの NFS（読むだけ。使う所を絞る）。機械のあいだは、Istesso の道で、自前の小さな頼みを運ぶ。
- 2 つに分けて進める。**W3a**：つなぎの形（Linux の FUSE と、Mac の手元だけの NFS を、Istesso の道につなぐ。場所は、ホームの下）。**W3b**：製品の形（Mac の FSKit。`/Istesso` にそろえる。インストーラーと合わせる）。

受け入れ条件（案）：

1. Ubuntu のプロジェクトのファイルを、Air のアプリで、写さずに開ける。Studio のプロジェクトを、Ubuntu で開ける（W3a）。場所が、どの機械でも同じ（W3b）。
2. ほかの機械からは、書けない。書こうとすると、断られる。元のファイルは、変わらない。開発の機械の側が、書く手続きを持たないことを、テストで確かめる。
3. 開発の機械が止まっているとき、開こうとしたアプリが、固まらない。決めた秒数のうちに、誤りが返る（試作では、すぐに返った）。
4. **SSH を、使っていない。** 権利のない端末には、見えない。権利を外すと、決めた秒数のうちに、見えなくなる。
5. root も、他社のカーネル拡張も、使っていない（W3a）。W3b で使う管理者の権限は、導入の 1 回だけ。
6. プロジェクトの外を指すリンクが、「開けない項目」として見える。その先は、開けない。
7. **見る側の機械の、ほかのプロセスから。** Linux：ほかのユーザーが、マウントに入れない。Mac のつなぎの形：ポートに直接つないで読める穴が、残っているかどうかを、試して、記録する（【問い 作13】）。囲いの中のコーディングエージェントからは、マウントも、ポートも、届かない。Mac の製品の形（W3b）：ほかのユーザーから、読めない。
8. マウントしているプロジェクトが、一覧に出る。止めるスイッチで、外れる。
9. 開発の機械の側の変更が、見る側で、一覧を見直せば、決めた秒数のうちに見える。知らせが届かないアプリがあることを、使う人向けの文書に書く。
10. cd で、別の持ち主のフォルダーに入ったときの動きが、決めたとおりである（ADR 0025 の 2.5。【問い 作6】は、持ち主が、試作に触ってから決める）。
11. ライセンスと特許の確かめが、文書にある（採るときに、原文で、もう一度）。
12. **Git が無視するものと、`.git` を、既定で見せない**（持ち主の決め、2026-11-19 の夜）。一覧に出ず、名指ししても「ない」。大文字と小文字、Unicode の形だけが違う綴りでも、届かない（破ろうとするテスト）。フォルダーごとに、「見せる」を選べる。無視の規則が、秘密を守る仕組みではないことを、使う人向けの文書に書く。
13. マウントの中のファイルを、メインのエディターで開ける（コマンドと、「このアプリケーションで開く」。ADR 0025 の 3.1 の入口 1）。ふつうのダブルクリックの動きは、【問い 作18】の答えのとおり。

### W4 ポートの転送と、URL を開く頼み

**これで消える ssh の場面：3（localhost が開かない）。**

- ADR 0025 の 4 章。

受け入れ条件（案）：

1. Ubuntu の作業場で、開発サーバーを始めると、手で何も打たずに、Air のブラウザーで、`http://localhost:<同じ番号>` が開く。ページの差し替え（WebSocket）も通る。
2. 作業場の外で開いたポート（目印の待ち受け）は、転送されない。
3. 番号がぶつかると、ずれて、知らせが出る。一覧に、両方の番号が出る。
4. 固定した番号は、使えないとき、ずれずに止まって、知らせが出る。
5. 道具が URL を開くと、Air の既定のブラウザーで開く。番号がずれていれば、ずれた番号で開く。
6. http と https のほかは、断られる。破ろうとするテストを付ける（ファイル、ほかの種類の URL、長すぎるもの、制御文字、転送にない番号）。
7. 一覧に、全部の転送が出る。止めるスイッチで、1 秒以内に、全部が閉じる。勝手に戻らない。
8. 待ち受けは、127.0.0.1（と、決めたなら ::1）だけ。LAN のほかの機械からは、届かない。
9. ブラウザーの機械から、開発の機械の、一覧にないポートには、届かない（何でも通す中継に、なっていない）。
10. コーディングエージェントのログイン（ブラウザーで開いて、localhost に戻る形）が、1 回、通る。
11. ページを開く速さを、測って、記録する。
12. **全部のネットワークで待ち受けているポートは、知らせる**（持ち主の気づき、2026-11-19 の夜）。ポートごとに 1 回。その機械の中だけで待ち受けたときは、出ない。転送は、127.0.0.1 のまま。
13. **Host の確かめ。** `Host` が、`localhost`、`127.0.0.1`、`[::1]` と、こちらの番号の組でない HTTP の求めは、開発の機械へつながずに、断られる（DNS の付け替えの形のテスト）。中身は、書き換えない。HTTPS の扱いは、決めたとおり（ADR 0025 の 4.9）。
14. 試用のブランチで毎日使う前の、守りの見直しが、済んでいる。

### W5 コーディングエージェントの範囲

**これで消える ssh の場面：7（範囲を狭めたせいで止まる。向こうの画面に出て、気づけない）。**

- ADR 0026。仕組みの案：Linux は、コーディングの専用ユーザーと、Landlock と、導入のときに root で入れるネットワークの決まり。Mac は、持ち主のユーザーと、Seatbelt。どちらも、宛先は、手元の中継で決める。
  - 【提案】（持ち主の決め 2026-11-21。ADR 0025 の決定 9）**既定は、どの機械も、持ち主のユーザーと、範囲の囲い**（Linux は Landlock と seccomp、Mac は Seatbelt）。Ubuntu の既定の範囲は、「うっかりを防ぐ柵」（抜け道が残る：Docker、ほかのターミナル、名前の付いたソケット、サービス管理）。上の Linux の形（専用ユーザー、root のネットワークの決まり）は、分ける設定を選んだ機械の形として残す。
- **M5 のあとに始める**（持ち主の決め、2026-11-20）。それまでは、試用のブランチでも、囲いなしで動く。Ubuntu では、この段で、作業場のユーザーへの引っ越しが、1 回ある（ADR 0025 の 6 章）。【提案】（2026-11-21）引っ越しは、分ける設定を選んだ機械だけ。既定の機械では、ない。

受け入れ条件（案）：

1. そのプロジェクトで、初めて起動すると、Air に問いが出る。答えるまで、始まらない。2 回目は、聞かれない。
2. 範囲が、一覧で見える。あとから、変えられる。
3. 範囲 (1) で、プロジェクトの外の目印のファイルが、読めない。書けない。**コーディングエージェントに頼まずに、囲いの中から直接試して、OS が止めること。** 子のプロセスからも、同じ。
4. **抜ける道を、破ろうとするテスト。** Linux：囲いの中から、Docker の口に届かない。ユーザーのサービス管理に頼んでも、専用ユーザーの外のファイルを読めない。Mac：囲いの中から、OS のサービス管理に頼んで、外でプロセスを起こせない。【提案】（2026-11-21、決定 9 のあと）Linux のこの 2 つは、分ける設定を選んだ機械の条件。既定の機械では、同じテストで、**どの道が抜けるかを記録し、問いの窓と文書の書き方（柵）が、その記録と合っていること**を条件にする。
5. ネットワーク：範囲 (1) で、コーディングエージェント自身の API のほかの宛先に、つながらない。同じ番号の、よその機械のポートにも、つながらない（Linux）。範囲 (3) で、一覧の宛先にだけ、つながる。
6. コーディングエージェントが、自分の範囲の覚えを、書き換えられない。
7. 範囲の外で止まると、決めた秒数のうちに、Air に、「今回だけ許す／広げる／断る」が出る。ホストの画面には、出ない。ネットワークは、止めたまま、待つ。Mac のファイルは、断ってから出る（【問い 範13】の答えによる）。
8. 「今回だけ」は、次の起動に残らない。「広げる」は、残る。「断る」は、コーディングエージェントに伝わる。答えがなければ、断る。
9. **iOS のプロジェクト**を、Studio で、範囲 (2) で：ビルド（シミュレーター向け）が通る。持ち主の許しのあとで、シミュレーターでの起動、本物の署名、実機を、1 回ずつ確かめる。通らないものは、理由と、要る範囲を書く。
10. **Web のプロジェクト**を、範囲 (1) と W4 で：開発サーバーと、ブラウザーが通る。パッケージを取ってくるのは、範囲 (3) で通る。
11. Mac で、OS の更新のあとに走らせる、囲いの確かめの試験がある。効いていないときは、範囲 (1)〜(3) の起動が、断られる。
12. ふつうのシェルで、コーディングエージェントを直接起動すると、知らせが出る。止まらない。
13. Mac と Linux の、守りの強さの違いが、文書と、問いの窓に、書いてある。Ubuntu の既定の形では、「うっかりを防ぐ柵」であることが、問いの窓に出る（持ち主の決め 2026-11-21）。
14. 囲いをかけたときの、ビルドの遅さを、測って、記録する。
15. コーディングエージェントが、「このファイルを見て」と出すと、手元に知らせが出る。押したら、メインのエディターで開く（ADR 0025 の 3.1 の入口 3。【問い 作18】）。
16. 範囲つきで起動したものが、アドレスを指定せずに待ち受けても、その機械の中だけで待ち受ける（試作で動いた形）。
17. Docker を使うプロジェクトが、決めた形で動く（【問い 範15】。おすすめは、専用ユーザーの、root なしの Docker）。囲いの中から、持ち主の Docker の口に届かない。【提案】（2026-11-21）後ろの 1 文は、分ける設定を選んだ機械の条件。既定の機械では、届くことを、柵の抜け道として、問いの窓に出す。
18. 機械の前から入っても、Air から入っても、同じコーディングエージェントの会話の続きができる（要件 2026-11-20）。

### W6 資格情報と署名

**これで消える ssh の場面：5（鍵や署名で止まる）。4 の残り（違う認証の機械で開いてしまう）。**

- 機械ごとに、狭い資格情報を置く形（ADR 0025 の【問い 作12】のおすすめ）。Istesso は、機械のあいだで、資格情報を写さない。

受け入れ条件（案）：

1. プロジェクトを開く前に、その開発の機械に足りないもの（Git の資格情報、署名の鍵、コーディングエージェントの API の鍵）が、分かる。
2. 足りないとき、何を、どの機械で、1 回すればよいかが、1 行で出る。
3. 署名や、キーチェーンの問いが、ホストの画面に出たまま、止まらない。出るものは、手元に知らせが来る。出ないようにできるものは、導入のときの 1 回で済ませる。やり方は、調べてから決める。
4. Air から頼んで、Studio で、署名つきのビルドが通る。
5. 記録と表示に、鍵、トークンが出ない。
6. 「足りないもの」に、メインのエディターと、作業場のユーザーの道具・設定・ログインも出る（ADR 0025 の 3.1 と 6 章）。Istesso は、設定を、機械のあいだで写さない。
