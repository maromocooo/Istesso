## 3. 信頼の境目

```text
 手元の端末（持ち主の Mac、AURA）
   │  ペアリングで固定した鍵。Noise XX。端末ごとの権限（閲覧、操作、インストール、USB、音、案：ファイル）
   │  ── 境目 A：ネットワーク（家の LAN、VPN）
   ▼
 ホスト
   ├─ root と、ほかのユーザー                ── 境目 B：OS のユーザーの権限
   ├─ 持ち主のふだんのユーザー（資1〜資3、資10）
   │     机のセッション、鍵束、ふだんのプロファイル
   │                                         ── 境目 C：OS のユーザーの権限（いまは、ない）
   ├─ アプリの専用ユーザー（資5、資9）
   │     エージェント、ランナー（隠れたコンポジター、エンコーダー）、アプリ、音の取り込み
   │                                         ── 境目 D：アプリとアプリのあいだ（いまは、ない）
   │                                         ── 境目 E：OS のユーザーの権限（いまは、ない）
   └─ コーディングの専用ユーザー（資12）
         herdr とコーディングエージェント。作業の場所を持つ（持ち主は書かない。【提案】、6.8）

 Mac Studio（ホストの役も、持ち主のユーザー）：境目 C がない。「操作」の権限の重さで守る（6.6）
```

- **いま（試用版）は、境目 C も D もありません。** ホストのすべてが、持ち主のふだんのユーザーで動いています。試用版がしている切り離し（アプリごとのセッションバス、試験用のプロファイル、`DISPLAY` を外す）は、**まちがって机に出ないための工夫で、守りではありません。** 同じユーザーのアプリは、机のバスの場所（`$XDG_RUNTIME_DIR/bus`）を知っていれば、変数がなくてもつなげます。持ち主のホームのファイルも、そのまま読めます（考え。OS のユーザーの権限の一般のふるまい）。
- 境目 C を作るのが、ADR 0003 と ADR 0014 の専用ユーザーです。境目 D は、まだどの文書にもありません（ADR 0014 の「既知の不足」：専用ユーザーの中のアプリどうしは、隔てない）。ADR 0021 で、段を分けて提案します。
- 境目 E：【決定】2026-11-19、持ち主：herdr とコーディングエージェントは、2 つめの専用ユーザーで動かす。API の鍵と Git の資格情報を持ち、外から読んだ指示で動きうるため。その上に Landlock を重ねる。分け合うのは作業の場所だけで、グループとフォルダーの権限は ADR 0021 の「コーディングエージェント（herdr）」にある。作業の場所を持ち主が書くと、境目 E が逆向きに破れる（6.8）。
- 境目 A の外側にあるもの（見直しの M4）：持ち運ぶ端末には、Istesso の鍵のほかに、VPN の資格情報と、herdr に入る SSH の鍵がありうる。ペアリングを解いても、VPN と SSH の道は切れない（6.7）。

## 5. いま届くものと、提案の形で届くもの

列の意味：

- **いま**：試用版と、いまの `main`。ホストのすべてが持ち主のユーザーで動く。
- **段 1**：ホストの役を、アプリの専用ユーザー 1 つで動かす（ADR 0014 の A。ADR 0021 の U2）。herdr とコーディングエージェントは、2 つめの専用ユーザー。設定は、決めた値だけを持ち主の側から渡す（ADR 0021 の「設定の渡し方」）。【決定】2026-11-19、持ち主：Linux のホストは、段 1 から始め、段 2 へ進む。
- **段 2**：段 1 に、アプリごとの囲いを足す（ADR 0021 の U5。Landlock を第一の候補にする）。コーディングの専用ユーザーにも、Landlock を重ねる。ホストの中の口で、送り主を確かめる。
- **Mac Studio**：どの段でも、持ち主のユーザーで動く（6.6）。見直しの M5 で、列を足した。

「届く」は、その攻め手が、その守るものを読める、変えられる、ということです。

| 攻め手 | いま | 段 1 | 段 2 | Mac Studio |
|---|---|---|---|---|
| 攻1 ほかのアプリ | **持ち主のすべてに届く**：資1（ふだんのブラウザーのプロファイル、`~/.ssh`、鍵束のファイル）、資3、資5、資10（机のバスの場所を知っていれば）。ほかのアプリの入力の口と、コンポジターのソケットにもつなげる（同じユーザー） | 持ち主のもの（資1〜資3、資10）には、OS の権限で届かない。**専用ユーザーの中には、まだ届く**：資5（端末の鍵）、資9、ほかのアプリの設定、ほかのセッションの入力の口とソケット、ホストにいる人の口 | 自分のフォルダーと、要るシステムのファイルだけ。資5 とほかのアプリのフォルダーは読めない。ほかのセッションの入力の口は、ソケットの組にして名前をなくす（ADR 0021。見直しの L1）。**ただし、名前の付いたソケットへのつなぎは、Landlock で止まらない（ホストで見た）。** 専用ユーザーの systemd とバス（囲いの外に出られる）、ほかのアプリのバス、PipeWire（ほかのアプリの音を録る）、セッションごとの入力方式には、手（ADR 0021 の H1 の (b)〜(d)。【問い】）を選ぶまで届く | **持ち主のすべて**（ホストの役が持ち主のユーザー） |

## 6. 大事な見方

### 6.1 「操作」の権限は、「アプリのユーザーとして、何でもできる」と同じ

ペアリングした端末が「操作」を持つと、アプリにキーとマウスを送れます。アプリの多くは、ファイルを選ぶ窓、ファイルを開く操作、端末（ターミナル）を開く操作を持っています。だから、**「操作」を持つ端末は、アプリが動いているユーザーとして、ファイルを読み、プログラムを動かせる**と考えます。

- このため、**アプリをどのユーザーで動かすかが、ペアリングした端末の届く範囲を決めます**（ADR 0014 の背景と同じ見方）。
- 「インストール」の権限は、root の要るインストール（`.deb`、`.pkg`）を頼めることに意味があります。専用ユーザーの中に置くだけのもの（`.AppImage`）は、「操作」だけでも、アプリの窓から動かせることがあります。
- 「ファイル」「USB」「音」の権限も、「操作」で素通りできる（見直しの L7）。これらの権限が守るのは、Istesso 自身の道（領域の一覧と取得、機器の切り替え、音の流れ）だけである。「操作」を持つ端末は、アプリの窓から、隔離領域のファイルを開き、アプリにつながった機器を使い、アプリの音を鳴らせる。
- 【提案】画面（ランチャーの、端末の権限を変えるところ）と文書に、「操作を与えると、その端末は、専用ユーザーとして何でもできます」と書く。

### 6.2 同じユーザーの中は、1 つの袋

OS のユーザーの権限は、ユーザーとユーザーのあいだを分けます。同じユーザーのプロセスどうしは、互いのファイル、ソケット、環境変数（`/proc` の下）に届きます。デバッガーでつなぐこと（ptrace）は、Ubuntu の既定（Yama の `ptrace_scope` が 1）で、自分の子孫にしかできません（考え）。

段 1 では、次のものが、同じ袋に入ります。

| 袋の中のもの | 袋の中のほかのものから |
|---|---|
| 端末の鍵とペアリングの一覧（資5） | 読める。ADR 0014 は、これを受け入れて、「鍵に手が届くことへの備え」で広がりを抑えている |
| セッションごとの入力の口（ADR 0010。`$XDG_RUNTIME_DIR/istesso/input-<セッション>.sock`） | 送れる。**あるアプリが、ほかのアプリにキーを打ち込める** |
| セッションごとのコンポジターのソケット | つなげる。ほかのアプリの絵の中に、窓を出せる（試用のコンポジターは、ほかのアプリの窓にはキーボードを渡さず、「見てほしい」の印を付ける。ADR 0009 の 6） |
| ホストにいる人の口（ADR 0010 の 13。セッションの一覧と、止める頼み） | 送れる。ほかのアプリを止められる |
| アプリごとの設定とプロファイル | 読める、変えられる |
| 専用ユーザーの systemd とセッションバス | つなげる。`systemd-run --user` で、囲いの外にプロセスを起こせる（見直しの H1） |
| ほかのアプリの自分のバス（試用版では `/tmp` の下） | つなげる。同じユーザーなので受け入れられる |
| 専用ユーザーの PipeWire | つなげる。ほかのアプリの音を録れる |
| セッションごとの入力方式 | つなげる。打った文字を読める |
| `/tmp` と `/dev/shm` | 読める、変えられる |

herdr とコーディングエージェントは、この袋に入れません（【決定】2026-11-19、持ち主：2 つめの専用ユーザー）。

ここから、段 2 の中身が決まります（ADR 0021）：アプリには、自分のフォルダーのほかを読ませない。ホストの中の口は、送り主のプロセスかユーザーを確かめる。

**ホストで見たこと（2026-11-19、見直しの H1）：** ホストのカーネル（6.17）の Landlock は版 7 で、ファイルの決まりで囲ったプロセスは、決まりに入れていないフォルダーのふつうのファイルを開けなかった（`EACCES`）。**同じフォルダーの、名前の付いたソケットには、つながった。** 抽象名前空間のソケットは、スコープを付けると断られた（`EPERM`）。中身は ADR 0021 の「ホストで見たこと」にある。だから、上の表の、名前の付いたソケットのもの（入力の口、コンポジター、systemd、バス、PipeWire、入力方式、ホストにいる人の口）は、Landlock だけでは塞げない。ADR 0021 に、ものごとの手と、選ぶための【問い】を書いた。

### 6.3 ふだんのプロファイルを使うと、アカウントが袋に入る

R-04 は、ふだんのプロファイル（ブラウザーのログインなど）を使うかどうかを、アプリごとに持ち主が選べる、としています（【決定】2026-11-18）。使うと、**資1（アカウント）が、そのアプリのユーザーの袋に入ります。** 写しでも、ブラウザー自身のログインでも、同じです。袋に入ったアカウントには、次のものが届きます。

- 「操作」を持つすべての端末（なくした端末を含む）。
- 段 1 では、同じ袋のほかのアプリ、コーディングエージェント、乗っ取られたエージェント。

だから、ふだんのプロファイルは、「8b の便利さ」と「隔離」がいちばん強くぶつかるところです。【決定】2026-11-19、持ち主（ADR 0021 の提案のとおり）：

- 設定だけのプロファイル（Blender の設定）は、写す。資1 を含まない。
- ログインを含むプロファイル（ブラウザー）は、アプリ自身のログインを使う。使うのは、段 2 の囲いができてから。それまでは、試験用のプロファイルのまま。
- 持ち主のユーザーでアプリを動かす形は、要るアプリが出たときだけ考える。
- ふだんのプロファイルを使うアプリを開く、つなぐには、端末に新しい権限「ふだんのプロファイル」を要る。新しくペアリングした端末には与えない。**AURA にも、既定で与えない**（外へ持ち出すため）。要るときだけ与え、済んだら外す。

### 6.4 机のセッションは、アプリから見えない所に置く

試用版は、机のセッションバスを切りました（【決定】2026-11-18：切る。机の画面に出る問いは、Mac の前の持ち主には見えない）。いまの切り方は、変数を替えることによるもので、同じユーザーのアプリは、その気になれば机のバスにつなげます（3 章）。段 1 では、机のバスと鍵束と入力方式は、持ち主のランタイムディレクトリ（ほかのユーザーは入れない）の中にあるので、OS の権限で届かなくなります（考え）。

### 6.5 持ち主の側に、ネットワークから受ける口を増やさない

8b のためには、持ち主の側（机のログイン）の値を、専用ユーザーへ運ぶ必要があります。運ぶ係が、ネットワークから頼みを受け付けると、攻6 と同じ穴が、持ち主の側に開きます。【提案】持ち主の側の係は、**頼みを受けず、決めた値を、同じ PC の中の専用ユーザーへ渡すだけ**にする（ADR 0021。【決定】2026-11-19、持ち主：設定の出どころは提案のとおり）。渡す口は、導入のときに root で作るグループつきのフォルダーの中に置く（【決定】2026-11-19、持ち主）。

### 6.6 Mac Studio：ホストの役が、持ち主のユーザーで動く

【決定】2026-11-19、持ち主：Mac Studio は、持ち主がふだん使う Mac であり、有線の判定の Mac のホストでもある。

- Mac の GUI のセッションは 1 つで、アプリは、ログインしているセッションの中でしか動かない（m4-plan.md の 4.2）。Studio に座るのは持ち主なので、**Studio のホストの役は、持ち主のユーザーで動く。** 境目 C がない。
- だから、6.1 のとおり、**Studio での「操作」は、持ち主のアカウントの全部（資1〜資3）に届く。** ふだんのブラウザー、鍵束、ファイル。
- 【決定】2026-11-19、持ち主：**Studio での「操作」は、「ふだんのプロファイル」と同じ重さで扱う。AURA には既定で与えない。** 【決定】2026-11-19、持ち主：**Studio では、新しくペアリングした端末は「閲覧」だけ。「操作」は、持ち主が端末ごとに与える。**
- Mac mini（ほかの人のホストの代表）は、ADR 0014 のとおり、ホスト専用で、専用ユーザーで使う（【決定】2026-11-19、持ち主）。
- 【調べる】macOS に、ほかのユーザーの GUI のセッションを並べて動かす方法（画面共有の裏のセッション、2 つめのログインのセッション）があるか。使えるなら、Studio のホストも専用ユーザーで動かせて、境目 C ができる（ADR 0021）。
- 見直しの M5：Studio で乗っ取られたエージェントは、持ち主のすべてに届く（5 章の Studio の列）。これは、ADR 0014 の 2（ふだんのユーザーのエージェントは、起動も入力も受け付けない）と、受け入れ条件 I4 とぶつかる。【提案】（ADR 0021）：例外は、持ち主がその Mac で選んだときだけ。Mac のホストでは、ホスト専用の印がないかぎり、新しい端末とペアリングし直した端末を「閲覧」だけにする。

### 6.7 なくした端末（見直しの M4）

いまの形では、なくした端末を止めるのに、手が要ります。

- 取り消し（`istesso peers deny`、`remove`）は、**ホストごとに、そのホストにいる人が**行う（ADR 0006）。ホストが 3 台なら 3 回。
- 眠っているホストは、取り消すまで、その端末とのペアリングを持ったまま。起きたときに、その端末からつながれうる。
- ペアリングを解いても、**VPN の資格情報と、herdr に入る SSH の鍵**は、別に生きている。
- 端末の鍵は、いまはファイル（ADR 0006 の「既知の不足」。キーチェーンへ移す）。

【提案】なくしたときの手順（文書に書き、ランチャーから辿れるようにする）：

1. ホストのそれぞれで、その端末のペアリングを外す（眠っているホストは、起こしてから。起こせないものは、一覧に残して、次に起きたときに外す）。
2. VPN の管理画面で、その端末を外す（持ち主の手。VPN は Istesso の外）。
3. herdr に入る SSH の鍵を、コーディングの専用ユーザーの許す鍵の一覧から外す。
4. その端末で使っていたアカウント（ブラウザーのログインなど）を、アカウントの側でログアウトさせる。

【提案】全部のホストで一度に取り消す仕組み（1 台のホストで外すと、ペアリングしたほかのホストにも伝わり、常時稼働のホストが、眠っているホストの起きたときに伝える）を考える。ペアリングの手順と権限に触るので、作る前に ADR 0006 を更新する。【問い】（ADR 0021 の 13）。

### 6.8 作業の場所を、持ち主が書かない（見直しの H2）

作業の場所を持ち主が読み書きすると、乗っ取られたコーディングエージェント（攻7）が置いたものが、持ち主のユーザーで動きます。Git の設定（`core.fsmonitor`、`core.pager`）とフック、ビルドの手順、エディターのタスクの設定です。持ち主が、そこで `git status`、ビルド、エディターで開く、をしたときに動きます。【提案】（ADR 0021。【問い】の 11。まだ決まっていない）：持ち主は書かない。直すのは herdr の中で、コーディングの専用ユーザーとして。持ち主のホームへは写しで持ち出す。

持ち主は、作業の場所に**書いてもよいアプリ**を名指しできる（【決定】2026-11-19、持ち主。既定では、名指ししたアプリが読むだけ）。書けるアプリが乗っ取られると（攻1）、同じものを置けて、コーディングエージェントが Git やビルドを動かしたときに、コーディングの専用ユーザーとして動く（資12 に届く）。持ち主がそこで動かせば、持ち主として動く。小さく保つ形（書けるのはプロジェクトのフォルダーだけ、`.git/` と手順のファイルは書かせない、アプリが書いた設定のフックと fsmonitor は動かさない、書けるアプリにはログインを持たせない）は、ADR 0021 の「作業の場所」の【提案】。

### 6.9 同じ PC の待ち受け（見直しの M8）

専用ユーザーでも、同じ PC のネットワークは隔てません（ADR 0014）。乗っ取られたブラウザー（攻1）は、同じ PC でループバックに待ち受けているもの（開発用のサーバー、データベース、管理の画面、コーディングエージェントのツールの口）につなげます。持ち主のユーザーや、コーディングの専用ユーザーが動かしているものも含みます。Istesso の制御チャンネルは、ペアリングした鍵がないとつなげません。待ち受けるものには、それぞれ認証を付けることを、文書に書きます（10 章）。

## 10. 残る危うさ（受け入れるもの）

- 段 1 のあいだ、専用ユーザーの中のアプリどうしは隔てない（ADR 0014 と同じ）。端末の鍵にも届く。段 2 で狭める。
- Mac Studio では、ホストの役と持ち主のあいだに、境目がない（6.6）。「操作」を与えた端末は、持ち主として何でもできる。
- コーディングエージェントは、自分の API の鍵と Git の資格情報に届く（使って動くため）。
- 「操作」を持つ端末は、専用ユーザーとして何でもできる（6.1）。権限を与えるときの判断に任せる。
- 専用ユーザーでも、同じ PC のネットワーク（ループバックの待ち受けを含む。6.9）、誰でも読める場所（`/tmp`、`/dev/shm`）、プロセスの一覧（名前と引数）は隔てない（ADR 0014）。
- このカーネルの Landlock では、名前の付いたソケットへのつなぎを止められない（見た）。手（ADR 0021 の H1）を選ぶまで、段 2 でも、囲ったアプリは、専用ユーザーの systemd、バス、PipeWire、入力方式に届く。
- エンコーダーの枠と GPU は、PC 全体で共有する。1 つのアプリが使い切ると、ほかが開けない（資11。ADR 0010 の 16 で、落ちずに知らせる）。
- 写した設定は、写したときの値のまま。持ち主がふだんの側で変えたものは、写し直すまで入らない（試用版の Blender と同じ）。
