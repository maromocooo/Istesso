## 3. 信頼の境目

```text
 手元の端末（持ち主の Mac、AURA）
   │  ペアリングで固定した鍵。Noise XX。端末ごとの権限（閲覧、操作、インストール、USB、音、案：ファイル）
   │  ── 境目 A：ネットワーク（家の LAN、VPN）
   ▼
 ホスト
   ├─ root と、ほかのユーザー                ── 境目 B：OS のユーザーの権限
   ├─ 持ち主のふだんのユーザー（資1〜資3、資10）
   │     机のセッション、鍵束、ふだんのプロファイル
   │                                         ── 境目 C：OS のユーザーの権限（いまは、ない）
   ├─ アプリの専用ユーザー（資5、資9）
   │     エージェント、ランナー（隠れたコンポジター、エンコーダー）、アプリ、音の取り込み
   │                                         ── 境目 D：アプリとアプリのあいだ（いまは、ない）
   │                                         ── 境目 E：OS のユーザーの権限（いまは、ない）
   └─ コーディングの専用ユーザー（API の鍵、Git の資格情報）
         herdr とコーディングエージェント。作業の場所だけを、持ち主と分け合う

 Mac Studio（ホストの役も、持ち主のユーザー）：境目 C がない。「操作」の権限の重さで守る（6.6）
```

- **いま（試用版）は、境目 C も D もありません。** ホストのすべてが、持ち主のふだんのユーザーで動いています。試用版がしている切り離し（アプリごとのセッションバス、試験用のプロファイル、`DISPLAY` を外す）は、**まちがって机に出ないための工夫で、守りではありません。** 同じユーザーのアプリは、机のバスの場所（`$XDG_RUNTIME_DIR/bus`）を知っていれば、変数がなくてもつなげます。持ち主のホームのファイルも、そのまま読めます（考え。OS のユーザーの権限の一般のふるまい）。
- 境目 C を作るのが、ADR 0003 と ADR 0014 の専用ユーザーです。境目 D は、まだどの文書にもありません（ADR 0014 の「既知の不足」：専用ユーザーの中のアプリどうしは、隔てない）。ADR 0021 で、段を分けて提案します。
- 境目 E：【決定】2026-11-19、持ち主：herdr とコーディングエージェントは、2 つめの専用ユーザーで動かす。API の鍵と Git の資格情報を持ち、外から読んだ指示で動きうるため。その上に Landlock を重ねる。分け合うのは作業の場所だけで、グループとフォルダーの権限は ADR 0021 の「コーディングエージェント（herdr）」にある。

- **段 1**：ホストの役を、アプリの専用ユーザー 1 つで動かす（ADR 0014 の A。ADR 0021 の U2）。herdr とコーディングエージェントは、2 つめの専用ユーザー。設定は、決めた値だけを持ち主の側から渡す（ADR 0021 の「設定の渡し方」）。【決定】2026-11-19、持ち主：Linux のホストは、段 1 から始め、段 2 へ進む。

## 6. 大事な見方

### 6.1 「操作」の権限は、「アプリのユーザーとして、何でもできる」と同じ

ペアリングした端末が「操作」を持つと、アプリにキーとマウスを送れます。アプリの多くは、ファイルを選ぶ窓、ファイルを開く操作、端末（ターミナル）を開く操作を持っています。だから、**「操作」を持つ端末は、アプリが動いているユーザーとして、ファイルを読み、プログラムを動かせる**と考えます。

- このため、**アプリをどのユーザーで動かすかが、ペアリングした端末の届く範囲を決めます**（ADR 0014 の背景と同じ見方）。
- 「インストール」の権限は、root の要るインストール（`.deb`、`.pkg`）を頼めることに意味があります。専用ユーザーの中に置くだけのもの（`.AppImage`）は、「操作」だけでも、アプリの窓から動かせることがあります。
- 【提案】画面（ランチャーの、端末の権限を変えるところ）と文書に、「操作を与えると、その端末は、専用ユーザーとして何でもできます」と書く。

### 6.2 同じユーザーの中は、1 つの袋

OS のユーザーの権限は、ユーザーとユーザーのあいだを分けます。同じユーザーのプロセスどうしは、互いのファイル、ソケット、環境変数（`/proc` の下）に届きます。デバッガーでつなぐこと（ptrace）は、Ubuntu の既定（Yama の `ptrace_scope` が 1）で、自分の子孫にしかできません（考え）。

段 1 では、次のものが、同じ袋に入ります。

| 袋の中のもの | 袋の中のほかのものから |
|---|---|
| 端末の鍵とペアリングの一覧（資5） | 読める。ADR 0014 は、これを受け入れて、「鍵に手が届くことへの備え」で広がりを抑えている |
| セッションごとの入力の口（ADR 0010。`$XDG_RUNTIME_DIR/istesso/input-<セッション>.sock`） | 送れる。**あるアプリが、ほかのアプリにキーを打ち込める** |
| セッションごとのコンポジターのソケット | つなげる。ほかのアプリの絵の中に、窓を出せる（試用のコンポジターは、ほかのアプリの窓にはキーボードを渡さず、「見てほしい」の印を付ける。ADR 0009 の 6） |
| ホストにいる人の口（ADR 0010 の 13。セッションの一覧と、止める頼み） | 送れる。ほかのアプリを止められる |
| アプリごとの設定とプロファイル | 読める、変えられる |
| herdr とコーディングエージェントの作業の場所 | 読める、変えられる |

herdr とコーディングエージェントは、この袋に入れません（【決定】2026-11-19、持ち主：2 つめの専用ユーザー）。

ここから、段 2 の中身が決まります（ADR 0021）：アプリには、自分のフォルダーのほかを読ませない。ホストの中の口は、送り主のプロセスかユーザーを確かめる。

### 6.3 ふだんのプロファイルを使うと、アカウントが袋に入る

R-04 は、ふだんのプロファイル（ブラウザーのログインなど）を使うかどうかを、アプリごとに持ち主が選べる、としています（【決定】2026-11-18）。使うと、**資1（アカウント）が、そのアプリのユーザーの袋に入ります。** 写しでも、ブラウザー自身のログインでも、同じです。袋に入ったアカウントには、次のものが届きます。

- 「操作」を持つすべての端末（なくした端末を含む）。
- 段 1 では、同じ袋のほかのアプリ、コーディングエージェント、乗っ取られたエージェント。

だから、ふだんのプロファイルは、「8b の便利さ」と「隔離」がいちばん強くぶつかるところです。【決定】2026-11-19、持ち主（ADR 0021 の提案のとおり）：

- 設定だけのプロファイル（Blender の設定）は、写す。資1 を含まない。
- ログインを含むプロファイル（ブラウザー）は、アプリ自身のログインを使う。使うのは、段 2 の囲いができてから。それまでは、試験用のプロファイルのまま。
- 持ち主のユーザーでアプリを動かす形は、要るアプリが出たときだけ考える。
- ふだんのプロファイルを使うアプリを開く、つなぐには、端末に新しい権限「ふだんのプロファイル」を要る。新しくペアリングした端末には与えない。**AURA にも、既定で与えない**（外へ持ち出すため）。要るときだけ与え、済んだら外す。

### 6.4 机のセッションは、アプリから見えない所に置く

試用版は、机のセッションバスを切りました（【決定】2026-11-18：切る。机の画面に出る問いは、Mac の前の持ち主には見えない）。いまの切り方は、変数を替えることによるもので、同じユーザーのアプリは、その気になれば机のバスにつなげます（3 章）。段 1 では、机のバスと鍵束と入力方式は、持ち主のランタイムディレクトリ（ほかのユーザーは入れない）の中にあるので、OS の権限で届かなくなります（考え）。

### 6.5 持ち主の側に、ネットワークから受ける口を増やさない

8b のためには、持ち主の側（机のログイン）の値を、専用ユーザーへ運ぶ必要があります。運ぶ係が、ネットワークから頼みを受け付けると、攻6 と同じ穴が、持ち主の側に開きます。【提案】持ち主の側の係は、**頼みを受けず、決めた値を、同じ PC の中の専用ユーザーへ渡すだけ**にする（ADR 0021。【決定】2026-11-19、持ち主：設定の出どころは提案のとおり）。渡す口は、導入のときに root で作るグループつきのフォルダーの中に置く（【決定】2026-11-19、持ち主）。

### 6.6 Mac Studio：ホストの役が、持ち主のユーザーで動く

【決定】2026-11-19、持ち主：Mac Studio は、持ち主がふだん使う Mac であり、有線の判定の Mac のホストでもある。

- Mac の GUI のセッションは 1 つで、アプリは、ログインしているセッションの中でしか動かない（m4-plan.md の 4.2）。Studio に座るのは持ち主なので、**Studio のホストの役は、持ち主のユーザーで動く。** 境目 C がない。
- だから、6.1 のとおり、**Studio での「操作」は、持ち主のアカウントの全部（資1〜資3）に届く。** ふだんのブラウザー、鍵束、ファイル。
- 【決定】2026-11-19、持ち主：**Studio での「操作」は、「ふだんのプロファイル」と同じ重さで扱う。AURA には既定で与えない。** 与え方の形（新しくペアリングした端末には「閲覧」だけ、など）は、ADR 0021 の【提案】。
- Mac mini（ほかの人のホストの代表）は、ADR 0014 のとおり、ホスト専用で、専用ユーザーで使う（【決定】2026-11-19、持ち主）。
- 【調べる】macOS に、ほかのユーザーの GUI のセッションを並べて動かす方法（画面共有の裏のセッション、2 つめのログインのセッション）があるか。使えるなら、Studio のホストも専用ユーザーで動かせて、境目 C ができる（ADR 0021）。

## 10. 残る危うさ（受け入れるもの）

- 段 1 のあいだ、専用ユーザーの中のアプリどうしは隔てない（ADR 0014 と同じ）。端末の鍵にも届く。段 2 で狭める。
- Mac Studio では、ホストの役と持ち主のあいだに、境目がない（6.6）。「操作」を与えた端末は、持ち主として何でもできる。
- コーディングエージェントは、自分の API の鍵と Git の資格情報に届く（使って動くため）。
- 「操作」を持つ端末は、専用ユーザーとして何でもできる（6.1）。権限を与えるときの判断に任せる。
- 専用ユーザーでも、同じ PC のネットワーク、誰でも読める場所（`/tmp`）、プロセスの一覧（名前と引数）は隔てない（ADR 0014）。
- エンコーダーの枠と GPU は、PC 全体で共有する。1 つのアプリが使い切ると、ほかが開けない（資11。ADR 0010 の 16 で、落ちずに知らせる）。
- 写した設定は、写したときの値のまま。持ち主がふだんの側で変えたものは、写し直すまで入らない（試用版の Blender と同じ）。
