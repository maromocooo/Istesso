# 構成

## 全体像

新しい OS は作りません。各 PC に常駐する**ホストエージェント**と、どの端末でも同じ画面を出す薄い**シェル**の組み合わせです。

```text
 操作する端末（どれでも同じ画面）
 ┌──────────────┐   ┌──────────────┐
 │ 自宅の実機     │   │ 出先の AURA    │
 │ Mac / Ubuntu  │   │ VPN 越し       │
 └──────┬───────┘   └──────┬───────┘
        │   つなぎ方（遅延の小さい順）  │
        │   1. 手元で動かす             │
        │   2. 文字は herdr             │
        │   3. 残りだけ映像             │
 ┌──────┴─────────────────────┴──────┐
 │ アプリが住む PC（専用ユーザーで稼働）   │
 │ Mac Studio / Ubuntu / MacBook Air    │
 │ （将来：Windows）                      │
 │ 統合ストレージ（各 PC の隔離領域を合算） │
 └───────────────────────────────────┘
```

## 3つの面

| 面 | 役割 | 方針 |
|---|---|---|
| 制御面 | 発見、ペアリング、役割表、アプリ一覧、起動、権限 | 内製。小さく保つ（このリポジトリの現在の範囲） |
| 映像・音声面 | アプリごとの映像、入力、音 | 取り込める部品を使い、足りない所だけ内製 |
| 状態面 | 統合ストレージ、セッション、クリップボード | 既存のファイル共有と union マウントを束ねる |

## クレート

| クレート | 内容 | 状況 |
|---|---|---|
| `istesso-proto` | 端末間、プロセス間で共有するデータ型（役割表、アプリ、配信の種類、配信セッション、ランナーとビューアーへの行） | 実装済み |
| `istesso-doctor` | PC の能力を調べて役割表を作る | 実装済み |
| `istesso-catalog` | アプリの列挙と、複数ホストの一覧の統合。アプリの起動のしかた（desktop entry から、プログラムと引数を出す） | 実装済み |
| `istesso-pair` | ペアリング（SPAKE2、鍵の固定、失効） | 実装済み |
| `istesso-link` | 固定した鍵で相互認証する制御チャンネル（Noise XX）と、その上のメッセージ（問い合わせ、配信セッションの開始と終了） | 実装済み |
| `istesso-agent` | エージェント（問い合わせへの応答、全端末の調査、LAN 内の発見、最後に見えた内容の記憶）。配信セッション（アプリを別の端末のために起動して、見守り、終わらせる。別の端末のアプリの窓を開く。[ADR 0010](adr/0010-session-start.md)） | 実装済み。常駐サービス化は未着手。配信セッションは、映像を運ばない偽物のランナーとビューアーで確かめた段階 |
| `istesso-cli` | コマンド `istesso` | 実装済み |
| `istesso-audio` | 音の出口と配信 | 未着手 |
| `istesso-media-*` | OS ごとの取り込み・圧縮・入力 | 未着手 |

## ホストエージェントの差し替え点

OS ごとの違いは、次の4つの口の裏に閉じ込めます。Windows を足すときは、この4つを実装します。

| 口 | macOS | Linux | Windows（将来） |
|---|---|---|---|
| 取り込みと圧縮 | ScreenCaptureKit + VideoToolbox | 仮想コンポジター + NVENC | Windows.Graphics.Capture + Media Foundation |
| 入力 | CGEvent | 仮想入力デバイス（uinput） | SendInput、仮想ゲームパッド |
| アプリ管理 | `.app`、Homebrew | `.desktop`、apt | スタートメニュー、winget |
| 起床 | 差し替え式（Wake-on-LAN など） | 同左 | 同左 |

## 配信セッション

リモートのアプリ 1 つ、その仮想ディスプレイ、それを映す手元の窓 1 枚の組を、配信セッションと呼びます（[ADR 0010](adr/0010-session-start.md)）。

```text
 クライアント                                   ホスト
 istesso open ──── 制御チャンネル ────▶ エージェント ──▶ アプリ（一覧にあるものだけ）
      │      session_start / attach / wait / stop    │
      ▼                                              ▼
  ビューアー ◀════════ 映像と入力（M1）════════▶ ランナー（仮想ディスプレイと送信）
```

- 制御面が決めるのは、どのアプリを、どのホストで、どの端末に向けて、いつまで動かすかです。映像と入力の運び方は、ランナーとビューアーという 2 つのプログラムの中にあり、制御面は中を見ません。
- ランナーとビューアーは、標準入出力に 1 行ずつの JSON で指示を受けます。映像の経路（M1）が `main` に入るまでは、映像を運ばない偽物（`scripts/fake-session-runner.sh`、`scripts/fake-viewer.sh`）で動かします。
- セッションは、アプリが終わるか、だれかが止めるまで、ホストで続きます。クライアントがいなくなっても、絵が止まるだけで、アプリは動き続けます。あとから `istesso open` でつなぎ直せます（R-03）。ふつうのセッションに別の端末からつなぐことは、まだ決まっていません。
- 端末のペアリングを解除すると、その端末は、その場で切られます（制御の接続を閉じ、絵を止めます）。その端末が開いたアプリは残り、「閲覧」と「操作」を持つほかの端末からも、ホストにいる人（`istesso sessions --local`）からも、見えて、つなげて、止められます。
- 窓を閉じるのは、アプリへの「閉じてほしい」という頼みです。アプリは、保存するかを尋ねて残ることができます。力ずくで終わらせるのは、`istesso sessions stop <ID> --force` と書いたときだけです。

## 配信の種類

`istesso-proto` に最初から2種類を定義しています。

- `AppWindow`：アプリ1つを手元の窓1枚として出す。入力は絶対座標で、カーソルは手元で描く。
- `Game`：全画面で、相対マウスとゲームパッドを使う。Windows 対応のための予約。

## ペアリングと信頼

```text
 1. ホスト側が8文字のコードを表示する
 2. 両者が SPAKE2 を実行する（コードが同じときだけ同じ鍵になる）
 3. その鍵の下で、長期公開鍵と署名を交換する
 4. 互いの公開鍵を固定して保存する。以後はこの鍵で相互認証する
```

詳細と脅威の整理は [adr/0006-pairing.md](adr/0006-pairing.md) にあります。

## 役割表

`istesso doctor --json` の出力がそのまま役割表の1行です。`roles` は検出結果から導きます。

| 役割 | 条件 |
|---|---|
| `gpu` | NVIDIA か AMD の GPU がある |
| `mac_apps` | macOS |
| `xcode_build` | Xcode がある |
| `always_on_candidate` | バッテリーを積んでいない |
| `hardware_encode` | ハードウェアエンコーダーがある |
| `app_audio_capture` | 追加ドライバーなしでアプリの音を取れる（macOS 14.2 以降、PipeWire など） |
