# Istesso

[English](README.md) · [日本語](README.ja.md) · [简体中文](README.zh-Hans.md) · **한국어** · [Español](README.es.md)

Istesso는 자체 암호화 채널을 통해 다른 컴퓨터에서 실행되는 앱을 눈앞의 컴퓨터에 일반 창으로 띄웁니다. 기준은 하나입니다. 조금이라도 원격으로 쓰는 느낌이 들면 실패입니다.

> [!IMPORTANT]
> Istesso는 현재 시험 사용 단계입니다. 개발자가 매일 써 보며 부족한 점을 찾고 있고, 그 작업의 상당 부분은 아직 `main`에 합쳐지지 않은 브랜치에서 진행 중입니다. 내려받을 바이너리가 없어 소스에서 직접 빌드해야 합니다. 지금 어떤 기능이 어느 기기에서 작동하는지는 아래 표에서 확인할 수 있습니다.

## Istesso란

Istesso는 각 작업을 지연이 가장 적은 곳에서 처리하도록 설계되었습니다. 순서는 다음과 같습니다.

1. 눈앞의 컴퓨터에서 실행할 수 있는 작업은 거기서 실행합니다. 다른 컴퓨터와는 상태만 동기화합니다.
2. 텍스트 작업은 터미널로 직접 연결해 처리합니다.
3. 남는 것은 화면이 필요하고 다른 컴퓨터에서 실행되는 앱입니다. 이런 앱만 영상으로 중계합니다. 앱 하나를 창 하나에 띄우고 포인터는 내 기기에서 그립니다.

어느 창이 원격인지 구별할 수 없어야 한다는 기준에는 실제로 통과 여부를 가리는 시험이 있습니다. 같은 앱을 로컬에서 실행한 창과 중계한 창을 같은 화면에서 측정해 비교하고, 사람이 눈으로 중계한 창을 골라낼 수 있는지도 시험합니다. 이 기준은 가정 내 유선 네트워크로 연결한 컴퓨터에 적용됩니다. Wi-Fi와 인터넷을 통한 연결은 범위에서 제외합니다.

이름은 음악 용어 *l'istesso tempo*에서 따왔습니다. 박자가 바뀌어도 같은 빠르기를 유지하라는 뜻입니다.

## 현재 사용할 수 있는 기능

각 열은 앱이 어디에서 실행되고 어느 기기에 표시되는지 나타냅니다.

| 기능 | Linux 호스트 → Mac | Mac 호스트 → Mac | Linux 호스트 → Android XR 헤드셋 |
|---|---|---|---|
| 일회용 코드로 두 기기 페어링 | `Verified` 2026-11-16 ([기록](docs/milestones.md#m0-共通の土台) (일본어)) | `Trial` | `Trial` |
| 모든 컴퓨터와 각 컴퓨터의 앱을 한 목록에서 보기 | `Verified` 2026-11-16 ([기록](docs/milestones.md#m0-共通の土台) (일본어)) | `Trial` | `Planned` |
| 호스트에서 앱을 열고 하나의 창에서 화면을 보며 키 입력, 포인터, 스크롤 사용 | `Trial` | `Trial` | `Trial` |
| 해당 창과 눈앞의 컴퓨터 사이에서 텍스트 복사 및 붙여넣기 | `Trial` | `Trial` | `Planned` |
| 입력기를 통해 일본어 입력 | `Trial` | `Trial` | `Trial` |
| 호스트의 소리를 내 기기에서 듣기 | `Planned` | `Planned` | `Planned` |
| 앱이 어느 컴퓨터에 설치되어 있든 실행기 창에서 열기 | `Planned` | `Planned` | `Planned` |
| USB 장치를 다른 컴퓨터로 넘겨 그곳에 직접 꽂힌 것처럼 쓰기 | `Out of scope` | `Out of scope` | `Out of scope` |

- `Verified`(검증 완료)는 해당 역할을 맡은 실제 기기에서 독자가 따를 절차대로 `main` 버전을 실행해 확인한 기능입니다. 확인한 날짜와 기록 링크가 항상 붙습니다.
- `Trial`(시험 사용)은 개발자가 브랜치에서 빌드한 시험판에서 작동합니다. 아직 `main`에서는 재현할 수 없습니다.
- `Planned`(계획 중)는 설계 중이거나 아직 착수하지 않은 기능입니다.
- `Out of scope`(범위 밖)는 이번 릴리스에 포함되지 않습니다.

헤드셋은 Wi-Fi로 연결하므로 가정 내 유선 네트워크에 적용하는 지연 기준의 범위를 벗어납니다. 헤드셋 열의 `Trial`은 시험판에서 사용할 수 있다는 뜻입니다. 지연 기준 충족 여부를 나타내지는 않습니다.

중계로 추가되는 지연은 같은 앱을 같은 화면에서 로컬로 실행한 창을 기준으로 측정합니다. 두 컴퓨터 모두 유선으로 연결하고, 85 Hz 디스플레이에 3440×1440 영상을 표시합니다. 추가 지연은 중앙값에서 12 ms, 95백분위수에서 24 ms, 99백분위수에서 47 ms를 넘지 않아야 합니다. 2026-11-17에 시제품 뷰어와 측정용 호스트로 중계를 시험해 이 단계를 통과했습니다. 최종 통과 여부는 Istesso 자체 클라이언트와 호스트로 측정한 뒤에 판정합니다([단계별 시험 기록](docs/measurements/2026-11-17-m1-gate.md) (일본어)).

## 앞으로의 계획

- Istesso 자체 클라이언트와 호스트를 `main`에 포함한 뒤 지연 기준 충족 여부를 최종 판정합니다.
- 어느 호스트의 소리든 선택한 출력 장치 하나에서 몇 시간 동안 끊김 없이 재생합니다.
- 여러 컴퓨터의 앱을 한곳에서 여는 실행기로 잠든 호스트를 깨울 수 있게 합니다.
- 컴퓨터 간에 저장 공간을 공유하고, 전용 사용자 계정으로 Istesso의 앱과 에이전트를 내 파일과 분리합니다.
- 빌드와 작업을 각각에 적합한 컴퓨터에서 실행합니다.
- 장치를 옮기지 않고 여러 컴퓨터에서 사용합니다. 모든 컴퓨터의 장치를 한 목록에서 보고, 장치가 필요한 앱은 그 장치가 꽂힌 컴퓨터에서 엽니다. 앱 창은 지금 있는 곳에서 조작합니다. 처음으로 직접 제어할 장치는 프로그래밍 가능한 키패드입니다. 표에 나온 대로 USB 장치 자체를 다른 컴퓨터로 넘기는 기능은 범위 밖입니다.
- Android XR 헤드셋용 클라이언트를 `main`에 포함합니다.
- macOS와 Ubuntu용 서명된 패키지 및 업데이트를 제공하고, 페어링에 대해 외부 검토를 받습니다.
- Windows 지원은 이번 릴리스 이후에 진행합니다.

각 단계와 그 단계에서 통과해야 하는 시험은 [docs/milestones.md](docs/milestones.md) (일본어)에 있습니다.

## 알려진 제약

- Istesso는 같은 컴퓨터에서 같은 사용자 계정으로 실행되는 다른 프로그램으로부터 보호되지 않습니다. 신뢰하는 프로그램만 실행하는 본인 소유의 컴퓨터에서 사용하세요.
- 지연 기준은 가정 내 유선 네트워크에 적용됩니다. Wi-Fi와 인터넷은 범위 밖입니다([Wi-Fi 참고 사항](docs/wifi.md) (일본어)).
- Linux 호스트에는 하드웨어 영상 인코더인 NVENC를 갖춘 NVIDIA GPU가 필요합니다.
- Mac 호스트를 재시작하면 누군가 그 Mac에서 한 번 로그인하기 전까지는 호스트를 사용할 수 없습니다.
- Mac을 호스트로 사용하면 30일마다 해당 Mac 화면에 macOS 확인 창이 뜹니다. 시스템의 화면 선택 창을 거치지 않고 앱이 계속 화면을 캡처하도록 허용할지 묻습니다. 이 방식으로 화면을 캡처하는 앱에 Apple이 적용하는 규칙으로, Istesso가 추가한 절차가 아닙니다. 소스에서 빌드해도 확인 창이 뜹니다. 현재 서명된 빌드는 배포하지 않으며, Istesso의 배포 방식은 아직 정해지지 않았습니다.
- 설치 프로그램, 자동 업데이트, 서명된 바이너리가 없습니다. 페어링은 아직 외부 검토를 받지 않았습니다.
- 지금까지의 지연 수치는 시제품 뷰어로 측정했습니다. 기준 충족 여부는 최종 판정 때 확정합니다.
- 이번 릴리스에서는 Windows를 지원하지 않습니다.

## 비슷한 도구와의 차이

| 도구 종류 | 제공하는 기능 | Istesso의 설계 | 해당 도구가 더 적합한 경우 |
|---|---|---|---|
| 원격 데스크톱(VNC, RDP 등) | 로그인 화면을 포함해 다른 컴퓨터의 데스크톱 전체를 사용할 수 있고, 인터넷을 통해서도 연결할 수 있습니다 | 각 앱이 내 데스크톱에서 창 하나로 열려 로컬 창, 다른 컴퓨터에서 온 창과 나란히 놓입니다 | 데스크톱 전체나 로그인 화면이 필요하거나, 인터넷을 통해 사용하거나, Windows가 필요할 때 |
| 터미널 멀티플렉서와 함께 쓰는 ssh 터미널 | 어떤 연결에서든 지연을 최소화해 텍스트로 작업할 수 있고, 연결이 끊겨도 세션이 유지됩니다 | Istesso는 이 도구를 대체하지 않습니다. 세 단계 중 두 번째가 터미널을 통한 텍스트 작업이며, 화면이 필요한 앱만 영상으로 전송합니다 | 텍스트로 작업할 때 |
| 창 전달(예: ssh를 통한 X11) | ssh 연결을 통해 원격 X11 앱의 창을 하나씩 내 화면에 띄웁니다 | 각 창을 하드웨어로 인코딩한 영상으로 보내고 로컬 창과 비교해 측정합니다 | 앱이 X11용이고 ssh 연결만 설정하고 싶을 때 |
| 게임 스트리밍 | 전체 화면, 마우스의 상대 이동, 게임패드, 인터넷을 통한 플레이를 지원합니다 | 앱 창을 위해 설계했습니다. 포인터의 절대 위치를 사용하고 커서는 내 기기에서 그립니다. 게임은 이번 릴리스의 범위 밖입니다 | 게임을 하고 싶을 때 |

## 빠른 시작

이 절차에는 컴퓨터 한 대만 사용합니다. Istesso가 이 컴퓨터에서 찾은 역할, 설치된 앱, 연결된 장치만 확인합니다. 두 컴퓨터를 연결해 원격 앱을 표시하는 단계는 새로 복제한 저장소에서 다시 실행해 보지 않았으므로 이 README에는 아직 싣지 않았습니다.

`git`, Rust 1.85 이상, C 도구 모음(macOS에서는 Xcode Command Line Tools)이 필요합니다.

```sh
git clone https://github.com/maromocooo/Istesso.git
cd Istesso
cargo build --release --locked -p istesso-cli
./target/release/istesso doctor
./target/release/istesso apps list
./target/release/istesso devices list
```

- `doctor`는 이 컴퓨터가 맡을 수 있는 역할을 출력합니다. 하드웨어 영상 인코더가 있는지, Apple 플랫폼용으로 빌드할 수 있는지, 상시 가동 호스트로 적합한지 등을 보여 줍니다. 컴퓨터 이름과 네트워크 주소도 출력하므로 다른 곳에 붙여넣기 전에 내용을 확인하세요.
- `apps list`는 이 컴퓨터에 설치된 앱을 출력합니다.
- `devices list`는 이 컴퓨터에 연결된 장치를 출력합니다.

새로 복제한 저장소에서 마지막으로 실행한 날짜는 2026-11-19이며 운영체제는 macOS 26.5(Apple silicon)였습니다([기록](docs/readme-checks.md) (일본어)).

## 소스에서 빌드하기

- Rust 1.85 이상이 필요합니다. macOS와 Linux에서 빌드할 수 있습니다. CI는 변경할 때마다 두 플랫폼 모두에서 빌드와 테스트를 수행합니다.
- 서명된 바이너리는 공개하지 않으며 Istesso의 배포 방식은 아직 정해지지 않았습니다.

변경 사항을 제출하기 전에 아래 명령을 실행하세요. CI도 같은 검사를 수행합니다.

```sh
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo deny check
```

`cargo deny check`를 실행하려면 [cargo-deny](https://github.com/EmbarkStudios/cargo-deny)가 필요합니다.

## 보안

- 페어링할 때 한 컴퓨터에 표시되는 문자 8개로 된 일회용 코드를 다른 컴퓨터에 입력합니다. 두 컴퓨터는 이 코드로 암호 인증 키 교환(PAKE) 방식인 SPAKE2를 실행한 뒤 서로의 장기 키를 교환하고 고정합니다([ADR 0006](docs/adr/0006-pairing.md) (일본어)).
- 이후 연결할 때마다 고정한 키로 양쪽의 신원을 확인하고 Noise 프로토콜 프레임워크를 사용해 연결을 암호화합니다. 영상도 같은 키로 암호화해 전송합니다([ADR 0007](docs/adr/0007-control-channel.md), [ADR 0015](docs/adr/0015-media-transport.md) (일본어)).
- 새로 페어링한 컴퓨터에는 보기 및 제어 권한만 부여됩니다. 각 권한은 그 권한을 부여한 컴퓨터에서 개별적으로 회수할 수 있습니다.

페어링은 아직 외부 검토를 받지 않았으며 릴리스 전에 검토를 받을 계획입니다. Istesso는 같은 컴퓨터에서 같은 사용자 계정으로 실행되는 다른 프로그램으로부터 보호되지 않습니다.

취약점은 GitHub의 비공개 취약점 신고 기능으로 알려 주세요. Security 탭에서 “Report a vulnerability”를 선택하세요. 취약점에 대해 공개 이슈를 열지 마세요.

- GPL 또는 AGPL 코드는 포함하지 않습니다. 외부 코드를 사용하기 전에 [docs/components.md](docs/components.md) (일본어)와 대조해 확인하세요. 명세나 프로토콜을 차용하기 전에는 라이선스와 특허 조건을 모두 확인하세요. 불분명한 것은 도입하지 않습니다.
- 영상, 입력 또는 소리의 경로를 변경하면 풀 리퀘스트에 변경 전후의 측정값을 기재하세요. 측정할 수 없었다면 그 사실을 밝혀 주세요.
- 장치 어댑터의 인터페이스가 아직 정해지지 않아 어댑터를 추가하는 풀 리퀘스트는 받지 않습니다([ADR 0012](docs/adr/0012-device-framework.md) (일본어)).
